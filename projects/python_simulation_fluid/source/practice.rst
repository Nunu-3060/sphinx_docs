手法の比較と実践上の注意
========================

最後の章では、これまでに実装した手法を比較し、自分でシミュレーションを作るときに役立つ実践的な注意点をまとめる。パラメーターの選び方、計算が発散したときの調べ方、結果を検証する手順、計算を速くする方法を順に説明し、さらに学ぶための道筋を示す。

パラメーターの選び方
--------------------

シミュレーションのパラメーターは、次の順に決めるとよい。

#. **無次元数を決める**: レイノルズ数など、再現したい流れの性質を決める無次元数を先に決める。速さや長さを 1 にそろえ、動粘性係数を無次元数から求めると扱いやすい(第 5 章)。
#. **解像度を決める**: 再現したい最も小さな構造(物体の直径、渦の大きさ、水の層の厚さ)が、何個の格子や粒子で表されるかを考える。目安として 10〜20 個以上は必要である。第 10 章では円柱の直径を 16 格子で表したが、流路の幅の影響もあり、ストローハル数は実験値より約 15 % 大きかった。
#. **時間刻み幅を決める**: 次の表の条件をすべて満たすように決める。

.. list-table:: 時間刻み幅の主な制約
   :header-rows: 1
   :widths: 25 40 35

   * - 制約
     - 条件の目安
     - 本書で扱った章
   * - 振動(ばね、接触)
     - :math:`\Delta t < 2/\omega_{\max}`、接触時間の数十分の 1
     - 第 2 章、第 4 章
   * - 移流の CFL 条件
     - :math:`U \Delta t / \Delta x \le 1`
     - 第 6 章
   * - 移流と粘性(中心差分)
     - :math:`U^2 \Delta t / \nu \le 2` 程度
     - 第 8 章
   * - 拡散(陽解法)
     - :math:`\nu \Delta t / \Delta x^2 \le 1/2`\ (2 次元では 1/4)
     - 第 6 章、第 8 章
   * - 音速による CFL 条件
     - :math:`\Delta t \le 0.25\,h/c_0`
     - 第 9 章

条件の目安はいずれも安定性の限界なので、実際にはさらに余裕を持たせる。また、安定であることと正確であることは別である。安定な時間刻み幅の中でも、時間刻み幅を半分にして結果が変わらないことを確かめるとよい。

計算が発散したときの調べ方
--------------------------

数値シミュレーションを作ると、値が急に大きくなって ``NaN``\ (非数)や ``inf``\ (無限大)になることがよくある。次の順に調べると原因を見つけやすい。

#. **時間刻み幅を確かめる**: 前の節の条件を満たしているかを確かめる。時間刻み幅を半分にして発散しなくなるなら、安定性の条件を満たしていなかった可能性が高い。
#. **最初に発散したステップを見つける**: 毎ステップ値が有限かどうかを調べ、最初に異常が起きたステップと場所を特定する。発散が始まった場所(壁際、特定の粒子、領域の端など)は、原因の大きな手がかりになる。
#. **保存量を監視する**: 全エネルギー、全質量、全運動量など、本来保存されるはずの量を毎ステップ記録する。発散する前から少しずつずれ始めていることが多い。
#. **問題を小さくする**: 粒子 2 個、格子を 1 次元にするなど、手計算や厳密解で確かめられる大きさまで問題を小さくして、同じ現象が起きるかを調べる。第 4 章の 2 粒子の衝突はその例である。
#. **境界条件と単位を確かめる**: 境界の処理の符号の誤り、配列の添字の向き(``[y, x]`` か ``[x, y]`` か)の取り違え、単位の不一致は、よくある誤りである。

2 番目の手順は、次のようなコードで簡単に実現できる(``advance`` と ``state`` は、それぞれ 1 ステップ進める関数と状態を表す仮の名前である)。

.. code-block:: python
   :linenos:

   for step in range(n_steps):
       advance(state)
       if not np.all(np.isfinite(state.u)):
           bad = np.argwhere(~np.isfinite(state.u))
           raise RuntimeError(f"ステップ {step} で発散した。最初の異常な位置: {bad[0]}")

計算を速くする
--------------

シミュレーションの計算時間を短くする方法は、効果の大きい順におおむね次のようになる。

#. **アルゴリズムを改善する**: 近傍探索を総当たり法からセル分割法に変えると、計算量そのものが :math:`N^2` に比例する状態から、ほぼ :math:`N` に比例する状態に下がった(第 4 章)。近傍リストの再利用(第 9 章)や、より速く収束する反復法(第 7 章)もこれにあたる。
#. **ベクトル化する**: Python の for 文を NumPy の配列演算に置き換える(第 3 章)。
#. **メモリーの使い方を見直す**: 大きな一時配列を何度も作らないようにする(第 10 章)。
#. **コンパイルする**: Numba などで Python の関数を機械語にコンパイルすると、NumPy で書きにくい逐次的な処理(ガウス-ザイデル法など)も高速に実行できる。
#. **並列化・GPU を使う**: CuPy、JAX、Taichi などを使うと、GPU で計算できる。格子ボルツマン法のように局所的な計算は、特に GPU に向いている。

どこに時間がかかっているかは、推測せずに測定して確かめる。Python 標準の ``cProfile`` を使うと、関数ごとの計算時間を調べられる。

.. code-block:: console
   :linenos:

   python -m cProfile -s tottime sph_dam_break.py

本書の SPH(第 9 章)では、このように調べた結果、最初の実装では計算時間の 6 割近くを近傍探索が占めていることが分かり、近傍リストの再利用などによって 1 ステップの計算時間を半分程度にできた。

さらに学ぶために
----------------

本書で扱ったのは、2 次元の基本的な手法だけである。さらに学ぶための方向をいくつか挙げる。

* **3 次元への拡張**: 本書の手法は、いずれも原理的にはそのまま 3 次元に拡張できる。ただし計算量が大きく増えるので、前の節の高速化が重要になる。
* **乱流**: レイノルズ数が高い流れでは、格子で解像できない小さな渦の効果をモデルで表す乱流モデル(LES など)が必要になる。
* **自由表面の格子法**: 格子法で水面を扱うには、VOF 法やレベルセット法などで水面の位置を追跡する。
* **格子と粒子の組み合わせ**: 粒子で物理量を運び、格子で圧力を計算する FLIP 法や APIC 法は、映像制作の液体の表現で広く使われている。
* **既存のソフトウェア**: 実務では、OpenFOAM(格子法)、DualSPHysics や PySPH(SPH)、Palabos(格子ボルツマン法)などのソフトウェアがよく使われる。本書で手法の中身を理解しておくと、これらのソフトウェアのパラメーターの意味や結果の限界を判断しやすくなる。

各ソフトウェアや参考書の情報は\ :doc:`references`\ にまとめた。

おわりに
--------

本書では、粒子の運動から始めて、格子法、粒子法、格子ボルツマン法による流体のシミュレーションを、小さな動くコードで実装してきた。どの章でも、結果がもっともらしく見えることと、結果が正しいことは別であり、数値で確かめる必要があることを繰り返し示した。

数値シミュレーションは、正しく使えば現象を深く理解するための強力な道具になる。本書のサンプルコードのパラメーターを変えたり、新しい力や境界を加えたりしながら、自分の手で確かめる経験を積んでほしい。
