第 2 章　基礎の道具箱
============================================================

プロシージャル生成の手法は多様だが、その部品はおおむね共通している。乱数を作り、値を滑らかにつなぎ、範囲を整え、色を付ける。本章では、以降のすべての章で使うこれらの部品を整理する。

本章の図は、次のスクリプトで作っている。

* :download:`randomness.py <../examples/python/randomness.py>`: 乱数とハッシュ関数
* :download:`easing.py <../examples/python/easing.py>`: 補間・イージング・範囲変換
* :download:`colors.py <../examples/python/colors.py>`: 色の生成

擬似乱数とシード
------------------------------------------------------------

計算機が作る乱数は、決まった計算で次々に数を作る\ **擬似乱数**\ である。計算の出発点となる値を\ **シード**\ （種）と呼ぶ。同じシードからは必ず同じ数列が得られる。

これはプロシージャル生成にとって欠点ではなく、重要な性質である。シードを 1 つ保存しておけば、生成した世界全体を後から同じ形で再現できる。Minecraft のワールドをシードの数値だけで共有できるのはこのためである。

.. code-block:: python
   :linenos:

   import numpy as np

   rng = np.random.default_rng(seed=42)
   print(rng.random(3))  # 何度実行しても同じ 3 個の数が出る

   rng = np.random.default_rng(seed=43)
   print(rng.random(3))  # シードを変えると別の数列になる

再現性を保つには、乱数をどこで何回使ったかにも注意が要る。たとえば、地形を作る処理の途中に乱数を 1 回使う処理を追加すると、それ以降に使う乱数がすべてずれ、同じシードでも別の地形になる。この問題は、次節のハッシュ関数を使うと避けられる。

位置から乱数を得る：ハッシュ関数
------------------------------------------------------------

上の擬似乱数は、内部に状態を持ち、呼び出すたびに状態を進めて次の値を返す。そのため、値は呼び出した順番で決まる。これに対して\ **ハッシュ関数**\ は、整数の入力を混ぜ合わせて、入力と無関係に見える整数を返す関数である。状態を持たないので、同じ入力には、いつ、どの順番で呼んでも同じ値を返す。

プロシージャル生成では、格子の座標 :math:`(i, j)` とシードをハッシュ関数に入れ、その場所に固有の乱数を得る使い方が多い。この方法には次の利点がある。

* 世界のどの部分から生成しても結果が変わらない。無限に広がる地形を、見えている範囲だけ生成できる。
* 各画素・各頂点を独立に計算できる。GPU のシェーダーのように、全画素を並列に計算する環境でも使える。
* 処理を追加・削除しても、ほかの場所の乱数がずれない。

本書では、GPU 向けのハッシュ関数を比較した研究（Jarzynski と Olano、2020 年）で品質と速さの釣り合いが良いとされた PCG ハッシュを使う。

.. literalinclude:: ../examples/python/prng.py
   :language: python
   :pyobject: hash_u32
   :lineno-match:
   :caption: examples/python/prng.py（hash_u32）

線形合同法で 1 歩進めた値 ``state`` を、値そのものの上位 4 bit で決まる量だけ右にシフトして混ぜる。シフト量が値によって変わるので、入力の規則性が出力に残りにくい。NumPy の符号なし 32 bit 整数の掛け算は、桁あふれした上位の bit を捨てる。GPU の ``uint`` の計算と同じ結果になるので、同じ式を GLSL でも使える。

2 次元の座標には、ハッシュ関数を入れ子にして使う。

.. literalinclude:: ../examples/python/prng.py
   :language: python
   :pyobject: hash2
   :lineno-match:
   :caption: examples/python/prng.py（hash2）

GLSL では、同じ計算を次のように書ける。

.. code-block:: glsl
   :linenos:

   uint pcg(uint v) {
       uint state = v * 747796405u + 2891336453u;
       uint word = ((state >> ((state >> 28u) + 4u)) ^ state) * 277803737u;
       return (word >> 22u) ^ word;
   }

   // 整数座標 (ix, iy) とシードから 0 以上 1 未満の乱数を作る
   float random2(ivec2 p, uint seed) {
       uint h = pcg(uint(p.y) + pcg(seed));
       h = pcg(uint(p.x) + h);
       return float(h) / 4294967296.0;
   }

ハッシュ関数の質は、結果を画像にすると確かめやすい。:numref:`fig-hash-compare` は、128 × 128 の格子の各点で計算したハッシュ値を明るさで表したものである。

.. _fig-hash-compare:

.. figure:: _generated/randomness/hash_compare.png
   :alt: 4 種類のハッシュ値を明るさで表した画像。左端だけ斜めの縞模様が見える

   ハッシュ関数の比較。左から、掛け算と剰余だけの式 :math:`(37 i + 91 j) \bmod 256`、sin ハッシュ、PCG ハッシュ（シード 0 と 1）

左端の式は値が座標の 1 次式なので、斜めの縞模様がはっきり現れる。このような規則性は、ノイズや配置に使うと目に見える模様として残る。

2 番目の sin ハッシュは、GLSL の作例でよく見かける ``fract(sin(dot(p, vec2(12.9898, 78.233))) * 43758.5453)`` である。この図では問題なく見えるが、結果が GPU の ``sin`` の精度に依存し、機種によって値が変わったり、座標が大きいと模様が崩れたりすることが知られている。本書では整数演算だけで計算できる PCG ハッシュを使う。

乱数の分布
------------------------------------------------------------

ハッシュ関数や擬似乱数が直接返すのは、0 以上 1 未満の範囲に均等に散らばる\ **一様乱数**\ である。生成の目的に応じて、これを別の分布に変換して使う。

.. _fig-distributions:

.. figure:: _generated/randomness/distributions.png
   :alt: 一様分布、一様乱数 3 個の平均、正規分布、重み付き選択のヒストグラム

   ハッシュ関数から作った 20000 個の乱数のヒストグラム

:numref:`fig-distributions` の各図は次の方法で作っている。

* **一様分布**: ハッシュ値を :math:`2^{32}` で割る。
* **一様乱数の平均**: 一様乱数を複数個平均すると、中央に寄った山形の分布になる（中心極限定理）。「だいたい中くらいで、たまに極端」な値が欲しいときに手軽に使える。
* **正規分布**: 2 個の一様乱数 :math:`u_1, u_2` から :math:`\sqrt{-2 \ln (1 - u_1)} \cos (2 \pi u_2)` を計算する（ボックス＝ミュラー法）。木の高さや色のばらつきなど、自然な個体差を表すのに向く。
* **重み付き選択**: 重みの累積和を作り、一様乱数がどの区間に入るかで選ぶ。「草を 5、低木を 3、岩を 1、花を 1 の割合で置く」のような配置に使う。

補間とイージング
------------------------------------------------------------

離れた点に置いた値の間を埋める操作を\ **補間**\ と呼ぶ。最も基本的なものは\ **線形補間**\ である。

.. math::

   \mathrm{lerp}(a, b, t) = a + (b - a) t \quad (0 \le t \le 1)

線形補間は、つなぎ目で傾きが急に変わるので、折れ線のような不自然さが残る。そこで、:math:`t` をそのまま使わず、両端で傾きが 0 になる曲線で変形してから補間する。代表的なものが次の 2 つである。

.. math::

   \mathrm{smoothstep}(t) &= 3t^2 - 2t^3 \\
   \mathrm{smootherstep}(t) &= 6t^5 - 15t^4 + 10t^3

smoothstep は両端で 1 階微分が 0 になり、smootherstep は 2 階微分も 0 になる。第 3 章のノイズでは、格子の継ぎ目を目立たなくするために smootherstep を使う。GLSL の組み込み関数 ``smoothstep(e0, e1, x)`` は、:math:`x` を :math:`e_0 \sim e_1` の範囲で 0〜1 に正規化してから上の 3 次式を適用する。

アニメーションでは、時間の進み方を変える同様の関数を\ **イージング**\ と呼ぶ。ゆっくり動き出す ease-in、ゆっくり止まる ease-out、その両方を持つ ease-in-out がある。

.. figure:: _generated/easing/easing_curves.png
   :alt: 線形、smoothstep、smootherstep と、各種イージング関数のグラフ

   補間の重みの曲線（左）とイージング関数（右）

範囲変換・しきい値・グラデーションマップ
------------------------------------------------------------

生成した値は、そのままでは使いにくいことが多い。ノイズの値は -1〜1 程度、画像の明るさは 0〜1、地形の高さは 0〜数百 m というように、使う場所ごとに必要な範囲が違うからである。そこで、次の 3 つの操作で値を整える。

**範囲変換**\ （remap）は、ある範囲の値を別の範囲へ線形に写す。

.. math::

   \mathrm{remap}(x) = y_0 + \frac{(x - x_0)(y_1 - y_0)}{x_1 - x_0}

**しきい値**\ は、値がある値より大きいかどうかで 2 値に分ける。陸と海、岩と土のように領域を分けるのに使う。境界をくっきりさせたくない場合は、しきい値の前後の狭い範囲だけを smoothstep でつなぐ。

**グラデーションマップ**\ は、0〜1 の値を、あらかじめ決めた色の並びに対応付ける。標高を色に変えれば地図になる。

色の生成
------------------------------------------------------------

手続きで色を決めるときは、どの色空間で計算するかで結果が大きく変わる。

色空間の選び方
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

画像ファイルの RGB 値は、通常 **sRGB** という規格で符号化されている。sRGB の値は光の強さに比例しない（人の目の感度に合わせて暗い側に細かく値を割り当てている）。光を足し合わせる計算は、sRGB を光の強さに比例する\ **線形 RGB** に戻してから行う。

**HSV** は色相・彩度・明度で色を指定する方法で、「色相を少しずつずらす」といった操作が直感的にできる。ただし、明度 V が同じでも、黄色は明るく青は暗く見える。

**OKLab** は、Björn Ottosson が 2020 年に発表した色空間である。L（明るさ）、a（緑〜赤）、b（青〜黄）の 3 成分で色を表し、成分の差が見た目の差におおむね比例するように作られている。OKLab の a, b を極座標で表したものを OKLCH（明るさ・彩度・色相）と呼ぶ。

:numref:`fig-color-interpolation` は、青と黄の間を 3 つの色空間で補間したものである。sRGB では中間が灰色にくすみ、HSV では色相環を回る途中の緑や水色を通る。OKLab では明るさが一定の割合で変わり、中間もくすみにくい。

.. _fig-color-interpolation:

.. figure:: _generated/colors/color_interpolation.png
   :alt: 青から黄へのグラデーションを sRGB、HSV、OKLab で補間した 3 本の帯

   2 色の補間の比較

:numref:`fig-hue-lightness` は、色相だけを変えたときの明るさを比べたものである。各色と輝度が等しい灰色を下に並べている。HSV では黄色と水色が明るく青が暗いのに対して、OKLCH では明るさがほぼそろう。ランダムな色相を選んでも明るさをそろえたい場合は、OKLCH で色相だけを変えるとよい。

.. figure:: _generated/colors/hue_lightness.png

   色相を変えたときの明るさ。HSV（上 2 本）と OKLCH（下 2 本）

コサインパレット
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Inigo Quilez が紹介した\ **コサインパレット**\ は、0〜1 の値 :math:`t` から色を作る式である。

.. math::

   \mathrm{color}(t) = \boldsymbol{a} + \boldsymbol{b} \cos \bigl( 2 \pi (\boldsymbol{c} t + \boldsymbol{d}) \bigr)

:math:`\boldsymbol{a}, \boldsymbol{b}, \boldsymbol{c}, \boldsymbol{d}` はそれぞれ RGB の 3 成分を持つベクトルである。:math:`\boldsymbol{a}` は平均の色、:math:`\boldsymbol{b}` は変化の幅、:math:`\boldsymbol{c}` は変化の速さ、:math:`\boldsymbol{d}` は成分ごとの位相のずれを表す。12 個の数だけで滑らかな配色が決まり、GLSL でも 1 行で書けるので、シェーダーでよく使われる。

.. figure:: _generated/colors/cosine_palettes.png
   :alt: 虹、夕焼け、海、砂漠の 4 種類のコサインパレットの帯

   コサインパレットの例（パラメーターは colors.py の PALETTES を参照）

まとめ
------------------------------------------------------------

* シードを決めれば、擬似乱数による生成は再現できる。
* 座標から乱数を得るハッシュ関数を使うと、生成の順番に依存しない、並列に計算できる乱数が得られる。
* 一様乱数を変換すれば、正規分布や重み付き選択など目的に合った分布を作れる。
* 補間には smoothstep などの曲線を使い、つなぎ目の不自然さをなくす。
* 範囲変換・しきい値・グラデーションマップで、生成した値を用途に合わせて整える。
* 色の補間やランダムな配色には、見た目の明るさがそろう OKLab・OKLCH が向く。
