第 9 章　陰関数と体積表現
============================================================

第 6 章では、形を頂点と三角形の並び（メッシュ）として作った。本章では、形を「空間の各点で値を返す関数」として表す方法を扱う。点を入れると、その点が形の内側か外側か、表面からどれだけ離れているかが分かる関数である。第 1 章の分類では関数型に当たり、ノイズと同じく、どの点からでも、どの順番でも計算できる。

この表し方では、形の足し引きや、2 つの形をなめらかに溶け合わせる操作が、数値の min・max だけで書ける。また、雲や煙のように表面のはっきりしないものも、空間の各点の「濃さ」として同じ枠組みで扱える。本章では、関数で形を作り、それをメッシュに変換する方法と、メッシュを作らずに直接描く方法（レイマーチング）を順に説明する。

本章の図は、次のスクリプトで作っている。

* :download:`implicit_sdf.py <../examples/python/implicit_sdf.py>`: 距離関数とブーリアン演算
* :download:`implicit_meshing.py <../examples/python/implicit_meshing.py>`: 等値面のメッシュ化、メタボール、洞窟
* :download:`raymarching.py <../examples/python/raymarching.py>`: レイマーチングによる描画と雲

距離関数などの部品はライブラリ :download:`sdf3d.py <../examples/python/sdf3d.py>` に、メッシュ化の処理は :download:`marching_tetrahedra.py <../examples/python/marching_tetrahedra.py>` にまとめた。

陰関数による形の表現
------------------------------------------------------------

球の表面は、中心 :math:`\boldsymbol{c}`、半径 :math:`r` を使って、:math:`|\boldsymbol{p} - \boldsymbol{c}| - r = 0` を満たす点 :math:`\boldsymbol{p}` の集まりとして書ける。このように、関数 :math:`f(\boldsymbol{p})` が 0 になる点の集まりとして面を表すものを\ **陰関数**\ （implicit function）による表現と呼ぶ。本書では、:math:`f < 0` の側を形の内側、:math:`f > 0` の側を外側とする。:math:`f = 0` の面は、関数の値が一定の面という意味で\ **等値面**\ （isosurface）とも呼ぶ。

メッシュによる表現と比べると、得意なことと苦手なことがはっきり分かれる。

.. list-table:: メッシュと陰関数の比較
   :header-rows: 1
   :widths: 24 38 38

   * - 操作
     - メッシュ
     - 陰関数
   * - 表面の点を列挙する
     - 頂点をそのまま使える
     - 直接は得られない。メッシュ化（本章）やレイマーチング（本章）が必要
   * - ある点が内側かどうかを調べる
     - 難しい（レイと全三角形の交差を数えるなど）
     - :math:`f` の符号を見るだけでよい
   * - 形の和・差・共通部分
     - 三角形の交差を計算する必要があり、難しい
     - min・max だけで書ける
   * - 2 つの形をなめらかにつなぐ
     - 難しい
     - スムーズな min で書ける
   * - GPU での描画
     - そのまま描ける
     - メッシュ化するか、シェーダーでレイマーチングする

符号付き距離関数
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

陰関数のうち、値の大きさが「表面までの最短距離」に等しいものを\ **符号付き距離関数**\ （signed distance function、SDF）と呼ぶ。上の球の式は、まさに表面までの距離を表しているので SDF である。SDF は、内外の判定に加えて「表面からどれだけ離れているか」も教えてくれる。この性質は、後で説明するレイマーチングで決定的な役割を果たす。

:numref:`fig-implicit-sdf-slice` は、3 次元の SDF を :math:`y = 0` の平面で切った断面に、値を色で表したものである。黒い線が表面（値 0）、青が内側、橙が外側で、縞の 1 本が距離 0.1 に当たる。外側の縞は、表面から離れるにつれて角が取れて丸くなっていく。

.. _fig-implicit-sdf-slice:

.. figure:: _generated/implicit_sdf/sdf_slice.png
   :alt: 球・直方体・トーラスの距離関数の断面。表面からの距離が等間隔の縞で表されている

   球・直方体・トーラスの距離関数の断面（y = 0）。黒い線が表面

基本形の距離関数
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

よく使う形の SDF は、Inigo Quilez が式を整理して公開している。本章では、その GLSL の式を NumPy に書き直して使う。点の座標は、最後の軸に :math:`(x, y, z)` を持つ配列で表し、多数の点をまとめて計算する。

.. literalinclude:: ../examples/python/sdf3d.py
   :language: python
   :pyobject: sd_box
   :lineno-match:
   :caption: examples/python/sdf3d.py（sd_box）

直方体の式は、まず対称性を使って点を第 1 象限に折り返し（``np.abs(p)``）、各軸について面からはみ出した量 :math:`\boldsymbol{q}` を求める。すべての成分が負なら点は内側にあり、最も近い面までの距離 :math:`\max(q_x, q_y, q_z)`\ （負）を返す。正の成分があれば、その成分だけを使ったベクトルの長さが、最も近い面・辺・角までの距離になる。

.. literalinclude:: ../examples/python/sdf3d.py
   :language: python
   :pyobject: sd_torus
   :lineno-match:
   :caption: examples/python/sdf3d.py（sd_torus）

トーラスは、点から z 軸までの距離と輪の半径の差 ``ring`` と、高さ :math:`z` を 2 次元の点とみなし、その点と原点の距離から管の半径を引く。:numref:`fig-implicit-sdf-primitives` は、これらの関数を後述の方法でメッシュにしたものである。

.. _fig-implicit-sdf-primitives:

.. figure:: _generated/implicit_sdf/sdf_primitives.png
   :alt: 距離関数から作った球、直方体、トーラスのメッシュ

   距離関数をメッシュ化した球・直方体・トーラス

基本形を動かしたり変形したりするには、関数そのものではなく、関数に渡す点のほうを変換する。

* **平行移動**: 中心を :math:`\boldsymbol{c}` に動かすには :math:`f(\boldsymbol{p} - \boldsymbol{c})` を計算する。
* **回転**: 形を回転行列 :math:`R` で回すには、点を逆向きに回して :math:`f(R^{\mathsf{T}} \boldsymbol{p})` とする。
* **拡大**: :math:`s` 倍に拡大するには :math:`s \, f(\boldsymbol{p} / s)` とする（最後に :math:`s` を掛けて、距離の尺度を戻す）。
* **角を丸める**: :math:`f(\boldsymbol{p}) - r` は、形を厚さ :math:`r` だけ膨らませ、角を半径 :math:`r` で丸める。
* **繰り返し**: 座標を周期で割った余りを使うと、同じ形を無数に並べられる（第 4 章のパターンと同じ考え方）。

ブーリアン演算とスムーズブレンド
------------------------------------------------------------

2 つの形の SDF を :math:`a`、:math:`b` とすると、形の和・共通部分・差は次のように書ける。点がどちらかの内側にあれば :math:`\min(a, b) < 0` になり、両方の内側にあれば :math:`\max(a, b) < 0` になる。差は、:math:`b` の内外を反転した :math:`-b` との共通部分である。このような形の足し引きを\ **ブーリアン演算**\ と呼ぶ。

.. math::

   \text{和: } \min(a, b), \qquad \text{共通部分: } \max(a, b), \qquad \text{差: } \max(a, -b)

.. _fig-implicit-sdf-boolean:

.. figure:: _generated/implicit_sdf/sdf_boolean.png
   :alt: 直方体と球の和、共通部分、差、スムーズな和のメッシュ

   直方体と球のブーリアン演算

:numref:`fig-implicit-sdf-boolean` は、直方体と、その角に重ねた球を組み合わせた結果である。わずか 1 回の min・max で、メッシュでは面倒な形の足し引きができる。ただし、和の内側や、共通部分・差の結果は、正確な距離ではなく「距離以下の値」になることがある。符号（内外）は正しく、距離を過大に見積もることもないので、メッシュ化にもレイマーチングにもそのまま使える。

共通部分と差の図では、2 つの面が交わる鋭い稜線がぎざぎざになっている。これは関数の誤りではなく、次節で説明するメッシュ化の方法が、格子の間隔より細かい鋭い角を表せないためである。

.. _implicit-smooth-min:

スムーズな min
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

min で作った和は、2 つの形の継ぎ目に鋭い折れ目ができる。粘土をくっつけたような、なめらかな継ぎ目にしたい場合は、min の代わりに\ **スムーズな min**\ （smooth min）を使う。ここでは Inigo Quilez が紹介した多項式による式を使う。

.. math::

   h = \mathrm{clamp}\left( \frac{1}{2} + \frac{b - a}{2k}, 0, 1 \right), \qquad
   \mathrm{smin}(a, b) = b + (a - b) h - k h (1 - h)

.. literalinclude:: ../examples/python/sdf3d.py
   :language: python
   :pyobject: smooth_min
   :lineno-match:
   :caption: examples/python/sdf3d.py（smooth_min）

:math:`a` と :math:`b` の差が :math:`k` 以上ある所では :math:`h` が 0 か 1 になり、結果は min と一致する。差が :math:`k` 未満の所、つまり 2 つの形の表面が近い所でだけ、min より小さい値を返して継ぎ目を埋める。値の下がり方は :math:`a = b` の所で最大になり、その量は :math:`k / 4` である。

.. _fig-implicit-smooth-min:

.. figure:: _generated/implicit_sdf/smooth_min.png
   :alt: min とスムーズな min のグラフと、丸みの幅 k を変えて 2 つの球をつないだ断面

   min とスムーズな min（左）。k を変えて 2 つの球をつないだ断面（右 3 枚）

:numref:`fig-implicit-smooth-min` の左は、:math:`a = x`、:math:`b = 1 - x` の最小値である。min の角が、:math:`k` が大きいほど広い範囲で丸められる。右の 3 枚では、:math:`k` を大きくするにつれて 2 つの球の間に首のような橋が架かり、最後は 1 つの塊になる。**k は、継ぎ目の丸みの幅を距離の単位で直接指定するパラメーター**\ なので、形の大きさに対して「どれくらい溶け合わせるか」を決めやすい。

共通部分や差の稜線を丸めるには、:math:`\max(a, b) = -\min(-a, -b)` の関係を使って、スムーズな max を作ればよい（``smooth_max``）。GLSL のデモ（後述）では、和・差・共通部分のそれぞれで :math:`k` を変えられる。

メッシュ化
------------------------------------------------------------

陰関数で作った形を、ゲームエンジンで描いたり、3D プリンターで出力したり、OBJ 形式で保存したりするには、三角形のメッシュに変換する必要がある。この変換を\ **メッシュ化**\ （ポリゴン化）と呼ぶ。基本的な考え方は、空間を格子に区切って各格子点で関数の値を計算し、値の符号が変わる所に面を張ることである。

2 次元で考える：マーチング・スクエア法
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

まず 2 次元で考える。:numref:`fig-implicit-marching-squares` の左のように、格子点ごとに関数の値を調べ、内側（値が負）の点を塗りつぶす。格子の 1 マス（セル）の 4 つの角のうち、内外が異なる角を結ぶ辺の上には、必ず境界が通っている。その辺の上で値が 0 になる位置を、両端の値 :math:`f_a, f_b` から線形補間で求める。

.. math::

   \boldsymbol{p} = \boldsymbol{p}_a + \frac{0 - f_a}{f_b - f_a} (\boldsymbol{p}_b - \boldsymbol{p}_a)

各セルで、こうして求めた点を線分で結べば、境界の折れ線が得られる。セルの 4 つの角の内外の組み合わせは :math:`2^4 = 16` 通りしかないので（:numref:`fig-implicit-marching-squares` の右）、どの辺とどの辺を結ぶかを、16 通りの表として前もって用意しておける。この方法を\ **マーチング・スクエア法**\ と呼ぶ。セルを 1 つずつ順に（行進するように）処理するのが名前の由来である。

.. _fig-implicit-marching-squares:

.. figure:: _generated/implicit_meshing/marching_squares.png
   :alt: 格子点の内外と取り出した境界線、および 4 つの角の内外の 16 通りとセルに引く線分

   マーチング・スクエア法。左: 格子点の内外と取り出した線。右: 16 通りの場合分け

番号 5 と 10 のように、対角の角だけが内側になる場合は、線の引き方が 2 通りあって、表だけでは決まらない（\ **曖昧なケース**\ ）。どちらを選んでも、ひと続きの線になることは保証される。

マーチング・キューブ法
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

3 次元では、格子のセルが立方体になる。立方体の 8 個の角の内外の組み合わせは :math:`2^8 = 256` 通りあり、それぞれについて「どの辺の上に頂点を置き、どう三角形を張るか」を表にしておく。各立方体で 8 個の角の符号から表の番号を作り、表に従って三角形を張る。これが\ **マーチング・キューブ法**\ （marching cubes）で、Lorensen と Cline が 1987 年に医用画像（CT の断層画像の積み重ね）から臓器の表面を取り出す方法として発表した。

256 通りの表は、回転・反転・内外の入れ替えで同じになるものをまとめると、15 通りの基本パターンに整理できる。ただし、2 次元と同じ曖昧なケースが立方体の面に現れ、隣り合う立方体で面の張り方が食い違うと、メッシュに穴が開く。これを避けるために表を改良した版がいくつも提案されている。

実用では、マーチング・キューブ法を自分で書くことは少ない。256 通りの表は長く、手で書き写すと誤りが入りやすいからである。Python なら scikit-image の ``skimage.measure.marching_cubes``、Houdini ならボリュームをポリゴンに変換するノード（Convert VDB など。第 16 章）のように、ライブラリやツールに用意されたものを使うのが普通である。本書では外部のライブラリを増やさないために、同じ考え方で表がずっと小さくて済む、次の方法を実装する。

マーチング・テトラヘドラ法
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**マーチング・テトラヘドラ法**\ （marching tetrahedra）は、マーチング・キューブ法の簡単な変種である。立方体をそのまま調べる代わりに、:numref:`fig-implicit-tetrahedra` の左のように、立方体を 6 個の四面体に分けてから処理する。

.. _fig-implicit-tetrahedra:

.. figure:: _generated/implicit_meshing/tetrahedra.png
   :alt: 立方体の角の番号と 6 個の四面体への分け方、四面体の中で作る三角形と四角形

   立方体を 6 個の四面体に分ける（左）。四面体の中で作る面（中、右）。塗りつぶした点が内側

6 個の四面体は、いずれも立方体の対角線 0–7 を共有する。角 0 から角 7 へ、x・y・z の軸に沿って 1 辺ずつたどる経路が :math:`3! = 6` 通りあり、それぞれの経路の 4 個の角が 1 個の四面体になる。

.. literalinclude:: ../examples/python/marching_tetrahedra.py
   :language: python
   :start-after: CORNERS = np.array
   :end-before: def tetra_cases
   :lineno-match:
   :caption: examples/python/marching_tetrahedra.py（6 個の四面体）

四面体の頂点は 4 個なので、内外の組み合わせは :math:`2^4 = 16` 通りしかない。しかも、作る面は次の 3 種類だけである。

* すべて内側か、すべて外側: 面は通らない。
* 1 個だけが仲間外れ（内側 1 個、または外側 1 個）: その頂点から出る 3 本の辺の上に頂点を置き、三角形を 1 枚作る。
* 内側 2 個・外側 2 個: 内外をまたぐ 4 本の辺の上の点が四角形を作るので、三角形 2 枚に分ける。

この規則から 16 通りの表をプログラムで作れる。四面体には曖昧なケースが無いのも利点である。

   :language: python
   :pyobject: tetra_cases
   :lineno-match:
   :caption: examples/python/marching_tetrahedra.py（tetra_cases）

メッシュ化の本体は次のとおりである。Python のループで立方体を 1 個ずつ処理すると遅いので、6 個の四面体と 16 通りの場合ごとに、該当するすべての立方体を NumPy の配列でまとめて処理する。

.. literalinclude:: ../examples/python/marching_tetrahedra.py
   :language: python
   :pyobject: marching_tetrahedra
   :lineno-match:
   :caption: examples/python/marching_tetrahedra.py（marching_tetrahedra）

実装の要点は 2 つある。

* **頂点の共有**: 隣り合う四面体は、同じ辺の上に同じ頂点を置く。辺を両端の格子点の番号の組で表し、``np.unique`` で同じ辺をまとめて頂点を 1 個にする。こうすると、メッシュが 1 枚につながり、頂点の法線（第 6 章）を周りの三角形から平均して求められる。
* **面の向き**: 三角形の表（頂点が反時計回りに見える側）が外側を向くように、三角形の法線と「内側の格子点から外側の格子点へ向かう向き」の内積を調べ、負なら頂点の順番を入れ替える。

隣り合う立方体は、共有する面を同じ対角線で 2 つの三角形に分けるので（どの面も、番号の小さい角と大きい角を結ぶ対角線で分かれる）、境目で面の張り方が食い違うことはなく、穴の無い閉じたメッシュが得られる。

一方、マーチング・キューブ法より三角形の数が多くなり、細長い三角形もできやすい。マーチング・キューブ法と同じく、格子の間隔より細かい形や鋭い角は表せない（:numref:`fig-implicit-sdf-boolean` のぎざぎざ）。鋭い角を保つには、関数の勾配も使って頂点の位置を決める Dual Contouring などの方法がある。

メタボール
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

メッシュ化する関数は、距離関数でなくてもよい。古くから使われる例が\ **メタボール**\ である。複数の点の周りに、中心で大きく、離れると 0 に近づく山形の値を置いて足し合わせ、合計がしきい値を超える所を内側とする。2 つの球が近づくと、山が重なって合計が増え、間が水滴のように自然につながる。

.. literalinclude:: ../examples/python/implicit_meshing.py
   :language: python
   :pyobject: metaball_field
   :lineno-match:
   :caption: examples/python/implicit_meshing.py（metaball_field）

ここでは山の形に :math:`(1 - r^2 / R^2)^3`\ （:math:`r` は中心からの距離、:math:`R` は影響範囲の半径）を使った。範囲 :math:`R` の外では値がちょうど 0 になるので、遠くの球の影響を計算せずに済む。この場は、合計がしきい値（ここでは 0.3）以上の所を内側とするので、``marching_tetrahedra`` には「しきい値 − 場」を渡す。

.. _fig-implicit-metaballs:

.. figure:: _generated/implicit_meshing/metaballs.png
   :alt: 4 個のメタボールを、格子の細かさを 10、20、56 に変えてメッシュ化したもの

   4 個のメタボールを、格子の細かさを変えてメッシュ化したもの

:numref:`fig-implicit-metaballs` は、同じ場を 3 種類の細かさの格子でメッシュ化したものである。格子を細かくすると形は正確になるが、三角形の数は格子の 1 辺の点の数のおよそ 2 乗で増え、関数を計算する格子点の数は 3 乗で増える。用途（遠くに小さく見えるのか、近くで大きく見るのか）に応じて細かさを選ぶ。

3 次元ノイズによる洞窟
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

第 7 章のハイトマップ（各地点の高さを並べた画像）による地形は、地点ごとに高さが 1 つしかないので、張り出した崖や洞窟を表せない。地形を「各点が岩か空気か」を表す 3 次元の密度の場として作れば、この制約が無くなる。

   :lineno-match:
   :caption: examples/python/implicit_meshing.py（cave_density）

最初の項 ``ground`` は、高さ 0.62 を境に、下ほど負（岩）、上ほど正（空気）になる。これに 3 次元の fBm（第 3 章）を足すと、地面の高さが場所ごとに上下し、ノイズが強い所では上下が入れ替わって張り出しや空洞ができる。さらに、2 つのノイズ :math:`n_1, n_2` の両方が 0 に近い所をくり抜く。ノイズが 0 になる点の集まりは曲面なので、2 つの曲面が交わる線の周りが細長い管、つまり洞窟の通路になる。最後に、直方体との共通部分を取ってブロックの形に切り取る。

.. _fig-implicit-noise-cave:

.. figure:: _generated/implicit_meshing/noise_cave.png
   :alt: 3 次元ノイズの密度から作った、洞窟の口が側面に見える地形のブロックと、その断面

   3 次元ノイズの密度から作った地形（左）と、その断面（右）。上を向いた面を草の色にした

:numref:`fig-implicit-noise-cave` の側面には洞窟の口が開いている。右の断面では、地面の下に空洞が散らばっている様子が分かる。主なパラメーターと効果は次のとおりである。

.. list-table:: 洞窟のある地形のパラメーター
   :header-rows: 1
   :widths: 30 70

   * - パラメーター
     - 効果
   * - 高さの項の係数（2.0）
     - 大きいほど地面が平らな層になり、張り出しや空洞が減る
   * - fBm の振幅（0.7）と周波数（1.8）
     - 振幅を上げると起伏・張り出しが増え、周波数を上げると細かくなる
   * - 洞窟のしきい値（0.09）
     - 大きいほど通路が太くなる。0 にすると洞窟が無くなる
   * - 洞窟用ノイズの周波数（1.5）
     - 大きいほど通路が細かく曲がり、数が増える

実際のゲームでは、世界を一定の大きさのブロック（チャンク）に分け、プレイヤーの周りのチャンクだけを生成・メッシュ化することが多い。密度の場は座標だけで決まる関数なので、どのチャンクから計算しても境目がずれない。岩を掘る・置くといった編集は、格子点の密度の値を書き換えて、そのチャンクだけをメッシュ化し直せばよい。

レイマーチングによる直接描画
------------------------------------------------------------

メッシュ化をせずに、陰関数で表した形を画面に直接描くこともできる。画面の各画素について、カメラからその画素の方向へ半直線（\ **レイ**\ ）を伸ばし、レイが最初に形の表面に当たる点を求めて、その点の色を画素の色にする。この方法を\ **レイマーチング**\ と呼ぶ。シェーダーで全画素を並列に計算できるので、GLSL の作例で広く使われている。

スフィアトレーシング
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

陰関数とレイの交点は、一般には式を解いて求められない。そこで、レイに沿って少しずつ進みながら、関数の符号が変わる所を探す。一定の小さな歩幅で進むと、歩幅が小さければ計算が遅く、大きければ薄い形を飛び越えてしまう。

SDF を使えば、この問題をうまく避けられる。点 :math:`\boldsymbol{p}` で SDF の値が :math:`d` なら、:math:`\boldsymbol{p}` を中心とする半径 :math:`d` の球の中には、表面が 1 つも無い。したがって、レイに沿って :math:`d` だけ進んでも、表面を飛び越えることはない。これを繰り返すと、表面から遠い所では大股に、近づくにつれて小股に進み、表面に吸い寄せられるように到達する（:numref:`fig-implicit-sphere-tracing`）。この方法は\ **スフィアトレーシング**\ と呼ばれ、Hart が 1996 年に発表した。

.. _fig-implicit-sphere-tracing:

.. figure:: _generated/raymarching/sphere_tracing.png
   :alt: カメラから伸びるレイに沿って、物体までの距離を半径とする円を描きながら進む様子

   スフィアトレーシング。各点で、物体までの距離を半径とする円（3 次元では球）の中には何も無いので、その半径だけ進む

NumPy では、全画素のレイをまとめて 1 歩ずつ進める。まだ表面に当たっていないレイだけを選んで計算する。

.. literalinclude:: ../examples/python/raymarching.py
   :language: python
   :pyobject: sphere_trace
   :lineno-match:
   :caption: examples/python/raymarching.py（sphere_trace）

表面に当たったかどうかは、距離が ``epsilon * t`` より小さいかどうかで判定する。遠くの物体は画面上で小さく見えるので、許す誤差を進んだ距離 :math:`t` に比例させても見た目は変わらず、反復回数を減らせる。どの物体にも当たらないレイは、``max_distance`` を超えた所で打ち切る。

法線と光
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

陰影を付けるには、当たった点の\ **法線**\ （面に垂直な向き）が要る。SDF の値は表面から離れる向きに最も速く増えるので、SDF の勾配 :math:`\nabla f` が外向きの法線になる。勾配は、各軸の方向に少しずらした 2 点の値の差（中心差分）で求める。

.. literalinclude:: ../examples/python/sdf3d.py
   :language: python
   :pyobject: gradient
   :lineno-match:
   :caption: examples/python/sdf3d.py（gradient）

光の当たり方は、第 6 章と同じランバート反射（法線と光の向きの内積）を基本とし、次の 3 つを加えた。

* **柔らかい影**: 当たった点から太陽の方向へもう一度スフィアトレーシングを行い、物体に当たれば影にする。さらに、レイが物体をかすめた所では「距離 / 進んだ距離」の最小値が小さくなることを使い、その値で影を薄めると、輪郭のぼけた半影ができる（Inigo Quilez による方法）。
* **環境光**: 上を向いた面ほど空からの光を多く受けるとして、法線の z 成分で明るさを足す。
* **霧**: 遠い点ほど空の色に近づけ、奥行きを感じさせる。

ボリュームとしての雲・煙
------------------------------------------------------------

雲・煙・霧には、はっきりした表面が無い。光は内部まで入り込み、少しずつ吸収・散乱されながら進む。このようなものは、表面ではなく、空間の各点の\ **密度**\ :math:`\rho(\boldsymbol{p})` で表す。これを\ **ボリューム**\ （体積）による表現と呼び、密度から画像を作ることを\ **ボリュームレンダリング**\ と呼ぶ。

光の減衰：Beer–Lambert の法則
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

密度 :math:`\rho` の媒質の中を光が距離 :math:`s` 進むと、光の強さは次の割合に減る。これを\ **Beer–Lambert の法則**\ と呼ぶ。

.. math::

   T = \exp(-\sigma \rho s)

:math:`T` を\ **透過率**\ 、:math:`\sigma` を\ **消散係数**\ と呼ぶ。消散は、光が吸収されることと、別の方向へ散乱されることを合わせたものである。密度が場所によって変わる場合は、レイに沿って一定の間隔 :math:`\Delta s` で密度を調べ、区間ごとの透過率を掛け合わせていく。

雲が明るく見えるのは、太陽の光が雲の中で散乱されて目に届くからである。本章では、この散乱を次のように簡略化する。

1. レイに沿った各区間で、そこに届いた光のうち :math:`1 - \exp(-\sigma \rho \Delta s)` の割合が散乱される。
2. 散乱される光の強さは、その点に太陽の光がどれだけ届いているか（太陽の方向へ進んだときの透過率、つまり雲自身が作る影）で決まる。これに、空からの一定の環境光を足す。
3. 散乱された光が目に届くまでに、手前の区間の透過率 :math:`T` を掛ける。
4. 最後に、雲を抜けた先の空の色に、全体の透過率を掛けて足す。

実際の雲の描画では、散乱の向きによる明るさの違い（位相関数）や、何度も散乱を繰り返す光（多重散乱）も考えるが、ここでは省いた。

.. figure:: _generated/raymarching/cloud_params.png
   :alt: 自己影なし、基準、被覆を増やした、消散係数を下げた 4 種類の雲

   雲のパラメーターの比較

.. list-table:: 雲のパラメーター
   :header-rows: 1
   :widths: 25 75

   * - パラメーター
     - 効果
   * - 被覆（coverage）
     - 密度を計算するときに足す一定の値。大きいほど雲の範囲が広がり、すき間が埋まる。時間とともに変えると、雲が湧いたり消えたりする
   * - 消散係数 :math:`\sigma`
     - 大きいほど雲が濃く不透明になり、自己影も強くなる。小さくすると薄い霧や煙のようになる

まとめ
------------------------------------------------------------

* 陰関数は、空間の各点で値を返す関数で形を表す。値が 0 の面が表面で、符号で内外が分かる。値が表面までの距離に等しいものを符号付き距離関数（SDF）と呼ぶ。
* SDF の和・共通部分・差は min・max で書ける。スムーズな min を使うと、継ぎ目を幅 k で丸めて、形をなめらかに溶け合わせられる。
* メッシュ化は、格子点で関数を評価し、符号の変わる辺の上に頂点を置いて面を張る。マーチング・キューブ法は 256 通りの表を使う。本章では、立方体を 6 個の四面体に分け、16 通りの場合だけで済むマーチング・テトラヘドラ法を実装した。
* 3 次元の密度の場を使うと、ハイトマップでは表せない張り出しや洞窟を持つ地形を作れる。
* スフィアトレーシングは、SDF の値だけレイを進めることで、メッシュを作らずに陰関数の形を描く。法線は SDF の勾配から求まる。
* 雲や煙は、3 次元ノイズで作った密度の場を、Beer–Lambert の法則に従って光を減衰させながらレイマーチングして描く。被覆・消散係数・自己影で見た目を制御できる。
