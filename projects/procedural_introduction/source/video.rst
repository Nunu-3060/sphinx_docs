第 14 章　映像の生成
============================================================

前の 2 章では動きを作った。本章では、それを動画のファイルとして書き出す方法を扱う。手続きで映像を作るときは、各フレームを時刻から決まる画像として設計しておくと、書き出し・やり直し・並列化が楽になる。そのうえで、完全にループする映像の作り方、モーショングラフィックスの基本、ffmpeg による書き出しと形式・圧縮の選び方を説明する。最後に、GLSL のシェーダーで描いた映像をブラウザーから録画する方法を示す。ffmpeg のコマンドとオプションは、付録 C の\ :doc:`ffmpeg`\ にまとめた。

本章の図と動画は、次のスクリプトで作っている。

* :download:`loop_noise.py <../examples/python/loop_noise.py>`: 4 次元ノイズによる完全なループ
* :download:`motion_graphics.py <../examples/python/motion_graphics.py>`: イージング・時間差・合成
* :download:`video_formats.py <../examples/python/video_formats.py>`: 形式と圧縮の設定による容量の測定
* :download:`video.py <../examples/python/video.py>`: ffmpeg による書き出し（共通ライブラリ）

フレームとタイムライン
------------------------------------------------------------

動画は、決まった間隔で並んだ静止画（フレーム）の列である。フレームレート :math:`F`\ （1 秒あたりのフレーム数、fps）の動画の :math:`n` 番目のフレームは、時刻 :math:`t = n / F` の画像である。10 秒・30 fps の動画なら、:math:`n = 0, 1, \ldots, 299` の 300 枚になる。

時刻からフレームを決める純関数
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

手続きで映像を作るときは、フレームを「時刻 :math:`t` を受け取って画像を返す関数」として書くのがよい。この関数は、:math:`t` とパラメーター（シードを含む）だけで結果が決まり、前のフレームの状態や外部の状態に依存しない\ **純関数**\ にする。

.. graphviz::
   :caption: 純関数としてフレームを作る流れ
   :align: center

   digraph G {
       rankdir=LR;
       node [shape=box, style="rounded,filled", fillcolor="#eef3fb", color="#4c72b0"];
       edge [color="#555555"];
       n [label="フレーム番号 n"];
       t [label="時刻 t = n / F"];
       r [label="render(t, パラメーター)\n純関数"];
       img [label="画像"];
       w [label="VideoWriter\n（ffmpeg）"];
       out [label="MP4", shape=ellipse, fillcolor="#fdf0e6", color="#dd8452"];
       n -> t -> r -> img -> w -> out;
   }

こう設計すると、次の利点がある。

* **シークできる**: 7 秒目の 1 枚だけを確認したいとき、0 秒目から計算し直す必要が無い。長い映像の一部だけを直すのも速い。
* **並列化できる**: 各フレームは独立に計算できるので、複数のプロセスや GPU で同時に描ける。
* **再現できる**: 同じパラメーターからは、何度描いても同じ映像になる。フレームレートや解像度を変えて書き出し直しても、動きのタイミングが変わらない。

第 12 章の周期関数・ノイズによる動きや、本章のモーショングラフィックスは、そのまま純関数として書ける。たとえば、時刻の関数 ``render`` を複数のプロセスで並列に計算するには、次のようにする。``map`` は結果を入力の順に返すので、フレームの順番は崩れない。

.. code-block:: python
   :linenos:

   from concurrent.futures import ProcessPoolExecutor

   from motion_graphics import DURATION, FPS, HEIGHT, WIDTH, render
   from video import VideoWriter

   if __name__ == "__main__":
       times = [n / FPS for n in range(int(DURATION * FPS))]
       with ProcessPoolExecutor() as pool, VideoWriter("motion.mp4", WIDTH, HEIGHT, fps=FPS) as writer:
           for frame in pool.map(render, times, chunksize=8):
               writer.write(frame)

一方、第 13 章の群れや布のようなシミュレーションは、前の状態から次の状態を作るので、純関数にはならない。この場合も、乱数のシードと時間の刻み :math:`\Delta t` を固定して、毎回同じ結果になるようにする。描画のフレームレートとシミュレーションの刻みは分けておき（例: 描画 30 fps、シミュレーション 60 Hz）、書き出しの設定を変えても動きが変わらないようにする。途中から書き出したい場合は、一定の時刻ごとに状態を保存しておき、そこから計算を再開する。

完全にループするアニメーション
------------------------------------------------------------

Web ページの背景や SNS の投稿のように繰り返し再生する映像では、最後のフレームの次に最初のフレームが来ても継ぎ目が見えないことが望ましい。周期 :math:`T` の映像がループするには、時刻 :math:`t` と :math:`t + T` の画像が同じであればよい。正弦波 :math:`\sin(2 \pi k t / T)`\ （:math:`k` は整数）のように、周期が :math:`T` を割り切る周期関数だけで作った動きは、自動的にループする。難しいのは、ノイズのような周期を持たない動きをループさせることである。

円周の上でノイズを読む
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

第 3 章では、2 次元ノイズを円周に沿って読むと、角度について周期的な 1 次元の値の列が得られることを見た。円周は閉じているので、1 周すると元の値に戻る。1 つの値（たとえば物の位置）をループさせるだけなら、これで足りる。

画像の場合は、画素ごとの値が時刻とともに変わる。ループしない時間変化なら、画像の座標 :math:`(x, y)` に時刻 :math:`z = st` を加えた 3 次元ノイズ :math:`n(x, y, st)` を使う（:math:`s` は変化の速さ）。これをループさせるには、時刻の座標を円周の上で 1 周させたい。しかし円は 2 次元の図形なので、時刻のために 2 つの座標 :math:`(z, w)` が要る。画像の 2 次元と合わせて、4 次元のノイズが必要になる。

.. math::

   \mathrm{loop}(x, y, t) = n_4 \bigl( x, \; y, \; R \cos(2 \pi t / T), \; R \sin(2 \pi t / T) \bigr)

各画素は、4 次元空間の中で、:math:`(x, y)` を固定して :math:`(z, w)` 平面の半径 :math:`R` の円を 1 周する。異なる画素は異なる円を通るので、画素どうしの値は独立に変わる。円周の長さは :math:`2 \pi R` なので、半径 :math:`R` が 1 周の間の変化の量を決める。3 次元ノイズで速さ :math:`s` の変化と同じ程度にしたいなら、:math:`R = sT / (2\pi)` とする。

3 次元ノイズで同じことを試みて、:math:`n(x + R\cos\theta, \; y + R\sin\theta, \; 0)` のように画像の座標そのものを円周の上で動かすと、ループはするが、模様全体が形を変えずに円を描いて平行移動するだけになる。模様そのものを変化させながらループさせるには、画像の 2 次元とは別に 2 つの次元が要る。

4 次元パーリンノイズ
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

第 3 章のパーリンノイズを 4 次元に広げる。4 次元の格子のセル（超立方体）は 16 個の頂点を持つ。各頂点に勾配ベクトルを置き、勾配と頂点からの変位の内積を、4 つの軸の方向に順に補間する。勾配には、成分の 1 つが 0 で残り 3 つが :math:`\pm 1` の 32 本のベクトルを使い、頂点の座標のハッシュで選ぶ。

fBm（第 3 章）のように複数のオクターブを重ねる場合は、どのオクターブも同じ周期 :math:`T` で 1 周させる。上の動画では、2 つ目のオクターブの座標を 2 倍にし、円の半径も 2 倍にしている。動画のフレームは :math:`t = 0, 1/F, \ldots, T - 1/F` の :math:`TF` 枚にする。:math:`t = T` のフレームは :math:`t = 0` と同じ画像なので、含めると同じ画像が 2 回続き、ループの継ぎ目で一瞬止まって見える。

ほかの方法との比較
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

ループを作る方法はほかにもある。:numref:`fig-video-loop-methods` で 3 つを比べる。

* **時刻をそのまま使う**: :math:`n(x, y, s \cdot (t \bmod T))`。周期ごとに値が飛ぶ（左の青線の 4 秒目）。
* **2 つの時刻を混ぜる**: :math:`t` の値と :math:`t - T` の値を、重み :math:`1 - t/T` と :math:`t/T` で混ぜる。値はつながるが、周期の中央では独立な 2 つのノイズを半分ずつ混ぜることになり、値のばらつき（コントラスト）が約 :math:`1/\sqrt{2} \approx 0.71` 倍に下がる（右のグラフ）。模様が周期的に薄くなり、2 枚の絵が重なって溶け合うように見える。
* **4 次元ノイズの円周**: 値もコントラストも一様に変わる。計算はノイズ 1 回あたり 16 頂点で、3 次元（8 頂点）のおよそ 2 倍かかる。

.. _fig-video-loop-methods:

.. figure:: _generated/loop_noise/loop_methods.png
   :alt: 3 つの方法で作ったループについて、1 画素の値の時間変化と、画像全体の標準偏差の時間変化を比べたグラフ

   ループの作り方の比較（周期 4 秒）。1 画素の値（左）と、画像全体の値の標準偏差（右）

このほか、時間方向の格子を周期 :math:`P` で繰り返す（格子の番号を :math:`P` で割った余りにする）3 次元ノイズを使い、:math:`z = Pt/T` とする方法もある。第 3 章のシームレスなテクスチャと同じ考え方を時間の軸に使うもので、こちらは 3 次元ノイズで済む。

モーショングラフィックス
------------------------------------------------------------

**モーショングラフィックス**\ は、図形や文字を動かして作る映像である。番組のタイトル、広告、データの可視化などで使われる。個々の動きは単純でも、イージング・時間差・合成の 3 つを組み合わせると、整った印象の映像になる。

動画の書き出し
------------------------------------------------------------

ffmpeg への受け渡し
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

フレームを動画にするには、各フレームを PNG などの連番画像として保存し、ffmpeg でまとめる方法がある。本書では、連番画像を作らずに、Python で作った画素の列を ffmpeg の標準入力へ直接流し込む。ディスクに大量の画像を書かずに済み、速い。共通ライブラリ ``video.py`` の ``VideoWriter`` がこれを行う。

.. literalinclude:: ../examples/python/video.py
   :language: python
   :pyobject: VideoWriter
   :lineno-match:
   :caption: examples/python/video.py（VideoWriter）

ffmpeg に渡している引数の意味は次のとおりである。

* ``-f rawvideo -pix_fmt rgb24 -s 640x360 -r 30 -i -``: 入力は標準入力（\ ``-``\ ）から読む、ヘッダーの無い生の画素列で、1 画素は RGB 各 8 bit、大きさ 640 × 360、30 fps である。生の画素列には大きさの情報が含まれないので、すべて指定する。
* ``-c:v libx264 -preset slow -crf 28``: H.264 で圧縮する。``-crf`` は画質の指定、``-preset`` は圧縮にかける手間の指定である（後述）。
* ``-pix_fmt yuv420p``: 色の情報を縦横半分の解像度で持つ形式で保存する。RGB を入力すると、何も指定しなければ ffmpeg は色を間引かない形式を選ぶが、その形式の H.264 は多くのブラウザーや再生機器で再生できない。この形式では幅と高さを偶数にする必要がある。
* ``-movflags +faststart``: 動画の目次にあたる情報をファイルの先頭に置く。ブラウザーはファイル全体を読み込む前に再生を始められる。

形式の選び方
------------------------------------------------------------

Web で使う動画の主な形式を比べる。MP4 や WebM はファイルの入れ物（コンテナ）の名前で、中身の映像の圧縮方式（コーデック）は H.264 や VP9 である。

.. list-table:: 主な動画の形式
   :header-rows: 1
   :widths: 18 18 64

   * - 形式
     - コーデック
     - 特徴
   * - MP4
     - H.264
     - ほぼすべてのブラウザー・機器で再生できる。書き出しが速い。迷ったらこれを使う
   * - WebM
     - VP9
     - 同じ画質で H.264 より小さくなることが多いが、書き出しに時間がかかる。Chrome・Firefox・Edge などで再生できる
   * - GIF
     - （画像形式）
     - 1 フレームあたり 256 色まで。動画のコーデックのような、動きを使ったフレーム間の予測を持たないので非常に大きくなる。音声は無い

ffmpeg で GIF を作るときは、動画全体から最適なパレット（使う色の一覧）を作ってから減色する（\ ``palettegen`` と ``paletteuse`` フィルター、付録 C）。WebM の VP9 は、滑らかな模様では H.264 の半分以下の大きさになったが、書き出しに H.264 の preset slow の約 3 倍の時間がかかった。

Web で使う場合
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Web ページに「GIF のように」自動で繰り返し再生される映像を置きたい場合も、GIF ではなく MP4 を ``<video>`` 要素で置くのがよい。容量が数十分の 1 になり、色も正確に出る。

.. code-block:: html
   :linenos:

   <video src="loop.mp4" autoplay loop muted playsinline></video>

``autoplay`` で自動再生し、``loop`` で繰り返す。多くのブラウザーは音声付きの自動再生を制限しているので、``muted``\ （消音）を付ける。``playsinline`` は、iPhone の Safari で全画面に切り替わらずにページの中で再生させるために付ける。本書の動画もこの形で埋め込んでいる。

圧縮の調整
------------------------------------------------------------

H.264 の容量と画質は、主に CRF・プリセット・解像度・フレームレートで決まる（:numref:`fig-video-compression`）。

   :alt: CRF と容量の関係を 2 種類の映像で比べたグラフ、プリセットごとの容量と書き出し時間の棒グラフ、解像度とフレームレートごとの容量の棒グラフ

   CRF と容量（左）、プリセットと容量・時間（中）、解像度とフレームレートと容量（右）

* **CRF**\ （Constant Rate Factor）: 目標の画質を指定する。0 は劣化なし、標準は 23 で、値を大きくするほど画質を下げて小さくする。目安として、6 増やすと容量はおよそ半分になる。必要な容量は映像の内容で大きく変わる。滑らかな模様は CRF 23 で 0.18 MB だったが、細かい粒を加えると 5.6 MB と約 30 倍になった。粒は動きから予測できない情報なので、そのまま残すには多くのデータが要る。CRF 28 では細かい粒は 0.17 MB まで小さくなったが、これは粒の大部分が圧縮で消されたためである（元の粒の標準偏差 7.2 に対して、残った乱れは 2.5 だった）。
* **プリセット**: 圧縮にかける手間を ``ultrafast`` から ``veryslow`` までの段階で指定する。遅いプリセットほど、同じ CRF で容量が小さくなる傾向がある。測定では ``ultrafast`` 0.26 MB（0.3 秒）、``slow`` 0.18 MB（1.5 秒）、``veryslow`` 0.14 MB（4.3 秒）だった。プリセットによって圧縮に使う機能が異なるので、同じ CRF でも画質は完全には同じにならず、容量が単調に減るとも限らない（測定では ``veryfast`` が ``medium`` より小さかった）。一度だけ書き出す作品なら ``slow`` が釣り合いの良い選択である。
* **解像度**: 画素の数におおむね比例して容量が変わる。640 × 360 から 320 × 180 にすると、CRF 28 で 0.09 MB から 0.03 MB になった。
* **フレームレート**: 30 fps を 15 fps にしても、容量は 0.09 MB から 0.08 MB にしか減らなかった。H.264 は前後のフレームとの差分を使って圧縮するので、フレームの間隔が短いほど差分が小さく、1 フレームあたりのデータが少なくて済むためである。動きが滑らかに見えなくなる割に容量は減らないので、フレームレートを下げる効果は小さい。

本書の動画は、640 × 360 以下、30 fps、10 秒以内、CRF 28、preset slow で書き出し、1 本 2 MB 以下に収めている。

動画の処理
------------------------------------------------------------

書き出した動画の大きさを変える、つなぐ、文字を入れる、といった処理も ffmpeg で行える。以下のコマンドは 1 行で入力する（Windows のコマンドプロンプトでも、Git Bash などでも同じ形で動く）。

拡大縮小とフレームレートの変更
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``-vf``\ （映像のフィルター）に ``scale`` を指定する。``-2`` は「縦横比を保ち、偶数になるように決める」の意味である。``flags=lanczos`` は縮小の品質の良い補間方法を選ぶ。フレームレートを変えるには ``fps`` フィルターを使う。複数のフィルターはコンマでつなぐ。

.. code-block:: bat
   :linenos:

   ffmpeg -i input.mp4 -vf "scale=320:-2:flags=lanczos" -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p small.mp4
   ffmpeg -i input.mp4 -vf "fps=15,scale=480:-2:flags=lanczos" -c:v libx264 -crf 23 -pix_fmt yuv420p out15.mp4

連結
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

同じ設定（コーデック・解像度・フレームレート）で書き出した動画は、再圧縮せずにつなげられる。つなぐファイルを列挙したテキストファイルを作り、concat を入力の形式に指定する。``-c copy`` は圧縮済みのデータをそのまま書き写す指定で、画質が落ちず、一瞬で終わる。

.. code-block:: text
   :linenos:
   :caption: list.txt

   file 'a.mp4'
   file 'b.mp4'

.. code-block:: bat
   :linenos:

   ffmpeg -f concat -safe 0 -i list.txt -c copy joined.mp4

文字の重ね合わせ
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``drawtext`` フィルターで文字を重ねる。日本語を表示するには、日本語を含むフォントファイルを ``fontfile`` で指定する。Windows のフォントは ``C:\Windows\Fonts`` にある（例: メイリオは ``meiryo.ttc``）。フィルターの中ではコロンが区切りの記号なので、ドライブ名のコロンは ``\:`` と書き、パスの区切りは ``/`` にする。``x``・``y`` には、画面の幅 ``w``・高さ ``h`` と文字の幅 ``text_w``・高さ ``text_h`` を使った式を書ける。次の例は、画面の下の中央に半透明の帯を付けて文字を表示する。

.. code-block:: bat
   :linenos:

   ffmpeg -i input.mp4 -vf "drawtext=fontfile='C\:/Windows/Fonts/meiryo.ttc':text='第 14 章　映像の生成':fontsize=28:fontcolor=white:box=1:boxcolor=black@0.5:boxborderw=8:x=(w-text_w)/2:y=h-text_h-24" -c:v libx264 -crf 23 -pix_fmt yuv420p titled.mp4

コマンドラインに日本語を書くと、端末の文字コードによっては文字化けする。その場合は、文字を UTF-8 のテキストファイルに保存し、``text=...`` の代わりに ``textfile=title.txt`` と指定する。

フレームの補間
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

フレームレートの低い動画から、中間のフレームを作って滑らかにするには ``minterpolate`` フィルターを使う。``mi_mode=mci`` は、画面の各部分の動き（動きベクトル）を推定し、その動きに沿って中間の画像を作る指定である。単純に前後のフレームを混ぜる（``mi_mode=blend``）と、動く物が二重に見える。動き補償による補間は計算が重く、速い動きや、物が重なる所では画像が崩れることがある。手続きで作った映像なら、補間に頼らず、最初から目的のフレームレートで描き直すほうが確実である。

.. code-block:: bat
   :linenos:

   ffmpeg -i input15.mp4 -vf "minterpolate=fps=30:mi_mode=mci" -c:v libx264 -crf 23 -pix_fmt yuv420p smooth30.mp4

GLSL の映像を書き出す
------------------------------------------------------------

GLSL のシェーダーで描いた映像は、ブラウザーの中で動画として録画できる。canvas 要素の ``captureStream`` メソッドは、canvas に描いた内容を映像のストリームにする。これを ``MediaRecorder`` に渡すと、ストリームを WebM などの動画ファイルとして記録できる。どちらも Chrome などのブラウザーが標準で備える機能で、外部のソフトウェアは要らない。

``MediaRecorder`` は、フレームが描かれた実際の時刻を記録する。そのため、描画が重くて画面の更新が間に合わないと、録画したフレームの間隔が不ぞろいになったり、フレームが抜けたりする。1 周の長さも、録画の開始と終了の時刻の誤差の分（1 フレーム程度）ずれることがある。フレームを 1 枚も落とさずに正確な時刻で書き出したい場合は、各フレームを決まった時刻 :math:`t = n/F` で描いて画像として保存し（Python なら本章の ``VideoWriter``）、ffmpeg で動画にする。保存した WebM を MP4 に変換するには、付録 C のコマンドを使う。

まとめ
------------------------------------------------------------

* フレームは時刻 :math:`t` から決まる純関数として設計すると、シーク・並列化・再現が容易になる。シミュレーションはシードと刻みを固定する。
* 画像を完全にループさせるには、時刻を 4 次元ノイズの 2 つの次元の円周に写す。円の半径で 1 周の変化の量を決める。2 つの時刻を混ぜる方法は、周期の中央でコントラストが下がる。
* モーショングラフィックスは、イージング、時間差、アルファ合成の組み合わせで作る。
* Python のフレームは、生の画素列として ffmpeg の標準入力に渡して書き出す。Web 向けには H.264・yuv420p・faststart の MP4 にする。
* GIF は MP4 の数十倍の大きさになる。Web で繰り返し再生する映像は ``<video autoplay loop muted playsinline>`` の MP4 にする。
* 容量は CRF と映像の内容で大きく変わる。解像度は効くが、フレームレートを下げる効果は小さい。
* GLSL の映像は、``captureStream`` と ``MediaRecorder`` でブラウザーから WebM に録画できる。
