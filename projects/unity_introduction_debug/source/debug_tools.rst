.. _debug-tools:

デバッグ用ツールと機能
======================

ログ出力は手軽ですが、確認したい値が増えるたびにコードを書き換えて再コンパイルする必要があります。本章では、コードを書き換えずにプログラムの状態を調べられるツールと、目に見えない情報を画面に表示する手法を紹介します。

.. _ide-debugger:

IDE のデバッガーによるステップ実行
----------------------------------

コードエディター（IDE）のデバッガーを使うと、実行中のプログラムを任意の行で一時停止し、その時点の変数の値を調べたり、1 行ずつ実行したりできます。

準備
^^^^

#. Unity のメニューの :menuselection:`Edit --> Preferences --> External Tools` を開き、:guilabel:`External Script Editor` で使用する IDE を選択します。
#. IDE に Unity 用の拡張機能を導入します。Visual Studio では Visual Studio Installer で「Unity によるゲーム開発」ワークロードを、Visual Studio Code では Unity 拡張機能をインストールします。JetBrains Rider は、Unity のサポートが標準で組み込まれています。
#. Unity エディターのウィンドウ右下にある虫のアイコンをクリックし、コードの最適化モードを Debug Mode に切り替えます。Release Mode のままではデバッガーを接続できません。

デバッガーの接続と基本操作
^^^^^^^^^^^^^^^^^^^^^^^^^^

IDE でデバッグを開始して Unity エディターに接続（アタッチ）し、Unity エディターで再生を開始します。Visual Studio では、ツールバーの :guilabel:`Unity にアタッチ` ボタンでデバッグを開始できます。

デバッガーの主な機能は次のとおりです。キーボードショートカットは Visual Studio の既定の設定です。

.. list-table::
   :header-rows: 1
   :widths: 25 15 60

   * - 機能
     - キー
     - 説明
   * - ブレークポイント
     - :kbd:`F9`
     - 実行を一時停止する行を指定します。
   * - 続行
     - :kbd:`F5`
     - 次のブレークポイントまで実行を再開します。
   * - ステップオーバー
     - :kbd:`F10`
     - 現在の行を実行し、次の行で停止します。メソッドの呼び出しがあっても、その中には入りません。
   * - ステップイン
     - :kbd:`F11`
     - 現在の行にあるメソッドの呼び出しの中に入って停止します。
   * - ステップアウト
     - :kbd:`Shift+F11`
     - 現在のメソッドの残りを実行し、呼び出し元に戻って停止します。
   * - ローカル変数・ウォッチ
     - －
     - 変数の値を一覧で表示します。ウォッチには、任意の変数や式を登録できます。
   * - 呼び出し履歴
     - －
     - 現在停止しているメソッドが、どのような経路で呼び出されたかを表示します。

条件付きブレークポイント
^^^^^^^^^^^^^^^^^^^^^^^^

毎フレーム実行される ``Update`` にブレークポイントを設定すると、毎回停止してしまい調査になりません。このような場合は、ブレークポイントに条件を設定します。たとえば ``hitPoint <= 0`` という条件を設定すると、HP が 0 以下になったときだけ停止します。Visual Studio では、ブレークポイントを右クリックして :guilabel:`条件` を選ぶと設定できます。

.. note::

   ブレークポイントで停止している間は、Unity エディター全体が応答しなくなります。調査が終わったら、続行するかデバッグを停止してください。

Inspector ウィンドウのデバッグモード
------------------------------------

Inspector ウィンドウは、通常はシリアライズされたフィールド（public のフィールドや ``[SerializeField]`` 属性が付いたフィールド）だけを表示します。Inspector ウィンドウのタブの右にある ⋮ メニューから :guilabel:`Debug` を選ぶとデバッグモードに切り替わり、private のフィールドも表示されます。

デバッグモードを使うと、デバッガーを接続しなくても、再生中の private のフィールドの値を確認できます。表示を元に戻すには、同じメニューから :guilabel:`Normal` を選びます。

.. _gizmos:

Gizmos と Debug.DrawLine による可視化
-------------------------------------

当たり判定の範囲や Ray の向きなど、ゲーム画面には表示されない情報が原因の不具合は、数値を見るだけでは原因をつかみにくいものです。このような情報は、線や図形として Scene ビューに表示すると理解しやすくなります。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 手段
     - 特徴
   * - ``Debug.DrawLine``、``Debug.DrawRay``
     - ``Update`` などから呼び出し、線を描画します。既定では 1 フレームだけ表示され、引数で表示時間を指定することもできます。
   * - ``Gizmos`` クラス
     - ``OnDrawGizmos`` または ``OnDrawGizmosSelected`` の中で使い、線、球、立方体などを描画します。再生していないときも表示されるため、設定値の確認にも使えます。

どちらの方法で描画した図形も Scene ビューに表示されます。Game ビューでも、ツールバーの :guilabel:`Gizmos` ボタンを有効にすると表示されます。

一時停止とフレーム送り
----------------------

一瞬だけ発生する不具合は、ツールバーの一時停止ボタンとフレーム送りボタンを使うと観察しやすくなります。

* 一時停止ボタン（:kbd:`Ctrl+Shift+P`）で再生を一時停止すると、その時点のシーンの状態を Scene ビューや Inspector ウィンドウで調べられます。
* 一時停止中にフレーム送りボタン（:kbd:`Ctrl+Alt+P`）を押すと、1 フレームずつ進められます。

特定の条件になった瞬間に止めたい場合は、スクリプトから ``Debug.Break`` を呼び出します。``Debug.Break`` を呼び出すと、そのフレームの処理が終わった時点で再生が一時停止します。

.. code-block:: csharp

   if (hitPoint <= 0)
   {
       // HP が 0 以下になったフレームの終わりで一時停止します。
       Debug.Break();
   }
