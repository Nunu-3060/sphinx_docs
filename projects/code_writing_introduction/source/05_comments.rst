==========================================
コメントと docstring
==========================================

コメントは、コードだけでは伝わらない情報を読む人に伝えるためのものである。ただし、コメントは多ければよいというものではない。不要なコメントや間違ったコメントは、かえって読む人を混乱させる。

コメントに書くべきこと
==========================================

コードを読めば分かることは、コメントに書く必要はない。コメントには、コードだけでは伝わらないことを書く。

.. list-table:: コメントに書くべきことと書くべきでないこと
   :header-rows: 1
   :widths: 50 50

   * - 書くべきこと
     - 書くべきでないこと
   * - なぜそのように書いたのか（理由や背景）
     - コードを日本語に言い換えただけの説明
   * - 一見おかしく見えるが、意図して書いた部分の説明
     - 名前を改善すれば不要になる説明
   * - 注意すべき点や制約（「この関数は 0 以上の値だけを想定している」など）
     - 古い情報や、コードと食い違う情報
   * - まだ対応していない課題（``TODO`` コメント）
     - 使わなくなったコードをコメントにして残したもの

コメントを書きたくなったときは、まず「名前を変えたり、関数に分けたりすれば、コメントが無くても伝わるのではないか」と考えるとよい。

.. code-block:: python
   :linenos:
   :caption: 悪い例

   # 合格かどうかを調べる
   if score >= 60:
       ...

.. code-block:: python
   :linenos:
   :caption: 良い例

   if score >= PASSING_SCORE:
       ...

良い例では、定数の名前によって「合格点以上かどうか」を調べていることが分かるため、コメントが不要になっている。

使わなくなったコードをコメントにして残しておくのも避ける。残す理由が分からないコードは、読む人を迷わせる。昔のコードが必要になったときは、第 11 章で紹介するバージョン管理システムの履歴から取り出せる。

コメントをコードと一致させる
==========================================

コメントは、コードと違って実行されないため、内容が間違っていてもエラーにならない。そのため、コードを変更したときにコメントを直し忘れやすい。コードと食い違ったコメントは、コメントが無いよりも有害である。

コードを変更するときは、周りのコメントも一緒に見直す習慣を付ける。

docstring を書く
==========================================

Python では、関数、クラス、モジュールの先頭に書いた文字列リテラルを :term:`docstring` と呼ぶ。docstring には、それが何をするのか、どう使うのかを書く。docstring は ``help()`` 関数で表示でき、多くのエディターでも関数の説明として表示される。

docstring の書き方は :pep:`257` で定められている。主な規則は次のとおりである。

* 3 つの二重引用符（``"""``）で囲む。
* 1 行目には、何をするのかを 1 文で簡潔に書く。
* 説明を続けて書く場合は、1 行目の後に空行を 1 行入れる。

引数や戻り値の書き方には決まった形式がいくつかある。良い例で使った ``Args:``、``Returns:`` などの見出しを使う形式は、Google のスタイルガイドで使われている形式であり、広く使われている。どの形式を使う場合も、1 つのプロジェクトの中ではそろえる。

短く、名前から内容が明らかな関数にまで、必ず docstring を書く必要はない。本書のサンプルコードでも、説明が必要な関数を中心に docstring を書いている。ただし、他の人が使うことを想定した関数やモジュールには、docstring を書くのが望ましい。

まとめ
==========================================

* コメントには、コードだけでは伝わらない理由や注意点を書く。
* コードを言い換えただけのコメントは書かない。名前を改善してコメントを不要にできないか考える。
* コードを変更したら、コメントも見直す。コードと食い違ったコメントは有害である。
* 関数やモジュールの目的や使い方は docstring に書く。
