==========================================
エラーの扱い方
==========================================

プログラムは、いつも想定どおりのデータを受け取るとは限らない。利用者が数字の代わりに文字を入力したり、読み込もうとしたファイルが存在しなかったりする。このようなときにどう振る舞うかを決めておくことも、良いコードの条件である。この章では、Python の :term:`例外` を使ったエラーの扱い方を説明する。

   0
   -5

このコードには次の問題がある。

* ``"abc"`` を変換しようとしたときに発生した例外を捕まえて、``0`` を返している。呼び出した側は、変換に失敗したことを知る方法が無く、利用者が 0 歳と入力したのか、入力が間違っていたのかを区別できない。
* ``except Exception:`` は、ほとんどすべての種類の例外を捕まえてしまう。想定していた変換の失敗だけでなく、プログラムのバグによる例外まで隠してしまう。

例外を握りつぶさない
==========================================

悪い例のように、例外を捕まえた後に何もしなかったり、それらしい値を返したりして、エラーが起きたことを隠すことを、例外を「握りつぶす」という。

例外を握りつぶすと、エラーが起きたことに誰も気付かないまま処理が進む。その結果、エラーの原因とは離れた場所で、おかしな結果が表れる。原因を調べるときには、どこで何が起きたのかが分からなくなっている。

自分の関数の中で適切に対処できないエラーは、例外として呼び出した側に伝える。呼び出した側が、エラーメッセージを表示する、入力をやり直してもらうなどの対処を決める。

捕まえる例外を絞る
==========================================

``except`` には、対処したい例外の種類だけを指定する。良い例の 21 行目では、``int()`` が変換に失敗したときに送出する ``ValueError`` だけを捕まえている。

特に、次のように例外の種類を指定しない ``except:`` は避ける。

.. code-block:: python
   :linenos:
   :caption: 悪い例

   try:
       age = int(text)
   except:
       age = 0

``except:`` は、すべての例外を捕まえる。プログラムのバグによる例外だけでなく、利用者が :kbd:`Ctrl+C` を押してプログラムを止めようとしたときに発生する ``KeyboardInterrupt`` まで捕まえてしまう。第 11 章で紹介する flake8 は、このような書き方を ``E722 do not use bare 'except'`` という警告で知らせてくれる。

不正な値は早く見つける
==========================================

悪い例は、``-5`` という年齢としてあり得ない値をそのまま返している。この値はプログラムの別の場所に渡され、そこで計算に使われるかもしれない。不正な値が使われた場所でようやく問題が見つかっても、その値がどこから来たのかを調べるのは難しい。

良い例では、23 行目と 24 行目で範囲を確認し、範囲外であればすぐに ``ValueError`` を送出している。不正な値は、できるだけ早い段階、つまり値を受け取った場所で見つける。

エラーメッセージを具体的に書く
==========================================

エラーメッセージには、次のことを書くとよい。

* 何が問題なのか（「整数でない」「範囲外である」など）
* 問題となった値（``'abc'`` や ``-5`` など）
* どうすればよいのか（「0 以上 150 以下で入力してください」など）

「エラーが発生しました」のようなメッセージでは、利用者も開発者も、何をすればよいのか分からない。

良い例の 22 行目では、``raise ... from error`` という書き方で、元の例外 ``error`` を新しい例外の原因として記録している。こうしておくと、プログラムが例外で止まったときに、元の例外の情報も表示されるため、原因を調べやすくなる。

特別な値でエラーを表さない
==========================================

悪い例は、変換に失敗したことを ``0`` という値で表している。エラーを ``0`` や ``-1`` のような特別な値で表すと、次の問題がある。

* その値が正常な結果なのかエラーなのかを区別できない場合がある（0 歳は正常な年齢である）。
* 呼び出した側が戻り値を確認し忘れると、エラーが見過ごされる。

Python では、エラーは例外で表すのが一般的である。例外は、捕まえて対処しない限りプログラムを止めるため、エラーが見過ごされることが無い。

なお、「値が見つからない」ことが異常ではなく、よくある結果の 1 つである場合は、``None`` を返すことも多い。例えば、辞書の ``get()`` メソッドは、キーが無い場合に ``None`` を返す。このような関数では、戻り値の型ヒントを ``str | None`` のように書いて、``None`` が返る可能性があることを明示する。

後片付けを確実に行う
==========================================

ファイルを開いたら、使い終わった後に閉じる必要がある。しかし、途中で例外が発生すると、ファイルを閉じる処理が実行されないことがある。``with`` 文を使うと、例外が発生した場合も含め、ブロックを抜けるときにファイルが確実に閉じられる。

.. code-block:: python
   :linenos:
   :caption: 悪い例

   file = open("scores.txt", encoding="utf-8")
   text = file.read()   # ここで例外が発生すると、ファイルが閉じられない
   file.close()

.. code-block:: python
   :linenos:
   :caption: 良い例

   with open("scores.txt", encoding="utf-8") as file:
       text = file.read()

まとめ
==========================================

* 例外を握りつぶさない。対処できないエラーは、呼び出した側に伝える。
* ``except`` には、対処したい例外の種類だけを指定する。``except:`` は使わない。
* 不正な値は、受け取った場所でできるだけ早く見つける。
* エラーメッセージには、何が問題で、どうすればよいのかを具体的に書く。
* エラーを特別な値で表さず、例外を使う。
* ファイルなどの後片付けが必要なものは、``with`` 文を使う。
