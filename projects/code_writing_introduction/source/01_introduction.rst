==========================================
はじめに
==========================================

本書の目的
==========================================

プログラミングを学び始めると、まずは「動くプログラムを書くこと」が目標になる。これはとても大切な一歩である。しかし、プログラムは一度書いたら終わりではない。後から機能を追加したり、バグを直したり、他の人が読んで手を加えたりする。そのときに困らないためには、「動く」だけでなく「読みやすく、直しやすい」コードを書く必要がある。

本書の目的は、読みやすいコードと保守しやすいコードを書くための基本的な考え方と具体的な方法を、初心者にも分かるように説明することである。

対象読者と前提知識
==========================================

本書は、次のような人を対象とする。

* プログラミングを学び始めたばかりの人
* 動くプログラムは書けるようになったが、「良いコード」が何か分からない人
* 自分が書いたコードを後から読み返して、意味が分からなくなった経験がある人

前提知識として、Python の基本的な文法（変数、``if`` 文、``for`` 文、関数の定義と呼び出し、リストと辞書）を理解していることを想定する。クラスや例外などの少し進んだ機能は、使う箇所で簡単に説明する。

本書のサンプルコードは Python 3.11 以上を対象とする。

本書の読み方
==========================================

第 2 章では、「良いコード」とは何かを説明する。第 3 章から第 10 章では、名前の付け方、見た目、コメント、関数、処理の流れ、重複、データ、エラーの扱い方という観点ごとに、良いコードを書くための方法を説明する。第 11 章では、コードの品質を保つために役立つ道具を紹介する。第 12 章では、それまでの章で学んだ方法を使い、悪いコードを段階的に書き直す。

第 3 章から第 10 章は、基本的に次の流れで説明する。

#. 悪いコードの例を示す。
#. そのコードの何が問題なのかを説明する。
#. 問題を直した良いコードの例を示す。
#. 章のまとめとして、要点を整理する。

最初から順に読むことを勧めるが、第 3 章から第 10 章は互いの関係が薄いため、気になる章から読んでもよい。巻末の付録には、コードを見直すためのチェックリストと用語集を用意した。

.. note::

   本書で紹介する方法は、絶対に守らなければならない規則ではない。大切なのは「このコードを読む人にとって分かりやすいか」を考えることである。規則を守ることが目的にならないように注意してほしい。

サンプルコードについて
==========================================

本書で使うサンプルコードは、各章の本文で表示し、ダウンロードもできるようにしている。一覧は :doc:`appendix_examples` にまとめた。

ダウンロードしたファイルは、次のように実行できる。

.. code-block:: console

   python ch03_naming_good.py

サンプルコードは、悪い例も含めてすべて正しく動作する。悪い例は「動くが、読みにくい・直しにくい」コードとして書いている。ただし、第 4 章で扱う見た目の悪い例など、一部の悪い例は本文中にだけ記載し、ファイルとしては用意していない。

すべてのサンプルコードは、第 11 章で紹介する flake8 と mypy の検査に合格することを確認している。
