==========================================
処理の流れを分かりやすくする
==========================================

``if`` 文や ``for`` 文が何重にも重なったコードや、複雑な条件式は、処理の流れを追うのが難しい。この章では、処理の流れを分かりやすくする方法を説明する。

悪い例
==========================================

次のコードには、3 つの関数がある。

* ``check_loan``：図書館で本を借りられるかどうかを調べ、結果を表す文字列を返す。会員でない場合、返却期限を過ぎた本がある場合、すでに 5 冊借りている場合は借りられない。
* ``is_discount_day``：割引日かどうかを調べる。毎月 1 日から 7 日までの土曜日と日曜日、および会員にとっての毎月 15 日が割引日である。曜日は、月曜日を ``0``、日曜日を ``6`` とする整数で表す。これは Python の ``datetime.date.weekday()`` の戻り値と同じ表し方である。
* ``print_ranking``：名前の一覧を順位付きで表示する。

このコードには次の問題がある。

* ``check_loan`` は ``if`` 文が 3 重の :term:`ネスト`\ （入れ子）になっている。どの ``else`` がどの ``if`` に対応するのかを確認しないと、どの条件でどの文字列が返るのか分からない。
* ``is_discount_day`` の条件式は長く、``and`` と ``or`` がどの順で評価されるのかを知らないと、意味を正しく読み取れない。また、``not (day > 7)`` という否定の形が、理解をさらに難しくしている。
* ``print_ranking`` は ``range(len(names))`` で添字を作り、``names[i]`` で要素を取り出している。Python ではもっと簡潔に書ける。

早期リターンでネストを浅くする
==========================================

良い例の ``check_loan`` では、「借りられない条件」を先に 1 つずつ調べ、当てはまったらすぐに ``return`` している。このように、条件を満たさない場合に関数の早い段階で処理を終える書き方を :term:`早期リターン` と呼ぶ。また、関数の先頭で例外的な条件を調べて処理を抜ける ``if`` 文を :term:`ガード節` と呼ぶ。

早期リターンを使うと、次の利点がある。

* ネストが浅くなり、コードが上から下へ一直線に読めるようになる。
* 1 つの条件と、その条件に当てはまったときの結果が、隣り合った行に並ぶ。
* 最後の行（17 行目）までたどり着いたときには、すべての条件を満たしていることが明らかになる。

また、悪い例の 9 行目のように ``return`` の後に ``else`` を書く必要は無い。``if`` の中で ``return`` すれば、それ以降の行は実行されないためである。

説明変数で条件式を分ける
==========================================

良い例の ``is_discount_day`` では、条件式の各部分に名前を付けた変数（21 行目から 23 行目）を用意し、最後にそれらを組み合わせている。このように、式の意味を説明するための変数を :term:`説明変数` と呼ぶ。

``is_weekend``\ （週末である）、``is_first_week``\ （第 1 週である）、``is_member_day``\ （会員の日である）という名前によって、24 行目の ``(is_weekend and is_first_week) or is_member_day`` は「第 1 週の週末であるか、会員の日である」と読める。

また、良い例では次の工夫もしている。

* 曜日を表す ``5`` と ``6`` の代わりに、標準ライブラリ ``calendar`` の定数 ``calendar.SATURDAY`` と ``calendar.SUNDAY`` を使っている。
* ``and`` と ``or`` を組み合わせるときは、かっこを付けて評価の順番を明示している。Python では ``and`` が ``or`` よりも先に評価されるため、悪い例の式もかっこが無くても同じ結果になる。しかし、読む人が評価の順番を正しく覚えているとは限らないため、かっこを付けた方が誤解を防げる。

否定の条件を避ける
==========================================

否定を含む条件は、肯定の条件よりも理解に時間がかかる。特に否定が重なると、意味を取り違えやすい。

.. code-block:: python
   :linenos:
   :caption: 悪い例

   if not (day > 7):
       ...
   if not is_not_valid:
       ...

.. code-block:: python
   :linenos:
   :caption: 良い例

   if day <= 7:
       ...
   if is_valid:
       ...

変数名にも、``is_not_valid`` のような否定形を使わない方がよい。``not`` と組み合わせたときに否定が二重になるためである。

Python らしいループを書く
==========================================

Python の ``for`` 文は、リストなどから要素を 1 つずつ直接取り出せる。添字が必要な場合は、組み込み関数 ``enumerate()`` を使うと、添字と要素を同時に取り出せる。良い例の 28 行目では、``start=1`` を指定して 1 から数え始めている。

.. list-table:: ループの書き方
   :header-rows: 1
   :widths: 30 35 35

   * - やりたいこと
     - 避けたい書き方
     - 良い書き方
   * - 要素を順に取り出す
     - ``for i in range(len(names)):`` で ``names[i]`` を使う
     - ``for name in names:``
   * - 添字と要素を取り出す
     - ``for i in range(len(names)):`` で ``i`` と ``names[i]`` を使う
     - ``for i, name in enumerate(names):``
   * - 2 つのリストを同時に取り出す
     - ``for i in range(len(names)):`` で ``names[i]`` と ``scores[i]`` を使う
     - ``for name, score in zip(names, scores):``

添字を使わない書き方は、短いだけでなく、添字の範囲を間違えるバグも防げる。

まとめ
==========================================

* 例外的な条件を先に調べて早期リターンし、ネストを浅くする。
* 複雑な条件式は、説明変数を使って意味のある部分に分ける。
* ``and`` と ``or`` を組み合わせるときは、かっこで評価の順番を明示する。
* 否定の条件、特に二重否定を避ける。
* ループでは、要素を直接取り出したり、``enumerate()`` や ``zip()`` を使ったりする。
