==========================================
データの扱い方
==========================================

プログラムは、データを受け取り、加工し、結果を出力する。データをどこに置き、どのような形で扱うかによって、コードの読みやすさと安全性は大きく変わる。この章では、データの扱い方で気を付けるべき点を説明する。

==========================================

グローバル変数を避ける
==========================================

悪い例の ``visit`` は、関数の外で定義した変数 ``visit_count`` を、``global`` 文を使って関数の中から変更している。関数の外で定義され、どこからでも参照できる変数を :term:`グローバル変数` と呼ぶ。

グローバル変数には、次の問題がある。

* プログラムのどこからでも変更できるため、値がおかしくなったとき、どこで変更されたのかを探すのが難しい。
* 関数の動作がグローバル変数の値に左右されるため、関数の引数と戻り値を見ただけでは、関数の動作が分からない。
* 関数を単独でテストしにくい。

良い例の ``visit`` は、現在の訪問回数を引数で受け取り、新しい訪問回数を戻り値で返す。関数が使うデータと関数が生み出すデータが、引数と戻り値として明示されている。

この例は単純化したものである。実際のプログラムで、複数の関数が同じデータを読み書きする必要がある場合は、データとそれを操作する関数をクラスにまとめることが多い。

ミュータブルなデフォルト引数を使わない
==========================================

悪い例の ``add_tag`` では、引数 ``tags`` のデフォルト値として空のリスト ``[]`` を指定している。Python では、デフォルト値は関数を定義したときに 1 回だけ作られ、その後の呼び出しでは同じオブジェクトが使い回される。そのため、1 回目の呼び出しで空のリストに追加した ``'Python'`` が、2 回目の呼び出しでも残っている。

この問題は、リストや辞書のように、作った後に中身を変更できるオブジェクトをデフォルト値にしたときに起きる。このようなオブジェクトを :term:`ミュータブル` なオブジェクトと呼ぶ。

ミュータブルなオブジェクトをデフォルト値にしたいときは、良い例のように、デフォルト値を ``None`` にして、関数の中で新しいオブジェクトを作る。

.. code-block:: python
   :linenos:

   def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
       if tags is None:
           tags = []
       tags.append(tag)
       return tags

型ヒントの ``list[str] | None`` は、「文字列のリスト、または ``None``」を表す。

関係するデータをまとめる
==========================================

悪い例の ``describe_book`` は、本の情報をタプル ``("Python 入門", 2000, True)`` で受け取り、``book[0]``、``book[1]``、``book[2]`` のように添字で値を取り出している。``book[2]`` が何を表すのかは、タプルを作っている箇所を探さないと分からない。また、値の順番を間違えても気付きにくい。

良い例では、``dataclasses`` モジュールの ``@dataclass`` を使って、本を表すクラス ``Book`` を定義した。

.. code-block:: python
   :linenos:

   @dataclass
   class Book:
       title: str
       price: int
       is_available: bool

``@dataclass`` を付けてクラスを定義すると、属性の名前と型を並べるだけで、データをまとめるためのクラスを作れる。このようなクラスを :term:`データクラス` と呼ぶ。データクラスを使うと、次の利点がある。

* ``book.title`` や ``book.price`` のように、名前で値を取り出せる。
* ``Book(title="Python 入門", price=2000, is_available=True)`` のように、名前を指定して作れる。
* 属性の名前を書き間違えると、実行時にエラーになる。また、mypy などの道具を使えば、実行する前に見つけられる。

辞書 ``{"title": "Python 入門", "price": 2000}`` を使ってデータをまとめる方法もある。しかし、辞書のキーは文字列であるため、キーを書き間違えてもエディターや mypy では見つけにくい。決まった項目を持つデータには、データクラスを使う方がよい。

決まった選択肢には列挙型を使う
==========================================

悪い例の ``status_message`` は、注文の状態を ``"shipped"`` や ``"delivered"`` という文字列で表している。文字列はどんな値でも受け取れるため、書き間違えた ``"shiped"`` もエラーにならずに処理されてしまう。

注文の状態のように、取り得る値が決まっているものには、``enum`` モジュールの ``Enum`` を使って :term:`列挙型` を定義するとよい。

.. code-block:: python
   :linenos:

   class OrderStatus(Enum):
       SHIPPED = "shipped"
       DELIVERED = "delivered"

列挙型を使うと、``OrderStatus.SHIPPED`` のように値を指定する。存在しない値を書くと、次のように、実行時にエラーになる。

.. code-block:: text
   :linenos:

   AttributeError: type object 'OrderStatus' has no attribute 'SHIPED'. Did you mean: 'SHIPPED'?

mypy を使えば、実行する前に次のように誤りを見つけられる。

.. code-block:: text
   :linenos:

   error: "type[OrderStatus]" has no attribute "SHIPED"  [attr-defined]

また、関数の引数の型ヒントを ``status: OrderStatus`` とすることで、この関数がどのような値を受け取るのかが明確になる。

まとめ
==========================================

* グローバル変数を避け、データは引数と戻り値で受け渡す。
* リストや辞書などのミュータブルなオブジェクトをデフォルト引数にしない。デフォルト値を ``None`` にして、関数の中で作る。
* 関係するデータは、添字で取り出すタプルではなく、データクラスにまとめる。
* 取り得る値が決まっているものには、列挙型を使う。
