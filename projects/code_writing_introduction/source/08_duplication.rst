==========================================
重複をなくす
==========================================

似た処理が必要になったとき、既存のコードをコピーして少しだけ書き換えるのは手軽である。しかし、同じようなコードが何か所にもあると、変更やバグの修正のたびに、すべての箇所を同じように直さなければならない。この章では、重複をなくす方法と、その注意点を説明する。

* 平均点の表示形式を変えたいとき、3 か所を直す必要がある。
* 科目を増やすたびに、引数と、ほぼ同じ 2 行のコードを追加する必要がある。

DRY 原則
==========================================

同じ知識をコードの中で何度も繰り返さないようにする考え方を :term:`DRY 原則` と呼ぶ。DRY は「Don't Repeat Yourself（同じことを繰り返すな）」の頭文字である。

重複をなくすには、次のような方法がある。

.. list-table:: 重複をなくす方法
   :header-rows: 1
   :widths: 35 65

   * - 方法
     - 説明
   * - 関数にまとめる
     - 何度も出てくる処理を関数にし、違う部分を引数にする。
   * - ループを使う
     - 対象だけが違う同じ処理は、対象をリストや辞書にまとめてループで処理する。
   * - 定数にする
     - 同じ値を何か所にも書かず、定数にする（第 3 章を参照）。
   * - 標準ライブラリを使う
     - よく使われる処理は、標準ライブラリに用意されていることが多い。自分で書く前に探してみる。

コピー＆ペーストをしたくなったときは、重複が生まれようとしているサインである。関数にまとめられないか考えるとよい。

共通化しすぎに注意する
==========================================

重複をなくすことは大切だが、何でも 1 つにまとめればよいわけではない。

見た目が似ているだけで、意味の違う処理を無理に 1 つの関数にまとめると、かえって分かりにくくなる。例えば、次の関数は、ユーザーの登録確認と商品の発送通知という目的の違う 2 種類のメールを、1 つの関数で送ろうとしている。

.. code-block:: python
   :linenos:
   :caption: 共通化しすぎた例

   def send_mail(address: str, kind: str, user_name: str = "", item_name: str = "",
                 is_urgent: bool = False, needs_receipt: bool = False) -> None:
       if kind == "registration":
           ...
       elif kind == "shipping":
           ...

このような関数は、引数 ``kind`` の値によって処理が分かれ、引数もどちらか一方でしか使わないものが多くなる。新しい種類のメールを追加するたびに、引数と条件分岐が増えていく。この場合は、``send_registration_mail`` と ``send_shipping_mail`` のように、目的ごとに関数を分けた方が分かりやすい。そのうえで、本当に共通する部分（メールを送信する処理など）だけを別の関数にまとめるとよい。

共通化するかどうかは、「片方を変更したとき、もう片方も必ず同じように変更する必要があるか」で判断するとよい。必ず同じように変更するのであれば、それは同じ知識であり、共通化すべきである。別々に変更される可能性があるのであれば、見た目が似ていても、無理に共通化しない方がよい。

まとめ
==========================================

* コピー＆ペーストで作った重複は、直し忘れによるバグの原因になる。
* 繰り返し出てくる処理は、関数やループにまとめる。
* よく使われる処理は、標準ライブラリを使う。
* 意味の違う処理を、見た目が似ているというだけで無理に共通化しない。
