DOT 言語の基本
==============

この章では、DOT 言語の文法を説明します。DOT 言語の文法は小さく、この章の内容を押さえれば、ほとんどの図を記述できます。

グラフの種類
------------

DOT ファイルには、1 つのグラフを記述します。グラフには、エッジに向きがない無向グラフと、向きがある有向グラフの 2 種類があります。

.. list-table::
   :header-rows: 1
   :widths: 20 20 60

   * - 種類
     - キーワード
     - エッジの書き方
   * - 無向グラフ
     - ``graph``
     - ``a -- b``
   * - 有向グラフ
     - ``digraph``
     - ``a -> b``

無向グラフでは ``->`` を、有向グラフでは ``--`` を使うことはできません。使うと構文エラーになります。

無向グラフ
^^^^^^^^^^

無向グラフは、友人関係やネットワークの接続のように、向きのない関係を表すのに使います。

.. literalinclude:: ../examples/dot/ch04_graph.dot
   :language: dot
   :caption: examples/dot/ch04_graph.dot

.. graphviz:: ../examples/dot/ch04_graph.dot
   :align: center

有向グラフ
^^^^^^^^^^

有向グラフは、処理の順序や依存関係のように、向きのある関係を表すのに使います。エッジの終点側に矢印が付きます。

.. literalinclude:: ../examples/dot/ch04_digraph.dot
   :language: dot
   :caption: examples/dot/ch04_digraph.dot

.. graphviz:: ../examples/dot/ch04_digraph.dot
   :align: center

有向グラフを既定のレイアウトエンジンである dot で描くと、エッジの向きに沿ってノードが上から下へ段状に並びます。この段のことをランク（rank）と呼びます。

strict
^^^^^^

``graph`` や ``digraph`` の前に ``strict`` を付けると、同じ 2 つのノードを結ぶエッジが 1 本にまとめられます。次の例では ``a -> b`` を 2 回書いていますが、描かれるエッジは 1 本です。

.. literalinclude:: ../examples/dot/ch04_strict.dot
   :language: dot
   :caption: examples/dot/ch04_strict.dot

.. graphviz:: ../examples/dot/ch04_strict.dot
   :align: center

``strict`` を付けない場合は、書いた数だけエッジが描かれます。データからグラフを生成する際に、重複したエッジを取り除く手間を省けます。

文の書き方
----------

グラフの ``{`` と ``}`` の間には、文を並べます。主な文は次の 4 種類です。

.. list-table::
   :header-rows: 1
   :widths: 25 35 40

   * - 文
     - 例
     - 意味
   * - ノード文
     - ``a [shape=box];``
     - ノードを宣言し、属性を指定します。
   * - エッジ文
     - ``a -> b [color=red];``
     - エッジを宣言し、属性を指定します。
   * - 属性文
     - ``node [shape=box];``
     - 以降に現れるノード、エッジ、グラフの既定の属性を指定します（5 章）。
   * - サブグラフ
     - ``subgraph s { a; b; }``
     - ノードやエッジをグループにまとめます（8 章）。

文の末尾のセミコロン ``;`` は省略できます。また、``[`` と ``]`` の中の属性を区切るカンマ ``,`` も省略でき、セミコロンで区切ることもできます。本資料のサンプルでは、読みやすさのため、文の末尾にセミコロンを付け、属性はカンマで区切ります。

コメント
^^^^^^^^

コメントの書き方は C 言語や Java と同じです。``//`` から行末まで、および ``/*`` から ``*/`` までがコメントになります。また、``#`` で始まる行も無視されます。

ID
--

ノードの名前やグラフの名前、属性の値などを ID と呼びます。ID には次の 4 つの書き方があります。

.. list-table::
   :header-rows: 1
   :widths: 35 30 35

   * - 書き方
     - 例
     - 備考
   * - 英字またはアンダースコアで始まり、英数字とアンダースコアが続く文字列
     - ``node_1``、``Hello``
     - 大文字と小文字は区別されます。
   * - 数値
     - ``42``、``-1.5``
     - 負の数や小数も使えます。
   * - 二重引用符で囲んだ文字列
     - ``"user name"``、``"a-b"``
     - 空白や記号、日本語を含めることができます。文字列の中の二重引用符は ``\"`` と書きます。
   * - HTML 風の文字列
     - ``<<b>bold</b>>``
     - 主にラベルに使います（6 章）。

``node``、``edge``、``graph``、``digraph``、``subgraph``、``strict`` はキーワードなので、そのままでは ID として使えません。キーワードは大文字と小文字を区別しないため、``Node`` や ``GRAPH`` も使えません。これらを ID にしたい場合は、``"node"`` のように二重引用符で囲みます。

次の例では、いろいろな書き方の ID を使っています。

.. literalinclude:: ../examples/dot/ch04_ids.dot
   :language: dot
   :caption: examples/dot/ch04_ids.dot

.. graphviz:: ../examples/dot/ch04_ids.dot
   :align: center

ノードは、ノード文で宣言しなくても、エッジ文に現れた時点で自動的に作られます。ノード文は、ノードに属性を指定したい場合や、エッジを持たないノードを置きたい場合に使います。

図に表示される文字（ラベル）は、既定ではノードの ID と同じです。ID とは別の文字を表示したい場合は ``label`` 属性を使います（6 章）。ID は短い英数字にし、表示する文字はラベルで指定するようにすると、DOT ファイルが読みやすくなります。

なお、日本語は ID やラベルに使えますが、既定のフォントでは文字化けすることがあります。日本語を表示する方法は 5 章で説明します。

エッジの書き方
--------------

エッジの連結
^^^^^^^^^^^^

``a -> b -> c`` のように、エッジは連結して書けます。これは ``a -> b`` と ``b -> c`` の 2 つのエッジを書いたのと同じです。連結したエッジに属性を指定すると、すべてのエッジにその属性が適用されます。

まとめて接続する
^^^^^^^^^^^^^^^^

エッジの始点や終点に ``{`` と ``}`` で囲んだノードの並びを書くと、並びの各ノードとの間にエッジが引かれます。たとえば ``x -> {y z}`` は、``x -> y`` と ``x -> z`` を書いたのと同じです。

.. literalinclude:: ../examples/dot/ch04_edge_chain.dot
   :language: dot
   :caption: examples/dot/ch04_edge_chain.dot

.. graphviz:: ../examples/dot/ch04_edge_chain.dot
   :align: center

``{`` と ``}`` で囲んだ部分は、名前のないサブグラフです。サブグラフについては 8 章で説明します。
