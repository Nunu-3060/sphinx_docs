トラブルシューティング
======================

この章では、Graphviz を使う際によく遭遇する問題と、その対処方法を説明します。

dot コマンドが見つからない
--------------------------

コマンドプロンプトで ``dot`` と入力して「認識されていません」と表示される場合や、Python で ``graphviz.ExecutableNotFound`` 例外が発生する場合は、Graphviz 本体がインストールされていないか、PATH が設定されていません。

#. 2 章の手順で Graphviz 本体をインストールします。
#. ``C:\Program Files\Graphviz\bin`` に ``dot.exe`` があることを確認します。
#. PATH にこのフォルダーを追加し、コマンドプロンプトやエディターを起動し直します。

Python の仮想環境や Jupyter を使っている場合も、PATH は OS の設定が使われます。PATH を変更した後は、Jupyter のサーバーも起動し直してください。

日本語が文字化けする
--------------------

日本語が「□」のように表示される場合は、使用しているフォントが日本語の文字を含んでいません。5 章で説明したとおり、``fontname`` 属性で日本語を含むフォントを指定します。

.. code-block:: dot

   graph [fontname="Meiryo"];
   node [fontname="Meiryo"];
   edge [fontname="Meiryo"];

``graph``、``node``、``edge`` のどれかに指定し忘れると、その部分だけが文字化けします。たとえば、ノードは正しく表示されるのにエッジのラベルだけが文字化けする場合は、``edge`` の ``fontname`` を確認してください。

また、DOT ファイルは UTF-8 で保存してください。ほかの文字コードで保存すると、エラーになったり文字化けしたりします。

構文エラーが発生する
--------------------

DOT の文法に誤りがあると、次のようなエラーが表示され、画像は出力されません。

.. code-block:: text

   Error: example.dot: syntax error in line 3 near '->'

エラーメッセージには、誤りが見つかった行番号と、その付近の文字が示されます。よくある原因は次のとおりです。

.. list-table::
   :header-rows: 1
   :widths: 45 55

   * - 原因
     - 対処
   * - 無向グラフ（``graph``）で ``->`` を、有向グラフ（``digraph``）で ``--`` を使っている
     - グラフの種類に合ったエッジの記号を使います。
   * - 空白や記号を含む ID を二重引用符で囲んでいない
     - ``"user name"`` のように二重引用符で囲みます。
   * - ``node`` や ``edge`` などのキーワードを ID に使っている
     - ``"node"`` のように二重引用符で囲むか、別の名前にします。
   * - ``#`` で始まる色を二重引用符で囲んでいない
     - ``color="#FF0000"`` のように二重引用符で囲みます。
   * - HTML 風ラベルのタグの対応が取れていない
     - 開始タグと終了タグが対応しているか確認します。

警告が表示される
----------------

画像は出力されても、警告が表示されることがあります。警告は図が意図どおりでない可能性を示しているので、内容を確認してください。

.. list-table::
   :header-rows: 1
   :widths: 45 55

   * - 警告
     - 原因と対処
   * - ``Warning: node 'x', graph 'g' size too small for label``
     - ``fixedsize=true`` を指定したノードが小さく、ラベルが収まりません。``width`` や ``height`` を大きくするか、``fixedsize`` を外します。
   * - ``Warning: Orthogonal edges do not currently handle edge labels. Try using xlabels.``
     - ``splines=ortho`` ではエッジの ``label`` に対応していません。``xlabel`` を使います（7 章）。
   * - ``Warning: x -> y: tail not inside tail cluster cluster_a``
     - ``ltail`` や ``lhead`` に、エッジの端のノードを含まないクラスターを指定しています（8 章）。

配置が意図どおりにならない
--------------------------

Graphviz の配置は自動で決まるため、思いどおりの位置にノードが置かれないことがあります。その場合は、次の順に調整を試してください。

#. **グラフの向きを変える**：``rankdir=LR`` などで、図の向きを変えます。
#. **段を揃える**：``rank=same`` で、同じ段に並べたいノードを指定します。
#. **エッジの影響を調整する**：主な流れのエッジの ``weight`` を大きくし、補足的なエッジに ``constraint=false`` を指定します。
#. **グループにまとめる**：関係の深いノードをクラスターにまとめます。
#. **見えないエッジを加える**：それでも足りない場合に、``style=invis`` のエッジで制約を加えます。

いずれの方法も、ノードの座標を直接指定するものではありません。ノードの位置を完全に固定したい場合は、neato でノードに ``pos="1,2!"`` のように座標を指定する方法もありますが、Graphviz の自動配置の利点が失われます。細かい位置にこだわる図は、作図ソフトウェアで描くほうが適している場合もあります。

大規模なグラフの描画が遅い
--------------------------

ノードやエッジが数千を超えると、dot での配置に時間がかかり、図も読み取りにくくなります。次の方法を検討してください。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 方法
     - 内容
   * - レイアウトエンジンを変える
     - sfdp は大規模なグラフを高速に配置できます（9 章）。
   * - エッジを減らす
     - ``concentrate=true`` をグラフに指定すると、dot で、同じ方向に並行するエッジがまとめて描かれます。
   * - 図を分割する
     - 全体を 1 枚に描くのではなく、クラスターやモジュールの単位で図を分けます。見せたい情報に絞った図のほうが、読み手に伝わりやすくなります。
   * - 横に広がりすぎた図を整える
     - 1 つのノードから多数のエッジが出るツリーは、横に長くなりがちです。Graphviz に付属する ``unflatten`` コマンド（graphviz パッケージでは ``unflatten()`` メソッド）を使うと、段を分けて縦横の比率を整えられます。
