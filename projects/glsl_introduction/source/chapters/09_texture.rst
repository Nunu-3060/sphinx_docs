第 9 章 テクスチャ
==================

テクスチャは、シェーダーから読み出せる画像データです。物体の表面に写真や模様を貼り付けるほか、計算結果を保存しておく入れ物としても使います（第 13 章）。この章では、テクスチャの使い方と、読み出し方を決めるパラメーターを説明します。

テクスチャとテクスチャ座標
--------------------------

テクスチャを構成する 1 つ 1 つの点を、画面のピクセルと区別してテクセルと呼びます。

テクスチャのどこを読むかは、テクスチャ座標で指定します。テクスチャ座標は、テクスチャの大きさによらず、横方向（s）と縦方向（t）がそれぞれ 0.0 から 1.0 の範囲になるように正規化されています。(0.0, 0.0) はテクスチャの先頭の行の先頭のテクセルの角、(1.0, 1.0) は最後の行の最後のテクセルの角にあたります。テクスチャ座標は UV 座標とも呼ばれます。

物体にテクスチャを貼り付けるには、頂点ごとにテクスチャ座標を持たせます。フラグメントシェーダーは、補間されたテクスチャ座標を使ってテクスチャを読みます。

シェーダーでテクスチャを読む
----------------------------

シェーダーでは、テクスチャを ``sampler2D`` 型の uniform 変数として宣言し、``texture`` 関数で読み出します。

.. code-block:: glsl

   uniform sampler2D uTexture;
   in vec2 vTexCoord;
   out vec4 outColor;

   void main() {
       outColor = texture(uTexture, vTexCoord);   // テクスチャ座標の位置の色を読む
   }

テクスチャから値を読み出すことを、サンプリングと呼びます。``texture`` 関数の戻り値は ``vec4`` で、一般的な画像のテクスチャでは RGBA の各成分が 0.0〜1.0 の値で返されます。

.. note::

   GLSL ES 1.00（WebGL 1.0）では、テクスチャの種類ごとに ``texture2D``、``textureCube`` という名前の関数を使っていました。GLSL ES 3.00 では、どの種類のテクスチャも ``texture`` 関数で読みます。

テクスチャに関係する主な関数は次のとおりです。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 関数
     - 内容
   * - ``texture(sampler, coord)``
     - テクスチャ座標 ``coord`` の位置をサンプリングします。フィルタリング（後述）が適用されます。
   * - ``textureLod(sampler, coord, lod)``
     - ミップマップ（後述）のレベルを ``lod`` で指定してサンプリングします。
   * - ``texelFetch(sampler, ivec2 texel, level)``
     - テクセルの番号（整数）を指定して、フィルタリングせずに 1 テクセルを読みます。
   * - ``textureSize(sampler, level)``
     - テクスチャの幅と高さ（テクセル数）を ``ivec2`` で返します。

主なサンプラー型には、2 次元のテクスチャ用の ``sampler2D`` のほか、立方体の 6 面からなるキューブマップ用の ``samplerCube``、3 次元のテクスチャ用の ``sampler3D``、テクスチャの配列用の ``sampler2DArray`` などがあります。``sampler3D`` と ``sampler2DArray`` には既定の精度がないため、使う場合は ``precision highp sampler3D;`` のように精度を指定する必要があります。

JavaScript での準備
-------------------

テクスチャを使うには、JavaScript で次の準備をします。

1. ``gl.createTexture`` でテクスチャを作り、``gl.bindTexture`` で選ぶ。
2. ``gl.texImage2D`` で画像のデータを転送する。
3. ``gl.texParameteri`` で、フィルタリングやラッピングのパラメーターを設定する。
4. 描画の前に、``gl.activeTexture`` でテクスチャユニットを選び、そのユニットにテクスチャを ``bindTexture`` する。
5. ``sampler2D`` の uniform 変数に、テクスチャユニットの番号を ``gl.uniform1i`` で設定する。

テクスチャユニットは、シェーダーからテクスチャを参照するための「差し込み口」のようなものです。シェーダーのサンプラー変数にはテクスチャそのものではなく、テクスチャユニットの番号を設定します。WebGL 2.0 では、フラグメントシェーダーから少なくとも 16 個のテクスチャユニットを使えます。

.. note::

   テクスチャの t = 0 の行は、転送したデータの最初の行です。一方、画像データは上の行から順に並んでいるので、そのまま転送すると、テクスチャ座標の (0, 0) が画像の左上になります。サンプルでは、``gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)`` で画像の上下を反転して転送し、(0, 0) が画像の左下になるようにしています。

.. note::

   ブラウザーのセキュリティ制限により、ローカルに保存した HTML ファイルからは、同じフォルダーにある画像ファイルであっても WebGL のテクスチャとして使えない場合があります。サンプル 06 では、この問題を避けるため、JavaScript で描いた画像をテクスチャにしています。自分で用意した画像を使う場合は、ローカルの Web サーバーを使ってください。

フィルタリング
--------------

テクスチャ座標は連続した値ですが、テクセルはとびとびに並んでいます。そのため、テクスチャ座標がテクセルとテクセルの間を指している場合に、どの値を返すかを決める必要があります。これをフィルタリングと呼びます。

テクスチャが画面上で拡大されて表示される場合（1 テクセルが複数のピクセルを覆う場合）のフィルタリングは、``TEXTURE_MAG_FILTER`` で指定します。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 値
     - 内容
   * - ``NEAREST``
     - 最も近いテクセルの値をそのまま使います。拡大するとテクセルの形がくっきりと四角く見えます。
   * - ``LINEAR``
     - 周囲 4 テクセルの値を、距離に応じて線形補間します（バイリニア補間）。拡大するとぼやけた見た目になります。

縮小されて表示される場合（1 ピクセルに複数のテクセルが入る場合）のフィルタリングは、``TEXTURE_MIN_FILTER`` で指定します。``NEAREST`` と ``LINEAR`` のほかに、後述するミップマップを使う 4 種類の値を指定できます。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 値
     - 内容
   * - ``NEAREST``
     - 最も近いテクセルの値を使います。
   * - ``LINEAR``
     - 周囲 4 テクセルを線形補間します。
   * - ``NEAREST_MIPMAP_NEAREST``
     - 最も適したミップマップのレベルを 1 つ選び、そのレベルで最も近いテクセルを使います。
   * - ``LINEAR_MIPMAP_NEAREST``
     - 最も適したミップマップのレベルを 1 つ選び、そのレベルで線形補間します。
   * - ``NEAREST_MIPMAP_LINEAR``
     - 適した 2 つのレベルで最も近いテクセルを取り、その 2 つの値を線形補間します。
   * - ``LINEAR_MIPMAP_LINEAR``
     - 適した 2 つのレベルでそれぞれ線形補間し、さらにその 2 つの値を線形補間します（トライリニア補間）。

``TEXTURE_MIN_FILTER`` の既定値は ``NEAREST_MIPMAP_LINEAR`` です。ミップマップを用意していないテクスチャで既定値のまま使うと、テクスチャが不完全とみなされ、サンプリングの結果が黒（0, 0, 0, 1）になります。ミップマップを作らない場合は、``NEAREST`` か ``LINEAR`` を指定してください。

ミップマップ
------------

ミップマップは、元のテクスチャを縦横 1/2 ずつ縮小した画像を、1 × 1 になるまで繰り返し作って並べたものです。元の画像をレベル 0、1/2 に縮小した画像をレベル 1、… と呼びます。``gl.generateMipmap`` を呼ぶと、GPU が自動的に作成します。

テクスチャを大きく縮小して表示すると、1 ピクセルに多数のテクセルが入ります。ミップマップを使わない場合、そのうちの 1〜4 テクセルだけを読むので、細かい模様がちらついたり、モアレ（本来ない縞模様）が現れたりします。ミップマップを使うと、表示される大きさに近い縮小画像から読むので、このような問題を抑えられます。

ラッピング
----------

テクスチャ座標が 0.0〜1.0 の範囲外になった場合の扱いを、ラッピングと呼びます。横方向は ``TEXTURE_WRAP_S``、縦方向は ``TEXTURE_WRAP_T`` で指定します。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 値
     - 内容
   * - ``REPEAT``
     - テクスチャを繰り返します（既定値）。整数部分を無視して、小数部分だけを使うことに相当します。
   * - ``CLAMP_TO_EDGE``
     - 範囲外では、端のテクセルの値を使い続けます。
   * - ``MIRRORED_REPEAT``
     - テクスチャを 1 回ごとに反転しながら繰り返します。

.. note::

   WebGL 1.0 では、幅と高さが 2 のべき乗（64、128、256 など）でないテクスチャには、``REPEAT`` やミップマップを使えないという制限がありました。WebGL 2.0 にはこの制限はありません。

次の操作で、各パラメーターの効果を確かめてください。

* 「テクスチャ座標の倍率」が 1 より小さいときは、テクスチャが拡大されて表示されます。「拡大時のフィルター」を切り替えて、``NEAREST`` と ``LINEAR`` の違いを確かめてください。
* 倍率を 1 より大きくすると、テクスチャ座標が 0.0〜1.0 の範囲外になります。「ラッピング」を切り替えて、範囲外の表示の違いを確かめてください。
* 倍率を 8 以上にすると、テクスチャが大きく縮小されます。「縮小時のフィルター」を ``NEAREST`` にしたときのちらつきやモアレと、``LINEAR_MIPMAP_LINEAR`` にしたときの見え方を比べてください。
* 「2 枚目のテクスチャを掛け合わせる」を選ぶと、2 つのテクスチャユニットを使って、円形のグラデーションのテクスチャを掛け合わせます。
