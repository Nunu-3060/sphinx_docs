第 12 章 ノイズ
===============

雲、炎、水面、大理石、木目など、自然界の模様の多くは、規則的でも完全にでたらめでもない、適度に不規則な形をしています。このような模様を作るのに使うのが、ノイズ関数です。この章では、ノイズの材料になる乱数（ハッシュ関数）の作り方と、代表的なノイズであるバリューノイズとパーリンノイズ、それらを重ねる fBm を説明します。

シェーダーでの乱数
------------------

GLSL には、JavaScript の ``Math.random`` のような乱数の関数がありません。また、シェーダーは前回の実行結果を覚えておけないので、乱数の状態を更新しながら次々に乱数を作ることもできません。

そこで、座標などの入力値から、でたらめに見える値を計算する関数を使います。このような関数をハッシュ関数と呼びます。同じ入力からは必ず同じ値が得られるので、同じ座標は毎回同じ色になります。

よく使われるのが、``sin`` を使う次のハッシュ関数です。

.. code-block:: glsl

   // 2 次元の座標から、0 以上 1 未満の擬似乱数を作る
   float hashSin(vec2 p) {
       return fract(sin(dot(p, vec2(12.9898, 78.233))) * 43758.5453);
   }

``dot`` で 2 次元の座標を 1 つの値にまとめ、``sin`` の結果に大きな数を掛けて、``fract`` で小数部分だけを取り出しています。``sin`` の値が少し変わるだけで、掛け算の結果の小数部分は大きく変わるので、入力が少し違うだけで出力はばらばらの値になります。

サンプル 09 の「格子ごとの乱数」では、``hash(floor(p))`` で、格子ごとに異なる明るさを表示しています。隣の格子との間に関係がないので、模様はモザイクのようになります。

sin を使うハッシュ関数の問題
----------------------------

``sin`` を使うハッシュ関数は短く、WebGL 1.0（GLSL ES 1.00）の時代から広く使われてきました。しかし、次の問題があります。

* ``float`` の精度は 10 進数で 7 桁程度です。``sin`` の結果に 43758.5453 を掛けると整数部分に 5 桁が使われるので、``fract`` で取り出した小数部分には 2〜3 桁程度の精度しか残りません。
* ``sin`` の計算の精度は GPU によって異なります。そのため、GPU が違うと同じ入力から異なる値が得られることがあります。
* 入力の座標が大きくなると、``dot`` の結果も大きくなり、その値の小数点以下の精度が失われます。例えば座標が 100000 のとき、``dot`` の結果は約 900 万になり、``float`` では 1 より細かい違いを表せません。その結果、出力に規則的な模様が現れます。

サンプル 09 で、表示内容を「格子ごとの乱数」、ハッシュ関数を「sin」、格子の細かさを 100 にして、「格子の番号に足す値」を 100000 にしてみてください。ばらばらだった模様に、斜めの縞模様がはっきり現れます。

座標が小さい範囲で使う分には、``sin`` を使うハッシュ関数でも十分な場合が多いです。一方、大きな座標を扱う場合や、どの GPU でも同じ結果を得たい場合は、次に説明する整数演算によるハッシュ関数を使います。

整数演算によるハッシュ関数
--------------------------

GLSL ES 3.00 では、``uint`` 型とビット演算（第 4 章）が使えます。``uint`` の演算は、結果が 32 ビットを超えた場合も上位の桁が捨てられるだけで（2\ :sup:`32` で割った余りになる）、どの GPU でも同じ結果になります。そのため、整数演算で作ったハッシュ関数は、``sin`` を使うハッシュ関数の問題を避けられます。

整数のハッシュ関数を使うには、格子の番号を ``uint`` に変換し、ハッシュ関数の結果の ``uint`` を 0 以上 1 未満の ``float`` に戻します。

.. code-block:: glsl

   uvec2 q = uvec2(ivec2(p));             // 格子の番号（整数の値を持つ vec2）を uint にする
   float value = float(x >> 8u) / 16777216.0;  // uint の上位 24 ビットを 0〜1 の float にする

* ``ivec2`` を経由して ``uvec2`` に変換すると、負の番号もビットの並びを保ったまま ``uint`` になります。
* ``uint`` を ``float`` に戻すとき、``float(x) / 4294967296.0``\ （2\ :sup:`32` で割る）とすると、``float`` の精度が足りず、丸めによって結果が 1.0 になることがあります。``float`` が正確に表せる上位 24 ビットだけを取り出して 2\ :sup:`24`\ （16777216）で割ると、結果は必ず 1 未満になります。

Xorshift
~~~~~~~~

Xorshift は、Marsaglia が 2003 年に発表した擬似乱数の生成方法です。ビットのシフトと XOR（排他的論理和）を 3 回繰り返すだけで、整数のビットをかき混ぜます。

.. code-block:: glsl

   uint xorshift32(uint x) {
       x ^= x << 13u;
       x ^= x >> 17u;
       x ^= x << 5u;
       return x;
   }

``x ^= x << 13u`` は、``x`` を 13 ビット左にずらしたものと元の ``x`` の XOR を取る処理です。これにより、各ビットに、別の位置のビットの情報が混ざります。左右両方向へのシフトを組み合わせることで、下位のビットの変化が上位へ、上位のビットの変化が下位へ広がります。本来は、この関数を繰り返し呼び出して乱数の列を作るための方法で、0 以外の値から始めると、2\ :sup:`32` - 1 個の異なる値を順に生成します。

Xorshift をハッシュ関数として使う場合は、次の点に注意が必要です。

* 入力が 0 のときは出力も 0 になります。そのため、定数を足して 0 を避けます。
* 格子の番号を単純に 1 つの整数にまとめて 1 回だけ ``xorshift32`` を通すと、隣り合う格子の入力が近い値になるため、出力に縞模様が現れます。乗算で入力をよく混ぜてから、``xorshift32`` を 2 回程度通します。

サンプル 09 では、次のように実装しています。

.. code-block:: glsl

   float hashXorshift(vec2 p) {
       uvec2 q = uvec2(ivec2(p));                       // 負の番号もそのまま uint にできる
       uint x = (q.x * 0x8da6b343u) ^ (q.y * 0xd8163841u); // 乗算で x と y を混ぜる
       x = xorshift32(x + 0x9e3779b9u);                 // 0 にならないように定数を足す
       x *= 0x2c1b3c6du;
       x = xorshift32(x);
       return float(x >> 8u) / 16777216.0;              // 上位 24 ビットを 0〜1 の float にする
   }

掛けている定数は、ビットがよく混ざるように選ばれた奇数です（``0x9e3779b9`` は黄金比の逆数（約 0.618）に 2\ :sup:`32` を掛けた値で、ハッシュ関数によく使われます）。

PCG ハッシュ
~~~~~~~~~~~~

PCG（Permuted Congruential Generator）は、O'Neill が 2014 年に発表した擬似乱数の生成方法です。線形合同法（状態に定数を掛けて定数を足す、古典的な方法）で内部の状態を進め、その状態のビットを並べ替えて出力します。線形合同法だけでは下位のビットの規則性が強いという弱点がありますが、出力の前にビットを並べ替えることで、この弱点を補っています。

Jarzynski と Olano は 2020 年に、GPU で使われるさまざまなハッシュ関数の品質と速さを比較し、PCG をもとにしたハッシュ関数が、品質と速さの釣り合いがよい選択であると報告しました。GPU で整数のハッシュ関数を使う場合は、まず PCG ハッシュを使うとよいでしょう。

.. code-block:: glsl

   uint pcg(uint v) {
       uint state = v * 747796405u + 2891336453u;
       uint word = ((state >> ((state >> 28u) + 4u)) ^ state) * 277803737u;
       return (word >> 22u) ^ word;
   }

   float hashPcg(vec2 p) {
       uvec2 q = uvec2(ivec2(p));
       return float(pcg(q.x + pcg(q.y)) >> 8u) / 16777216.0;
   }

``pcg`` 関数の各行の処理は、次のとおりです。

1. ``v * 747796405u + 2891336453u``：線形合同法で状態を 1 段階進めます。
2. ``(state >> ((state >> 28u) + 4u)) ^ state``：状態の上位 4 ビットで決まる量（4〜19 ビット）だけ右にずらして XOR を取ります。ずらす量が値ごとに変わるのが PCG の特徴です。
3. ``* 277803737u``：定数を掛けて、ビットをさらに混ぜます。
4. ``(word >> 22u) ^ word``：最後にもう一度シフトと XOR を行い、上位のビットの情報を下位に広げます。

2 次元の番号は、``pcg(q.x + pcg(q.y))`` のように、y をハッシュした結果に x を足して、もう一度ハッシュすることで 1 つの値にまとめています。

バリューノイズ
--------------

ハッシュ関数で作った乱数は、隣の格子との間に関係がありません。ノイズ関数では、この乱数をなめらかにつないで、連続的に変化する模様を作ります。

バリューノイズは、格子点に乱数を置き、格子点の間をなめらかに補間したノイズです。以下の ``hash`` は、前の節のいずれかのハッシュ関数です。

.. code-block:: glsl

   float valueNoise(vec2 p) {
       vec2 i = floor(p);  // 格子の番号
       vec2 f = fract(p);  // 格子の中での位置（0 から 1）

       // 周囲 4 つの格子点の乱数
       float a = hash(i);
       float b = hash(i + vec2(1.0, 0.0));
       float c = hash(i + vec2(0.0, 1.0));
       float d = hash(i + vec2(1.0, 1.0));

       // 補間の重みを 3 次曲線で滑らかにする
       vec2 u = f * f * (3.0 - 2.0 * f);

       return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);
   }

格子の中での位置 ``f`` をそのまま補間の重みに使うと、格子の境界で変化の傾きが急に変わり、格子の形が見えてしまいます。そこで、:math:`u = 3f^2 - 2f^3`\ （``smoothstep`` と同じ式）で重みを変換しています。この曲線は :math:`f = 0` と :math:`f = 1` で傾きが 0 になるので、格子の境界でなめらかにつながります。

バリューノイズの結果は 0〜1 の範囲です。ただし、明るい点や暗い点が格子点の位置に来やすいため、格子に沿ったブロック状の形が目立ちます。

パーリンノイズ
--------------

パーリンノイズは、Ken Perlin が 1985 年に発表したノイズで、最もよく知られたノイズ関数です。バリューノイズと同じく格子を使いますが、格子点に乱数の値ではなく、乱数で決めた向きの勾配（ベクトル）を置きます。このように勾配を使うノイズを、グラディエントノイズと呼びます。

各格子点は、「その格子点を通り、勾配の向きに傾いた坂」を表します。ある点 :math:`p` での値は、周囲 4 つの格子点について「勾配」と「格子点から :math:`p` へのベクトル」の内積を求め、それを補間して計算します。格子点の上では内積が 0 になるので、ノイズの値は格子点で必ず 0 になり、明るい点や暗い点は格子点の間に現れます。そのため、バリューノイズよりも格子の形が目立たない、自然な模様になります。

勾配は、ハッシュ関数で決めた角度の単位ベクトルとして作ります。

.. code-block:: glsl

   vec2 gradient(vec2 cell) {
       float angle = 6.28318530718 * hash(cell);  // 0 から 2π の角度
       return vec2(cos(angle), sin(angle));
   }

   float perlinNoise(vec2 p) {
       vec2 i = floor(p);
       vec2 f = fract(p);

       // 各格子点の勾配と、格子点から p へのベクトルの内積
       float a = dot(gradient(i), f);
       float b = dot(gradient(i + vec2(1.0, 0.0)), f - vec2(1.0, 0.0));
       float c = dot(gradient(i + vec2(0.0, 1.0)), f - vec2(0.0, 1.0));
       float d = dot(gradient(i + vec2(1.0, 1.0)), f - vec2(1.0, 1.0));

       // 補間の重みを 5 次曲線 6t^5 - 15t^4 + 10t^3 で滑らかにする
       vec2 u = f * f * f * (f * (f * 6.0 - 15.0) + 10.0);

       return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);
   }

補間曲線
~~~~~~~~

パーリンノイズでは、補間の重みに次の 5 次曲線を使います。

.. math::

   u(t) = 6t^5 - 15t^4 + 10t^3

この曲線は、:math:`t = 0` と :math:`t = 1` で 1 階微分（傾き）だけでなく 2 階微分（傾きの変化）も 0 になります。バリューノイズで使った 3 次曲線 :math:`3t^2 - 2t^3` は、2 階微分が :math:`6 - 12t` なので、格子の境界で 2 階微分が急に変わります。ノイズを凹凸（法線）の計算に使うと、この変化が格子状の模様として見えることがあります。Perlin は 2002 年に発表した改良版でこの 5 次曲線を採用し、この問題を解決しました。

値の範囲
~~~~~~~~

パーリンノイズの値は、0 を中心とした正負の値になります。本書の 2 次元の実装では、おおよそ -0.7〜0.7（:math:`\pm\sqrt{2}/2`）の範囲です。色として表示する場合や、0〜1 の値として使う場合は、0.5 を足します。

.. note::

   Perlin が発表した元の方式では、格子点の番号から勾配を選ぶために、0〜255 の数を並べ替えた表（順列表）を使います。シェーダーでは、表の代わりにハッシュ関数で勾配を決める実装がよく使われます。本書では、このハッシュ関数を使う実装もパーリンノイズと呼んでいます。

.. note::

   Perlin が 2001 年に発表したシンプレックスノイズは、正方形の格子の代わりに三角形（3 次元では四面体）の格子を使うノイズです。次元が高くなっても計算量が増えにくく、格子の方向による偏りも小さくなります。

サンプル 09 の「バリューノイズ」と「パーリンノイズ」を切り替えて、模様の違いを比べてください。

fBm
---

1 つのノイズだけでは、模様がぼんやりとして単調になります。自然の模様は、大きな形の中に中くらいの形があり、その中にさらに細かい形がある、という構造をしています。そこで、周波数（細かさ）を上げながら振幅（強さ）を下げたノイズを何枚も重ねます。これを fBm（fractional Brownian motion、フラクショナルブラウン運動）と呼びます。

.. math::

   \mathrm{fbm}(p) = \sum_{i=0}^{n-1} g^i \, \mathrm{noise}(\ell^i p)

重ねるノイズの 1 枚 1 枚をオクターブ、:math:`\ell` をラクナリティ（周波数の倍率、通常 2）、:math:`g` をゲイン（振幅の倍率、通常 0.5）と呼びます。

.. code-block:: glsl

   const int MAX_OCTAVES = 8;

   float fbm(vec2 p) {
       float value = 0.0;
       float amplitude = 0.5;
       for (int i = 0; i < MAX_OCTAVES; i++) {
           if (i >= uOctaves) {
               break;
           }
           value += amplitude * noise(p);
           p *= 2.0;          // 周波数を 2 倍にする
           amplitude *= 0.5;  // 振幅を 1/2 にする
       }
       return value;
   }

``noise`` には、バリューノイズとパーリンノイズのどちらを使ってもかまいません。サンプル 09 では、「fBm などに使うノイズ」で選んだノイズを 0〜1 の範囲に変換して使っています（パーリンノイズの場合は 0.5 を足しています）。

GLSL ES 3.00 では ``for (int i = 0; i < uOctaves; i++)`` のように書くこともできます。サンプルでは、GLSL ES 1.00 でも動く書き方として、最大回数を定数で決めて ``break`` で抜ける形にしています。

サンプル 09 で「オクターブ数」を増やすと、細かい模様が加わっていく様子を確かめられます。

ノイズの応用
------------

ノイズは、そのまま明るさとして使うだけでなく、ほかの計算と組み合わせて使います。

大理石
~~~~~~

縞模様を作る ``sin(p.x)`` の位相を、fBm でずらします。まっすぐな縞が不規則に曲がり、大理石のような模様になります。

.. code-block:: glsl

   float stripes = sin(p.x * 2.0 + 8.0 * fbm(p));
   float v = 0.5 + 0.5 * stripes;

雲（ドメインワーピング）
~~~~~~~~~~~~~~~~~~~~~~~~

fBm の結果を使ってノイズに渡す座標をずらし、もう一度 fBm を計算します。この手法をドメインワーピングと呼びます。模様が渦を巻くように複雑にゆがみ、雲や煙のような模様になります。ずらす量に時間を加えると、模様がゆっくりと流れるように動きます。

.. code-block:: glsl

   vec2 q = vec2(fbm(p + vec2(0.0, 0.1 * uTime)),
                 fbm(p + vec2(5.2, 1.3) - vec2(0.05 * uTime, 0.0)));
   float f = fbm(p + 2.0 * q);

``vec2(5.2, 1.3)`` は、2 つの fBm が異なる値になるように座標をずらすための、適当な定数です。

試してみよう
------------

* 表示内容を「格子ごとの乱数」にし、「格子の番号に足す値」を 100000 にした状態で、ハッシュ関数を sin、Xorshift、PCG の順に切り替えて、模様の違いを確かめる。
* ``hashXorshift`` の 2 行目以降を ``return float(xorshift32(q.x + q.y * 4096u) >> 8u) / 16777216.0;`` の 1 行に置き換えて、入力を混ぜずに Xorshift を 1 回だけ使うと縞模様が現れることを確かめる。
* fBm のゲイン（``amplitude *= 0.5``）を 0.3 や 0.7 に変えて、模様の粗さの変化を確かめる。
* パーリンノイズの補間曲線を 3 次曲線 ``f * f * (3.0 - 2.0 * f)`` に変えて、模様の違いを確かめる。
* 雲の色を、夕焼けの空のような色に変える。
