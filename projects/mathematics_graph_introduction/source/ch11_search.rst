第 11 章 グラフの探索
=====================

グラフのアルゴリズムの多くは、頂点を辺に沿って系統的にたどる\ **探索**\ を基礎にしている。迷路の解法、Web ページの巡回、ガベージコレクションによる不要なメモリの検出、ビルドの順序の決定などは、いずれもグラフの探索である。本章では、最も基本的な 2 つの探索方法である幅優先探索と深さ優先探索を学び、その応用としてトポロジカルソートと強連結成分分解を扱う。

本章では、:numref:`fig-ch11-graph` の無向グラフを例として使う。

.. _fig-ch11-graph:

.. graphviz::
   :caption: 探索の例に用いる無向グラフ
   :align: center

   graph g {
       layout=neato;
       node [shape=circle, width=0.4, fixedsize=true, fontsize=13, style=filled, fillcolor="#dbe8f5"];
       A [pos="1.2,2.4!"]; B [pos="0.4,1.2!"]; C [pos="2.0,1.2!"]; D [pos="-0.4,0!"]; E [pos="1.2,0!"]; F [pos="2.8,0!"];

幅優先探索
----------

**幅優先探索**\ （breadth-first search、BFS）は、始点から近い順に頂点を訪問する方法である。始点の隣接頂点をすべて訪問し、次にそれらの隣接頂点を訪問し、…… と、波紋が広がるように探索を進める。訪問待ちの頂点を\ **キュー**\ （先入れ先出しの待ち行列）で管理する。

1. 始点を発見済みにしてキューに入れる。
2. キューの先頭から頂点 :math:`u` を取り出し、:math:`u` に隣接する未発見の頂点をすべて発見済みにしてキューの末尾に入れる。
3. キューが空になるまで 2 を繰り返す。

.. literalinclude:: ../examples/traversal.py
   :language: python
   :linenos:
   :pyobject: bfs_order
   :caption: 幅優先探索

Python の ``collections.deque`` は両端の追加と削除が :math:`O(1)` で行えるので、キューとして使う。リストの ``pop(0)`` は :math:`O(n)` 時間かかるので避ける。各頂点は高々 1 回キューに入り、各頂点の隣接リストは 1 回ずつ走査されるので、計算量は :math:`O(n + m)` である。

:numref:`fig-ch11-graph` のグラフで頂点 A から幅優先探索を行うと、訪問順は A, B, C, D, E, F となる。頂点 :math:`v` を発見したときに通った辺 :math:`uv` を集めると、始点を根とする全域木（連結でなければ到達できた部分の木）が得られる。これが第 6 章で述べた幅優先探索木である（:numref:`fig-ch11-trees` 左）。

幅優先探索の最も重要な性質は、始点からの距離の順に頂点を発見することである。

.. admonition:: 定理 11.1

   幅優先探索で、始点 :math:`s` から頂点 :math:`v` を発見したときの幅優先探索木における深さは、距離 :math:`d(s, v)` に等しい。

このため、幅優先探索木の根から各頂点への道は最短経路になる。第 4 章で距離を計算した ``bfs_distances`` は、この性質を利用したものである。キューの中の頂点の距離は常に「:math:`k` が並んだ後に :math:`k + 1` が並ぶ」状態に保たれ、距離の小さい頂点から順に取り出されることが証明の要点である。

深さ優先探索
------------

**深さ優先探索**\ （depth-first search、DFS）は、行けるところまで進み、行き止まりになったら引き返して別の道を試す方法である。迷路で「左手を壁につけて進む」方法に似ている。再帰呼び出しを使うと簡潔に書ける。

.. literalinclude:: ../examples/traversal.py
   :language: python
   :linenos:
   :pyobject: dfs_order
   :caption: 深さ優先探索（再帰版）

再帰の代わりにスタック（後入れ先出し）を使って書くこともできる。幅優先探索のキューをスタックに置き換えたものとほぼ同じ構造になる。計算量は幅優先探索と同じく :math:`O(n + m)` である。

:numref:`fig-ch11-graph` のグラフで頂点 A から深さ優先探索を行うと、訪問順は A, B, D, E, F, C となる。B から D に進んで行き止まりになり、B に戻って E へ進み、さらに F, C と進む。発見に使った辺を集めた木が深さ優先探索木である。

幅優先探索木は「浅く広い」木に、深さ優先探索木は「深く細い」木になる傾向がある。無向グラフの深さ優先探索では、木に含まれない辺は必ず先祖と子孫を結ぶ。このような辺を\ **後退辺**\ という。:numref:`fig-ch11-trees` の右図では、辺 CA が後退辺である。後退辺があることと閉路があることは同値なので、深さ優先探索で閉路の有無を判定できる。第 4 章の切断点と橋の計算も、後退辺の性質を利用している。

有向グラフで深さ優先探索を行う場合は、木に含まれない辺が後退辺（子孫から先祖へ）、前進辺（先祖から子孫へ）、横断辺（それ以外）の 3 種類に分かれる。有向グラフが有向閉路を持つことは、後退辺が存在することと同値である。

再帰による実装は簡潔だが、第 4 章で述べたように、Python の再帰の深さの上限（既定では 1000 程度）に注意する。

2 つの探索の使い分け
~~~~~~~~~~~~~~~~~~~~

.. list-table:: 幅優先探索と深さ優先探索の比較
   :header-rows: 1
   :widths: 24 38 38

   * - 項目
     - 幅優先探索
     - 深さ優先探索
   * - 管理するデータ構造
     - キュー
     - スタック（または再帰）
   * - 訪問順
     - 始点から近い順
     - 1 本の道を行けるところまで
   * - 計算量
     - :math:`O(n + m)`
     - :math:`O(n + m)`
   * - 主な用途
     - 重みのない最短経路、二部グラフの判定、近い順の探索
     - 閉路の検出、トポロジカルソート、強連結成分、切断点と橋

単に到達可能な頂点を列挙するだけなら、どちらを使ってもよい。

トポロジカルソート
------------------

第 5 章で述べたように、有向非巡回グラフ（DAG）の頂点は、すべての辺が前から後ろへ向かうように 1 列に並べられる。この並べ方を求めることを\ **トポロジカルソート**\ という。授業の履修順序、ビルドの順序、表計算ソフトの再計算の順序などを決めるのに使う。

.. _fig-ch11-courses:

.. graphviz::
   :caption: 授業の先修関係を表す DAG
   :align: center

   digraph g {
       rankdir=LR;
       node [shape=box, style="rounded,filled", fillcolor="#dbe8f5", fontsize=12];
       "プログラミング基礎" -> "データ構造";
       "プログラミング基礎" -> "離散数学";
       "離散数学" -> "アルゴリズム";
       "離散数学" -> "グラフ理論";
       "データ構造" -> "アルゴリズム";
       "アルゴリズム" -> "コンパイラ";
   }

.. admonition:: 定理 11.2

   有向グラフがトポロジカル順序を持つための必要十分条件は、有向閉路を持たないことである。

**証明**\ ：有向閉路 :math:`v_1 \to v_2 \to \cdots \to v_k \to v_1` があれば、どの並べ方でも閉路上のどこかで後ろから前へ向かう辺ができるので、トポロジカル順序は存在しない。逆に、DAG には入次数 0 の頂点が必ず存在する（そうでなければ、辺を逆向きにたどり続けると有限個の頂点のどこかに戻り、有向閉路ができる）。入次数 0 の頂点を先頭に置いて取り除いても DAG のままなので、これを繰り返せばトポロジカル順序が得られる。□

この証明をそのまま実装したものが\ **カーンのアルゴリズム**\ （Kahn's algorithm）である。各頂点の入次数を数え、入次数 0 の頂点をキューから取り出して出力し、その頂点から出る辺の終点の入次数を 1 ずつ減らす。

.. literalinclude:: ../examples/traversal.py
   :language: python
   :linenos:
   :pyobject: topological_sort
   :caption: カーンのアルゴリズムによるトポロジカルソート

最後まで出力されない頂点が残った場合は、有向閉路があることを意味する。:numref:`fig-ch11-courses` に適用すると、次の順序が得られる。

.. code-block:: text
   :linenos:

   トポロジカル順序: ['プログラミング基礎', 'データ構造', '離散数学', 'アルゴリズム', 'グラフ理論', 'コンパイラ']

トポロジカル順序は一般に一意ではない。たとえば「データ構造」と「離散数学」の順序は入れ替えてもよい。深さ優先探索を用いて、各頂点の探索を終えた順（帰りがけ順）を逆に並べる方法でも、トポロジカル順序が得られる。

強連結成分分解
--------------

有向グラフの強連結成分（第 4 章）は、互いに行き来できる頂点の極大な集まりである。:numref:`fig-ch11-scc` の有向グラフは、{a, b, c}、{e, f, g}、{d}、{h} の 4 つの強連結成分に分かれる。

.. _fig-ch11-scc:

.. graphviz::
   :caption: 有向グラフとその強連結成分（枠で囲んだ部分）
   :align: center

   digraph g {
       rankdir=LR;
       node [shape=circle, width=0.4, fixedsize=true, fontsize=13, style=filled, fillcolor="#dbe8f5"];
       subgraph cluster_1 { label=""; style="rounded,dashed"; color="#e07b28"; a; b; c; }
       subgraph cluster_2 { label=""; style="rounded,dashed"; color="#e07b28"; e; f; g; }
       subgraph cluster_3 { label=""; style="rounded,dashed"; color="#e07b28"; d; }
       subgraph cluster_4 { label=""; style="rounded,dashed"; color="#e07b28"; h; }
       a -> b; b -> c; c -> a; b -> e; c -> d; d -> h;
       e -> f; f -> g; g -> e; g -> h;
   }

各強連結成分を 1 つの頂点にまとめると、DAG が得られる。もし有向閉路があれば、閉路上の成分同士が互いに行き来できることになり、強連結成分の極大性に反するからである。この DAG を\ **縮約グラフ**\ （または成分グラフ）という。強連結成分分解は、複雑な有向グラフを「成分の中」と「成分の間の DAG」に分けて理解するための基本的な道具である。たとえば、ソフトウェアのモジュール間の循環依存を検出したり、論理式の充足可能性問題の一種（2-SAT）を解いたりするのに使われる。

強連結成分は、深さ優先探索を用いて :math:`O(n + m)` 時間で求められる。代表的な方法が 2 つある。

* **コサラジュのアルゴリズム**\ ：深さ優先探索を 2 回行う。1 回目は元のグラフで行い、各頂点の探索を終えた順序を記録する。2 回目は辺の向きをすべて逆にしたグラフで、探索を終えた順序の遅い頂点から深さ優先探索を行う。2 回目の各探索で到達した頂点の集合が強連結成分になる。
* **タージャンのアルゴリズム**\ ：深さ優先探索を 1 回だけ行う。第 4 章の切断点の計算と同様に訪問順の番号（ここでは ``index`` と呼ぶ。第 4 章の ``order`` にあたる）と ``low`` を管理し、探索中の頂点をスタックに積んでおく。頂点 :math:`u` の探索を終えたときに ``low[u] == index[u]`` なら、:math:`u` は強連結成分の中で最初に訪問した頂点（根）であり、スタック上の :math:`u` と、:math:`u` より上に積まれた頂点が 1 つの強連結成分になる。

   :language: python
   :linenos:
   :pyobject: strongly_connected_components
   :caption: タージャンのアルゴリズムによる強連結成分分解

:numref:`fig-ch11-scc` のグラフに適用し、NetworkX の ``nx.strongly_connected_components`` と比較した結果は次のとおりである。

.. code-block:: text
   :linenos:

   強連結成分: [['h'], ['d'], ['e', 'f', 'g'], ['a', 'b', 'c']]
   NetworkX と一致: True

タージャンのアルゴリズムは、縮約グラフのトポロジカル順序の逆順に成分を出力するという性質も持つ。実際、出力の順序 h, d, {e, f, g}, {a, b, c} を逆にすると、縮約グラフの辺の向きに沿った順序になっている。

まとめ
------

* 幅優先探索はキューを使って始点から近い順に頂点を訪問し、重みのないグラフの最短経路を求められる。
* 深さ優先探索はスタックまたは再帰を使って行けるところまで進む探索であり、後退辺の有無で閉路を検出できる。
* どちらの探索も計算量は :math:`O(n + m)` である。
* 有向グラフは有向閉路を持たないときに限りトポロジカル順序を持ち、カーンのアルゴリズムや深さ優先探索で求められる。
* 強連結成分はタージャンのアルゴリズムやコサラジュのアルゴリズムで求められ、強連結成分を縮約したグラフは DAG になる。
