第 6 章 木と全域木
==================

閉路を持たない連結グラフを木という。木は最も単純な連結グラフであり、ファイルシステムのディレクトリ構造、プログラムの構文木、探索アルゴリズムの探索木、組織図など、情報科学や工学のいたるところに現れる。本章では木の基本的な性質を学んだ後、グラフの全頂点をつなぐ木である全域木と、重みの合計が最小の全域木を求めるアルゴリズムを扱う。

木の定義と性質
--------------

.. admonition:: 定義 6.1（木・森）

   閉路を持たない連結グラフを\ **木**\ という。閉路を持たないグラフ（連結とは限らない）を\ **森**\ という。

森の各連結成分は木である。木の次数 1 の頂点を\ **葉**\ という。

       c1 -- c2; c1 -- c3; c2 -- c4; c2 -- c5; c3 -- c6;
   }

.. admonition:: 定理 6.1

   頂点数が 2 以上の木は、少なくとも 2 つの葉を持つ。

**証明**\ ：木の中で最も長い道 :math:`P = (v_0, \ldots, v_k)` を 1 つ選ぶ。頂点数が 2 以上の連結グラフには辺があるので :math:`k \ge 1` である。端点 :math:`v_0` が :math:`v_1` 以外の頂点 :math:`w` と隣接しているとする。:math:`w` が :math:`P` 上にあれば閉路ができ、:math:`P` 上になければ :math:`P` の前に :math:`w` をつなげてより長い道ができる。いずれも矛盾なので、:math:`\deg(v_0) = 1` である。:math:`v_k` についても同様である。□

葉を 1 つ取り除いても、残りは連結で閉路を持たないので、やはり木である。この「葉を取り除いて小さな木に帰着させる」方法は、木に関する性質を数学的帰納法で示すときの基本的な手段である。たとえば次の定理の (3) は、葉を 1 つずつ取り除くと頂点と辺が 1 つずつ減り、最後に頂点 1 個、辺 0 本の木になることから分かる。

.. admonition:: 定理 6.2（木の特徴付け）

   頂点数 :math:`n` のグラフ :math:`G` について、次の条件はすべて同値である。

   1. :math:`G` は木である（連結で閉路を持たない）。
   2. :math:`G` の任意の 2 頂点の間に、道がちょうど 1 つ存在する。
   3. :math:`G` は連結で、辺数が :math:`n - 1` である。
   4. :math:`G` は閉路を持たず、辺数が :math:`n - 1` である。
   5. :math:`G` は連結で、どの辺を取り除いても連結でなくなる（すべての辺が橋である）。
   6. :math:`G` は閉路を持たず、隣接していない 2 頂点を結ぶ辺を 1 本加えると閉路がちょうど 1 つできる。

証明の要点だけを述べる。(1) と (2) の同値性は、2 頂点を結ぶ道が 2 つあれば閉路ができ、逆に閉路があればその上の 2 頂点を結ぶ道が 2 つあることから分かる。(1) と (5) の同値性は、定理 4.3（橋はどの閉路にも含まれない辺）から直ちに従う。辺数に関する (3) と (4) は、次のように示せる。木の辺数が :math:`n - 1` であることは前述のとおりである。閉路を持たないグラフの各連結成分は木なので、連結成分が :math:`c` 個なら辺数は :math:`n - c` になる。よって閉路を持たず辺数が :math:`n - 1` なら :math:`c = 1`、つまり連結である。逆に連結で辺数が :math:`n - 1` のグラフに閉路があれば、閉路上の辺を除いても連結性は保たれるので、辺数 :math:`n - 2` 以下の連結グラフが得られ、定理 4.2 に反する。

この定理は、木が「連結であるための最小限の辺を持つグラフ」であり、同時に「閉路を作らずに持てる最大限の辺を持つグラフ」であることを示している。

根付き木
--------

木の頂点を 1 つ選んで特別扱いしたものを\ **根付き木**\ といい、選んだ頂点を\ **根**\ という。根付き木では、根から各頂点への道が一意に定まるので、次の用語が定義できる。

* 頂点 :math:`v` の\ **深さ**\ ：根から :math:`v` への道の長さ。
* 根から :math:`v` への道で :math:`v` の直前にある頂点を :math:`v` の\ **親**\ 、:math:`v` を親とする頂点を :math:`v` の\ **子**\ という。
* 根から :math:`v` への道の上にある頂点を :math:`v` の\ **祖先**\ 、:math:`v` を祖先とする頂点を :math:`v` の\ **子孫**\ という。
* 木の\ **高さ**\ ：深さの最大値。

各頂点の子が高々 2 個の根付き木を\ **二分木**\ という。二分探索木やヒープ、ハフマン符号の符号木など、多くのデータ構造が根付き木を基礎にしている。根付き木では親を記録しておけば根への道をたどれるので、配列 ``parent[v]`` だけで木全体を表せる。この表現は、本章の Union-Find や、第 11 章の探索木、第 12 章の最短経路木でも使う。

全域木
------

.. admonition:: 定義 6.2（全域木）

   グラフ :math:`G` の全域部分グラフで木であるものを、:math:`G` の\ **全域木**\ という。

全域木は、すべての頂点を最小限の辺でつなぐ「骨組み」である。連結グラフは必ず全域木を持つ。実際、連結グラフに閉路があれば、その閉路上の辺を 1 本取り除いても連結性は保たれる（定理 4.3）。閉路がなくなるまでこれを繰り返せば全域木が得られる。連結でないグラフは全域木を持たないが、各連結成分の全域木を合わせた\ **全域森**\ を持つ。

実際に全域木を求めるには、幅優先探索や深さ優先探索で、新しい頂点を初めて発見したときに通った辺を集めればよい。こうして得られる全域木を、それぞれ\ **幅優先探索木**\ 、\ **深さ優先探索木**\ という（第 11 章）。

ケイリーの公式
--------------

頂点に 1 から :math:`n` の番号を付けた（ラベル付きの）全域木は、完全グラフ :math:`K_n` にいくつあるだろうか。:math:`n = 3` なら 3 個、:math:`n = 4` なら 16 個である。一般には次の美しい公式が成り立つ。

.. admonition:: 定理 6.3（ケイリーの公式）

   頂点集合 :math:`\{1, 2, \ldots, n\}` 上の木の個数は :math:`n^{n-2}` である。

この公式は、木と「長さ :math:`n - 2`、各要素が 1 から :math:`n` の数列」の間に 1 対 1 の対応を作ることで証明できる。その対応が\ **プリューファー符号**\ である。以下ではプログラムに合わせて頂点を 0 から :math:`n - 1` で表す。

木からプリューファー符号を作る手順は次のとおりである。

1. 番号が最小の葉を選び、それに隣接する頂点の番号を符号の末尾に書く。
2. その葉を木から取り除く。
3. 頂点が 2 個になるまで 1, 2 を繰り返す。

:numref:`fig-ch06-prufer` の木では、葉 0, 1, 2, 5 のうち最小の 0 を取り除いて 3 を書き、続いて葉 1、葉 2 を取り除いて 3 を 2 回書く。すると頂点 3 が葉になるので、最小の葉 3 を取り除いて 4 を書く。残りは頂点 4, 5 の 2 個なので終了し、符号 :math:`(3, 3, 3, 4)` が得られる。

.. _fig-ch06-prufer:

.. graphviz::
   :caption: プリューファー符号 (3, 3, 3, 4) に対応する木
   :align: center

   graph g {

       node [shape=circle, width=0.35, fixedsize=true, fontsize=12, style=filled, fillcolor="#dbe8f5"];
       0 [pos="0,1!"]; 1 [pos="0,0!"]; 2 [pos="0,-1!"]; 3 [pos="1.2,0!"]; 4 [pos="2.4,0!"]; 5 [pos="3.6,0!"];
       0 -- 3; 1 -- 3; 2 -- 3; 3 -- 4; 4 -- 5;

各頂点が符号に現れる回数は「その頂点の次数 - 1」に等しい。葉は一度も現れない。このことを使うと、符号から木を復元できる。符号を先頭から読みながら、「まだ使っていない頂点のうち、残りの符号に現れない最小の頂点」を葉として、読んだ頂点と結べばよい。最後に残った 2 頂点を結ぶと木が完成する。

符号化と復元は互いに逆の操作であり、任意の数列が何らかの木に対応する。長さ :math:`n - 2` で各要素が :math:`n` 通りの数列は :math:`n^{n-2}` 個あるので、ケイリーの公式が得られる。サンプルコード ``spanning_tree.py`` では、すべての数列を復元して異なる木の個数を数え、公式と一致することを確かめている。

.. code-block:: text
   :linenos:

   プリューファー符号: [3, 3, 3, 4]
   復元した木: [(0, 3), (1, 3), (2, 3), (3, 4), (4, 5)]
   n = 2: 木の個数 = 1, n^(n-2) = 1
   n = 3: 木の個数 = 3, n^(n-2) = 3
   n = 4: 木の個数 = 16, n^(n-2) = 16
   n = 5: 木の個数 = 125, n^(n-2) = 125
   n = 6: 木の個数 = 1296, n^(n-2) = 1296

完全グラフに限らず、一般のグラフの全域木の個数は、第 14 章の行列木定理によって行列式として計算できる。

最小全域木
----------

重み付き連結グラフの全域木のうち、辺の重みの合計が最小のものを\ **最小全域木**\ という。いくつかの拠点を通信回線や送電線で結ぶとき、各区間の敷設費用を重みとすれば、全拠点をつなぐ最も安い配線は最小全域木になる。ほかにも、データのクラスタリング（単連結法）や、巡回セールスマン問題の近似アルゴリズム（第 7 章）などに使われる。

カット性質
~~~~~~~~~~

最小全域木のアルゴリズムの正しさは、次のカット性質に基づく。頂点集合を 2 つに分けたとき、両側にまたがる辺の集合を\ **カット**\ という。

.. admonition:: 定理 6.4（カット性質）

   重み付き連結グラフの頂点集合を空でない 2 つの集合 :math:`S` と :math:`V \setminus S` に分ける。:math:`S` と :math:`V \setminus S` を結ぶ辺のうち重みが最小のものを :math:`e` とすると、:math:`e` を含む最小全域木が存在する。

**証明**\ ：最小全域木 :math:`T` を 1 つとり、:math:`e = uv` が :math:`T` に含まれないとする（含まれていれば示すことはない）。:math:`T` に :math:`e` を加えると閉路が 1 つできる（定理 6.2 の 6）。この閉路は :math:`u \in S` から :math:`v \in V \setminus S` へ渡り、また :math:`S` に戻ってくるので、:math:`e` 以外にも :math:`S` と :math:`V \setminus S` を結ぶ辺 :math:`f` を含む。:math:`T` から :math:`f` を除いて :math:`e` を加えた :math:`T' = T - f + e` は、閉路が切れるので全域木である。:math:`e` の重みは最小なので :math:`w(e) \le w(f)` であり、:math:`T'` の重みの合計は :math:`T` 以下である。:math:`T` が最小なので :math:`T'` も最小全域木であり、:math:`e` を含む。□

このように、木の辺を 1 本入れ替えて別の木を作る操作を\ **辺の交換**\ という。辺の交換は、木に関する最適性の証明でよく使う論法である。

クラスカル法
~~~~~~~~~~~~

**クラスカル法**\ （Kruskal's algorithm）は、辺を重みの小さい順に調べ、すでに選んだ辺と閉路を作らないものだけを採用する方法である。

1. 辺を重みの小さい順に並べる。
2. 順に辺 :math:`uv` を調べ、:math:`u` と :math:`v` がまだ選んだ辺で結ばれていなければ採用する。
3. :math:`n - 1` 本採用したら終了する。

辺 :math:`uv` を採用するとき、:math:`u` を含む成分を :math:`S` とすれば、:math:`uv` は :math:`S` から出る辺のうち重みが最小である（より軽い辺はすでに調べ終わっており、採用されたか、閉路を作るとして捨てられている）。よってカット性質により、採用した辺は最小全域木の一部になる。

:numref:`fig-ch06-mst` の例では、重み 5 の辺 03 と 24、重み 6 の辺 35、重み 7 の辺 01 と 14 を順に採用する。この時点で 5 本（:math:`n - 1` 本）採用したので終了する。

「:math:`u` と :math:`v` がすでに結ばれているか」の判定には、次に述べる Union-Find を使う。辺の整列に :math:`O(m \log m)` 時間かかり、これが全体の計算量になる。

Union-Find
~~~~~~~~~~

**Union-Find**\ （素集合データ構造）は、互いに素な集合の族を管理し、次の 2 つの操作を高速に行うデータ構造である。

* ``find(x)``\ ：:math:`x` が属する集合の代表元を返す。2 要素の ``find`` の結果が等しければ同じ集合に属する。
* ``union(x, y)``\ ：:math:`x` の集合と :math:`y` の集合を併合する。

各集合を根付き木で表し、根を代表元とする。``find`` は親をたどって根を求め、``union`` は一方の根をもう一方の根の子にする。木が高くなりすぎないよう、次の 2 つの工夫をする。

* **ランクによる併合**\ ：木の高さの目安（ランク）が小さい方の根を、大きい方の根の子にする。
* **経路圧縮**\ ：``find`` でたどった頂点を、根の近くに付け替える。

この 2 つを併用すると、操作 1 回あたりの償却計算量は :math:`O(\alpha(n))` になる。:math:`\alpha` はアッカーマン関数の逆関数で、現実的なすべての :math:`n` に対して 5 以下であり、実質的には定数とみなせる。

プリム法
~~~~~~~~

**プリム法**\ （Prim's algorithm）は、1 つの頂点から始めて木を少しずつ成長させる方法である。

1. 任意の頂点を 1 つ選び、それだけからなる木を作る。
2. 木に含まれる頂点と含まれない頂点を結ぶ辺のうち、重みが最小のものを木に加える。
3. すべての頂点が木に含まれるまで 2 を繰り返す。

手順 2 で加える辺は、木の頂点集合を :math:`S` とするカットの最小の辺なので、カット性質により正しさが保証される。最小の辺を効率よく選ぶには、優先度付きキュー（Python の ``heapq``）を使う。計算量は :math:`O(m \log n)` である。

このコードでは、木に入った頂点から出る辺をすべてヒープに入れ、取り出したときに相手の頂点がすでに木に含まれていれば読み飛ばしている。:numref:`fig-ch06-mst` の例に両方の方法を適用し、NetworkX の ``nx.minimum_spanning_tree`` と比較した結果は次のとおりである。辺は（重み, 端点, 端点）の組で表している。

.. code-block:: text
   :linenos:

   クラスカル法: [(5, 0, 3), (5, 2, 4), (6, 3, 5), (7, 0, 1), (7, 1, 4)] 重み合計 = 30
   プリム法    : [(5, 0, 3), (6, 3, 5), (7, 0, 1), (7, 1, 4), (5, 4, 2)] 重み合計 = 30
   NetworkX    : 重み合計 = 30.0

2 つの方法は辺を選ぶ順序が異なるが、同じ最小全域木が得られている。重みがすべて異なるグラフでは最小全域木は一意に定まる。重みが等しい辺がある場合は、最小全域木が複数存在することがあるが、重みの合計はどれも等しい。

クラスカル法とプリム法の使い分けの目安は、疎グラフでは辺リストから直接処理できるクラスカル法、密グラフでは隣接行列を使った :math:`O(n^2)` 版のプリム法である。

まとめ
------

* 木は閉路を持たない連結グラフであり、:math:`n` 頂点の木はちょうど :math:`n - 1` 本の辺を持つ。木の特徴付けには多くの同値な言い換えがある。
* 根付き木は親子関係を持ち、多くのデータ構造の基礎になる。
* 連結グラフは必ず全域木を持つ。ラベル付きの :math:`n` 頂点の木は :math:`n^{n-2}` 個あり（ケイリーの公式）、プリューファー符号によって数列と 1 対 1 に対応する。
* 最小全域木はカット性質に基づくクラスカル法やプリム法で求められる。クラスカル法では Union-Find を使って閉路の判定を行う。
