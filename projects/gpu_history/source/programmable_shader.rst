プログラマブルシェーダの時代（2001 年〜）
=========================================

本章では、GPU がプログラム可能なプロセッサへと変わり始めた時代について述べる。この時代に導入された\ :term:`シェーダ`\ は、グラフィックスの表現力を飛躍的に高めただけでなく、GPU を描画以外の計算に使う試みのきっかけにもなった。

シェーダとは
------------

シェーダとは、グラフィックスパイプラインの特定の段階で GPU が実行する小さなプログラムである。この時代には、次の 2 種類のシェーダが導入された。

.. list-table:: プログラマブルシェーダの種類
   :header-rows: 1
   :widths: 25 75

   * - 種類
     - 役割
   * - :term:`頂点シェーダ`
     - 頂点ごとに実行され、座標変換や光源計算などの頂点処理を行う。固定機能の T&L を置き換えるもの。
   * - :term:`ピクセルシェーダ`
     - ピクセルごとに実行され、テクスチャの参照や色の計算を行う。OpenGL ではフラグメントシェーダと呼ぶ。

シェーダの導入により、プログラマは光源モデルや材質の表現を自由に記述できるようになった。固定機能パイプラインでは実現が難しかった、凹凸を擬似的に表現するバンプマッピングや、ピクセル単位の精密な光源計算などが、リアルタイムで実現できるようになった。

シェーダという考え方自体は新しいものではない。映画などのオフラインレンダリングの分野では、Pixar の RenderMan が 1980 年代末から専用のシェーディング言語を提供していた。この時代の GPU は、その考え方をリアルタイム描画に持ち込んだものといえる。

DirectX 8 と GeForce 3
----------------------

2000 年に公開された DirectX 8 は、頂点シェーダとピクセルシェーダを API の機能として定義した。DirectX は、GPU が対応すべきシェーダの機能水準を\ :term:`シェーダモデル`\ という版番号で定めており、DirectX 8 のシェーダはシェーダモデル 1.x にあたる。

2001 年に NVIDIA が発表した GeForce 3 は、DirectX 8 のシェーダに対応した最初の GPU である。GeForce 3 の頂点シェーダは、命令を組み合わせたプログラムを実行できる、真の意味でプログラマブルな処理装置であった。一方、ピクセルシェーダは命令数が非常に少なく、演算も固定小数点で行うなど、依然として固定機能に近い制約を持っていた。同年に ATI が発表した Radeon 8500 は、より柔軟なピクセルシェーダ（シェーダモデル 1.4）を備えていた。

この時代のシェーダは、GPU 固有のアセンブリ言語に近い形式で記述する必要があり、プログラムの作成は容易ではなかった。

DirectX 9 と浮動小数点演算
--------------------------

2002 年に公開された DirectX 9 は、シェーダモデル 2.0 を定義し、ピクセルシェーダでの浮動小数点演算を必須とした。それまでのピクセルシェーダは色の値を 8 ビット程度の整数で扱っていたため、計算を重ねると誤差が蓄積し、表現できる明るさの範囲も限られていた。浮動小数点演算の導入により、精度の高い計算や、現実の明るさの幅を扱う HDR（High Dynamic Range）レンダリングが可能になった。

DirectX 9 に対応した最初の GPU は、2002 年に ATI が発表した Radeon 9700 である。Radeon 9700 は 8 本のピクセルパイプラインと 256 ビットのメモリバスを備え、ピクセルシェーダを 24 ビットの浮動小数点で実行した。高い性能により、ATI が NVIDIA から性能面での主導権を奪った製品として知られる。NVIDIA が 2002 年末に発表し、2003 年に発売した GeForce FX は、16 ビットと 32 ビットの浮動小数点に対応したが、DirectX 9 のシェーダを実行した際の性能で Radeon 9700 系に及ばなかった。

2004 年には、シェーダモデル 3.0 に対応した NVIDIA の GeForce 6800 が登場した。シェーダモデル 3.0 では、シェーダ内での動的な分岐やループ、頂点シェーダからのテクスチャ参照が可能になり、シェーダは汎用のプログラムに一歩近づいた。同年には、AGP に代わる拡張バスとして PCI Express を採用したグラフィックスカードも登場した。また NVIDIA は、複数の GPU を連携させて描画性能を高める技術を、3dfx の技術名を引き継いで SLI（Scalable Link Interface）として製品化した。

シェーディング言語の登場
------------------------

シェーダが複雑になるにつれて、アセンブリ言語に近い形式で記述することは現実的ではなくなった。そこで、C 言語に似た文法でシェーダを記述できる高水準のシェーディング言語が登場した。

.. list-table:: 主なシェーディング言語
   :header-rows: 1
   :widths: 20 20 60

   * - 言語
     - 公開年
     - 概要
   * - Cg
     - 2002 年
     - NVIDIA が開発した言語。DirectX と OpenGL の両方で利用できた。
   * - HLSL
     - 2002 年
     - Microsoft が DirectX 9 とともに導入した言語。Cg と同系統の文法を持つ。
   * - GLSL
     - 2004 年
     - OpenGL 2.0 で標準となった言語。OpenGL の拡張機能としては 2003 年から利用できた。

高水準言語の登場により、シェーダの開発効率は大きく向上し、GPU のプログラミングがグラフィックスの専門家以外にも開かれていった。

GPGPU の始まり
--------------

プログラマブルシェーダと浮動小数点演算の導入によって、GPU は大量の浮動小数点演算を並列に実行できるプロセッサになった。2000 年代前半には、GPU の演算性能とメモリ帯域幅は同時代の CPU を上回るようになっており、研究者たちはこの性能を描画以外の計算に利用しようと試み始めた。このような取り組みは :term:`GPGPU`\ （General-Purpose computation on GPUs）と呼ばれるようになった。

当時の GPU には汎用計算のための API が存在しなかったため、計算をグラフィックス処理に見立てて実行する必要があった。典型的な手法は次のとおりである。

1. 入力データを\ :term:`テクスチャ`\ として GPU に転送する。
2. 出力先として、画面ではなくテクスチャを指定する（オフスクリーンレンダリング）。
3. 出力先の全体を覆う四角形を描画する。これにより、出力の各要素（ピクセル）に対してピクセルシェーダが 1 回ずつ実行される。
4. ピクセルシェーダの中で入力テクスチャを読み出し、計算結果を色として出力する。

:numref:`code-gpgpu-glsl` に、この手法で 2 つの配列の要素ごとの和を求めるピクセルシェーダの例を示す。

.. _code-gpgpu-glsl:

.. code-block:: glsl
   :caption: ピクセルシェーダによる配列の加算の例（GLSL）
   :linenos:

   uniform sampler2D array_a;  // 入力配列 A を格納したテクスチャ
   uniform sampler2D array_b;  // 入力配列 B を格納したテクスチャ

   void main()
   {
       // このピクセルに対応する配列の位置を求める
       vec2 index = gl_TexCoord[0].st;

       // 2 つの配列の要素を読み出し、和を「色」として出力する
       gl_FragColor = texture2D(array_a, index) + texture2D(array_b, index);
   }

配列の要素をテクスチャ座標で指定し（7 行目）、計算結果をピクセルの色として書き出している（10 行目）。この方法には次のような制約があった。

* 任意の位置にデータを書き込むこと（スキャッタ）ができない。各ピクセルシェーダは、自分の担当するピクセルにしか書き込めない。
* スレッド間でデータを共有したり、同期したりする手段がない。
* 浮動小数点演算の精度や丸めの仕様が GPU ごとに異なり、IEEE 754 に完全には準拠していなかった。
* 計算をグラフィックスの概念に置き換える必要があり、グラフィックス API の知識が不可欠であった。

それでも、行列演算、流体シミュレーション、画像処理など、データ並列性の高い問題で CPU を大きく上回る性能が報告された\ [Owens2007]_。2004 年には、スタンフォード大学の Ian Buck らが、GPU をストリームプロセッサとして扱うための言語 Brook を GPU 向けに実装した BrookGPU を発表した\ [Buck2004]_。BrookGPU はグラフィックス API を隠蔽し、C 言語を拡張した文法で並列計算を記述できるようにした。Buck は後に NVIDIA に移り、次章で述べる CUDA の開発を主導することになる。

プログラマブルシェーダの時代の意義
----------------------------------

この時代に GPU は、決められた処理を高速に実行する専用回路から、プログラムを実行するプロセッサへと性格を変えた。また、浮動小数点演算の導入と高水準言語の登場により、GPU の計算能力を描画以外の分野で活用する道が開かれた。

一方で、頂点シェーダとピクセルシェーダは別々のハードウェアとして実装されていたため、処理の内容によってはどちらか一方だけが忙しく、もう一方が遊んでしまうという非効率が生じていた。また、GPGPU はグラフィックス API を経由する不自然なプログラミングを強いられていた。次章で述べる統合シェーダアーキテクチャと CUDA は、この 2 つの問題を同時に解決するものであった。
