GPU を理解するための基礎知識
============================

本章では、後続の章で繰り返し登場する概念をまとめて説明する。歴史の記述を読む際に用語や仕組みが分からなくなったときは、本章に戻って確認してほしい。

リアルタイム 3D グラフィックスの処理の流れ
------------------------------------------

GPU はもともと、3D 空間に置かれた物体を 2D の画面に描画する処理を高速化するために生まれた。現在のゲームなどで使われるリアルタイム 3D グラフィックスの多くは、:term:`ラスタライズ`\ と呼ばれる方式で描画する。物体の表面を三角形（:term:`ポリゴン`）の集まりで表現し、各三角形を画面上のピクセルに変換して色を決める方式である。

この処理は、:numref:`fig-pipeline` に示す一連の段階で構成される。この流れを\ :term:`グラフィックスパイプライン`\ と呼ぶ。

.. _fig-pipeline:

.. graphviz::
   :caption: グラフィックスパイプラインの概略
   :align: center

   digraph pipeline {
       rankdir=TB;
       ranksep=0.25;
       node [shape=box, style="rounded,filled", fillcolor="#eef3fb", color="#2a6fdb", fontsize=12, width=4];
       edge [color="#59636e"];
       input [label="頂点データ（座標・法線など）", shape=note, fillcolor="#ffffff", color="#59636e"];
       vertex [label="頂点処理：座標変換・光源計算"];
       setup [label="プリミティブ処理：三角形の組み立て・クリッピング"];
       raster [label="ラスタライズ：三角形をピクセルに分解"];
       pixel [label="ピクセル処理：テクスチャ参照・色の計算"];
       output [label="出力合成：深度テスト・ブレンド"];
       fb [label="フレームバッファ", shape=cylinder, fillcolor="#ffffff", color="#59636e"];
       input -> vertex -> setup -> raster -> pixel -> output -> fb;
   }

各段階の役割は次のとおりである。

.. list-table:: グラフィックスパイプラインの各段階
   :header-rows: 1
   :widths: 20 80

   * - 段階
     - 役割
   * - 頂点処理
     - 三角形の頂点の座標を、物体ごとの座標系から画面上の座標系へ変換する。頂点ごとに光の当たり方を計算することもある。座標変換（Transform）と光源計算（Lighting）を合わせて :term:`T&L` と呼ぶ。
   * - プリミティブ処理
     - 頂点を三角形などの図形（プリミティブ）に組み立て、画面外にはみ出した部分を切り取る（クリッピング）。
   * - ラスタライズ
     - 三角形が覆う画面上のピクセルを求め、頂点の属性（色やテクスチャ座標など）をピクセルごとに補間する。
   * - ピクセル処理
     - ピクセルごとに最終的な色を計算する。画像を表面に貼り付ける\ :term:`テクスチャ`\ マッピングもこの段階で行う。OpenGL ではこの段階をフラグメント処理と呼ぶ。
   * - 出力合成
     - 奥行き（深度）を比較して手前の物体だけを残したり、半透明の色を合成したりして、結果を\ :term:`フレームバッファ`\ に書き込む。

座標変換は、頂点の座標を同次座標 :math:`\mathbf{v} = (x, y, z, 1)^\top` で表し、:math:`4 \times 4` の行列を掛けることで行う。物体の配置を表すモデル行列 :math:`M`、視点の位置と向きを表すビュー行列 :math:`V`、遠近感を表す射影行列 :math:`P` を用いると、変換後の座標 :math:`\mathbf{v}'` は次の式で求められる。

.. math::

   \mathbf{v}' = P \, V \, M \, \mathbf{v}

頂点 1 つあたりの計算量は小さいが、1 フレームあたりの頂点数は数十万から数百万に達する。

ここで重要なのは、この処理には膨大な量の\ **独立した**\ 計算が含まれるという点である。たとえば 1920 × 1080 ピクセルの画面を毎秒 60 回描き換える場合、1 秒あたりに色を決めるピクセルの数は次のようになる。

.. math::

   1920 \times 1080 \times 60 = 124{,}416{,}000

実際には 1 ピクセルに複数の三角形が重なるため、計算量はさらに大きい。一方、あるピクセルの色の計算は、原則として隣のピクセルの計算結果に依存しない。頂点処理も同様である。このように、同じ種類の処理を大量のデータに対して独立に適用できる性質を\ :term:`データ並列性`\ と呼ぶ。GPU の歴史は、このデータ並列性をハードウェアでいかに効率よく処理するかを追求してきた歴史であるといえる。

CPU と GPU の設計思想の違い
---------------------------

CPU と GPU はどちらもプロセッサであるが、最適化の目標が異なる（:numref:`fig-cpu-gpu`）。

CPU は、1 つの処理の流れ（スレッド）をできるだけ短い時間で終えること、すなわち\ :term:`レイテンシ`\ の短縮を重視して設計されている。そのため、分岐予測やアウトオブオーダー実行といった複雑な制御回路と、メモリアクセスの待ち時間を隠すための大容量キャッシュに多くのチップ面積を割く。

GPU は、単位時間あたりに処理できる仕事の総量、すなわち\ :term:`スループット`\ を重視して設計されている。個々の演算器は単純にし、その代わりに大量の演算器を並べる。メモリアクセスには数百サイクルの待ち時間がかかるが、GPU はこれを大容量キャッシュではなく、大量のスレッドを用意しておき、待ちが発生したスレッドの代わりに別のスレッドを実行することで隠す。この方式をレイテンシ隠蔽と呼ぶ。スレッドの切り替えを低コストで行うため、GPU は多数のスレッドの状態（レジスタ）を同時にチップ上に保持する大容量のレジスタファイルを持つ。

この違いから、逐次的で分岐の多い処理は CPU が得意とし、データ並列性の高い大量の計算は GPU が得意とする。現在のシステムでは、CPU が全体の制御を担い、データ並列性の高い部分を GPU に任せる構成が一般的である。

SIMD と SIMT
------------

多数の演算器を少ない制御回路で動かすため、GPU は 1 つの命令で複数のデータを同時に処理する。この方式を :term:`SIMD`\ （Single Instruction, Multiple Data）と呼ぶ。

現在の GPU の多くは、プログラマに対しては各スレッドが独立したプログラムを実行しているように見せつつ、ハードウェアの内部では一定数のスレッドをまとめて 1 つの命令で実行する。NVIDIA はこの方式を :term:`SIMT`\ （Single Instruction, Multiple Threads）と呼ぶ。まとめて実行されるスレッドの集団を、NVIDIA は\ :term:`ワープ`\ （32 スレッド）、AMD は\ :term:`ウェーブフロント`\ （64 スレッドまたは 32 スレッド）と呼ぶ。

SIMT では、同じワープ内のスレッドが条件分岐で異なる方向に進むと、両方の経路を順番に実行し、該当しないスレッドを無効化する。この現象を分岐発散（ダイバージェンス）と呼び、性能低下の原因になる。GPU 向けのプログラムで分岐をなるべく揃えることが推奨されるのはこのためである。

性能を表す指標
--------------

GPU の性能を比較する際には、主に演算性能とメモリ帯域幅の 2 つの指標が用いられる。

演算性能
~~~~~~~~

演算性能は、1 秒あたりに実行できる浮動小数点演算の回数である :term:`FLOPS` で表す。理論上の最大性能（ピーク性能）は次の式で求められる。

.. math::

   \text{ピーク性能 [FLOPS]} = \text{演算器の数} \times \text{クロック周波数 [Hz]} \times \text{1 サイクルあたりの演算回数}

GPU の演算器の多くは、:math:`a \times b + c` を 1 命令で計算する積和演算（FMA）に対応しており、これを 2 回の演算として数える。たとえば 2006 年の GeForce 8800 GTX は、128 個の演算器が 1.35 GHz で動作し、1 サイクルあたり積和演算を 1 回（2 演算）実行できるため、単精度のピーク性能は次のようになる。

.. math::

   128 \times 1.35 \times 10^{9} \times 2 = 345.6 \times 10^{9} \ \text{FLOPS} = 345.6 \ \text{GFLOPS}

演算性能は数値の精度によって大きく異なる。64 ビットの倍精度（FP64）、32 ビットの単精度（FP32）、16 ビットの半精度（FP16）など、精度が低いほど 1 つの演算に必要な回路が小さく、データ量も少ないため、高い性能が得られる。どの精度の性能を重視するかは時代と用途によって変わってきた（「:ref:`deep_learning`」を参照）。

メモリ帯域幅
~~~~~~~~~~~~

メモリ帯域幅は、1 秒あたりにメモリとの間で転送できるデータ量である。GPU に直結されたメモリ（:term:`VRAM`）の帯域幅は、次の式で求められる。

.. math::

   \text{帯域幅 [B/s]} = \frac{\text{メモリバス幅 [bit]}}{8} \times \text{1 ピンあたりのデータ転送速度 [転送/s]}

GeForce 8800 GTX は 384 ビットのメモリバスを持ち、1 ピンあたり毎秒 18 億回（1.8 GT/s）のデータ転送を行うため、帯域幅は次のようになる。

.. math::

   \frac{384}{8} \times 1.8 \times 10^{9} = 86.4 \times 10^{9} \ \text{B/s} = 86.4 \ \text{GB/s}

演算強度とルーフラインモデル
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

ある処理が演算性能とメモリ帯域幅のどちらで制約されるかは、メモリから読み書きする 1 バイトあたりの演算回数で判断できる。これを\ :term:`演算強度`\ （単位は FLOP/B）と呼ぶ。演算強度を :math:`I`、ピーク性能を :math:`P_{\text{peak}}`、メモリ帯域幅を :math:`B` とすると、達成できる性能 :math:`P` の上限は次の式で表される。この考え方をルーフラインモデルと呼ぶ\ [Williams2009]_。

.. math::

   P = \min \left( P_{\text{peak}}, \; B \times I \right)

GeForce 8800 GTX の場合、:math:`P_{\text{peak}} / B = 345.6 / 86.4 = 4` であるため、演算強度が 4 FLOP/B より低い処理はメモリ帯域幅で、高い処理は演算性能で上限が決まる。後の章で見るように、GPU の演算性能はメモリ帯域幅よりも速いペースで向上してきたため、この境界は年々高くなっている。メモリの技術が GPU の歴史の中で重要な位置を占めるのはこのためである（「:ref:`trends`」を参照）。

各社の用語の対応
----------------

GPU のハードウェアやプログラミングモデルの用語は、メーカーや API によって異なる。本書では原則として NVIDIA の用語を用いるが、:numref:`table-terms` に主な用語の対応を示す。

.. _table-terms:

.. list-table:: 主な用語の対応
   :header-rows: 1
   :widths: 25 25 25 25

   * - 概念
     - NVIDIA（CUDA）
     - AMD（ROCm / HIP）
     - OpenCL
   * - 演算器をまとめた処理単位
     - SM（Streaming Multiprocessor）
     - CU（Compute Unit）
     - Compute Unit
   * - 1 命令で同時に実行されるスレッドの集団
     - ワープ（warp）
     - ウェーブフロント（wavefront）
     - サブグループ（sub-group）
   * - 協調して動作するスレッドの集団
     - スレッドブロック
     - ワークグループ
     - ワークグループ
   * - 処理単位内で共有する高速メモリ
     - 共有メモリ（shared memory）
     - LDS（Local Data Share）
     - ローカルメモリ
   * - GPU に接続された大容量メモリ
     - グローバルメモリ
     - グローバルメモリ
     - グローバルメモリ

なお、NVIDIA の「CUDA コア」や AMD の「ストリームプロセッサ」は、いずれも単精度の演算器 1 つ分を指すマーケティング上の呼称である。CPU の「コア」とは意味が異なり、独立した命令の流れを持つわけではない点に注意が必要である。
