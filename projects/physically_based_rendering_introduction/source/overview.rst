レンダリングの全体像
====================

本章では、個々の理論に入る前に、画像が作られるまでの流れを概観する。

画像ができるまで
----------------

レンダリングの入力となるシーンは、主に次の 4 つの要素で構成される。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 要素
     - 内容
   * - 形状
     - 物体の形。三角形の集まり（ポリゴンメッシュ）で表すことが多い。本書のサンプルコードでは球と長方形だけを扱う。
   * - 材質
     - 物体の表面が光をどのように反射・透過するか。PBR では BRDF（「:doc:`brdf`」で説明する）で表す。
   * - 光源
     - 光を放つもの。電球のような点光源、蛍光灯のような面光源、空全体からの光（環境光）などがある。
   * - カメラ
     - シーンをどこから、どの向きに、どの画角で見るか。

レンダリングとは、カメラの各画素に届く光の量を計算する処理である。画素に届く光は、光源から出て、多くの場合は物体の表面で反射し、最後にカメラに入ったものである。この過程の概念図を\ :numref:`fig-render-flow` に示す。

.. graphviz::
   :name: fig-render-flow
   :caption: 光源からカメラに光が届くまでの概念図
   :align: center

   digraph flow {
     rankdir=LR;
     node [shape=box, style="rounded,filled", fillcolor="#eef3fb", fontsize=12];
     edge [fontsize=10];
     light [label="光源"];
     s1 [label="物体の表面\n（反射・屈折）"];
     s2 [label="別の物体の表面\n（反射・屈折）"];

     light -> s1 [label="直接光"];
     s1 -> s2 [label="間接光"];
     s2 -> cam;
     s1 -> cam [style=dashed];
   }

ラスタライズとレイトレーシング
------------------------------

画素に届く光を計算する方法は、大きく 2 つに分けられる。

ラスタライズ（rasterization）
   物体を構成する三角形を 1 つずつ画面に投影し、その三角形が覆う画素の色を計算する方法である。GPU はこの処理を非常に高速に実行できるように作られており、ゲームなどのリアルタイム用途で主に使われる。各画素では、その画素に見えている表面の情報しか得られないため、映り込みや影、周囲からの照り返しなどを正確に扱うには工夫が必要になる。

レイトレーシング（ray tracing）
   画素ごとに、カメラから半直線（レイ）を飛ばし、レイがシーン中のどの物体に当たるかを調べる方法である。当たった点からさらに光源や他の物体の方向へレイを飛ばすことで、影、映り込み、間接光などを自然に扱える。計算量は多いが、物理的に正確な画像を得やすいため、映画の CG や建築の可視化などで使われてきた。近年は GPU のハードウェア支援により、ゲームでも部分的に使われるようになっている。

PBR はどちらの方法とも組み合わせられる考え方であり、特定の描画方法を指すものではない。本書では、光の伝わり方を素直に表現できるレイトレーシングを中心に説明し、ラスタライズにおける PBR の実際は「:doc:`practical_pbr`」で扱う。

直接照明と大域照明
------------------

光源から出た光が 1 回だけ反射してカメラに届く成分を直接照明（direct illumination）と呼ぶ。これに対して、複数の物体の間で反射を繰り返してから届く成分を間接照明（indirect illumination）と呼ぶ。

直接照明だけを計算する方法を局所照明（local illumination）、間接照明まで含めて計算する方法を大域照明（global illumination）と呼ぶ。大域照明を扱うと、次のような現象が再現される。

* 白い壁の近くに赤い物体を置くと、壁がほんのり赤く色づく（カラーブリーディング）。
* 光源から直接見えない場所も、周囲からの反射光で真っ暗にはならない。
* 部屋の隅や物体同士が接する部分は、光が届きにくいため少し暗くなる。

本書のトップページの画像では、左右の壁の赤と緑で床や白い球がほんのり色づいている様子や、光源のすぐ横の天井が、直接光は届かないのに照らされている様子が確認できる。これらはすべて間接照明の効果である。

本書の道筋
----------

物理的に正しい画像を計算するには、次の 3 つの問いに答える必要がある。

1. 光の「量」をどのように表すか（「:doc:`light_and_color`」「:doc:`radiometry`」）
2. 表面に当たった光はどの方向にどれだけ反射されるか（「:doc:`light_matter`」「:doc:`brdf`」「:doc:`microfacet`」）
3. シーン全体で光はどのように行き交い、その結果カメラにはどれだけの光が届くか（「:doc:`rendering_equation`」「:doc:`monte_carlo`」「:doc:`path_tracing`」）

次章から、これらの問いに順に答えていく。
