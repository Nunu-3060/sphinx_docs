========================
セルオートマトンの理論
========================

セルオートマトンとは
======================

セルオートマトン（Cellular Automaton）とは、格子状に並んだ「セル」の集合と、各セルの状態を更新するための「ルール」からなる離散的な計算モデルである。各セルは有限個の状態（多くの場合 0 か 1 の 2 状態）のいずれかを取り、時間ステップごとに、あらかじめ定められたルールに従ってすべてのセルが同時に（同期的に）状態を更新する。

セルオートマトンは以下の要素によって定義される。

* **格子（lattice）**: セルが配置される空間の構造。1 次元・2 次元格子がよく用いられる。
* **近傍（neighbourhood）**: 各セルの状態更新に影響を与える周囲のセルの集合。
* **状態（state）**: 各セルが取り得る値の集合。
* **遷移規則（rule）**: 現在の自セルの状態と近傍の状態から、次の状態を決定する規則。
* **境界条件（boundary condition）**: 格子の端をどのように扱うかの規則。

ライフゲームのルール
======================

ライフゲーム（Conway's Game of Life）は、2 次元格子上で定義されるセルオートマトンの代表例である。各セルは「生 (1)」または「死 (0)」のいずれかの状態を取り、以下のルールに従って次の世代の状態が決定される。

* **誕生**: 死んでいるセルの周囲にちょうど 3 つの生きたセルがあれば、そのセルは次の世代で誕生する。
* **生存**: 生きているセルの周囲に 2 つまたは 3 つの生きたセルがあれば、そのセルは次の世代でも生存する。
* **過疎・過密による死**: 生きているセルの周囲の生きたセルが 1 つ以下、または 4 つ以上であれば、そのセルは次の世代で死ぬ。

このルールは、生存する近傍セル数の集合を :math:`S`、誕生する近傍セル数の集合を :math:`B` として :math:`B3/S23` のように表記されることが多い。本資料で扱う実装では、誕生条件・生存条件をそれぞれリストとして与えることで、標準ルール以外の任意のライフゲーム系ルールも表現できるようにしている（詳細は :doc:`core` を参照）。

ムーア近傍
==========

ライフゲームでは、あるセルの状態更新に影響する近傍として、上下左右および斜め方向を含む 8 近傍（**ムーア近傍**, Moore neighbourhood）が用いられる。すなわち、格子上の座標 :math:`(i, j)` にあるセルの近傍は

.. math::

   \{(i + di,\ j + dj) \mid di, dj \in \{-1, 0, 1\},\ (di, dj) \neq (0, 0)\}

の 8 マスである。これに対し、斜め方向を含まない上下左右 4 近傍は **フォン・ノイマン近傍** （von Neumann neighbourhood）と呼ばれる。

境界条件
========

格子の端に位置するセルは近傍の一部が格子の外側にはみ出すため、これをどう扱うかを別途定める必要がある。代表的な境界条件には以下のようなものがある。

* **周期境界条件（トーラス境界）**: 格子の端を反対側の端に接続する。上端の外側は下端、左端の外側は右端とみなすことで、格子全体がトーラス（ドーナツ）状の位相を持つことになる。
* **固定境界条件**: 格子の外側を常に「死」（あるいは特定の固定値）とみなす。

本資料の実装では、NumPy の ``np.roll`` を用いて格子全体をシフトさせることで周期境界条件による近傍計算を実現している。また、固定境界条件を再現したい場合には、各世代の更新後に最外周のセルを強制的に 0 にすることで、実質的に外側が常に死んでいる状態を模している（詳細は :doc:`core` を参照）。

同期更新
========

ライフゲームでは、全セルの状態を同時に（他のセルの更新結果を参照せずに）次の状態へ遷移させる **同期更新** が用いられる。これは、あるセルを更新した結果を別のセルの更新に使ってしまう「逐次更新」とは異なる。実装上は、更新前の格子全体から近傍セル数を計算し、その結果をもとに新しい格子を作成してから、最後にまとめて置き換えることで同期更新を実現する。
