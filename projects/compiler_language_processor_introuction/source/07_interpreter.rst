################################################################
第 7 章 インタプリタ
################################################################

ここまでで、Tiny のプログラムを型情報付きの抽象構文木に変換できるようになりました。この章では、抽象構文木を直接たどって実行する\ :term:`木構造インタプリタ`\ を作ります。これで Tiny のプログラムを実際に動かせるようになります。

木構造インタプリタ
================================================================

木構造インタプリタは、抽象構文木の各ノードに対して「そのノードを実行（評価）する」処理を再帰的に適用します。たとえば ``Binary("+", left, right)`` を評価するには、``left`` と ``right`` をそれぞれ評価し、得られた 2 つの値を足します。構造が単純で、言語の意味をそのままプログラムとして書き下せるため、言語の試作や、意味の定義を確かめる用途に向いています。

インタプリタが扱う対象は、値を返す「式」と、値を返さずに状態を変える「文」の 2 種類です。本書の実装では、式は ``eval`` メソッドで評価し、文は ``exec_stmt`` メソッドで実行します。

================================================================

================================================================

``exec_stmt`` は、文の種類に応じて処理を分けます。``if`` 文と ``while`` 文は、Tiny の ``if`` と ``while`` を Python の ``if`` と ``while`` でそのまま実行しています。

``return`` 文の扱いには工夫が必要です。``return`` は、関数の本体のどれほど深い位置にあっても、関数の呼び出し元まで一気に戻らなければなりません。そこで、``return`` 文を実行したら戻り値を持った例外 ``ReturnSignal`` を送出し、関数呼び出しの処理でそれを捕まえます。Python の例外の「呼び出しの途中を飛び越えて戻る」性質を利用しているわけです。

   :language: python
   :linenos:
   :lineno-match:
   :pyobject: Interpreter.call_function
   :caption: tiny_interp.py（関数呼び出し）

関数を呼び出すたびに新しい環境を作り、引数を定義しています。呼び出し元の環境は参照しないので、関数の中から呼び出し元の局所変数は見えません。再帰呼び出しでも、呼び出しごとに別の環境ができるため、各呼び出しの ``n`` は互いに干渉しません。

``&&`` と ``||`` は、ほかの二項演算子より前のパターンで処理しています。Python の ``and`` と ``or`` は短絡評価を行うので、Tiny の ``&&`` と ``||`` の短絡評価がそのまま実現できます。ほかの二項演算子と同じように両辺を先に評価してしまうと、``i < len(a) && a[i] > 0`` のような式で範囲外アクセスのエラーが起きてしまいます。

木構造インタプリタの長所と短所
================================================================

木構造インタプリタは実装が簡単ですが、実行速度の面では不利です。

* ノードを 1 つ評価するたびに、ノードの種類による分岐、属性の参照、再帰呼び出しが起こります。``s = s + i`` という単純な文でも、多数の Python の関数呼び出しが発生します。
* 変数を参照するたびに、環境の連鎖を名前でたどって探します。変数の位置はコンパイル時に分かっているにもかかわらず、実行時に毎回探しています。
* ループの中の式は、実行のたびに同じ解析（ノードの種類の判定など）を繰り返します。

これらの無駄を省くには、実行前にプログラムをより実行しやすい形に変換しておくのが効果的です。:doc:`第 8 章 <08_ir>`\ では最適化しやすい形である中間表現に、:doc:`第 10 章 <10_vm>`\ では実行しやすい形であるバイトコードに変換します。

まとめ
================================================================

* 木構造インタプリタは、抽象構文木をたどりながら式を評価し、文を実行します。
* 変数の値は環境で管理します。環境はブロックや関数呼び出しごとに作り、外側の環境への参照を持ちます。
* ``return`` 文は例外を使って関数の呼び出し元まで戻します。
* 演算の意味を実行時ライブラリにまとめておくと、複数の実行方式で同じ結果を保証しやすくなります。
* 木構造インタプリタは簡単に作れますが、実行時の無駄が多くなります。
