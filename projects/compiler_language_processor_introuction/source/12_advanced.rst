JIT コンパイル
================================================================

:term:`JIT コンパイル`\ （Just-In-Time コンパイル）は、プログラムの実行中に機械語を生成する方式です。インタプリタで実行しながら、頻繁に実行される関数やループ（ホットスポット）を見つけ、その部分だけを機械語にコンパイルします。

JIT コンパイルには、事前のコンパイル（AOT コンパイル）にはない利点があります。実行時に観測した情報を最適化に使えることです。たとえば Python の ``a + b`` は、``a`` と ``b`` の型によって整数の加算にも文字列の連結にもなりますが、実行時に「この ``+`` にはいつも整数が来る」と分かれば、整数の加算の機械語を生成できます。予想が外れた場合に備えて型の検査を残し、外れたらインタプリタに戻ります（脱最適化）。JavaScript の V8 や Java の HotSpot は、このような方法で高い性能を実現しています。

CPython も 3.13 から実験的な JIT コンパイラを備えています [PEP744]_。あらかじめ用意した機械語の断片（テンプレート）をつなぎ合わせ、アドレスなどの穴を埋めて機械語を作る「コピー & パッチ」という方式で、機械語の生成を高速に行います。

LLVM の利用
================================================================

本書では IR、最適化、コード生成をすべて自作しましたが、実用的な言語を作る場合は、既存のコンパイラ基盤を使うのが一般的です。代表的なものが :term:`LLVM` です。フロントエンドが LLVM IR を生成すれば、LLVM が高度な最適化と多数の CPU 向けのコード生成を行ってくれます。

LLVM IR は、本書の IR と同じく SSA 形式の三番地コードです。関数 ``sum`` を LLVM IR で書くと、たとえば次のようになります。本書の IR と見比べてみてください。

.. code-block:: llvm
   :linenos:

   define i64 @sum(i64 %n) {
   entry:
     br label %cond

   cond:
     %s = phi i64 [ 0, %entry ], [ %s.next, %body ]
     %i = phi i64 [ 1, %entry ], [ %i.next, %body ]
     %c = icmp sle i64 %i, %n
     br i1 %c, label %body, label %end

   body:
     %s.next = add i64 %s, %i
     %i.next = add i64 %i, 1
     br label %cond

   end:
     ret i64 %s
   }

LLVM IR には型があり（``i64`` は 64 ビット整数、``i1`` は真偽値）、基本ブロック、φ 関数、条件分岐の構造は本書の IR とほぼ同じです。Python からは llvmlite などのライブラリを使って LLVM IR を生成し、JIT コンパイルして実行できます。

構文解析器生成系と PEG
================================================================

本書では構文解析器を手で書きましたが、文法の定義から構文解析器を自動生成する\ :term:`構文解析器生成系`\ も広く使われています。

.. list-table::
   :header-rows: 1
   :widths: 25 25 50

   * - ツール
     - 方式
     - 特徴
   * - yacc、Bison
     - LALR(1)
     - C 言語向けの古典的なツールで、多くの言語処理系で使われてきた
   * - ANTLR
     - ALL(*)
     - Java、Python など多くの言語に対応した構文解析器を生成する
   * - Lark
     - Earley、LALR(1)
     - Python のライブラリで、文法を書くだけですぐに使える
   * - pegen
     - PEG
     - CPython の構文解析器の生成に使われている

文法を宣言的に書けることや、文法の誤り（曖昧さなど）を生成系が検出してくれることが利点です。一方、分かりやすいエラーメッセージを出すことや、エラー回復を細かく制御することは、手書きの構文解析器のほうが得意です。

言語サーバ
================================================================

現代のプログラミング言語では、コンパイラだけでなく、エディタでの補完、定義へのジャンプ、エラーの即時表示といった開発支援の機能が重視されています。これらの機能をエディタに依存しない形で提供するための通信規約が LSP（Language Server Protocol）です [LSP]_。言語ごとに 1 つの\ :term:`言語サーバ`\ を作れば、LSP に対応した多くのエディタで同じ機能を使えます。

言語サーバは、コンパイラのフロントエンド（字句解析、構文解析、意味解析）を再利用して作ります。ただし、編集途中の不完全なプログラムを扱う必要があるため、エラー回復の能力が特に重要になります。また、キー入力のたびに解析し直すので、変更された部分だけを解析し直す差分解析の工夫も必要です。

セルフホスティング
================================================================

ある言語のコンパイラを、その言語自身で書くことを\ :term:`セルフホスティング`\ と呼びます。C コンパイラの GCC は C（現在は C++）で、Rust のコンパイラは Rust で、Go のコンパイラは Go で書かれています。最初のコンパイラは別の言語で書く必要があり、そのコンパイラで自分自身をコンパイルできるようになるまでの過程をブートストラップと呼びます。

セルフホスティングは、言語が実用的なプログラムを書けるほど成熟したことの証になるとともに、コンパイラの開発者が自分の言語を日常的に使うことで、言語の問題点に気付きやすくなるという利点があります。

演習課題
================================================================

本書の Tiny 処理系を拡張して、理解を深めてみましょう。多くの課題では、字句解析から仮想マシンまでの複数の段階に手を入れる必要があります。変更後は ``test_tiny.py`` を実行して、すべての実行方式の結果が一致することを確かめてください。

#. ``for`` 文、``break`` 文、``continue`` 文を追加してください。``break`` は IR では「ループの出口のブロックへの ``jump``」になります。
#. 浮動小数点数の型 ``float`` を追加してください。整数との混在した演算をどう扱うか（暗黙の変換を許すか）も決める必要があります。
#. 意味解析器が、最初のエラーで止まらずに複数のエラーを報告するようにしてください。
#. 最適化器に、ループ不変式の移動を追加してください。ループを見つけるには、辺の行き先のブロックが辺の出発元のブロックを支配しているような辺（後退辺、back edge）を探します。
#. 線形走査法にコピーの合併を追加し、関数 ``sum`` のスピルとコピー命令がどれだけ減るかを確かめてください。
#. 関数を値として扱えるようにし、クロージャを追加してください。:doc:`第 6 章 <06_semantic>`\ で紹介した自由変数を、どのように実行時に保持するかが課題になります。

さらに学ぶために
================================================================

本書の内容をさらに深く学ぶための資料を\ :doc:`付録 C <appendix_c_references>` に挙げました。目的別に、次の順で読むことをお勧めします。

* インタプリタを作りながら言語の実装を学びたい場合は、[Nystrom2021]_ が最適です。木構造インタプリタとバイトコード仮想マシンの両方を、一から丁寧に作ります。
* コンパイラの理論を体系的に学びたい場合は、[Aho2006]_ が定番の教科書です。字句解析と構文解析の理論が特に詳しく書かれています。
* 最適化とコード生成を深く学びたい場合は、[Cooper2022]_ や [Appel1998]_ を読むとよいでしょう。SSA 形式、データフロー解析、レジスタ割り当てが詳しく解説されています。
* 実在する処理系のしくみを知りたい場合は、CPython のソースコードや LLVM の文書を読むのが近道です。本書で学んだ概念の多くが、そのまま使われていることが分かるはずです。

まとめ
================================================================

* JIT コンパイルは、実行時の情報を使って最適化した機械語を生成します。
* 実用的な言語の実装では、LLVM のようなコンパイラ基盤や構文解析器生成系を活用できます。
* 言語サーバは、コンパイラのフロントエンドを開発支援に応用したものです。
* 本書の Tiny 処理系を拡張することで、各段階の理解をさらに深められます。
