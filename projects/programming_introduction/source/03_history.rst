コンピュータとプログラミングの歴史
==================================

現在のプログラミング言語や開発手法は、ある日突然できあがったものではない。それぞれの時代に直面した問題を解決するために生まれ、積み重なってきたものである。この章では、プログラミングの考え方が形づくられた経緯を概観する。年号や人名を覚えることが目的ではない。「なぜ今のような書き方になっているのか」を理解する手がかりとして読んでほしい。

プログラムという考え方の誕生
----------------------------

機械に手順を与えるという考え方は、電子式のコンピュータより前から存在した。1801 年にジョゼフ・マリー・ジャカールが発明したジャカード織機は、穴を開けたカードの並びによって織物の模様を制御した。カードを差し替えれば、機械を作り直さずに別の模様を織ることができた。

1830 年代には、チャールズ・バベッジが、計算の手順をパンチカードで与える汎用の機械式計算機「解析機関」を設計した。解析機関は完成しなかったが、エイダ・ラブレスは 1843 年に発表した解析機関の解説の中で、ベルヌーイ数を計算する手順を示した。これは、世界最初のプログラムと呼ばれることがある。

計算できることの理論
--------------------

1936 年、数学者アラン・チューリングは、紙テープ上の記号を読み書きするだけの仮想的な機械（チューリングマシン）を考案し、「機械的な手順で計算できるとはどういうことか」を数学的に定義した\ [Turing1936]_。現在のプログラミング言語の多くは、原理的にはチューリングマシンと同じ範囲の計算を表現できる。この性質をチューリング完全と呼ぶ。

電子式コンピュータとプログラム内蔵方式
--------------------------------------

1940 年代になると、真空管を使った電子式のコンピュータが作られた。1946 年に公開された ENIAC はその代表である。ENIAC では、計算の手順を変えるたびに、配線やスイッチを人手で組み替える必要があった。

この問題を解決したのが、:doc:`02_how_computers_work`\ で述べた\ :term:`プログラム内蔵方式`\ である。プログラムをデータと同じくメモリに格納すれば、配線を変えずにプログラムを入れ替えられる。この方式は、1945 年にジョン・フォン・ノイマンがまとめた EDVAC に関する報告書の草稿で広く知られるようになった\ [Neumann1945]_。1948 年には英国マンチェスター大学の試作機 Manchester Baby が、1949 年には英国ケンブリッジ大学の EDSAC が、メモリに格納したプログラムの実行に成功した。

機械語からアセンブリ言語へ
--------------------------

初期のプログラマーは、:term:`機械語`\ を数値の列として直接書いていた。数値の列は人間には読みにくく、誤りも起こりやすい。そこで、``ADD`` や ``LOAD`` のような短い記号で命令を書き、それを機械語に変換する\ :term:`アセンブリ言語`\ が使われるようになった。これは、人間にとって扱いやすい表現と、機械が実行する表現とを分けるという考え方の始まりである。

高水準言語の登場
----------------

アセンブリ言語は機械語と 1 対 1 に対応するため、CPU の種類ごとに書き直す必要があり、数式のような処理を書くにも多くの命令を並べる必要があった。1950 年代後半になると、人間の考え方に近い形で処理を書ける\ :term:`高水準言語`\ が登場した。

.. list-table::
   :header-rows: 1
   :widths: 15 20 65

   * - 年
     - 言語
     - 特徴
   * - 1957
     - FORTRAN
     - ジョン・バッカスらが IBM で開発した。数式をそのまま書ける科学技術計算向けの言語であり、:term:`コンパイラ`\ によって効率のよい機械語を生成できることを示した。
   * - 1958
     - LISP
     - ジョン・マッカーシーが考案した。リストを基本のデータ構造とし、関数型プログラミングの源流となった。
   * - 1959
     - COBOL
     - 事務処理向けの言語。英語に近い記述を特徴とし、現在も金融などの基幹システムで使われている。

構造化プログラミング
--------------------

1960 年代になると、コンピュータの性能が向上し、ソフトウェアは大規模になった。その一方で、開発の遅延や品質の低下が深刻になり、「ソフトウェア危機」と呼ばれた。1968 年に NATO が開催した会議では、ソフトウェアの開発を工学として扱う「ソフトウェア工学」という言葉が用いられた。

同じ頃、命令の実行位置を任意に飛ばす ``goto`` 文の多用が、プログラムを理解しにくくしていることが問題になった。1966 年、コラド・ベームとジュゼッペ・ヤコピーニは、どのような手順も「順次」「分岐」「反復」の 3 つの構造の組み合わせで表せることを示した\ [BohmJacopini1966]_。1968 年には、エドガー・ダイクストラが ``goto`` 文の弊害を指摘する書簡を発表した\ [Dijkstra1968]_。これらを背景に、3 つの構造でプログラムを組み立てる\ :term:`構造化プログラミング`\ が広まった。この 3 つの構造は、:doc:`05_basic_elements`\ で扱う\ :term:`制御構造`\ そのものである。

1972 年にはデニス・リッチーがベル研究所で C 言語を開発した。C 言語は UNIX の開発に使われ、高水準言語でありながらハードウェアに近い処理も書けることから、OS や組み込みソフトウェアの分野で広く使われるようになった。

オブジェクト指向
----------------

ソフトウェアがさらに大規模になると、データとそれを操作する手続きをまとめて部品として扱う\ :term:`オブジェクト指向プログラミング`\ が注目された。1967 年の Simula で原型が生まれ、1970 年代にアラン・ケイらが開発した Smalltalk で考え方が確立した。1980 年代には C 言語を拡張した C++ が、1995 年には Java が登場し、オブジェクト指向は業務システムの開発で主流になった。

現在へ
------

1990 年代以降は、インターネットの普及とともに、開発の効率を重視した言語が広く使われるようになった。1991 年にはグイド・ヴァンロッサムが Python を公開し、1995 年には Web ブラウザで動く JavaScript が登場した。

開発の進め方も変化した。オープンソースソフトウェアの普及により、世界中の開発者が作った部品を組み合わせて開発することが当たり前になった。2001 年には、変化に柔軟に対応する開発手法の価値観をまとめた「アジャイルソフトウェア開発宣言」が発表された。2020 年代には、大規模言語モデルを使ってコードを生成する支援ツールが普及しつつある。

歴史から分かること
------------------

ここまでの歴史には、一貫した流れがある。それは、人間が扱う表現と、機械が実行する表現との距離を、道具によって埋めてきたという流れである。配線の組み替えはプログラム内蔵方式に、機械語はアセンブリ言語に、アセンブリ言語は高水準言語に置き換わった。そのたびに、人間は機械の詳細から解放され、解きたい問題そのものに集中できるようになった。

この「詳細を隠し、本質だけを扱えるようにする」ことを\ :term:`抽象化`\ と呼ぶ。抽象化は、プログラミングを理解するうえで最も重要な考え方の 1 つであり、:doc:`07_abstraction`\ で改めて扱う。
