アルゴリズムと計算量
====================

:doc:`01_what_is_programming`\ で、プログラミングの中心は手順の設計であると述べた。この章では、その手順である\ :term:`アルゴリズム`\ と、アルゴリズムの効率を比べるための\ :term:`計算量`\ を説明する。

アルゴリズムとは
----------------

アルゴリズムとは、問題を解くための明確な手順である。ドナルド・クヌースは、アルゴリズムが満たすべき性質として次の 5 つを挙げている\ [Knuth1997]_。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 性質
     - 説明
   * - 有限性
     - 有限回の手順で必ず終了する。
   * - 明確性
     - 各手順が厳密に、曖昧さなく定められている。
   * - 入力
     - 0 個以上の入力を持つ。
   * - 出力
     - 1 個以上の出力を持つ。
   * - 実効性
     - 各手順が、人間が紙と鉛筆で有限の時間内に実行できる程度に基本的である。

同じ問題を解くアルゴリズムは 1 つとは限らない。そして、どのアルゴリズムを選ぶかによって、処理にかかる時間が大きく変わることがある。

例：探索
--------

数値の並びから、目的の値がどこにあるかを探す問題を考える。この問題を探索と呼ぶ。

~~~~~~~~

二分探索
~~~~~~~~

データが昇順に並んでいるなら、より効率のよい方法がある。探す範囲の中央の値と目的の値を比べ、目的の値の方が大きければ後半を、小さければ前半を次に探す範囲とする。これを繰り返すと、1 回の比較で探す範囲が半分になる。この方法を二分探索と呼ぶ。

.. literalinclude:: ../examples/binary_search.py
   :language: python
   :linenos:

8〜9 行目で探す範囲の両端を ``low`` と ``high`` に設定し、11 行目で中央の位置を求める。14〜17 行目で、比較の結果に応じて探す範囲を後半または前半に絞る。

範囲が半分ずつになるため、データが :math:`n` 個のとき、最悪の場合の比較回数は次のとおりである。

.. math::

   \lfloor \log_2 n \rfloor + 1

ここで :math:`\lfloor x \rfloor` は :math:`x` 以下の最大の整数を表す。たとえば :math:`n = 1{,}000{,}000` のとき、線形探索では最悪 1,000,000 回の比較が必要だが、二分探索では最悪 20 回で済む。

計算量
------

アルゴリズムの効率は、入力の大きさ :math:`n` に対して、処理の手間がどのように増えるかで表す。これを計算量と呼び、処理時間に注目したものを時間計算量、使うメモリの量に注目したものを空間計算量と呼ぶ。

O 記法
~~~~~~

計算量は、一般に :math:`O` 記法で表す。関数 :math:`f(n)` と :math:`g(n)` について、ある正の定数 :math:`c` と :math:`n_0` が存在して、:math:`n_0` 以上のすべての :math:`n` で次の式が成り立つとき、:math:`f(n) = O(g(n))` と書く。

.. math::

   0 \leq f(n) \leq c \cdot g(n)

つまり :math:`O` 記法は、:math:`n` が十分に大きいときの増え方の上限を、定数倍の違いを無視して表す。たとえば :math:`3n^2 + 5n + 2` は :math:`O(n^2)` である。この記法を使うと、線形探索の時間計算量は :math:`O(n)`、二分探索の時間計算量は :math:`O(\log n)` と表せる。

代表的な計算量
~~~~~~~~~~~~~~

代表的な計算量と、:math:`n` に対する手間のおおよその大きさを次に示す。

.. list-table::
   :header-rows: 1
   :widths: 20 20 20 20 40

   * - 計算量
     - :math:`n = 10`
     - :math:`n = 1{,}000`
     - :math:`n = 10^6`
     - 例
   * - :math:`O(1)`
     - 1
     - 1
     - 1
     - 辞書のキーによる値の取得（平均）
   * - :math:`O(\log n)`
     - 約 3
     - 約 10
     - 約 20
     - 二分探索
   * - :math:`O(n)`
     - 10
     - 1,000
     - :math:`10^6`
     - 線形探索
   * - :math:`O(n \log n)`
     - 約 33
     - 約 10,000
     - 約 :math:`2 \times 10^7`
     - 効率のよい整列（並べ替え）
   * - :math:`O(n^2)`
     - 100
     - :math:`10^6`
     - :math:`10^{12}`
     - 単純な整列、二重の繰り返しによる全組み合わせの比較

:math:`n` が小さいうちは差がわずかでも、:math:`n` が大きくなると差は急激に広がる。1 回の処理に 1 ナノ秒かかるとすると、:math:`n = 10^6` のとき、:math:`O(n \log n)` の処理は約 0.02 秒で終わるが、:math:`O(n^2)` の処理は約 1,000 秒（約 17 分）かかる。

アルゴリズムを選ぶときの注意
----------------------------

計算量が小さいアルゴリズムが、常に最良とは限らない。二分探索は、データが整列されていることを前提とする。データを整列するには :math:`O(n \log n)` の時間がかかるため、1 回しか探索しないなら線形探索の方が速い。また、:math:`n` が小さい場合は、定数倍の違いや実装の単純さの方が重要になることもある。アルゴリズムは、データの量、データの性質、処理の頻度を考慮して選ぶ。
