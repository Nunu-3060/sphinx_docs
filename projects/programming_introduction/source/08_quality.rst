よいプログラムを書くために
==========================

正しく動くことは、プログラムに求められる最低限の条件である。実際の開発では、プログラムは書かれたあとも何度も読まれ、修正される。この章では、読みやすく、誤りの少ないプログラムを書き、それを保つための手法を説明する。

可読性
------

プログラムは、書かれる回数よりも読まれる回数の方がはるかに多い。読むのは、他のメンバーや、数か月後の自分である。読みやすいプログラムは、誤りを見つけやすく、修正もしやすい。

命名
~~~~

変数や関数の名前は、その役割が分かるように付ける。

.. code-block:: python
   :linenos:

   # 悪い例：名前から役割が分からない
   def f(a: list[int]) -> int:
       t = 0
       for x in a:
           t += x
       return t


   # よい例：名前から役割が分かる
   def total_price(prices: list[int]) -> int:
       total = 0
       for price in prices:
           total += price
       return total

2 つの関数は同じ処理を行うが、2 つ目の関数は名前を読むだけで、何をする関数なのかが分かる。

コーディング規約
~~~~~~~~~~~~~~~~

インデントの幅、空白の入れ方、名前の付け方などの書き方を、チームや言語のコミュニティで統一するための決まりをコーディング規約と呼ぶ。書き方が統一されていれば、読む人は書き方の違いに気をとられず、内容に集中できる。Python では、PEP 8 [PEP8]_ が標準的なコーディング規約として広く使われている。

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - PEP 8 の規則の例
     - 例
   * - インデントは空白 4 個とする。
     - ``if`` 文や関数の本体を 4 個の空白で字下げする。
   * - 関数名と変数名は小文字の単語を ``_`` でつなぐ。
     - ``total_price``、``linear_search``
   * - クラス名は単語の先頭を大文字にしてつなぐ。
     - ``Shape``、``BinarySearchTest``
   * - トップレベルの関数やクラスの定義の前後には空行を 2 行入れる。
     - 本書のサンプルコードを参照。

テスト
------

プログラムが意図どおりに動くことを確かめる作業を\ :term:`テスト`\ と呼ぶ。テストのうち、関数やクラスなどの小さな単位を個別に確かめるものを単体テストと呼ぶ。単体テストをプログラムとして書いておけば、プログラムを修正するたびに自動で繰り返し実行でき、修正によって既存の機能が壊れていないことを確かめられる。

テストは、誤りがあることを示せても、誤りがないことは示せない。それでも、適切に設計したテストを積み重ねることで、プログラムの信頼性を大きく高められる。

デバッグ
--------

プログラムの誤り（:term:`バグ`）を見つけて修正する作業を\ :term:`デバッグ`\ と呼ぶ。やみくもにプログラムを書き換えるのではなく、次の手順で進めると効率がよい。

#. 再現：バグが起こる条件を特定し、確実に再現できるようにする。
#. 切り分け：入力を単純にしたり、途中の値を表示したりして、誤りのある箇所を絞り込む。デバッガを使えば、プログラムを 1 行ずつ実行しながら変数の値を確認できる。
#. 修正：原因を理解したうえで修正する。症状だけを抑える修正は、別のバグを生みやすい。
#. 確認：バグが直ったこと、他の機能が壊れていないことをテストで確かめる。同じバグが再発しないよう、そのバグを検出するテストを追加するとよい。

静的解析
--------

プログラムを実行せずに、ソースコードを解析して問題を見つけることを\ :term:`静的解析`\ と呼ぶ。Python では、次のツールがよく使われる。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - ツール
     - 検出する問題
   * - flake8 [Flake8]_
     - PEP 8 に違反する書き方、使われていない変数や ``import`` 文、未定義の名前など。
   * - mypy [Mypy]_
     - :term:`型ヒント`\ と矛盾する値の使い方。たとえば、``int`` 型を返すと宣言した関数が文字列を返している箇所など。

本書のサンプルコードは、次のコマンドで違反が検出されないことを確認している。

.. code-block:: console
   :linenos:

   $ python -m flake8 examples
   $ python -m mypy --strict examples
   Success: no issues found in 14 source files

静的解析は、人間が見落としやすい単純な誤りを機械的に見つけられる。テストと組み合わせて使うことで、誤りを早い段階で発見できる。

バージョン管理
--------------

ファイルの変更の履歴を記録し、過去の状態に戻したり、変更の内容を比べたりできるようにする仕組みを\ :term:`バージョン管理`\ と呼ぶ。現在は Git [Git]_ が広く使われている。バージョン管理を使うと、次のことができる。

* いつ、誰が、なぜ変更したのかを記録し、あとから確認できる。
* 誤った変更を取り消し、過去の正しい状態に戻せる。
* 複数の人が同じプログラムを並行して変更し、その結果を統合できる。

プログラムを書くときは、小さな変更ごとに、変更の意図を説明するメッセージを付けて記録するとよい。
