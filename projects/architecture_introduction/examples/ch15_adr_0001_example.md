# ADR-0001: 在庫データの保存に JSON ファイルを使う

- 状態: 承認
- 日付: 2026-04-01
- 決定者: 在庫管理ツールの開発チーム

## 背景

倉庫の担当者が使う、小さな在庫管理の CLI ツールを作ります。利用者は 1 人で、
複数のプロセスから同時に更新することはありません。商品の数は多くても数百件
です。データは、人が直接開いて確認できることが望まれています。

## 検討した選択肢

1. JSON ファイル
2. SQLite
3. サーバー型のデータベース（PostgreSQL など）

## 決定

JSON ファイルを使います。

- PostgreSQL などとは異なり、サーバーの用意や運用が不要です。
- テキストエディターで内容を確認でき、Git で差分を確認できます。
- 件数が少ないため、ファイル全体を毎回読み書きしても性能の問題はありません。

SQLite は、同時の更新や検索が必要になった場合の移行先とします。サーバー型の
データベースは、この規模では運用の負担に見合わないので採用しません。

## 結果

- 保存の処理はリポジトリのクラスに閉じ込め、アプリケーションサービスは
  リポジトリのインターフェースだけに依存させます。保存先を SQLite に変える
  場合も、リポジトリのクラスを追加するだけで済むようにします。
- 複数のプロセスから同時に更新すると、データが失われる可能性があります。
  利用者が増えた場合は、この決定を見直します。
