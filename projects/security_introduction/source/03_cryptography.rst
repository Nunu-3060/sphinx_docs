暗号技術の基礎
==============

暗号技術は、通信の保護、パスワードの保存、ソフトウェアの改ざん検知など、多くのセキュリティ対策の土台になっています。この章では、暗号技術の種類と用途、正しい使い方を説明します。

最初に強調しておきたいのは、**暗号アルゴリズムや暗号プロトコルを自作してはいけない**\ ということです。暗号は、専門家が長年にわたって攻撃を試みても破られなかったことで信頼されています。自作の暗号は、見た目では安全に見えても、専門家にはすぐに破られることがほとんどです。実務では、広く使われている実績のあるライブラリを、推奨された方法で使います。

エンコード・暗号化・ハッシュの違い
----------------------------------

最初に、混同されやすい 3 つの処理の違いを整理します。

.. list-table:: エンコード・暗号化・ハッシュの違い
   :header-rows: 1
   :widths: 16 28 28 28

   * - 処理
     - 目的
     - 元に戻せるか
     - 例
   * - エンコード
     - データを別の形式で表現します（例: バイナリーを文字列で表す）。
     - 誰でも戻せます（鍵は不要です）。
     - Base64、URL エンコード
   * - 暗号化
     - 鍵を持たない人がデータを読めないようにします。
     - 鍵を持つ人だけが戻せます。
     - AES、RSA
   * - ハッシュ
     - データから固定長の「指紋」を作ります。
     - 戻せません。
     - SHA-256

共通鍵暗号
----------

:term:`共通鍵暗号`\ は、暗号化と復号に同じ鍵を使う方式です。処理が高速なため、データ本体の暗号化に使われます。現在の標準は AES（Advanced Encryption Standard）で、鍵の長さは 128 ビット、192 ビット、256 ビットから選べます。

AES は 16 バイト（128 ビット）単位のブロックを暗号化する方式です。それより長いデータを暗号化するときの、ブロックのつなぎ方を\ **暗号利用モード**\ と呼びます。利用モードの選択を誤ると、AES 自体が安全でも暗号文から情報が漏れます。

認証付き暗号
^^^^^^^^^^^^

CTR モードはパターンを隠せますが、暗号文の改ざんは検知できません。攻撃者が暗号文の特定のビットを反転させると、復号結果の対応するビットも反転します。そこで現在は、暗号化と同時に改ざん検知用のタグを付ける\ :term:`認証付き暗号`\ を使います。代表的なものが AES-GCM と ChaCha20-Poly1305 です。

AES-GCM では、暗号化のたびに\ **ナンス**\ （一度だけ使う値）を指定します。**同じ鍵で同じナンスを 2 回使うと、暗号の安全性が大きく損なわれます。**\ ナンスは暗号化のたびに乱数で生成するのが簡単で確実です。

公開鍵暗号
----------

共通鍵暗号には、通信相手と事前に安全な方法で鍵を共有しておく必要がある、という課題があります。この課題を解決するのが\ :term:`公開鍵暗号`\ です。公開鍵暗号では、対になる 2 つの鍵を使います。

* **公開鍵**: 誰に公開してもよい鍵。暗号化や署名の検証に使います。
* **秘密鍵**: 持ち主だけが保管する鍵。復号や署名の作成に使います。

RSA の原理
^^^^^^^^^^

代表的な公開鍵暗号である RSA の原理を、数式で簡単に示します。まず、2 つの大きな素数 :math:`p` と :math:`q` を選び、次の値を計算します。

.. math::

   n = pq, \qquad \varphi(n) = (p - 1)(q - 1)

次に、:math:`\varphi(n)` と互いに素な整数 :math:`e` を選び、次の式を満たす :math:`d` を求めます。

.. math::

   ed \equiv 1 \pmod{\varphi(n)}

:math:`(n, e)` が公開鍵、:math:`d` が秘密鍵です。平文を整数 :math:`m`\ （ただし :math:`0 \le m < n`）で表すと、暗号化と復号は次のように計算します。

.. math::

   c = m^{e} \bmod n, \qquad m = c^{d} \bmod n

例えば、:math:`p = 61`、:math:`q = 53` とすると、:math:`n = 3233`、:math:`\varphi(n) = 3120` です。:math:`e = 17` とすると :math:`d = 2753` となり、平文 :math:`m = 65` は暗号文 :math:`c = 65^{17} \bmod 3233 = 2790` になります。:math:`2790^{2753} \bmod 3233` を計算すると、元の 65 に戻ります。

:math:`n` から :math:`p` と :math:`q` を求める（素因数分解する）ことができれば :math:`d` も計算できますが、:math:`n` が十分に大きければ、現在のコンピューターでは現実的な時間で素因数分解できません。これが RSA の安全性の根拠です。実際の RSA では、2048 ビット以上の :math:`n` を使い、平文をそのまま暗号化するのではなく、OAEP などのパディング方式と組み合わせます。

ハイブリッド暗号
^^^^^^^^^^^^^^^^

公開鍵暗号は共通鍵暗号に比べて処理が遅いため、データ本体の暗号化には使いません。実際には、公開鍵暗号の仕組みを使って共通鍵を安全に共有し、データ本体はその共通鍵で暗号化します。この組み合わせをハイブリッド暗号と呼びます。:doc:`05_network`\ で説明する TLS も、この方式を使っています。

ハッシュ関数
------------

:term:`ハッシュ関数`\ は、任意の長さのデータから、固定長の値（ハッシュ値）を計算する関数です。セキュリティの用途に使うハッシュ関数（暗号学的ハッシュ関数）には、次の性質が求められます。

.. list-table:: 暗号学的ハッシュ関数に求められる性質
   :header-rows: 1
   :widths: 30 70

   * - 性質
     - 意味
   * - 原像計算困難性
     - ハッシュ値から、元のデータを求めることが困難です。
   * - 第 2 原像計算困難性
     - あるデータと同じハッシュ値を持つ、別のデータを見つけることが困難です。
   * - 衝突困難性
     - 同じハッシュ値を持つ 2 つのデータの組を見つけることが困難です。

衝突困難性の強さには、出力の長さによって決まる上限があります。:math:`N` 通りの値をとるハッシュ関数に、ランダムなデータを :math:`k` 個入力したとき、どれか 2 つのハッシュ値が一致する確率は、近似的に次の式で表されます。

.. math::

   P(k) \approx 1 - \exp\left(-\frac{k^{2}}{2N}\right)

:math:`P(k) = 1/2` となる :math:`k` は約 :math:`1.18\sqrt{N}` です。これは「23 人集まると、同じ誕生日の人がいる確率が 50 % を超える」という誕生日のパラドックスと同じ現象で、衝突を探す攻撃を誕生日攻撃と呼びます。出力が :math:`n` ビットのハッシュ関数（:math:`N = 2^{n}`）では、約 :math:`2^{n/2}` 回の計算で衝突が見つかる計算になります。SHA-256 では :math:`2^{128}` 回程度となり、現実的には不可能です。

MD5 と SHA-1 は、この理論値よりもはるかに少ない計算で衝突を見つける攻撃が発見されています。SHA-1 については 2017 年に実際に衝突する 2 つの PDF ファイルが公開されました。これらはセキュリティの用途に使ってはいけません。

.. note::

   ハッシュ関数をパスワードの保存にそのまま使ってはいけません。SHA-256 は非常に高速なため、総当たりで元のパスワードを短時間で見つけられてしまいます。パスワードの保存方法は\ :doc:`04_authentication`\ で説明します。

メッセージ認証コード
--------------------

ハッシュ値は誰でも計算できるため、ハッシュ値だけでは改ざんを防げません。攻撃者はデータを書き換えたうえで、ハッシュ値も計算し直せるからです。改ざんを検知するには、共有の秘密鍵を使う :term:`MAC`\ （メッセージ認証コード）を使います。代表的なものが、ハッシュ関数を使って MAC を構成する HMAC です。

デジタル署名
------------

MAC は送信者と受信者が同じ鍵を共有するため、受信者も正しい MAC を作れます。そのため、第三者に対して「このデータは確かに送信者が作った」と証明することはできません。

:term:`デジタル署名`\ は、公開鍵暗号の仕組みを使い、秘密鍵で署名を作成し、公開鍵で検証します。署名を作れるのは秘密鍵の持ち主だけなので、完全性に加えて真正性と否認防止も実現できます。ソフトウェアの配布、:doc:`05_network`\ で説明する証明書、:doc:`04_authentication`\ で説明するパスキーなどで使われています。

鍵管理
------

暗号の安全性は、鍵の安全性に依存します。アルゴリズムが強くても、鍵が漏えいすれば意味がありません。鍵の管理では、次の点に注意します。

* **鍵をソースコードに書かないでください。**\ リポジトリに登録された鍵は、履歴から削除しても複製されている可能性があります。シークレットの扱いは\ :doc:`07_secure_coding`\ で説明します。
* **専用の仕組みで保管してください。**\ クラウドの鍵管理サービス（KMS）やシークレット管理サービス、ハードウェアセキュリティモジュール（HSM）を使うと、鍵そのものをアプリケーションに渡さずに暗号化や署名ができます。
* **用途ごとに鍵を分けてください。**\ 暗号化用と署名用、本番環境と開発環境で、別の鍵を使います。
* **鍵を定期的に、また漏えいの疑いがあるときはすぐに更新してください。**\ 更新できるように、暗号文や署名にどの鍵を使ったかを記録しておきます。

アルゴリズムの選び方と危殆化
----------------------------

計算機の性能向上や新しい攻撃手法の発見によって、かつて安全とされたアルゴリズムが安全でなくなることを\ :term:`危殆化`\ と呼びます。アルゴリズムは、最新の推奨に従って選び、危殆化したものは使わないようにします。

.. list-table:: アルゴリズムの選び方の目安
   :header-rows: 1
   :widths: 22 39 39

   * - 用途
     - 推奨されるもの
     - 使ってはいけないもの
   * - 共通鍵暗号
     - AES-GCM、ChaCha20-Poly1305（認証付き暗号）
     - DES、3DES、RC4、ECB モード
   * - ハッシュ関数
     - SHA-256、SHA-384、SHA-512、SHA-3
     - MD5、SHA-1
   * - デジタル署名
     - Ed25519、ECDSA（P-256 以上）、RSA（2048 ビット以上）
     - RSA（1024 ビット以下）
   * - パスワードの保存
     - Argon2id、scrypt、bcrypt
     - ハッシュ関数をそのまま使うこと、可逆な暗号化

日本では、CRYPTREC（暗号技術評価委員会）が、電子政府での利用を推奨する暗号の一覧を公開しています。米国の NIST も、アルゴリズムと鍵長の推奨を公開しています。

また、将来アルゴリズムを入れ替えられるように設計しておくことも重要です。この性質を\ **暗号の俊敏性**\ （クリプトアジリティ）と呼びます。例えば、保存するデータにアルゴリズムの識別子を含めておけば、新旧のアルゴリズムを併存させながら移行できます。

耐量子計算機暗号
----------------

大規模な量子コンピューターが実用化されると、RSA や楕円曲線暗号は、Shor のアルゴリズムによって現実的な時間で破られると考えられています。共通鍵暗号やハッシュ関数への影響は比較的小さく、鍵長や出力長を十分に取れば対応できるとされています。

これに備えて、量子コンピューターでも解読が困難と考えられる\ :term:`耐量子計算機暗号`\ （PQC）の標準化が進められています。NIST は 2024 年に、次の 3 つの標準を公開しました。

.. list-table:: NIST が 2024 年に公開した耐量子計算機暗号の標準
   :header-rows: 1
   :widths: 25 25 50

   * - 規格
     - 方式
     - 用途
   * - FIPS 203
     - ML-KEM
     - 鍵共有（鍵カプセル化）
   * - FIPS 204
     - ML-DSA
     - デジタル署名
   * - FIPS 205
     - SLH-DSA
     - デジタル署名（ハッシュ関数に基づく方式）

量子コンピューターがまだ実用化されていなくても、対策は今から必要です。攻撃者が現在の暗号化通信を保存しておき、将来量子コンピューターで解読する攻撃（Harvest Now, Decrypt Later）が考えられるためです。長期間にわたって秘密にすべきデータを扱うシステムでは、移行の計画を立てておく必要があります。主要なブラウザーや OS では、従来の鍵共有方式と ML-KEM を組み合わせた方式の採用がすでに始まっています。
