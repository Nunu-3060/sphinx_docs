まとめ
======

各章の要点
----------

本書で説明した内容の要点を、章ごとにまとめます。

.. list-table:: 各章の要点
   :header-rows: 1
   :widths: 30 70

   * - 章
     - 要点
   * - セキュリティの基本概念
     - 守りたいものを機密性・完全性・可用性で整理し、リスクの大きさに応じて対策を選びます。多層防御と最小権限の原則は、あらゆる場面に当てはまります。
   * - 暗号技術の基礎
     - 暗号は自作せず、推奨されるアルゴリズムを実績のあるライブラリで使います。エンコードは暗号化ではありません。乱数には secrets モジュールを使います。
   * - 認証と認可
     - パスワードは Argon2id などで保存し、多要素認証やパスキーを導入します。認可は、サーバー側で、データごとに確認します。
   * - ネットワークセキュリティ
     - 通信は TLS で保護し、証明書の検証を無効にしません。公開するポートを最小限にし、ネットワークを分離します。
   * - Web アプリケーションのセキュリティ
     - データとプログラムを分離します（プレースホルダー、エスケープ、引数のリスト）。Cookie の属性とセキュリティヘッダーを設定します。
   * - セキュアコーディング
     - 外部からのデータはすべて信頼しません。シークレットをコードやログに含めません。危険な関数を避けます。
   * - ソフトウェアサプライチェーン
     - 依存関係を最小限にしてバージョンを固定し、脆弱性を継続的にスキャンします。CI/CD のパイプラインの権限を最小限にします。
   * - クラウドとコンテナのセキュリティ
     - データと権限の設定は利用者の責任です。IAM の権限を最小限にし、設定を IaC で管理して検査します。
   * - AI・LLM アプリケーションのセキュリティ
     - LLM はだまされ得るという前提で、出力を信頼せず、エージェントの権限を最小限にします。
   * - セキュリティテストと脅威モデリング
     - 設計段階で脅威を洗い出し、静的解析、動的解析、ファジング、レビューを組み合わせて脆弱性を見つけます。
   * - 運用とインシデント対応
     - ログを集めて監視し、パッチを速やかに適用し、復旧できるバックアップを持ちます。インシデントに備えて準備と訓練を行います。

チェックリスト
--------------

日々の開発と運用で確認すべき項目を、チェックリストにまとめます。すべての項目がすべてのシステムに当てはまるわけではありませんが、見落としがないかを確認する際に活用してください。

.. list-table:: 設計時のチェックリスト
   :header-rows: 1
   :widths: 10 90

   * - 確認
     - 項目
   * - □
     - 守るべき情報と、それに対する脅威を洗い出しましたか（脅威モデリング）。
   * - □
     - 利用者とプログラムに与える権限は最小限ですか。
   * - □
     - 初期設定の状態で安全ですか（デバッグ機能の無効化、非公開の初期設定など）。
   * - □
     - 認証に多要素認証やパスキーを利用できますか。
   * - □
     - AI エージェントに与えるツールと権限は最小限ですか。重要な操作に人間の承認を求めますか。

.. list-table:: 実装時のチェックリスト
   :header-rows: 1
   :widths: 10 90

   * - 確認
     - 項目
   * - □
     - SQL 文にはプレースホルダーを使っていますか。
   * - □
     - HTML への出力はエスケープしていますか（テンプレートエンジンの自動エスケープを無効にしていませんか）。
   * - □
     - 外部のコマンドを、シェルを経由せずに引数のリストで実行していますか。
   * - □
     - ファイルのパスや URL を、利用者の入力から組み立てる箇所で検証していますか。
   * - □
     - すべての API で、データごとにアクセス権限を確認していますか。
   * - □
     - パスワードは Argon2id などの専用の関数で保存していますか。
   * - □
     - 乱数には secrets モジュールを使っていますか。
   * - □
     - シークレットをソースコードやログに含めていませんか。
   * - □
     - Cookie に Secure、HttpOnly、SameSite の各属性を設定していますか。
   * - □
     - セキュリティ関連の HTTP ヘッダーを設定していますか。
   * - □
     - 依存パッケージのバージョンを固定し、脆弱性をスキャンしていますか。

.. list-table:: 運用時のチェックリスト
   :header-rows: 1
   :widths: 10 90

   * - 確認
     - 項目
   * - □
     - TLS 1.2 以上だけを有効にし、証明書の更新を自動化していますか。
   * - □
     - 公開しているポートとサービスは必要最小限ですか。
   * - □
     - 認証やアクセス制御のイベントを記録し、異常を検知して通知する仕組みがありますか。
   * - □
     - パッチを速やかに適用する手順がありますか。サポートが終了したソフトウェアを使っていませんか。
   * - □
     - オフラインまたは変更不可のバックアップがあり、復旧の訓練を行っていますか。
   * - □
     - インシデント対応の体制、連絡先、手順を決めていますか。
   * - □
     - 脆弱性の報告を受け付ける窓口を用意していますか。

学習の進め方
------------

セキュリティの知識は、一度学べば終わりではありません。新しい攻撃手法や技術が次々に登場するため、継続的に学ぶ必要があります。本書を読み終えた後は、次のような方法で学習を進めることをお勧めします。

* **信頼できる資料を読んでください。**\ IPA の「安全なウェブサイトの作り方」は、Web アプリケーションの脆弱性と対策を日本語で詳しく解説しています。OWASP Cheat Sheet Series は、テーマごとに実装の推奨事項を簡潔にまとめています。いずれも付録の\ :doc:`references`\ に掲載しています。
* **演習環境で手を動かしてください。**\ 意図的に脆弱性を持たせた練習用のアプリケーション（OWASP Juice Shop など）を自分の環境で動かし、攻撃と対策を試すと、理解が深まります。:doc:`01_introduction`\ で説明したとおり、演習は必ず自分が管理する環境で行ってください。
* **CTF に参加してください。**\ CTF（Capture The Flag）は、セキュリティの課題を解いて得点を競う競技です。初心者向けの大会や、常設の練習サイトもあります。
* **資格の取得を目指してください。**\ 日本の国家資格である情報処理安全確保支援士試験は、セキュリティの知識を体系的に学ぶ目標になります。
* **最新の情報を追ってください。**\ IPA、JPCERT/CC、利用している製品やライブラリのセキュリティ情報を定期的に確認します。

セキュリティは、特別な専門家だけのものではありません。日々の設計、実装、レビュー、運用の中で、本書で説明した考え方を少しずつ実践していくことが、安全なソフトウェアにつながります。
