################################################################
第 20 章 デバッグの方法
################################################################

プログラムの誤り（バグ）を見つけて直す作業を、デバッグと呼びます。プログラムは、最初から思いどおりに動くことはほとんどありません。この章では、Unity でのデバッグの方法と、よくあるエラーへの対処方法を学びます。

Console ウィンドウ
================================================================

Console ウィンドウには、スクリプトから出力したメッセージのほか、コンパイルエラーや、実行中に発生した例外が表示されます。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 機能
     - 説明
   * - Clear
     - 表示されているメッセージを消します。
   * - Collapse
     - 同じ内容のメッセージを 1 行にまとめ、回数を表示します。
   * - Error Pause
     - エラーが発生したときに、Play モードを一時停止します。
   * - 右上の 3 つのボタン
     - 通常のメッセージ、警告、エラーの表示と非表示を切り替えます。

メッセージを選ぶと、ウィンドウの下部に詳細とスタックトレースが表示されます。スタックトレースは、エラーが発生するまでにどのメソッドがどの順番で呼ばれたかを示す情報です。メッセージをダブルクリックすると、コードエディターで該当する行が開きます。

Debug クラス
================================================================

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - メソッド
     - 説明
   * - ``Debug.Log(メッセージ)``
     - 通常のメッセージを表示します。
   * - ``Debug.Log(メッセージ, オブジェクト)``
     - Console ウィンドウでメッセージを選ぶと、指定したオブジェクトが Hierarchy ウィンドウで強調表示されます。同じスクリプトを多くの GameObject にアタッチしているときに、どの GameObject のメッセージかを確認できます。
   * - ``Debug.LogWarning(メッセージ)``
     - 警告（黄色）を表示します。
   * - ``Debug.LogError(メッセージ)``
     - エラー（赤色）を表示します。
   * - ``Debug.Assert(条件, メッセージ)``
     - 条件が ``false`` のときだけ、エラーを表示します。「ここでは必ずこうなっているはず」という前提を確かめるのに使います。
   * - ``Debug.DrawRay(開始位置, 向きと長さ, 色)``
     - Scene ビューに線を描きます（Game ビューでは、Gizmos を有効にしたときだけ表示されます）。向きや距離の計算を目で確かめるのに使います。

値を確かめたい変数を ``Debug.Log`` で表示するのは、最も手軽なデバッグの方法です。「このメソッドは呼ばれているか」「この変数の値は何か」を 1 つずつ確かめていくと、問題のある場所を絞り込めます。

デバッガーを使う
================================================================

コードエディターのデバッガーを使うと、プログラムを好きな行で一時停止させ、そのときの変数の値を確認できます。

#. コードエディターで、止めたい行の左端（行番号の左）をクリックします。赤い丸が表示されます。これをブレークポイントと呼びます。
#. Visual Studio では「Unity にアタッチ」ボタンを、Visual Studio Code では Run and Debug の「Attach to Unity」を選び、デバッガーを Unity に接続します。
#. Unity エディターで Play ボタンを押します。ブレークポイントの行が実行される直前で、プログラムが一時停止します。
#. 変数にマウスカーソルを重ねると、その時点の値が表示されます。

一時停止した後は、次の操作でプログラムを少しずつ進められます。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - 説明
   * - ステップオーバー
     - 現在の行を実行し、次の行で止まります。メソッドの呼び出しは、中に入らずに実行します。
   * - ステップイン
     - 現在の行で呼び出しているメソッドの中に入って止まります。
   * - 続行
     - 次のブレークポイントまで実行を続けます。

.. note::

   Unity エディターの右下にある虫のアイコンで、Code Optimization を Debug Mode にしておく必要があります。Release Mode のままデバッガーを接続しようとすると、Debug Mode に切り替えるかどうかを確認する画面が表示されます。

よくあるエラー
================================================================

コンパイルエラー
----------------------------------------------------------------

コンパイルエラーのメッセージは、次の形式で表示されます。

.. code-block:: text

   Assets/PlayerController.cs(25,13): error CS0103: The name 'speed' does not exist in the current context

``(25,13)`` は 25 行目の 13 文字目、``CS0103`` はエラーの種類を表す番号です。よく見るコンパイルエラーは次のとおりです。

.. list-table::
   :header-rows: 1
   :widths: 15 40 45

   * - 番号
     - メッセージ
     - 主な原因
   * - CS1002
     - ; expected
     - 文の終わりの ``;`` が抜けている。
   * - CS1513
     - } expected
     - ``{`` と ``}`` の数が合っていない。
   * - CS0103
     - The name '...' does not exist in the current context
     - 変数名やメソッド名のつづりが間違っている。スコープの外で変数を使っている。
   * - CS0246
     - The type or namespace name '...' could not be found
     - 型名のつづりが間違っている。``using`` が足りない（``List<T>`` なら ``using System.Collections.Generic;``）。
   * - CS0029
     - Cannot implicitly convert type '...' to '...'
     - 型が合わない値を代入している（第 2 章）。
   * - CS0664
     - Literal of type double cannot be implicitly converted to type 'float'; use an 'F' suffix to create a literal of this type
     - ``float`` の値に ``f`` を付け忘れている（第 2 章）。
   * - CS1612
     - Cannot modify the return value of '...' because it is not a variable
     - ``transform.position.x`` などを直接書き換えようとしている（第 13 章）。

コンパイルエラーが多数表示された場合は、一番上のエラーから直してください。1 つの誤りが原因で、後に続く多くのエラーが表示されていることがよくあります。

実行時のエラー
----------------------------------------------------------------

プログラムの実行中に発生するエラー（例外）は、次のようなものがよく見られます。

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 例外
     - 主な原因と対処
   * - ``NullReferenceException``
     - ``null`` の変数のメンバーにアクセスしています。``FindAction`` で入力アクションが見つからなかった場合などに発生します。
   * - ``UnassignedReferenceException``
     - ``[SerializeField]`` のフィールドに、Inspector ウィンドウで参照を設定していません。メッセージに表示されるフィールド名とスクリプト名を手がかりに設定します。
   * - ``MissingComponentException``
     - ``GetComponent`` で見つからなかったコンポーネントを使おうとしています。GameObject に必要なコンポーネントがアタッチされているかを確認します（第 13 章）。
   * - ``MissingReferenceException``
     - ``Destroy`` で破棄したオブジェクトを使おうとしています。``!= null`` で確認してから使います（第 18 章）。
   * - ``IndexOutOfRangeException``
     - 配列の範囲外のインデックスを使っています（第 5 章）。
   * - ``ArgumentOutOfRangeException``
     - ``List<T>`` の範囲外のインデックスを使っています（第 5 章）。

例外が発生すると、そのメソッドのそれ以降の処理は実行されません。ただし、ゲーム自体は止まらず、次のフレームでは再び ``Update`` などが呼ばれます。そのため、同じ例外が毎フレーム表示され続けることがあります。

エラーではないのに動かない場合
----------------------------------------------------------------

エラーが表示されないのに思いどおりに動かない場合は、次の点を確認してください。

* スクリプトが GameObject にアタッチされ、コンポーネントと GameObject が有効になっているか。
* イベント関数の名前のつづり（大文字と小文字を含む）が正しいか（第 11 章）。
* Inspector ウィンドウの値が、意図した値になっているか。コードの初期値を変えても、アタッチ済みのコンポーネントの値は変わりません（第 12 章）。
* 衝突やトリガーのイベント関数が呼ばれない場合は、Rigidbody と Collider の条件を満たしているか（第 16 章）。

まとめ
================================================================

* Console ウィンドウのメッセージをダブルクリックすると、該当するコードの行が開きます。
* ``Debug.Log`` で値を表示したり、デバッガーのブレークポイントでプログラムを止めたりして、問題のある場所を絞り込みます。
* コンパイルエラーは、一番上のエラーから直します。
* ``NullReferenceException`` や ``UnassignedReferenceException`` が発生したら、参照が正しく設定されているかを確認します。
