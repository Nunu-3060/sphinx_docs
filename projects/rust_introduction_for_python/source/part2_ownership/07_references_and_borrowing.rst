借用と参照
==========

前章では、値を関数に渡したり別の変数に代入したりするたびに所有権が移動(ムーブ)することを学びました。しかし、値の所有権を渡さずに、一時的に「借りる」だけで済ませたい場面は非常に多くあります。例えば、文字列の長さを調べる関数にいちいち所有権を渡してしまうと、呼び出し元ではその文字列を使えなくなってしまい不便です。このような場合に使うのが「参照(reference)」と「借用(borrowing)」という仕組みです。

参照と可変参照
----------------------------------------

変数の前に ``&`` を付けると、その値への「参照」を作ることができます。参照は値そのものの所有権を持たず、あくまで値を借用しているだけです。

.. code-block:: rust

    fn main() {
        let s1 = String::from("hello");

        let len = calculate_length(&s1); // s1 への参照を渡す(所有権は移動しない)

        println!("'{}' の長さは {} です", s1, len); // s1 はまだ有効
    }

    fn calculate_length(s: &String) -> usize {
        s.len()
    } // s はスコープを抜けるが、参照なので値そのものは破棄されない

``calculate_length`` は ``String`` そのものではなく ``&String`` (参照)を受け取っているため、関数を抜けても呼び出し元の ``s1`` は所有権を保ったままです。これを「借用」と呼びます。

参照はデフォルトでは不変(読み取り専用)です。借用した値を関数の中で書き換えたい場合は、``&mut`` を使って可変参照を作ります。

.. code-block:: rust

    fn main() {
        let mut s = String::from("hello");

        change(&mut s); // 可変参照を渡す

        println!("{}", s); // "hello, world" と表示される
    }

    fn change(some_string: &mut String) {
        some_string.push_str(", world");
    }

可変参照を使うには、元の変数自体も ``mut`` で宣言されている必要があります。

借用チェッカーのルール
----------------------------------------

Rust のコンパイラには「借用チェッカー(borrow checker)」と呼ばれる仕組みがあり、参照が安全に使われているかをコンパイル時に検証します。借用チェッカーが強制するルールは、次の2つにまとめられます。

- 不変参照(``&T``)は同時にいくつでも存在してよい
- 可変参照(``&mut T``)は同時に1つしか存在できず、かつ不変参照と同時に存在することもできない

つまり「複数の読み取り」または「1つだけの書き込み」のどちらかしか許されません。

.. code-block:: rust

    fn main() {
        let mut s = String::from("hello");

        let r1 = &s; // 不変参照その1
        let r2 = &s; // 不変参照その2(複数の不変参照は同時に持てる)
        println!("{} と {}", r1, r2);
        // r1, r2 はここより後で使われないため、実質的にここでスコープが終わる

        let r3 = &mut s; // 可変参照(r1, r2 の使用が終わった後なので OK)
        println!("{}", r3);
    }

なお、先のコード例で ``r1``、``r2`` が最後に使われた行より後で ``r3`` を作れているのは、参照の有効期間は宣言された場所ではなく、実際に最後に使われた場所までとコンパイラが判断してくれるためです(この仕組みの正式名称は、後の「ライフタイム」の章で紹介します)。

もし不変参照が使われている間に可変参照を作ろうとすると、コンパイルエラーになります。

.. code-block:: rust

    fn main() {
        let mut s = String::from("hello");

        let r1 = &s;     // 不変参照
        let r2 = &mut s; // ※これはコンパイルエラーになります
        // error[E0502]: cannot borrow `s` as mutable because it is
        // also borrowed as immutable

        println!("{} {}", r1, r2);
    }

このルールは一見厳しく感じられますが、複数の場所から同時にデータが書き換えられる「データ競合(data race)」をコンパイル時に根本から排除するためのものです。

借用チェッカーが防ぐのは可変参照と不変参照の同時使用だけではありません。値が借用されている間は、その値自体をムーブすることもできません。

.. code-block:: rust

    fn main() {
        let s = String::from("hello");
        let r = &s;

        let s2 = s; // ※これはコンパイルエラーになります(s は借用中のためムーブできない)
        // error[E0505]: cannot move out of `s` because it is borrowed

        println!("{}", r);
    }

Python では、あるオブジェクトを別の変数が参照している最中でも、元の変数を自由に別のものへ再代入したり渡したりできます。Rust ではこれが許されず、参照が使われている間は所有者を手放すこともできない、という点は Python 経験者にとって意外に感じられるかもしれません。

ダングリング参照の防止
----------------------------------------

C や C++ では、すでに解放されたメモリを指すポインタ(ダングリングポインタ)を誤って使ってしまうバグがしばしば発生します。Rust では、借用チェッカーがこれをコンパイル時に検出し、コンパイルエラーとして防いでくれます。

.. code-block:: rust

    fn main() {
        let reference_to_nothing = dangle(); // ※これはコンパイルエラーになります
    }

    fn dangle() -> &String { // 関数の戻り値として参照を返そうとしている
        let s = String::from("hello");
        &s // s への参照を返そうとしているが、
    } // s はここでスコープを抜けて破棄されてしまう
    // error[E0106]: missing lifetime specifier
    // (s の値がこの関数を抜けた時点で破棄されるため、参照先が存在しなくなる)

この場合、正しくは参照ではなく ``String`` そのもの(所有権)を返す必要があります。

.. code-block:: rust

    fn main() {
        let s = no_dangle();
        println!("{}", s);
    }

    fn no_dangle() -> String {
        let s = String::from("hello");
        s // 所有権をそのまま返す
    }

.. admonition:: Python 経験者向けメモ
   :class: tip

   Python では、複数の変数が同じリストや辞書を参照し、どこからでも自由に書き換えることができます。``a = [1, 2, 3]`` のあとに ``b = a`` として ``b.append(4)`` とすれば ``a`` も変化します。便利な反面、意図せず別の場所で値が書き換わってしまう「見えないバグ」の温床にもなります。

   Rust の借用チェッカーは、このような「複数箇所からの同時書き込み」や「読み取り中の書き込み」をコンパイル時に一切禁止します。実行時のロックなどのコストをかけずに、コンパイルが通った時点でデータ競合が起きないことが保証されるのです。最初はコンパイルエラーに戸惑うかもしれませんが、これは実行時に発生したかもしれないバグをコンパイル時に教えてくれていると捉えると前向きに学習できます。

まとめ
------

- ``&T`` は不変参照、``&mut T`` は可変参照であり、どちらも所有権を移動させずに値を借用できます
- 不変参照は同時に複数持てますが、可変参照は同時に1つまでしか持てず、不変参照と同時にも持てません
- このルールにより、コンパイル時にデータ競合を防ぐことができます
- 関数からその場で作った値への参照を返そうとすると、ダングリング参照としてコンパイルエラーになります
- 借用チェッカーは実行時コストなしでメモリ安全性を保証する Rust の中核機能です
