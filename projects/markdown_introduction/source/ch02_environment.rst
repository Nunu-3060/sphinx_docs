書く環境を用意する
==================

この章では、Markdown の文書を書き、その表示結果を確かめる環境を用意する。Markdown のソースはただのテキストファイルなので、メモ帳などのテキストエディタがあれば書ける。ただし、書いた内容がどう表示されるかをすぐに確かめられる環境を用意すると、学習がずっと楽になる。

ファイルの拡張子と文字コード
----------------------------

Markdown の文書は、拡張子を ``.md`` にしたテキストファイルとして保存するのが一般的である。``.markdown`` という拡張子も使えるが、あまり使われない。GitHub やエディタは、拡張子が ``.md`` のファイルを Markdown の文書として扱い、表示結果を見せてくれる。

文字コードは UTF-8 にする。GitHub をはじめ、Markdown を扱うほとんどのツールは UTF-8 を前提にしている。Shift_JIS などの別の文字コードで保存すると、日本語が文字化けすることがある。

ファイル名は自由に付けてよいが、リポジトリの説明に使う ``README.md`` のように、名前に決まった意味があるファイルもある（第 11 章で説明する）。

Markdown が HTML に変換される流れ
---------------------------------

Markdown のソースは、そのままではただのテキストである。見出しが大きな文字で表示されたり、箇条書きに記号が付いたりするのは、変換プログラムが Markdown のソースを HTML に変換し、その HTML をブラウザなどが表示しているからである。

.. graphviz::
   :caption: Markdown が表示されるまでの流れ
   :align: center

   digraph flow {
       rankdir=LR;
       node [shape=box, style="rounded,filled", fillcolor="#f0f4f8"];
       md [label="Markdown のソース\n（.md ファイル）"];
       conv [label="変換プログラム\n（エディタやサービスに内蔵）", fillcolor="#dbeafe"];
       html [label="HTML"];
       view [label="画面に表示\n（ブラウザ・プレビュー）", fillcolor="#dcfce7"];
       md -> conv -> html -> view;
   }

GitHub やエディタは、この変換プログラムを内蔵しており、利用者が意識しなくても自動で変換と表示を行う。変換プログラムによって細部の解釈が異なることがあるのは、第 1 章で説明した方言のためである。

VS Code でプレビューする
------------------------

Markdown を書く環境として、本書では Visual Studio Code（以下、VS Code）を勧める。VS Code は Microsoft が無償で公開しているエディタで、拡張機能を追加しなくても Markdown のプレビュー（表示結果の確認）ができる。

VS Code で ``.md`` ファイルを開いた状態で、次のキー操作を行うとプレビューが表示される。

.. list-table:: VS Code のプレビューのキー操作（Windows、Linux の場合）
   :header-rows: 1
   :widths: 35 65

   * - キー操作
     - 動作
   * - ``Ctrl+Shift+V``
     - プレビューを新しいタブで開く
   * - ``Ctrl+K`` の後に ``V``
     - プレビューをエディタの横に並べて開く

macOS では ``Ctrl`` の代わりに ``Cmd`` キーを使う。エディタの横に並べて開くと、ソースを書き換えるたびにプレビューが更新されるので、記号と表示結果の対応を確かめながら書ける。本書を読みながら記法を試すときは、この方法を使うとよい。

VS Code のプレビューは、本書の表示結果と同じ系統の変換プログラム（markdown-it）を使っており、表示結果は本書とほぼ同じになる。ただし、タスクリスト（第 6 章）のチェックボックスや、GitHub の独自機能（第 10 章）の一部は、VS Code の標準のプレビューでは表示されない。

GitHub で表示を確かめる
-----------------------

GitHub のリポジトリに ``.md`` ファイルを置くと、ファイルを開いたときに表示結果が表示される。ソースを見たいときは、ファイルの画面にある「Code」ボタンに切り替える。

GitHub の Issue やプルリクエストのコメント欄も Markdown で書ける。入力欄の上にある「Preview」タブを押すと、投稿する前に表示結果を確かめられる。リポジトリを持っていなくても、自分の練習用のリポジトリに Issue を作れば、GitHub での表示を気軽に試せる。

ただし、同じ GitHub でも、``.md`` ファイルとコメント欄では改行の扱いが異なる。この違いは第 4 章で説明する。
