ゲームエンジンの選定
====================

ゲームを作る道具は数多くあり、どれを選ぶかで作業の進め方や公開できるプラットフォームが大きく変わる。この章では、道具の種類と選定の基準を説明し、主な製品を紹介する。

ゲームエンジンとフレームワーク
------------------------------

ゲームを作る道具は、大きく\ :term:`ゲームエンジン`\ と\ :term:`フレームワーク`\ に分けられる。

**ゲームエンジン**\ は、ゲーム制作に必要な機能を一式そろえた統合環境である。描画、物理演算、音声、入力、アニメーションなどの実行時の機能に加え、オブジェクトを画面上に配置する\ **エディター**\ 、素材を取り込む仕組み、各プラットフォーム向けの書き出し機能を備える。Unity、Unreal Engine、Godot などがこれに当たる。

**フレームワーク**\ （またはライブラリー）は、描画や入力などの基本機能をプログラムから呼び出せる形で提供するものである。エディターは無いか最小限で、ゲームの構造はプログラマーが自分で組み立てる。本書で使う pygame-ce はこちらに当たる。

.. list-table:: ゲームエンジンとフレームワークの比較
   :header-rows: 1
   :widths: 20 40 40

   * - 観点
     - ゲームエンジン
     - フレームワーク
   * - 制作の進め方
     - エディター上で配置・設定し、必要な部分をスクリプトで書く
     - ほぼすべてをコードで書く
   * - 学習の対象
     - エンジン固有のエディター操作と概念
     - ゲームプログラミングの基礎そのもの
   * - 大規模・3D の制作
     - 向いている
     - 機能を自作する必要があり、負担が大きい
   * - 仕組みの見通し
     - 内部がブラックボックスになりやすい
     - すべて自分で書くので、何が起きているか分かる
   * - 書き出し先
     - PC、モバイル、家庭用ゲーム機など多数
     - 主に PC。ほかはライブラリー次第

どちらが優れているということではない。商業規模の 3D ゲームを作るならゲームエンジンを使うのが現実的である。一方、ゲームループや当たり判定といった基礎を理解する目的では、フレームワークで一から組み立てる経験が役に立つ。基礎を理解していれば、ゲームエンジンのエディターの裏で何が起きているかを推測できるようになる。

選定の基準
----------

道具を選ぶときは、次の観点で比較する。

.. list-table:: 選定の観点
   :header-rows: 1
   :widths: 25 75

   * - 観点
     - 確認すること
   * - 2D か 3D か
     - 2D 専用の機能が充実しているか、3D の描画性能や表現力が必要か
   * - 公開するプラットフォーム
     - Windows、macOS、ブラウザー、スマートフォン、家庭用ゲーム機のうち、どこに書き出せるか
   * - 使用する言語
     - 自分やチームが使える言語か。Python、C#、C++、GDScript、JavaScript など
   * - 費用とライセンス
     - 無料で使えるか、売上に応じた支払い（ロイヤリティー）があるか、作ったゲームを販売できるか
   * - 学習コスト
     - 最初のゲームが動くまでにどれだけ学ぶ必要があるか
   * - 情報の量
     - 公式ドキュメント、チュートリアル、日本語の情報、質問できるコミュニティーがあるか
   * - ジャンルとの相性
     - 作りたいジャンルの定番機能（RPG の戦闘やメニュー、ノベルの文章表示など）が用意されているか

迷った場合は、作りたいゲームに近い作品がそのツールで作られているかを調べるとよい。実例があれば、そのツールで実現できることの裏付けになる。

汎用のゲームエンジン
--------------------

ジャンルを問わず使える代表的なゲームエンジンを次の表に示す。いずれも無料で使い始められる。

.. list-table:: 汎用のゲームエンジン（2026 年 10 月時点）
   :header-rows: 1
   :widths: 16 18 30 36

   * - 名称
     - 主な言語
     - 特徴
     - 費用の概要
   * - `Unity <https://unity.com/>`_
     - C#
     - 2D・3D の両方に対応し、モバイルゲームでの採用例が多い。資料と追加素材（アセットストア）が豊富
     - 直近 12 か月の収益と調達資金が一定額（執筆時点では 20 万米ドル）未満なら無料の Personal プランを使える。超えると有料プランが必要
   * - `Unreal Engine <https://www.unrealengine.com/>`_
     - C++、Blueprint（ビジュアルスクリプト）
     - 高品質な 3D 表現に強く、大規模な商業タイトルで多く使われる
     - 無料で使える。ゲームの総売上が製品ごとに 100 万米ドルを超えると、超えた分に 5 % のロイヤリティーがかかる
   * - `Godot <https://godotengine.org/>`_
     - GDScript、C#
     - オープンソース（MIT ライセンス）。軽量で 2D に強い。GDScript は Python に似た文法を持つ
     - 完全に無料。ロイヤリティーも無い
   * - `GameMaker <https://gamemaker.io/>`_
     - GML（独自言語）
     - 2D 専用。インディーゲームでの採用実績が多い
     - 非商用なら無料。作品を販売するには有償ライセンスが必要

費用の条件は頻繁に改定される。例えば Unity は 2023 年に、ゲームのインストール数に応じて料金を課す制度（Runtime Fee）を発表し、開発者からの強い反発を受けて 2024 年に撤回した。費用の条件は採用を決める前に必ず公式サイトで確認し、将来変わる可能性も考慮しておく。

Python で使えるライブラリー
---------------------------

Python でゲームを作る場合は、次のライブラリーが候補になる。

.. list-table:: Python 向けのゲーム制作ライブラリー
   :header-rows: 1
   :widths: 20 45 35

   * - 名称
     - 特徴
     - 向いている用途
   * - `pygame-ce <https://pyga.me/>`_
     - 長い歴史を持つ pygame から 2023 年に分かれたコミュニティー版。SDL というマルチメディアライブラリーを Python から使えるようにしたもので、描画、入力、音声の基本機能を提供する
     - ゲームプログラミングの基礎の学習、小規模な 2D ゲーム
   * - `Pyxel <https://pypi.org/project/pyxel/>`_
     - レトロゲーム風のゲームエンジン。16 色のパレットや 4 チャンネルの音源などの制約があり、画像と音を作るエディターも内蔵する
     - ドット絵のレトロゲーム、ゲームジャム
   * - `Python Arcade <https://api.arcade.academy/>`_
     - OpenGL を使った 2D ライブラリー。スプライトの一括描画や物理エンジンとの連携機能を持つ
     - スプライトの多い 2D ゲーム

Python のライブラリーは、手軽に始められて学習に向く一方、スマートフォンや家庭用ゲーム機への書き出しは基本的にできない。PC とブラウザー向けの小規模なゲームが主な守備範囲である。

ジャンル特化型のツール
----------------------

特定のジャンルを作ることに特化したツールもある。ジャンルの定番の仕組み（RPG のマップ移動・戦闘・メニュー、ノベルゲームの文章表示・選択肢・セーブなど）が最初から用意されており、プログラムをほとんど書かずに作品を完成させられる。

.. list-table:: ジャンル特化型のツールの例
   :header-rows: 1
   :widths: 25 20 55

   * - 名称
     - ジャンル
     - 特徴
   * - `RPG ツクール <https://tkool.jp/>`_
     - RPG
     - 1990 年代から続く国内で非常に有名なシリーズ。ツール自体は有償だが、作ったゲームを販売することもできる。最近の版（RPG ツクール MZ）は JavaScript のプラグインで機能を拡張できる
   * - `WOLF RPG エディター <https://silversecond.com/WolfRPGEditor/>`_
     - RPG
     - 通称ウディタ。無料で使え、商用利用も可能。システムの自由度が高い
   * - `ティラノビルダー <https://b.tyrano.jp/>`_
     - ノベルゲーム
     - 画面上の操作でノベルゲームを作れる有償ツール。基盤のエンジン（ティラノスクリプト）は無料で公開されている
   * - `Ren'Py <https://www.renpy.org/>`_
     - ノベルゲーム
     - Python を基にしたスクリプトでノベルゲームを作るオープンソースのエンジン。海外での採用例が多い

これらのツールは、作りたいジャンルが合っていれば最短で完成にたどり着ける、非常に有力な選択肢である。RPG ツクールで作られた作品が商業的に成功した例も少なくない。一方で、ジャンルの枠から外れた仕組みを作ろうとすると、かえって手間がかかる。また、ツールが用意した仕組みの上で作るため、ゲームループや当たり判定といった汎用的なプログラミングの基礎を学ぶ機会は少ない。

本書は、プログラミング経験を活かして、ジャンルを問わず応用できる基礎を身に付けることを目的としている。そのため、前の節までは汎用のゲームエンジンと Python のライブラリーを中心に紹介した。作りたいものが RPG やノベルゲームと決まっているなら、ジャンル特化型のツールから始めることを積極的に勧める。

その他の選択肢
--------------

上記のほかにも、次のような選択肢がある。

.. list-table:: その他のゲームエンジン・フレームワーク
   :header-rows: 1
   :widths: 22 20 58

   * - 名称
     - 主な言語
     - 特徴
   * - `Phaser <https://phaser.io/>`_
     - JavaScript、TypeScript
     - ブラウザー向けの 2D フレームワーク。Web 技術の経験を活かせる
   * - `LÖVE <https://love2d.org/>`_
     - Lua
     - 軽量な 2D フレームワーク。pygame-ce と同様に、コードでゲームを組み立てる
   * - `Defold <https://defold.com/>`_
     - Lua
     - 無料の 2D 向けゲームエンジン。書き出したゲームのファイルサイズが小さい
   * - `GDevelop <https://gdevelop.io/>`_
     - （ノーコード）
     - オープンソースのノーコードエンジン。条件と動作を組み合わせる「イベント」で処理を記述する
   * - `Construct <https://www.construct.net/>`_
     - （ノーコード）、JavaScript
     - ブラウザー上で動くノーコードエンジン。継続課金制
   * - `Bevy <https://bevy.org/>`_
     - Rust
     - オープンソースのゲームエンジン。ECS（Entity Component System）という設計を中心に据える

本書での選択
------------

本書の実践では pygame-ce を使う。理由は次のとおりである。

- 読者がすでに知っている Python で書ける。
- エディターの操作を覚える必要が無く、コードを読めばゲームの仕組みがすべて分かる。
- ゲームループ、デルタタイム、当たり判定、シーン管理など、どのゲームエンジンでも通用する基礎を自分の手で実装できる。

本書で 1 本完成させた後、より大きなゲームやスマートフォン向けのゲームを作りたくなったら、Godot や Unity に進むとよい。特に Godot の GDScript は Python に似ているため、移行しやすい。
