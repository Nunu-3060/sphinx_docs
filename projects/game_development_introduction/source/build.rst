ビルドと配布物の作成
====================

完成したゲームをプレイヤーに届けるには、配布できる形にまとめる必要がある。この作業を\ :term:`ビルド`\ と呼ぶ。この章では、Python で作ったゲームを Windows の実行ファイルとブラウザー版にする方法を説明する。

配布物を作る理由
----------------

:doc:`practice`\ のゲームは、Python と pygame-ce がインストールされた環境でしか動かない。しかし、プレイヤーの多くは Python を使っていない。そこで、Python の実行環境とライブラリーをゲームと一緒にまとめ、ダブルクリックするだけで起動できる形にする。

ゲームエンジンを使う場合は、エンジンに書き出し機能が備わっている。Unity ではビルドの設定画面で、Godot ではエクスポートの設定画面で書き出し先のプラットフォームを選べば、そのプラットフォーム向けの配布物が作られる。Python の場合は、以下で説明するツールを使う。

PyInstaller で実行ファイルを作る
--------------------------------

`PyInstaller <https://pyinstaller.org/>`_ は、Python のプログラムを、Python が無い環境でも動く実行ファイルにまとめるツールである。

.. code-block:: powershell
   :linenos:
   :caption: PyInstaller による実行ファイルの作成

   py -m pip install pyinstaller
   py -m PyInstaller --onefile --windowed --name breakout step07_polish.py

2 行目を実行すると、``dist`` フォルダーに ``breakout.exe`` が作られる。主なオプションは次のとおりである。

.. list-table:: PyInstaller の主なオプション
   :header-rows: 1
   :widths: 30 70

   * - オプション
     - 意味
   * - ``--onefile``
     - すべてを 1 つの実行ファイルにまとめる
   * - ``--onedir``
     - 実行ファイルと、必要なファイルを入れたフォルダーを出力する（既定）
   * - ``--windowed``
     - 起動時にコンソールのウィンドウを表示しない
   * - ``--name``
     - 出力する実行ファイルの名前
   * - ``--icon``
     - 実行ファイルのアイコン（.ico ファイル）
   * - ``--add-data``
     - 画像や音声などのファイルを配布物に含める。``"assets:assets"`` のように「元の場所:配布物の中の場所」の形で指定する

``--onefile`` は配布物が 1 ファイルで済むので手軽だが、起動するたびに中身を一時フォルダーに展開するため、起動が遅くなる。また、この形式はマルウェアにも使われることがあるため、ウイルス対策ソフトに誤って検出されることがある。本格的に配布する場合は、``--onedir`` で作ったフォルダーを ZIP にまとめて配布するのが無難である。

なお、PyInstaller は実行した OS 向けの実行ファイルしか作れない。macOS 版や Linux 版を作るには、それぞれの OS 上で実行する。

アセットの読み込み
~~~~~~~~~~~~~~~~~~

``--add-data`` で含めたファイルは、実行時には実行ファイルの場所とは別のフォルダーに置かれる。そのフォルダーの場所は ``sys._MEIPASS`` に入っているので、アセットを読み込むときは次のような関数で場所を求める。

.. code-block:: python
   :linenos:
   :caption: 配布物の中のアセットの場所を求める関数

   import sys
   from pathlib import Path


   def resource_path(relative: str) -> Path:
       """アセットの場所を返す。PyInstaller の配布物でも、通常の実行でも使える。"""
       base = Path(getattr(sys, "_MEIPASS", Path(__file__).parent))
       return base / relative

``pygame.image.load(resource_path("assets/sprites.png"))`` のように使う。通常の Python で実行した場合は ``sys._MEIPASS`` が無いので、スクリプトのあるフォルダーが基準になる。

コード署名
~~~~~~~~~~

インターネットから入手した実行ファイルを起動すると、Windows は「Windows によって PC が保護されました」という警告（SmartScreen）を表示することがある。発行元を証明する\ :term:`コード署名`\ が無い実行ファイルや、まだ利用実績の少ない実行ファイルに対して表示される。この警告を避けるには、コード署名用の証明書を購入して署名する必要があるが、費用がかかる。個人の小規模な配布では、警告が出ることと、「詳細情報」から「実行」を選べば起動できることを、配布ページに書いておくのが現実的である。

macOS では、Apple Developer Program に登録して署名し、さらに Apple の公証（ノータリゼーション）を受けないと、通常の操作では起動できない。macOS 向けに本格的に配布する場合は、この手続きも計画に入れておく。

pygbag でブラウザー版を作る
---------------------------

`pygbag <https://pygame-web.github.io/>`_ は、pygame-ce のゲームをブラウザーで動かせるようにするツールである。Python の実行環境を WebAssembly（ブラウザー上で高速に動くプログラムの形式）に変換したものを使い、ゲームのコードをブラウザー上で実行する。ブラウザー版はダウンロードやインストールが不要で、遊んでもらうまでの手間が最も少ない。

pygbag で動かすには、次の 2 つの条件を満たす必要がある。

- ゲームのフォルダーに ``main.py`` という名前で起動用のファイルを置く。
- メインループを ``async def`` で書き、フレームごとに ``await asyncio.sleep(0)`` を呼ぶ。

:doc:`practice`\ の Step 7 は、2 つ目の条件を満たすように書いてある。そのため、次のようにフォルダーを作ってファイルをコピーするだけで準備は整う。

.. code-block:: powershell
   :linenos:
   :caption: pygbag によるブラウザー版の作成

   py -m pip install pygbag
   mkdir breakout_web
   copy step07_polish.py breakout_web\main.py
   py -m pygbag breakout_web

4 行目を実行すると、ブラウザー版が作られ、確認用の Web サーバーが起動する。表示されるアドレス（通常は ``http://localhost:8000``\ ）をブラウザーで開くと、ゲームを遊べる。作られたファイルは ``breakout_web\build\web`` フォルダーに出力される。

ブラウザーでは、利用者が画面をクリックするなどの操作をするまで音を鳴らせない決まりになっている。そのため、pygbag のゲームは、起動時にクリックを求める画面を表示してから始まる。

pygbag は比較的新しいツールで、使い方が変わることがある。うまく動かない場合は、公式のドキュメントで最新の情報を確認してほしい。

公開前の確認
------------

配布物ができたら、公開する前に次の点を確認する。

.. list-table:: 公開前の確認項目
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 確認すること
   * - 別の環境での起動
     - Python が入っていない PC や、別のブラウザーで起動できるか
   * - 画面の大きさ
     - 解像度の異なるモニターや、画面の拡大率を変えた環境で表示が崩れないか
   * - 入力
     - キーボードの配列の違い（日本語配列と英語配列）で操作できないキーが無いか
   * - 音
     - 音量が大きすぎないか。音声機器が無い環境でも起動できるか
   * - 終了
     - ウィンドウの閉じるボタン、Esc キーなどで正しく終了するか
   * - デバッグ用の機能
     - 無敵やステージ選択などのデバッグ用の操作が無効になっているか
   * - クレジット
     - 使用した素材やフォントのクレジットとライセンスの表記が含まれているか
