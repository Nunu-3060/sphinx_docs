他の実装との違い
================

正規表現の基本的な構文は多くの実装で共通しているが、細部は実装ごとに異なる。この章では、Python の ``re`` で学んだ知識を他の環境で使うときに注意すべき違いをまとめる。

正規表現の系統
--------------

現在使われている正規表現の実装は、おおまかに次の 3 つの系統に分けられる。

.. list-table:: 正規表現の主な系統
   :header-rows: 1
   :widths: 25 40 35

   * - 系統
     - 特徴
     - 主な実装
   * - POSIX（:term:`BRE`、:term:`ERE`）
     - UNIX のツールの標準。機能は少ない。選択では最も長い一致を選ぶ
     - grep、sed、awk
   * - Perl 系
     - バックトラック方式。先読み、後方参照など機能が豊富
     - Python の ``re``、:term:`PCRE`、JavaScript、Java、.NET、Ruby
   * - 線形時間保証
     - バックトラックを使わず、入力の長さに比例する時間で照合する。後方参照や先読みは使えない
     - RE2、Go の ``regexp``、Rust の ``regex``

Python の ``re`` は Perl 系に属する。同じ系統の実装どうしでは、本書で説明した構文の大部分がそのまま使える。

grep と sed（POSIX）
--------------------

grep と sed は、既定では :term:`BRE`\ （基本正規表現）を使う。BRE では ``(``、``)``、``{``、``}`` をメタ文字として使うときに、逆に ``\`` を付ける必要がある。``+``、``?``、``|`` は POSIX の BRE には含まれていないが、GNU 版の grep と sed では ``\+``、``\?``、``\|`` として使える。

``-E`` オプションを指定すると、:term:`ERE`\ （拡張正規表現）になり、Python とほぼ同じ書き方ができる。特別な理由がなければ ``-E`` を使うとよい。

.. code-block:: console
   :linenos:
   :caption: grep と sed の使用例

   # BRE (GNU 拡張の \| を使用)
   grep 'ERROR\|WARN' sample.log

   # ERE: 日付、時刻の後に ERROR が続く行
   grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9:]+ ERROR' sample.log

   # sed で日付を「日/月/年」の順に並べ替える
   sed -E 's/^([0-9]{4})-([0-9]{2})-([0-9]{2})/\3\/\2\/\1/' sample.log

POSIX の正規表現には ``\d`` がない。数字は ``[0-9]`` か、POSIX 文字クラス ``[[:digit:]]`` で表す。同様に ``[[:alpha:]]``\ （英字）、``[[:space:]]``\ （空白文字）などがある。GNU grep で ``\d`` と書くと、数字ではなく ``d`` という文字として扱われるので注意する（新しい版では警告が出る）。なお、GNU grep の ``-P`` オプションを使うと、PCRE の構文が使える。

JavaScript
----------

JavaScript は、Python と同じ Perl 系の構文を持つが、次の点が異なる。

* パターンを ``/.../`` で囲んだリテラルとして書き、フラグは後ろに付ける（例: ``/error/i``）。
* すべての一致を対象にするには ``g`` フラグを指定する。
* 名前付きグループは ``(?<name>...)``、後方参照は ``\k<name>`` と書く。
* 置換文字列でのグループの参照は ``$1`` や ``$<name>`` と書く。
* ``$`` は、``m`` フラグがなければ文字列の末尾だけに一致し、末尾の改行の直前には一致しない。
* ``\d`` と ``\w`` は常に ASCII 文字だけに一致する。

.. code-block:: javascript
   :linenos:
   :caption: JavaScript での使用例

   const m = "2026-10-19".match(/(?<year>\d{4})-(?<month>\d{2})/);
   console.log(m.groups.year);  // 2026

   const s = "2026-10-19".replace(/(\d{4})-(\d{2})-(\d{2})/, "$3/$2/$1");
   console.log(s);  // 19/10/2026

VS Code などのエディターの検索と置換も、多くは JavaScript と同じ構文を使う。置換文字列では ``\1`` ではなく ``$1`` と書く点に注意する。

PCRE
----

:term:`PCRE`\ （Perl Compatible Regular Expressions）は、Perl の正規表現と互換性を持つ C 言語のライブラリである。PHP の ``preg_*`` 関数、GNU grep の ``-P`` オプションなど、多くのソフトウェアで使われている。Python の ``re`` とほぼ同じ構文に加えて、パターンの再帰 ``(?R)`` や、一致の開始位置を後ろにずらす ``\K`` など、Python の ``re`` にない機能を持つ。

Python の regex モジュール
--------------------------

サードパーティの ``regex`` モジュールは、``re`` と互換性を保ちながら機能を拡張したモジュールである。``pip install regex`` でインストールでき、``import regex`` として ``re`` と同じように使える。主な追加機能は次のとおりである。

* 長さの決まらない後読み（例: ``(?<=\d+円)``）
* Unicode のプロパティを指定する ``\p{...}``\ （例: 漢字に一致する ``\p{Han}``、ひらがなに一致する ``\p{Hiragana}``）
* 指定した数までの誤りを許して照合する、あいまい一致
* 照合に時間の上限を設ける ``timeout`` 引数

``re`` で足りない機能が必要になったときは、このモジュールを検討するとよい。

RE2 と線形時間のエンジン
------------------------

RE2 は Google が開発した正規表現ライブラリで、入力の長さに比例する時間で照合することを保証する。そのため、第 11 章で説明した破滅的バックトラックが原理的に起こらない。Go の ``regexp`` パッケージや Rust の ``regex`` クレートも同じ設計である。

その代わり、後方参照と、先読みや後読みは使えない。後方参照を含むパターンの照合は、一般に線形時間では行えないことが知られている。先読みと後読みは、原理的には線形時間で実現する方法もあるが、RE2 などは対応していない。外部からの入力に任意のパターンを適用するような、安全性が重視される場面に向いている。

まとめ
------

* 正規表現の実装は、POSIX、Perl 系、線形時間保証の 3 系統に大別できる。Python の ``re`` は Perl 系である。
* 名前付きグループの書き方、``\d`` の範囲、``\Z`` の意味などは実装によって異なる。
* grep と sed では ``-E`` を指定して ERE を使い、``\d`` の代わりに ``[0-9]`` を使う。
* JavaScript とエディターの置換では、グループを ``$1`` で参照する。
* ``re`` にない機能が必要なら ``regex`` モジュールを、安全性が重要なら RE2 などの線形時間のエンジンを検討する。
