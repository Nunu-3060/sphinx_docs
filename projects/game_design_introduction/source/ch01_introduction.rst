はじめに
========

本書の目的
----------

本書の目的は、ゲームを作った経験のない読者が、ゲームデザインとレベルデザインの基本的な考え方を身に付け、小さなゲームとそのレベルを自分で設計できるようになることである。

ゲームの「面白さ」は、才能やセンスだけで生まれるものと思われがちである。しかし、実際のゲーム制作の現場では、面白さを言葉で説明できる形に分解し、仮説を立て、試作して確かめ、改善するという地道な作業が繰り返されている。これはソフトウェアの設計や実験の進め方とよく似ている。本書では、エンジニアが慣れている考え方（状態機械、フィードバック、確率と期待値、シミュレーション、グラフ探索など）を足がかりに、ゲームデザインの考え方を説明する。

対象読者と前提知識
------------------

本書は次のような読者を想定している。

* ゲーム制作は未経験だが、Python などでプログラムを書いた経験があるエンジニア
* 情報系・機械系・電気系などの工学系の大学生

前提知識として、Python の基本的な文法（関数、クラス、リスト、辞書）が分かればよい。サンプルコードは型ヒント付きで書いてあるが、型ヒントの知識が無くても読める。数学は高校程度の確率と関数のグラフが分かれば十分である。

ゲームエンジン（Unity、Unreal Engine、Godot など）の使い方は扱わない。本書で学ぶ考え方は、どのゲームエンジンを使う場合にも、またボードゲームやカードゲームのようなアナログゲームにもそのまま使える。

ゲームデザインとレベルデザイン
------------------------------

本書の題目にある 2 つの言葉は、次のように使い分ける。

.. list-table:: ゲームデザインとレベルデザイン
   :header-rows: 1
   :widths: 20 40 40

   * - 項目
     - ゲームデザイン
     - レベルデザイン
   * - 決めるもの
     - ゲームの目的、ルール、操作、数値、成長や報酬の仕組み
     - ルールを遊ぶための具体的な場所と、その中での体験の順番
   * - 問い
     - このゲームでは何をして遊ぶのか。なぜそれが面白いのか
     - その遊びを、どの順番で、どこで、どのくらいの難しさで体験させるか
   * - 成果物の例
     - コアループの図、ルールの仕様、パラメーターの表
     - マップ、敵やアイテムの配置、レベルの流れを表す図
   * - 例（横スクロールのアクションゲーム）
     - ジャンプの高さ、敵を踏むと倒せるというルール、残り人数の仕組み
     - 最初のレベルで穴をいくつ、どの間隔で置くか。敵をどこで初めて登場させるか

ここでいう「レベル」は、ゲームの中の 1 つの面（ステージ、マップ、ダンジョンの 1 階層など）を指す。キャラクターの強さを表す「レベル」とは意味が異なる。本書では、面を指す場合に「レベル」、キャラクターの強さを指す場合に「キャラクターのレベル」と書いて区別する。

ゲームデザインとレベルデザインは独立した作業ではない。ルールが決まらなければレベルは作れず、レベルを作ってみて初めてルールの問題点に気付くことも多い。本書でも前半でゲームデザインを、後半でレベルデザインを扱うが、両者を行き来しながら読み進めてほしい。

制作現場での役割分担
--------------------

商業ゲームの開発では、次のような職種が分担して作業する。小規模な開発では、1 人が複数の役割を兼ねることも多い。

.. list-table:: ゲーム開発の主な職種
   :header-rows: 1
   :widths: 25 75

   * - 職種
     - 主な仕事
   * - ゲームデザイナー
     - ゲームのルール、システム、数値を設計し、仕様書にまとめる。ゲームプランナーとも呼ばれる
   * - レベルデザイナー
     - マップやステージを作り、敵やアイテムを配置して、プレイヤーの体験を組み立てる
   * - プログラマー
     - ゲームの処理、ツール、データの仕組みを実装する
   * - アーティスト
     - キャラクター、背景、エフェクト、UI などの見た目を作る
   * - サウンドデザイナー
     - 効果音や音楽を作り、ゲームに組み込む
   * - QA（品質保証）
     - テストを行い、不具合や遊びにくい箇所を見つけて報告する

エンジニアがゲームデザインを学ぶ意義
------------------------------------

プログラマーとして開発に参加する場合でも、ゲームデザインの知識は役に立つ。

* 仕様書に書かれていない部分（入力の受け付け方、当たり判定の大きさ、乱数の扱いなど）は、実装する人が決めることが多い。その小さな判断が操作感や公平感を大きく左右する。
* ゲームデザイナーと同じ言葉で話せると、仕様の意図を正しく理解し、よりよい実装を提案できる。
* パラメーターを調整するツールや、シミュレーションで数値を検証する仕組みは、エンジニアの得意分野である。

本書の構成
----------

本書は次のように構成されている。

.. list-table:: 本書の構成
   :header-rows: 1
   :widths: 15 30 55

   * - 章
     - 題目
     - 内容
   * - 第 1 章
     - はじめに
     - 本書の目的、対象読者、サンプルの実行環境
   * - 第 2 章
     - ゲームとは何か
     - ゲームの定義、遊びの分類、MDA フレームワーク
   * - 第 3 章
     - 楽しさとプレイヤー
     - 楽しさの種類、プレイヤータイプ、動機付け、フロー理論、意味のある選択
   * - 第 4 章
     - ゲームをシステムとして捉える
     - コアループ、状態機械、資源の流れ、フィードバックループ、創発
   * - 第 5 章
     - ゲームバランス
     - 成長曲線、コスト、非推移的な関係、確率と期待値、シミュレーションによる検証
   * - 第 6 章
     - 難易度と学習
     - 難易度曲線、学習の段階、失敗の設計、動的難易度調整、アクセシビリティ
   * - 第 7 章
     - 操作感とフィードバック
     - 応答性、ジャンプの設計、視覚・聴覚のフィードバック、UI
   * - 第 8 章
     - レベルデザインの基礎
     - レベルの役割、目標の提示、導線、ゲーティング、ブロックアウト
   * - 第 9 章
     - レベルの構成とペーシング
     - 新しい要素の見せ方、緊張と緩和、配置、レベルの構造、グラフによる検証
   * - 第 10 章
     - 手続き型生成
     - ランダムウォーク、セル・オートマトン、BSP、生成結果の検証
   * - 第 11 章
     - プロトタイピングとプレイテスト
     - 試作の進め方、プレイテストの方法、ログの分析、改善の反復
   * - 第 12 章
     - 総合演習
     - 小さなパズルゲームを題材に、設計からプレイテストまでを一通り行う

付録には、設計文書のテンプレート、サンプルコードの一覧、用語集、参考文献を収めた。

各章の最後には演習を設けた。演習には決まった正解が無いものが多い。自分の答えを書き出し、可能であれば他の人と見せ合うと理解が深まる。

サンプルコードの実行環境
------------------------

サンプルコードは次の環境で動作を確認している。

.. list-table:: 動作を確認した環境
   :header-rows: 1
   :widths: 30 70

   * - ソフトウェア
     - バージョン
   * - OS
     - Windows 11
   * - Python
     - 3.14（3.10 以上で動作する書き方をしている）
   * - pygame-ce
     - 2.5
   * - matplotlib
     - 3.11
   * - Pillow
     - 13.0

必要なライブラリは次のコマンドでインストールできる。

.. code-block:: console
   :linenos:

   python -m pip install pygame-ce matplotlib pillow

pygame-ce は、ゲーム制作用のライブラリ pygame から派生したコミュニティ版である。本家の pygame と同じ ``import pygame`` で使える。両方を同時にインストールすると衝突するため、pygame がインストール済みの場合は先にアンインストールしておく。

グラフや画像の中の日本語は、Windows に標準で入っている游ゴシックまたはメイリオで表示する。

サンプルコードは :doc:`appendix_examples` からダウンロードできる。コードの検査の方法も同じページにまとめた。
