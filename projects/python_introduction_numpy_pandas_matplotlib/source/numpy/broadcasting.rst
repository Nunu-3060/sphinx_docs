ブロードキャスト
==================

形状が異なる配列同士でも、一定のルールに従って自動的に形状を揃えてから演算が行われることがあります。これを「ブロードキャスト」と呼びます。

.. code-block:: python

   import numpy as np

   m: np.ndarray = np.array([[1, 2, 3], [4, 5, 6]])
   v: np.ndarray = np.array([10, 20, 30])

   m + v
   # array([[11, 22, 33],
   #        [14, 25, 36]])
   # v (shape (3,)) が m の各行に対して繰り返し適用される

スカラー（単一の値）との演算は、ブロードキャストの最も単純な例です。

.. code-block:: python

   m * 2
   # array([[ 2,  4,  6],
   #        [ 8, 10, 12]])

ブロードキャストにより、``for`` ループを書かずに配列全体へ効率的に演算を適用できます。

ブロードキャストのルール
---------------------------

どのような形状同士なら演算できるのかは、次のルールで判定されます。

1. 2 つの配列の次元数が異なる場合は、次元数が少ない方の ``shape`` の先頭に 1 を補って次元数を揃えます。
2. 2 つの ``shape`` を、末尾（右側）の次元から順に比較します。
3. 比較した次元のサイズが「等しい」か、「どちらか一方が 1」であれば、その次元は演算可能です。サイズが 1 の次元は、もう一方のサイズに合わせて拡張されます。
4. すべての次元でこの条件を満たす場合にのみ、ブロードキャストが成立します。1 つでも条件を満たさない次元があると、``ValueError`` になります。

先ほどの ``m + v`` の例では、``m`` の ``shape`` は ``(2, 3)``、``v`` の ``shape`` は ``(3,)`` です。``v`` は次元数が 1 つ少ないため、先頭に 1 が補われて ``(1, 3)`` として扱われます。末尾から比較すると 3 と 3 は等しく、先頭の次元は 2 と 1 で一方が 1 のため、条件を満たしてブロードキャストが成立します。

ブロードキャストできない例
-----------------------------

ルールを満たさない形状同士で演算しようとすると、``ValueError`` になります。

.. code-block:: python

   m: np.ndarray = np.array([[1, 2, 3], [4, 5, 6]])
   v: np.ndarray = np.array([1, 2])

   m + v
   # ValueError: operands could not be broadcast together with shapes (2,3) (2,)

``m`` の ``shape`` は ``(2, 3)``、``v`` の ``shape`` は ``(2,)`` です。末尾の次元を比較すると 3 と 2 になり、どちらも 1 ではなく値も異なるため、拡張できずにエラーになります。エラーが発生したときは、まず演算しようとしている配列同士の ``shape`` を確認する習慣をつけると原因を特定しやすくなります。
