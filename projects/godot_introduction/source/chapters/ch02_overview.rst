=====================
第 2 章　Godot の概要
=====================

本章では、ゲームエンジンとは何かを説明したあと、Godot の特徴、対応するプログラミング言語、他のゲームエンジンとの違いを紹介する。

ゲームエンジンとは
==================

ゲームは、画像の描画、音の再生、キーボードやゲームパッドからの入力、物体どうしの衝突判定など、多くの処理を毎秒数十回のペースで繰り返すプログラムである。これらをすべて一から作るのは大変なので、通常はゲームエンジンを使う。

ゲームエンジンは、ゲームに共通して必要な機能をまとめたソフトウェアである。多くのゲームエンジンは、次の 2 つの要素からなる。

* **ランタイム**：ゲームの実行中に動くプログラム。描画、物理演算、音声、入力などの処理を受け持つ。
* **エディター**：ゲームを作るための GUI ツール。画面に物体を配置したり、スクリプトを書いたり、ゲームを試しに動かしたりできる。

Web 開発にたとえると、ランタイムはフレームワークとそのライブラリ、エディターは IDE に近い。開発者はゲーム固有の部分（キャラクターの動き、ルール、画面構成など）を作ることに集中できる。

Godot の歴史
============

Godot は、Juan Linietsky 氏と Ariel Manzur 氏が開発していた社内向けのエンジンを、2014 年に MIT ライセンスで公開したことに始まる。その後は世界中の開発者が参加するオープンソースプロジェクトとして開発が続いている。2023 年に公開された Godot 4.0 で描画エンジンやスクリプト言語が大きく刷新され、本書で扱う 4.7 はその流れをくむバージョンである。

Godot の特徴
============

Godot には次のような特徴がある。

.. list-table:: Godot の主な特徴
   :header-rows: 1
   :widths: 25 75

   * - 特徴
     - 説明
   * - 無料でオープンソース
     - MIT ライセンスで公開されている。作ったゲームを販売しても、使用料やロイヤリティはかからない。エンジンのソースコードを読んだり改造したりもできる。
   * - 軽量
     - Windows 版のエディターは 200 MB 弱の実行ファイル 1 つで動き、インストールは不要である。起動も速い。
   * - ノードとシーン
     - ゲームを「ノード」という部品の木構造で組み立てる。部品のまとまりは「シーン」として保存し、別のシーンの中で再利用できる。詳しくは :ref:`ch05` で説明する。
   * - 専用の 2D エンジン
     - 2D の描画と物理は 3D とは別に実装されており、座標の単位はピクセルである。3D 空間にカメラを固定して 2D に見せる方式ではないので、2D ゲームを素直に作れる。
   * - 統合されたエディター
     - シーンの編集、スクリプトの編集、デバッガー、アニメーションの編集、シェーダーの編集などが 1 つのエディターにまとまっている。エディター自身も Godot の UI 機能で作られている。
   * - 多くのプラットフォームに対応
     - Windows、macOS、Linux、Android、iOS、Web ブラウザー向けにゲームを書き出せる。家庭用ゲーム機向けは、各社との契約が必要なため公式には提供されておらず、移植を請け負う企業を通じて対応する。

対応するプログラミング言語
==========================

Godot のゲームのロジックは、主に次のいずれかの言語で書く。

.. list-table:: Godot で使える主なプログラミング言語
   :header-rows: 1
   :widths: 20 40 40

   * - 言語
     - 特徴
     - 向いている用途
   * - GDScript
     - Godot 専用のスクリプト言語。Python に似た文法で、エンジンと密に統合されている。追加のインストールは不要。
     - ほとんどのゲームのロジック。本書はこの言語を使う。
   * - C#
     - .NET 版の Godot で使える。静的型付けで、.NET のライブラリを利用できる。
     - C# や Unity の経験がある場合、大規模なプロジェクト
   * - C++ など（GDExtension）
     - エンジンを再ビルドせずに、ネイティブコードのライブラリとして機能を追加する仕組み。
     - 処理速度が重要な部分、既存の C/C++ ライブラリとの連携

GDScript はインデントでブロックを表す、動的型付けを基本とするがオプションで型を書ける、など Python に似た点が多い。Python の経験がある読者は短期間で書けるようになるだろう。一方で、整数の割り算の結果や、ループ変数の扱いなどに細かな違いがある。これらは :ref:`ch06` と :ref:`ch07` で説明する。

なお、Godot のエディター自体は C++ で書かれている。GDScript で書いたコードは、エンジンの C++ の機能を呼び出して動く。重い処理（描画、物理演算など）はエンジン側で行われるため、GDScript の実行速度が Python 程度であっても、多くのゲームでは問題にならない。

他のゲームエンジンとの比較
==========================

よく比較される Unity、Unreal Engine との違いを、おおまかにまとめる。各エンジンの料金体系は変わることがあるので、利用する際は公式サイトで最新の情報を確認してほしい。

.. list-table:: 主なゲームエンジンの比較
   :header-rows: 1
   :widths: 20 26 27 27

   * - 項目
     - Godot
     - Unity
     - Unreal Engine
   * - ライセンス
     - MIT ライセンス（無料、オープンソース）
     - 独自のライセンス。規模に応じた有料プランがある。
     - 独自のライセンス。ソースコードは公開されているが、売上が一定額を超えるとロイヤリティがかかる。
   * - 主な言語
     - GDScript、C#
     - C#
     - C++、Blueprint（ビジュアルスクリプト）
   * - 得意な分野
     - 2D ゲーム、小～中規模の 3D ゲーム
     - 2D、3D、モバイルゲームなど幅広い
     - 高品質なグラフィックスの 3D ゲーム
   * - エディターの大きさ
     - 小さい（インストール不要）
     - 大きい（専用のインストーラーで管理）
     - 非常に大きい

Godot は特に、2D ゲームや個人・小規模チームでの開発、学習用途に向いている。3D の機能も年々充実しているが、最先端のグラフィックスを追求する大規模な 3D ゲームでは、Unreal Engine などのほうが資料や実績が多い。

Godot でゲームを作る流れ
========================

Godot でのゲーム制作は、おおむね次の流れで進む。本書の章立ても、この流れに沿っている。

.. graphviz::
   :caption: Godot でゲームを作る流れ

   digraph flow {
     rankdir=LR;
     node [shape=box, style="rounded,filled", fillcolor="#e8f0fe", fontsize=11];
     edge [fontsize=10];
     project [label="プロジェクトを作る\n（第 3 章）"];
     scene [label="ノードを配置して\nシーンを作る\n（第 5 章）"];
     script [label="スクリプトで\n動きを付ける\n（第 6 章～）"];
     run [label="実行して確かめる\n（第 18 章）"];
     export [label="エクスポートして\n配布する\n（第 19 章）"];
     project -> scene -> script -> run -> export;
     run -> scene [label="修正", style=dashed, constraint=false];
   }

シーンを作り、スクリプトを書き、実行して確かめる、という作業を何度も繰り返してゲームを完成させる。Godot はエディターからすぐにゲームを実行できるので、この繰り返しを短い間隔で回せる。
