======================
第 19 章　エクスポート
======================

作ったゲームを、Godot を持っていない人にも遊んでもらうには、プラットフォームごとの実行形式に書き出す必要がある。これをエクスポート（export）と呼ぶ。本章では、Windows 向けと Web ブラウザー向けのエクスポートの手順と、配布する前に確認すべきことを説明する。

エクスポートの仕組み
====================

エクスポートしたゲームは、次の 2 つの部分からなる。

* **実行ファイル**：Godot のランタイム（エディターの機能を除いたエンジン本体）。プラットフォームごとに用意された「エクスポートテンプレート」から作られる。
* **PCK ファイル**：プロジェクトのシーン、スクリプト、画像などをまとめたデータ。Windows 向けでは、実行ファイルに埋め込んで 1 つのファイルにすることもできる。

エクスポートテンプレートは、エディター本体とは別にダウンロードする必要がある。テンプレートのバージョンは、エディターのバージョン（本書では 4.7.2）と一致していなければならない。

エクスポートテンプレートを入手する
==================================

#. エディターの「エディター」→「エクスポートテンプレートの管理...」を開く。
#. ダウンロード元のミラーを選び、ダウンロードしてインストールするボタンを押す。

テンプレートはすべてのプラットフォーム向けのものがまとめて入っているので、ファイルが大きく、ダウンロードに時間がかかる。インターネットに接続できない環境では、公式サイトから ``.tpz`` ファイルを別途ダウンロードし、同じ画面の「ファイルからインストール」でインストールする。

エクスポートのプリセットを作る
==============================

どのプラットフォームに、どのような設定で書き出すかを「プリセット」として登録する。

#. 「プロジェクト」→「エクスポート...」を開く。
#. 「追加...」を押し、プラットフォームを選ぶ（例：「Windows Desktop」）。
#. 右側に表示される設定を確認し、「エクスポート先のパス」に出力するファイルの名前を指定する。

プリセットの内容は、プロジェクトのフォルダーの ``export_presets.cfg`` に保存される。

Windows 向けにエクスポートする
==============================

「Windows Desktop」のプリセットでは、次の設定をよく使う。

.. list-table:: Windows Desktop の主な設定
   :header-rows: 1
   :widths: 35 65

   * - 設定
     - 内容
   * - 実行可能
     - オンにすると、エディターの実行ボタンの横のメニューから、このプリセットで直接実行（デプロイ）できる。
   * - 組み込みPCK
     - オンにすると、PCK ファイルを実行ファイルに埋め込み、1 つの ``.exe`` ファイルにする。
   * - リソースの変更
     - オンにすると、実行ファイルのアイコンやバージョン情報を、プロジェクトの設定に合わせて書き換える。
   * - アプリケーションのアイコン、製品名、バージョンなど
     - 実行ファイルのプロパティに表示される情報

設定を確認したら、「プロジェクトのエクスポート...」を押してファイルの保存先を選ぶ。保存のダイアログにある「デバッグ付きエクスポート」は、オフにするとリリース版としてエクスポートする。配布するときはオフにする。

リリース版では、``assert()`` やデバッガーとの接続が無効になり、少し速く動く。エラーが起きてもゲームは止まらず、エラーを出力したうえで処理を続ける（:ref:`ch07`）。

.. note::

   エクスポートしたゲームの ``res://`` は読み取り専用である。実行中にファイルを書き込む処理は、``user://`` を使っていれば問題なく動く（:ref:`ch15`）。エディターでは動いたのにエクスポートすると保存できない場合は、保存先が ``res://`` になっていないか確認する。

Web ブラウザー向けにエクスポートする
====================================

「Web」のプリセットでエクスポートすると、ブラウザーで遊べる形式で出力される。出力は ``.html``、``.js``、``.wasm``\ （WebAssembly のエンジン本体）、``.pck`` などのファイルの組である。Web 向けのエクスポートは互換性レンダラー（:ref:`ch03`）でのみ動作する。

出力された ``.html`` ファイルをダブルクリックしてもゲームは動かない。セキュリティの制約のため、Web サーバーから配信する必要がある。手元で確認するには、Web のプリセットで「実行可能」をオンにし、エディター右上の実行ボタンの横に表示される「ブラウザで実行」のボタンを使う。エディターが一時的な Web サーバーを起動し、既定のブラウザーでゲームを開く。

itch.io などのゲーム投稿サイトに公開する場合は、出力したファイルを zip にまとめてアップロードする。プリセットの「Thread Support」（スレッドのサポート）がオフになっていれば、特別なサーバーの設定（クロスオリジン分離）を必要とせずに動作する。投稿する前に確認しておく。

.. warning::

   :ref:`ch13` で説明したとおり、Web 向けにエクスポートしたゲームでは OS のフォントを使えないため、日本語の文字が表示されないことがある。日本語を表示するゲームは、日本語のフォントをプロジェクトに入れて、テーマに設定しておく。

コマンドラインからエクスポートする
==================================

プリセットを作っておけば、エディターを開かずにコマンドラインからエクスポートすることもできる。継続的インテグレーション（CI）で自動的にビルドする場合に使う。

.. code-block:: console
   :linenos:

   Godot_v4.7.2-stable_win64_console.exe --headless --path プロジェクトのフォルダー --export-release "Windows Desktop" build/game.exe

``--export-release`` の後には、プリセットの名前と出力先のパスを指定する。デバッグ版を出力する場合は ``--export-debug`` を使う。

配布する前に確認すること
========================

.. list-table:: 配布前のチェックリスト
   :header-rows: 1
   :widths: 35 65

   * - 項目
     - 確認する内容
   * - 動作確認
     - エクスポートしたゲームを、Godot をインストールしていない別の PC で起動して確認する。
   * - セーブデータの保存先
     - ``user://`` に保存しているか。
   * - フォント
     - 日本語などの文字が、フォントを含めて正しく表示されるか。
   * - ライセンスの表記
     - 使った素材（画像、音声、フォント）のライセンスに従ってクレジットを表記しているか。Godot 自体も MIT ライセンスなので、著作権表示とライセンス文をゲームのクレジットなどに含める必要がある。
   * - 不要なファイル
     - テスト用のシーンや素材が含まれていないか。プリセットの「リソース」タブで、エクスポートするファイルを絞り込める。

Godot のライセンス文は、エディターの「ヘルプ」→「Godotについて...」で開くダイアログや、公式サイトの「License」のページで確認できる。
