6 章　デザイン
==============

この章では、ゲームの面白さを説明し、設計するための概念を紹介する。ここで説明する概念は、8 章で実際にゲームを分析するときの道具になる。

面白さとは何か
--------------

ゲームの面白さを 1 つの理論で説明することはできないが、よく引用される考え方が 3 つある。

**フロー**
   心理学者ミハイ・チクセントミハイは、人が時間を忘れて活動に没頭している状態を\ :term:`フロー`\ と呼んだ（『フロー体験　喜びの現象学』1990）。フローは、課題の難しさと本人の技能がつり合っているときに生じやすい。課題が技能より難しすぎると不安を感じ、易しすぎると退屈を感じる。ゲームでは、プレイヤーの上達に合わせて課題を難しくしていくことで、フローの状態を保とうとする。

**楽しさは学習である**
   ゲームデザイナーのラフ・コスターは『「おもしろい」のゲームデザイン』（2004）で、ゲームの楽しさの正体は、パターンを学び、身に付けることだと論じた。パターンを完全に理解すると、そのゲームは退屈になる。大人が三目並べで遊ばなくなるのは、引き分けにする方法をすでに学び終えているからである（5 章）。

**意味のある選択**
   ゲームデザイナーのシド・マイヤーは「ゲームとは興味深い選択の連続である」と述べたとされる。選択肢が 1 つしかない、どれを選んでも結果が同じ、どれが正解か明らかである、といった選択は、プレイヤーにとって意味が無い。意味のある選択とは、それぞれの選択肢に利点と欠点があり、結果がゲームの展開に影響するものである。

1 章の作業定義で「選択を重ねる」をゲームの条件に含めたのは、この考え方による。

MDA フレームワーク
------------------

:term:`MDA フレームワーク`\ は、ロビン・ハニキー、マーク・ルブラン、ロバート・ズベックが 2004 年に発表した、ゲームを 3 つの層に分けて考える枠組みである。

.. list-table:: MDA の 3 つの層
   :header-rows: 1
   :widths: 20 40 40

   * - 層
     - 意味
     - すごろくの例
   * - メカニクス（Mechanics）
     - ルール、データ、アルゴリズム。設計者が直接決めるもの
     - サイコロを振り、出た目だけ進む。先にゴールに着いた人が勝つ
   * - ダイナミクス（Dynamics）
     - メカニクスが、プレイヤーの行動と組み合わさって実際に生む振る舞い
     - 抜きつ抜かれつの展開。大差がついても逆転が起こりうる
   * - エステティクス（Aesthetics）
     - プレイヤーが感じる感情的な反応
     - サイコロを振る瞬間のどきどき感。勝ち負けを気にせず皆で笑える

.. graphviz::
   :caption: 設計者とプレイヤーから見た MDA
   :align: center

   digraph mda {
     rankdir=LR;
     node [shape=box, style="rounded,filled", fillcolor="#e8f0f8", color="#1f5f99", fontsize=12];

設計者はメカニクスしか直接決められない。一方、プレイヤーが最初に触れるのはエステティクスであり、メカニクスはその奥に隠れている。設計者は「どのような感情を生みたいか」から逆算してメカニクスを決め、プレイヤーは感情からさかのぼってルールを理解する。

ハニキーらは、エステティクスの例として次の 8 つを挙げている：感覚（Sensation）、空想（Fantasy）、物語（Narrative）、挑戦（Challenge）、仲間（Fellowship）、発見（Discovery）、表現（Expression）、暇つぶし（Submission）。

コアループ
----------

ゲームの中で繰り返される行動の単位を\ :term:`コアループ`\ と呼ぶ。たとえば、アクション RPG の短いループは「敵を見つける → 戦う → 報酬を得る」であり、長いループは「報酬で装備を強くする → より難しい場所に行く」である。

.. list-table:: コアループの例
   :header-rows: 1
   :widths: 25 35 40

   * - ゲーム
     - 短いループ（数秒〜数分）
     - 長いループ（1 ゲーム〜数日）
   * - 将棋
     - 相手の手を読む → 指す
     - 対局する → 振り返る → 定跡を学ぶ
   * - デッキ構築のボードゲーム
     - カードを使う → 新しいカードを買う
     - 山札が強くなり、より高い得点のカードが買えるようになる
   * - 落ち物パズル
     - ブロックを置く → 列が消える
     - 速度が上がる → 高得点を目指して再挑戦する

コアループが楽しくないと、それをどれだけ飾っても楽しいゲームにはならない。4 章で述べたプロトタイプの段階で確かめるのは、主にこのコアループの面白さである。

フィードバックループ
--------------------

ゲームの状態が、次の状態に影響を与え続ける仕組みを\ :term:`フィードバックループ`\ と呼ぶ。

.. graphviz::
   :caption: 正のフィードバックループ（左）と負のフィードバックループ（右）
   :align: center

   digraph loops {
     node [shape=box, style="rounded,filled", fontsize=11];
     subgraph cluster_pos {
       label="正のループ（差が広がる）"; fontsize=12; color="#d9822b";
       p1 [label="リードする", fillcolor="#fbeee2", color="#d9822b"];
       p2 [label="多くの資源を得る", fillcolor="#fbeee2", color="#d9822b"];
       p3 [label="さらに有利になる", fillcolor="#fbeee2", color="#d9822b"];
       p1 -> p2 -> p3 -> p1;
     }
     subgraph cluster_neg {
       label="負のループ（差が縮まる）"; fontsize=12; color="#3a8f5c";
       n1 [label="遅れる", fillcolor="#e6f2ea", color="#3a8f5c"];
       n2 [label="救済を受ける\n（強いアイテムなど）", fillcolor="#e6f2ea", color="#3a8f5c"];
       n3 [label="追いつく", fillcolor="#e6f2ea", color="#3a8f5c"];
       n1 -> n2 -> n3 -> n1;
     }
   }

.. list-table:: 正と負のフィードバックループ
   :header-rows: 1
   :widths: 20 40 40

   * - 種類
     - 効果
     - 例
   * - 正のループ
     - 有利な側がさらに有利になり、差が広がる。ゲームを終わりに向かわせる
     - モノポリーで、土地を多く持つ人が家賃を集めてさらに土地を買う
   * - 負のループ
     - 不利な側が追いつきやすくなり、差が縮まる。接戦を生む
     - レースゲームで、下位のプレイヤーほど強いアイテムが出る

正のループが強すぎると、序盤で勝負が決まり、残りの時間が消化試合になる。負のループが強すぎると、序盤の努力が意味を失い、最後の運だけで勝負が決まる。多くのゲームは両方を組み合わせて、終盤まで緊張感が続くように調整している。8 章の演習 4 では、すごろくにこの 2 種類のループを加えて、効果を数値で確かめる。

バランス
--------

ゲームの選択肢（キャラクター、カード、戦略など）の強さの関係を\ **バランス**\ と呼ぶ。

**推移的な関係**
   A が B より強く、B が C より強ければ、A は C より強い、という関係。強さに一列の順位がつく。コスト（値段、手間）と効果をつり合わせることで、弱い選択肢にも使う理由を持たせる。

**非推移的な関係**
   じゃんけんのように、A は B に、B は C に、C は A に強い、という三すくみの関係。どれか 1 つが常に最善ということが無いので、相手の選択を読むことが重要になる。

バランスが崩れ、1 つの選択肢が常に最善になると、他の選択肢は意味を失う。これは「意味のある選択」が失われることでもある。5 章の「グリコ」の計算のように、点数（効果）を変えると最適な選び方の割合が変わる。バランスの調整は、この割合を設計者の意図に近づける作業といえる。

難易度とチュートリアル
----------------------

時間とともに難しさがどう変わるかを示したものを\ **難易度曲線**\ と呼ぶ。フローの考え方に従えば、難易度はプレイヤーの上達に合わせて上がっていくのが望ましい。ただし、一直線に上げ続けると疲れてしまうので、難しい場面のあとに易しい場面を挟み、緩急をつけることが多い。

新しいプレイヤーにルールと操作を教える部分を\ **チュートリアル**\ と呼ぶ。よいチュートリアルは、説明の文章を読ませるのではなく、安全な状況で実際に試させ、1 つずつ新しい要素を加えていく。

8 章の演習 7 では、Godot のサンプルでブロックの出現間隔を変え、難易度曲線を実際に描く。

手触り
------

デジタルゲームでは、操作したときの感触も面白さを大きく左右する。これを\ :term:`ゲームフィール`\ （手触り）と呼ぶ。スティーブ・スウィンクは『Game Feel』（2008）で、手触りは、実時間での操作への反応、ゲームの中の空間での動き、それを強調する演出（エフェクト、音、画面の揺れなど）からなるとした。

.. list-table:: 手触りを左右する要素
   :header-rows: 1
   :widths: 25 75

   * - 要素
     - 内容
   * - 反応の速さ
     - ボタンを押してから画面が変わるまでの時間。短いほど「自分が動かしている」感覚が強い
   * - 加速と減速
     - 最高速度に達するまでの時間と、止まるまでの時間。短いと機敏に、長いと重く滑るように感じる
   * - 重力と跳躍
     - 跳ぶ高さと落ちる速さ。現実の物理に従うより、上りより下りを速くする方が気持ちよく感じられることが多い
   * - 演出
     - 当たったときの効果音、一瞬の停止、画面の揺れなど。同じ動きでも、演出によって手応えが大きく変わる

8 章の演習 6 では、Godot のサンプルで加速度や減速度を変え、手触りの違いを体験する。

アナログゲーム特有の課題
------------------------

アナログゲームには、デジタルゲームでは目立たない設計上の課題がある。

.. list-table:: アナログゲーム特有の課題
   :header-rows: 1
   :widths: 25 75

   * - 課題
     - 内容
   * - :term:`ダウンタイム`
     - 他のプレイヤーの手番を待つ時間。長いと退屈になる。全員が同時に行動する、他人の手番にも関われるなどの工夫で短くする
   * - :term:`キングメーカー問題`
     - 勝つ見込みの無くなったプレイヤーの行動が、誰が勝つかを決めてしまう問題。多人数の対戦で起きやすい
   * - ルールの量
     - デジタルゲームでは計算機がルールを処理するが、アナログゲームでは人がルールを覚え、処理しなければならない。ルールが多すぎると、遊ぶ前の説明だけで疲れてしまう

記入例

.. list-table:: 記入例：協力型のボードゲーム
   :header-rows: 1
   :widths: 25 75

   * - 項目
     - 記入例
   * - メカニクス

     - 危機が増える → 相談する → 能力を組み合わせて対処する
