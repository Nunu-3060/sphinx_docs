命令セットアーキテクチャ
========================

プロセッサが実行できる命令の種類と形式、プログラムから見えるレジスタ、メモリの扱い方などを定めた仕様を\ **命令セットアーキテクチャ**\ （Instruction Set Architecture：ISA）と呼びます。ISA はソフトウェアとハードウェアの境界にある約束事です。コンパイラは ISA に従って機械語を生成し、プロセッサの設計者は ISA に従う限り内部の回路を自由に工夫できます。

この章では、ISA が定めるものを整理したあと、本書で例として使う RISC-V（RV32I）の命令形式、アドレッシングモード、主な命令を説明します。さらに、x86-64 と AArch64 と比較しながら RISC と CISC の違いを考え、最後に 1 つの命令を実際に 32 ビットの機械語に符号化してみます。

ISA が定めるもの
----------------

ISA は、プログラムを正しく実行するためにソフトウェアが知っておく必要のあることをすべて定めます。逆に、命令を何サイクルで実行するか、キャッシュがいくつあるかといった性能に関わる実装の詳細は ISA には含まれず、\ **マイクロアーキテクチャ**\ （microarchitecture）の側で決まります。ISA が定める主な項目は次のとおりです。

.. list-table:: ISA が定める主な項目
   :header-rows: 1
   :widths: 22 48 30

   * - 項目
     - 内容
     - RISC-V（RV32I）の例
   * - レジスタ
     - プログラムから見えるレジスタの数、幅、用途
     - 32 ビットの汎用レジスタ 32 本（x0 は常に 0）と PC
   * - データ型
     - 命令が扱うデータの大きさと解釈
     - バイト（8 ビット）、ハーフワード（16 ビット）、ワード（32 ビット）
   * - 命令
     - 命令の種類、動作、ビット列への符号化
     - 算術論理、ロード／ストア、分岐、ジャンプなど 40 種類
   * - アドレッシングモード
     - オペランドやメモリアドレスの指定方法
     - レジスタ、即値、ベース + 変位、PC 相対
   * - メモリモデル
     - アドレス空間、バイト順序、整列、複数のコアから見たメモリ操作の順序
     - バイト単位のアドレス、リトルエンディアン、RVWMO
   * - 例外と特権
     - 不正な命令や割り込みが起きたときの動作、特権レベル
     - マシンモード、スーパーバイザーモード、ユーザーモード、CSR

同じ ISA に従うプロセッサであれば、内部の構造が大きく異なっていても同じ機械語のプログラムを実行できます。たとえば x86-64 には、省電力向けの小さなコアから、1 サイクルに多数の命令を実行するサーバー向けのコアまでがありますが、どれも同じプログラムを実行できます。この性質を\ **バイナリ互換性**\ （binary compatibility）と呼びます。

.. note::

   RISC-V では「ワード」は 32 ビットを指します。x86 の用語では歴史的な経緯から「ワード」が 16 ビット、「ダブルワード」が 32 ビットを指すので、文書を読むときは注意が必要です。

レジスタとレジスタファイル
--------------------------

**レジスタ**\ （register）は、プロセッサの内部にある少数の高速な記憶場所です。演算の入力と出力は原則としてレジスタに置きます。プログラムから番号で指定できるレジスタを\ **汎用レジスタ**\ （general-purpose register）と呼び、汎用レジスタをまとめて実装した回路を\ **レジスタファイル**\ （register file）と呼びます。

RV32I には 32 ビット幅の汎用レジスタが 32 本（x0〜x31）あります。命令の中でレジスタ番号を表すのに 5 ビット（:math:`2^5 = 32`）を使います。x0 は特別なレジスタで、読むと常に 0 が返り、書き込みは無視されます。定数 0 がいつでも使えるため、「レジスタの値をコピーする」「何もしない」といった操作を専用の命令なしで表現できます。汎用レジスタとは別に、次に実行する命令のアドレスを保持する\ **プログラムカウンタ**\ （Program Counter：PC）があります。RISC-V の PC はプログラムから直接は読み書きできず、分岐やジャンプ命令、\ ``auipc``\ 命令を通じて間接的に扱います。

レジスタの本数は ISA の重要な設計判断です。本数が多いほど多くの変数をレジスタに置けてメモリアクセスが減りますが、レジスタ番号を表すビット数が増えて命令が長くなり、レジスタファイルも大きく遅くなります。32 本は、この兼ね合いから多くの RISC 型 ISA が選んでいる値です。レジスタファイルの回路は「:doc:`08_digital_logic`」で説明します。

命令形式
--------

RV32I の命令はすべて 32 ビットの固定長で、\ **命令形式**\ （instruction format）は R、I、S、B、U、J の 6 種類です。どの形式でも、下位 7 ビットが命令の種類を表す\ **オペコード**\ （opcode）で、レジスタ番号を表すフィールド rd（書き込み先）、rs1、rs2（読み出し元）は、使う形式では常に同じビット位置にあります。こうしておくと、命令の種類を判別する前にレジスタファイルの読み出しを始められるので、ハードウェアが単純で高速になります。

   :header-rows: 1
   :widths: 8 16 13 13 11 16 11 12

   * - 形式
     - 31〜25
     - 24〜20
     - 19〜15
     - 14〜12
     - 11〜7
     - 6〜0
     - 主な用途
   * - R
     - funct7
     - rs2
     - rs1
     - funct3
     - rd
     - opcode
     - レジスタ間の演算
   * - I
     - imm[11:5]
     - imm[4:0]
     - rs1
     - funct3
     - rd
     - opcode
     - 即値演算、ロード、jalr
   * - S
     - imm[11:5]
     - rs2
     - rs1
     - funct3
     - imm[4:0]
     - opcode
     - ストア
   * - B
     - imm[12|10:5]
     - rs2
     - rs1
     - funct3
     - imm[4:1|11]
     - opcode
     - 条件分岐
   * - U
     - imm[31:25]
     - imm[24:20]
     - imm[19:15]
     - imm[14:12]
     - rd
     - opcode
     - lui、auipc
   * - J
     - imm[20|10:5]
     - imm[4:1|11]
     - imm[19:15]
     - imm[14:12]
     - rd
     - opcode
     - jal

表の imm[11:5] は「即値のビット 11〜5 がこの位置に入る」という意味です。funct3 と funct7 は、同じオペコードの中で演算の種類を区別するためのフィールドです。たとえば add と sub はどちらも R 形式でオペコードも funct3 も同じですが、funct7 が 0000000 か 0100000 かで区別します。

即値の扱いには次のような工夫があります。

* 即値の最上位ビット（符号ビット）は、どの形式でも命令のビット 31 にあります。そのため、形式を判別する前に符号拡張の準備ができます。
* I 形式の即値は 12 ビットの符号付き整数で、:math:`-2048` から :math:`2047` までを表せます。
* B 形式と J 形式の即値は 2 の倍数（ビット 0 が常に 0）なので、ビット 0 を命令に含めず、その分だけ範囲を広げています。条件分岐は PC から約 :math:`\pm 4` KiB、jal は約 :math:`\pm 1` MiB の範囲に飛べます。
* U 形式の即値は 32 ビットの上位 20 ビットを与えます。lui で上位 20 ビットを、addi で下位 12 ビットを設定すると、任意の 32 ビット定数を 2 命令で作れます。addi の即値は符号拡張されるので、定数のビット 11 が 1 のときは lui に渡す値を 1 だけ大きくして補正します（「:doc:`07_machine_language`」の擬似命令 li を参照）。

B 形式や J 形式の即値のビットの並びが不規則に見えるのは、S 形式や I 形式とできるだけ同じ位置に同じ即値ビットが来るように並べた結果です。人間には読みにくくなりますが、即値を組み立てるマルチプレクサが減り、ハードウェアが単純になります。

アドレッシングモード
--------------------

命令がオペランドの値やメモリのアドレスをどう指定するかを\ **アドレッシングモード**\ （addressing mode）と呼びます。RISC-V は意図的に少数のモードだけを持ちます。

.. list-table:: 主なアドレッシングモード
   :header-rows: 1
   :widths: 22 38 40

   * - モード
     - 意味
     - 例
   * - レジスタ
     - オペランドはレジスタの値
     - ``add x5, x6, x7``\ （x5 ← x6 + x7）
   * - 即値
     - オペランドは命令に埋め込まれた定数
     - ``addi x5, x6, 10``\ （x5 ← x6 + 10）
   * - ベース + 変位
     - アドレス = レジスタの値 + 定数
     - ``lw x5, 8(x6)``\ （x5 ← メモリ[x6 + 8]）
   * - PC 相対
     - アドレス = PC + 定数
     - ``beq x5, x6, label``\ 、\ ``auipc x5, 0x12``
   * - ベース + インデックス × スケール + 変位
     - アドレス = レジスタ + レジスタ × 1、2、4、8 + 定数（x86-64）
     - ``mov eax, [rbx + rcx*4 + 8]``
   * - プリインデックス／ポストインデックス
     - アドレス計算と同時にベースレジスタを更新します（AArch64）。
     - ``ldr x0, [x1], #8``\ （x0 ← メモリ[x1]、x1 ← x1 + 8）

RISC-V のメモリアクセスは「ベース + 変位」の 1 種類だけです。変位を 0 にすればレジスタ間接、ベースを x0 にすればアドレス 0 付近の絶対アドレスになるので、これだけで多くの用途をまかなえます。配列の要素 ``a[i]`` のアドレスのように x86-64 なら 1 命令で計算できるものも、RISC-V ではシフトと加算の命令を別に使います。

主な命令
--------

ここでは RV32I の命令を用途別に見ていきます。すべての命令の一覧は「:doc:`appendix_riscv`」にあります。アセンブリ言語では、書き込み先のレジスタを最初に書くのが RISC-V の慣習です。

算術論理命令
^^^^^^^^^^^^

算術論理命令は、レジスタ同士（R 形式）またはレジスタと即値（I 形式）の間で演算します。

.. code-block:: text
   :linenos:

   add  x5, x6, x7     # x5 = x6 + x7
   sub  x5, x6, x7     # x5 = x6 - x7
   addi x5, x6, -1     # x5 = x6 - 1（subi はなく、負の即値を使う）
   and  x5, x6, x7     # ビットごとの AND
   ori  x5, x6, 0xff   # ビットごとの OR（即値）
   slli x5, x6, 2      # 左シフト（x5 = x6 * 4）
   srai x5, x6, 1      # 算術右シフト（符号付きの 2 での除算に近い）
   slt  x5, x6, x7     # 符号付きで x6 < x7 なら 1、そうでなければ 0
   lui  x5, 0x12345    # x5 = 0x12345000

加算と減算はオーバーフローしても例外を起こさず、結果の下位 32 ビットを残します。RV32I には乗算と除算の命令がなく、M 拡張（後述）で追加されます。

ロード命令とストア命令
^^^^^^^^^^^^^^^^^^^^^^

メモリを読む命令を\ **ロード**\ （load）、書く命令を\ **ストア**\ （store）と呼びます。アドレスは「ベース + 変位」で指定します。

.. code-block:: text
   :linenos:

   lw   x5, 8(x6)      # x5 = メモリ[x6 + 8] の 4 バイト
   lb   x5, 0(x6)      # 1 バイト読み、符号拡張して 32 ビットにする
   lbu  x5, 0(x6)      # 1 バイト読み、ゼロ拡張して 32 ビットにする
   sw   x5, 12(x6)     # メモリ[x6 + 12] に x5 の 4 バイトを書く
   sb   x5, 3(x6)      # x5 の下位 1 バイトを書く

1 バイトや 2 バイトの読み出しには、符号拡張する lb、lh と、ゼロ拡張する lbu、lhu があります。C 言語の ``signed char`` と ``unsigned char`` の区別は、この命令の使い分けとして機械語に現れます。RISC-V はリトルエンディアンで、ワードの最下位バイトが最も小さいアドレスに置かれます。

分岐命令とジャンプ命令
^^^^^^^^^^^^^^^^^^^^^^

条件分岐命令は 2 つのレジスタを比較し、条件が成り立てば PC 相対のアドレスへ分岐します。比較と分岐が 1 命令になっていて、比較結果を保持する\ **フラグ**\ （flag）を使わないのが RISC-V の特徴です。

.. code-block:: text
   :linenos:

   beq  x5, x6, L1     # x5 == x6 なら L1 へ
   bne  x5, x0, L1     # x5 != 0 なら L1 へ
   blt  x5, x6, L1     # 符号付きで x5 < x6 なら L1 へ
   bgeu x5, x6, L1     # 符号なしで x5 >= x6 なら L1 へ
   jal  x1, func       # x1 = PC + 4 として func へジャンプ（関数呼び出し）
   jalr x0, 0(x1)      # x1 + 0 のアドレスへジャンプ（関数からの戻り）

**jal**\ （jump and link）は、次の命令のアドレス（PC + 4）を rd に保存してからジャンプします。保存したアドレスに jalr で戻れば、関数呼び出しと復帰になります。rd に x0 を指定すると戻りアドレスは捨てられ、単なるジャンプになります。「より大きい」「以下」の分岐命令はありませんが、オペランドを入れ替えれば blt と bge で表せます。

ロード／ストアアーキテクチャ
----------------------------

RISC-V では、メモリにアクセスできるのはロード命令とストア命令だけで、算術論理命令のオペランドは必ずレジスタか即値です。このような ISA を\ **ロード／ストアアーキテクチャ**\ （load/store architecture）と呼びます。たとえば「メモリ上の変数 ``x`` に 1 を足す」には、次の 3 命令が必要です。

.. code-block:: text
   :linenos:

   lw   x5, 0(x10)     # x5 = x（x10 は x のアドレス）
   addi x5, x5, 1      # x5 = x5 + 1
   sw   x5, 0(x10)     # x = x5

x86-64 では ``add dword ptr [rdi], 1`` の 1 命令で同じことができます。命令数だけを比べると x86-64 のほうが少なく見えますが、ロード／ストアアーキテクチャには次の利点があります。

* 1 つの命令が行うメモリアクセスは高々 1 回で、命令の実行の流れが単純になります。パイプライン化（「:doc:`10_pipeline`」）が容易になります。
* メモリアクセスで起きる例外（ページフォールトなど）の発生箇所が限られ、例外処理が単純になります。
* ロードを早めに発行して、値が届くまでの間に他の命令を実行するといった最適化をコンパイラが行いやすくなります。

RISC-V のモジュール構成
-----------------------

RISC-V は、小さな基本 ISA に必要な\ **拡張**\ （extension）を組み合わせる\ **モジュール構成**\ をとります。仕様はオープンで、誰でもライセンス料なしに RISC-V のプロセッサを設計できます。RISC-V はカリフォルニア大学バークレー校で 2010 年に始まったプロジェクトから生まれ、現在は RISC-V International が仕様を管理しています。

.. list-table:: RISC-V の主な基本 ISA と拡張
   :header-rows: 1
   :widths: 16 54 30

   * - 名前
     - 内容
     - 主な命令の例
   * - RV32I
     - 32 ビットの整数基本 ISA。レジスタは 32 ビット × 32 本。
     - add、lw、beq、jal
   * - RV64I
     - 64 ビットの整数基本 ISA。レジスタは 64 ビット × 32 本。32 ビット演算用の命令を追加。
     - ld、sd、addw
   * - RV32E
     - 組み込み向けにレジスタを 16 本に減らした基本 ISA
     - RV32I と同じ
   * - M
     - 整数の乗算と除算
     - mul、mulh、div、rem
   * - A
     - アトミック命令（マルチコアでの同期に使用）
     - lr.w、sc.w、amoadd.w
   * - F
     - 単精度浮動小数点数。浮動小数点レジスタ f0〜f31 を追加。
     - fadd.s、flw、fmadd.s
   * - D
     - 倍精度浮動小数点数（F が前提）
     - fadd.d、fld
   * - C
     - よく使う命令の 16 ビット版（圧縮命令）。コードサイズを 25〜30% 程度削減します。
     - c.addi、c.lw、c.j
   * - V
     - ベクトル長を実行時に設定できるベクトル演算
     - vsetvli、vle32.v、vadd.vv

ISA の名前は、基本 ISA に拡張の文字を並べて表します。たとえば RV64IMAFDC は、64 ビットの整数基本 ISA に M、A、F、D、C 拡張を加えたものです。汎用 OS を動かすのに必要な IMAFD と CSR 関連の拡張（Zicsr、Zifencei）をまとめて G と書き、RV64GC と表すこともあります。拡張が多くなりすぎて組み合わせが分かりにくくなったため、RVA22、RVA23 のように、アプリケーションプロセッサが備えるべき拡張の組をまとめた\ **プロファイル**\ （profile）も定められています。

本書では主に RV32I と M 拡張の命令を使います。SIMD やベクトル拡張は「:doc:`15_parallel`」で扱います。

x86-64、AArch64 との比較
------------------------

RISC-V と、現在広く使われている x86-64、AArch64 を比較します。

.. list-table:: 3 つの ISA の比較
   :header-rows: 1
   :widths: 22 26 26 26

   * - 項目
     - RISC-V（RV64I）
     - AArch64
     - x86-64
   * - 命令長
     - 32 ビット固定（C 拡張で 16 ビットも可）
     - 32 ビット固定
     - 1〜15 バイトの可変長
   * - 汎用レジスタ数
     - 32 本（x0 は常に 0）
     - 31 本（X0〜X30）と、番号 31 に割り当てたゼロレジスタまたは SP
     - 16 本
   * - 演算のオペランド数
     - 3（rd ← rs1 op rs2）
     - 3
     - 主に 2（dst ← dst op src）
   * - 算術命令のメモリオペランド
     - なし（ロード／ストアのみ）
     - なし（ロード／ストアのみ）
     - あり
   * - 条件フラグ
     - なし（比較と分岐が一体）
     - NZCV（ADDS、CMP などフラグを設定する命令だけが更新）
     - RFLAGS（多くの算術命令が更新）
   * - アドレッシングモード
     - ベース + 変位のみ
     - ベース + 変位、ベース + レジスタ（スケール付き）、プリ／ポストインデックス
     - ベース + インデックス × スケール + 変位、RIP 相対など
   * - メモリ順序モデル
     - RVWMO（弱い順序）
     - 弱い順序
     - TSO（強い順序に近い）
   * - 仕様の管理
     - RISC-V International（オープン）
     - Arm（ライセンス制）
     - Intel、AMD

x86-64 の 2 オペランド形式では、\ ``add rax, rbx``\ が rax ← rax + rbx を意味し、元の rax の値が失われます。元の値を残したい場合は先に別のレジスタにコピーする命令が必要です。一方、x86-64 の可変長命令は、よく使う命令を短く符号化できるのでコードが小さくなる利点があります。メモリ順序モデルの違いは、マルチスレッドのプログラムの正しさに関わります。詳しくは「:doc:`15_parallel`」で説明します。

.. note::

   Intel は、x86-64 の汎用レジスタを 32 本に増やし、3 オペランド形式の命令を追加する拡張 APX（Advanced Performance Extensions）を発表しています。レジスタ数やオペランド数が性能に効くことを示す例です。

RISC と CISC
------------

1980 年前後に、命令を単純にして高速に実行するという設計思想が提唱され、\ **RISC**\ （Reduced Instruction Set Computer）と呼ばれました。これに対して、それ以前の複雑な命令を持つ ISA は\ **CISC**\ （Complex Instruction Set Computer）と呼ばれるようになりました。歴史的な経緯は「:doc:`03_history`」で説明しています。典型的な特徴を比べると次のようになります。

.. list-table:: RISC と CISC の典型的な特徴
   :header-rows: 1
   :widths: 25 37 38

   * - 観点
     - RISC
     - CISC
   * - 命令長
     - 固定長
     - 可変長
   * - メモリアクセス
     - ロード／ストア命令だけ
     - 多くの命令がメモリオペランドを取れます。
   * - 1 命令の仕事量
     - 小さいです（命令数は増えます）。
     - 大きいです（命令数は減ります）。
   * - デコード
     - 単純です。
     - 複雑です（命令の境界を見つけるだけでも手間がかかります）。
   * - 代表例
     - RISC-V、AArch64、MIPS、SPARC、POWER
     - x86、x86-64、IBM System/360 の後継、VAX

性能の式（「:doc:`04_performance`」）で考えると、CPU 時間は「命令数 × CPI × クロックサイクル時間」です。CISC は命令数を減らし、RISC は CPI とクロックサイクル時間を減らすことを狙った設計といえます。

現在では、この区別は ISA の表面上のものになっています。x86-64 のプロセッサは、Intel の Pentium Pro（1995 年）以降、x86 の命令をデコーダで RISC 風の単純な内部命令である\ **マイクロオペレーション**\ （micro-operation：μop）に分解して実行しています。たとえば ``add dword ptr [rdi], 1`` は、おおよそ「ロード」「加算」「ストア」の μop に分解されます。複雑な命令はマイクロコードによって多数の μop の列に展開されます。分解した μop は、RISC のプロセッサと同じようにパイプラインとアウトオブオーダー実行（「:doc:`11_ilp`」）で処理されます。最近の x86-64 のプロセッサは、デコード済みの μop を保存する μop キャッシュを持ち、複雑なデコードを繰り返さずに済むようにしています。

つまり、CISC の ISA の利点（バイナリ互換性とコード密度）を保ちながら、内部は RISC と同じ技術で高速化しているのです。その代償として、デコーダの面積と電力が余分にかかります。

エンコード例
------------

最後に、命令 ``add x5, x6, x7`` を 32 ビットの機械語に符号化する手順を追います。

1. add はレジスタ間の演算なので R 形式です。
2. 仕様から、add のオペコードは 0110011、funct3 は 000、funct7 は 0000000 です。
3. rd = x5、rs1 = x6、rs2 = x7 なので、それぞれ 5 ビットの 2 進数で 00101、00110、00111 です。
4. 各フィールドを R 形式の位置に並べます。

.. list-table:: add x5, x6, x7 の符号化
   :header-rows: 1
   :widths: 16 14 14 14 14 14 14

   * - フィールド
     - funct7
     - rs2
     - rs1
     - funct3
     - rd
     - opcode
   * - ビット位置
     - 31〜25
     - 24〜20
     - 19〜15
     - 14〜12
     - 11〜7
     - 6〜0
   * - 値
     - 0
     - 7
     - 6
     - 0
     - 5
     - 0x33
   * - 2 進数
     - 0000000
     - 00111
     - 00110
     - 000
     - 00101
     - 0110011

並べた 32 ビットを 4 ビットずつ区切って 16 進数にします。

.. code-block:: text
   :linenos:

   0000000 00111 00110 000 00101 0110011
   = 0000 0000 0111 0011 0000 0010 1011 0011
   = 0x007302B3

したがって ``add x5, x6, x7`` の機械語は 0x007302B3 です。メモリにはリトルエンディアンで B3 02 73 00 の順にバイトが並びます。

同様に I 形式の ``addi x5, x6, -1`` を符号化してみます。即値 :math:`-1` は 12 ビットの 2 の補数で 111111111111 です。addi のオペコードは 0010011、funct3 は 000 なので、次のようになります。

.. code-block:: text
   :linenos:

   111111111111 00110 000 00101 0010011
   = 1111 1111 1111 0011 0000 0010 1001 0011
   = 0xFFF30293

逆に、機械語からアセンブリを復元することを\ **逆アセンブル**\ （disassemble）と呼びます。デコーダは下位 7 ビットのオペコードで形式を判別し、funct3、funct7 で演算を特定します。これはプロセッサの命令デコーダが行っていることと同じです。命令を実際に実行するシミュレーターは「:doc:`09_datapath`」で作ります。

この章のまとめ
--------------

* ISA は、レジスタ、データ型、命令とその符号化、アドレッシングモード、メモリモデル、例外を定める、ソフトウェアとハードウェアの約束事です。
* RV32I の命令は 32 ビット固定長で、R、I、S、B、U、J の 6 形式があり、レジスタ番号と即値の符号ビットの位置がそろえられています。
* RISC-V のアドレッシングモードはレジスタ、即値、ベース + 変位、PC 相対の少数に限られます。
* メモリにアクセスできるのはロードとストアだけです（ロード／ストアアーキテクチャ）。
* RISC-V は基本 ISA（RV32I、RV64I）に M、A、F、D、C、V などの拡張を組み合わせるモジュール構成です。
* x86-64 は可変長命令、2 オペランド、メモリオペランド、フラグを持つ CISC 型の ISA ですが、内部では μop に分解して RISC と同様の技術で実行しています。
* ``add x5, x6, x7`` の機械語は 0x007302B3 です。
