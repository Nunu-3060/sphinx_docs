まとめ
======

本書では、命令セットアーキテクチャという「ソフトウェアとハードウェアの約束事」から出発し、それを実現するプロセッサの設計、パイプラインや命令レベル並列性による高速化、メモリ階層、並列アーキテクチャ、GPU やアクセラレーターまでを、性能という観点から積み上げて説明してきました。この章では、各章の要点を振り返り、性能向上の手法を整理したうえで、ソフトウェアエンジニアが実務で意識すべき点と、次に学ぶとよいことをまとめます。

性能向上の主要な手法の整理
--------------------------

本書を通じて登場した高速化の手法は、数が多いように見えますが、いくつかの基本的な考え方に整理できます。ここでは\ **並列性・局所性・投機・特化**\ の 4 つの観点でまとめます。多くの実際の技術は、これらを組み合わせたものです。

.. list-table:: 4 つの観点による性能向上の手法
   :header-rows: 1
   :widths: 16 44 40

   * - 観点
     - 考え方
     - 本書での例
   * - 並列性
     - 複数の処理を同時に行い、単位時間あたりの処理量を増やします。
     - パイプライン、スーパースカラ、マルチコア、SIMD、GPU の SIMT、DMA。
   * - 局所性
     - 最近使ったもの・近くにあるものは再び使われやすいという性質を利用し、速い記憶に置いて待ち時間を隠します。
     - キャッシュ、TLB、GPU の共有メモリ、ブロッキング（タイリング）。
   * - 投機
     - 結果が確定する前に予測して先に進め、当たれば時間を稼ぎ、外れたらやり直します。
     - 分岐予測、投機実行、プリフェッチ。
   * - 特化
     - 特定の種類の計算に合わせた回路を用意し、汎用の実装より高い性能と電力効率を得ます。
     - GPU、TPU などのアクセラレーター、専用回路、ドメイン特化型アーキテクチャ。

これらの手法には、共通する注意点があります。第 1 に、どれも\ **アムダールの法則**\ の制約を受けます。高速化できるのは全体の一部分であり、その部分をいくら速くしても、残りが全体の性能を左右します。第 2 に、多くの手法は\ **電力**\ との引き換えです。デナード・スケーリングが終わった現在、性能あたりの電力が設計の中心的な制約になっています。第 3 に、投機や共有といった高速化の仕組みが、「:doc:`18_security_reliability`」で見たように、セキュリティ上の新たな問題を生むこともあります。性能・電力・コスト・安全性のバランスをとることが、アーキテクチャの本質です。

ソフトウェアエンジニアのためのチェックリスト
--------------------------------------------

アーキテクチャの知識は、ハードウェアを設計しないソフトウェアエンジニアにとっても役に立ちます。性能が問題になったとき、その原因がどの階層にあるのかを推測し、適切な対策を選ぶ助けになるからです。実務で意識するとよい点を、チェックリストとして挙げます。

* まず測る：推測で最適化せず、プロファイラなどで実際のボトルネックを特定します。「:doc:`04_performance`」のとおり、効果が大きいのは、よく実行される部分を速くしたときです。
* メモリアクセスの局所性を意識する：配列を連続した順序でたどる、データ構造を小さくまとめるなど、キャッシュに乗りやすい書き方を心がけます（「:doc:`12_memory_hierarchy`」）。キャッシュミスは、見かけの命令数以上に性能を左右します。
* 分岐とデータ依存を減らす：予測しにくい分岐や、長い依存の連鎖は、パイプラインや命令レベル並列性の効果を損ないます（「:doc:`10_pipeline`」「:doc:`11_ilp`」）。
* 並列性を正しく使う：マルチコアやスレッドを使うときは、同期のコストとキャッシュの一貫性（「:doc:`15_parallel`」）を意識します。ロックの競合や、複数のコアが同じキャッシュラインを奪い合う現象に注意します。
* 適した計算機を選ぶ：大量の規則的な並列計算は GPU やアクセラレーターが得意ですが、データの転送コストや、問題が並列化に向くかを見極めます（「:doc:`16_gpu`」「:doc:`17_accelerators`」）。
* 数値の性質を理解する：浮動小数点数の誤差や範囲、整数のオーバーフローを踏まえて型を選びます（「:doc:`05_data_representation`」）。
* セキュリティと信頼性を忘れない：メモリ安全性の欠陥を避け、必要に応じて ECC や冗長化を考えます（「:doc:`18_security_reliability`」）。
* 電力を意識する：モバイルやデータセンターでは、処理を速く終えて休ませる、不要な処理を減らすことが、そのまま省電力につながります（「:doc:`19_trends`」）。
* 抽象の裏側を想像する：高級言語の 1 行が、どのような命令・メモリアクセス・分岐になるのかを大まかに思い描けると、性能の見通しが立てやすくなります。

次に学ぶべきこと
----------------

本書は入門であり、各分野にはさらに深い内容があります。学びを進めるための方向を紹介します。

定番の教科書
^^^^^^^^^^^^

コンピューターアーキテクチャには、ヘネシーとパターソンによる 2 冊の定番の教科書があります。1 冊は、本書と同じように基礎から学ぶ *Computer Organization and Design*\ （邦訳『コンピュータの構成と設計』、通称パターソン&ヘネシー）です。原著には RISC-V 版があり、本書で扱った内容をより詳しく学べます。もう 1 冊は、より高度な内容を定量的に扱う *Computer Architecture: A Quantitative Approach*\ （邦訳『コンピュータアーキテクチャ 定量的アプローチ』、通称ヘネシー&パターソン）で、パイプライン、メモリ階層、並列性、ドメイン特化型アーキテクチャなどを深く掘り下げています。詳しい書誌は「:doc:`appendix_references`」にまとめてあります。

シミュレーターで試す
^^^^^^^^^^^^^^^^^^^^

実際のハードウェアを作らなくても、シミュレーターを使えばアーキテクチャの挙動を観察できます。研究や教育で広く使われているのが **gem5** です。さまざまな ISA とマイクロアーキテクチャを、サイクル単位で詳しくシミュレートでき、キャッシュの構成やパイプラインの段数を変えたときの性能の変化を調べられます。ほかにも、キャッシュの動作を学ぶための簡単なシミュレーターや、RISC-V の命令の動作を確かめる QEMU のようなエミュレーターがあります。本書の付録「:doc:`appendix_examples`」の Python サンプルも、小さなシミュレーターとして動作を確かめるのに役立ちます。

HDL で CPU を自作する
^^^^^^^^^^^^^^^^^^^^^

理解を最も深める方法の 1 つが、自分で簡単な CPU を設計してみることです。**HDL**\ （Hardware Description Language：ハードウェア記述言語）である Verilog や VHDL、Verilog を拡張した SystemVerilog、Scala の上に作られた Chisel などを使い、本書の「:doc:`09_datapath`」「:doc:`10_pipeline`」で学んだデータパスと制御を記述します。RISC-V の RV32I は命令数が少なく、自作の題材として適しています（命令の一覧は「:doc:`appendix_riscv`」にあります）。まずはシミュレーターで動作を確認し、次に述べる FPGA に実装すると、自分の設計した CPU が本当に動く様子を見られます。

FPGA で動かす
^^^^^^^^^^^^^

**FPGA**\ （Field-Programmable Gate Array）は、回路の構成を書き換えられる集積回路です（「:doc:`17_accelerators`」）。HDL で記述した CPU やアクセラレーターを、専用のチップを作らずに実際のハードウェアとして動かせます。学習用の安価な FPGA ボードが入手でき、自作の CPU を載せて LED を光らせたり、簡単なプログラムを実行させたりできます。設計がそのまま動く手ごたえは、ソフトウェアのシミュレーションとはまた違った学びになります。

さらに進むには
^^^^^^^^^^^^^^

* 並列プログラミング：OpenMP、MPI、CUDA などを使い、マルチコアや GPU の性能を引き出す方法を学びます。
* コンパイラ：高級言語がどのように最適化され機械語になるかを学ぶと、アーキテクチャとソフトウェアのつながりがよく分かります。
* オペレーティングシステム：仮想記憶やプロセスの管理など、ハードウェアと密接に関わる部分を扱います。本書では詳しく扱いませんでした。
* 最新の研究：ISCA、MICRO、ASPLOS、HPCA といった国際会議で、最新のアーキテクチャの研究が発表されています。

おわりに
--------

コンピューターアーキテクチャは、物理の制約と、ソフトウェアからの要求がぶつかり合う場所です。トランジスタという限られた資源をどう使えば、与えられた電力とコストの中で最も役に立つ計算機になるか——その問いに、設計者たちは並列性・局所性・投機・特化という道具を組み合わせて答え続けてきました。デナード・スケーリングが終わり、ムーアの法則が鈍化したいまこそ、問題の性質に合わせて賢く設計する、アーキテクチャの工夫がいっそう重要になっています。本書が、その面白さに触れ、ソフトウェアを書くときにハードウェアの姿を思い描く助けになれば幸いです。

本書のまとめ
------------

* 本書は、ISA からプロセッサ、パイプライン、メモリ階層、並列アーキテクチャ、GPU・アクセラレーターまでを、性能という観点で積み上げて説明しました。
* 性能向上の手法は、並列性・局所性・投機・特化の 4 つの観点に整理でき、多くの実際の技術はこれらの組み合わせです。
* どの手法もアムダールの法則の制約を受け、電力との引き換えであり、ときに安全性の問題も生みます。性能・電力・コスト・安全性のバランスをとることがアーキテクチャの本質です。
* ソフトウェアエンジニアも、局所性・分岐・並列性・数値・電力を意識することで、性能の見通しを立てやすくなります。
* さらに学ぶには、定番の教科書、gem5 などのシミュレーター、HDL での CPU 自作、FPGA での実装が有効です。
