入出力とバス
============

ここまでの章では、プロセッサとメモリの内部を見てきました。しかし、コンピューターが役に立つのは、キーボードやネットワーク、ストレージなどの外部の装置とデータをやり取りできるからです。この章では、プロセッサが入出力装置（I/O デバイス）とどのようにやり取りするかを、ハードウェアの立場から学びます。

まず、速度が何桁も異なる I/O デバイスの多様性を確認し、プロセッサからデバイスを操作する方法（メモリマップト I/O）と、データの受け渡しの方式（ポーリング、割り込み、DMA）を比較します。次に、装置どうしをつなぐバスとインターコネクトの変遷と、現在の標準である PCI Express を説明します。最後に、ストレージ（HDD、SSD、NVMe）、キャッシュと I/O の関係、IOMMU、ネットワークを取り上げます。デバイスドライバなど OS 側の詳細には立ち入りません。

I/O デバイスの多様性
--------------------

I/O デバイスは、用途もデータの転送速度も多様です。次の表は、代表的なデバイスのデータ転送速度のおおよその値です。

.. list-table:: I/O デバイスのデータ転送速度（目安）
   :header-rows: 1
   :widths: 30 30 40

   * - デバイス
     - 転送速度（目安）
     - 備考
   * - キーボード、マウス
     - 数 B/s〜数 KB/s
     - 人間の操作に依存します。
   * - HDD
     - 約 200〜300 MB/s（連続アクセス）
     - ランダムアクセスでは大きく低下します。
   * - SATA 接続の SSD
     - 約 550 MB/s
     - SATA 3.0（6 Gbit/s）のインターフェースが上限になります。
   * - NVMe SSD（PCIe 4.0 x4）
     - 約 7 GB/s
     - PCIe 5.0 x4 ではその約 2 倍。
   * - イーサネット
     - 125 MB/s（1 Gbit/s）〜50 GB/s（400 Gbit/s）
     - データセンターでは 100 Gbit/s 以上が一般的になりつつあります。
   * - GPU（PCIe 5.0 x16）
     - 約 63 GB/s（片方向）
     - GPU 内部のメモリ帯域はさらに 1〜2 桁大きいです。

最も遅いものと最も速いものでは、10 桁近い差があります。また、キーボードのように人間を相手にするデバイスはレイテンシ（反応の速さ）が、ストレージやネットワークはスループット（帯域）とレイテンシの両方が重要です。I/O のシステムは、このように性質の異なるデバイスを、共通の仕組みで扱えるように設計されています。

デバイスの操作：メモリマップト I/O とポートマップト I/O
-------------------------------------------------------

I/O デバイスには、プロセッサから読み書きできる\ **デバイスレジスタ**\ （device register）があります。代表的なものは次の 3 種類です。

* 制御レジスタ：デバイスへの命令（送信開始、リセットなど）を書き込みます。
* ステータスレジスタ：デバイスの状態（処理が完了したか、エラーがあるかなど）を読み出します。
* データレジスタ：送受信するデータを読み書きします。

プロセッサからデバイスレジスタにアクセスする方法には、次の 2 つがあります。

**メモリマップト I/O**\ （memory-mapped I/O：MMIO）
   物理アドレス空間の一部をデバイスレジスタに割り当て、通常のロード命令とストア命令でアクセスします。特別な命令が不要で、仮想記憶の保護の仕組みでアクセスを制限できます。RISC-V や AArch64 は、I/O に専用の命令を持たず、メモリマップト I/O だけを使います。

**ポートマップト I/O**\ （port-mapped I/O）
   メモリとは別の I/O 用のアドレス空間（I/O ポート）を用意し、専用の命令でアクセスします。x86 の ``in`` 命令と ``out`` 命令がその例で、16 ビットのアドレスで指定する 65,536 個の I/O ポートがあります。現在の x86-64 のシステムでも、互換性のために一部のデバイスで使われていますが、主流はメモリマップト I/O です。

メモリマップト I/O のアドレスへのアクセスは、通常のメモリと同じように扱ってはいけません。ステータスレジスタは読むたびに値が変わる可能性があり、データレジスタへの書き込みは順序と回数そのものに意味があります。このため、デバイスレジスタの領域はキャッシュしない（uncacheable）領域として設定し、プロセッサがアクセスを並べ替えたりまとめたりしないようにします。C 言語でデバイスレジスタを扱うときに ``volatile`` を付けるのは、コンパイラによるアクセスの削除や並べ替えを防ぐためです。

ポーリング・割り込み・DMA
-------------------------

デバイスとのデータのやり取りには、大きく 3 つの方式があります。

ポーリング
^^^^^^^^^^

プロセッサがステータスレジスタを繰り返し読み、デバイスの準備ができたかを調べる方式を\ **ポーリング**\ （polling）と呼びます。単純ですが、デバイスの準備ができるまでの間、プロセッサの時間を浪費します。

ポーリングのコストを見積もってみます。1 回のポーリングに 400 サイクルかかり、プロセッサのクロックが 1 GHz だとします。マウスを毎秒 30 回ポーリングするなら、毎秒 :math:`30 \times 400 = 12000` サイクルで、プロセッサの時間の 0.0012% にすぎません。しかし、毎秒 1 GB のデータを 16 バイトずつポーリングで受け取るデバイスでは、毎秒 :math:`6.25 \times 10^{7}` 回のポーリングが必要で、:math:`6.25 \times 10^{7} \times 400 = 2.5 \times 10^{10}` サイクルとなり、プロセッサの能力の 25 倍を必要とします。高速なデバイスのデータを、プロセッサがポーリングで少しずつ受け取るのは不可能です。

割り込み
^^^^^^^^

デバイスの側から、準備ができたことや処理が完了したことをプロセッサに知らせる方式を\ **割り込み**\ （interrupt）と呼びます。割り込みを受けたプロセッサは、実行中の命令列を中断して、割り込みハンドラを実行し、終わったら元の処理に戻ります。デバイスを待つ間にプロセッサは別の仕事ができますが、割り込み 1 回ごとに、パイプラインのフラッシュ、レジスタの退避と復元、キャッシュの汚染などのオーバーヘッドがかかります。このため、イベントが非常に頻繁に起こる場合は、かえってポーリングの方が効率的なこともあります。高速なネットワークやストレージでは、負荷が高いときにポーリングに切り替えたり、複数のイベントをまとめて 1 回の割り込みで通知したり（割り込みの集約、interrupt coalescing）する工夫が使われます。

DMA
^^^

大量のデータの転送をプロセッサを介さずに、デバイスと主記憶の間で直接行う方式を\ **DMA**\ （Direct Memory Access）と呼びます。プロセッサは、転送元・転送先のアドレスと転送量などをデバイス（または DMA コントローラ）に設定して転送を開始させ、転送が完了したら割り込みで通知を受けます。プロセッサが関わるのは転送の開始と完了のときだけで、その間は別の仕事ができます。

現代の高速なデバイスでは、主記憶上に\ **ディスクリプタ**\ （descriptor）と呼ぶ転送の指示書を並べたリング状のキューを置き、デバイスがそれを DMA で読み出して次々に処理する方式が一般的です。プロセッサは、キューに指示を追加したことを、デバイスの\ **ドアベルレジスタ**\ （doorbell register）への書き込みで知らせます。

   :header-rows: 1
   :widths: 16 28 28 28

   * - 方式
     - データの転送
     - 完了・準備の検知
     - 向いている用途
   * - ポーリング
     - プロセッサが行います。
     - プロセッサがステータスを繰り返し読みます。
     - 単純な機器、イベントが非常に頻繁で低レイテンシが必要な場合

割り込みコントローラ
--------------------

多数のデバイスからの割り込みを受け付け、優先度を付けて、どのコアに届けるかを決めるのが\ **割り込みコントローラ**\ （interrupt controller）です。アーキテクチャごとに次のようなものがあります。

* RISC-V：外部割り込みを扱う PLIC（Platform-Level Interrupt Controller）と、タイマー割り込みやコア間割り込みを扱う CLINT（またはその後継の ACLINT）が広く使われています。メッセージ方式の割り込みを扱う AIA（Advanced Interrupt Architecture）も定められています。
* x86-64：各コアに Local APIC があり、I/O APIC がデバイスの割り込みを Local APIC に配送します。
* AArch64：GIC（Generic Interrupt Controller）が使われます。

PCI Express のデバイスは、割り込み専用の信号線を使わずに、特定のアドレスへのメモリ書き込みとして割り込みを通知する\ **MSI**\ （Message Signaled Interrupts）、またはその拡張の MSI-X を使います。MSI-X では 1 つのデバイスが多数の割り込みを持てるので、たとえばネットワークカードの受信キューごとに別の割り込みを用意し、それぞれを別のコアに届けることができます。

バスとインターコネクト
----------------------

共有バス
^^^^^^^^

プロセッサ、メモリ、I/O デバイスを結ぶ信号線の束を\ **バス**\ （bus）と呼びます。初期のコンピューターでは、1 組の信号線（アドレス線、データ線、制御線）にすべての装置をつなぐ\ **共有バス**\ （shared bus）が使われました。共有バスは安価で、装置の追加も簡単ですが、次のような限界があります。

* 同時に 1 組の装置しか通信できないので、つなぐ装置が増えるほど 1 台あたりの帯域が減ります。どの装置に使わせるかを決める調停（arbitration）も必要になります。
* 多数の装置がつながった長い信号線は電気的な負荷が大きく、クロック周波数を上げにくくなります。
* 多数の信号線を並列に使うパラレル伝送では、信号線ごとの到着時刻のずれ（スキュー）が高速化の妨げになります。

PC で広く使われた PCI バスは、32 ビット幅、33 MHz の共有パラレルバスで、帯域は約 133 MB/s でした。

Point-to-Point の高速シリアル接続へ
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

2000 年代以降、外部のバスは共有のパラレルバスから、2 つの装置を 1 対 1 でつなぐ\ **Point-to-Point**\ の高速シリアル接続に移りました。差動信号の 1 対の線で、クロックをデータに埋め込んで送ることでスキューの問題を避け、1 本あたり毎秒数十ギガビットの速度を実現しています。複数の装置をつなぐには、スイッチを介して接続します。PCI Express、プロセッサどうしをつなぐ Intel の UPI や AMD の Infinity Fabric、USB、SATA などは、いずれもこの方式です。

チップの内部でも、多数のコア、キャッシュのスライス、メモリコントローラ、I/O をつなぐために、リング状やメッシュ状の\ **オンチップインターコネクト**\ （Network on Chip：NoC）が使われています。マルチコアのインターコネクトについては「:doc:`15_parallel`」でも触れます。

PCI Express
-----------

**PCI Express**\ （PCIe）は、現在のコンピューターで GPU、SSD、ネットワークカードなどの高速なデバイスをつなぐ標準のインターコネクトです。名前は PCI を引き継いでおり、ソフトウェアから見たデバイスの設定の仕組み（コンフィギュレーション空間など）は PCI と互換性がありますが、物理的には Point-to-Point のシリアル接続です。

PCIe の 1 組の送信用と受信用の差動信号線を\ **レーン**\ （lane）と呼びます。1 レーンで送信と受信を同時に行えます（全二重）。レーンを束ねて帯域を増やすことができ、束ねた数を x1、x4、x8、x16 のように表します。たとえば、GPU は x16、NVMe SSD は x4 で接続するのが一般的です。

GT/s（ギガトランスファー毎秒）は、1 レーンで 1 秒あたりに送るビット数（符号化のオーバーヘッドを含む）を表します。8b/10b 符号化では 8 ビットのデータを 10 ビットで送るので実効的な帯域は 80% になり、128b/130b 符号化では約 98.5% になります。たとえば PCIe 3.0 の 1 レーンの帯域は :math:`8 \times 10^{9} \times 128/130 / 8 \approx 985` MB/s です。おおむね世代ごとに帯域が 2 倍になっています。PCIe 6.0 は、1 回の信号で 2 ビットを送る 4 値の信号方式（PAM4）を使い、信号の変化の速さは 5.0 と同じまま 64 GT/s を実現しています。また、データを固定長の FLIT（flow control unit）にまとめて誤り訂正の符号を付けるので、6.0 の欄の値（:math:`64 / 8 = 8` GB/s）からさらに数 % の効率の低下があります。表の値はパケットのヘッダなどのオーバーヘッドを含まないので、実際に得られるデータの転送速度はこれより小さくなります。

PCIe の通信は、メモリの読み書きや設定の読み書きを表す\ **トランザクション層パケット**\ （Transaction Layer Packet：TLP）でやり取りされます。プロセッサ側の\ **ルートコンプレックス**\ （root complex）を根として、スイッチを介してデバイス（エンドポイント）が木構造につながります。デバイスのレジスタはメモリマップト I/O でアクセスでき、デバイスからの DMA や MSI も、メモリへの書き込みのパケットとして送られます。PCIe の物理層の上に、キャッシュコヒーレンスを保ってメモリを共有する CXL（Compute Express Link）という規格も作られており、「:doc:`19_trends`」で説明します。

ストレージ
----------

HDD
^^^

**HDD**\ （Hard Disk Drive）は、回転する磁気ディスク（プラッタ）にデータを記録します。データを読むには、ヘッドを目的のトラックに移動させ（シーク）、目的のセクタがヘッドの下に回ってくるのを待つ（回転待ち）必要があります。毎分 7200 回転のディスクでは、1 回転に :math:`60 / 7200 \approx 8.33` ms かかるので、平均の回転待ちはその半分の約 4.2 ms です。これに数 ms のシーク時間が加わるので、ランダムな位置の読み出しには平均で 10 ms 前後かかり、1 秒あたりのランダムアクセスの回数（IOPS）は 100 回程度にとどまります。一方、連続した領域の読み出しは速く、200 MB/s 以上になります。

SSD とフラッシュメモリ
^^^^^^^^^^^^^^^^^^^^^^

**SSD**\ （Solid State Drive）は、NAND 型\ **フラッシュメモリ**\ （flash memory）にデータを記録します。機械的な動作がないので、ランダムアクセスでも数十 µs 程度で読み出せ、IOPS は HDD の数千倍に達します。ただし、NAND フラッシュメモリには次のような性質があります。

* 読み出しと書き込みは\ **ページ**\ （数 KB〜十数 KB 程度）単位で行います。
* すでに書き込んだページを上書きすることはできず、書き直す前に消去が必要です。消去は、多数のページをまとめた\ **ブロック**\ （数 MB 程度）単位でしかできません。
* 1 つのブロックは、決まった回数（数百〜数万回程度。1 セルに記録するビット数が多い TLC や QLC ほど少ない）しか消去・書き込みができません。

これらの制約をホストから隠すのが、SSD のコントローラで動く\ **フラッシュ変換層**\ （Flash Translation Layer：FTL）です。FTL は、ホストから見た論理ブロックアドレスと、フラッシュメモリ上の物理的な位置の対応表を管理します。書き込みのたびに、データを空いているページに書いて対応表を書き換え（上書きせずに別の場所に書く）、古いページは無効とします。無効なページが増えたブロックは、まだ有効なページを別の場所にコピーしてから消去します。これを\ **ガベージコレクション**\ （garbage collection）と呼びます。また、特定のブロックに書き込みが集中しないように分散させる\ **ウェアレベリング**\ （wear leveling）も行います。

ガベージコレクションによるコピーのため、フラッシュメモリへの実際の書き込み量はホストからの書き込み量より多くなります。この比を\ **書き込み増幅**\ （write amplification）と呼びます。OS が不要になった領域を SSD に通知する TRIM コマンドは、ガベージコレクションでの無駄なコピーを減らし、書き込み増幅を抑えます。仮想記憶とよく似た「アドレス変換の層」が、ストレージの中にもあることになります。

NVMe
^^^^

SSD を接続するインターフェースとして、当初は HDD 用に作られた SATA と、そのコマンド体系の AHCI が使われました。AHCI はコマンドのキューが 1 つ（最大 32 コマンド）で、回転待ちのある HDD を前提にした設計でした。

**NVMe**\ （NVM Express）は、PCIe に直接接続するフラッシュメモリ向けに設計されたインターフェースです。最大で約 6 万 5 千個のキューを持ち、各キューに約 6 万 5 千個のコマンドを入れられます。キューは主記憶上に置かれ、ホストはコマンドを投入（submission）キューに書いてドアベルレジスタで知らせ、SSD は完了したコマンドを完了（completion）キューに書いて割り込み（MSI-X）で知らせます。コアごとに専用のキューの組を持たせれば、コア間でロックを取り合わずに並列に I/O を発行できます。フラッシュメモリの内部は多数のチップとチャネルに分かれていて並列に動作できるので、多数のコマンドを同時に発行することが性能を引き出す鍵になります。

キャッシュコヒーレントな I/O
----------------------------

DMA はプロセッサのキャッシュを経由せずに主記憶を読み書きするので、キャッシュとの間で内容の食い違いが起こりえます。具体的には次の 2 つの場合です。

* デバイスが主記憶に書き込んだのに、プロセッサのキャッシュに同じアドレスの古いデータが残っている場合。
* プロセッサがライトバックキャッシュに書いたデータが主記憶にまだ書き戻されていないのに、デバイスが主記憶から古いデータを読む場合。

ハードウェアがこれを解決しない場合、ソフトウェア（デバイスドライバ）が、DMA の前にキャッシュの内容を主記憶に書き戻し（フラッシュ）、DMA の後にキャッシュの該当部分を無効化する必要があります。組み込み向けのプロセッサにはこの方式のものが多くあります。

一方、PC やサーバーのプロセッサの多くは、DMA のアクセスもキャッシュコヒーレンスの仕組み（「:doc:`15_parallel`」で説明します）に参加させ、デバイスの書き込みでキャッシュの古いデータを無効化し、デバイスの読み出しにはキャッシュの最新のデータを返します。これを\ **キャッシュコヒーレントな I/O**\ （cache-coherent I/O）と呼びます。さらに、高速なネットワークの受信データなどを主記憶ではなく直接 L3 キャッシュに書き込んで、プロセッサがすぐに読めるようにする機能を持つプロセッサもあります。

IOMMU
-----

DMA を行うデバイスは、物理アドレスを使って主記憶を直接読み書きします。もしデバイスやそのドライバに誤りがあったり、悪意のあるデバイスが接続されたりすると、OS のメモリを含む任意の場所が書き換えられてしまいます。

**IOMMU**\ （I/O Memory Management Unit）は、デバイスからのメモリアクセスに対してアドレス変換と保護を行う装置です。プロセッサの MMU と同様に、デバイスが使うアドレス（I/O 仮想アドレス）をページテーブルで物理アドレスに変換し、許可されていない領域へのアクセスを禁止します。IOMMU は次のような用途に使われます。

* 保護：各デバイスには、そのデバイス用に OS が用意したバッファにだけアクセスを許します。
* 仮想化：仮想マシンにデバイスを直接割り当てるとき、ゲスト OS が指定したアドレス（ゲストの物理アドレス）を本当の物理アドレスに変換します。
* 連続領域の見かけ：物理的にばらばらのページを、デバイスからは連続した領域に見せます。

Intel の VT-d、AMD の AMD-Vi、Arm の SMMU がその例で、RISC-V でも IOMMU の仕様が定められています。IOMMU にも TLB に相当する変換キャッシュ（IOTLB）があります。

ネットワーク
------------

ネットワークとの接続は\ **NIC**\ （Network Interface Card：ネットワークインターフェースカード）が受け持ちます。現代の NIC は、DMA とディスクリプタのリングを使ってパケットを主記憶と直接やり取りします。送信では、ドライバが送るパケットの位置を送信リングに書いてドアベルで知らせ、NIC がパケットを DMA で読み出して送ります。受信では、NIC が受け取ったパケットを、あらかじめ受信リングに用意されたバッファに DMA で書き込み、割り込みで知らせます。

毎秒数千万個にもなるパケットを処理するために、NIC には次のような機能があります。

* 複数の受信キュー：パケットのヘッダから計算したハッシュ値でキューを振り分け（RSS：Receive Side Scaling）、キューごとに別のコアで処理します。
* オフロード：チェックサムの計算や、大きなデータの TCP セグメントへの分割などを NIC が肩代わりします。
* 割り込みの集約：複数のパケットの到着を 1 回の割り込みでまとめて通知します。

さらに、\ **RDMA**\ （Remote Direct Memory Access）は、あるコンピューターのメモリから別のコンピューターのメモリへ、相手の OS や CPU を介さずに NIC どうしで直接データを転送する仕組みです。InfiniBand や、イーサネット上で RDMA を実現する RoCE（RDMA over Converged Ethernet）があり、スーパーコンピューターや AI の学習用のクラスタ、データセンターのストレージなどで、マイクロ秒単位の低いレイテンシと高い帯域を実現するために使われています。

この章のまとめ
--------------

* I/O デバイスのデータ転送速度は 10 桁近くも異なり、性質の異なるデバイスを共通の仕組みで扱う必要があります。
* プロセッサはデバイスレジスタを、メモリマップト I/O（通常のロード・ストア）またはポートマップト I/O（専用の命令）で操作します。デバイスレジスタの領域はキャッシュしないように設定します。
* データのやり取りの方式にはポーリング、割り込み、DMA があり、高速なデバイスはディスクリプタのリングと DMA を使います。
* 割り込みコントローラが多数の割り込みを優先度に従ってコアに配送します。PCIe のデバイスは MSI/MSI-X で割り込みを通知します。
* バスは共有のパラレルバスから、Point-to-Point の高速シリアル接続へ移りました。
* PCI Express はレーンを束ねて帯域を増やし、世代ごとにおおむね帯域が 2 倍になっています。
* HDD はシークと回転待ちのためランダムアクセスが遅く、SSD はフラッシュメモリの制約をフラッシュ変換層で隠しています。NVMe は多数のキューで SSD の並列性を引き出します。
* DMA とキャッシュの食い違いは、ソフトウェアによるフラッシュ・無効化か、キャッシュコヒーレントな I/O で解決します。
* IOMMU は、デバイスからのメモリアクセスにアドレス変換と保護を提供します。
* NIC は複数のキューやオフロード機能を持ち、RDMA は CPU を介さずにメモリ間で直接データを転送します。
