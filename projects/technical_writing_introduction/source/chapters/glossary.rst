用語集
======

.. glossary::
   :sorted:

   ADR
      Architecture Decision Record の略。設計上の重要な判断を、判断ごとに背景、内容、結果を記した短い文書として記録する手法。

   Diátaxis
      Daniele Procida が提唱した、技術文書の構成の枠組み。技術文書をチュートリアル、ハウツーガイド、リファレンス、解説の 4 種類に分類する。

   Docs as Code
      文書をソースコードと同じ方法で管理する考え方。テキスト形式で書き、バージョン管理システムで管理し、レビューと自動検査を経て公開する。

   一文一義
      一つの文には一つの内容だけを書くという原則。

   逆ピラミッド型
      最も重要な情報を先頭に置き、重要度の高い順に情報を並べる文書の構成。

   敬体
      「です・ます」で文を終える文体。

   常体
      「だ・である」で文を終える文体。

   スタイルガイド
      文体、用語、表記などの規則をまとめた文書。

   体言止め
      文を名詞で終える書き方。箇条書きや表の項目を簡潔に書くときに使う。

   トピックセンテンス
      段落の先頭に置き、その段落の要点を述べる文。

   パラグラフライティング
      1 段落に 1 トピックだけを書き、段落の先頭にトピックセンテンスを置く段落の書き方。

   表記ゆれ
      同じ語を、文書の中で異なる表記で書くこと。「サーバー」と「サーバ」の混在など。

   ブレームレス
      障害の原因を個人の責任として追及せず、誤りを防げなかった仕組みの問題として分析する姿勢。

   ペルソナ
      文書の読者として想定する、具体的な人物像。

   ポストモーテム
      障害の経緯、原因、再発防止策を記録する文書。障害報告書とも呼ぶ。
