バージョン管理と Git
====================

バージョン管理とは
------------------

バージョン管理とは、ファイルの変更履歴を記録し、必要に応じて過去の状態を参照したり復元したりできるようにすることです。

バージョン管理の仕組みを使わずに開発を進めると、次のような問題が起こりがちです。

* ``main_v2.py`` や ``main_最新_修正版.py`` のようなファイルが増え、どれが最新なのか分からなくなります。
* いつ、誰が、なぜ変更したのかが分かりません。
* 動いていた状態に戻したくても、戻す手段がありません。
* 複数人で同じファイルを編集すると、他の人の変更を上書きしてしまいます。

バージョン管理システムを使うと、変更のたびに「何を、いつ、誰が、なぜ変更したか」が記録されます。そのため、過去の任意の時点の状態を確認したり、特定の変更だけを取り消したりできます。

集中型と分散型
--------------

バージョン管理システムは、大きく集中型と分散型に分けられます。

.. list-table::
   :header-rows: 1
   :widths: 20 40 40

   * - 項目
     - 集中型
     - 分散型
   * - 代表例
     - Subversion（SVN）
     - Git、Mercurial
   * - 履歴の保存場所
     - サーバーだけが履歴を持ちます。
     - 各開発者の手元のリポジトリも、すべての履歴を持ちます。
   * - オフラインでの作業
     - コミットや履歴の参照にはサーバーへの接続が必要です。
     - サーバーに接続しなくても、コミットや履歴の参照ができます。
   * - サーバー障害時の影響
     - サーバーが停止すると作業が止まります。
     - 手元で作業を続けられ、どのリポジトリからでも履歴を復元できます。

Git は分散型のバージョン管理システムです。手元のリポジトリに完全な履歴があるため、多くの操作をネットワークに接続せずに高速に実行できます。

Git の特徴
----------

Git には次のような特徴があります。

スナップショットで記録する
   Git はコミットのたびに、その時点のファイル全体の状態をスナップショットとして記録します。変更されていないファイルは、前回と同じデータを参照するだけなので、容量はほとんど増えません。

ブランチが軽量である
   Git のブランチは、特定のコミットを指すだけの小さなデータです。そのため、ブランチの作成や切り替えが一瞬で終わり、気軽にブランチを作って作業を分けられます。

データの完全性が保証される
   Git はすべてのデータをハッシュ値で管理します。ファイルの内容が 1 文字でも変わるとハッシュ値が変わるため、データの破損や改ざんを検出できます。

Git と GitHub の違い
--------------------

Git と GitHub は混同されやすいですが、別のものです。

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 名前
     - 説明
   * - Git
     - バージョン管理システムそのものです。手元のコンピューターにインストールして使うソフトウェアであり、GitHub がなくても使えます。
   * - GitHub
     - Git のリポジトリをインターネット上で保管・共有するためのサービスです。プルリクエストやイシュー（課題管理）など、共同開発を支援する機能を提供しています。

GitHub と同様のサービスには、GitLab や Bitbucket などがあります。本資料では、リモートリポジトリの例として主に GitHub を取り上げます。
