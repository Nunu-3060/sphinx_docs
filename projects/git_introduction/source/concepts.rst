Git の基本概念
==============

Git のコマンドを覚える前に、Git がどのようにファイルを管理しているかを理解しておくと、各コマンドの意味が分かりやすくなります。

3 つのエリア
------------

Git では、ファイルは次の 3 つのエリアを行き来します。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - エリア
     - 説明
   * - ワーキングツリー
     - 実際にファイルを編集する場所です。エクスプローラーやエディターで見えているファイルがこれにあたります。
   * - ステージングエリア
     - 次のコミットに含める変更を一時的に置いておく場所です。インデックスとも呼ばれます。
   * - リポジトリ
     - コミットの履歴を保存する場所です。プロジェクトの最上位にある ``.git`` ディレクトリの中に保存されます。

ファイルを変更してからコミットするまでの流れは、次のとおりです。

.. code-block:: text

   Working tree        Staging area        Repository
        |                   |                   |
        |---- git add ----->|                   |
        |                   |--- git commit --->|
        |                   |                   |
        |<-- git restore ---|                   |
        |                   |<-- git restore ---|
        |                   |    --staged       |

1. ワーキングツリーでファイルを編集します。
2. ``git add`` で、コミットしたい変更をステージングエリアに追加します。
3. ``git commit`` で、ステージングエリアの内容をリポジトリに記録します。

変更を取り消す場合は、逆向きに ``git restore`` を使います。``git restore`` の使い方は :doc:`undo` で説明します。

ステージングエリアがあることで、ワーキングツリーで行った複数の変更のうち、一部だけを選んでコミットできます。たとえば、バグの修正と新機能の追加を同時に進めていても、それぞれを別のコミットとして記録できます。

ファイルの状態
--------------

ワーキングツリーにあるファイルは、Git から見て次のいずれかの状態にあります。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 状態
     - 説明
   * - 未追跡（untracked）
     - Git の管理対象になっていないファイルです。新しく作成したファイルは、最初はこの状態です。
   * - 変更なし（unmodified）
     - 管理対象であり、最後のコミットから変更されていないファイルです。
   * - 変更あり（modified）
     - 管理対象であり、最後のコミットから変更されているが、まだステージされていないファイルです。
   * - ステージ済み（staged）
     - 変更がステージングエリアに追加され、次のコミットに含まれるファイルです。

ファイルの状態は ``git status`` で確認できます。詳しくは :doc:`basic` で説明します。

コミット
--------

コミットとは、ある時点のプロジェクト全体のスナップショットを記録したものです。各コミットには、次の情報が含まれます。

* スナップショット（その時点のすべての管理対象ファイルの内容）
* 作成者と作成日時
* コミットメッセージ
* 親コミット（直前のコミット）への参照

各コミットは親コミットへの参照を持つため、コミットをたどることで過去の履歴を順にさかのぼれます。

コミット ID
^^^^^^^^^^^

各コミットには、内容から計算されたハッシュ値が ID として付けられます。Git は標準で SHA-1 というハッシュ関数を使い、ID は 40 桁の 16 進数で表されます。

.. code-block:: text

   3f5a1c9e8b2d4f6a7c0e1b3d5f7a9c2e4b6d8f0a

40 桁の 16 進数で表せる値の種類は次のとおりであり、異なる内容のコミットが偶然同じ ID になることは、実用上まず起こりません。

.. math::

   16^{40} = 2^{160} \approx 1.46 \times 10^{48}

コミット ID は、他のコミットと区別できる範囲で先頭の数文字に省略できます。``git log --oneline`` などでは、先頭の 7 文字程度が表示されます。

ブランチと HEAD
---------------

ブランチは、特定のコミットを指す名前付きの目印です。新しいコミットを作成すると、現在のブランチは自動的にその新しいコミットを指すように移動します。

HEAD は、現在作業しているブランチを指す特別な目印です。通常、HEAD はブランチを指し、そのブランチがコミットを指しています。

.. code-block:: text

                   HEAD
                    |
                    v
                   main
                    |
                    v
   [A] <-- [B] <-- [C]

上の図では、``main`` ブランチが最新のコミット C を指し、HEAD が ``main`` ブランチを指しています。矢印は、各コミットが親コミットを参照していることを表しています。この状態でコミットすると、コミット C を親とする新しいコミットが作成され、``main`` はその新しいコミットを指すように移動します。

ブランチの詳しい使い方は :doc:`branch` で説明します。
