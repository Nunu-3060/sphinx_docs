用語集
======

本資料で使用している主な用語を、アルファベット順、五十音順にまとめます。

.. glossary::
   :sorted:

   CI
      継続的インテグレーション（Continuous Integration）の略です。コードの変更のたびに、テストなどを自動で実行する仕組みを指します。GitHub では GitHub Actions で実現できます。

   GitHub Actions
      プッシュやプルリクエストの作成などをきっかけに、テストやビルドなどの処理を GitHub のサーバー上で自動的に実行する機能です。

   HEAD
      現在作業しているブランチ、またはコミットを指す特別な目印です。

   イシュー
      バグの報告や機能の要望、作業の予定などを記録する、GitHub の課題管理の機能です。

   コミット
      ある時点のプロジェクト全体のスナップショットを、作成者やメッセージとともにリポジトリに記録したものです。また、それを記録する操作を指します。

   コミット ID
      コミットの内容から計算されるハッシュ値で、コミットを一意に識別するために使います。

   コンフリクト
      マージやリベースの際に、2 つのブランチで同じ箇所が変更されていて、Git が自動で統合できない状態です。競合とも呼びます。

   ステージ
      変更をステージングエリアに追加し、次のコミットに含める操作です。

   ステージングエリア
      次のコミットに含める変更を一時的に置いておく場所です。インデックスとも呼びます。

   フェッチ
      リモートリポジトリの新しいコミットを、ローカルリポジトリに取り込む操作です。

   フォーク
      他の人のリポジトリを、自分の GitHub アカウントに複製したものです。書き込み権限のないリポジトリに変更を提案するときに使います。


   ブランチ
      特定のコミットを指す名前付きの目印です。コミットを作成すると、現在のブランチは新しいコミットを指すように移動します。

   プッシュ
      ローカルリポジトリのコミットを、リモートリポジトリに送信する操作です。

   プル
      フェッチした変更を、現在のブランチに統合する操作です。

   プルリクエスト
      自分のブランチの変更を別のブランチに取り込むよう依頼する、GitHub の機能です。

   マージ
      別のブランチの変更を、現在のブランチに統合する操作です。

   リベース
      現在のブランチのコミットを、別のブランチの先端の後ろに付け替える操作です。

   リポジトリ
      ファイルとその変更履歴を保存する場所です。

   リモートリポジトリ
      GitHub などのサーバー上に置かれたリポジトリです。

   リモート追跡ブランチ
      最後にフェッチした時点での、リモートリポジトリのブランチの位置を記録したものです。``origin/main`` のように表します。

   ローカルリポジトリ
      手元のコンピューターにあるリポジトリです。

   ワーキングツリー
      実際にファイルを編集する場所です。
