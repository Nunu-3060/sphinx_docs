.. _ch-integration:

ゲームへの組み込み
==================

作った音は、ゲームに組み込んで初めて役に立つ。この章では、音声ファイルの形式の選び方、ループ再生、音量のバランスなど、ゲームに音を組み込むときに知っておくべき事柄を説明し、最後に pygame-ce で実際に BGM と効果音を鳴らす。

ファイル形式の選び方
--------------------

ゲームで使う音声ファイルの形式は、主に次の 3 つである。

.. list-table:: 音声ファイルの形式
   :header-rows: 1
   :widths: 18 42 40

   * - 形式
     - 特徴
     - 主な用途
   * - WAV
     - 圧縮しない。ファイルは大きいが、読み込みが速く、音質が劣化しない。
     - 効果音
   * - Ogg Vorbis
     - 非可逆圧縮。ファイルを小さくでき、ループ再生でつなぎ目に隙間が入りにくい。
     - BGM
   * - MP3
     - 非可逆圧縮。広く普及しているが、変換時にファイルの先頭と末尾に短い無音が入るため、ループ再生でつなぎ目に隙間ができやすい。
     - ループしない音声

効果音は短いのでファイルの大きさは問題になりにくく、すぐに鳴らす必要があるため WAV が向いている。BGM は長いので、Ogg Vorbis に変換してファイルを小さくするのが一般的である。ゲームエンジンによっては、読み込み時に独自の形式へ変換するものもある。

WAV から Ogg Vorbis への変換には、音声編集ソフトの Audacity や、コマンドラインツールの FFmpeg などが使える。FFmpeg では次のように変換する（``-q:a`` は品質で、値が大きいほど高音質になる）。

.. code-block:: bat
   :linenos:

   ffmpeg -i bgm_loop.wav -c:a libvorbis -q:a 5 bgm_loop.ogg

8 bit サウンドは、高い周波数の倍音を多く含む。非可逆圧縮の品質を下げすぎると、倍音が崩れてざらついた音になりやすいので、変換後の音を必ず聞いて確かめること。

サンプリング周波数とチャンネル数
--------------------------------

サンプリング周波数は、ゲームエンジンやライブラリの出力設定（多くは 44100 Hz または 48000 Hz）に合わせるとよい。異なるサンプリング周波数のファイルを再生すると、再生時に変換（リサンプリング）が行われ、処理の負荷や音質の変化の原因になる。

8 bit サウンドはもともとモノラルなので、効果音も BGM もモノラル（1 チャンネル）で問題ない。ステレオにするとファイルが 2 倍の大きさになるが、同じ音を左右に入れるだけなら得るものはない。ゲームの中で音を左右に振りたい場合は、ゲームエンジンの機能で再生時に振るとよい。

ファイル名の付け方
------------------

音声ファイルの数は、ゲームの開発が進むとすぐに増える。種類がわかる接頭辞を付け、一定の規則で名前を付けておくと管理しやすい。本書のサンプルでは、効果音に ``se_``、BGM に ``bgm_`` を付けている。

.. list-table:: ファイル名の付け方の例
   :header-rows: 1
   :widths: 40 60

   * - ファイル名
     - 内容
   * - ``se_jump.wav``
     - ジャンプの効果音
   * - ``se_ui_select.wav``
     - メニューの決定音（UI の音であることを示す）
   * - ``bgm_stage1.ogg``
     - ステージ 1 の BGM
   * - ``bgm_stage1_intro.ogg``、``bgm_stage1_loop.ogg``
     - イントロとループ部を分けた BGM

ループ再生
----------

ファイル全体をループする
~~~~~~~~~~~~~~~~~~~~~~~~

イントロのない BGM は、ファイル全体を繰り返し再生すればよい。多くのゲームエンジンやライブラリには、ループ再生を指定する設定がある。ただし、ファイルの末尾と先頭がきれいにつながっていなければ、つなぎ目で音が途切れたりクリック音が出たりする。

「:ref:`ch-bgm`」のシーケンサでは、曲の末尾からはみ出した余韻を先頭に足し込んでいるので、ファイル全体をループ再生してもつなぎ目は自然に聞こえる。音声編集ソフトで BGM を切り出す場合も、ループの長さを小節の長さの整数倍に正確に合わせ、余韻を先頭に重ねる必要がある。

イントロ付きの BGM
~~~~~~~~~~~~~~~~~~

イントロ付きの BGM を再生する方法は 2 つある。

* ループポイントを使う: 1 つのファイルの中で、ループの開始位置と終了位置を指定する。終了位置に達したら開始位置へ戻る。ループポイントを設定できるかどうかは、ゲームエンジンや形式によって異なる。
* ファイルを分ける: イントロとループ部を別のファイルにし、イントロの再生が終わったらループ部のループ再生を始める。どの環境でも使えるが、2 つのファイルの切り替えで隙間が出ないように、再生の予約などの機能を使う必要がある。

ループの位置は、秒数ではなくサンプル数で指定できるとよい。秒数で指定すると丸め誤差が生じ、わずかなずれが繰り返しのたびに聞こえることがある。

音量のバランス
--------------

BGM と効果音の音量
~~~~~~~~~~~~~~~~~~

BGM と効果音が同時に鳴ったとき、効果音が聞き取れることが大切である。一般に、BGM は効果音より小さめに設定する。ゲームの設定画面で、プレイヤーが BGM と効果音の音量を別々に調整できるようにしておくとよい。

クリッピングを防ぐ
~~~~~~~~~~~~~~~~~~

ゲームの中では、BGM と複数の効果音が同時に鳴る。それらの合計が最大の振幅を超えると、「:ref:`ch-shaping`」で説明したクリッピングが起き、音がひずむ。音声ファイルを作る段階で最大振幅に余裕（ヘッドルーム）を残しておき、再生時の音量もそれを考慮して設定する。本書のサンプルでは、効果音の最大振幅を 0.5、BGM を 0.8 にしている。

聞こえる大きさをそろえる
~~~~~~~~~~~~~~~~~~~~~~~~

最大振幅をそろえても、聞こえる大きさがそろうとは限らない。長く鳴る音や、耳が敏感な 2000 Hz から 5000 Hz 付近の成分を多く含む音は、大きく聞こえる。聞こえる大きさを数値で表す指標として\ :term:`ラウドネス`\ があり、国際規格 ITU-R BS.1770 で測定方法が定められている。単位は LUFS（Loudness Units relative to Full Scale）である。

放送の分野では、欧州放送連合（EBU）の勧告 EBU R 128 が番組のラウドネスを -23 LUFS にそろえることを求めている。ゲームには広く統一された基準はないが、プロジェクトの中で目標とするラウドネスを決めて、それにそろえると全体のバランスが取りやすくなる。小規模な開発では、実際にゲームの中で聞きながら調整するのが現実的である。

同時発音数と優先度
------------------

同じ効果音が短い間隔で何度も鳴ると、音が重なって大きくなりすぎたり、ほかの音が聞こえなくなったりする。ゲームエンジンやライブラリには同時に鳴らせる音の数（同時発音数）の上限があり、上限を超えると新しい音が鳴らなかったり、古い音が止められたりする。

これに対処するには、次のような工夫をする。

* 同じ効果音の同時発音数を制限する: 例えば、同じ効果音は 2 つまでとし、それを超えたら最も古いものを止める。
* 優先度を決める: プレイヤーの被ダメージ音など、重要な音は必ず鳴るようにし、重要度の低い音を先に止める。
* 鳴らす間隔を空ける: 同じ効果音を、例えば 0.05 秒以内には再び鳴らさないようにする。

これは、限られたチャンネルを効果音と BGM で取り合っていたファミコンの時代と同じ考え方である。ファミコンのゲームでは、効果音が鳴っている間、BGM のチャンネルの一部が効果音に譲られていた。

遅延
----

キーを押してから効果音が鳴るまでに遅れがあると、操作の手応えが悪くなる。この遅れは、主に音声を出力するための\ :term:`バッファ`\ の大きさで決まる。バッファが小さいほど遅れは短くなるが、小さすぎると処理が間に合わずに音が途切れることがある。44100 Hz で 512 サンプルのバッファなら、バッファ 1 つ分の遅れは約 12 ミリ秒である。

pygame-ce で鳴らす
------------------

ここまでの内容を踏まえて、pygame-ce で BGM と効果音を鳴らすプログラムを作る。pygame-ce は、Python で 2D ゲームを作るためのライブラリ pygame の派生版であり、活発に開発が続けられている。

.. literalinclude:: ../examples/play_pygame.py
   :language: python
   :lineno-match:
   :caption: play_pygame.py

このプログラムは次のことを行っている。

* ``pygame.mixer.pre_init`` で、初期化の前に音声出力の設定（44100 Hz、16 bit、ステレオ、バッファ 512 サンプル）を指定する。出力をステレオにしても、モノラルのファイルは左右の両方から同じ音で鳴る。
* ``pygame.mixer.set_num_channels`` で、効果音の同時発音数を 8 にする。
* 効果音は ``pygame.mixer.Sound`` で読み込む。``Sound`` は音声ファイル全体をメモリに読み込むので、すぐに鳴らせる。
* BGM は ``pygame.mixer.music`` で再生する。``music`` はファイルを少しずつ読み込みながら再生するので、長い BGM に向いている。``play(loops=-1)`` で無限にループ再生する。
* 上下キーで BGM の音量を変えられるようにしている。

先に ``make_all.py`` を実行して ``output`` フォルダに音声ファイルを作ってから、次のコマンドで実行する。

.. code-block:: bat
   :linenos:

   python make_all.py
   python play_pygame.py

スペースキーでジャンプ、C キーでアイテム取得、X キーで爆発の効果音が鳴る。キーを連打して、効果音が重なって鳴ることや、BGM がつなぎ目なくループすることを確かめてほしい。

ゲームエンジンでの扱い
----------------------

Unity や Godot などのゲームエンジンでも、基本的な考え方は同じである。

* 音声ファイルをプロジェクトに取り込み（インポート）、ループするかどうかなどの設定をする。
* 音を鳴らす部品（オーディオソース、オーディオプレーヤーなど）に音声を割り当て、プログラムから再生する。
* BGM 用と効果音用で音量の系統を分け、まとめて音量を調整できるようにする。

具体的な操作は、使うゲームエンジンの公式ドキュメントを参照すること。
