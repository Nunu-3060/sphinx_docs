誕生の背景と設計思想
--------------------

Rust は、Mozilla の社員であったグレイドン・ホーアが個人的に始めたプロジェクトである。のちに Mozilla が、Web ブラウザのような大規模で並行性の高いソフトウェアを安全に書くための言語として開発を支援した。C や C++ で書かれたソフトウェアでは、メモリ管理の誤りに起因する脆弱性が後を絶たず、また並行処理におけるデータ競合の検出も困難であった。

Rust の目標は、C や C++ と同等の性能と低水準の制御を保ちながら、メモリ安全性とスレッド安全性をコンパイル時に保証することである。そのために、GC を使わず、:term:`所有権`\ と\ :term:`借用`\ という独自の仕組みを型システムに組み込んだ。

主な特徴
--------

* **所有権と借用**\ ：各値の所有者は常に 1 つであり、所有者がスコープを抜けると値は自動的に解放される。値への参照（借用）は、「共有参照（読み取り専用）は複数同時に存在できるが、可変参照は 1 つだけ」という規則のもとで、借用チェッカがコンパイル時に検査する。これにより、解放後の使用、二重解放、データ競合をコンパイル時に排除する。
* **ゼロコスト抽象化**\ ：C++ と同様に、ジェネリクスは\ :term:`単相化`\ され、イテレータなどの高水準の抽象化も実行時のコストなしに使える。
* **代数的データ型とパターンマッチ**\ ：値を持てる列挙型（``enum``）と ``match`` 式によって、状態を型安全に表現できる。null は存在せず、値がないことは ``Option`` 型で、失敗し得る処理は ``Result`` 型で表す。
* **トレイト**\ ：型が備える振る舞いを\ :term:`トレイト`\ として定義する。クラスの継承はなく、トレイトによってポリモーフィズムを実現する。
* **unsafe**\ ：ハードウェアの操作や C との連携など、コンパイラが安全性を検証できない処理は ``unsafe`` ブロックの中に限定して記述する。危険な箇所が明示されるため、レビューや監査の範囲を絞り込める。
* **async/await**\ ：非同期処理の構文を言語として持つが、実行するランタイム（Tokio など）はライブラリとして選択する。

主な用途
--------

* システムソフトウェア：Linux カーネル（6.1 から Rust によるコードの取り込みが始まった）、Android、Windows の一部のコンポーネント
* Web ブラウザ：Firefox の CSS エンジンなど
* クラウドインフラ：AWS の Firecracker、Cloudflare のプロキシなど
* コマンドラインツール：ripgrep、fd など
* 開発ツール：Python のパッケージ管理ツール uv や静的解析ツール Ruff、JavaScript 向けの Biome など、他言語向けの高速なツールの実装
* WebAssembly、組込みソフトウェア

エコシステム
------------

* **ビルドツールとパッケージマネージャ**\ ：Cargo。ビルド、依存関係の管理、テスト、ドキュメント生成を一元的に扱う。
* **パッケージリポジトリ**\ ：crates.io
* **開発ツール**\ ：rustup（ツールチェーンの管理）、rustfmt（フォーマッタ）、Clippy（静的解析）、rust-analyzer（言語サーバ）
* **主要なライブラリ**\ ：Tokio（非同期ランタイム）、Serde（シリアライズ）、Axum（Web フレームワーク）

長所と短所
----------

長所

* GC なしでメモリ安全性とスレッド安全性をコンパイル時に保証する。
* C や C++ に匹敵する実行性能を持つ。
* Cargo を中心とした統一的で使いやすいツール群がある。
* コンパイラのエラーメッセージが丁寧で分かりやすい。

短所

* 所有権・借用・ライフタイムの概念の習得に時間がかかる。
* コンパイル時間が長い。
* 循環参照を持つデータ構造（グラフなど）の表現が難しい。
* 非同期処理の仕組みが複雑で、ランタイムの選択も必要である。
