C++
===

基本情報
--------

.. list-table::
   :header-rows: 0
   :widths: 25 75

   * - 登場年
     - 1983 年（1979 年に「C with Classes」として開発開始、1985 年に最初の商用版）
   * - 設計者
     - ビャーネ・ストロヴストルップ（ベル研究所）
   * - 標準仕様
     - ISO/IEC 14882。C++98 以降、C++11 からは 3 年ごとに改訂。最新の発行済み規格は C++23
   * - 主な処理系
     - GCC、Clang、MSVC
   * - 2026 年時点の状況
     - 次期規格 C++26 の策定が最終段階にあり、静的リフレクションや契約プログラミング（contracts）などが加わる予定である。

誕生の背景と設計思想
--------------------

ストロヴストルップは、Simula のクラスによる抽象化の有用性と、C の実行効率を兼ね備えた言語を求めて C++ を開発した。C との高い互換性を保ったことで、既存の C のコードや開発者を取り込みながら普及した。

C++ の中心的な設計原則は\ **ゼロオーバーヘッド原則**\ である。これは「使わない機能にはコストを払わない」「使う機能は手で書いた場合と同等以上に効率的である」という考え方である。高水準の抽象化（クラス、テンプレート）を提供しながら、実行性能では C に匹敵することを目指している。

主な特徴
--------

* **マルチパラダイム**\ ：手続き型、オブジェクト指向、ジェネリックプログラミング、関数型の書き方をすべて支援する。
* **テンプレート**\ ：型や値を引数に取るテンプレートにより、型ごとに最適化されたコードをコンパイル時に生成する（:term:`単相化`）。C++20 では、テンプレート引数の制約を記述するコンセプト（concepts）が導入された。
* **RAII とスマートポインタ**\ ：オブジェクトの寿命に資源の解放を結び付ける :term:`RAII` により、メモリやファイルなどの資源を自動的に解放する。``std::unique_ptr`` や ``std::shared_ptr`` といったスマートポインタを使うことで、``new`` と ``delete`` を直接書く必要はほとんどない。
* **標準ライブラリ**\ ：コンテナ（``vector``、``map`` など）、アルゴリズム、スレッド、正規表現などを含む。
* **継続的な進化**\ ：C++11 でラムダ式、ムーブセマンティクス、``auto``、スレッドが加わり、「モダン C++」と呼ばれる書き方が定着した。C++20 ではコンセプト、モジュール、コルーチン、Ranges が、C++23 では ``std::expected`` や ``std::print`` が加わった。

一方、C との互換性を重視したため、C と同じくメモリ安全ではなく、未定義動作も多い。後方互換性を保ちながら機能を追加し続けた結果、言語仕様は非常に大きく複雑になっている。

主な用途
--------

* ゲームエンジン（Unreal Engine）とゲーム開発
* Web ブラウザ（Chromium、Firefox）
* データベース（MySQL、MongoDB）
* 金融取引システムなど低遅延が求められる分野
* 科学技術計算、機械学習フレームワークの内部実装（PyTorch、TensorFlow）
* 組込みソフトウェア、自動車の制御ソフトウェア

エコシステム
------------

* **ビルドツール**\ ：CMake が事実上の標準であり、Meson、Bazel なども使われる。
* **パッケージマネージャ**\ ：vcpkg、Conan
* **主要なライブラリ**\ ：Boost、Qt、Eigen、fmt
* **ガイドライン**\ ：C++ Core Guidelines（ストロヴストルップらが中心となって作成）

長所と短所
----------

長所

* 高い抽象化と高い実行性能を両立できる。
* C の資産をそのまま利用できる。
* ゲーム、ブラウザ、金融など、性能が重要な分野で豊富な実績とライブラリがある。

短所

* 言語仕様が巨大で複雑であり、習得に時間がかかる。
* メモリ安全ではなく、未定義動作による不具合や脆弱性が起こり得る。
* コンパイル時間が長く、エラーメッセージ（特にテンプレート関連）が難解になりやすい。
* ビルドシステムやパッケージ管理が統一されていない。
