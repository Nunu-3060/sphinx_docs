SQL
===

基本情報
--------

.. list-table::
   :header-rows: 0
   :widths: 25 75

   * - 登場年
     - 1974 年（SEQUEL として発表）
   * - 設計者
     - ドナルド・チェンバリン、レイモンド・ボイス（IBM）
   * - 標準仕様
     - ISO/IEC 9075。1986 年に ANSI、1987 年に ISO で標準化され、最新は SQL:2023 である。
   * - 主な処理系
     - PostgreSQL、MySQL、SQLite、Oracle Database、Microsoft SQL Server など、リレーショナルデータベース管理システム（RDBMS）の各製品
   * - 2026 年時点の状況
     - SQL:2023 で、プロパティグラフへの問い合わせ（SQL/PGQ）や JSON の扱いが強化された。

誕生の背景と設計思想
--------------------

1970 年、IBM のエドガー・F・コッドは、データを「関係（表）」の集まりとして扱うリレーショナルモデルを提唱した。それまでのデータベースでは、プログラムがデータの格納構造をたどりながら目的のデータを探す必要があった。リレーショナルモデルでは、データの論理的な構造と物理的な格納方法が分離され、利用者は「どのようなデータが欲しいか」だけを記述すればよい。

IBM のチェンバリンとボイスは、このモデルに基づく実験的なデータベース System R のための問い合わせ言語として SEQUEL（Structured English Query Language）を設計した。のちに商標の問題から SQL と改名された。英語に近い構文を採用したのは、プログラマ以外の利用者も使えるようにするためである。1979 年に Relational Software 社（現在のオラクル）が最初の商用 RDBMS を発売し、SQL はリレーショナルデータベースの標準言語となった。

主な特徴
--------

* **宣言型**\ ：取り出したいデータの条件を記述し、データの探し方（どの索引を使うか、どの順で表を結合するかなど）は RDBMS のクエリオプティマイザが決める（:term:`宣言型プログラミング`）。
* **集合指向**\ ：1 件ずつ処理するのではなく、行の集合に対して一括で操作を行う。
* **用途ごとの文の分類**\ ：データ定義言語（DDL：``CREATE`` など）、データ操作言語（DML：``SELECT``、``INSERT`` など）、データ制御言語（DCL：``GRANT`` など）、トランザクションの制御（``COMMIT`` など）に分けられる。
* **三値論理**\ ：値が存在しないことを ``NULL`` で表し、``NULL`` との比較の結果は真でも偽でもない「不明」となる。この性質は、誤りの原因になりやすい。
* **方言**\ ：標準仕様は存在するが、各 RDBMS は独自の拡張や仕様の差異を持つ。たとえば取得する行数の制限は、標準では ``FETCH FIRST n ROWS ONLY`` であるが、``LIMIT n`` （PostgreSQL、MySQL、SQLite）や ``TOP n`` （SQL Server）も広く使われる。
* **拡張**\ ：再帰的な共通表式（``WITH RECURSIVE``、SQL:1999）、ウィンドウ関数（SQL:2003）、JSON の扱い（SQL:2016）などが標準に加わり、表現力が高まっている。手続き的な処理は、PL/SQL（Oracle）、T-SQL（SQL Server）、PL/pgSQL（PostgreSQL）などの拡張言語で記述する。

SQL には文章を単語に分割する標準の機能がないため、このサンプルでは単語に分割済みのデータを表に格納している（4〜12 行目）。集計の本体は 15〜20 行目の ``SELECT`` 文であり、``GROUP BY`` で小文字にそろえた単語ごとに行をまとめ、``COUNT(*)`` で行数を数え、``ORDER BY`` で並べ替えている。ほかの言語の実装と異なり、ループや一時的な変数は現れず、「どのような結果が欲しいか」だけを記述している点が宣言型の言語の特徴である。

主な用途
--------

* 業務システム、Web アプリケーションにおけるデータの保存と検索
* データ分析、データウェアハウス（BigQuery、Snowflake、Amazon Redshift）
* 組込みのデータベース（SQLite。スマートフォンのアプリやブラウザの内部でも使われる）
* 分析用の組込みデータベース（DuckDB）

エコシステム
------------

* **RDBMS**\ ：PostgreSQL、MySQL、MariaDB、SQLite、Oracle Database、Microsoft SQL Server
* **アプリケーションからの利用**\ ：各言語のデータベースドライバや、:term:`ORM`\ （Hibernate、Entity Framework、Django ORM、Active Record など）
* **スキーマの管理**\ ：Flyway、Liquibase などのマイグレーションツール

アプリケーションから SQL を組み立てる際に、利用者の入力を文字列として直接連結すると、:term:`SQL インジェクション`\ の脆弱性が生じる。入力値はプレースホルダ（プリペアドステートメント）を使って渡す必要がある。

長所と短所
----------

長所

* 宣言的に記述でき、データの探し方の最適化を RDBMS に任せられる。
* 50 年以上の実績があり、ほぼすべての RDBMS とデータ分析基盤で使える。
* 職種を問わず、多くのエンジニアやデータ分析者に共通する知識となっている。

短所

* RDBMS ごとの方言の差が大きく、移植性は高くない。
* NULL と三値論理の扱いが直感に反することがある。
* 複雑な処理を書くとクエリが長大になり、性能の予測や保守が難しくなる。
* オブジェクト指向の言語のデータ構造との対応付けに手間がかかる（インピーダンスミスマッチ）。
