誕生の背景と設計思想
--------------------

JavaScript は、ネットスケープ社の Web ブラウザ Netscape Navigator で動作する言語として、ブレンダン・アイクがわずか 10 日ほどで最初の版を開発したとされる。当初は Mocha、次に LiveScript と呼ばれていたが、当時注目を集めていた Java にあやかって JavaScript と名付けられた。名称は似ているが、Java とは別の言語である。

JavaScript は、Web ページに手軽に動きを加えるためのスクリプト言語として設計された。構文は Java（すなわち C の系統）に似せつつ、Scheme から第一級関数とクロージャを、Self からプロトタイプによるオブジェクト指向を取り入れた。1997 年には、ブラウザ間の互換性を確保するために ECMAScript として標準化された。

その後、Ajax（2005 年ごろ）による動的な Web アプリケーション、高速な JIT コンパイラを備えた V8 エンジン（2008 年）、サーバサイドの実行環境 Node.js（2009 年）の登場を経て、JavaScript は Web のフロントエンドとバックエンドの両方で使われる言語となった。

主な特徴
--------

* **ブラウザで動作する唯一の標準的な言語**\ ：すべての主要な Web ブラウザが JavaScript の実行環境を備えている（WebAssembly も実行できるが、DOM の操作などは JavaScript を介して行う）。
* **動的型付けかつ弱い型付け**\ ：暗黙の型変換が広く行われる。``==`` による比較は型変換を伴うため、型変換を伴わない ``===`` を使うのが一般的である。
* **第一級関数とクロージャ**\ ：関数を値として受け渡し、外側のスコープの変数を捕捉できる（:term:`クロージャ`）。
* **プロトタイプベースのオブジェクト指向**\ ：オブジェクトはほかのオブジェクト（プロトタイプ）から直接性質を受け継ぐ（:term:`プロトタイプベース`）。ECMAScript 2015 で ``class`` 構文が導入されたが、内部ではプロトタイプの仕組みが使われている。
* **イベントループと非同期処理**\ ：JavaScript のコードは 1 つのスレッドで実行され、I/O などの完了は\ :term:`イベントループ`\ を通じてコールバックとして処理される。Promise（ECMAScript 2015）と ``async``・``await`` （ECMAScript 2017）によって、非同期処理を読みやすく記述できる。
* **ECMAScript 2015 による刷新**\ ：``let``・``const``、アロー関数、クラス、モジュール、テンプレート文字列、分割代入などが追加され、現在の JavaScript の書き方の基礎となった。

主な用途
--------

* Web ブラウザで動作するフロントエンド（React、Vue.js、Angular、Svelte）
* サーバサイド（Node.js、Deno、Bun 上の Express、Fastify など）
* デスクトップアプリ（Electron）、モバイルアプリ（React Native）
* ブラウザの拡張機能、各種アプリケーションのスクリプト

エコシステム
------------

* **実行環境**\ ：Node.js、Deno、Bun
* **パッケージマネージャ**\ ：npm、pnpm、Yarn
* **パッケージリポジトリ**\ ：npm レジストリ（公開パッケージの数が最も多いリポジトリの 1 つ）
* **ビルドツール**\ ：Vite、webpack、esbuild
* **静的解析・整形**\ ：ESLint、Prettier、Biome

長所と短所
----------

長所

* Web ブラウザで動作する唯一の標準的な言語であり、Web 開発には欠かせない。
* フロントエンドとバックエンドを同じ言語で書ける。
* V8 などの JIT コンパイラにより、動的言語としては非常に高速である。
* ライブラリやフレームワーク、情報が非常に豊富である。

短所

* 暗黙の型変換など、歴史的な経緯による言語仕様の癖が多い。
* 動的型付けのため、大規模な開発では型の誤りが問題になりやすい（TypeScript が広く使われる理由である）。
* 依存パッケージの数が膨らみやすく、:term:`サプライチェーン攻撃`\ の標的になりやすい。
* フレームワークやツールの移り変わりが速い。
