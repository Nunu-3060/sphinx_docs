誕生の背景と設計思想
--------------------

Ruby は、まつもとゆきひろ（通称 Matz）が 1993 年に開発を始め、1995 年に公開したオブジェクト指向のスクリプト言語である。Perl のような実用的なテキスト処理の能力と、Smalltalk のような純粋なオブジェクト指向を兼ね備えた言語を目指して設計された。日本で生まれ、国際的に広く使われている数少ないプログラミング言語の 1 つでもある。

Ruby の設計思想は「プログラマの楽しさ」と「プログラマの幸福」を重視することにある。まつもとは、コンピュータの都合よりも人間の感覚に合うことを優先し、自然に読み書きできる言語を目指したと述べている。同じことを複数の方法で書ける柔軟さを許容している点は、「明らかなやり方は 1 つ」を掲げる Python と対照的である。

2004 年に公開された Web アプリケーションフレームワーク Ruby on Rails が、Ruby を世界的に普及させる契機となった。Rails が掲げた「設定より規約（Convention over Configuration）」や「DRY（Don't Repeat Yourself）」の考え方は、ほかの言語の Web フレームワークにも大きな影響を与えた。

主な特徴
--------

* **純粋なオブジェクト指向**\ ：整数や ``nil`` も含め、すべての値がオブジェクトである。``5.times { ... }`` のように、数値に対してもメソッドを呼び出せる。
* **ブロック**\ ：メソッドの呼び出しに処理のまとまり（ブロック）を渡せる。繰り返し、リソースの管理、コールバックなど、さまざまな場面で使われる Ruby らしい書き方である。
* **動的型付け**\ ：Ruby 3.0 で型シグネチャの記述言語 RBS が導入され、Steep などの型検査ツールで静的に検査できるようになった。Stripe が開発した Sorbet という型検査ツールもある。
* **ミックスイン**\ ：クラスの単一継承に加え、モジュールを取り込む\ :term:`ミックスイン`\ によって機能を共有する。
* **オープンクラスとメタプログラミング**\ ：既存のクラス（組込みクラスを含む）にあとからメソッドを追加できる。実行時にメソッドを定義するといった\ :term:`メタプログラミング`\ が容易であり、Rails のような簡潔な記述を可能にしている。
* **実行方式**\ ：CRuby はソースコードをバイトコードに変換して仮想マシン（YARV）で実行する。Ruby 3.1 以降は JIT コンパイラ YJIT が利用でき、Ruby 4.0 では新しい JIT コンパイラ ZJIT も導入された。
* **並行・並列処理**\ ：CRuby にも GVL（Python の GIL に相当）があり、スレッドによる並列処理は制限される。Ruby 3.0 で導入された Ractor を使うと、並列に実行できる。

主な用途
--------

* Web アプリケーション（Ruby on Rails）。GitHub、Shopify、Cookpad などが Rails で構築されたことで知られる。
* スタートアップや新規サービスの迅速な開発
* 開発ツール：Homebrew、CocoaPods、fastlane、Chef など
* テキスト処理、システム管理のスクリプト

エコシステム
------------

* **パッケージマネージャ**\ ：RubyGems、Bundler（依存関係の管理）
* **パッケージリポジトリ**\ ：RubyGems.org
* **主要なフレームワーク**\ ：Ruby on Rails、Sinatra、Hanami
* **開発ツール**\ ：RuboCop（静的解析）、RSpec・Minitest（テスト）

長所と短所
----------

長所

* 簡潔で表現力が高く、読み書きしやすい。
* Ruby on Rails により、Web アプリケーションを迅速に開発できる。
* テストを重視する文化が根付いており、テストのためのツールが充実している。

短所

* 実行速度がコンパイル型の言語より遅い（YJIT などで改善されつつある）。
* 動的な機能が強力な反面、大規模なコードでは処理の流れを追いにくくなることがある。
* Web 開発以外の分野では採用例が少なく、利用者の数も以前より伸び悩んでいる。
