Java
====

基本情報
--------

.. list-table::
   :header-rows: 0
   :widths: 25 75

   * - 登場年
     - 1995 年（1996 年に JDK 1.0）
   * - 設計者
     - ジェームズ・ゴスリンら（サン・マイクロシステムズ）。2010 年にサンを買収したオラクルが開発を主導している。
   * - 標準仕様
     - Java Language Specification（JLS）と Java Virtual Machine Specification。新機能は JEP（JDK Enhancement Proposal）として提案・策定される。
   * - 主な処理系
     - OpenJDK と、それを基にした各社のディストリビューション（Oracle JDK、Eclipse Temurin、Amazon Corretto など）、GraalVM
   * - 2026 年時点の状況
     - 6 か月ごとに新しいバージョンが公開され、2 年ごとに長期サポート（:term:`LTS`）版が指定される。最新の LTS 版は Java 25（2025 年 9 月）である。

誕生の背景と設計思想
--------------------

Java は、サン・マイクロシステムズで家電製品向けの言語を開発するプロジェクト（Green プロジェクト、言語の当初の名称は Oak）から生まれた。さまざまな CPU を搭載する機器で同じプログラムを動かす必要があったことから、プログラムを仮想マシン（JVM）向けのバイトコードにコンパイルする方式が採用された。家電向けの市場は立ち上がらなかったが、同じ時期に普及し始めた Web ブラウザ上で動くアプレットによって Java は注目を集めた。

Java は「Write once, run anywhere（一度書けば、どこでも動く）」を標語とし、C++ に似た親しみやすい構文を持ちながら、ポインタ演算、多重継承、手動のメモリ管理といった C++ の複雑で危険な機能を取り除いた。単純さ、移植性、安全性を重視した設計である。

主な特徴
--------

* **JVM 上での実行**\ ：Java のソースコードはバイトコードにコンパイルされ、JVM が実行する。HotSpot VM は、頻繁に実行される部分を :term:`JIT コンパイル`\ して高い性能を得る。JVM 上では Kotlin、Scala、Clojure など Java 以外の言語も動作する。
* **クラスベースのオブジェクト指向**\ ：すべてのコードはクラスの中に書く。クラスの多重継承はなく、インタフェースによって複数の型を実装する。
* **ガベージコレクション**\ ：G1 GC を標準とし、停止時間を極めて短く抑える ZGC など、用途に応じて GC を選択できる。
* **検査例外**\ ：メソッドが送出し得る例外の一部を宣言させ、呼び出し側での処理を強制する。
* **後方互換性**\ ：古いバージョン向けに書かれたコードやライブラリが、新しい JVM でもそのまま動作することが重視されている。
* **継続的な言語の改良**\ ：Java 8（2014 年）でラムダ式とストリーム API、Java 10 でローカル変数の型推論（``var``）、Java 16 でレコード、Java 17 でシールクラス、Java 21 で仮想スレッドと switch のパターンマッチが正式機能となった。Java 25 では、クラス宣言を省略して小さなプログラムを書ける機能（JEP 512）が正式機能となった。

特に Java 21 で導入された仮想スレッドは、JVM が管理する軽量なスレッド（:term:`グリーンスレッド`）であり、従来の同期的な書き方のまま大量の並行処理を扱えるようにした。

主な用途
--------

* 企業の基幹システム、金融機関のシステムなどの業務アプリケーション
* Web アプリケーションのバックエンド（Spring Boot など）
* 大規模データ処理：Apache Hadoop、Apache Kafka、Elasticsearch など
* Android アプリ（現在は Kotlin が推奨されているが、Java も使える）
* 開発ツール：IntelliJ IDEA、Eclipse

エコシステム
------------

* **ビルドツール**\ ：Maven、Gradle
* **パッケージリポジトリ**\ ：Maven Central
* **主要なフレームワーク**\ ：Spring（Spring Boot）、Jakarta EE、Quarkus、Micronaut
* **開発環境**\ ：IntelliJ IDEA、Eclipse、Visual Studio Code

長所と短所
----------

長所

* JVM による高い移植性と、JIT コンパイルによる高い実行性能を持つ。
* 後方互換性が高く、長期間にわたって保守するシステムに向く。
* ライブラリ、フレームワーク、開発ツール、技術者の層が厚い。
* 静的型付けと充実した開発環境により、大規模なチームでの開発に向く。

短所

* 記述が冗長になりやすい（近年の改良で改善されつつある）。
* JVM の起動時間とメモリ使用量が大きい。ただし GraalVM Native Image などで改善できる。
* null 安全ではなく、``NullPointerException`` が起こり得る。
