C

--------

誕生の背景と設計思想
--------------------

C は、ベル研究所で UNIX を開発する過程で生まれた。UNIX は当初アセンブリ言語で書かれていたが、リッチーは BCPL とその後継の B を発展させて C を設計し、1973 年に UNIX のカーネルの大部分を C で書き直した。OS を高水準言語で記述したことで、UNIX は異なるハードウェアへ移植しやすくなり、C も UNIX とともに広まった。

C の設計思想は「プログラマを信頼する」ことにある。言語仕様は小さく、メモリやハードウェアを直接操作する手段を提供する一方、安全性の検査の多くはプログラマに委ねられている。1978 年にカーニハンとリッチーが著した『プログラミング言語 C』（通称 K&R）は、長く事実上の仕様書として扱われた。

主な特徴
--------

* **静的型付け**\ ：型は静的に検査されるが、ポインタの型変換や整数と浮動小数点数の暗黙の変換が許されるなど、型による保護は比較的弱い。
* **AOT コンパイル**\ ：ソースコードは機械語に直接コンパイルされ、ランタイムはほぼ不要である。実行性能が高く、実行ファイルも小さい。
* **手動のメモリ管理**\ ：ヒープ領域は ``malloc`` と ``free`` で明示的に確保・解放する。ポインタによってメモリを直接操作できるが、範囲外アクセスや解放後の使用は\ :term:`未定義動作`\ となる。
* **プリプロセッサ**\ ：``#include`` や ``#define`` によるテキスト置換でソースコードを組み立てる。
* **最小限の標準ライブラリ**\ ：文字列処理、入出力、メモリ操作などに限られ、連想配列や動的配列のようなデータ構造は標準では提供されない。

C は、OS の API や多くのライブラリが公開するインタフェースの事実上の標準でもある。ほかの言語から既存のライブラリを呼び出す :term:`FFI` は、多くの場合 C の呼び出し規約（:term:`ABI`）を介して行われる。

C23 では、``nullptr``、``bool``・``true``・``false`` のキーワード化、``typeof``、``constexpr`` （オブジェクトのみ）、``#embed`` によるバイナリファイルの埋め込み、2 進数リテラルなどが追加された。

コード例
--------

.. literalinclude:: ../../examples/c/word_count.c

C の標準ライブラリには連想配列がないため、10〜13 行目で単語と出現回数の組を構造体として定義し、17〜29 行目で配列を線形探索して出現回数を数えている。単語の切り出し（49〜64 行目）も、正規表現を使わずに 1 文字ずつ判定して行う。並べ替えには標準ライブラリの ``qsort`` を使い、比較関数を関数ポインタとして渡す（66 行目）。

格納できる単語の数と長さを固定長の配列（7〜8 行目）で制限している点にも注意してほしい。可変長にするには ``malloc`` や ``realloc`` でメモリを確保し、使い終わったら ``free`` で解放する必要がある。ほかの言語の実装と比べると、C では低水準の処理を自分で書く必要があることが分かる。

主な用途
--------

* OS のカーネル（Linux、Windows や macOS のカーネルの大部分）
* 組込みソフトウェア、マイコンのファームウェア
* データベース（SQLite、PostgreSQL）や Web サーバ（nginx）などのミドルウェア
* ほかの言語の処理系（CPython、Ruby の処理系 CRuby、PHP の Zend Engine）
* 高性能な数値計算ライブラリ

エコシステム
------------

* **ビルドツール**\ ：Make、CMake、Meson
* **パッケージマネージャ**\ ：言語標準のものはない。OS のパッケージ管理（apt など）や、C/C++ 向けの vcpkg、Conan が使われる。
* **静的解析・検査**\ ：clang-tidy、Clang Static Analyzer、AddressSanitizer などのサニタイザ

長所と短所
----------

長所

* 実行性能が高く、メモリ使用量と実行ファイルのサイズが小さい。
* ほぼすべてのプラットフォームにコンパイラが存在し、移植性が高い。
* ハードウェアや OS の機能を直接扱える。
* 言語仕様が小さく、生成される機械語を予測しやすい。

短所

* メモリ安全ではなく、バッファオーバーフローなどの脆弱性を生みやすい。
* 抽象化の手段（ジェネリクス、名前空間、例外など）が乏しく、大規模な開発では記述量が増える。
* 未定義動作が多く、コンパイラの最適化によって予期しない挙動となることがある。
* 標準的なパッケージ管理の仕組みがない。
