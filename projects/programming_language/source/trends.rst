今後の動向
==========

本章では、2026 年時点でプログラミング言語を取り巻く主な動向を述べる。

メモリ安全性への移行
--------------------

Microsoft や Google は、自社製品の深刻な脆弱性のおよそ 7 割がメモリ安全性に関する誤りに起因すると報告してきた。こうした状況を受けて、2022 年に米国国家安全保障局（NSA）がメモリ安全な言語の利用を推奨する文書 [NSA-Memory-Safety]_ を公開し、その後も米国の政府機関が、ソフトウェアの製造者にメモリ安全な言語への移行計画を求める文書を相次いで公開した。

この流れの中で、C や C++ で書かれてきた領域に Rust を導入する動きが広がっている。

* Linux カーネルは、2022 年のバージョン 6.1 から Rust によるコードの取り込みを始めた。
* Android は新規のコードに Rust などのメモリ安全な言語を積極的に採用しており、Google はこれによってメモリ安全性に関する脆弱性の割合が大きく減少したと報告している [Android-Memory-Safety]_。
* Windows のカーネルや、各社のクラウドインフラにも Rust で書かれたコンポーネントが導入されている。

既存の膨大な C や C++ のコードをすべて書き換えることは現実的ではないため、C++ 自体の安全性を高める取り組みも進められている。標準ライブラリの境界検査を有効にする強化モード（hardening）や、安全でない機能の使用を制限する「プロファイル」の検討がその例である。

WebAssembly の広がり
--------------------

:term:`WebAssembly`\ （Wasm）は、Web ブラウザ上で高速に動作する、CPU に依存しないバイナリ形式の命令セットである。2019 年に W3C の勧告となった。C、C++、Rust などで書いたプログラムを WebAssembly にコンパイルすることで、ブラウザ上でネイティブに近い性能で実行できる。

WebAssembly 上で GC を扱う仕組み（WasmGC）が主要なブラウザに実装されたことで、Kotlin、Dart、Java などの GC を持つ言語も効率よく WebAssembly に対応できるようになった。また、ブラウザの外でも、WASI（WebAssembly System Interface）によって、サーバやエッジ環境で安全に隔離されたプログラムを実行する用途が広がっている。

型の重視
--------

動的型付けの言語に型を導入する動きが、あらゆる分野で進んでいる。JavaScript に対する TypeScript の普及に加えて、Python の型ヒント、Ruby の RBS、PHP の型宣言のように、動的型付けの言語自身も型の記述と検査の仕組みを取り入れてきた。大規模なコードの保守、エディタによる支援、後述する AI によるコードの生成の観点から、型の情報の価値はさらに高まっている。

また、静的型付けの言語でも、null 安全、代数的データ型とパターンマッチ、データ競合のコンパイル時の検出（Rust、Swift 6）など、より多くの誤りを型システムで検出しようとする傾向が続いている。

開発ツールの高速化
------------------

近年、言語の処理系や開発ツールを、Rust や Go などの高速な言語で書き直す動きが目立つ。Python のパッケージ管理ツール uv や静的解析ツール Ruff、JavaScript のバンドラ esbuild（Go）や静的解析・整形ツール Biome（Rust）などがその例である。TypeScript のコンパイラ自体も、Go で書き直したネイティブ版の開発が進められている。開発ツールの高速化は、大規模なコードベースでの開発体験を大きく改善している。

AI によるコード生成と言語
-------------------------

大規模言語モデルを用いたコーディング支援ツールが急速に普及し、コードの生成、補完、レビュー、リファクタリングにおいて AI が日常的に使われるようになった。これは言語の選択にも影響を与え始めている。

* AI の学習データとして大量のコードが存在する言語（Python、JavaScript、TypeScript、Java など）では、生成されるコードの品質が高い傾向がある。
* 静的型付けの言語では、型検査やコンパイラのエラーが、AI が生成したコードの誤りを検出するための手掛かりとなる。GitHub Octoverse の 2025 年の報告 [Octoverse]_ でも、TypeScript の利用の拡大と AI による開発支援の普及との関連が指摘されている。
* 一方で、AI が生成したコードを人間がレビューし、理解し、保守する必要があることに変わりはない。言語の読みやすさや、誤りを早期に検出する仕組みの重要性は、むしろ高まっているといえる。

まとめ
------

プログラミング言語の歴史は、より安全に、より効率よく、より大規模なソフトウェアを書くための工夫の積み重ねである。新しい言語は既存の言語の課題を解決するために生まれ、既存の言語も新しい言語から機能を取り入れて進化を続けている。言語ごとの設計思想と得意分野を理解しておくことは、目的に合った言語を選ぶうえでも、使い慣れた言語をより深く理解するうえでも役立つ。
