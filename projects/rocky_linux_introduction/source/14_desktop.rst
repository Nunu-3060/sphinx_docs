デスクトップ環境の利用
======================

本書はサーバー用途を中心に解説していますが、Rocky Linux はデスクトップ環境（GUI）を導入して、開発用の端末や、GUI の管理ツールを使う環境としても利用できます。この章では、デスクトップ環境の導入方法と基本的な使い方、リモートデスクトップによる接続を説明します。

Rocky Linux のデスクトップ環境
------------------------------

Rocky Linux の標準のデスクトップ環境は :term:`GNOME` です。NVIDIA の GPU を搭載したマシンでデスクトップ環境を快適に使うには、GPU のドライバーの導入が必要です（「:ref:`ch-gpu`」を参照）。Rocky Linux 10 では GNOME 47 が採用されています。また、Rocky Linux 9 から、標準のアプリケーションの一部が入れ替わっています。例えば、端末のアプリケーションは GNOME Terminal から Ptyxis に、テキストエディターは gedit から GNOME Text Editor に変わりました。LibreOffice などの一部のアプリケーションは標準のリポジトリに含まれなくなり、Flatpak（「アプリケーションの追加」の節を参照）で導入します。

Rocky Linux 10 では、画面を描画する仕組み（ディスプレイサーバー）が :term:`Wayland` に一本化され、従来の X.Org サーバー（X11）は削除されました（「:ref:`sec-rocky10-changes`」を参照）。X11 向けに作られたアプリケーションは、Wayland の上で X11 の機能を提供する :term:`Xwayland` によって、多くの場合そのまま動作します。ただし、画面全体を取得するツールや、他のウィンドウを操作するツールなど、X11 の仕組みに強く依存するアプリケーションは動作しない場合があります。

サーバーにデスクトップ環境を導入するかどうか
--------------------------------------------

デスクトップ環境を導入すると、次のような影響があります。サーバーとして使う場合は、必要性をよく検討してください。

* 多数のパッケージが導入されるため、ディスクの使用量と、セキュリティアップデートの対象が増えます。
* GUI のためにメモリと CPU を消費します。
* Web サーバーなどの用途では、Cockpit（「:ref:`ch-log-monitoring`」を参照）を使えば GUI で管理できるため、デスクトップ環境は必要ありません。

一方、次のような用途ではデスクトップ環境が役に立ちます。

* Rocky Linux 上で動作する GUI のアプリケーションを開発・検証する場合
* 本番環境と同じ OS で、開発用の端末を用意する場合
* GUI でしか操作できない管理ツールやインストーラーを使う場合

デスクトップ環境の導入
----------------------

インストール時に導入する
~~~~~~~~~~~~~~~~~~~~~~~~

インストール時の「ソフトウェアの選択」で、次のいずれかのベース環境を選ぶと、デスクトップ環境が導入されます（「:ref:`ch-installation`」を参照）。

.. list-table:: デスクトップ環境を含むベース環境
   :header-rows: 1
   :widths: 30 70

   * - ベース環境
     - 内容
   * - サーバー（GUI 使用）（Server with GUI）
     - サーバー向けの構成に GNOME を加えたもの
   * - ワークステーション（Workstation）
     - デスクトップ用途の構成。オフィスソフトなどのアプリケーションも含む

インストール後に導入する
~~~~~~~~~~~~~~~~~~~~~~~~

最小構成でインストールしたシステムにも、後からデスクトップ環境を導入できます。ベース環境はパッケージグループの一種（環境グループ）として提供されています。

.. code-block:: console
   :linenos:

   $ dnf group list
   $ sudo dnf group install "Server with GUI"
   $ sudo systemctl set-default graphical.target
   $ sudo systemctl reboot

1 行目で導入できる環境グループの名前を確認し、2 行目で導入します。3 行目で起動時のターゲットを ``graphical.target`` に変更すると、次回の起動時から GUI のログイン画面が表示されます（「:ref:`sec-boot-target`」を参照）。

日本語環境の設定
----------------

GUI のログイン画面でログインした後、日本語で表示・入力できるようにします。

1. 日本語のフォントと入力メソッドを導入します。「:ref:`ch-initial-setup`」で ``langpacks-ja`` を導入済みの場合、この手順は不要です。

   .. code-block:: console
      :linenos:

      $ sudo dnf install langpacks-ja

2. 画面右上のメニューから「設定」を開き、「システム」→「地域と言語」で、表示言語を「日本語」にします。変更はログインし直すと反映されます。
3. 「設定」の「キーボード」→「入力ソース」で「入力ソースを追加」を選び、「日本語」の入力メソッドを追加します。
4. 入力ソースは、:kbd:`Super+Space` （:kbd:`Super` は Windows キー）で切り替えます。

基本的な操作
------------

GNOME の基本的な操作は次のとおりです。

.. list-table:: GNOME の基本的な操作
   :header-rows: 1
   :widths: 35 65

   * - 操作
     - 動作
   * - :kbd:`Super` キー、または画面左上の「アクティビティ」
     - アクティビティ画面を開く。開いているウィンドウの一覧と、アプリケーションの検索が表示される
   * - アクティビティ画面で文字を入力
     - アプリケーションやファイルを検索する。例えば「端末」と入力すると端末（ターミナル）を起動できる
   * - :kbd:`Super+A`
     - 導入されているアプリケーションの一覧を表示する
   * - 画面右上のメニュー
     - ネットワーク、音量、電源、設定などを操作する

端末の中では、これまでの章で説明したコマンドをそのまま使えます。

アプリケーションの追加
----------------------

デスクトップ用のアプリケーションは、次の方法で導入できます。

.. list-table:: アプリケーションの導入方法
   :header-rows: 1
   :widths: 25 75

   * - 方法
     - 内容
   * - ``dnf``
     - Rocky Linux のリポジトリや EPEL からパッケージとして導入する（「:ref:`ch-package`」を参照）
   * - ソフトウェア
     - GNOME の GUI のアプリケーション管理ツール。検索して導入できる
   * - :term:`Flatpak`
     - OS から独立した形式で配布されるアプリケーションを導入する仕組み。OS のパッケージより新しいバージョンのアプリケーションを使える

Flatpak のアプリケーションの主な配布元は Flathub です。Flathub を登録してアプリケーションを導入するには、次のようにします。

.. code-block:: console
   :linenos:

   $ sudo dnf install flatpak
   $ flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
   $ flatpak search --user firefox
   $ flatpak install --user flathub org.mozilla.firefox

``--user`` を付けると、自分のホームディレクトリにだけ導入され、管理者権限は不要です。Flathub のアプリケーションは、Rocky Linux のプロジェクトではなく、それぞれの開発者などによって提供されています。業務で使う場合は、提供元を確認してください。

リモートデスクトップによる接続
------------------------------

デスクトップ環境を導入したサーバーには、クライアント PC からリモートデスクトップで接続できます。Rocky Linux 10 の GNOME には、:term:`RDP` （Remote Desktop Protocol）に対応した「GNOME リモートデスクトップ」の機能が含まれています。RDP は Windows のリモートデスクトップと同じプロトコルのため、Windows 標準の「リモートデスクトップ接続」（``mstsc``）から接続できます。なお、Rocky Linux 10 では TigerVNC が削除され、VNC サーバーは提供されていません。

GNOME リモートデスクトップには、次の 2 つの方式があります。

.. list-table:: GNOME リモートデスクトップの方式
   :header-rows: 1
   :widths: 25 75

   * - 方式
     - 内容
   * - デスクトップ共有
     - サーバーでログインしている画面を、そのままリモートから操作する。サーバーの画面の前に人がいる環境向け
   * - リモートログイン
     - サーバーでログインしていなくても、リモートから新しくログインして操作する。画面を接続していないサーバー向け

リモートログインを設定する手順は次のとおりです。

1. サーバーで GUI にログインし、「設定」→「システム」→「リモートデスクトップ」を開きます。
2. 「リモートログイン」のタブで、ロックを解除してから「リモートログイン」を有効にし、接続に使うユーザー名とパスワードを設定します。ここで設定するのは RDP の接続用の資格情報で、OS のユーザーのパスワードとは別のものです。
3. ファイアウォールで RDP のポート（3389/tcp）を許可します。

   .. code-block:: console
      :linenos:

      $ sudo firewall-cmd --permanent --add-port=3389/tcp
      $ sudo firewall-cmd --reload

4. クライアント PC で「リモートデスクトップ接続」を起動し、サーバーの IP アドレスを入力して接続します。最初に手順 2 で設定した資格情報を入力し、次に表示される GNOME のログイン画面で OS のユーザーとしてログインします。

.. warning::

   RDP のポートをインターネットに直接公開しないでください。リモートから接続する場合は、VPN を経由するか、接続元のネットワークを firewalld で限定してください（「:ref:`ch-security`」を参照）。

GUI と CUI の切り替え
---------------------

デスクトップ環境を導入したシステムでも、CUI で操作することができます。

* GUI の実行中に :kbd:`Ctrl+Alt+F3` から :kbd:`Ctrl+Alt+F6` を押すと、CUI のログイン画面（仮想コンソール）に切り替わります。GUI に戻るには、GUI が動作している仮想コンソール（通常は :kbd:`Ctrl+Alt+F1` または :kbd:`Ctrl+Alt+F2`）に切り替えます。
* 普段は CUI で起動し、必要なときだけ GUI を使う場合は、既定のターゲットを ``multi-user.target`` に戻し、必要なときに ``sudo systemctl isolate graphical.target`` で GUI を起動します。

.. code-block:: console
   :linenos:

   $ sudo systemctl set-default multi-user.target
   $ sudo systemctl isolate graphical.target
