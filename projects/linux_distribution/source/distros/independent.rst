独立系
======

本節では、Debian 系、Red Hat 系、SUSE 系のいずれにも属さず、独自のパッケージ管理と方針を持つ代表的なディストリビューションを紹介する。

Arch Linux
----------

Arch Linux は、簡潔さと利用者による制御を重視するローリングリリースのディストリビューションである。最小限の構成から、利用者が必要なものを選んでシステムを組み上げる。

.. list-table:: Arch Linux の基本情報
   :header-rows: 0
   :widths: 30 70
   :stub-columns: 1

   * - 開発主体
     - Arch Linux プロジェクト（コミュニティ）
   * - 初版
     - 2002 年 3 月（Arch Linux 0.1）
   * - 最新版
     - ローリングリリースのため、バージョンの区切りはない（インストールイメージは毎月更新される）
   * - パッケージ管理
     - pkg.tar.zst 形式、pacman
   * - リリースモデル
     - ローリングリリース
   * - サポート期間
     - 常に最新の状態のみをサポートする

**特徴**

* 簡潔さ（simplicity）、近代性（modernity）、実用主義（pragmatism）、利用者中心（user centrality）、汎用性（versatility）を原則に掲げる。ここでの簡潔さとは、使いやすさではなく、不要な追加や変更をしないことを意味する。
* インストールは原則として手作業で行う。ガイド付きのインストールスクリプト archinstall もインストールイメージに含まれている。
* 公式ドキュメントの ArchWiki は内容が充実しており、Arch Linux 以外の利用者にも参照されている。
* 利用者がビルドスクリプト（PKGBUILD）を共有する AUR（Arch User Repository）がある。AUR のパッケージは公式のサポート対象外であるため、ビルドスクリプトの内容を確認してから使う必要がある。
* システムの一部だけを更新する部分更新はサポートされない。更新は常に ``pacman -Syu`` でシステム全体に対して行う。
* 公式にサポートするアーキテクチャは x86_64 のみである。
* Manjaro、EndeavourOS、Valve 社の SteamOS 3 など、Arch Linux を基にしたディストリビューションがある。

**主な用途**

最新のソフトウェアを使いたい上級者のデスクトップや、Linux の仕組みを学ぶ環境として使われる。

Gentoo
------

Gentoo は、ソースコードからのビルドを基本とするディストリビューションである。利用者は必要な機能を選択してビルドし、自分の環境に最適化したシステムを構築できる。

.. list-table:: Gentoo の基本情報
   :header-rows: 0
   :widths: 30 70
   :stub-columns: 1

   * - 開発主体
     - Gentoo Foundation とコミュニティ（Daniel Robbins が創設）
   * - 初版
     - 2002 年 3 月（Gentoo 1.0）
   * - 最新版
     - ローリングリリースのため、バージョンの区切りはない
   * - パッケージ管理
     - ebuild（ビルド手順を記述したスクリプト）、Portage（コマンドは emerge）
   * - リリースモデル
     - ローリングリリース
   * - サポート期間
     - 常に最新の状態のみをサポートする

**特徴**

* USE フラグにより、各ソフトウェアに組み込む機能をシステム全体またはパッケージ単位で選択できる。
* コンパイラの最適化オプションを指定して、システム全体をビルドできる。
* 2023 年 12 月から、ビルド済みのバイナリパッケージも公式に提供している。
* 標準の init システムは OpenRC であり、systemd も選択できる。C ライブラリも glibc と musl から選択できる。
* ChromeOS の基盤となる ChromiumOS のビルドシステムには Portage が使われている。

**主な用途**

細かな最適化やカスタマイズが必要な環境や、ディストリビューションの仕組みを学ぶ環境として使われる。

Slackware
---------

Slackware は、1993 年から開発が続く現存最古のディストリビューションである。創設者の Patrick Volkerding が中心となって管理しており、伝統的な UNIX に近い簡潔な構成を維持している。

.. list-table:: Slackware の基本情報
   :header-rows: 0
   :widths: 30 70
   :stub-columns: 1

   * - 開発主体
     - Patrick Volkerding とコミュニティ
   * - 初版
     - 1993 年 7 月
   * - 最新版
     - Slackware 15.0（2022 年 2 月）。次期版の開発は開発版の slackware-current で進められている
   * - パッケージ管理
     - txz 形式、pkgtools（installpkg、upgradepkg、removepkg）、slackpkg
   * - リリースモデル
     - 不定期の固定リリース
   * - サポート期間
     - 明示されていない

**特徴**

* パッケージ管理ツールは依存関係を自動で解決しない。依存関係は利用者が把握して管理する。
* 公式リポジトリにないソフトウェアは、コミュニティが管理する SlackBuilds.org のビルドスクリプトを使って導入することが多い。
* systemd を採用せず、BSD 風の init スクリプト（/etc/rc.d 配下）で起動処理を行う。

**主な用途**

UNIX の伝統的な構成を好む利用者や、Linux の仕組みを学ぶ環境として使われる。

Alpine Linux
------------

Alpine Linux は、小ささ、簡潔さ、セキュリティを重視するディストリビューションである。C ライブラリに musl を、基本コマンドに BusyBox を採用し、非常に小さなフットプリントを実現している。

.. list-table:: Alpine Linux の基本情報
   :header-rows: 0
   :widths: 30 70
   :stub-columns: 1

   * - 開発主体
     - Alpine Linux 開発チーム（Natanael Copa が創設）
   * - 初版
     - 2005 年（開発開始）
   * - 最新版
     - Alpine Linux 3.24（2026 年 6 月）
   * - パッケージ管理
     - apk 形式、apk
   * - リリースモデル
     - 固定リリース（約 6 か月ごと）。開発版の edge はローリングリリース
   * - サポート期間
     - main リポジトリのパッケージは約 2 年

**特徴**

* コンテナのベースイメージは数 MB と小さく、イメージの容量や取得時間を抑えられる。
* init システムには OpenRC を採用している。
* C ライブラリが musl であるため、glibc を前提としたソフトウェアやビルド済みバイナリがそのままでは動作しないことがある。また、名前解決などで glibc と挙動が異なる場合がある。
* OS 全体をメモリ上で動作させるディスクレスモードがあり、ネットワーク機器などにも使われる。
* 不具合の修正は最新の安定版にのみ提供され、それ以前のサポート中の版にはセキュリティ修正のみが提供される。

**主な用途**

コンテナのベースイメージとして広く使われる。ルータやファイアウォールなどのネットワーク機器、組込み機器にも使われる。
