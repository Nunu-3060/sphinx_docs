用語集
======

本書に登場する主な用語の意味を示す。英字で始まる用語をアルファベット順に、それ以外の用語を五十音順に並べた。各用語の末尾には、その用語を扱っている章を示す。

英字
----

.. glossary::

   ACID 特性
      トランザクションが満たすべき原子性（Atomicity）・一貫性（Consistency）・分離性（Isolation）・永続性（Durability）の 4 つの性質である。

      関連する章: 「:doc:`ch11_databases`」

   ALU
      算術論理演算装置（Arithmetic Logic Unit）である。CPU の中で加算・減算・論理演算・シフト・比較などを行う組み合わせ回路である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   ASCII
      英字、数字、記号、制御文字に 0〜127 の番号を割り当てた 7 ビットの文字コードである。1963 年に米国で制定された。

      関連する章: 「:doc:`ch01_data_representation`」

   ASLR
      プログラムの起動ごとに、スタック、ヒープ、ライブラリなどを置く仮想アドレスをランダムに変える緩和策である。Address Space Layout Randomization の略である。攻撃者が実行を移すべきアドレスを事前に知ることを難しくする。

      関連する章: 「:doc:`ch14_application_security`」

   Belady の異常
      ページ置換に FIFO を使うと、ページフレームを増やしたのにページフォールトの回数が増えることがある現象である。LRU や最適置換では起きない。

      関連する章: 「:doc:`ch08_operating_systems`」

   BNF
      Backus-Naur Form（バッカス・ナウア記法）の略である。文脈自由文法を記述するための記法で、プログラミング言語の文法の定義に広く使われる。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   B+ 木
      1 つの節点に多数のキーを持つ平衡木で、行の位置は葉にだけ格納し、葉どうしを連結する。検索・挿入・削除が :math:`O(\log N)` で行え、データベースのインデックスに広く使われる。

      関連する章: 「:doc:`ch11_databases`」

   CAP 定理
      ネットワーク分断が起きているとき、線形化可能性（一貫性）と、故障していないすべてのノードが応答すること（可用性）を両立できないという定理である。分断時にどちらを優先するかの選択を意味する。

      関連する章: 「:doc:`ch12_distributed_systems`」

   CAS
      Compare-And-Swap の略である。メモリ上の値が期待する値と等しいときだけ新しい値に書き換える操作を不可分に行うアトミック操作で、ロックフリーのデータ構造の基本となる。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   CIDR
      IP アドレスのネットワーク部のビット数を「/24」のように明示してアドレスの範囲を表す方式である。Classless Inter-Domain Routing の略である。

      関連する章: 「:doc:`ch10_networks`」

   CISC
      Complex Instruction Set Computer の略である。1 つの命令で複雑な処理を行える、可変長の命令を持つ命令セットの設計思想である。x86 が代表例である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   Cookie
      サーバが Set-Cookie ヘッダで指定した名前と値の組をブラウザが保存し、以後のリクエストに付けて送り返す仕組みである。セッション ID の受け渡しに使い、Secure・HttpOnly・SameSite などの属性を指定できる。

      関連する章: 「:doc:`ch14_application_security`」

   CPU
      中央処理装置（Central Processing Unit）である。メモリから命令を読み出して解釈し、演算や制御を行う。

      関連する章: 「:doc:`ch03_computer_architecture`」

   CRC
      ビット列を多項式とみなし、生成多項式で割った余りを検査用の値とする誤り検出の方法である。巡回冗長検査とも呼ぶ。連続したビットの誤り（バースト誤り）に強く、イーサネットや ZIP、PNG で使われる。

      関連する章: 「:doc:`ch01_data_representation`」

   DNS
      ドメイン名から IP アドレスなどの情報を得る名前解決のための、階層的な分散データベースである。Domain Name System の略である。

      関連する章: 「:doc:`ch10_networks`」

   GIL
      CPython が持つロックで、同時に 1 つのスレッドだけが Python のバイトコードを実行できるようにする。Global Interpreter Lock の略である。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   happened-before 関係
      分散システムのイベントの因果的な前後関係である。同じプロセスで先に起きたイベント、メッセージの送信とその受信、およびそれらの推移的な組み合わせで定義され、:math:`a \to b` と書く。どちら向きにも成り立たない 2 つのイベントは並行であるという。

      関連する章: 「:doc:`ch12_distributed_systems`」

   HTTP
      クライアントがリクエストを送りサーバがレスポンスを返す、Web の基盤となるステートレスなアプリケーション層のプロトコルである。

      関連する章: 「:doc:`ch10_networks`」

   I/O 多重化
      1 回のシステムコールで多数のファイル記述子を監視し、読み書きできる状態になったものだけを知る仕組みである。select、poll、epoll、kqueue などがある。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   IEEE 754
      浮動小数点数の形式と演算を定めた標準規格である。64 ビットの binary64 は、符号 1 ビット、指数 11 ビット（バイアス 1023）、仮数 52 ビットからなる。

      関連する章: 「:doc:`ch01_data_representation`」

   IP アドレス
      インターネット層で機器を識別するアドレスである。IPv4 では 32 ビット、IPv6 では 128 ビットである。

      関連する章: 「:doc:`ch10_networks`」

   JIT コンパイル
      プログラムの実行中に、頻繁に実行される部分を機械語にコンパイルして高速化する方式である。JIT は Just-In-Time の略である。

      関連する章: 「:doc:`ch07_programming_languages`」

   JWT
      JSON で表したクレームを、ヘッダ・ペイロード・署名の 3 つの部分を Base64URL で符号化してピリオドでつないだ形式で受け渡すトークンである。JSON Web Token の略である。署名は改ざんを検出するが、内容は暗号化されない。

      関連する章: 「:doc:`ch14_application_security`」

   LRU キャッシュ
      容量を超えたときに、最も長い間使われていない要素を追い出すキャッシュである。ハッシュ表と双方向連結リストを組み合わせると、取得と追加を平均 :math:`O(1)` で行える。

      関連する章: 「:doc:`ch04_data_structures`」

   MAC アドレス
      ネットワークインタフェースに割り当てられる 48 ビットのアドレスで、リンク層で同じネットワーク内の送信元と宛先を表す。

      関連する章: 「:doc:`ch10_networks`」

   MVCC
      行の更新時に古い版を残して新しい版を作り、各トランザクションにスナップショットを読ませる同時実行制御の方式である。読み出しと書き込みが互いを待たない。多版型同時実行制御（Multi-Version Concurrency Control）の略である。

      関連する章: 「:doc:`ch11_databases`」

   NAT
      ルータがパケットの IP アドレス（とポート番号）を書き換え、プライベートアドレスの機器がインターネットと通信できるようにする仕組みである。Network Address Translation の略である。

      関連する章: 「:doc:`ch10_networks`」

   NP 完全
      NP に属し、かつ NP 困難である問題である。どれか 1 つでも多項式時間で解ければ P = NP となる。SAT、ハミルトン閉路問題などがある。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   NP 困難
      NP に属するすべての問題が多項式時間帰着できる問題である。NP に属するとは限らない。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   NTP
      ネットワークを通じてコンピュータの時計を合わせるプロトコル（Network Time Protocol）である。UDP の 123 番ポートを使い、要求と応答の 4 つの時刻から時計のずれと往復の遅延を推定する。

      関連する章: 「:doc:`ch12_distributed_systems`」

   NULL
      SQL で値が存在しない、または不明であることを表す特別な印である。NULL との比較は真でも偽でもない UNKNOWN になる（三値論理）。

      関連する章: 「:doc:`ch11_databases`」

   NX ビット
      ページテーブルの属性の 1 つで、そのページの内容を命令として実行することを禁止するものである。スタックやヒープに送り込まれた機械語の実行を防ぐ。OS の機能としては DEP とも呼ばれる。

      関連する章: 「:doc:`ch14_application_security`」

   OAuth 2.0
      利用者がパスワードを渡さずに、アプリケーションに自分のリソースへの限られた範囲のアクセスを許可するための、認可の委譲の枠組みである。認証の仕組みではない。

      関連する章: 「:doc:`ch14_application_security`」

   OpenID Connect
      OAuth 2.0 の上に認証の機能を加えた仕様である。発行者が署名した ID トークンによって、クライアントは利用者が認証されたことを確かめられる。

      関連する章: 「:doc:`ch14_application_security`」

   OSI 参照モデル
      ISO が定めた、ネットワークの機能を物理層からアプリケーション層までの 7 層に分けて整理する枠組みである。

      関連する章: 「:doc:`ch10_networks`」

   O 記法
      関数の増え方の上界を、定数倍と低次の項を無視して表す記法である。:math:`f(n) = O(g(n))` は、:math:`n` が十分大きいとき :math:`f(n)` が :math:`g(n)` の定数倍以下であることを表す。オー記法、ビッグオー記法とも呼ぶ。

      関連する章: 「:doc:`ch05_algorithms`」

   Raft
      理解しやすさを重視して設計された合意アルゴリズムである。任期ごとに過半数の票でリーダを選び、リーダがログを複製して、過半数のノードに保存された項目をコミットする。

      関連する章: 「:doc:`ch12_distributed_systems`」

   ReDoS
      Regular expression Denial of Service の略である。バックトラック型の正規表現エンジンで照合時間が入力長に対して指数的に増えるパターンを悪用し、細工した入力で CPU を占有させる攻撃である。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   RISC
      Reduced Instruction Set Computer の略である。命令を単純で規則的な固定長のものに限定し、メモリアクセスをロード命令とストア命令に限る命令セットの設計思想である。ARM や RISC-V が代表例である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   SIMD
      1 つの命令で複数のデータに同じ演算を行う並列処理の方式である。x86-64 の SSE や AVX、ARM の NEON などの命令がある。

      関連する章: 「:doc:`ch03_computer_architecture`」

   SMT
      1 つのコアがプログラムカウンタやレジスタを複数組持ち、複数のスレッドの命令を同時に実行する技術である。同時マルチスレッディングとも呼び、実行用の回路を共有するので性能は 2 倍にはならない。

      関連する章: 「:doc:`ch03_computer_architecture`」

   SQL
      関係データベースを操作するための標準的な言語である。表を定義する DDL と、データを検索・更新する DML などからなる。

      関連する章: 「:doc:`ch11_databases`」

   SQL インジェクション
      利用者の入力を文字列連結で SQL に埋め込むことで、入力の一部が SQL の構文として解釈されてしまう脆弱性である。プレースホルダを使って防ぐ。

      関連する章: 「:doc:`ch11_databases`」、「:doc:`ch14_application_security`」

   TCP
      IP の上で、失われず重複せず順序どおりに届く、信頼性のあるバイト列の通信を提供するトランスポート層のプロトコルである。

      関連する章: 「:doc:`ch10_networks`」

   TLB
      最近使った仮想アドレスから物理アドレスへの変換結果を保持する、MMU 内の小さなキャッシュである。Translation Lookaside Buffer の略である。

      関連する章: 「:doc:`ch08_operating_systems`」

   TLS
      鍵交換、証明書による認証、認証付き暗号を組み合わせて、通信の機密性・完全性・認証を提供するプロトコルである。HTTPS は HTTP を TLS で保護したものである。Transport Layer Security の略である。

      関連する章: 「:doc:`ch13_security`」

   TTL
      DNS では、リソースレコードをキャッシュしてよい秒数である。IP ヘッダでは、ルータを通過するたびに 1 減らされ、0 になるとパケットが破棄される値を指す。Time To Live の略である。

      関連する章: 「:doc:`ch10_networks`」

   UDP
      IP にポート番号と簡単な誤り検出を加えただけの、接続を確立しない軽量なトランスポート層のプロトコルである。到達や順序を保証しない。

      関連する章: 「:doc:`ch10_networks`」

   Unicode
      世界中の文字に一意の番号（コードポイント）を割り当てる文字集合の標準である。範囲は U+0000〜U+10FFFF である。

      関連する章: 「:doc:`ch01_data_representation`」

   Unicode 正規化
      見た目や意味が同じでもコードポイントの列が異なる文字列を、決まった形にそろえる処理である。NFC・NFD・NFKC・NFKD の 4 つの形式がある。

      関連する章: 「:doc:`ch01_data_representation`」

   Union-Find
      要素を互いに重ならないグループに分け、グループの併合（union）と代表の検索（find）を行うデータ構造である。経路圧縮とランクによる併合を組み合わせると、1 回の操作の償却計算量は実用上ほぼ定数になる。素集合データ構造とも呼ぶ。

      関連する章: 「:doc:`ch04_data_structures`」

   UTF-8
      Unicode のコードポイントを 1〜4 バイトの可変長のバイト列で表す符号化方式である。ASCII と互換性があり、Web やファイルで事実上の標準となっている。

      関連する章: 「:doc:`ch01_data_representation`」

あ行
----

.. glossary::

   i ノード
      Unix 系のファイルシステムで、ファイルの大きさ、所有者、アクセス権、データの位置などの管理情報を格納する構造である。ファイル名は含まず、名前はディレクトリに記録される。

      関連する章: 「:doc:`ch08_operating_systems`」

   アセンブリ言語
      機械語の各命令を、ニーモニックと呼ばれる英単語の略号で表したプログラミング言語である。アセンブラによって機械語に変換される。

      関連する章: 「:doc:`ch03_computer_architecture`」

   アドホック多相
      同じ名前に、型ごとに別々の実装を用意する多相である。関数や演算子のオーバーロードが代表例である。

      関連する章: 「:doc:`ch07_programming_languages`」

   アトミック操作
      メモリ上の値の読み出し、変更、書き込みを、他のスレッドやコアに割り込まれずに不可分に行う操作である。ロックなどの同期の道具の土台になる。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   アムダールの法則
      並列化できる部分の割合を :math:`p`、コア数を :math:`n` としたとき、速度向上率が :math:`1/((1-p)+p/n)` になるという法則である。コアをいくら増やしても :math:`1/(1-p)` を超えない。

      関連する章: 「:doc:`ch03_computer_architecture`」

   アルゴリズム
      問題を解くための明確な手順を有限の長さで記述したものである。どの入力に対しても有限回の手順で終了し、正しい出力を返すことが求められる。

      関連する章: 「:doc:`ch05_algorithms`」

   暗号学的に安全な擬似乱数生成器
      それまでの出力をいくら観測しても次の出力を予測できないように設計された擬似乱数生成器である。CSPRNG と略す。鍵やトークンの生成に使い、Python では ``secrets`` モジュールや ``os.urandom`` から利用できる。

      関連する章: 「:doc:`ch13_security`」

   暗号学的ハッシュ関数
      原像計算困難性・第 2 原像計算困難性・衝突困難性を満たすハッシュ関数である。SHA-256 が代表例である。

      関連する章: 「:doc:`ch01_data_representation`」、「:doc:`ch13_security`」

   安定ソート
      等しいキーを持つ要素の相対的な順序をソートの前後で保つソートである。Python の ``sorted()`` は安定ソートである。

      関連する章: 「:doc:`ch05_algorithms`」

   イベントループ
      入出力やタイマの通知を待ち、通知が来たものに対応する処理を呼ぶことを繰り返すプログラムの構造である。1 つのスレッドで多数の待ちをさばける。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   入れ子ループ結合
      一方の関係の各行について、もう一方の関係の全行と結合条件を比較する結合方式である。時間計算量は :math:`O(NM)` だが、任意の結合条件に使える。

      関連する章: 「:doc:`ch11_databases`」

   インタプリタ
      ソースコード、またはそれを変換したバイトコードなどを読み込み、その意味に従って直接実行するプログラムである。

      関連する章: 「:doc:`ch07_programming_languages`」

   インデックス
      表の特定の列の値から行の位置を素早く求めるための補助的なデータ構造である。検索を速くする代わりに、格納領域を使い書き込みを遅くする。

      関連する章: 「:doc:`ch11_databases`」

   エントロピー
      情報源が出す 1 記号あたりの情報量の期待値で、:math:`H = -\sum_i p_i \log_2 p_i` ビットで表す。可逆圧縮で達成できる平均ビット数の下限を与える。

      関連する章: 「:doc:`ch01_data_representation`」

   オーバーフロー
      演算の結果が、そのデータ型で表現できる範囲を超えることである。固定幅の整数では、結果が :math:`2^n` を法とする剰余に切り詰められることが多い。

      関連する章: 「:doc:`ch01_data_representation`」

   オブジェクトファイル
      1 つのソースファイルをコンパイルした結果のファイルである。機械語のコードとデータのほか、シンボル表と再配置情報を含む。

      関連する章: 「:doc:`ch07_programming_languages`」

   オープンアドレス法
      ハッシュ表の衝突の解決方法の 1 つである。すべての要素をバケットの配列に直接格納し、割り当てられたバケットが埋まっていれば決められた規則で別のバケットを探して格納する。

      関連する章: 「:doc:`ch04_data_structures`」

   オペレーティングシステム
      ハードウェア資源を管理し、プログラムにプロセス、アドレス空間、ファイルなどの抽象を提供するソフトウェアである。OS と略す。

      関連する章: 「:doc:`ch08_operating_systems`」

か行
----

.. glossary::

   外部キー
      別の関係の主キーを参照する属性である。外部キー制約により、存在しない値を参照するタプルが登録されないこと（参照整合性）が保証される。

      関連する章: 「:doc:`ch11_databases`」

   解放後使用
      解放したメモリ領域を、それを指していたポインタを通じて使い続ける誤りである（use-after-free）。再利用された領域を攻撃者が操作し、実行を乗っ取ることがある。

      関連する章: 「:doc:`ch14_application_security`」

   鍵配送問題
      共通鍵暗号で使う鍵を、盗聴されるおそれのある通信路を通じて相手と安全に共有することが難しいという問題である。

      関連する章: 「:doc:`ch13_security`」

   仮想化
      ハードウェアを模した仮想マシンをソフトウェアで作り、その上で OS をそのまま動かす技術である。1 台の物理マシンで複数の OS を分離して動かせる。

      関連する章: 「:doc:`ch08_operating_systems`」

   仮想メモリ
      プログラムが使う仮想アドレスと主記憶上の物理アドレスを分離し、MMU が変換する仕組みである。プロセス間の分離やデマンドページングを実現する。

      関連する章: 「:doc:`ch08_operating_systems`」

   型消去
      ジェネリクスの型パラメータをコンパイル時の型検査だけに使い、検査後に取り除いて共通の 1 つのコードを生成する実装方式である。Java のジェネリクスが代表例である。

      関連する章: 「:doc:`ch07_programming_languages`」

   型推論
      プログラムの書き方から、式や変数の型を処理系が自動的に導く機能である。型を明示しなくても静的な型検査を受けられる。

      関連する章: 「:doc:`ch07_programming_languages`」

   型ヒント
      Python で関数の引数や戻り値、変数に付ける型の注釈である。実行時には検査されず、mypy などの型検査器が実行前に検査する。

      関連する章: 「:doc:`ch07_programming_languages`」

   カーネル
      OS の中核で、カーネルモードで動作し、資源の管理と保護を担う部分である。

      関連する章: 「:doc:`ch08_operating_systems`」

   カプセル化
      送信側で、上の層から受け取ったデータに各層が自分のヘッダを付けて下の層に渡すことである。

      関連する章: 「:doc:`ch10_networks`」

   ガベージコレクション
      プログラムが使わなくなったヒープ上の領域を、処理系が自動的に見つけて解放する仕組みである。GC とも呼ぶ。参照カウントとトレーシング GC に大別される。

      関連する章: 「:doc:`ch07_programming_languages`」

   可用性
      許可された者が、必要なときに情報やサービスを利用できることである。情報セキュリティの 3 要素の 1 つである。

      関連する章: 「:doc:`ch12_distributed_systems`」、「:doc:`ch13_security`」

   関係代数
      関係を入力とし関係を出力する演算の体系である。選択・射影・結合などの演算を組み合わせて問い合わせを表現する。

      関連する章: 「:doc:`ch11_databases`」

   関係モデル
      データをタプル（行）の集合である関係（表）の集まりとして表すデータモデルである。1970 年に E. F. Codd が提案し、関係データベースの基礎となっている。

      関連する章: 「:doc:`ch11_databases`」

   関数型プログラミング
      状態の変更を避け、値を受け取って値を返す純粋関数の組み合わせとしてプログラムを記述するパラダイムである。高階関数や不変なデータ構造をよく使う。

      関連する章: 「:doc:`ch07_programming_languages`」

   完全性
      情報が正確であり、許可なく改ざんされていないことである。情報セキュリティの 3 要素の 1 つである。

      関連する章: 「:doc:`ch13_security`」

   機械語
      CPU が直接実行できる、ビット列で表された命令である。命令セットアーキテクチャごとに形式が異なる。

      関連する章: 「:doc:`ch03_computer_architecture`」

   偽共有
      複数のスレッドが別々の変数を書き換えているのに、それらが同じキャッシュラインに載っているために、コア間でラインの奪い合いが起きて遅くなる現象である。false sharing とも呼ぶ。

      関連する章: 「:doc:`ch03_computer_architecture`」

   擬似乱数生成器
      内部の状態を一定の規則で更新しながら、乱数のように見える数の列を出力するアルゴリズムである。同じシードからは同じ列が得られる。

      関連する章: 「:doc:`ch13_security`」

   基数
      位取り記数法で、各桁の重みの底となる数である。2 進数の基数は 2、16 進数の基数は 16 である。

      関連する章: 「:doc:`ch01_data_representation`」

   機能的完全性
      ある演算の集合だけを組み合わせて、任意の論理関数を表現できる性質である。NAND だけ、または NOR だけの集合は機能的完全である。

      関連する章: 「:doc:`ch02_logic_circuits`」

   機密性
      許可された者だけが情報にアクセスできることである。情報セキュリティの 3 要素の 1 つである。

      関連する章: 「:doc:`ch13_security`」

   キャッシュ
      遅い記憶装置の内容の一部の複製を保持する、小さく高速な記憶装置である。CPU のキャッシュは主記憶へのアクセスを減らすために使われる。

      関連する章: 「:doc:`ch03_computer_architecture`」

   キャッシュコヒーレンシ
      複数のコアのキャッシュが、同じアドレスについて矛盾した値を持たないようにする性質、またはその仕組みである。MESI などのプロトコルにより、キャッシュライン単位でハードウェアが管理する。

      関連する章: 「:doc:`ch03_computer_architecture`」

   キャッシュライン
      キャッシュと主記憶の間でデータを転送する単位となる連続した領域である。多くの CPU では 64 バイトである。

      関連する章: 「:doc:`ch03_computer_architecture`」

   キュー
      最初に入れた値を最初に取り出す（FIFO）抽象データ型である。処理待ちの管理や幅優先探索に使われる。

      関連する章: 「:doc:`ch04_data_structures`」

   競合状態
      複数のスレッドが共有データにアクセスし、その結果が実行の順序やタイミングによって変わってしまう状況である。レースコンディションとも呼ぶ。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   偽陽性
      実際には条件を満たさないものを、満たすと誤って判定することである。ブルームフィルタでは、追加していない要素を「含まれるかもしれない」と答えることを指す。

      関連する章: 「:doc:`ch04_data_structures`」

   共通鍵暗号
      暗号化と復号に同じ鍵を使う暗号方式である。高速だが、鍵を相手と安全に共有する必要がある。AES が代表例である。

      関連する章: 「:doc:`ch13_security`」

   共有ライブラリ
      動的リンクで使われるライブラリである。Linux では ``.so``、Windows では ``.dll`` の拡張子を持ち、複数のプロセスでコードを共有できる。

      関連する章: 「:doc:`ch07_programming_languages`」

   クイックソート
      ピボットを選んで、それ以下の要素と大きい要素に分割し、それぞれを再帰的にソートするソートアルゴリズムである。平均 :math:`O(n \log n)`、最悪 :math:`O(n^2)` である。

      関連する章: 「:doc:`ch05_algorithms`」

   空間計算量
      アルゴリズムが使う記憶領域の量を、入力の大きさの関数として表したものである。

      関連する章: 「:doc:`ch05_algorithms`」

   組み合わせ回路
      出力がその時点の入力だけで決まり、記憶を持たない論理回路である。加算器やマルチプレクサがその例である。

      関連する章: 「:doc:`ch02_logic_circuits`」

   クラス NP
      非決定性チューリングマシンが多項式時間で解ける判定問題全体の集合である。答えが Yes であることの証明書が与えられれば、それを多項式時間で検証できる問題の集合と言い換えられる。「多項式時間で解けない」という意味ではない。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   クラス P
      決定性チューリングマシンが入力の長さの多項式時間で解ける判定問題全体の集合である。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   グラフ
      頂点の集合と、頂点同士を結ぶ辺の集合からなる構造である。路線図、SNS の関係、依存関係などを表すのに使われる。

      関連する章: 「:doc:`ch04_data_structures`」

   クリティカルセクション
      共有データにアクセスするため、同時に 1 つのスレッドしか実行してはならないコードの区間である。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   クロージャ
      関数と、その関数が参照する外側の変数の環境を組にしたものである。外側の関数から戻った後も、その変数を保持し続ける。

      関連する章: 「:doc:`ch07_programming_languages`」

   クロスサイトスクリプティング
      攻撃者が用意したスクリプトが、脆弱なサイトのページの一部として利用者のブラウザで実行されてしまう脆弱性である。XSS と略し、出力時のエスケープで防ぐ。

      関連する章: 「:doc:`ch14_application_security`」

   クロスサイトリクエストフォージェリ
      ログイン中の利用者のブラウザから、攻撃者のページを経由して利用者の意図しない要求を送らせる攻撃、またはその脆弱性である。CSRF と略し、CSRF トークンや SameSite 属性で防ぐ。

      関連する章: 「:doc:`ch14_application_security`」

   クロック
      一定の周期で 0 と 1 を繰り返す信号である。同期式の回路では、フリップフロップがクロックのエッジで一斉に値を更新する。

      関連する章: 「:doc:`ch02_logic_circuits`」

   計算複雑性理論
      判定可能な問題を、解くのに必要な時間や記憶領域の量によって分類する理論である。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   計算量
      アルゴリズムが必要とする手間や記憶領域の量を、入力の大きさの関数として表したものである。時間計算量と空間計算量がある。単に計算量といえば時間計算量を指すことが多い。

      関連する章: 「:doc:`ch05_algorithms`」

   経路圧縮
      Union-Find の find で根までたどった要素の親を、すべて根に付け替える工夫である。以後の find が速くなる。

      関連する章: 「:doc:`ch04_data_structures`」

   結果整合性
      新しい書き込みが止まれば、いずれすべての複製が同じ値に収束することだけを保証する一貫性モデルである。それまでの間は古い値が読まれうる。

      関連する章: 「:doc:`ch12_distributed_systems`」

   決定性有限オートマトン
      現在の状態と入力記号から次の状態がただ 1 つに決まる有限オートマトンである。DFA（Deterministic Finite Automaton）とも呼ぶ。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   合意
      複数のノードが 1 つの値について同じ結論に達することである。リーダ選出、分散ロック、複製のログの順序の決定などが合意問題に帰着する。

      関連する章: 「:doc:`ch12_distributed_systems`」

   公開鍵暗号
      公開してよい公開鍵で暗号化し、本人だけが持つ秘密鍵で復号する暗号方式である。鍵配送問題を解決するが、共通鍵暗号より遅い。RSA が代表例である。

      関連する章: 「:doc:`ch13_security`」

   公開鍵証明書
      公開鍵とその持ち主（ドメイン名など）の対応に、認証局がデジタル署名したデータである。形式は X.509 で定められている。

      関連する章: 「:doc:`ch13_security`」

   構文解析
      トークンの列が文法に従っているかを調べ、その構造を抽象構文木などの木で表す処理である。文法の記述には文脈自由文法を使う。

      関連する章: 「:doc:`ch07_programming_languages`」

   後方参照
      正規表現の中で、前のグループにマッチしたのと同じ文字列を表す記法である（例: ``\1``）。正規言語を超える言語を表せるが、効率のよい照合ができなくなる。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   コストベース最適化
      候補となる実行計画ごとに、読むページ数や処理する行数から実行の費用を見積もり、最も安い計画を選ぶ問い合わせ最適化の方式である。見積もりには統計情報を使う。

      関連する章: 「:doc:`ch11_databases`」

   コードポイント
      Unicode で各文字に割り当てられた番号である。U+3042 のように「U+」に続く 16 進数で表記する。

      関連する章: 「:doc:`ch01_data_representation`」

   コピーオンライト
      複製や変更の際にすぐにはデータをコピーせず、書き込みが起きた部分だけをその時点でコピーする手法である。fork によるアドレス空間の複製、コンテナのレイヤ、一部のファイルシステムで使われる。

      関連する章: 「:doc:`ch08_operating_systems`」

   コルーチン
      途中で実行を中断し、後から中断したところから再開できる関数である。Python では async def で定義し、await で中断する。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   コンシステントハッシュ
      ハッシュ値の空間を円環とみなし、ノードとキーを円環上に配置して、各キーを時計回りに最初に出会うノードに割り当てる方法である。ノードの増減時に移動するキーが一部で済む。

      関連する章: 「:doc:`ch12_distributed_systems`」

   コンテキストスイッチ
      CPU を実行中のプロセスやスレッドから別のものに切り替える処理である。レジスタなどの状態を保存し、次に実行するものの状態を復元する。

      関連する章: 「:doc:`ch08_operating_systems`」

   コンテナ
      OS のカーネルを共有したまま、名前空間と cgroups によってプロセスの集まりに独立した実行環境を与える技術である。仮想マシンより軽く速いが、分離は弱い。

      関連する章: 「:doc:`ch08_operating_systems`」

   コンパイラ
      ソースコードを実行前にまとめて別の言語（多くの場合は機械語）に翻訳するプログラムである。

      関連する章: 「:doc:`ch07_programming_languages`」

さ行
----

.. glossary::

   再帰
      関数が自分自身を呼び出すことである。問題を同じ形の小さな問題に帰着させて解く手順を素直に表せる。

      関連する章: 「:doc:`ch05_algorithms`」

   再帰下降構文解析
      文法の非終端記号 1 つに 1 つの関数を対応させ、関数が互いに再帰的に呼び出し合うことで構文解析を行う方法である。左再帰を繰り返しに書き換える必要がある。

      関連する章: 「:doc:`ch07_programming_languages`」

   参照カウント
      各オブジェクトを参照している箇所の数を記録し、0 になった時点でオブジェクトを解放するメモリ管理の方式である。循環参照を回収できない。

      関連する章: 「:doc:`ch07_programming_languages`」

   参照の局所性
      プログラムのメモリアクセスが、最近アクセスしたデータ（時間的局所性）やその近くのアドレス（空間的局所性）に偏る性質である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   ジェネリクス
      型パラメータを持つ関数や型を定義できる言語機能である。``list[T]`` のように、要素の型に依存しないコードを型安全に書ける。

      関連する章: 「:doc:`ch07_programming_languages`」

   時間計算量
      アルゴリズムが実行する基本的な操作の回数を、入力の大きさの関数として表したものである。通常は O 記法で表す。

      関連する章: 「:doc:`ch05_algorithms`」

   字句解析
      ソースコードの文字の並びを、識別子や演算子などのトークンの列に変換する処理である。各トークンの形は正規表現で表せるので、有限オートマトンとして実装できる。

      関連する章: 「:doc:`ch07_programming_languages`」

   シグナル
      カーネルがプロセスに非同期に事象を知らせる仕組みである。SIGINT や SIGTERM などの種類があり、プロセスは既定の動作をするか、登録したハンドラを実行する。

      関連する章: 「:doc:`ch08_operating_systems`」

   指数バックオフ
      再試行の待ち時間を、失敗するたびに 2 倍、4 倍と指数的に伸ばす方法である。多数のクライアントの再試行が一斉に届かないよう、乱数の揺らぎ（ジッタ）を加えて使う。

      関連する章: 「:doc:`ch12_distributed_systems`」

   システムコール
      ユーザモードのプログラムがカーネルに処理を依頼するための窓口である。専用の命令でカーネルモードに切り替わって実行される。

      関連する章: 「:doc:`ch08_operating_systems`」

   実行計画
      DBMS が問い合わせを実行する具体的な手順である。各表の読み方（全件走査かインデックスか）、結合の順序、結合方式などの選択からなる。

      関連する章: 「:doc:`ch11_databases`」

   シード
      擬似乱数生成器の内部状態の初期値を決める値である。同じシードを与えると同じ乱数列が再現される。

      関連する章: 「:doc:`ch13_security`」

   シャーディング
      データを重ならない部分（シャード、パーティション）に分け、それぞれを別のノードに置くことである。キーの範囲による分割とハッシュによる分割がある。

      関連する章: 「:doc:`ch12_distributed_systems`」

   ジャーナリング
      ファイルシステムの一連の更新を、本来の場所に書く前にジャーナルと呼ぶ領域へ先に記録する方式である。クラッシュ後はジャーナルを調べて完結した更新だけをやり直し、整合性を保つ。

      関連する章: 「:doc:`ch08_operating_systems`」

   主キー
      関係の中でタプルを一意に識別するために選んだ属性または属性の組である。値の重複と NULL は許されない。

      関連する章: 「:doc:`ch11_databases`」

   順序回路
      出力が現在の入力だけでなく、過去の入力によって決まる内部状態にも依存する論理回路である。フィードバックによって状態を保持する。

      関連する章: 「:doc:`ch02_logic_circuits`」

   償却計算量
      一連の操作全体にかかる手間を操作の回数で割って評価した計算量である。まれに重い操作があっても、全体として平均すれば軽い場合の評価に使う。

      関連する章: 「:doc:`ch04_data_structures`」

   条件変数
      ミューテックスと組にして使い、ある条件が成り立つまでスレッドを眠らせ、他のスレッドからの通知で起こす同期の道具である。待つ条件は while で確かめ直す。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   書記素クラスタ
      人間が 1 文字と感じる単位であり、1 つ以上のコードポイントからなる。結合文字付きの文字や、ZWJ でつないだ絵文字、国旗などは 1 つの書記素クラスタになる。

      関連する章: 「:doc:`ch01_data_representation`」

   真理値表
      論理式や論理回路の出力を、入力のすべての組み合わせについて列挙した表である。入力が :math:`n` 個なら :math:`2^n` 行になる。

      関連する章: 「:doc:`ch02_logic_circuits`」

   スケジューラ
      実行可能なプロセスやスレッドのうち、次に CPU を割り当てるものを選ぶ OS の機能である。

      関連する章: 「:doc:`ch08_operating_systems`」

   スコープ
      プログラム中の名前（変数名や関数名）が有効な範囲である。多くの言語はソースコード上の入れ子の構造で決まる静的スコープを採用している。

      関連する章: 「:doc:`ch07_programming_languages`」

   スタック
      最後に入れた値を最初に取り出す（LIFO）抽象データ型である。関数呼び出しの管理や深さ優先探索に使われる。

      関連する章: 「:doc:`ch04_data_structures`」

   スタックカナリア
      スタックフレームの局所変数と戻り先アドレスの間にランダムな値を置き、関数から戻る前にその値が変わっていないかを確かめる緩和策である。バッファオーバーフローによる戻り先の書き換えを検出する。

      関連する章: 「:doc:`ch14_application_security`」

   スタックの巻き戻し
      例外が伝播する際に、例外を処理しない関数の実行を打ち切り、そのスタックフレームを順に取り除くことである。途中で finally 節やデストラクタが実行される。

      関連する章: 「:doc:`ch07_programming_languages`」

   ステータスコード
      HTTP のレスポンスで処理結果を表す 3 桁の数値である。先頭の桁が成功、リダイレクト、クライアントの誤り、サーバの誤りなどの分類を表す。

      関連する章: 「:doc:`ch10_networks`」

   ストレッチング
      ハッシュ値の計算を多数回繰り返すなどして、パスワードの照合 1 回あたりの計算量を意図的に増やすことである。総当たり攻撃を遅くする。

      関連する章: 「:doc:`ch14_application_security`」

   3 ウェイハンドシェイク
      TCP の接続を確立する手順である。クライアントが SYN、サーバが SYN-ACK、クライアントが ACK を送り、シーケンス番号の初期値を交換する。

      関連する章: 「:doc:`ch10_networks`」

   スレッド
      プロセスの中の実行の流れである。同じプロセスのスレッドはアドレス空間を共有し、レジスタとスタックはスレッドごとに持つ。

      関連する章: 「:doc:`ch08_operating_systems`」

   正規化
      属性間の関数従属に着目して表を分割し、データの重複と更新時異常を取り除く設計手法である。第 1〜第 3 正規形などの段階がある。

      関連する章: 「:doc:`ch11_databases`」

   正規言語
      有限オートマトンで認識できる言語である。正規表現で表せる言語と一致する。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   正規表現
      和、連接、0 回以上の繰り返し（クリーネ閉包）の組み合わせで文字列の集合を表す記法である。実用の正規表現エンジンは、後方参照などで理論上の正規表現を拡張している。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   制御装置
      命令を解釈（デコード）し、レジスタ・ALU・メモリなどに制御信号を送って命令を実行させる CPU の構成要素である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   生産者・消費者問題
      データを作るスレッドと処理するスレッドが、容量に限りのあるバッファを介して安全に受け渡しをする同期の問題である。条件変数やセマフォで解ける。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   脆弱性
      脅威が実際に損害をもたらすことを可能にする弱点である。プログラムの不具合、設定の誤り、運用手順の不備などが含まれる。

      関連する章: 「:doc:`ch13_security`」

   静的型付け
      プログラムの実行前（コンパイル時）に型を検査し、型エラーがあれば実行させない方式である。C、Java、Rust などが採用している。

      関連する章: 「:doc:`ch07_programming_languages`」

   静的リンク
      リンクの時点でライブラリのコードを実行ファイルにコピーして結合する方式である。実行ファイルだけで動くが、ライブラリの更新には再リンクが必要になる。

      関連する章: 「:doc:`ch07_programming_languages`」

   セッション
      ステートレスな HTTP の上で、複数のリクエストにまたがって利用者のログイン状態などを引き継ぐ仕組み、またはその一連のやり取りである。Cookie のセッション ID やトークンで実現する。

      関連する章: 「:doc:`ch14_application_security`」

   セッション固定攻撃
      攻撃者が知っているセッション ID を被害者に使わせ、被害者がログインした後にそのセッション ID で被害者になりすます攻撃である。ログイン成功時にセッション ID を再発行して防ぐ。

      関連する章: 「:doc:`ch14_application_security`」

   セマフォ
      整数のカウンタを持つ同期の道具である。カウンタの初期値によって、資源を同時に使えるスレッドの数を制限できる。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   全加算器
      1 ビットの 2 つの数と下の桁からの桁上げの 3 ビットを足し、和と桁上げを出力する回路である。半加算器 2 個と OR ゲート 1 個で作れる。

      関連する章: 「:doc:`ch02_logic_circuits`」

   線形化可能性
      複製がいくつあっても、システムがデータのコピーが 1 つしかないかのように振る舞うことを保証する一貫性モデルである。書き込みが完了した後に始まった読み出しは、必ずその値かそれより新しい値を返す。

      関連する章: 「:doc:`ch12_distributed_systems`」

   線形探索
      配列の先頭から順に 1 つずつ目的の値と比較していく探索方法である。計算量は :math:`O(n)` である。

      関連する章: 「:doc:`ch05_algorithms`」

   ソートマージ結合
      両方の関係を結合列でソートし、先頭から並行にたどって値の一致する行を突き合わせる結合方式である。入力がすでにソート済みならマージの :math:`O(N + M)` だけで済む。

      関連する章: 「:doc:`ch11_databases`」

   ソルト
      パスワードのハッシュ値を計算する前に加える、利用者ごとにランダムな値である。事前計算した表による攻撃を防ぎ、同じパスワードでも保存値を異なるものにする。

      関連する章: 「:doc:`ch14_application_security`」

.. glossary::

   帯域幅
      通信路で単位時間あたりに送れるデータ量であり、bit/s で表す。

      関連する章: 「:doc:`ch10_networks`」

   対角線論法
      すべての対象を並べた表の対角線上の要素をすべて反転させたものを作り、それが表のどの行とも異なることから矛盾を導く証明手法である。停止問題の判定不能性や実数の非可算性の証明に使われる。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   ダイクストラ法
      辺の重みが非負のグラフで、出発点から各頂点への最短距離を求めるアルゴリズムである。未確定の頂点のうち暫定距離が最小のものを順に確定させる。

      関連する章: 「:doc:`ch05_algorithms`」

   チェイン法
      ハッシュ表の衝突の解決方法の 1 つである。各バケットにリストを持たせ、同じバケットに割り当てられたキーをそのリストに並べて格納する。

      関連する章: 「:doc:`ch04_data_structures`」

   チェックサム
      データを一定の単位に区切った数値の和を、誤り検出用の値として使う方法である。インターネットチェックサムは IPv4、TCP、UDP で使われる。

      関連する章: 「:doc:`ch01_data_representation`」

   遅延
      データが送られてから相手に届くまでの時間である。レイテンシとも呼び、往復の時間を RTT と呼ぶ。

      関連する章: 「:doc:`ch10_networks`」

   チャーチ＝チューリングのテーゼ
      直観的な意味で機械的に計算できる関数は、チューリングマシンで計算できる関数とちょうど一致するという主張である。証明できる定理ではないが、広く受け入れられている。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   中間表現
      コンパイラの内部で使う、特定のソース言語にも CPU にも依存しないプログラムの表現である。IR とも呼ぶ。最適化の多くは中間表現の上で行われる。

      関連する章: 「:doc:`ch07_programming_languages`」

   抽象構文木
      プログラムの構造のうち、意味に関係する部分だけを残して木の形で表したものである。AST（Abstract Syntax Tree）とも呼ぶ。

      関連する章: 「:doc:`ch07_programming_languages`」

   抽象データ型
      データに対して行える操作とその意味だけを定め、内部の実現方法を定めないデータの型である。スタックやキューなどがある。

      関連する章: 「:doc:`ch04_data_structures`」

   チューリングマシン
      無限に長いテープ、テープを読み書きするヘッド、有限個の状態を持つ制御部からなる計算モデルである。1936 年にチューリングが考案し、計算の最も一般的なモデルとされる。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   停止問題
      任意のプログラムと入力が与えられたとき、そのプログラムがその入力に対していずれ停止するかを判定する問題である。判定不能であることが対角線論法で証明されている。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   デジタル署名
      秘密鍵で作成し、公開鍵で検証する署名である。改ざんの検出に加え、署名者が後から署名を否定できない否認防止を実現する。

      関連する章: 「:doc:`ch13_security`」

   データ構造
      データをメモリ上に格納し、操作するための形式である。格納方法によって各操作にかかる計算量が異なる。

      関連する章: 「:doc:`ch04_data_structures`」

   データベース管理システム
      データの格納・検索・更新、同時実行の制御、障害からの回復を一手に引き受けるソフトウェアである。DBMS（Database Management System）と略す。

      関連する章: 「:doc:`ch11_databases`」

   デッドロック
      複数のスレッドが互いに相手の持つ資源の解放を待ち、どれも先に進めなくなった状態である。相互排除、保持と待機、横取り不可、循環待ちの 4 条件がすべて成り立つときに起きる。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   統計情報
      DBMS が表ごとに保持する、行数、列ごとの異なる値の数、NULL の割合、値の分布（ヒストグラム）などの情報である。オプティマイザが行数を推定するのに使い、ANALYZE で更新する。

      関連する章: 「:doc:`ch11_databases`」

   動的型付け
      型を実行時の値が持ち、型の検査を操作の実行時に行う方式である。Python、Ruby、JavaScript などが採用している。

      関連する章: 「:doc:`ch07_programming_languages`」

   動的計画法
      重なり合う部分問題の答えを表に記録し、再利用することで効率よく問題を解く設計手法である。最長共通部分列やナップサック問題などに使われる。

      関連する章: 「:doc:`ch05_algorithms`」

   動的配列
      容量が尽きるとより大きな領域を確保して要素をコピーし、自動的に大きさを広げる配列である。容量を一定の比率で増やすことで、末尾への追加の償却計算量を :math:`O(1)` にしている。Python の list は動的配列である。

      関連する章: 「:doc:`ch04_data_structures`」

   動的リンク
      実行ファイルには使うライブラリとシンボルだけを記録し、読み込み時または実行中に共有ライブラリと結合する方式である。

      関連する章: 「:doc:`ch07_programming_languages`」

   ド・モルガンの法則
      論理積の否定は否定の論理和に等しく、論理和の否定は否定の論理積に等しいという、ブール代数の法則である。

      関連する章: 「:doc:`ch02_logic_circuits`」

   トライ
      文字列の集合を、根から 1 文字ずつたどる木として表すデータ構造である。検索の手間が文字列の長さだけで決まり、接頭辞検索が得意である。

      関連する章: 「:doc:`ch04_data_structures`」

   トランザクション
      データベースに対する一連の操作をひとまとまりとして扱う単位である。コミットで確定し、ロールバックで取り消す。

      関連する章: 「:doc:`ch11_databases`」、「:doc:`ch12_distributed_systems`」

   貪欲法
      各段階でその時点で最も良く見える選択を行い、後から選び直さないアルゴリズムの設計手法である。単純で高速であるが、常に最適解が得られるとは限らない。

      関連する章: 「:doc:`ch05_algorithms`」

な行
----

.. glossary::

   二相コミット
      複数のノードにまたがるトランザクションを原子的にコミットする方法である。準備フェーズで全参加者の同意を得てからコミットフェーズで決定を伝えるが、途中で調整役が故障すると参加者が待ち続けることがある。

      関連する章: 「:doc:`ch12_distributed_systems`」

   2 の補数
      負の整数を表す方法の 1 つである。:math:`n` ビットの最上位ビットの重みを :math:`-2^{n-1}` とみなす表現で、加算と減算を符号なし整数と同じ回路で行える。

      関連する章: 「:doc:`ch01_data_representation`」

   二分探索
      整列済みの配列で、探す範囲の中央の要素と比較して範囲を半分ずつ絞り込む探索方法である。計算量は :math:`O(\log n)` である。

      関連する章: 「:doc:`ch05_algorithms`」

   二分探索木
      各ノードについて、左の部分木のキーはそのノードのキーより小さく、右の部分木のキーは大きいという性質を満たす二分木である。探索・挿入・削除の計算量は木の高さに比例する。

      関連する章: 「:doc:`ch04_data_structures`」

   認可
      認証された相手に、どの操作や資源へのアクセスを許すかを決めることである。

      関連する章: 「:doc:`ch14_application_security`」

   認証
      相手が誰であるかを確かめることである。知識・所持・生体の要素を用いる。

      関連する章: 「:doc:`ch14_application_security`」

   認証局
      公開鍵証明書を発行し、公開鍵の持ち主を保証する第三者機関である。CA（Certificate Authority）と略す。

      関連する章: 「:doc:`ch13_security`」

   ネットワーク分断
      ノード自体は動いているが、ネットワークの故障により、ノードの集まりが互いに通信できない複数のグループに分かれることである。各グループが相手側を停止したとみなして独自に動くと、データの食い違いが起こる。

      関連する章: 「:doc:`ch12_distributed_systems`」

   ノイマン型アーキテクチャ
      プログラム内蔵方式に基づき、CPU、命令とデータを共に格納する主記憶、入出力装置をバスで結んだコンピュータの構成である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   ノンブロッキング I/O
      データがまだ無いときに待たず、直ちに「今は読み書きできない」ことを返す入出力の方式である。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

      8 ビットをまとめた単位である。現在のほぼすべてのコンピュータは、バイトを単位としてメモリにアドレスを付けている。

      実在の CPU ではなく、ソフトウェアで実装された仮想マシンのための命令列である。Java や CPython が使っている。

      仮想マシンを作り出し、CPU、メモリ、入出力装置を各仮想マシンに割り当てて管理するソフトウェアである。ハードウェア上で直接動くタイプ 1 と、ホスト OS 上で動くタイプ 2 がある。

      命令の処理を複数の段階に分け、異なる命令の異なる段階を同時に処理することで、スループットを高める CPU の技法である。

      データ本体を共通鍵暗号で暗号化し、その共通鍵を公開鍵暗号の技術で共有する方式である。両者の長所を組み合わせる。

   配列
      同じ大きさの要素をメモリ上の連続した領域に順に並べたデータ構造である。添字による要素の参照を :math:`O(1)` で行える。

      関連する章: 「:doc:`ch04_data_structures`」

   ハザード
      パイプラインで、次の命令を予定どおりに進められなくなる状況である。構造ハザード、データハザード、制御ハザードがある。

      関連する章: 「:doc:`ch03_computer_architecture`」

   ハッシュ関数
      データから固定長の整数（ハッシュ値）を計算する関数である。同じデータからは必ず同じ値を返す。ハッシュ表では値がなるべく偏らずに散らばることが求められる。

      関連する章: 「:doc:`ch04_data_structures`」、「:doc:`ch12_distributed_systems`」

   ハッシュ結合
      小さいほうの関係から結合列をキーとするハッシュ表を作り、もう一方の関係の各行でそれを引く結合方式である。平均 :math:`O(N + M)` で計算できるが、等価条件にしか使えない。

      関連する章: 「:doc:`ch11_databases`」

   ハッシュ表
      ハッシュ関数でキーを格納場所（バケット）の番号に変換して格納するデータ構造である。検索・挿入・削除を平均 :math:`O(1)` で行える。Python の dict と set はハッシュ表である。

      関連する章: 「:doc:`ch04_data_structures`」

   バッファオーバーフロー
      配列などの領域に、その大きさを超えるデータを書き込んでしまう誤りである。スタック上の戻り先アドレスなどが上書きされ、任意のコードの実行につながることがある。

      関連する章: 「:doc:`ch14_application_security`」

   幅優先探索
      キューを使い、出発点に近い頂点から順に訪問するグラフの探索方法である。辺の重みが無いグラフの最短距離を求められる。BFS とも呼ぶ。

      関連する章: 「:doc:`ch05_algorithms`」

   ハフマン符号
      出現頻度の高い記号に短い符号語を割り当てる語頭符号で、頻度の小さい 2 つの木を繰り返しまとめて構築する。記号ごとに符号化する語頭符号の中で、平均符号長が最小になる。

      関連する章: 「:doc:`ch01_data_representation`」

   ハミング符号
      検査ビットを 2 の累乗の位置に置き、再計算したパリティ（シンドローム）から誤った位置を特定する誤り訂正符号である。(7,4) 符号は 4 ビットのデータに 3 ビットを加え、1 ビットの誤りを訂正できる。

      関連する章: 「:doc:`ch01_data_representation`」

   パラメトリック多相
      型を引数のように受け取り、どの型に対しても同じ 1 つのコードが同じように動く多相である。ジェネリクスやテンプレートで実現される。

      関連する章: 「:doc:`ch07_programming_languages`」

   パリティビット
      データ中の 1 のビットの個数を偶数（または奇数）にそろえるために付け加える 1 ビットである。奇数個のビットの誤りを検出できるが、訂正はできない。

      関連する章: 「:doc:`ch01_data_representation`」

   半加算器
      1 ビットの 2 つの数を足し、和と桁上げを出力する回路である。XOR ゲートと AND ゲートで作れるが、下の桁からの桁上げを受け取れない。

      関連する章: 「:doc:`ch02_logic_circuits`」

   判定不能
      すべての入力に対して必ず停止して正しく Yes か No を答えるアルゴリズム（チューリングマシン）が存在しないことである。決定不能とも呼ぶ。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   悲観的ロック
      競合が起きるものと考え、データを読む時点でロックを取得して他者の更新を防ぐ方法である。``SELECT ... FOR UPDATE`` などで実現する。

      関連する章: 「:doc:`ch11_databases`」

   非決定性有限オートマトン
      状態と入力記号の組に対して遷移先が複数（または 0 個）あってもよく、入力を読まない :math:`\varepsilon` 遷移も許す有限オートマトンである。NFA とも呼ぶ。認識できる言語のクラスは DFA と等しい。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   ビッグエンディアン
      複数バイトの値の最上位のバイトを最も小さいアドレスに置くバイトオーダーである。インターネットのプロトコルで使われるため、ネットワークバイトオーダーとも呼ぶ。

      関連する章: 「:doc:`ch01_data_representation`」

   ビット
      0 または 1 のどちらかの値を取る、情報の最小単位である。binary digit の略である。

      関連する章: 「:doc:`ch01_data_representation`」

   ビット演算
      整数をビット列とみなし、各ビットごとに AND、OR、XOR、NOT やシフトを行う演算である。

      関連する章: 「:doc:`ch01_data_representation`」

   ヒープ
      どのノードもその子以下の値を持つ（最小ヒープの場合）完全二分木である。配列で表し、値の追加と最小値の取り出しを :math:`O(\log n)` で行える。プログラムが動的に確保するメモリ領域の「ヒープ」とは別の概念である。

      関連する章: 「:doc:`ch04_data_structures`」

   ファイル記述子
      Unix 系の OS で、プロセスが開いているファイル、パイプ、ソケットなどを指す小さな非負の整数である。read や write などのシステムコールはこの番号を指定して行う。

      関連する章: 「:doc:`ch08_operating_systems`」

   ファイルシステム
      補助記憶のブロックの上に、名前の付いたファイルとディレクトリの階層を構成し、管理する仕組みである。

      関連する章: 「:doc:`ch08_operating_systems`」

   深さ優先探索
      スタックまたは再帰を使い、行けるところまで先へ進んでから戻るグラフの探索方法である。連結性の判定、閉路の検出、トポロジカルソートなどに使われる。DFS とも呼ぶ。

      関連する章: 「:doc:`ch05_algorithms`」

   負荷率
      ハッシュ表に格納している要素数をバケット数で割った値である。負荷率が大きいほど衝突が増えるため、一定値を超えるとバケット数を増やして要素を入れ直す。

      関連する章: 「:doc:`ch04_data_structures`」

   輻輳制御
      ネットワークの混雑を避けるため、TCP の送信側が送信量を自ら調整する仕組みである。

      関連する章: 「:doc:`ch10_networks`」

   浮動小数点数
      実数を、符号・指数・仮数の組で近似的に表す形式である。広い範囲の値を一定の相対精度で表せるが、多くの値は丸め誤差を伴う。

      関連する章: 「:doc:`ch01_data_representation`」

   部分型多相
      ある型を期待する場所に、その部分型の値を使える多相である。継承やインタフェースによって実現され、実際の処理は実行時に値の型に応じて選ばれる。

      関連する章: 「:doc:`ch07_programming_languages`」

   部分故障
      分散システムの一部のノードやネットワークだけが故障し、残りは動き続ける状態である。応答が無いとき、相手が停止したのか、処理済みで応答だけが失われたのかを区別できないことが、設計を難しくする。

      関連する章: 「:doc:`ch12_distributed_systems`」

   フリップフロップ
      クロック信号の変化の瞬間（エッジ）にだけ入力を取り込み、それ以外のときは値を保持する 1 ビットの記憶回路である。

      関連する章: 「:doc:`ch02_logic_circuits`」

   ブール代数
      0（偽）と 1（真）の 2 値を扱い、論理積・論理和・否定を基本演算とする代数である。論理回路の設計の数学的な基礎となる。

      関連する章: 「:doc:`ch02_logic_circuits`」

   ブルームフィルタ
      ビット配列と複数のハッシュ関数で集合を表し、要素が含まれるかを少ないメモリで判定するデータ構造である。偽陽性はあるが偽陰性は無く、要素の削除はできない。

      関連する章: 「:doc:`ch04_data_structures`」

   プログラミングパラダイム
      プログラムをどのような考え方で組み立てるかという流儀である。手続き型、オブジェクト指向、関数型、宣言型などがある。

      関連する章: 「:doc:`ch07_programming_languages`」

   プログラムカウンタ
      次に実行する命令のアドレスを保持する CPU のレジスタである。命令を読み出すたびに進み、分岐命令で書き換えられる。

      関連する章: 「:doc:`ch03_computer_architecture`」

   プログラム内蔵方式
      プログラムをデータと同じようにメモリに格納し、そこから命令を順に読み出して実行する方式である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   プロセス
      実行中のプログラムである。OS は各プロセスに独立した仮想アドレス空間を与え、互いに分離する。

      関連する章: 「:doc:`ch08_operating_systems`」

   プロトコル
      通信する者同士が守る約束事である。メッセージの形式、送る順序、エラーの扱いなどを定める。

      関連する章: 「:doc:`ch10_networks`」

   分割統治法
      問題を同じ形の小さな問題に分割し、それぞれを再帰的に解いて結果を組み合わせるアルゴリズムの設計手法である。マージソートや二分探索が例である。

      関連する章: 「:doc:`ch05_algorithms`」

   分岐予測
      分岐命令の結果が確定する前にその結果を予想し、予想した先の命令の処理を進めておく CPU の技法である。外れた場合は処理を破棄してやり直す。

      関連する章: 「:doc:`ch03_computer_architecture`」

   分散システム
      ネットワークでつながった複数のコンピュータが、メッセージをやり取りしながら協調して 1 つの仕事をするシステムである。規模の拡大、可用性の向上、地理的な分散のために使われる。

      関連する章: 「:doc:`ch12_distributed_systems`」

   文脈自由文法
      左辺が非終端記号 1 つだけの生成規則の集まりで言語を定義する文法である。括弧の対応のような入れ子構造を表せ、プログラミング言語の構文の記述に使われる。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   分離レベル
      同時に実行されるトランザクションの分離の度合いを、許容する異常（ダーティリード、ファジーリード、ファントムリード）の種類で定めたものである。SQL 標準は READ UNCOMMITTED から SERIALIZABLE までの 4 段階を定める。

      関連する章: 「:doc:`ch11_databases`」、「:doc:`ch12_distributed_systems`」

   平衡木
      挿入や削除のたびに形を調整し、高さを常に :math:`O(\log n)` に保つ探索木である。AVL 木、赤黒木、B 木などがある。

      関連する章: 「:doc:`ch04_data_structures`」

   冪等キー
      1 つの論理的な操作ごとにクライアントが生成して要求に付ける一意な識別子である。サーバは同じキーの要求を一度だけ処理し、再び届いたら前回の結果を返すので、冪等でない操作も安全に再試行できる。

      関連する章: 「:doc:`ch12_distributed_systems`」

   ベクタ時計
      各プロセスがプロセス数だけの要素を持つカウンタの配列を持つ論理時計である。配列を要素ごとに比べることで、2 つのイベントが因果関係にあるか並行かを判定できる。

      関連する章: 「:doc:`ch12_distributed_systems`」

   ページ置換アルゴリズム
      空きページフレームが無いときに、主記憶から追い出すページを選ぶ規則である。FIFO、LRU、最適置換（OPT）、クロック法などがある。

      関連する章: 「:doc:`ch08_operating_systems`」

   ページテーブル
      仮想ページ番号から物理ページフレーム番号への対応と、アクセス権などの属性を記録した表である。

      関連する章: 「:doc:`ch08_operating_systems`」

   ページフォールト
      アクセスしたページが主記憶に無い、または許可されていない操作をしたときに MMU が発生させる例外である。

      関連する章: 「:doc:`ch08_operating_systems`」

   ページング
      アドレス空間と物理メモリを固定長のページに区切り、ページ単位で仮想アドレスを物理アドレスに対応付ける方式である。

      関連する章: 「:doc:`ch08_operating_systems`」

   ポート番号
      トランスポート層で、同じコンピュータ上の通信相手のプログラムを区別する 16 ビットの番号である。

      関連する章: 「:doc:`ch10_networks`」

   ポンピング補題
      正規言語（または文脈自由言語）に属する十分長い文字列は、その一部を何回繰り返しても同じ言語に属するという性質である。ある言語が正規言語（文脈自由言語）でないことを示すのに使う。

      関連する章: 「:doc:`ch06_theory_of_computation`」

ま行
----

.. glossary::

   マージソート
      配列を半分に分けてそれぞれを再帰的にソートし、2 つの整列済みの列を併合するソートアルゴリズムである。入力によらず :math:`O(n \log n)` で、安定である。

      関連する章: 「:doc:`ch05_algorithms`」

   マスク
      ビット演算で、特定のビットを取り出したり変更したりするために使うビット列である。

      関連する章: 「:doc:`ch01_data_representation`」

   マルチコアプロセッサ
      命令を実行するコアを 1 つのチップに複数載せたプロセッサである。各コアが独立に命令の流れを実行し、L3 キャッシュや主記憶を共有することが多い。

      関連する章: 「:doc:`ch03_computer_architecture`」

   マルチプレクサ
      複数の入力の中から、選択信号で指定された 1 つを出力に通す回路である。MUX とも書く。

      関連する章: 「:doc:`ch02_logic_circuits`」

   丸め誤差
      数値を有限の桁数に収めるために丸めることで生じる誤差である。浮動小数点数の演算では、演算のたびに生じて蓄積しうる。

      関連する章: 「:doc:`ch01_data_representation`」

   ミューテックス
      取得と解放の操作を持ち、同時に 1 つのスレッドだけが取得できる排他制御の道具である。ロックとも呼ぶ。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   命令実行サイクル
      CPU が命令をフェッチ（読み出し）、デコード（解釈）、実行する一連の手順である。CPU はこれを繰り返してプログラムを実行する。

      関連する章: 「:doc:`ch03_computer_architecture`」

   命令セットアーキテクチャ
      CPU が実行できる命令の集合と、その形式・動作の取り決めである。ハードウェアとソフトウェアの間の契約にあたる。ISA と略す。

      関連する章: 「:doc:`ch03_computer_architecture`」

   メッセージ認証コード
      共有した秘密鍵とメッセージから計算する短い値（タグ）で、メッセージの完全性と送信元の真正性を検証するために使う。MAC と略し、HMAC が代表的な構成である。

      関連する章: 「:doc:`ch01_data_representation`」、「:doc:`ch13_security`」

   メモ化
      関数の計算結果を引数ごとに記録しておき、同じ引数で呼ばれたときに記録を返す手法である。Python では ``functools.cache`` で実現できる。

      関連する章: 「:doc:`ch05_algorithms`」

   メモリ安全性
      プログラムが、自分に割り当てられた範囲の、まだ有効なメモリだけを正しく読み書きすることが保証される性質である。C や C++ では言語によって保証されない。

      関連する章: 「:doc:`ch14_application_security`」

   メモリ階層
      レジスタ、キャッシュ、主記憶、補助記憶のように、速度・容量・価格の異なる記憶装置を階層的に組み合わせた構成である。

      関連する章: 「:doc:`ch03_computer_architecture`」

   メモリバリア
      その前の読み書きが、その後の読み書きより先に他のコアから見えることを保証する命令である。メモリフェンスとも呼ぶ。ロックの取得と解放にも含まれている。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   メモリモデル
      複数のスレッドからの読み書きについて、どのような並べ替えが起こり得て、読み出しがどの値を返してよいかを定めた規則である。CPU と言語処理系がそれぞれ定める。

      関連する章: 「:doc:`ch09_concurrency_and_io`」

   文字コード
      文字とビット列（数値）を対応付ける規則である。文字に番号を振る文字集合と、番号をバイト列に変換する符号化方式からなる。

      関連する章: 「:doc:`ch01_data_representation`」

   文字化け
      バイト列を、書き込んだときとは異なる文字コードで解釈することで、意図しない文字が表示される現象である。

      関連する章: 「:doc:`ch01_data_representation`」

   モノトニッククロック
      ある基準点からの経過時間を表し、決して逆戻りしない時計である。値の差だけが意味を持ち、経過時間の測定やタイムアウトの判定に使う。Python では ``time.monotonic()`` で得られる。

      関連する章: 「:doc:`ch12_distributed_systems`」

や行
----

.. glossary::

   有限オートマトン
      有限個の状態を持ち、入力の文字列を先頭から 1 文字ずつ読みながら状態を移っていく計算モデルである。記憶は現在の状態だけであり、正規言語を認識する。

      関連する章: 「:doc:`ch06_theory_of_computation`」

   優先度付きキュー
      値を追加する操作と、最も優先度の高い値を取り出す操作を持つ抽象データ型である。通常はヒープで実装する。

      関連する章: 「:doc:`ch04_data_structures`」

ら行
----

.. glossary::

   ラウンドロビン
      実行可能な列の先頭から選んで一定時間（クォンタム）だけ実行し、終わらなければ列の末尾に戻すスケジューリング方式である。

      関連する章: 「:doc:`ch08_operating_systems`」

   楽観的ロック
      読むときにはロックを取らず、書き込むときにバージョン列などで、読んだ後に他者が更新していないかを確かめる方法である。更新件数が 0 なら競合とみなして再試行する。

      関連する章: 「:doc:`ch11_databases`」

   ラッチ
      1 ビットの状態を保持する回路のうち、入力の変化に直ちに反応するものである。SR ラッチや D ラッチがある。

      関連する章: 「:doc:`ch02_logic_circuits`」

   ランポート時計
      各プロセスが 1 つの整数カウンタを持ち、イベントごとに 1 増やし、受信時には自分の値とメッセージに付いた値の大きい方に 1 を足す論理時計である。:math:`a \to b` ならば :math:`L(a) < L(b)` が成り立つが、逆は成り立たない。

      関連する章: 「:doc:`ch12_distributed_systems`」

   リトルエンディアン
      複数バイトの値の最下位のバイトを最も小さいアドレスに置くバイトオーダーである。x86-64 や、AArch64 を使う主要な OS が採用している。

      関連する章: 「:doc:`ch01_data_representation`」

   リプルキャリー加算器
      全加算器を :math:`n` 個並べ、各桁の桁上げを 1 つ上の桁に渡して :math:`n` ビットの加算を行う回路である。構成は単純だが、遅延がビット数に比例する。

      関連する章: 「:doc:`ch02_logic_circuits`」

   リンカ
      複数のオブジェクトファイルとライブラリを結合して 1 つの実行ファイルを作るプログラムである。シンボルの解決と再配置を行う。

      関連する章: 「:doc:`ch07_programming_languages`」

   隣接行列
      頂点数を :math:`V` として :math:`V \times V` の 2 次元配列でグラフを表す方法である。辺の有無を :math:`O(1)` で判定できるが、:math:`O(V^2)` のメモリを使う。

      関連する章: 「:doc:`ch04_data_structures`」

   隣接リスト
      頂点ごとに、辺でつながった頂点の一覧を持つことでグラフを表す方法である。メモリ使用量が頂点数と辺数の和に比例し、辺の少ないグラフに適している。

      関連する章: 「:doc:`ch04_data_structures`」

   ルーティング
      パケットの宛先に応じて次の転送先を決めることである。ルータは経路表の最長一致で経路を選ぶ。

      関連する章: 「:doc:`ch10_networks`」

   例外処理
      エラーを通常の戻り値とは別の経路で呼び出し元に伝える仕組みである。送出された例外は、それを処理する箇所が見つかるまでコールスタックをさかのぼって伝播する。

      関連する章: 「:doc:`ch07_programming_languages`」

   レジスタ
      フリップフロップを並べて作る、複数ビットの値を記憶する回路である。CPU の内部で演算の入力や結果を一時的に保持する、最も高速な記憶領域として使われる。

      関連する章: 「:doc:`ch02_logic_circuits`」

   レプリケーション
      同じデータの複製を複数のノードに持たせることである。可用性と耐久性の向上、読み出しの分散、遅延の削減を目的とし、単一リーダ型、マルチリーダ型、リーダレス型がある。

      関連する章: 「:doc:`ch12_distributed_systems`」

   連結リスト
      値と次の要素への参照を組にしたノードを、参照でつないで並べたデータ構造である。位置が分かっていれば挿入・削除を :math:`O(1)` で行えるが、添字による参照には :math:`O(n)` かかる。

      関連する章: 「:doc:`ch04_data_structures`」

   ログ先行書き込み
      データのページを補助記憶に書き込む前に、変更内容を記録したログを先に永続化する方式である。障害後はログをもとに REDO と UNDO を行って回復する。WAL（Write-Ahead Logging）と略す。

      関連する章: 「:doc:`ch11_databases`」

   ローダ
      実行ファイルを補助記憶から読み込み、プロセスの仮想アドレス空間に配置して実行を開始する仕組みである。多くの場合 OS の一部である。

      関連する章: 「:doc:`ch07_programming_languages`」

   論理ゲート
      AND、OR、NOT などのブール代数の演算を実現する電子回路の基本素子である。現在の集積回路では CMOS トランジスタで作られる。

      関連する章: 「:doc:`ch02_logic_circuits`」

   論理時計
      物理的な時刻を使わず、イベントの因果関係と矛盾しない値を各イベントに割り当てる仕組みである。ランポート時計やベクタ時計がある。

      関連する章: 「:doc:`ch12_distributed_systems`」

.. glossary::

   割り込み
      実行中の命令の流れを中断して、カーネルの処理に制御を移す仕組みである。装置からのハードウェア割り込みと、命令が原因で起きる例外がある。

      関連する章: 「:doc:`ch08_operating_systems`」
