アルゴリズムと計算量
====================

「:doc:`ch04_data_structures`」では、データの格納方法と、各操作にかかる手間を学んだ。この章では、そのデータ構造を使って問題を解く手順、すなわちアルゴリズムを扱う。まず、アルゴリズムの効率を比べるための尺度である計算量と O 記法を定義する。次に、探索とソートという基本的な問題を例に、計算量の異なるアルゴリズムを比べる。さらに、再帰と分割統治、動的計画法、貪欲法という代表的な設計手法を学び、最後にグラフ上の探索と最短経路の求め方を扱う。

アルゴリズムとは
----------------

:term:`アルゴリズム`\ とは、問題を解くための明確な手順を、有限の長さで記述したものである。例えば「整列済みの名簿から目的の名前を探す」「荷物の配送経路のうち最も短いものを求める」といった問題に対して、どのような順に何を計算すれば答えが得られるかを定めたものがアルゴリズムである。アルゴリズムには次の性質が求められる。

* 各手順が曖昧さなく定められており、機械的に実行できる。
* どのような入力に対しても、有限回の手順で終了する。
* 正しい出力（問題の答え）を返す。

アルゴリズムはプログラミング言語とは独立した概念であり、同じアルゴリズムを Python でも C でも書ける。逆に、同じ問題を解く複数のアルゴリズムがあり、それらの効率は大きく異なることがある。データが少ないうちはどのアルゴリズムでも一瞬で終わるが、データが 100 万件、1 億件と増えたとき、選んだアルゴリズムの違いが数秒と数日の差になって現れる。

なお、「どのようなアルゴリズムでも解けない問題」も存在する。これについては「:doc:`ch06_theory_of_computation`」で扱う。

計算量と O 記法
---------------

計算量を何で測るか
^^^^^^^^^^^^^^^^^^

アルゴリズムの効率を実行時間の秒数で比べると、CPU の性能、プログラミング言語、他に動いているプロセスなどの影響を受けてしまう。そこで、アルゴリズムが実行する基本的な操作（比較、代入、算術演算など）の回数を、入力の大きさ :math:`n` の関数として数える。これを\ :term:`時間計算量`\ と呼ぶ。同様に、アルゴリズムが使う記憶領域の量を :math:`n` の関数として表したものを\ :term:`空間計算量`\ と呼ぶ。両者を合わせて\ :term:`計算量`\ と呼び、単に計算量といえば時間計算量を指すことが多い。入力の大きさは、配列なら要素数、文字列なら文字数、グラフなら頂点数と辺数で表す。

操作の回数を正確に数えるのは難しく、また正確な値にはあまり意味がない。例えば、ある処理の回数が :math:`3n^2 + 5n + 2` 回だったとしても、:math:`n` が大きくなると :math:`3n^2` の項が圧倒的に大きくなり、係数の 3 も CPU や言語によって変わる。重要なのは「:math:`n` が 2 倍になると手間がおよそ 4 倍になる」という増え方である。そこで、最も増え方の大きい項だけを残し、定数倍を無視して増え方を表す。

O 記法・Ω 記法・Θ 記法
^^^^^^^^^^^^^^^^^^^^^^

増え方を表す記法が :term:`O 記法`\ （オー記法、ビッグオー記法）である。関数 :math:`f(n)` と :math:`g(n)` について、ある正の定数 :math:`c` と :math:`n_0` が存在し、:math:`n \ge n_0` を満たすすべての :math:`n` に対して次の不等式が成り立つとき、:math:`f(n) = O(g(n))` と書く。

.. math::

   0 \le f(n) \le c \cdot g(n)

これは「:math:`n` が十分大きければ、:math:`f(n)` は :math:`g(n)` の定数倍を超えない」こと、すなわち :math:`g(n)` が :math:`f(n)` の増え方の\ **上界**\ であることを表す。例えば :math:`n \ge 1` のとき :math:`3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2` なので、:math:`c = 10`、:math:`n_0 = 1` とすれば :math:`3n^2 + 5n + 2 = O(n^2)` である。この定義から、次の規則が導かれる。

* 定数倍は無視できる。:math:`100n = O(n)` である。
* 和では増え方の大きい項だけが残る。:math:`n^2 + n \log n = O(n^2)` である。
* 対数の底は無視できる。底の変換公式 :math:`\log_a n = \log_b n / \log_b a` より、底の違いは定数倍の違いにすぎないからである。そのため、本書では O 記法の中で底を書かない。O 記法の外で底を省略した :math:`\log n` は、底 2 の対数 :math:`\log_2 n` を表す。

同様に、下界と、上下からの評価を表す記法がある。

* :math:`f(n) = \Omega(g(n))`\ （オメガ記法）: ある正の定数 :math:`c` と :math:`n_0` が存在し、:math:`n \ge n_0` で :math:`f(n) \ge c \cdot g(n) \ge 0` が成り立つ。:math:`g(n)` が下界であることを表す。
* :math:`f(n) = \Theta(g(n))`\ （シータ記法）: :math:`f(n) = O(g(n))` かつ :math:`f(n) = \Omega(g(n))` である。増え方がちょうど :math:`g(n)` であることを表す。

厳密には、:math:`O` は上界にすぎないので、:math:`O(\log n)` で終わるアルゴリズムは :math:`O(n)` でもある。しかし実務や多くの文献では、:math:`O` を「ちょうどその増え方」という :math:`\Theta` の意味で使うことが多い。本書でも、誤解の無い範囲で :math:`O` を使う。より厳密な扱いは [CLRS]_ を参照。

最悪・平均・最良
^^^^^^^^^^^^^^^^

同じ大きさの入力でも、入力の内容によって手間は変わる。例えば配列の先頭から値を探す場合、目的の値が先頭にあれば 1 回の比較で済むが、存在しなければ :math:`n` 回の比較が必要である。そこで、次の 3 つを区別する。

* 最悪計算量: 大きさ :math:`n` の入力のうち、最も手間のかかる入力に対する計算量。
* 平均計算量: 入力の現れ方に確率分布（例えばすべての並び順が等確率）を仮定したときの計算量の期待値。
* 最良計算量: 最も手間の少ない入力に対する計算量。

特に断らない限り、計算量は最悪計算量を指す。最悪計算量は「どんな入力が来てもこれ以上はかからない」という保証になるからである。ただし、後で扱うクイックソートや第 4 章のハッシュ表のように、最悪の場合はまれで平均が実用上の性能をよく表すものもある。また、第 4 章の「:ref:`ch04-dynamic-array`」で扱った償却計算量は、一連の操作全体の最悪の手間を操作の回数で割ったもので、確率の仮定を置かない点で平均計算量とは異なる。

実務での見積もり
^^^^^^^^^^^^^^^^

実務でコードを読むときは、ループの入れ子の深さと、ループの中で呼び出している操作の計算量に注目すると、おおよその計算量を見積もれる。:math:`n` 件のデータに対する 1 重のループは :math:`O(n)`、2 重のループは :math:`O(n^2)` である。注意したいのは、ループが目に見えない形で隠れている場合である。

* ループの中で ``list`` に対して ``in``、``index()``、``remove()``、``pop(0)`` を使うと、それぞれが :math:`O(n)` のため全体が :math:`O(n^2)` になる（「:doc:`ch04_data_structures`」）。
* ループの中で文字列を ``+=`` で連結し続けると、処理系によっては毎回新しい文字列へのコピーが発生し、全体で :math:`O(n^2)` になる。``"".join()`` を使えば :math:`O(n)` で済む。
* データベースの検索をループの中で 1 件ずつ発行すると、:math:`n` 件のデータに対して :math:`1 + n` 回の問い合わせが発生する。これは N+1 問題と呼ばれ、1 回ごとの通信の遅延が積み重なって大きな遅れになる。まとめて 1 回で取得するか、結合を使う（「:doc:`ch11_databases`」）。

目安として、Python で単純な操作を繰り返すと 1 秒間に :math:`10^7` 回程度（環境によって大きく異なる）実行できる。:math:`n` と計算量から操作の回数を見積もり、この値と比べると、書く前にそのアルゴリズムが実用的かどうかを判断できる。

探索
----

配列の中から目的の値を探す問題を\ **探索**\ と呼ぶ。

線形探索
^^^^^^^^

:term:`線形探索`\ は、先頭から順に 1 つずつ目的の値と比較していく方法である。データが整列していなくても使えるが、最悪の場合（値が末尾にあるか存在しない場合）は :math:`n` 回の比較が必要で、計算量は :math:`O(n)` である。値が存在し、どの位置にあるかが等確率なら、平均の比較回数は約 :math:`n/2` 回であり、これも :math:`O(n)` である。Python の ``list`` に対する ``in`` 演算子や ``index()`` メソッドは線形探索である。

二分探索
^^^^^^^^

データが整列済みなら、より速く探せる。:term:`二分探索`\ は、探す範囲の中央の要素と目的の値を比較し、目的の値が小さければ左半分、大きければ右半分に範囲を絞り込む方法である。辞書を引くとき、真ん中あたりを開いて前か後ろかを判断する作業を繰り返すのと同じである。

1 回の比較で範囲が半分になるので、:math:`n` 個の要素は :math:`k` 回の比較で :math:`n / 2^k` 個以下に絞られる。範囲が 1 個になるまでの比較回数は :math:`\log n` 程度で、最悪の比較回数は :math:`\lfloor \log n \rfloor + 1` 回である。したがって計算量は :math:`O(\log n)` である。

線形探索の比較回数は :math:`n` に比例して増えるが、二分探索は :math:`n` が 10 倍になっても 3〜4 回しか増えない。二分探索の比較回数は、いずれも :math:`\lfloor \log n \rfloor + 1` に一致している。

.. note::

   二分探索は単純に見えるが、範囲の端を含むか含まないか、ループの終了条件、``mid`` の更新を誤りやすい。また、C や Java のように整数の大きさに上限がある言語では、``(lo + hi) / 2`` の加算があふれる（オーバーフローする）ことがあり、``lo + (hi - lo) / 2`` と書くのが安全である。Python の整数には上限が無いので、この問題は起きない。

bisect モジュール
^^^^^^^^^^^^^^^^^

Python では、整列済みの ``list`` に対する二分探索に標準ライブラリの ``bisect`` モジュールを使う。``bisect_left(a, x)`` は「``x`` を挿入しても整列が保たれる最も左の位置」、すなわち ``x`` 以上の最初の要素の位置を返し、``bisect_right(a, x)`` は ``x`` より大きい最初の要素の位置を返す。サンプルの後半のように、2 つを組み合わせると「ある範囲の値がいくつあるか」を :math:`O(\log n)` で求められる。時刻順に並んだログから指定した期間のものを取り出す、点数から評価の段階を決める、といった処理に使える。

``insort()`` は整列を保ったまま値を挿入するが、挿入位置を探すのが :math:`O(\log n)` でも、``list`` の途中への挿入で後ろの要素をずらすため、全体では :math:`O(n)` かかる。挿入と検索を大量に繰り返す場合は、平衡木（第 4 章）のようなデータ構造が必要になる。

また、整列には次節で見るように :math:`O(n \log n)` かかる。1 回だけ探すなら、整列してから二分探索するより、線形探索の方が速い。何度も探す場合に、整列の手間を多くの探索で分け合うことで二分探索が有利になる。キーによる検索だけで十分なら、``set`` や ``dict`` で平均 :math:`O(1)` の検索をする方が簡単である。

再帰と分割統治
--------------

再帰
^^^^

関数が自分自身を呼び出すことを\ :term:`再帰`\ と呼ぶ。再帰を使うと、「問題を同じ形の小さな問題に分けて解く」手順を素直に書ける。例えば :math:`n` の階乗 :math:`n!` は、:math:`0! = 1` および :math:`n! = n \times (n-1)!` と定義でき、そのまま次のように書ける。

.. code-block:: python
   :linenos:

   def factorial(n: int) -> int:
       if n == 0:
           return 1                   # 基底部: これ以上分けずに答えを返す
       return n * factorial(n - 1)    # 再帰部: 小さな問題に帰着する

再帰関数には、それ以上自分を呼ばずに答えを返す\ **基底部**\ と、より小さな問題について自分を呼ぶ\ **再帰部**\ が必要である。再帰部が必ず基底部に近づくように書かないと、呼び出しが無限に続く。

関数を呼び出すたびに、引数や局所変数を保存する領域（スタックフレーム）がコールスタックに積まれる（「:doc:`ch07_programming_languages`」）。そのため再帰の深さに比例した空間計算量が必要であり、深すぎるとスタックがあふれる。Python は既定で再帰の深さを 1000 程度に制限しており（``sys.getrecursionlimit()`` で確認できる）、超えると ``RecursionError`` になる。深さが :math:`n` に比例する再帰は、Python ではループに書き直すのが安全である。

分割統治法
^^^^^^^^^^

問題を同じ形のいくつかの小さな問題に分割し（分割）、それぞれを再帰的に解き（統治）、その結果を組み合わせて元の問題の答えを得る設計手法を\ :term:`分割統治法`\ と呼ぶ。前節の二分探索は、問題を半分に分けて片方だけを解く、最も簡単な分割統治法である。次節のマージソートとクイックソートも分割統治法である。

分割統治法の計算量は、大きさ :math:`n` の問題にかかる手間 :math:`T(n)` を、より小さな問題の手間で表した式（漸化式）で表せる。例えば二分探索は、大きさ :math:`n/2` の問題 1 つと、定数の手間の比較からなるので、次の漸化式になる。

.. math::

   T(n) = T(n/2) + c

これを繰り返し展開すると :math:`T(n) = T(n/2^k) + kc` となり、:math:`k = \log n` で :math:`T(1)` に達するので :math:`T(n) = O(\log n)` である。代表的な漸化式とその解を次の表に示す。

.. list-table::
   :header-rows: 1
   :widths: 40 25 35

   * - 漸化式
     - 解
     - 例
   * - :math:`T(n) = T(n/2) + O(1)`
     - :math:`O(\log n)`
     - 二分探索
   * - :math:`T(n) = 2T(n/2) + O(n)`
     - :math:`O(n \log n)`
     - マージソート
   * - :math:`T(n) = T(n-1) + O(n)`
     - :math:`O(n^2)`
     - クイックソートの最悪の場合
   * - :math:`T(n) = 2T(n-1) + O(1)`
     - :math:`O(2^n)`
     - ハノイの塔

ソート
------

データを決められた順序に並べ替えることを\ **ソート**\ （整列）と呼ぶ。ソートは、二分探索の前処理、重複の除去、順位付け、データベースの結合など、多くの処理の基礎となる。ここでは要素同士の比較によって並べ替える 3 つのアルゴリズムを取り上げる。

挿入ソート
^^^^^^^^^^

挿入ソートは、配列の先頭側を「整列済みの部分」とし、その次の要素を整列済みの部分の適切な位置に挿入することを繰り返す方法である。トランプの手札を並べるときの方法に近い。挿入する要素より大きい要素を 1 つずつ右にずらしながら、挿入位置を探す。

最悪の場合（逆順に並んでいる場合）、:math:`i` 番目の要素の挿入に :math:`i` 回の比較が必要で、比較の総数は :math:`1 + 2 + \cdots + (n-1) = n(n-1)/2` 回、計算量は :math:`O(n^2)` である。一方、すでに整列している場合は各要素で 1 回比較するだけで済み、:math:`O(n)` で終わる。このため、ほぼ整列済みのデータや要素数の少ないデータに対しては高速であり、後述の Timsort の内部でも使われている。

マージソート
^^^^^^^^^^^^

:term:`マージソート`\ は、配列を半分に分け、それぞれを再帰的にソートし、2 つの整列済みの列を 1 つに併合（マージ）する分割統治法である。2 つの整列済みの列の併合は、それぞれの先頭を比べて小さい方を取り出すことを繰り返せばよく、:math:`O(n)` でできる。したがって計算量は次の漸化式で表せる（:math:`c` は定数）。

.. math::

   T(n) = 2T(n/2) + cn

これを展開すると次のようになる。

.. math::

   T(n) &= 2T(n/2) + cn \\
        &= 4T(n/4) + 2cn \\
        &= 2^k T(n/2^k) + kcn

:math:`k = \log n` のとき :math:`n/2^k = 1` となるので、:math:`T(n) = nT(1) + cn \log n = O(n \log n)` である。分割を繰り返すと :math:`\log n` 段になり、各段の併合の手間の合計が :math:`cn` であると考えてもよい。マージソートは入力の並びによらず常に :math:`O(n \log n)` であるが、併合のために :math:`O(n)` の作業領域が必要である。

.. _ch05-quick-sort:

クイックソート
^^^^^^^^^^^^^^

:term:`クイックソート`\ は、配列から 1 つの要素（ピボット）を選び、ピボット以下の要素を左に、大きい要素を右に集める分割を行い、左右をそれぞれ再帰的にソートする方法である。分割が終わった時点でピボットは最終的な位置に確定するので、併合の手間は要らない。

ピボットによって配列がほぼ半分に分かれれば、マージソートと同じく :math:`O(n \log n)` になる。しかし、ピボットが常に最小値や最大値になると、分割のたびに要素が 1 つ減るだけになり、漸化式 :math:`T(n) = T(n-1) + cn` から :math:`O(n^2)` になる。例えば末尾の要素を常にピボットに選ぶ実装に整列済みの配列を与えると、この最悪の場合になる。ピボットをランダムに選べば、どのような入力に対しても平均 :math:`O(n \log n)` になる。クイックソートは作業領域が少なく、内側のループが単純でキャッシュの効果も得やすいため、実用上は高速なことが多い。C++ の ``std::sort()`` の多くの実装は、クイックソートを基に、再帰が深くなりすぎたらヒープソートに切り替えるなどして最悪の場合を避ける工夫（イントロソート）を加えたものである。

比較ソートの下限
^^^^^^^^^^^^^^^^

要素同士の比較だけを使うソートは、どれほど工夫しても最悪の場合に :math:`\Omega(n \log n)` 回の比較が必要であることが知られている。:math:`n` 個の異なる要素の並び方は :math:`n!` 通りあり、ソートはこのうちどれが入力されたかを比較の結果だけから見分けなければならない。1 回の比較の結果は「以下」か「より大きい」の 2 通りなので、:math:`k` 回の比較で見分けられるのは高々 :math:`2^k` 通りである。したがって :math:`2^k \ge n!`、すなわち次が必要である。

.. math::

   k \ge \log (n!)

:math:`n!` には :math:`n/2` 以上の数が :math:`n/2` 個以上含まれるので :math:`n! \ge (n/2)^{n/2}` であり、:math:`\log (n!) \ge (n/2) \log (n/2) = \Omega(n \log n)` となる。実行結果の 1 行目の「下限」はこの :math:`\log (n!)` の値であり、マージソートの 3,837 回はこの下限に近い。マージソートは比較ソートとして漸近的に最適である。

なお、この下限は比較だけを使う場合のものである。値が小さな範囲の整数であることが分かっていれば、値ごとの個数を数える計数ソートや、桁ごとに分類する基数ソートによって :math:`O(n)` でソートできる場合がある。

安定性と Python の sorted
^^^^^^^^^^^^^^^^^^^^^^^^^

ソートの前後で、等しいキーを持つ要素の相対的な順序が保たれるソートを\ :term:`安定ソート`\ と呼ぶ。例えば、受付順に並んだ応募者を点数でソートしたとき、同じ点数の人が受付順のまま並ぶのが安定ソートである。安定ソートを使えば、「部署順、同じ部署なら入社順」のような複数のキーによる並べ替えを、優先度の低いキーから順にソートを重ねることで実現できる。挿入ソートとマージソート（併合で等しいときに左を先に出す場合）は安定であり、クイックソートは一般に安定ではない。

Python の ``sorted()`` と ``list.sort()`` は Timsort と呼ばれるアルゴリズムを使っている。Timsort はマージソートと挿入ソートを組み合わせたもので、入力の中にすでに整列している区間（ラン）を見つけて活用する。最悪の場合も :math:`O(n \log n)` であり、整列済みやほぼ整列済みのデータでは :math:`O(n)` に近い手間で終わる。また、安定ソートであることが保証されている [PythonDocs]_。実行結果の最後の行では、点数の高い順に並べたとき、同じ 90 点の「鈴木」と「田中」、同じ 80 点の「佐藤」と「高橋」が元の順序を保っている。``reverse=True`` を指定しても安定性は保たれる。

実務では、ソートアルゴリズムを自作する必要はほとんどなく、``sorted()`` に ``key`` 引数を渡して使えばよい。自作のソートより速く、安定性も保証されている。

動的計画法
----------

問題を小さな部分問題に分けて解く点は分割統治法と同じであるが、部分問題が互いに重なり合い、同じ部分問題が何度も現れる場合には、別の工夫が有効である。部分問題の答えを表に記録しておき、同じ部分問題が現れたら記録を再利用する設計手法を\ :term:`動的計画法`\ （DP: Dynamic Programming）と呼ぶ。動的計画法が使えるのは、元の問題の最適解が部分問題の最適解から組み立てられる（最適部分構造を持つ）場合である。

フィボナッチ数とメモ化
^^^^^^^^^^^^^^^^^^^^^^

フィボナッチ数は次の漸化式で定義される。

.. math::

   F(0) = 0, \quad F(1) = 1, \quad F(n) = F(n-1) + F(n-2) \quad (n \ge 2)

これを定義どおりに再帰で書くと、:math:`F(n-1)` の計算の中でも :math:`F(n-2)` が計算されるため、同じ値が何度も計算される。関数の呼び出し回数は :math:`F(n)` 自体と同じく指数関数的に増え、計算量は :math:`O(\phi^n)`\ （:math:`\phi = (1 + \sqrt{5})/2 \approx 1.618` は黄金比）になる。

一度計算した結果を記録しておき、同じ引数で呼ばれたら記録を返す方法を\ :term:`メモ化`\ と呼ぶ。メモ化すると、:math:`F(0)` から :math:`F(n)` までをそれぞれ 1 回だけ計算するので、計算量は :math:`O(n)` になる。Python では ``functools.cache`` デコレータを付けるだけでメモ化できる。

   fib(30) = 832040: 素朴な再帰 2,692,537 回, メモ化 31 回の計算

素朴な再帰の呼び出し回数は :math:`2F(n+1) - 1` 回になり、:math:`n` が 10 増えるごとに約 120 倍になっている。メモ化した場合は、実際に計算した回数（記録に無かった回数）が :math:`n + 1` 回で済んでいる。

メモ化は「上から」再帰で解く方法であるが、:math:`F(0)`、:math:`F(1)`、:math:`F(2)`、… と「下から」順にループで表を埋めてもよい。こちらは再帰の深さの制限を受けず、直前の 2 つの値だけを覚えておけば空間計算量も :math:`O(1)` にできる。

最長共通部分列
^^^^^^^^^^^^^^

動的計画法の典型的な例として、2 つの文字列の\ **最長共通部分列**\ （LCS: Longest Common Subsequence）を求める問題を取り上げる。部分列とは、文字列からいくつかの文字を取り除いて（順序は変えずに）得られる列である。例えば ``ACA`` は ``AGCAT`` の部分列であり、``GACTA`` の部分列でもあるので、両者の共通部分列である。2 つのファイルの差分を表示する ``diff`` コマンドや Git の差分表示も、この問題と密接に関係する問題を解いている。

文字列 :math:`a` の先頭 :math:`i` 文字と、文字列 :math:`b` の先頭 :math:`j` 文字の LCS の長さを :math:`L(i, j)` とする。:math:`a` の :math:`i` 文字目を :math:`a_i` と書くと、:math:`L(i, j)` は次の漸化式で求まる。

.. math::

   L(i, j) =
   \begin{cases}
   0 & (i = 0 \lor j = 0) \\
   L(i-1, j-1) + 1 & (a_i = b_j) \\
   \max(L(i-1, j), L(i, j-1)) & (a_i \ne b_j)
   \end{cases}

末尾の文字が等しければ、その文字を LCS に含めて残りの LCS に 1 を足せばよい。等しくなければ、どちらか一方の末尾の文字を捨てた 2 つの部分問題のうち、長い方が答えになる。:math:`L(i, j)` を :math:`i` と :math:`j` の小さい順に表に埋めていけば、各要素は定数の手間で求まり、計算量は文字列の長さを :math:`m`、:math:`n` として :math:`O(mn)` である。すべての部分列を列挙する方法では :math:`O(2^m)` 個の部分列を調べることになるので、大きな改善である。

貪欲法
------

:term:`貪欲法`\ は、各段階でその時点で最も良く見える選択を行い、後から選び直さない設計手法である。手順が単純で高速なことが多いが、常に最適解が得られるとは限らない。貪欲法で最適解が得られるかどうかは、問題ごとに証明が必要である。

例として、指定した金額をできるだけ少ない枚数の硬貨で支払う問題を考える。貪欲法では「支払える範囲で額の最も大きい硬貨を使う」ことを繰り返す。日本の硬貨（1、5、10、50、100、500 円）では、この方法で常に最小枚数になる。しかし、硬貨の種類が 1、3、4 円の場合に 6 円を支払うと、貪欲法は 4 + 1 + 1 の 3 枚を選ぶが、最適解は 3 + 3 の 2 枚である。最初に 4 円を選んだ時点で、最適解への道が閉ざされている。

この問題は、金額 :math:`x` を支払う最小枚数を :math:`B(x)` とすると、硬貨の額面の集合を :math:`C` として次の漸化式で表せるので、動的計画法で確実に解ける。

.. math::

   B(0) = 0, \quad B(x) = \min_{c \in C,\ c \le x} \bigl( B(x - c) + 1 \bigr)

   fib(30) = 832040: 素朴な再帰 2,692,537 回, メモ化 31 回の計算
   LCS(AGCAT, GACTA) = ACA
   硬貨 [1, 5, 10, 50, 100, 500], 6 円: 貪欲法 [5, 1], 動的計画法 [1, 5]
   硬貨 [1, 3, 4], 6 円: 貪欲法 [4, 1, 1], 動的計画法 [3, 3]

日本の硬貨では、貪欲法と動的計画法が同じ枚数（2 枚）の解を出している（並び順の違いは復元の順序によるもので、組み合わせは同じである）。1、3、4 円の硬貨では、貪欲法が 3 枚、動的計画法が 2 枚となり、貪欲法が最適解を出せていない。

貪欲法が最適解を与える問題も多い。次節のダイクストラ法は、「まだ確定していない頂点のうち最も近いものを確定する」という貪欲法の一種であり、辺の重みが非負なら正しい最短距離が得られることが証明されている。また、データ圧縮に使われるハフマン符号の構成も貪欲法である。

幅優先探索
^^^^^^^^^^

:term:`幅優先探索`\ （BFS: Breadth-First Search）は、出発点に近い頂点から順に訪問する方法である。キューを使い、取り出した頂点に隣接する未訪問の頂点をキューの末尾に追加することを繰り返す。こうすると、出発点から辺 1 本で行ける頂点をすべて訪問してから、辺 2 本で行ける頂点に進む。したがって、すべての辺の重みが等しいグラフでは、各頂点を初めて発見したときの辺の数がそのまま出発点からの最短距離になる。

   :language: python
   :linenos:
   :lineno-match:
   :caption: ch05_graph.py（幅優先探索）
   :pyobject: bfs

キューには第 4 章で学んだ ``collections.deque`` を使っている。``list`` の ``pop(0)`` を使うと取り出しのたびに :math:`O(V)` かかってしまう。各頂点はキューに 1 回だけ入り、各頂点の隣接リストを 1 回ずつ調べるので、計算量は :math:`O(V + E)` である。隣接行列で表した場合は、各頂点の隣接する頂点を列挙するのに :math:`O(V)` かかるため :math:`O(V^2)` になる。SNS で「友達の友達」を求める処理や、迷路の最短手数を求める処理は幅優先探索である。

ダイクストラ法
^^^^^^^^^^^^^^

辺に距離や所要時間などの重みがある場合、辺の数が少ない経路が最短とは限らない。辺の重みが非負のグラフで、出発点から各頂点への最短距離を求める代表的なアルゴリズムが\ :term:`ダイクストラ法`\ である [Dijkstra1959]_。

ダイクストラ法は、各頂点について「現時点で分かっている最短距離（暫定距離）」を持ち、まだ確定していない頂点のうち暫定距離が最小の頂点を確定させる。そして、確定した頂点から出る辺をたどって、隣接する頂点の暫定距離をより短くできれば更新する（緩和）。辺の重みが非負なので、暫定距離が最小の頂点には、他の未確定の頂点を経由してもより短く到達できない。これがこの貪欲な選択が正しい理由である。

暫定距離が最小の頂点を効率よく選ぶために、第 4 章で学んだ優先度付きキュー（``heapq``）を使う。

実行結果は次のとおりである。

.. code-block:: text
   :linenos:

   BFS の距離: {'A': 0, 'B': 1, 'C': 1, 'D': 2, 'E': 2, 'F': 2}
   DFS の訪問順: ['A', 'B', 'D', 'E', 'F', 'C']
   ダイクストラ法の距離: {'S': 0, 'A': 5, 'B': 2, 'C': 10, 'G': 6}
   S から G への最短経路: S -> B -> A -> G

BFS では、A から辺 1 本の B と C が距離 1、辺 2 本の D、E、F が距離 2 になっている。DFS では、B から D へ進み、行き止まりになったので B に戻って E、F、C と進んでいる。ダイクストラ法では、S から A へ直接行く辺（7）より、B を経由する経路（2 + 3 = 5）の方が短いことが見つかり、G への最短経路は S→B→A→G（距離 6）となった。

辺の重みに負の値があると、確定した頂点に後からより短く到達できる可能性があり、ダイクストラ法は正しい答えを返さない。その場合はベルマン・フォード法などの別のアルゴリズムを使う [CLRS]_。カーナビの経路探索や、ルータの経路表を自動で作る OSPF などのルーティングプロトコル（ルーティングは「:doc:`ch10_networks`」で扱う）では、ダイクストラ法やそれを改良したアルゴリズムが使われている。

まとめ
------

* アルゴリズムは問題を解くための明確で有限の手順であり、同じ問題でもアルゴリズムによって効率が大きく異なる。
* 計算量は基本的な操作の回数を入力の大きさ :math:`n` の関数として表したもので、O 記法で定数倍と低次の項を無視した増え方を表す。:math:`O` は上界、:math:`\Omega` は下界、:math:`\Theta` は上下両方からの評価である。
* 特に断らない限り計算量は最悪計算量を指す。平均計算量や償却計算量が実用上の性能をよく表す場合もある。
* ループの入れ子や、ループ内の ``in``、データベースへの問い合わせなど、隠れたループに注意すると、コードの計算量を見積もれる。
* 線形探索は :math:`O(n)`、整列済みの配列に対する二分探索は :math:`O(\log n)` である。Python では ``bisect`` を使う。
* 挿入ソートは最悪 :math:`O(n^2)` であるが、ほぼ整列済みのデータには速い。マージソートは常に :math:`O(n \log n)`、クイックソートは平均 :math:`O(n \log n)`、最悪 :math:`O(n^2)` である。比較ソートには :math:`\Omega(n \log n)` の下限がある。
* Python の ``sorted()`` は Timsort による安定ソートである。
* 分割統治法は問題を分割して再帰的に解き、計算量は漸化式で表せる。Python では再帰の深さに制限がある。
* 動的計画法は重なり合う部分問題の答えを記録して再利用する。フィボナッチ数のメモ化や最長共通部分列が典型例である。
* 貪欲法は各段階で最良に見える選択をする。単純で高速であるが、硬貨の問題のように最適解を出さない場合がある。
* 幅優先探索と深さ優先探索は :math:`O(V + E)` でグラフをたどる。重みの無いグラフの最短距離は幅優先探索で、重みが非負のグラフの最短距離はダイクストラ法で求める。
