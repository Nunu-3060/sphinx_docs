計算理論
========

この章では、「計算とは何か」「計算機に解ける問題と解けない問題の境界はどこにあるか」「解ける問題のうち、現実的な時間で解けるものはどれか」という問いを扱う。まず計算を数学的にモデル化する意義を述べ、最も単純なモデルである有限オートマトンと、それと同じ表現力を持つ正規表現を学ぶ。次に、より強力な文脈自由文法と、計算の最も一般的なモデルであるチューリングマシンを紹介する。後半では、どんなプログラムでも解けない問題（停止問題）が存在することを示し、最後に、解けるが効率よく解けるとは限らない問題を分類する計算複雑性理論（P、NP、NP 完全）を概観する。

本章の内容は、第 7 章「:doc:`ch07_programming_languages`」で扱う字句解析・構文解析の理論的な土台でもある。本章の内容をより厳密に学びたい場合は [Sipser]_ を参照するとよい。

計算をモデル化する意義
----------------------

第 5 章「:doc:`ch05_algorithms`」までは、アルゴリズムの効率を :math:`O(n \log n)` のような計算量で評価してきた。そこでは「1 回の比較は定数時間で行える」のような、暗黙の計算機の能力を前提にしていた。しかし、「どんなアルゴリズムを使っても解けない問題はあるか」という問いに答えるには、「アルゴリズム」や「計算」そのものを明確に定義する必要がある。特定のプログラミング言語や CPU を前提にすると、その言語や CPU の細かな仕様に議論が左右されてしまう。

そこで計算理論では、計算を行う機械を最小限の構成要素で数学的に定義した\ **計算モデル**\ を考える。モデルを単純にしておくと、その能力と限界を証明できる。そして、どのモデルで何ができるかが分かれば、その結論は現実の計算機にもそのまま当てはまる。

本章では、問題を「文字列がある性質を満たすかどうか」という形の\ **判定問題**\ （決定問題とも呼ぶ）として扱う。例えば「入力の 2 進数は 3 の倍数か」「入力の文字列は正しい Python プログラムか」「入力のグラフにすべての頂点を 1 度ずつ通る閉路があるか」は、いずれも Yes か No で答える判定問題である。入力に使える記号の有限集合を\ **アルファベット**\ と呼び、:math:`\Sigma` で表す。:math:`\Sigma` の記号を有限個並べたものが文字列であり、長さ 0 の文字列（空文字列）を :math:`\varepsilon` で表す。:math:`\Sigma` 上の文字列全体の集合を :math:`\Sigma^*` と書き、その部分集合を\ **言語**\ と呼ぶ。判定問題は「Yes と答えるべき文字列の集合」という言語と同一視できるので、「問題を解く」ことは「与えられた文字列がその言語に属するかを判定する」ことに言い換えられる。

有限オートマトン
----------------

.. _ch06-dfa:

決定性有限オートマトン
^^^^^^^^^^^^^^^^^^^^^^

:term:`有限オートマトン`\ は、有限個の状態を持ち、入力の文字列を先頭から 1 文字ずつ読みながら状態を移っていく機械である。メモリとしては「現在の状態」しか持たず、読んだ文字を書き留めたり、前に戻って読み直したりはできない。自動販売機や信号機、通信プロトコルの状態管理など、身近なシステムの多くは有限オートマトンとして記述できる。

現在の状態と入力文字から次の状態がただ 1 つに決まるものを\ :term:`決定性有限オートマトン`\ （DFA: Deterministic Finite Automaton）と呼ぶ。DFA は次の 5 つ組 :math:`M = (Q, \Sigma, \delta, q_0, F)` で定義される。

* :math:`Q`: 状態の有限集合
* :math:`\Sigma`: アルファベット（入力記号の有限集合）
* :math:`\delta: Q \times \Sigma \to Q`: 遷移関数。状態と入力記号の組に、次の状態を対応させる
* :math:`q_0 \in Q`: 開始状態
* :math:`F \subseteq Q`: 受理状態の集合

DFA は開始状態 :math:`q_0` から始めて、入力を 1 文字読むごとに :math:`\delta` に従って状態を移る。入力をすべて読み終えたときに受理状態（:math:`F` の要素）にいれば入力を\ **受理**\ し、そうでなければ\ **拒否**\ する。DFA :math:`M` が受理する文字列全体の集合を :math:`M` が認識する言語と呼び、:math:`L(M)` と書く。

例として、2 進数の文字列を上位の桁から読み、その値が 3 の倍数かどうかを判定する DFA を作る。ポイントは、それまでに読んだ数そのものではなく、それを 3 で割った余りだけを覚えておけば十分だという点である。それまでに読んだ数を :math:`n`、その余りを :math:`r = n \bmod 3` とすると、次のビット :math:`b` を読んだ後の数は :math:`2n + b` なので、新しい余りは :math:`(2r + b) \bmod 3` となり、:math:`r` と :math:`b` だけから計算できる。そこで状態を余りに対応させて :math:`Q = \{q_0, q_1, q_2\}` とし、:math:`\delta(q_r, b) = q_{(2r + b) \bmod 3}` と定める。余りが 0 の状態 :math:`q_0` が開始状態かつ唯一の受理状態である。この DFA の遷移関数を表にしたもの（\ **状態遷移表**\ ）を次に示す。

.. list-table::
   :header-rows: 1
   :widths: 30 25 25 20

   * - 状態（余り）
     - 入力 0
     - 入力 1
     - 備考
   * - :math:`q_0`\ （0）
     - :math:`q_0`
     - :math:`q_1`
     - 開始・受理
   * - :math:`q_1`\ （1）
     - :math:`q_2`
     - :math:`q_0`
     -
   * - :math:`q_2`\ （2）
     - :math:`q_1`
     - :math:`q_2`
     -

例えば入力 ``1001``\ （10 進数の 9）に対しては、:math:`q_0 \to q_1 \to q_2 \to q_1 \to q_0` と移り、受理状態 :math:`q_0` で終わるので受理する。どれほど長い 2 進数でも、状態は 3 つで足りる点に注目してほしい。

非決定性有限オートマトン
^^^^^^^^^^^^^^^^^^^^^^^^

DFA の制約を緩め、ある状態とある入力記号に対して遷移先が複数あってもよい（0 個でもよい）ものを\ :term:`非決定性有限オートマトン`\ （NFA: Nondeterministic Finite Automaton）と呼ぶ。NFA では、入力を読まずに状態を移る :math:`\varepsilon` 遷移も許す。遷移関数は状態の集合を返す関数 :math:`\delta: Q \times (\Sigma \cup \{\varepsilon\}) \to \mathcal{P}(Q)` となる。ここで :math:`\mathcal{P}(Q)` は :math:`Q` のべき集合（:math:`Q` の部分集合全体の集合）である。NFA は、選択肢のどれかをたどって入力を読み終えたときに受理状態にいられる道筋が 1 つでもあれば、入力を受理する。

NFA は「正しい選択肢を常に言い当てる」機械と考えることもできるし、「すべての選択肢を並行してたどる」機械と考えることもできる。後者の見方に立つと、NFA のシミュレーションは「現在いる可能性のある状態の集合」を 1 文字ごとに更新する処理になる。

NFA は DFA より強力に見えるが、認識できる言語のクラスは DFA と同じである。任意の NFA に対して、同じ言語を認識する DFA を構成できるからである。この構成法を\ **部分集合構成法**\ と呼び、「NFA の状態の集合」を DFA の 1 つの状態とみなす。NFA の状態数が :math:`k` なら、DFA の状態数は最大で :math:`2^k` になる。つまり、表現力は等しいが、同じ言語を表すのに必要な状態数は NFA の方が指数的に少なくて済む場合がある。例えば「後ろから 3 文字目が 1 である 2 進文字列」は、NFA なら 4 状態で表せるが、DFA では少なくとも 8 状態が必要である。

正規言語と正規表現
------------------

正規言語と正規表現の定義
^^^^^^^^^^^^^^^^^^^^^^^^

ある DFA（したがって NFA）で認識できる言語を\ :term:`正規言語`\ と呼ぶ。正規言語を文字列のパターンとして簡潔に書き表す記法が\ :term:`正規表現`\ である。理論上の正規表現は、次の規則だけで帰納的に定義される。

* :math:`\emptyset`\ （空集合）、:math:`\varepsilon`\ （空文字列）、および各記号 :math:`a \in \Sigma` は正規表現である。
* :math:`R` と :math:`S` が正規表現なら、和 :math:`R \mid S`\ （:math:`R` または :math:`S`）、連接 :math:`RS`\ （:math:`R` の後に :math:`S`）、\ **クリーネ閉包** :math:`R^*`\ （:math:`R` の 0 回以上の繰り返し）も正規表現である。

例えば :math:`(0 \mid 1)^* 1` は「1 で終わる 2 進文字列」を表す。実用の正規表現でよく使う ``a+``\ （1 回以上）、``a?``\ （0 回または 1 回）、``[0-9]``\ （文字クラス）、``a{2,4}``\ （回数指定）は、いずれも上の 3 つの演算の組み合わせに書き換えられる糖衣構文である。例えば ``a+`` は :math:`aa^*` と同じである。

正規表現と有限オートマトンは、表現できる言語のクラスがちょうど一致する。すなわち、任意の正規表現から同じ言語を認識する NFA を機械的に構成でき（トンプソンの構成法が有名である）、逆に任意の有限オートマトンから同じ言語を表す正規表現を構成できる。この事実はクリーネの定理と呼ばれる。正規表現エンジンや字句解析器の生成ツールは、この対応を利用して「正規表現 → NFA → DFA」と変換し、文字列を高速に照合する。先ほどの「3 の倍数である 2 進数」も正規言語なので、正規表現で書ける（ただし、その正規表現は DFA よりかなり読みにくい）。

正規言語で表せないもの
^^^^^^^^^^^^^^^^^^^^^^

有限オートマトンの記憶は「有限個の状態のどれにいるか」だけなので、無制限に数を数えることはできない。典型的な例が、:math:`0` を :math:`n` 個並べた後に :math:`1` を :math:`n` 個並べた文字列の集合 :math:`\{ 0^n 1^n \mid n \ge 0 \}` である。この言語を判定するには、読んだ 0 の個数を覚えておく必要があるが、個数には上限がないので、有限個の状態では足りない。同じ理由で、「括弧の対応が取れている文字列」（例: ``(()())`` は正しく、``(()`` は正しくない）も正規言語ではない。開き括弧が何重にも入れ子になると、その深さを覚えておく必要があるからである。

この直観を厳密にしたものが、正規言語に対する\ :term:`ポンピング補題`\ である。概要だけを述べると、「任意の正規言語 :math:`L` には定数 :math:`p` が存在し、長さ :math:`p` 以上の :math:`L` の任意の文字列は、先頭から :math:`p` 文字以内にある空でない部分 :math:`y` を何回繰り返しても（0 回に減らしても）\ :math:`L` に属する」という性質である。状態数 :math:`p` の DFA が長さ :math:`p` 以上の文字列を読むと、鳩の巣原理により同じ状態を 2 度通るので、その間のループ部分を何度回っても結果が変わらない、というのが直観的な理由である。:math:`\{ 0^n 1^n \mid n \ge 0 \}` に属する :math:`0^p 1^p` では、先頭 :math:`p` 文字以内の部分 :math:`y` は 0 だけからなるので、:math:`y` を繰り返すと 0 と 1 の個数がずれて言語から外れる。したがってこの言語は正規言語ではない。

.. _ch06-practical-regex:

理論上の正規表現と実用の正規表現エンジン
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Python の ``re`` モジュールをはじめ、プログラミング言語に組み込まれている正規表現は、理論上の正規表現を拡張したものであり、両者は同じではない。代表的な拡張が\ :term:`後方参照`\ である。後方参照 ``\1`` は「1 番目のグループにマッチしたのと同じ文字列」を表す。次の例は、同じ単語が空白を挟んで 2 回続く箇所を探す。

.. code-block:: python
   :linenos:

   import re

   pattern = re.compile(r"\b(\w+) \1\b")
   print(pattern.search("this is is a pen"))
   print(pattern.search("this is a pen"))

.. code-block:: text
   :linenos:

   <re.Match object; span=(5, 10), match='is is'>
   None

後方参照を使うと、「ある文字列を 2 回繰り返した文字列」の集合 :math:`\{ ww \mid w \in \Sigma^* \}` のような、正規言語ではない（後述の文脈自由言語でもない）言語も表せる。表現力が上がる代わりに、後方参照を含むパターンとの照合は一般には効率よく行えないことが知られており、有限オートマトンによる線形時間の照合はできなくなる。

実用の正規表現エンジンは、実装方式によって大きく 2 種類に分かれる。

.. list-table::
   :header-rows: 1
   :widths: 20 40 40

   * - 方式
     - バックトラック型
     - オートマトン型
   * - 動作
     - パターンを先頭から試し、失敗したら直前の選択肢に戻って別の選択肢を試す
     - パターンを NFA または DFA に変換し、入力を 1 回走査する
   * - 最悪の照合時間
     - 入力長に対して指数時間になりうる
     - 入力長に対して線形時間
   * - 後方参照
     - 使える
     - 使えない（理論上の正規表現の範囲に限られる）
   * - 例
     - Python の ``re``、Perl、Java、JavaScript
     - Go の ``regexp``、RE2、Rust の ``regex``

.. warning::

   バックトラック型のエンジンでは、パターンと入力の組み合わせによって照合時間が入力長に対して指数的に増えることがある。これを悪用して、細工した入力でサーバの CPU を占有させる攻撃を :term:`ReDoS`\ （Regular expression Denial of Service）と呼ぶ。典型的な危険なパターンは ``^(a+)+$`` のように、繰り返しの中に繰り返しがあり、同じ文字列を複数の分け方でマッチできるものである。入力 ``aaaa...ab`` に対して、エンジンは最後の ``b`` で失敗するたびに ``a`` の並びの分け方をすべて試すので、``a`` が 1 個増えるごとに照合時間がおよそ 2 倍になる。筆者の環境で ``a`` の個数を 16、18、20、22 と増やしたところ、照合時間は約 0.008 秒、0.026 秒、0.085 秒、0.305 秒と増えた（時間は環境によって異なる）。``a`` が 40 個あれば、照合は事実上終わらない。対策としては、入れ子の量指定子や重なり合う選択肢を避けること、外部から受け取る入力の長さを制限すること、Python 3.11 以降で使えるアトミックグループ ``(?>...)`` や強欲な量指定子 ``a++`` でバックトラックを抑えること、信頼できない入力にはオートマトン型のエンジンを使うことなどがある。

文脈自由文法
------------

文法による言語の定義
^^^^^^^^^^^^^^^^^^^^

括弧の対応のような入れ子構造は、プログラミング言語の至るところに現れる。式の中の括弧、ブロックの中のブロック、関数呼び出しの引数の中の関数呼び出しなどである。こうした構造を表すために使われるのが\ :term:`文脈自由文法`\ （CFG: Context-Free Grammar）である。

文脈自由文法は、:math:`A \to \alpha` という形の\ **生成規則**\ の集まりで言語を定義する。:math:`A` は\ **非終端記号**\ （構文上の概念を表す変数）、:math:`\alpha` は非終端記号と\ **終端記号**\ （アルファベットの記号）の列である。開始記号から始めて、非終端記号を生成規則の右辺で置き換えることを繰り返し、終端記号だけの列が得られたら、その列は文法が生成する言語に属する。左辺が非終端記号 1 つだけで、その記号の前後（文脈）に関係なく置き換えられることが「文脈自由」の名の由来である。

プログラミング言語の文法を記述するには、:term:`BNF`\ （Backus-Naur Form、バッカス・ナウア記法）がよく使われる。BNF では非終端記号を ``<...>`` で囲み、``::=`` を「は次のように定義される」、``|`` を「または」の意味で用いる。括弧の対応が取れた文字列の言語は、次の BNF で定義できる。

.. code-block:: text
   :linenos:

   <balanced> ::= "" | "(" <balanced> ")" <balanced>

1 行目は「対応の取れた括弧列は、空であるか、または『開き括弧、対応の取れた括弧列、閉じ括弧、対応の取れた括弧列』を順に並べたものである」と読む。例えば ``(())()`` は、外側の ``(`` と ``)`` の間に ``()`` が入り、その後ろに ``()`` が続いた形として生成できる。右辺に左辺と同じ非終端記号が現れる、つまり定義が再帰的であることが、入れ子を表現できる理由である。同様に、:math:`\{ 0^n 1^n \mid n \ge 0 \}` は ``<s> ::= "" | "0" <s> "1"`` という 1 つの規則で表せる。このように、正規言語でない言語も文脈自由文法では表せる。実用的な文法記述では、BNF に繰り返し ``{ ... }`` や省略可能 ``[ ... ]`` を加えた拡張 BNF（EBNF）もよく使われる。第 7 章「:doc:`ch07_programming_languages`」では、EBNF で書いた四則演算の文法から構文解析器を作る。

文脈自由文法で生成できる言語を\ **文脈自由言語**\ と呼ぶ。正規言語はすべて文脈自由言語であるが、逆は成り立たない。文脈自由言語は、有限オートマトンにスタックを 1 本追加した\ **プッシュダウンオートマトン**\ で認識できる言語のクラスと一致する。括弧の対応を調べるとき、開き括弧をスタックに積み、閉じ括弧で取り出すという方法を思い浮かべれば、スタックが入れ子の深さを記憶する役割を果たすことが分かるだろう。

文脈自由文法にも限界がある。例えば :math:`\{ a^n b^n c^n \mid n \ge 0 \}` は文脈自由言語ではない。これは文脈自由言語に対するポンピング補題（正規言語の場合と同様に、十分長い文字列の一部を繰り返しても言語に属するという性質。ただし繰り返す部分が 2 か所になる）を使って示せる。プログラミング言語でも、「変数は使う前に宣言されていなければならない」のような規則は文脈自由文法では表せないので、構文解析の後の意味解析で検査する。

チョムスキー階層
^^^^^^^^^^^^^^^^

言語学者のチョムスキーは、文法を生成規則の形の制限によって 4 つの型に分類した。これを\ **チョムスキー階層**\ と呼ぶ。型の番号が大きいほど生成規則の制限が強く、表せる言語のクラスは小さい。

チューリングマシン
------------------

チューリングマシンの定義
^^^^^^^^^^^^^^^^^^^^^^^^

:term:`チューリングマシン`\ は、1936 年にチューリングが「機械的な手順で計算する」ことを定式化するために考案した計算モデルである [Turing1936]_。有限オートマトンとの違いは、読み書きできる無限に長い\ **テープ**\ を記憶として持ち、テープ上を左右に移動できる点である。

チューリングマシンは、マス目に区切られた両方向（または片方向）に無限に長いテープ、テープの 1 マスを読み書きする\ **ヘッド**\ 、有限個の状態を持つ制御部からなる。テープの最初には入力文字列が書かれており、それ以外のマスは空白記号 ␣ で埋められている。各ステップで、マシンは現在の状態とヘッドの位置の記号に応じて、（1）そのマスに記号を書き、（2）ヘッドを左右どちらかに 1 マス動かし、（3）次の状態に移る。形式的には、遷移関数は次のように書ける。

.. math::

   \delta: Q \times \Gamma \to Q \times \Gamma \times \{L, R\}

ここで :math:`Q` は状態の有限集合、:math:`\Gamma` はテープに書ける記号の有限集合（入力のアルファベット :math:`\Sigma` と空白記号を含む）、:math:`L` と :math:`R` はヘッドの移動方向（左と右）である。これに開始状態と停止状態（受理状態と拒否状態）を加えたものがチューリングマシンの定義である。マシンは停止状態に入ると止まるが、入力によっては永久に止まらないこともある。この「止まらないことがある」という性質が、後で述べる停止問題につながる。

チューリングマシンは、判定問題を解く（受理か拒否で止まる）だけでなく、停止したときのテープの内容を出力とみなせば、関数を計算する機械として使うこともできる。

チャーチ＝チューリングのテーゼ
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

チューリングマシンは非常に単純だが、驚くほど強力である。テープを複数本にしても、非決定性を加えても、認識できる言語のクラスは変わらない（時間効率は変わりうる）。また、チャーチのラムダ計算や帰納的関数など、同時期に独立に提案されたまったく異なる計算モデルも、チューリングマシンと同じ関数を計算できることが証明されている。

こうした事実から、「直観的な意味で機械的な手順により計算できる関数は、チューリングマシンで計算できる関数とちょうど一致する」という主張が広く受け入れられている。これを\ :term:`チャーチ＝チューリングのテーゼ`\ と呼ぶ。「直観的に計算できる」は数学的に定義された概念ではないので、このテーゼは証明できる定理ではなく、計算という概念の定義に関する主張である。しかし、これまでに考案されたどの計算モデルもチューリングマシンを超える計算能力を持たなかったことが、テーゼの強い根拠となっている。

現実のプログラミング言語の多くは、メモリが無制限にあると仮定すれば、チューリングマシンと同じ計算能力を持つ。この性質を\ **チューリング完全**\ と呼ぶ。Python、C、Java はもちろん、条件分岐と繰り返し（または再帰）があれば、ほとんどの言語がチューリング完全になる。したがって、「チューリングマシンでは解けない」ことが示された問題は、どんなプログラミング言語でも、どんなに高速な計算機でも解けない。また、他のチューリングマシンの記述と入力をテープから読み取り、その動作をシミュレートするチューリングマシンを作れる。これを\ **万能チューリングマシン**\ と呼ぶ。プログラムをデータとしてメモリに格納して実行するという、プログラム内蔵方式の計算機（第 3 章「:doc:`ch03_computer_architecture`」を参照）の理論的な原型である。

計算可能性と停止問題
--------------------

判定可能な問題と判定不能な問題
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

ある判定問題に対して、どんな入力に対しても必ず停止し、正しく Yes か No を答えるチューリングマシンが存在するとき、その問題は\ **判定可能**\ （決定可能）であるという。そのようなチューリングマシンが存在しない問題は\ :term:`判定不能`\ （決定不能）である。ここで重要なのは「どんな入力に対しても必ず停止する」という条件である。答えが Yes の入力に対してはいずれ Yes と答えるが、答えが No の入力に対しては止まらないことがある、というチューリングマシンしか作れない問題もある。

ここで「判定不能」とは、「まだ効率のよいアルゴリズムが見つかっていない」という意味ではない。どれほど時間をかけても、どれほど賢いプログラムを書いても、すべての入力に正しく答えるプログラムは原理的に存在しない、という意味である。

.. _ch06-halting-problem:

停止問題
^^^^^^^^

判定不能な問題の代表例が\ :term:`停止問題`\ である。停止問題とは、「プログラム :math:`P` と入力 :math:`x` が与えられたとき、:math:`P` に :math:`x` を与えて実行すると、いずれ停止するか」を判定する問題である。チューリングは、この問題を正しく判定するプログラムは存在しないことを証明した [Turing1936]_。

証明の概要を、Python 風の擬似コードで説明する。仮に、停止問題を判定する関数 ``halts(p, x)`` が存在したとする。``halts`` は、プログラムのソースコード ``p`` と入力 ``x`` を受け取り、``p`` が ``x`` に対して停止するなら ``True``\ 、停止しないなら ``False`` を、必ず有限時間で返すものとする。この ``halts`` を使って、次の関数 ``paradox`` を作る。

.. code-block:: python
   :linenos:

   def paradox(p):
       if halts(p, p):   # p に自分自身のソースコードを与えると停止するなら
           while True:   # 永久に止まらない
               pass
       else:             # 停止しないなら
           return        # すぐに停止する

``paradox`` はプログラム ``p`` を受け取り、「``p`` に ``p`` 自身を入力として与えたときの振る舞い」と逆のことをする。では、``paradox`` に ``paradox`` 自身のソースコードを与えると、どうなるだろうか。

* ``paradox(paradox)`` が停止すると仮定する。このとき ``halts(paradox, paradox)`` は ``True`` を返すので、2〜4 行目により ``paradox(paradox)`` は永久に止まらない。これは仮定に反する。
* ``paradox(paradox)`` が停止しないと仮定する。このとき ``halts(paradox, paradox)`` は ``False`` を返すので、5〜6 行目により ``paradox(paradox)`` はすぐに停止する。これも仮定に反する。

どちらの場合も矛盾が生じる。``paradox`` は ``halts`` さえあれば素直に書けるプログラムなので、矛盾の原因は「``halts`` が存在する」という最初の仮定にある。したがって、停止問題を正しく判定するプログラムは存在しない。

この証明は\ :term:`対角線論法`\ と呼ばれる手法に基づいている。すべてのプログラムを縦に、すべての入力を横に並べ、プログラム :math:`P_i` に入力 :math:`P_j` を与えたときに停止するかどうかを表に書き込んだとする。``paradox`` は、この表の対角線上（:math:`P_i` に :math:`P_i` 自身を与える場合）の結果をすべて反転させたプログラムなので、表のどの行とも少なくとも 1 か所（対角線上）で振る舞いが異なる。つまり ``paradox`` は表のどの行にも現れないが、表にはすべてのプログラムが並んでいるはずなので矛盾する。これは、実数全体が自然数と 1 対 1 に対応させられないこと（実数が非可算であること）を示したカントールの議論と同じ構造である。

.. note::

   停止問題が判定不能だからといって、個々のプログラムの停止性が分からないわけではない。``while True: pass`` は止まらないし、``for`` 文で ``range(10)`` を回すだけのプログラムは止まる。判定不能とは、「すべてのプログラムと入力の組に対して、常に正しく答える 1 つのアルゴリズム」が存在しないという意味である。また、停止するプログラムについては、実際に実行してみれば停止することは確認できる。確認できないのは、停止しない場合に「停止しない」と有限時間で言い切ることである。

.. _ch06-undecidability-practice:

実務への影響
^^^^^^^^^^^^

停止問題の判定不能性からは、多くの問題の判定不能性が導かれる。ある問題を解くプログラムがあれば停止問題も解けてしまう、ということを示せば（このような問題の変換を\ **帰着**\ と呼ぶ）、その問題も判定不能だと分かる。さらに一般に、ライスの定理は「プログラムの入出力の振る舞いに関する自明でない性質は、すべて判定不能である」ことを示している。例えば「このプログラムはどんな入力に対しても例外を起こさないか」「この 2 つの関数は常に同じ値を返すか」「このプログラムはウイルスか」は、いずれも完全には判定できない。

これは、静的解析ツール、型検査器、コンパイラの最適化器が、原理的に「完全」にはなれないことを意味する。実際のツールは、誤検出を許して安全側に倒す（問題のないコードにも警告を出す）か、見逃しを許して実用性を取る（一部の問題を検出しない）かのどちらかの妥協をしている。mypy のような型検査器が、実行すれば問題なく動くコードを拒否することがあるのも、この妥協の現れである。

計算複雑性
----------

判定可能な問題であっても、解くのに天文学的な時間がかかるなら実用上は解けないのと同じである。\ :term:`計算複雑性理論`\ は、判定可能な問題を、解くのに必要な時間や記憶領域の量によって分類する理論である。ここでは時間に注目する。入力の長さを :math:`n` としたとき、:math:`n^2` や :math:`n^3` のような多項式で抑えられる時間を「効率がよい」とみなし、:math:`2^n` や :math:`n!` のように多項式で抑えられない時間を「効率が悪い」とみなすのが基本的な考え方である。

クラス P
^^^^^^^^

ある定数 :math:`k` について、決定性チューリングマシンが :math:`O(n^k)` 時間で解ける判定問題全体の集合を\ :term:`クラス P`\ （P は Polynomial、多項式の頭文字）と呼ぶ。チューリングマシンと現実の計算機（をモデル化したもの）は、互いに相手を多項式時間の増加だけでシミュレートできるので、P はどちらのモデルで定義しても同じクラスになる。整列、最短経路、最大流、素数判定（2002 年に多項式時間アルゴリズムが発見された）などは P に属する。

クラス NP
^^^^^^^^^

:term:`クラス NP` の NP は Nondeterministic Polynomial（非決定性多項式時間）の略であり、「非決定性チューリングマシンが多項式時間で解ける判定問題」全体の集合である。非決定性チューリングマシンは、NFA と同様に各ステップで複数の選択肢を持てるチューリングマシンで、どれかの選択の列で受理に至れば受理する。

NP には、これと等価で分かりやすい特徴付けがある。NP は「答えが Yes であることの証拠（\ **証明書**\ ）が与えられれば、それが正しいことを多項式時間で検証できる」判定問題全体の集合である。非決定性チューリングマシンの「正しい選択の列」が、そのまま証明書に相当する。例えば次の問題は NP に属する。

* **充足可能性問題**\ （SAT）: 論理式 :math:`(x_1 \lor \lnot x_2) \land (x_2 \lor x_3)` のような式が与えられたとき、式全体を真にする変数への真偽値の割り当てが存在するか。証明書は割り当てそのもので、式に代入すれば多項式時間で検証できる。
* **ハミルトン閉路問題**: グラフのすべての頂点をちょうど 1 度ずつ通って元に戻る閉路が存在するか。証明書は頂点の並びである。
* **巡回セールスマン問題の判定版**: すべての都市を 1 度ずつ回って戻る経路で、総距離が :math:`K` 以下のものが存在するか。

P に属する問題は、証明書を使わずに多項式時間で解けるので、明らかに NP にも属する。つまり :math:`\mathrm{P} \subseteq \mathrm{NP}` である。

.. warning::

   NP は「多項式時間で解けない問題」という意味ではない。NP は P を含むので、整列や最短経路のような簡単な問題も NP に属する。NP は「Yes の答えを多項式時間で検証できる」という上限側の性質であり、問題が難しいことを意味しない。問題が難しいことを表すのは、次に述べる NP 困難や NP 完全という概念である。

NP 完全
^^^^^^^

問題 :math:`A` の任意の入力を、問題 :math:`B` の入力に多項式時間で変換でき、変換前後で答えが一致するとき、:math:`A` は :math:`B` に多項式時間帰着できるという。このとき、:math:`B` が多項式時間で解ければ :math:`A` も多項式時間で解けるので、:math:`B` は :math:`A` 以上に難しいと言える。

NP に属するすべての問題が多項式時間帰着できる問題を :term:`NP 困難`\ と呼び、NP 困難でありかつ NP に属する問題を :term:`NP 完全`\ と呼ぶ。NP 完全問題は、NP の中で最も難しい問題たちである。1971 年にクックが（独立にレビンも）SAT が NP 完全であることを証明し、その後、ハミルトン閉路問題、巡回セールスマン問題の判定版、グラフの彩色問題、ナップサック問題の判定版、スケジューリングの多くの問題など、実務に現れる数千もの問題が NP 完全であることが示されている。最適化問題としての巡回セールスマン問題（最短の経路を求める）は、答えが Yes/No ではないので NP には属さないが、NP 困難である。

NP 完全問題には、「どれか 1 つでも多項式時間で解ければ、NP のすべての問題が多項式時間で解ける（:math:`\mathrm{P} = \mathrm{NP}` となる）」という重要な性質がある。

P≠NP 予想
^^^^^^^^^

:math:`\mathrm{P} = \mathrm{NP}` か :math:`\mathrm{P} \neq \mathrm{NP}` かは、計算機科学における最大の未解決問題である。多くの研究者は :math:`\mathrm{P} \neq \mathrm{NP}`\ 、つまり「解を検証するのは易しいが、解を見つけるのは本質的に難しい」問題が存在すると予想している。これを P≠NP 予想と呼ぶ。数十年にわたって多くの研究者が NP 完全問題の多項式時間アルゴリズムを探してきたが見つかっていないことが、この予想の状況証拠となっている。しかし、証明はまだない。

.. note::

   暗号の安全性は、素因数分解や離散対数問題が効率よく解けないという仮定に依存している（第 13 章「:doc:`ch13_security`」を参照）。これらの問題は NP に属するが、NP 完全であるとは知られていない。したがって、P≠NP が証明されても、これらの問題が難しいことは直ちには導かれない。逆に、もし P = NP であれば、これらの問題も多項式時間で解けることになる。

実務での意味
^^^^^^^^^^^^

業務で扱う問題が NP 完全（または NP 困難）だと分かったら、どうすればよいか。まず認識すべきなのは、入力の規模が大きくなったときにすべての入力に対して最適解を効率よく求めるアルゴリズムは、（P≠NP 予想が正しければ）存在しないということである。厳密解を求める汎用的なアルゴリズムを探し続けるのは、多くの場合時間の無駄である。そのうえで、次のような現実的な方針を取る。

* **入力が小さい場合は厳密に解く**: 指数時間のアルゴリズムでも、:math:`n` が数十程度なら実用的なことがある。動的計画法や分枝限定法で、総当たりより大幅に速くできることも多い。
* **問題を制限する**: 一般のグラフでは NP 完全な問題でも、木や平面グラフに限れば多項式時間で解けることがある。実際の入力が持つ特別な構造を利用できないか検討する。
* **近似アルゴリズムを使う**: 最適解は諦めるが、最適解からのずれに保証がある解を多項式時間で求める。例えば、グラフの全辺を覆う最小の頂点集合を求める頂点被覆問題には、最適解の 2 倍以内のサイズの解を求める単純なアルゴリズムがある。
* **ヒューリスティックを使う**: 品質の保証はないが、経験的によい解を速く求める手法である。貪欲法、局所探索、焼きなまし法、遺伝的アルゴリズムなどがある。
* **専用のソルバを使う**: SAT ソルバや整数計画ソルバは、最悪の場合は指数時間だが、実務に現れる多くの入力を高速に解けるよう高度に工夫されている。問題をこれらのソルバの入力形式に帰着させるのは有力な選択肢である。

NP 完全性は最悪の場合の計算量に関する性質であり、実際に現れる入力が常に難しいわけではない。一方で、入力の規模がある程度を超えると急に解けなくなる、という形で問題が表面化しやすい。設計の早い段階で問題の計算複雑性を見積もっておくことが重要である。

.. note::

   ナップサック問題（の判定版）は NP 完全であるが、品物の数を :math:`n`\ 、容量を :math:`W` とすると、動的計画法により :math:`O(nW)` 時間で解ける。これは多項式時間のように見えるが、:math:`W` は入力中で約 :math:`\log W` ビットで表されるので、:math:`W` は入力の長さに対して指数的に大きくなりうる。このように、入力中の数値の大きさについての多項式時間を\ **擬多項式時間**\ と呼ぶ。容量が小さい実務の問題では、このアルゴリズムで十分に速く解けることが多い。

まとめ
------

* 計算理論では、計算を単純な数学的モデルで定義することで、何が計算できて何が計算できないかを証明する。問題は「文字列がある言語に属するか」という判定問題として扱う。
* 決定性有限オートマトン（DFA）は、有限個の状態だけを記憶として入力を 1 文字ずつ読む機械である。非決定性有限オートマトン（NFA）は DFA と同じ言語のクラスを認識する。
* DFA で認識できる言語が正規言語であり、正規表現と表現力が一致する。括弧の対応のように、無制限に数を数える必要がある言語は正規言語ではない。
* 実用の正規表現エンジンは後方参照などで理論上の正規表現を拡張している。バックトラック型のエンジンでは ReDoS に注意する。
* 文脈自由文法は入れ子構造を表せる文法であり、BNF で記述する。プログラミング言語の構文の記述に使われる。
* チューリングマシンは計算の最も一般的なモデルである。チャーチ＝チューリングのテーゼにより、機械的に計算できることはチューリングマシンで計算できることと同一視される。
* 停止問題は判定不能であり、対角線論法で証明される。この結果から、プログラムの振る舞いを完全に判定する静的解析は不可能であることが分かる。
* P は多項式時間で解ける問題、NP は Yes の答えを多項式時間で検証できる問題のクラスである。NP 完全問題は NP の中で最も難しい問題であり、P≠NP 予想は未解決である。実務で NP 完全問題に出会ったら、近似アルゴリズム、ヒューリスティック、専用のソルバなどを検討する。
