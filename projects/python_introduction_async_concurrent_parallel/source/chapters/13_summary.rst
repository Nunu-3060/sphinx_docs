第 13 章 まとめ
===============

本書では、Python による非同期処理・並行処理・並列処理について、手法を選ぶための考え方と実装方法を説明してきた。この章では、判断のためのチェックリストと各手法の要点をまとめる。

判断のチェックリスト
--------------------

並行処理や並列処理の導入を検討するときは、次の項目を順に確認する。

1. 遅い原因を計測で確認したか。推測で判断していないか。
2. アルゴリズムの改善、I/O の削減、最適化されたライブラリの利用で解決できないか。
3. 時間の大半は CPU の計算か、I/O の待ち時間か。
4. CPU の計算なら、計算を独立した塊に分けられるか。塊ごとの計算時間は、プロセス間の受け渡しの時間より十分に大きいか。
5. I/O の待ち時間なら、同時に扱う数はどのくらいか。使うライブラリは非同期に対応しているか。
6. 接続先に負荷をかけすぎないよう、同時実行数を制限しているか。
7. 待ち続ける可能性のある処理に、タイムアウトを設定しているか。
8. 一部のタスクが失敗したとき、全体をどうするか（中止するか、続行するか）を決めているか。
9. スレッド間で共有するデータを、ロックや ``Queue`` で保護しているか。
10. 並列化の前後で結果が一致することを確認したか。並列化によって実際に速くなったことを計測で確認したか。

各手法の要点
------------

.. list-table:: 各手法の要点
   :header-rows: 1
   :widths: 18 82

   * - 手法
     - 要点
   * - スレッド
     - I/O バウンドな処理に使う。同期的なライブラリをそのまま使える。GIL のため、Python で書かれた CPU バウンドな処理は速くならない。共有データにはロックが必要であり、データの受け渡しには ``Queue`` を使う。
   * - プロセス
     - CPU バウンドな処理に使う。``ProcessPoolExecutor`` で並列に実行できる。関数と引数は pickle できる必要がある。起動と受け渡しの負荷があるため、タスクを十分に大きな塊にまとめる。``if __name__ == "__main__":`` を忘れない。
   * - concurrent.futures
     - スレッドとプロセスを同じ書き方で扱える。``submit()`` と ``as_completed()`` で完了した順に結果を処理でき、例外は ``Future.result()`` で受け取る。
   * - asyncio
     - 多数の I/O を 1 つのスレッドで並行に扱う。タスクが切り替わるのは ``await`` の箇所だけである。Python 3.11 以降では ``TaskGroup`` と ``asyncio.timeout()`` を使う。ブロッキングする処理は ``asyncio.to_thread()`` や ``run_in_executor()`` で別のスレッドやプロセスに任せる。
   * - free-threaded ビルド、サブインタプリタ
     - プロセスを使わずに CPU バウンドな処理を並列に実行する新しい手段である。ライブラリの対応状況を確認したうえで検討する。

さらに学ぶために
----------------

本書で扱わなかった話題のうち、次の段階として学ぶとよいものを挙げる。

* **非同期に対応したライブラリ**：HTTP クライアントの ``aiohttp`` や ``httpx``、Web フレームワークの FastAPI など、``asyncio`` を前提としたライブラリの使い方
* **分散処理**：1 台の計算機に収まらない処理を、複数の計算機で実行する方法（ジョブキュー、分散処理のフレームワークなど）
* **NumPy などによる高速化**：計算そのものを C 言語で実装されたライブラリに任せる方法。並列化と組み合わせることもできる
* **free-threaded ビルドとサブインタプリタの動向**：今後のバージョンで、対応するライブラリや機能が増えていくと考えられる

いずれの場合も、本書で説明した「処理の時間は何に使われているか」を見極めることが出発点になる。
