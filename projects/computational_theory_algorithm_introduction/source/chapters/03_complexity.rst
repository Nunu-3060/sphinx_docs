第 3 章 アルゴリズムと計算量
============================

**アルゴリズム**\ とは、問題を解くための手順を、曖昧さなく有限の長さで記述したものである。同じ問題を解くアルゴリズムが複数あるとき、それらを比べる物差しが必要になる。本章では、アルゴリズムの効率を\ **計算量**\ として測る方法を説明する。

計算モデル
----------

実行時間を秒で測ると、計算機の性能やプログラミング言語、実装の細部によって結果が変わってしまう。そこでアルゴリズムの解析では、抽象化した計算機（\ **計算モデル**\ ）を考え、その上での基本操作の回数を数える。

本書の第 2 部では、次のような **RAM モデル**\ （Random Access Machine）を用いる。

* メモリは番号付きのセルの列であり、どのセルにも一定時間で読み書きできる。
* 四則演算、比較、代入、配列の添字によるアクセス、関数呼び出しといった基本操作は、それぞれ一定時間（1 ステップ）で実行できる。
* 1 つのセルに入る整数の大きさは、入力サイズ :math:`n` に対して :math:`O(\log n)` ビット程度とする。

最後の仮定は、巨大な整数の演算を 1 ステップで行うという非現実的な状況を避けるためのものである。Python の ``int`` は任意の大きさの整数を扱えるが、桁数が大きくなるとその演算は一定時間では終わらない。

第 3 部では、より単純な計算モデルであるチューリング機械を扱う。RAM モデルとチューリング機械の実行時間は多項式の範囲で互いに変換できることが知られており、第 11 章で扱う「多項式時間で解けるか」という区別はどちらのモデルで考えても変わらない。

時間計算量と空間計算量
----------------------

入力サイズ :math:`n` の入力に対してアルゴリズムが実行する基本操作の回数を、\ :math:`n` の関数として表したものを\ **時間計算量**\ と呼ぶ。同様に、使用するメモリの量を\ **空間計算量**\ と呼ぶ。入力サイズは問題に応じて決める。例えば整列ならリストの要素数、グラフの問題なら頂点数 :math:`V` と辺の数 :math:`E` を使う。

例として、リストの最大値を求める関数を考える。

.. code-block:: python
   :linenos:

   def maximum(values: list[int]) -> int:
       best = values[0]
       for v in values[1:]:
           if v > best:
               best = v
       return best

2 行目は 1 回、3 行目から 5 行目は :math:`n - 1` 回繰り返され、各回の操作数は定数で抑えられる。したがって時間計算量は :math:`\Theta(n)` である。3 行目の ``values[1:]`` は長さ :math:`n - 1` のリストのコピーを作るため、空間計算量は :math:`\Theta(n)` になる。添字でループすれば追加の領域は :math:`O(1)` で済む。このように、Python では 1 行に見える処理が一定時間で終わるとは限らない点に注意が必要である（後述の表を参照）。

最悪計算量・平均計算量・償却計算量
----------------------------------

同じ入力サイズでも、入力の内容によって実行時間が変わることがある。例えばリストを先頭から調べて値を探す線形探索は、目的の値が先頭にあれば 1 回の比較で終わるが、存在しなければ :math:`n` 回の比較が必要になる。そこで計算量は次のように区別して述べる。

.. list-table:: 計算量の種類
   :header-rows: 1
   :widths: 20 80

   * - 種類
     - 意味
   * - 最悪計算量
     - サイズ :math:`n` の全ての入力の中で、最も時間がかかる場合の計算量。単に「計算量」と言えば通常はこれを指す。
   * - 平均計算量
     - 入力が何らかの確率分布に従うと仮定したときの、計算量の期待値。
   * - 償却計算量
     - 一連の操作の合計時間を操作の回数で割った、1 操作あたりの計算量。ときどき重い操作が起きても、それが全体に占める割合が小さければ償却計算量は小さくなる。

最悪計算量は、どんな入力に対しても性能を保証できる点で最も重要である。平均計算量は、入力の分布についての仮定が現実に合っているかどうかに依存する。乱択アルゴリズム（第 5 章、第 12 章）では、入力ではなくアルゴリズム自身が使う乱数について期待値をとった\ **期待計算量**\ を考える。

償却計算量の例：Python のリストの append
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Python の ``list`` は、内部に確保した配列が一杯になると、より大きな配列を確保して要素を全てコピーする。コピーには :math:`O(n)` 時間がかかるが、配列の容量を毎回定数倍（例えば 2 倍）に増やしておけば、コピーが起きる頻度は次第に下がる。容量を 2 倍ずつ増やす場合、\ :math:`n` 回の ``append`` で行われるコピーの総数は高々

.. math::

   1 + 2 + 4 + \cdots + 2^{\lfloor \log n \rfloor} < 2n

である（第 2 章の等比級数の性質）。したがって :math:`n` 回の ``append`` の合計は :math:`O(n)` 時間であり、1 回あたりの償却計算量は :math:`O(1)` となる。なお、CPython の実際の増加率は約 1.125 倍だが、定数倍で増やす限り同じ結論が得られる。

漸化式とマスター定理
--------------------

再帰的なアルゴリズムの計算量は、\ **漸化式**\ で表すと見通しがよくなる。例えば、サイズ :math:`n` の問題をサイズ :math:`n/2` の部分問題 2 つに分け、結果を :math:`O(n)` 時間で統合するアルゴリズム（第 5 章のマージソートなど）の計算量 :math:`T(n)` は次の式を満たす。

.. math::

   T(n) = 2T(n/2) + cn, \quad T(1) = c

この式を展開すると、再帰の各段で合計 :math:`cn` の仕事があり、段数は :math:`\log n` なので、\ :math:`T(n) = cn \log n + cn = \Theta(n \log n)` となる。

より一般に、次の形の漸化式には\ **マスター定理**\ が使える。

.. math::

   T(n) = a T(n/b) + f(n) \quad (a \ge 1,\ b > 1)

これは、サイズ :math:`n` の問題をサイズ :math:`n/b` の部分問題 :math:`a` 個に分け、分割と統合に :math:`f(n)` 時間かかるアルゴリズムを表す。\ :math:`n^{\log_b a}` と :math:`f(n)` を比べて、次のように :math:`T(n)` が決まる。

.. list-table:: マスター定理（簡略版）
   :header-rows: 1
   :widths: 40 30 30

   * - 条件
     - 結論
     - 意味
   * - ある :math:`\varepsilon > 0` について :math:`f(n) = O(n^{\log_b a - \varepsilon})`
     - :math:`T(n) = \Theta(n^{\log_b a})`
     - 部分問題の数が支配的
   * - :math:`f(n) = \Theta(n^{\log_b a})`
     - :math:`T(n) = \Theta(n^{\log_b a} \log n)`
     - 各段の仕事量が等しい
   * - ある :math:`\varepsilon > 0` について :math:`f(n) = \Omega(n^{\log_b a + \varepsilon})` で、さらにある定数 :math:`c < 1` について十分大きな :math:`n` で :math:`a f(n/b) \le c f(n)`
     - :math:`T(n) = \Theta(f(n))`
     - 最上段の仕事が支配的

代表的な適用例を示す。

.. list-table:: マスター定理の適用例
   :header-rows: 1
   :widths: 35 30 35

   * - アルゴリズム
     - 漸化式
     - 計算量
   * - 二分探索
     - :math:`T(n) = T(n/2) + O(1)`
     - :math:`\Theta(\log n)`
   * - マージソート
     - :math:`T(n) = 2T(n/2) + \Theta(n)`
     - :math:`\Theta(n \log n)`
   * - カラツバ法（整数の乗算）
     - :math:`T(n) = 3T(n/2) + \Theta(n)`
     - :math:`\Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})`
   * - 二分木（第 4 章）の全ノードの走査
     - :math:`T(n) = 2T(n/2) + O(1)`
     - :math:`\Theta(n)`

Python の組み込み型の計算量
---------------------------

Python でアルゴリズムを実装するときは、組み込み型の操作の計算量を知っておく必要がある。CPython における主な操作の計算量を次の表に示す（\ :math:`n` は要素数、dict と set は平均計算量）。

.. list-table:: 組み込み型の主な操作の計算量
   :header-rows: 1
   :widths: 15 45 40

   * - 型
     - 操作
     - 計算量
   * - list
     - 添字によるアクセス ``a[i]``\ 、末尾への追加 ``a.append(x)``\ 、末尾の削除 ``a.pop()``
     - :math:`O(1)`\ （append は償却）
   * - list
     - 先頭への挿入 ``a.insert(0, x)``\ 、先頭の削除 ``a.pop(0)``
     - :math:`O(n)`
   * - list
     - 所属判定 ``x in a``\ 、\ ``a.index(x)``
     - :math:`O(n)`
   * - list
     - スライス ``a[i:j]``
     - :math:`O(j - i)`
   * - list
     - 整列 ``a.sort()``\ 、\ ``sorted(a)``
     - :math:`O(n \log n)`
   * - dict、set
     - 追加、削除、所属判定 ``x in s``
     - 平均 :math:`O(1)`\ 、最悪 :math:`O(n)`
   * - collections.deque
     - 両端への追加と削除
     - :math:`O(1)`
   * - heapq
     - ``heappush``\ 、\ ``heappop``
     - :math:`O(\log n)`

例えば、キューとして ``list`` を使い ``pop(0)`` で先頭を取り出すと、1 回ごとに :math:`O(n)` 時間がかかる。第 7 章の幅優先探索で ``collections.deque`` を使うのはこのためである。

:math:`n` が 2 倍になると、\ :math:`O(n^2)` の方法は約 4 倍に増えている。他の 2 つは実行時間が短すぎて測定誤差の影響が大きいが、\ :math:`O(n^2)` の方法との差は桁違いであることが分かる。\ :math:`n` が小さいうちは測定誤差の影響が大きいが、\ :math:`n` を大きくするほど計算量の差がはっきり現れる。

章末のまとめ
------------

* アルゴリズムの効率は、計算モデル上の基本操作の回数（時間計算量）と使用メモリ（空間計算量）で測る。
* 計算量は通常、最悪計算量を漸近記法で表す。償却計算量は、一連の操作全体で見た 1 操作あたりのコストである。
* 分割統治型の再帰アルゴリズムの計算量は、漸化式とマスター定理で求められる。
* Python の組み込み型の操作には、一定時間で終わらないものがある。
