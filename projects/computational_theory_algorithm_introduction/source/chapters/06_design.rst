第 6 章 アルゴリズム設計技法
============================

新しい問題に出会ったとき、アルゴリズムを一から考えるのは難しい。しかし多くのアルゴリズムは、少数の典型的な考え方の組み合わせで作られている。本章では、分割統治法、貪欲法、動的計画法、バックトラッキングという 4 つの設計技法を紹介する。

分割統治法
----------

**分割統治法**\ は、問題を同じ形の小さな部分問題に分割し、部分問題を再帰的に解いて、その結果を統合する技法である。第 5 章のマージソートとクイックソートはその典型例であり、計算量は第 3 章の漸化式とマスター定理で解析できる。

もう 1 つの例として、\ :math:`x^n` を計算する問題を考える。素朴に :math:`x` を :math:`n` 個掛け合わせると :math:`n - 1` 回の乗算が必要だが、\ :math:`x^n = (x^{n/2})^2`\ （\ :math:`n` が偶数のとき）を利用すると、問題のサイズを半分にできる。

.. code-block:: python
   :linenos:

   def power(x: int, n: int) -> int:
       """x の n 乗を O(log n) 回の乗算で求める。"""
       if n == 0:
           return 1
       half = power(x, n // 2)
       if n % 2 == 0:
           return half * half
       return half * half * x

乗算の回数は漸化式 :math:`T(n) = T(n/2) + O(1)` を満たし、\ :math:`O(\log n)` 回で済む。この方法は\ **繰り返し二乗法**\ と呼ばれ、第 12 章のミラー-ラビン素数判定法で使う Python の組み込み関数 ``pow(a, d, n)`` の内部でも使われている。

分割統治法が有効なのは、部分問題が互いに独立しており、統合が効率よく行える場合である。部分問題が重なり合っている場合は、次に述べる動的計画法を検討する。

貪欲法
------

**貪欲法**\ は、解を少しずつ組み立てる際に、各段階でその時点で最もよく見える選択を行い、その選択を後から取り消さない技法である。実装が簡単で高速だが、常に最適解が得られるとは限らない。貪欲法を使うときは、それが最適解を与えることを証明する必要がある。

区間スケジューリング
^^^^^^^^^^^^^^^^^^^^

会議室の利用申請が複数あり、各申請は開始時刻と終了時刻を持つ。時間が重ならないように、できるだけ多くの申請を受け付けたい。この問題を\ **区間スケジューリング問題**\ と呼ぶ。

「開始時刻が早い順」「長さが短い順」に選ぶ貪欲法は、反例があり最適ではない。例えば開始時刻が早い順では、最初に非常に長い区間を選んでしまうと他の区間を全く選べなくなる。正しいのは「\ **終了時刻が早い順**\ に、既に選んだ区間と重ならないものを選ぶ」という貪欲法である。

**証明**\ ：貪欲法が選んだ区間を終了時刻の順に :math:`g_1, g_2, \ldots, g_k`\ 、ある最適解の区間を終了時刻の順に :math:`o_1, o_2, \ldots, o_m` とする（\ :math:`k \le m`\ ）。帰納法により、全ての :math:`i \le k` について「\ :math:`g_i` の終了時刻は :math:`o_i` の終了時刻以下」であることを示す。\ :math:`i = 1` では、\ :math:`g_1` は全区間の中で終了時刻が最も早いので成り立つ。\ :math:`i - 1` で成り立つとすると、\ :math:`o_i` は :math:`o_{i-1}` の終了後に始まるので、\ :math:`g_{i-1}` の終了後にも始まる。したがって :math:`o_i` は貪欲法が :math:`i` 番目を選ぶときの候補に含まれており、貪欲法はその中で終了時刻が最も早いものを選ぶので、\ :math:`g_i` の終了時刻は :math:`o_i` の終了時刻以下になる。最後に、\ :math:`k < m` と仮定すると、\ :math:`o_{k+1}` は :math:`g_k` の終了後に始まるので貪欲法はまだ区間を選べたことになり、矛盾する。よって :math:`k = m` である。

このように、貪欲法の解が最適解に「常に遅れをとらない」ことを示す論法や、最適解の一部を貪欲法の選択に置き換えても悪くならないことを示す論法（\ **交換論法**\ ）が、貪欲法の正しさを示す典型的な方法である。

動的計画法
----------

**動的計画法**\ は、問題を部分問題に分割し、各部分問題の答えを表に記録して再利用する技法である。英語の Dynamic Programming から DP と略されることもある。分割統治法と異なり、同じ部分問題が何度も現れる（部分問題が重なり合う）場合に威力を発揮する。

動的計画法が使えるのは、問題の最適解が部分問題の最適解から組み立てられる場合である。この性質を\ **最適部分構造**\ と呼ぶ。動的計画法でアルゴリズムを設計するときは、次の手順で考えるとよい。

1. 部分問題を定義する（表の各セルが何を表すかを決める）。
2. 部分問題の間の関係を漸化式で表す。
3. 小さい部分問題から順に表を埋める（ボトムアップ）か、再帰呼び出しの結果を記録する（トップダウン、\ **メモ化**\ ）。
4. 必要なら、表を逆にたどって最適解そのものを復元する。

メモ化：フィボナッチ数
^^^^^^^^^^^^^^^^^^^^^^

フィボナッチ数 :math:`F_n = F_{n-1} + F_{n-2}`\ （\ :math:`F_0 = 0, F_1 = 1`\ ）を定義どおりに再帰で計算すると、同じ :math:`F_k` を何度も計算するため、呼び出し回数は :math:`\Theta(\varphi^n)`\ （\ :math:`\varphi \approx 1.618` は黄金比）に増える。計算済みの値を記録しておけば、各 :math:`F_k` は 1 回ずつしか計算されず、\ :math:`O(n)` 回の呼び出しで済む。Python では ``functools.lru_cache``\ （または ``functools.cache``\ ）を関数に付けるだけでメモ化できる。

0-1 ナップサック問題
^^^^^^^^^^^^^^^^^^^^

:math:`n` 個の品物があり、品物 :math:`i` の重さは :math:`w_i`\ 、価値は :math:`v_i` である。重さの合計が :math:`W` 以下になるように品物を選び（各品物は選ぶか選ばないかのどちらか）、価値の合計を最大にしたい。これを **0-1 ナップサック問題**\ と呼ぶ。

全ての選び方を試すと :math:`2^n` 通りになる。そこで、部分問題を次のように定義する。

* :math:`dp[i][w]`\ ：品物 :math:`0, 1, \ldots, i - 1` の中から、重さの合計が :math:`w` 以下になるように選んだときの価値の最大値

品物 :math:`i - 1` を選ぶか選ばないかで場合分けすると、次の漸化式が得られる。

.. math::

   dp[i][w] = \begin{cases} dp[i-1][w] & (w_{i-1} > w) \\ \max(dp[i-1][w],\ dp[i-1][w - w_{i-1}] + v_{i-1}) & (w_{i-1} \le w) \end{cases}

表の大きさは :math:`(n + 1) \times (W + 1)` で、各セルを :math:`O(1)` 時間で埋められるので、計算量は :math:`O(nW)` である。

この計算量は :math:`n` と :math:`W` の多項式に見えるが、\ :math:`W` は入力の中では :math:`\log W` ビットで表される数値である。入力の長さに対しては指数時間であり、このようなアルゴリズムを\ **擬多項式時間**\ アルゴリズムと呼ぶ。第 11 章で見るように、ナップサック問題（の判定版）は NP 完全であり、この区別が重要な意味を持つ。

最長共通部分列
^^^^^^^^^^^^^^

文字列から 0 個以上の文字を取り除いて得られる文字列を、元の文字列の\ **部分列**\ と呼ぶ（取り除く文字は連続していなくてもよい）。2 つの文字列 :math:`s` と :math:`t` に共通する部分列のうち最長のものを\ **最長共通部分列**\ （LCS: Longest Common Subsequence）と呼ぶ。LCS は ``diff`` コマンドによるファイルの差分表示などに使われている。

:math:`dp[i][j]` を :math:`s` の先頭 :math:`i` 文字と :math:`t` の先頭 :math:`j` 文字の LCS の長さとすると、次の漸化式が成り立つ。

.. math::

   dp[i][j] = \begin{cases} 0 & (i = 0 \text{ または } j = 0) \\ dp[i-1][j-1] + 1 & (s_{i-1} = t_{j-1}) \\ \max(dp[i-1][j],\ dp[i][j-1]) & (s_{i-1} \ne t_{j-1}) \end{cases}

:math:`s` と :math:`t` の長さをそれぞれ :math:`m`\ 、\ :math:`n` とすると、計算量は :math:`O(mn)` である。

動的計画法は第 7 章のベルマン-フォード法やワーシャル-フロイド法、第 9 章の CYK 法でも使われる。

バックトラッキングと分枝限定法
------------------------------

効率のよいアルゴリズムが見つからない問題では、可能な解を全て調べる\ **全探索**\ に頼ることになる。\ **バックトラッキング**\ は、解を 1 要素ずつ決めていき、途中で条件を満たさないことが分かった時点でその先の探索を打ち切って（\ **枝刈り**\ ）、直前の選択に戻って別の候補を試す技法である。

N クイーン問題
^^^^^^^^^^^^^^

:math:`n \times n` の盤面に、縦・横・斜めのいずれの方向にも互いに取り合わないように :math:`n` 個のクイーンを置く問題を考える。各行にクイーンはちょうど 1 個置かれるので、1 行目から順に列を決めていく。既に置いたクイーンと同じ列または同じ斜線上には置けないので、その候補はすぐに捨てる。

分枝限定法
^^^^^^^^^^

最適化問題に対しては、バックトラッキングをさらに強化した\ **分枝限定法**\ が使える。探索の途中で、「この先をどのように選んでも得られる解の値の上限（最大化問題の場合）」を見積もり、その上限がこれまでに見つかった最良の解の値以下であれば、その先の探索を打ち切る。例えばナップサック問題では、残りの品物を分割して入れてもよいと緩めた問題（貪欲法で最適に解ける）の値を上限として使える。

バックトラッキングや分枝限定法は、最悪の場合には指数時間かかる。しかし枝刈りがよく効けば、実用的な大きさの問題を解けることも多い。第 12 章の DPLL アルゴリズムは、充足可能性問題に対するバックトラッキングである。

章末のまとめ
------------

.. list-table:: 設計技法の比較
   :header-rows: 1
   :widths: 20 40 40

   * - 技法
     - 考え方
     - 本書での例
   * - 分割統治法
     - 独立な部分問題に分けて再帰的に解き、統合する
     - マージソート、クイックソート、繰り返し二乗法
   * - 貪欲法
     - 各段階で最もよく見える選択を行い、取り消さない
     - 区間スケジューリング、ダイクストラ法、クラスカル法
   * - 動的計画法
     - 重なり合う部分問題の答えを表に記録して再利用する
     - ナップサック問題、LCS、ベルマン-フォード法、CYK 法
   * - バックトラッキング
     - 解を 1 要素ずつ決め、矛盾したら戻る
     - N クイーン問題、DPLL アルゴリズム

* 貪欲法を使うときは、それが最適解を与えることを証明する必要がある。
* 動的計画法では、部分問題の定義と漸化式を決めることが設計の中心になる。
* 数値 :math:`W` に比例する計算量は、入力の長さに対しては指数時間であり、擬多項式時間と呼ばれる。
