第 5 章 探索と整列
==================

データの中から目的の値を見つける\ **探索**\ と、データを順序どおりに並べ替える\ **整列**\ （ソート）は、最も基本的な計算である。整列済みのデータに対しては探索が速くなるため、両者は密接に関係している。本章では代表的なアルゴリズムを紹介し、「比較だけを使う整列は :math:`\Omega(n \log n)` 時間より速くできない」という下界を証明する。

本章のアルゴリズムは全て次のサンプルコードに含まれている。

:download:`ch05_sorting.py <../../examples/ch05_sorting.py>`

線形探索と二分探索
------------------

**線形探索**\ は、リストの要素を先頭から順に調べる方法であり、最悪 :math:`O(n)` 時間かかる。Python の ``x in a``\ （\ ``a`` が ``list`` の場合）は線形探索である。

リストが整列済みであれば、\ **二分探索**\ により :math:`O(\log n)` 時間で探索できる。探索範囲の中央の要素と目的の値を比べ、目的の値が中央より小さければ左半分、大きければ右半分に範囲を絞ることを繰り返す。1 回の比較で範囲が半分になるので、比較の回数は約 :math:`\log_2 n` 回である。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: binary_search
   :caption: 二分探索（ch05_sorting.py より）

二分探索は単純だが、範囲の端の扱いを誤りやすい。このコードでは探索範囲を半開区間 ``values[lo:hi]`` として扱い、ループの間「目的の値があるとすれば ``values[lo:hi]`` の中にある」という性質（\ **ループ不変条件**\ ）が保たれるように ``lo`` と ``hi`` を更新している。ループ不変条件を明確にすることは、ループを含むアルゴリズムの正しさを示す基本的な方法である。

Python の標準ライブラリでは、\ ``bisect.bisect_left`` などが二分探索を提供している。

単純な整列：挿入ソート
----------------------

**挿入ソート**\ は、先頭から順に、要素をそれより前の整列済みの部分の適切な位置に挿入していく方法である。トランプの手札を並べるときの方法に近い。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: insertion_sort
   :caption: 挿入ソート（ch05_sorting.py より）

逆順に並んだ入力では、\ :math:`i` 番目の要素を挿入するのに :math:`i` 回の比較と移動が必要になり、合計 :math:`1 + 2 + \cdots + (n - 1) = \Theta(n^2)` 時間かかる。一方、ほぼ整列済みの入力では、各要素の移動が少ないので :math:`O(n)` に近い時間で終わる。この性質から、挿入ソートは要素数の少ない部分の整列に使われることがある。Python の ``sorted`` が採用している Timsort も、短い区間の整列に挿入ソートを利用している。

分割統治による整列：マージソート
--------------------------------

**マージソート**\ は、リストを半分に分けてそれぞれを再帰的に整列し、整列済みの 2 つのリストを併合（マージ）する方法である。このように問題を小さな部分問題に分けて解き、その結果を組み合わせる方法を\ **分割統治法**\ と呼ぶ（第 6 章で詳しく扱う）。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: merge_sort
   :caption: マージソート（ch05_sorting.py より）

整列済みの 2 つのリストの併合は、それぞれの先頭の小さい方を取り出すことを繰り返せばよく、\ :math:`O(n)` 時間で行える。したがって計算量は漸化式 :math:`T(n) = 2T(n/2) + \Theta(n)` を満たし、第 3 章で見たとおり :math:`T(n) = \Theta(n \log n)` である。この計算量は入力の内容によらない。一方、併合のために :math:`O(n)` の追加の領域が必要になる。

等しいキーを持つ要素の相対的な順序が整列の前後で変わらないとき、その整列を\ **安定**\ であるという。マージソートは、併合のときに左側の要素を優先する（11 行目の ``<=``\ ）ことで安定になる。安定な整列を使うと、「まず第 2 キーで整列し、次に第 1 キーで整列する」という方法で複数のキーによる整列が実現できる。

平均的に速い整列：クイックソート
--------------------------------

**クイックソート**\ は、ピボットと呼ぶ要素を 1 つ選び、ピボットより小さい要素を左に、それ以外を右に集めてから（分割）、左右をそれぞれ再帰的に整列する方法である。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: quick_sort
   :caption: 乱択クイックソート（ch05_sorting.py より）

分割によってリストがほぼ半分ずつに分かれれば、計算量はマージソートと同じ :math:`\Theta(n \log n)` になる。しかし、ピボットとして常に最小値や最大値を選んでしまうと、分割のたびに要素が 1 つしか減らず、計算量は :math:`\Theta(n^2)` になる。例えば「常に末尾の要素をピボットにする」という規則では、整列済みの入力がこの最悪の場合に当たる。

このコードではピボットを無作為に選んでいる（8 行目）。こうすると、どんな入力に対しても、比較の回数の期待値は :math:`O(n \log n)` になる。ここでの期待値は入力についてではなく、アルゴリズムが使う乱数についてとったものである。したがって、特定の入力で必ず遅くなるということはない。このように乱数を使うアルゴリズムを\ **乱択アルゴリズム**\ と呼び、第 12 章で再び扱う。

クイックソートは、追加の領域が再帰呼び出しのスタック分（期待 :math:`O(\log n)`\ ）で済み、内側のループが単純であるため、実用上は非常に速い。ただし安定ではない。

最悪でも速い整列：ヒープソート
------------------------------

**ヒープソート**\ は、第 4 章の二分ヒープを使った整列である。まずリスト全体を最大ヒープに変換し、根（最大値）を末尾の要素と交換してヒープの範囲を 1 つ縮める操作を繰り返す。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: heap_sort
   :caption: ヒープソート（ch05_sorting.py より）

最大ヒープの構築は、葉に近いノードから順に ``sift_down`` を行うことで :math:`O(n)` 時間で行える。その後の :math:`n - 1` 回の取り出しはそれぞれ :math:`O(\log n)` なので、全体の計算量は最悪でも :math:`O(n \log n)` である。追加の領域は :math:`O(1)` で済むが、安定ではない。

比較ソートの下界
----------------

ここまでの整列アルゴリズムは、要素どうしの比較（\ ``<`` や ``<=``\ ）の結果だけを使って要素の順序を決めている。このような整列を\ **比較ソート**\ と呼ぶ。比較ソートは、どのように工夫しても最悪 :math:`\Omega(n \log n)` 回の比較が必要である。

**定理**\ ：任意の比較ソートは、要素数 :math:`n` の入力に対して、最悪の場合に :math:`\Omega(n \log n)` 回の比較を行う。

**証明**\ ：相異なる :math:`n` 個の要素の並べ方は :math:`n!` 通りあり、比較ソートはその全てを区別して正しく並べ替えなければならない。比較ソートの動作を、各内部ノードが 1 回の比較を、各葉が最終的な並べ替え方を表す二分木（\ **決定木**\ ）として表す。入力ごとに比較の結果が決まり、根から葉への 1 本の経路が定まる。異なる並べ方の入力には異なる並べ替えを施す必要があるので、決定木は少なくとも :math:`n!` 枚の葉を持つ。高さ :math:`h` の二分木の葉は高々 :math:`2^h` 枚なので、\ :math:`2^h \ge n!` すなわち :math:`h \ge \log n!` である。最悪の場合の比較の回数は :math:`h` に等しく、第 2 章で述べたように :math:`\log n! = \Theta(n \log n)` なので、\ :math:`h = \Omega(n \log n)` となる。

この定理から、マージソートとヒープソートは比較ソートとして漸近的に最適である。このように「どんなアルゴリズムでもこれ以上速くはできない」という\ **下界**\ を示すことは、計算理論の重要な目標の 1 つであり、第 11 章の議論につながる。

比較を使わない整列
------------------

要素が小さな範囲の整数であるなど、比較以外の情報を使えるときは、\ :math:`O(n \log n)` より速く整列できる。

**計数ソート**\ は、\ :math:`0` 以上 :math:`k` 以下の整数を整列する方法である。各値が何回現れるかを数えてから、小さい値から順に、数えた回数だけ並べる。計算量は :math:`O(n + k)` である。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: counting_sort
   :caption: 計数ソート（ch05_sorting.py より）

**基数ソート**\ は、整数を下の桁から 1 桁ずつ見て、その桁の値で安定に振り分けることを繰り返す方法である。各段階が安定なので、上の桁の振り分けが終わった時点で、下の桁の順序も正しく保たれている。\ :math:`d` 桁の整数を基数 :math:`b` で扱うと、計算量は :math:`O(d(n + b))` になる。

.. literalinclude:: ../../examples/ch05_sorting.py
   :language: python
   :linenos:
   :pyobject: radix_sort
   :caption: 基数ソート（ch05_sorting.py より）

これらの方法は比較ソートの下界に矛盾しない。下界は「比較だけを使う」アルゴリズムについての主張であり、計数ソートや基数ソートは要素の値そのものを配列の添字として使っているからである。

章末のまとめ
------------

.. list-table:: 整列アルゴリズムの比較
   :header-rows: 1
   :widths: 20 20 20 20 20

   * - アルゴリズム
     - 最悪計算量
     - 平均（期待）計算量
     - 追加の領域
     - 安定性
   * - 挿入ソート
     - :math:`O(n^2)`
     - :math:`O(n^2)`
     - :math:`O(1)`
     - 安定
   * - マージソート
     - :math:`O(n \log n)`
     - :math:`O(n \log n)`
     - :math:`O(n)`
     - 安定
   * - クイックソート（乱択）
     - :math:`O(n^2)`
     - :math:`O(n \log n)`
     - :math:`O(\log n)`
     - 安定でない
   * - ヒープソート
     - :math:`O(n \log n)`
     - :math:`O(n \log n)`
     - :math:`O(1)`
     - 安定でない
   * - 計数ソート
     - :math:`O(n + k)`
     - :math:`O(n + k)`
     - :math:`O(n + k)`
     - 安定（実装による）
   * - 基数ソート
     - :math:`O(d(n + b))`
     - :math:`O(d(n + b))`
     - :math:`O(n + b)`
     - 安定

* 整列済みのデータに対しては、二分探索で :math:`O(\log n)` 時間の探索ができる。
* 比較ソートには :math:`\Omega(n \log n)` の下界があり、マージソートとヒープソートはこれを達成する。
* 値の範囲が限られていれば、比較を使わない整列で下界より速く整列できる。
