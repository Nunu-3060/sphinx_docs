第 8 章 有限オートマトンと正規言語
==================================

第 3 部では、「計算とは何か」を数学的に定義し、計算で何ができて何ができないかを調べる。そのために、能力を制限した単純な計算モデルから始めて、段階的に強力なモデルへと進む。本章で扱う\ **有限オートマトン**\ は、有限個の状態しか記憶できない最も単純な計算モデルである。単純ではあるが、字句解析、正規表現による検索、通信プロトコルの設計など、実用上の応用は非常に多い。

アルファベット・文字列・言語
----------------------------

計算理論では、計算の問題を「文字列がある集合に属するかどうか」という形で表す。そのための用語を定義する。

* **アルファベット**\ ：記号の空でない有限集合。\ :math:`\Sigma` で表すことが多い。例：\ :math:`\Sigma = \{0, 1\}`\ 。
* **文字列**\ （語）：アルファベットの記号を有限個並べた列。長さ 0 の文字列を\ **空列**\ と呼び、\ :math:`\varepsilon` で表す。文字列 :math:`w` の長さを :math:`|w|` と書く。
* :math:`\Sigma^*`\ ：\ :math:`\Sigma` 上の文字列全体の集合（空列を含む）。
* **言語**\ ：\ :math:`\Sigma^*` の部分集合。つまり文字列の集合である。

例えば「2 進数として読んだ値が 3 の倍数である文字列の集合」や「\ :math:`0` を :math:`n` 個並べた後に :math:`1` を :math:`n` 個並べた文字列の集合 :math:`\{0^n 1^n \mid n \ge 0\}`\ 」は言語である。

「与えられた数は素数か」「与えられたグラフは連結か」といった、答えが「はい」か「いいえ」の問題（\ **判定問題**\ ）は、入力を文字列で符号化すれば、「答えが『はい』になる入力の文字列全体」という言語で表せる。こうして「問題を解く」ことは「文字列が言語に属するかを判定する」ことに置き換えられる。

文字列 :math:`x` と :math:`y` をこの順につなげた文字列を :math:`xy` と書き、\ :math:`x` と :math:`y` の\ **連接**\ と呼ぶ。言語 :math:`A` と :math:`B` についても、連接 :math:`AB = \{xy \mid x \in A, y \in B\}` と、\ **スター閉包** :math:`A^* = \{x_1 x_2 \cdots x_k \mid k \ge 0, x_i \in A\}` を定義する。\ :math:`A^*` は :math:`A` の文字列を 0 個以上つなげたもの全体であり、常に空列を含む。

決定性有限オートマトン
----------------------

**決定性有限オートマトン**\ （DFA: Deterministic Finite Automaton）は、次の 5 つ組 :math:`M = (Q, \Sigma, \delta, q_0, F)` で定義される。

* :math:`Q`\ ：状態の有限集合
* :math:`\Sigma`\ ：入力アルファベット
* :math:`\delta : Q \times \Sigma \to Q`\ ：遷移関数
* :math:`q_0 \in Q`\ ：開始状態
* :math:`F \subseteq Q`\ ：受理状態の集合

DFA は開始状態 :math:`q_0` から始め、入力文字列を先頭から 1 文字ずつ読み、現在の状態 :math:`q` と読んだ記号 :math:`a` から次の状態 :math:`\delta(q, a)` に移る。全ての文字を読み終えたときに受理状態にいれば入力を\ **受理**\ し、そうでなければ\ **拒否**\ する。DFA :math:`M` が受理する文字列全体の集合を :math:`M` が\ **認識する言語**\ と呼び、\ :math:`L(M)` で表す。DFA で認識できる言語を\ **正規言語**\ と呼ぶ。

DFA は、状態という有限の記憶だけを持ち、入力を一方向に 1 回だけ読む計算機と考えられる。入力の長さに関係なく記憶の量が一定である点が本質的な制約である。

例：3 の倍数を判定する DFA
^^^^^^^^^^^^^^^^^^^^^^^^^^

2 進数として読んだ値が 3 の倍数である文字列を受理する DFA を作る。値そのものを覚えておくことはできないが、「ここまで読んだ値を 3 で割った余り」だけを覚えておけば十分である。値 :math:`x` の後ろにビット :math:`b` を付けると値は :math:`2x + b` になるので、余り :math:`r` の状態からビット :math:`b` を読んだら、余り :math:`(2r + b) \bmod 3` の状態に移ればよい。状態を :math:`q_0, q_1, q_2`\ （添字は余り）とし、開始状態と受理状態を :math:`q_0` とすると、遷移関数は次の表のようになる。

.. list-table:: 3 の倍数を判定する DFA の遷移関数
   :header-rows: 1
   :widths: 40 30 30

   * - 状態
     - 0 を読む
     - 1 を読む
   * - :math:`\to q_0`\ （開始、受理）
     - :math:`q_0`
     - :math:`q_1`
   * - :math:`q_1`
     - :math:`q_2`
     - :math:`q_0`
   * - :math:`q_2`
     - :math:`q_1`
     - :math:`q_2`

例えば入力 ``110``\ （値 6）では、\ :math:`q_0 \xrightarrow{1} q_1 \xrightarrow{1} q_0 \xrightarrow{0} q_0` と遷移し、受理状態で終わるので受理される。

この DFA の状態は、第 2 章で述べた「3 で割った余りが等しい」という同値関係の同値類に対応している。DFA を設計するときは、「将来の判定のために、これまでの入力について何を覚えておけば十分か」を考え、それを有限個の状態で表せばよい。

非決定性有限オートマトン
------------------------

**非決定性有限オートマトン**\ （NFA: Nondeterministic Finite Automaton）は、DFA の遷移関数を次のように緩めたものである。

* 状態と記号の組に対して、遷移先が 0 個でも複数個でもよい。つまり遷移関数は :math:`\delta : Q \times (\Sigma \cup \{\varepsilon\}) \to 2^Q` である。
* 記号を読まずに状態を移る\ **空列遷移**\ （\ :math:`\varepsilon` 遷移）を許す。

NFA は、遷移先が複数あるときに「全ての可能性を同時に試す」と考える。入力を読み終えたときに、受理状態に至る遷移の選び方が 1 つでもあれば入力を受理する。言い換えると、NFA は「うまい選択を推測する」ことができる計算機である。

例：後ろから 3 文字目が 1 である文字列
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

アルファベット :math:`\{0, 1\}` 上で、後ろから 3 文字目が 1 である文字列を受理する NFA を考える。状態 :math:`q_0` で入力を読み進め、1 を読んだときに「これが後ろから 3 文字目だ」と推測したら状態 :math:`q_1` に移る。その後、任意の 2 文字を読んで状態 :math:`q_3` に至れば受理する。推測が外れた場合（\ :math:`q_3` に達した後にまだ文字が残っている場合）は、遷移先がなくなってその可能性は消える。

.. list-table:: 後ろから 3 文字目が 1 である文字列を受理する NFA の遷移関数
   :header-rows: 1
   :widths: 40 30 30

   * - 状態
     - 0 を読む
     - 1 を読む
   * - :math:`\to q_0`\ （開始）
     - :math:`\{q_0\}`
     - :math:`\{q_0, q_1\}`
   * - :math:`q_1`
     - :math:`\{q_2\}`
     - :math:`\{q_2\}`
   * - :math:`q_2`
     - :math:`\{q_3\}`
     - :math:`\{q_3\}`
   * - :math:`q_3`\ （受理）
     - :math:`\emptyset`
     - :math:`\emptyset`

この言語を DFA で認識するには、直近の 3 文字を全て覚えておく必要があり、\ :math:`2^3 = 8` 個の状態が必要になる。

部分集合構成法
^^^^^^^^^^^^^^

NFA は DFA より強力に見えるが、認識できる言語の範囲は変わらない。

**定理**\ ：任意の NFA に対して、同じ言語を認識する DFA が存在する。

**証明の考え方**\ ：NFA が「ある時点で取りうる状態の集合」を、DFA の 1 つの状態とみなす。NFA の状態集合を :math:`Q` とすると、DFA の状態は :math:`Q` の部分集合であり、高々 :math:`2^{|Q|}` 個しかないので有限である。DFA の開始状態は、NFA の開始状態から空列遷移でたどり着ける状態の集合（\ :math:`\varepsilon` 閉包）とする。DFA の状態 :math:`S` から記号 :math:`a` で移る先は、\ :math:`S` の各状態から :math:`a` で移れる状態を全て集め、その :math:`\varepsilon` 閉包をとった集合とする。NFA の受理状態を 1 つでも含む集合を DFA の受理状態とすればよい。この構成を\ **部分集合構成法**\ と呼ぶ。

部分集合構成法では状態数が最大で指数的に増える。上の NFA を変換すると 8 状態の DFA になり、一般に「後ろから :math:`n` 文字目が 1」という言語では、\ :math:`n + 1` 状態の NFA に対して DFA は :math:`2^n` 状態を必要とする。NFA は DFA と同じ言語しか認識できないが、ずっと簡潔に言語を表せる場合がある。

正規表現
--------

**正規表現**\ は、言語を式で表す方法である。アルファベット :math:`\Sigma` 上の正規表現とそれが表す言語を、次のように帰納的に定義する。

.. list-table:: 正規表現の定義
   :header-rows: 1
   :widths: 30 70

   * - 正規表現
     - 表す言語
   * - :math:`a`\ （\ :math:`a \in \Sigma`\ ）
     - :math:`\{a\}`
   * - :math:`\varepsilon`
     - :math:`\{\varepsilon\}`
   * - :math:`\emptyset`
     - :math:`\emptyset`
   * - :math:`R_1 \mid R_2`
     - :math:`R_1` と :math:`R_2` が表す言語の和集合
   * - :math:`R_1 R_2`
     - :math:`R_1` と :math:`R_2` が表す言語の連接
   * - :math:`R^*`
     - :math:`R` が表す言語のスター閉包

例えば :math:`(0 \mid 1)^* 1 (0 \mid 1)(0 \mid 1)` は、後ろから 3 文字目が 1 である文字列全体を表す。

**定理**\ （クリーネの定理）：言語が正規表現で表せることと、有限オートマトンで認識できることは同値である。

正規表現から NFA を作るには、正規表現の構造に沿って、和集合・連接・スター閉包のそれぞれに対応する NFA を空列遷移でつなぎ合わせればよい（\ **トンプソンの構成法**\ ）。逆に有限オートマトンから正規表現を作るには、状態を 1 つずつ取り除きながら、遷移のラベルを正規表現で置き換えていけばよい。

Python の re モジュールとの関係
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Python の ``re`` モジュールなどで使われる正規表現は、上で定義した理論上の正規表現を拡張したものである。\ ``+`` や ``?``\ 、\ ``[a-z]``\ 、\ ``{2,5}`` などは理論上の正規表現の略記にすぎないが、後方参照（\ ``(a+)b\1`` のように、前にマッチした文字列と同じものを要求する機能）は正規言語の範囲を超える。例えば ``(.*)\1`` は「同じ文字列を 2 回繰り返した文字列」を表すが、この言語は正規言語ではない。

また、Python の ``re`` モジュールは、NFA の可能性を 1 つずつ試すバックトラッキングで実装されている。そのため、\ ``(a+)+b`` のような正規表現に ``aaaa...a``\ （\ ``b`` を含まない長い文字列）を与えると、試す可能性が指数的に増えて処理が終わらなくなる。これは ReDoS（Regular expression Denial of Service）と呼ばれる脆弱性の原因になる。部分集合構成法のように状態の集合を追跡する方式で実装すれば、入力の長さに比例する時間で照合できる。Go 言語の ``regexp`` パッケージや Google の RE2 ライブラリはこの方式を採用している。

正規言語の性質
--------------

閉包性
^^^^^^

正規言語は、次の演算について閉じている。つまり、正規言語に次の演算を施した結果もまた正規言語である。

* 和集合、連接、スター閉包：正規表現の定義から明らか。
* 補集合：DFA の受理状態と非受理状態を入れ替えればよい。
* 共通部分：\ :math:`A \cap B = \overline{\overline{A} \cup \overline{B}}`\ （ド・モルガンの法則）から従う。2 つの DFA を同時に動かす\ **直積構成**\ で直接作ることもできる。

閉包性は、ある言語が正規であることを示したり、次に述べるポンピング補題と組み合わせて正規でないことを示したりするのに使える。

ポンピング補題
^^^^^^^^^^^^^^

有限オートマトンは有限個の状態しか持たないので、「\ :math:`0` の個数と :math:`1` の個数が等しい」のような、際限なく数を数える必要がある言語は認識できないと予想される。これを厳密に示す道具が\ **ポンピング補題**\ である。

**補題**\ （正規言語のポンピング補題）：\ :math:`L` が正規言語ならば、ある正の整数 :math:`p` が存在して、長さが :math:`p` 以上の任意の :math:`w \in L` は、次の 3 条件を満たすように :math:`w = xyz` と分割できる。

1. 全ての :math:`i \ge 0` について :math:`x y^i z \in L`
2. :math:`|y| \ge 1`
3. :math:`|xy| \le p`

**証明**\ ：\ :math:`L` を認識する DFA の状態数を :math:`p` とする。長さ :math:`n \ge p` の文字列 :math:`w \in L` を読むとき、DFA は開始状態を含めて :math:`n + 1` 個の状態を順に通る。最初の :math:`p + 1` 個の状態の中には、鳩の巣原理により同じ状態が 2 回現れる。その 2 回の間に読んだ部分を :math:`y`\ 、それより前を :math:`x`\ 、後ろを :math:`z` とすると、\ :math:`y` を読む間に DFA は同じ状態に戻ってくるので、\ :math:`y` を何回繰り返しても（0 回でも）最後の状態は変わらず、受理される。同じ状態が現れる 2 つの位置は異なるので :math:`|y| \ge 1` であり、最初の :math:`p + 1` 個の状態の中で見つけたので :math:`|xy| \le p` である。

**例**\ ：\ :math:`L = \{0^n 1^n \mid n \ge 0\}` は正規言語ではない。\ :math:`L` が正規言語であると仮定し、ポンピング補題の定数を :math:`p` とする。\ :math:`w = 0^p 1^p \in L` を考えると、条件 3 より :math:`xy` は先頭の :math:`p` 文字の中に収まるので、\ :math:`y` は :math:`0` だけからなる。条件 2 より :math:`y` は 1 文字以上なので、\ :math:`xy^2z` は :math:`0` の個数が :math:`1` の個数より多くなり、\ :math:`L` に属さない。これは条件 1 に矛盾する。

同様にして、「対応のとれた括弧の列」も正規言語でないことが示せる。そのため、正規表現だけでは HTML やプログラミング言語の入れ子構造を正しく解析できない。入れ子構造を扱うには、第 9 章の文脈自由文法が必要になる。

応用：文字列照合と KMP 法
-------------------------

テキストの中からパターンが現れる位置を全て見つける問題を\ **文字列照合**\ と呼ぶ。素朴な方法では、テキストの各位置からパターンとの比較を始め、不一致があれば次の位置からやり直す。テキストの長さを :math:`n`\ 、パターンの長さを :math:`m` とすると、最悪 :math:`O(nm)` 時間かかる。

パターン :math:`P` で終わる文字列全体の言語 :math:`\Sigma^* P` は正規言語である。これを認識する DFA にテキストを読ませると、受理状態に入るのはちょうどパターンの出現が終わる位置なので、テキストを 1 回走査するだけで全ての出現位置が分かる。\ **KMP 法**\ （クヌース-モリス-プラット法）は、この DFA を :math:`O(m)` 時間で前計算できるコンパクトな形で表したものである。

KMP 法では、パターンの各位置 :math:`i` について、\ :math:`P[0..i]` の真の接頭辞（それ自身を除く接頭辞）であって接尾辞でもあるもののうち最長のものの長さ ``fail[i]`` を前計算する（\ **失敗関数**\ ）。照合中に不一致が起きたら、テキスト側は戻らずに、パターン側の位置だけを失敗関数に従って戻す。既に一致した部分の情報を捨てずに再利用するため、テキストの各文字は定数回（償却）しか比較されず、全体の計算量は :math:`O(n + m)` になる。

パターン ``ABABC`` の失敗関数は ``[0, 0, 1, 2, 0]`` となる。例えば ``fail[3] = 2`` は、\ ``ABAB`` の真の接頭辞かつ接尾辞である最長の文字列が ``AB``\ （長さ 2）であることを表す。\ ``ABAB`` まで一致した後に不一致が起きても、末尾の ``AB`` は既にパターンの先頭 2 文字と一致しているので、パターンの 3 文字目から照合を再開すればよい。

章末のまとめ
------------

* 判定問題は、「答えが『はい』になる入力の文字列全体」という言語で表せる。
* DFA と NFA は同じ言語のクラス（正規言語）を認識する。NFA から DFA への変換では、状態数が指数的に増えることがある。
* 正規表現と有限オートマトンは等価である。実用の正規表現エンジンには、理論上の正規表現を超える機能や、バックトラッキングによる性能上の問題がある。
* ポンピング補題を使うと、\ :math:`\{0^n 1^n\}` のような言語が正規言語でないことを示せる。
