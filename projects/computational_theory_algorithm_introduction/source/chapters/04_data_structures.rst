第 4 章 基本データ構造
======================

アルゴリズムの効率は、データをどのような形で保持するかに大きく左右される。データを保持し、決められた操作を提供する仕組みを\ **データ構造**\ と呼ぶ。本章では、後の章で繰り返し使う基本的なデータ構造を、提供する操作とその計算量に注目して紹介する。

なお本書では、連結リストや木を構成する一つ一つの要素を\ **ノード**\ と呼ぶ。グラフ理論の用語では頂点に当たる。

配列と連結リスト
----------------

**配列**\ は、要素をメモリ上に連続して並べたデータ構造である。\ :math:`i` 番目の要素の位置は先頭の位置から計算できるので、添字によるアクセスは :math:`O(1)` で行える。一方、途中に要素を挿入したり削除したりすると、後ろの要素を全てずらす必要があり :math:`O(n)` 時間かかる。Python の ``list`` は、第 3 章で説明したように容量を自動的に拡張する配列（可変長配列）である。

**連結リスト**\ は、各ノードが値と次のノードへの参照を持ち、参照をたどって要素を順に並べるデータ構造である。挿入や削除をしたい位置のノードが分かっていれば、参照をつなぎ替えるだけなので :math:`O(1)` で済む。その代わり、\ :math:`i` 番目の要素にたどり着くには先頭から :math:`i` 回参照をたどる必要があり、\ :math:`O(i)` 時間かかる。

.. list-table:: 配列と連結リストの比較
   :header-rows: 1
   :widths: 40 30 30

   * - 操作
     - 配列（可変長）
     - 連結リスト
   * - :math:`i` 番目の要素へのアクセス
     - :math:`O(1)`
     - :math:`O(i)`
   * - 末尾への追加
     - 償却 :math:`O(1)`
     - :math:`O(1)`\ （末尾への参照を持つ場合）
   * - 先頭への挿入
     - :math:`O(n)`
     - :math:`O(1)`
   * - 位置が分かっている要素の削除
     - :math:`O(n)`
     - :math:`O(1)`\ （双方向リストの場合）

実際の計算機では、連続したメモリをまとめて読み込むキャッシュの効果により、配列の方が漸近的な計算量以上に速いことが多い。

スタックとキュー
----------------

**スタック**\ は、最後に入れた要素を最初に取り出す（LIFO: Last In, First Out）データ構造であり、\ **キュー**\ は、最初に入れた要素を最初に取り出す（FIFO: First In, First Out）データ構造である。どちらも追加と取り出しを :math:`O(1)` で行える。

.. list-table:: Python でのスタックとキュー
   :header-rows: 1
   :widths: 20 40 40

   * - データ構造
     - 追加
     - 取り出し
   * - スタック
     - ``stack.append(x)``\ （\ ``list``\ ）
     - ``stack.pop()``
   * - キュー
     - ``queue.append(x)``\ （\ ``collections.deque``\ ）
     - ``queue.popleft()``

スタックは関数呼び出しの管理（呼び出しスタック）や深さ優先探索に、キューは幅優先探索（第 7 章）に使われる。第 9 章のプッシュダウンオートマトンは、有限オートマトンにスタックを 1 本追加した計算モデルである。

ハッシュテーブル
----------------

**ハッシュテーブル**\ は、キーから値を平均 :math:`O(1)` 時間で引けるデータ構造であり、Python の ``dict`` と ``set`` はハッシュテーブルで実装されている。

ハッシュテーブルは、大きさ :math:`m` の配列と\ **ハッシュ関数** :math:`h` からなる。ハッシュ関数はキーを :math:`0` 以上 :math:`m - 1` 以下の整数に変換する関数であり、キー :math:`k` に対応する値を配列の :math:`h(k)` 番目の位置に格納する。異なるキーが同じ位置に割り当てられることを\ **衝突**\ と呼ぶ。衝突を処理する方法には、同じ位置に割り当てられた要素をリストでつなぐ\ **連鎖法**\ と、空いている別の位置を規則に従って探す\ **開番地法**\ がある。CPython の ``dict`` は開番地法を採用している。

要素数 :math:`n` と配列の大きさ :math:`m` の比 :math:`\lambda = n/m` を\ **負荷率**\ と呼ぶ。ハッシュ関数がキーを一様に散らすと仮定すると、1 回の操作で調べる位置の数の期待値は負荷率だけで決まる。負荷率が一定値を超えたら配列を拡張して全ての要素を入れ直すことで、操作の平均計算量を :math:`O(1)` に保てる。拡張にかかる時間は、\ ``list`` の ``append`` と同じ理由で償却すれば :math:`O(1)` である。

ただし、全てのキーが同じ位置に割り当てられる最悪の場合には、1 回の操作に :math:`O(n)` 時間かかる。攻撃者がそのようなキーを意図的に送り込むことを防ぐため、Python は文字列のハッシュ値の計算に、起動のたびに変わる乱数を混ぜている。

ヒープと優先度付きキュー
------------------------

**優先度付きキュー**\ は、要素の追加と、最小（または最大）の要素の取り出しを提供するデータ構造である。第 7 章のダイクストラ法やプリム法で使う。

優先度付きキューの代表的な実装が\ **二分ヒープ**\ である。二分ヒープは、各ノードの値がその子の値以下であるという条件（ヒープ条件）を満たす完全二分木である。完全二分木なので、配列の添字だけで親子関係を表せる。添字 :math:`i` のノードの子は添字 :math:`2i + 1` と :math:`2i + 2`\ 、親は添字 :math:`\lfloor (i - 1)/2 \rfloor` にある。

* 追加: 末尾に要素を置き、親より小さい間は親と交換して上へ移動させる。
* 最小値の取り出し: 根（添字 0）を取り出し、末尾の要素を根に移してから、子より大きい間は小さい方の子と交換して下へ移動させる。

木の高さは :math:`O(\log n)` なので、どちらの操作も :math:`O(\log n)` 時間で済む。Python では ``heapq`` モジュールが、\ ``list`` を二分ヒープとして扱う関数を提供している。

.. code-block:: python
   :linenos:

   import heapq

   heap: list[int] = []
   for x in [5, 1, 8, 3, 2]:
       heapq.heappush(heap, x)
   print([heapq.heappop(heap) for _ in range(len(heap))])  # [1, 2, 3, 5, 8]

``heapq`` は最小ヒープだけを提供する。最大値を取り出したい場合は、値の符号を反転して格納する。

二分探索木と平衡木
------------------

**二分探索木**\ は、各ノードについて「左の部分木のキーは全てそのノードのキーより小さく、右の部分木のキーは全て大きい」という条件を満たす二分木である。探索は根から始め、目的のキーと比べて左右どちらかに進むことを繰り返す。追加と削除も同様に行える。

これらの操作の計算量は木の高さ :math:`h`\ （根から最も深い葉までの経路の辺の数）に比例し :math:`O(h)` である。キーを無作為な順に追加すると高さは平均 :math:`O(\log n)` になるが、整列済みの順に追加すると木が一直線に伸びて :math:`h = n - 1` となり、操作は :math:`O(n)` に劣化する。

この問題を解決するのが\ **平衡二分探索木**\ である。追加や削除のたびに回転と呼ばれる局所的な変形を行い、高さを常に :math:`O(\log n)` に保つ。代表的なものに AVL 木と赤黒木がある。平衡二分探索木は、ハッシュテーブルと異なり、キーの順序を保ったまま次の操作を :math:`O(\log n)` で提供できる。

* 最小値・最大値の取得
* あるキー以上で最小のキーの探索
* ある範囲に含まれるキーの列挙

Python の標準ライブラリには平衡二分探索木がない。整列済みのリストに対して ``bisect`` モジュールで二分探索を行えば、探索は :math:`O(\log n)` で行えるが、挿入と削除は :math:`O(n)` になる。

Union-Find
----------

**Union-Find**\ （素集合データ構造）は、要素を互いに素な集合に分けて管理し、次の 2 つの操作を提供する。

* union(x, y): :math:`x` を含む集合と :math:`y` を含む集合を合併する。
* find(x): :math:`x` を含む集合の代表元を返す。2 つの要素の find の結果が等しければ、両者は同じ集合に属する。

各集合を根付き木で表し、根を代表元とする。素朴に実装すると木が一直線に伸びて find が :math:`O(n)` になるが、次の 2 つの工夫を組み合わせると、1 操作あたりの償却計算量は :math:`O(\alpha(n))` になる。ここで :math:`\alpha(n)` は逆アッカーマン関数であり、現実的な :math:`n` に対しては 4 以下なので、実質的に定数とみなせる。

* union by size: 合併のとき、要素数の少ない木の根を、要素数の多い木の根の子にする。これだけで木の高さは :math:`O(\log n)` に抑えられる。
* 経路圧縮: find の途中で通ったノードを、全て根に直接つなぎ直す。

Union-Find は、第 2 章で述べた同値類を動的に管理するデータ構造であり、第 7 章のクラスカル法で「2 つの頂点が既に同じ木に属するか」を判定するのに使う。
