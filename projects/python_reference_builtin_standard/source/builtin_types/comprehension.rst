内包表記
========

既存のイテラブルから新しい ``list``/``dict``/``set`` を簡潔に生成するための構文。``for`` 文で書ける処理を1行で表現でき、Python では広く使われるイディオムになっている。

リスト内包表記
--------------

``[式 for 変数 in イテラブル]`` の形式で、新しい ``list`` を生成する。

.. code-block:: python

   >>> [x * x for x in range(5)]
   [0, 1, 4, 9, 16]

.. note::

   これは次の通常の ``for`` 文と同じ結果になる。

   .. code-block:: python

      >>> squares = []
      >>> for x in range(5):
      ...     squares.append(x * x)
      >>> squares
      [0, 1, 4, 9, 16]

条件によるフィルタ（if）
--------------------------

``if`` を末尾に付けると、条件を満たす要素だけを対象にする。

.. code-block:: python

   >>> [x for x in range(10) if x % 2 == 0]
   [0, 2, 4, 6, 8]

条件式（if / else）
----------------------

要素ごとに異なる値を生成したい場合は、``for`` の前に三項演算子形式の条件式を書く。末尾に付ける「フィルタの if」とは書く位置も意味も異なる点に注意する。

.. code-block:: python

   >>> ["偶数" if x % 2 == 0 else "奇数" for x in range(5)]
   ['偶数', '奇数', '偶数', '奇数', '偶数']

辞書内包表記・集合内包表記
-----------------------------

波括弧を使うと ``dict``\ （``{キー: 値 for ...}``）や ``set``\ （``{式 for ...}``）も同様に生成できる。

.. code-block:: python

   >>> {x: x * x for x in range(5)}
   {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
   >>> {x % 3 for x in range(10)}
   {0, 1, 2}

ネストした内包表記
--------------------

``for`` を複数並べると、多重ループを1つの内包表記で表現できる。

.. code-block:: python

   >>> matrix = [[1, 2], [3, 4], [5, 6]]
   >>> [x for row in matrix for x in row]
   [1, 2, 3, 4, 5, 6]

.. note::

   上の例は次の入れ子の ``for`` 文と同じ順序で評価される（外側から内側の順に ``for`` を並べる）。

   .. code-block:: python

      >>> result = []
      >>> for row in matrix:
      ...     for x in row:
      ...         result.append(x)

   ``for`` を重ねすぎると読みにくくなるため、2重程度を超える場合は通常の ``for`` 文に書き直した方が可読性が高くなることが多い。

ジェネレータ式
--------------

角括弧の代わりに丸括弧を使うと、リストを作らずに1要素ずつ遅延生成するジェネレータ式になる。大きなデータを扱う際にメモリを節約できる。

.. code-block:: python

   >>> gen = (x * x for x in range(5))
   >>> next(gen)
   0
   >>> next(gen)
   1

関数の唯一の引数として渡す場合は、丸括弧を省略できる。

.. code-block:: python

   >>> sum(x * x for x in range(5))
   30

.. note::

   :doc:`../builtins/iteration` の ``map``/``filter`` も同様に遅延評価されるイテレータを返す。既存の名前付き関数を渡すだけで済む場合や複数のイテラブルを同時に扱う場合は ``map``/``filter`` が簡潔になることもあるが、多くの場面では内包表記・ジェネレータ式の方が読みやすいとされる。
