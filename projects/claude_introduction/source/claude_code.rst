Claude Code 入門
==========================================

Claude Code とは
------------------------------------------

Claude Code は、Anthropic が提供するコーディングエージェントです。利用者が自然言語で作業を依頼すると、Claude がソースコードを読み、コマンドを実行し、ファイルを編集しながら作業を進めます。コードの調査、機能の実装、不具合の修正、テストの作成、リファクタリング、Git の操作など、開発作業の多くを任せられます。

Claude Code は次の環境で使えます。

* ターミナル（コマンドラインツール ``claude``）
* VS Code と JetBrains 系 IDE の拡張機能
* Claude のデスクトップアプリ
* Web ブラウザ（クラウド上の環境で実行）

本章では、すべての環境に共通する基本として、ターミナルでの使い方を説明します。

インストールと起動
------------------------------------------

インストーラーを使ってインストールします。

.. code-block:: console
   :caption: Claude Code のインストール
   :linenos:

   # macOS / Linux
   $ curl -fsSL https://claude.ai/install.sh | bash

   # Windows（PowerShell）
   PS> irm https://claude.ai/install.ps1 | iex

インストール後、作業したいプロジェクトのディレクトリで ``claude`` を実行します。初回は認証を求められるので、claude.ai の有料プランか Claude Console のアカウントでログインします。

.. code-block:: console
   :caption: Claude Code の起動
   :linenos:

   $ cd ~/projects/my-app
   $ claude

基本操作
------------------------------------------

起動すると対話画面になり、依頼を入力して Enter キーで送信します。Claude は必要に応じてファイルを読み、コマンドを実行し、変更を提案します。ファイルの編集やコマンドの実行の前には、既定では利用者の許可を求めます。

.. list-table:: 基本操作
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - 内容
   * - ``@`` に続けてファイル名を入力
     - そのファイルを参照させます。例：``@src/app.py のエラー処理を見直して``
   * - ``!`` に続けてコマンドを入力
     - Claude を介さずにシェルのコマンドを直接実行し、結果を会話に含めます
   * - Esc キー
     - Claude の作業を中断します。中断後に指示を出し直せます
   * - Esc キーを 2 回
     - 過去の時点に戻り、会話やファイルの変更を巻き戻します
   * - Shift + Tab キー
     - 権限モードを切り替えます（後述）
   * - ``/`` に続けてコマンド名を入力
     - スラッシュコマンドを実行します（後述）

主なスラッシュコマンド
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table:: 主なスラッシュコマンド
   :header-rows: 1
   :widths: 25 75

   * - コマンド
     - 内容
   * - ``/help``
     - 使い方とコマンドの一覧を表示します
   * - ``/init``
     - プロジェクトを調査し、CLAUDE.md の雛形を作成します
   * - ``/clear``
     - 会話の履歴を消去します。別の作業に移るときに使います
   * - ``/compact``
     - これまでの会話を要約して、コンテキストを節約します
   * - ``/model``
     - 使用するモデルを切り替えます
   * - ``/permissions``
     - ツールの使用許可の設定を確認、変更します
   * - ``/mcp``
     - MCP サーバーの接続状態を確認します
   * - ``/agents``
     - サブエージェントを作成、管理します

作業の進め方
------------------------------------------

Claude Code に大きな作業を任せるときは、:numref:`fig-claude-code-flow` の流れで進めると、手戻りを減らせます。

.. _fig-claude-code-flow:

.. graphviz::
   :caption: Claude Code での作業の流れ
   :align: center

   digraph flow {
     rankdir=TB;
     node [shape=box, style="rounded,filled", fillcolor="#EEF3FA", color="#4C78A8"];
     edge [color="#555555", fontsize=10];

     explore [label="調査\n関連するコードを読ませる"];
     plan    [label="計画\n方針を立てさせ、確認する"];
     impl    [label="実装\n計画に沿って変更させる"];
     verify  [label="検証\nテストと静的解析を実行させる"];
     commit  [label="記録\n差分を確認してコミット", fillcolor="#E8F5E9", color="#2E7D32"];

     explore -> plan -> impl -> verify -> commit;
     verify -> impl [label="失敗したら修正", style=dashed];
   }

#. **調査**：いきなり実装を頼まず、まず関連するコードを読ませ、現状を説明させます。
#. **計画**：変更の方針を立てさせ、内容を確認します。後述の計画モードを使うと、Claude はファイルを変更せずに調査と計画だけを行います。
#. **実装**：計画に合意したら、実装を依頼します。
#. **検証**：テストや静的解析を実行させ、失敗したら修正させます。検証の手段を用意しておくことが、品質を保つうえで最も重要です。
#. **記録**：変更内容を確認し、コミットします。こまめにコミットしておくと、問題があったときに戻しやすくなります。

依頼のこつ
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

* **具体的に頼む**：「テストを書いて」より「``src/order.py`` の ``calculate_total`` に、割引が 100% の場合と数量が 0 の場合のテストを追加して」のほうが、意図どおりの結果になります。
* **完了条件を示す**：「``pytest`` がすべて成功するまで修正して」のように、Claude が自分で確かめられる条件を示します。
* **作業ごとに会話を分ける**：別の作業に移るときは ``/clear`` で履歴を消します。無関係な履歴が残っていると、判断の質が下がり、利用量も増えます。
* **画面やエラーをそのまま渡す**：エラーメッセージやスクリーンショットは、要約せずにそのまま貼り付けます。

CLAUDE.md
------------------------------------------

:term:`CLAUDE.md` は、プロジェクトの情報や作業のルールを Claude Code に伝えるためのファイルです。セッションの開始時に自動的に読み込まれるため、毎回同じ説明をする必要がなくなります。

.. list-table:: CLAUDE.md の置き場所
   :header-rows: 1
   :widths: 35 65

   * - 場所
     - 用途
   * - プロジェクト直下の ``CLAUDE.md``
     - プロジェクト固有の情報。リポジトリに含めてチームで共有します
   * - サブディレクトリの ``CLAUDE.md``
     - そのディレクトリ配下で作業するときにだけ必要な情報
   * - ``~/.claude/CLAUDE.md``
     - すべてのプロジェクトに共通する個人の好み

CLAUDE.md には、Claude がコードを読むだけでは分からないこと、つまり、よく使うコマンド、コーディング規約、触れてはいけないファイル、作業時の注意を書きます。記述例を示します。

.. literalinclude:: ../examples/CLAUDE.sample.md
   :language: markdown
   :caption: CLAUDE.md の例（CLAUDE.sample.md）
   :linenos:

CLAUDE.md の内容は、毎回コンテキストに含まれます。長くなりすぎないよう、要点に絞って書いてください。``/init`` を実行すると、プロジェクトを調査して雛形を作成します。

権限モード
------------------------------------------

Claude Code が利用者の許可なしにどこまで操作してよいかは、:term:`権限モード`\ で切り替えます。

.. list-table:: 主な権限モード
   :header-rows: 1
   :widths: 25 75

   * - モード
     - 内容
   * - default
     - ファイルの編集やコマンドの実行のたびに許可を求めます
   * - acceptEdits
     - ファイルの編集は許可なしで行い、コマンドの実行には許可を求めます
   * - plan
     - 調査と計画だけを行い、ファイルの変更や、変更を伴うコマンドの実行はしません
   * - auto
     - 安全と判断された操作は自動で実行し、危険の可能性がある操作は止めます
   * - dontAsk
     - 設定ファイルで事前に許可した操作だけを実行し、それ以外は確認せずに拒否します。無人で動かす自動化向けです
   * - bypassPermissions
     - すべての操作を許可なしで実行します。外部から隔離された環境以外では使いません

慣れないうちは default で始め、Claude の振る舞いを確認しながら、信頼できる操作を後述の設定ファイルで許可していくのが安全です。

設定ファイル
------------------------------------------

Claude Code の設定は、``settings.json`` に書きます。

.. list-table:: 設定ファイルの置き場所
   :header-rows: 1
   :widths: 40 60

   * - 場所
     - 用途
   * - ``~/.claude/settings.json``
     - すべてのプロジェクトに共通する個人の設定
   * - ``.claude/settings.json``
     - プロジェクトの設定。リポジトリに含めてチームで共有します
   * - ``.claude/settings.local.json``
     - プロジェクトに対する個人の設定。リポジトリには含めません

フック
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

:term:`フック`\ は、Claude Code の動作の特定の時点で、指定したコマンドを自動的に実行する仕組みです。上の例の ``hooks`` では、Claude がファイルを編集するたびに flake8 を実行しています（13 〜 25 行目）。フックのコマンドが終了コード 2 で終わると、標準エラー出力の内容が Claude に伝えられます。この例では flake8 が違反を検出したときに終了コード 2 を返すようにしているため（20 行目）、Claude は違反の内容を読んで修正します。

.. list-table:: 主なフックの種類
   :header-rows: 1
   :widths: 28 72

   * - 種類
     - 実行される時点
   * - ``PreToolUse``
     - ツールを使う直前。コマンドの終了コードによって、ツールの使用を止めることもできます
   * - ``PostToolUse``
     - ツールを使った直後。整形ツールや静的解析の実行に使います
   * - ``UserPromptSubmit``
     - 利用者が依頼を送信したとき
   * - ``Stop``
     - Claude が応答を終えたとき。作業完了の通知などに使います
   * - ``SessionStart``
     - セッションを開始したとき

CLAUDE.md に書いた指示は Claude が判断して従うものですが、フックは必ず実行されます。「編集後は必ず整形する」のように例外なく守らせたい処理は、フックで実現します。

Claude Code の拡張
------------------------------------------

スキル
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

:term:`スキル`\ は、特定の作業の手順や知識をまとめたものです。``.claude/skills/<スキル名>/SKILL.md`` に置くと、Claude は関連する作業を頼まれたときに、そのスキルを読み込んで手順に従います。``/<スキル名>`` で明示的に呼び出すこともできます。

.. literalinclude:: ../examples/SKILL.sample.md
   :language: markdown
   :caption: スキルの例（SKILL.sample.md）
   :linenos:

先頭の ``name`` と ``description``\ （2 〜 3 行目）は常に Claude に示され、Claude はこの説明を見て、スキルを使うかどうかを判断します。本文は使うときにだけ読み込まれるため、スキルをたくさん用意してもコンテキストを圧迫しません。

サブエージェント
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

:term:`サブエージェント`\ は、特定の作業を担当する専用のエージェントです。メインの会話とは別のコンテキストで作業し、結果だけを返します。大量のファイルを読む調査や、独立した観点でのレビューを任せると、メインの会話のコンテキストを節約できます。

サブエージェントは ``.claude/agents/<名前>.md`` に定義します。``/agents`` コマンドで対話的に作成することもできます。

.. literalinclude:: ../examples/agent.sample.md
   :language: markdown
   :caption: サブエージェントの例（agent.sample.md）
   :linenos:

``tools`` で使えるツールを、``model`` で使うモデルを指定できます（4 〜 5 行目）。この例では、レビュー担当にファイルを編集する Edit や Write のツールを与えていません。

MCP サーバー
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

:doc:`mcp`\ で説明したとおり、MCP サーバーを登録すると、Claude Code から外部のサービスやデータベースを操作できます。課題管理サービスの MCP サーバーを登録すれば、「課題 123 の内容を読んで実装して」のような依頼ができるようになります。

自動化での利用
------------------------------------------

``-p`` オプションを付けると、Claude Code を対話画面なしで実行し、結果を標準出力に出力できます。シェルスクリプトや CI（継続的インテグレーション）に組み込めます。

.. code-block:: console
   :caption: 対話画面なしでの実行
   :linenos:

   # 結果をテキストで受け取る
   $ claude -p "src 配下の TODO コメントを一覧にして"

   # 結果を JSON で受け取り、jq で処理する
   $ claude -p "直近のコミットの変更点を要約して" --output-format json | jq -r .result

   # 標準入力からデータを渡す
   $ cat error.log | claude -p "このログからエラーの原因を推定して"

GitHub と連携すると、プルリクエストや課題のコメントで Claude に依頼し、レビューや修正を任せることもできます。より高度な自動化には、:doc:`agents`\ で説明する Claude Agent SDK を使います。

安全に使うために
------------------------------------------

* **権限は段階的に広げる**：最初は default モードで振る舞いを確認し、信頼できる操作だけを許可します。
* **機密情報を読ませない**：認証情報を含むファイルは、設定ファイルの ``deny`` で読み取りを禁止します。
* **変更は必ずレビューする**：Claude が作成したコードも、人が書いたコードと同じくレビューしてからマージします。
* **信頼できない内容に注意する**：外部から取得したファイルや Web ページに、Claude を誤った操作に誘導する指示が含まれている場合があります（:ref:`prompt-injection`\ 参照）。信頼できないリポジトリで作業するときは、権限を絞るか、隔離された環境を使います。
