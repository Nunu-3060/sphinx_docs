第 13 章 頂点アニメーション
===========================

頂点シェーダーでは、頂点の位置を自由に変えられる。この章では、この性質を使って、メッシュを波打たせる表現と、オブジェクトを常にカメラの方に向ける表現（ビルボード）を作る。

この章のサンプルコードは、``examples/chapter13`` フォルダーにある。

頂点アニメーションの特徴
------------------------

頂点アニメーションは、C# のスクリプトでメッシュの頂点を書き換える方法と比べて、次の特徴がある。

* GPU で計算するため、頂点の数が多くても高速である。
* メッシュのデータ自体は変わらないため、物理演算の当たり判定（Collider）には反映されない。
* 頂点を動かした結果は、カメラの視錐台によるカリングに反映されない。メッシュの元の範囲（バウンディングボックス）が画面の外にあると、動かした頂点が画面の中にあっても描画されないことがある。

頂点の変位
~~~~~~~~~~

頂点の変位は、次の式で求めている。:math:`A` は振幅（``_Amplitude``）、:math:`f` は周波数（``_Frequency``）、:math:`s` は速さ（``_Speed``）、:math:`t` は経過時間（``_Time.y``）である。

.. math::

   y = A \sin(f x + s t)

:math:`t` が増えるにつれて波の形が x の負の方向へ移動し、波が流れているように見える。

法線の再計算
~~~~~~~~~~~~

頂点を動かすと、面の向きが変わるため、メッシュに記録された元の法線は使えなくなる。そのまま使うと、形は波打っているのに陰影は平らなままになる。そこで、波の傾きから法線を計算し直している。

波の式を x で微分すると、傾きは :math:`\frac{dy}{dx} = A f \cos(f x + s t)` になる。x 方向に 1 進むと y が傾きの分だけ変わるので、表面に沿った方向（接線）は :math:`(1,\ \frac{dy}{dx},\ 0)` である。法線はこれに垂直な方向なので、次のようになる。

.. math::

   \mathbf{n} = \mathrm{normalize}\left(-\frac{dy}{dx},\ 1,\ 0\right)

接線との内積を計算すると :math:`-\frac{dy}{dx} + \frac{dy}{dx} = 0` となり、垂直であることが確かめられる。

.. note::

   Plane の頂点は 1 単位ごとにしかないため、``_Frequency`` を大きくすると、波の山と谷の間に頂点がなくなり、波の形が崩れる。細かい波を表現するには、頂点の多いメッシュを使う必要がある。テッセレーションで実行時に頂点を増やす方法もあるが、動作する環境が限られるため、本資料では扱わない（第 4 章を参照）。

ビルボード
----------

ビルボードは、板ポリゴンを常にカメラの方に向けて描画する技法である。木や草、炎、パーティクルなどを、少ない頂点で表現するときに使う。

:menuselection:`GameObject --> 3D Object --> Quad` で Quad を作成し、このシェーダーのマテリアルを設定する。Scene ビューでカメラを回り込ませても、Quad は常にこちらを向いて表示される。

ビルボードのしくみ
~~~~~~~~~~~~~~~~~~

ビュー空間では、x 軸が画面の右、y 軸が画面の上を向いている（第 3 章を参照）。そのため、ビュー空間で頂点を xy 方向にずらすと、頂点は常に画面と平行な面に並ぶ。

サンプルでは、次の手順で頂点の位置を求めている。

#. オブジェクトの中心（オブジェクト空間の原点）を、ワールド空間を経由してビュー空間に変換する。
#. ビュー空間の中心の位置に、頂点のオブジェクト空間の xy 座標を加える。Quad の頂点は、オブジェクト空間の XY 平面上にあるため、これで画面と平行な Quad になる。
#. ``TransformWViewToHClip`` 関数で、ビュー空間からクリップ空間に変換する。

モデル変換の行列を頂点に直接適用しないため、Transform の Rotation と Scale は反映されない。大きさを変えたい場合は、シェーダーにプロパティを追加して、xy 座標に掛ける必要がある。

バッチングの無効化
~~~~~~~~~~~~~~~~~~

サブシェーダーのタグで ``"DisableBatching" = "True"`` を指定している。Unity の静的バッチングなどは、複数のオブジェクトのメッシュを 1 つにまとめ、頂点をワールド空間の座標にして描画する。その場合、オブジェクト空間の原点が各オブジェクトの中心ではなくなるため、ビルボードの計算が正しく行えない。このタグを指定すると、このシェーダーを使うオブジェクトはバッチングの対象から外れる。
