用語集
==========================================

本書で使う主な用語をまとめる。

.. glossary::

   Chain-of-Thought
      答えを出す前に、考える過程を段階的に出力させる手法。複雑な問題で精度が上がることが知られている。

   Evals
      AI の出力の品質を測るための評価。評価ケース（タスクと期待結果）、採点器、指標などからなる。

   few-shot プロンプト
      期待する入力と出力の例をいくつか含めたプロンプト。出力の形式や判断の基準を例で示す。

   Human-in-the-loop
      AI による処理の流れの中に、人間による確認や承認を組み込むこと。

   LLM
      Large Language Model（大規模言語モデル）の略。大量のテキストで学習し、入力に続くテキストを生成するモデル。

   MCP
      Model Context Protocol の略。AI アプリケーションと外部のツールやデータを接続するための標準規格。

   pass@k
      :math:`k` 回試行して 1 回以上成功する確率。:math:`k` 回すべて成功する確率は :math:`\mathrm{pass}^k` で表す。

   RAG
      Retrieval-Augmented Generation（検索拡張生成）の略。検索で得た情報をコンテキストに加えて生成させる手法。

   Vibe Coding
      AI が生成したコードの中身をほとんど読まず、動かした結果だけを見ながら、対話で修正を頼み続ける開発の仕方。

   受け入れ条件
      機能が完成したと判断するための、検証できる条件。

   エージェント
      目標を与えられると、どのツールをどの順で使うかを自ら判断しながら作業を進める仕組み。

   オーケストレーション
      複数のエージェントの役割分担と作業の流れを設計し、制御すること。

   規約ファイル
      プロジェクトの情報や作業のルールを書き、エージェントがセッションの開始時など（ファイルによっては該当ディレクトリで作業するとき）に読み込むファイル。``AGENTS.md``、``CLAUDE.md`` など。

   計画モード
      Claude Code で、ファイルを変更せずに調査と計画だけを行うモード。

   権限モード
      Claude Code が利用者の許可なしにどこまで操作してよいかを決める設定。

   構造化出力
      出力が指定した JSON スキーマに必ず従うようにする機能。

   コーディングエージェント
      ソフトウェア開発用のエージェント。ソースコードを読み、ファイルを編集し、コマンドを実行しながら開発作業を進める。

   コンテキスト
      推論のたびにモデルへ渡す情報全体。システムプロンプト、ツール定義、会話履歴、ツールの実行結果などからなる。

   コンテキストウィンドウ
      モデルが一度に扱える入力と出力の合計の上限。トークン数で表す。

   コンテキストエンジニアリング
      モデルに渡す情報全体を設計し、管理する技術。

   コンパクション
      会話履歴などのうち古い部分を要約に置き換え、コンテキストを空けること。

   サブエージェント
      主となるエージェントから作業の一部を任される別のエージェント。独立したコンテキストで作業し、結果だけを返す。

   サンドボックス
      プログラムの実行環境を隔離し、ファイルシステムやネットワークへのアクセスを制限する仕組み。

   システムプロンプト
      会話全体を通じて適用される指示。役割、制約、出力形式などを書く。

   仕様駆動開発
      実装の前に仕様書を作り、それを基準として AI に計画・実装・検証をさせる開発の進め方。

   スキル
      Claude Code などで、特定の作業の手順や知識をまとめたもの。必要なときにだけ読み込まれる。

   知識のカットオフ
      モデルの学習データが収集された時点。それより後の出来事や変更をモデルは知らない。

   ツール呼び出し
      モデルが、テキストの代わりに「このツールをこの引数で呼び出してほしい」という要求を出力する機能。ツールの実行はアプリケーションが行う。

   トークン
      LLM がテキストを扱う単位。英語ではおおむね単語や単語の一部、日本語では 1 文字から数文字に相当する。

   ハーネス
      エージェントのうちモデル以外のすべて。ツール、実行環境、制約（権限など）、検証の仕組みなど。

   ハーネスエンジニアリング
      モデルを動かすための道具、実行環境、制約、検証の仕組みを設計し、改善する技術。

   ハルシネーション
      LLM が事実と異なる内容をもっともらしく出力すること。

   評価駆動開発
      AI の出力の品質を測る評価を先に用意し、その結果に基づいて変更を判断する開発の進め方。

   フック
      エージェントの動作の特定の時点で、指定した処理を自動的に実行する仕組み。

   プロンプト
      LLM への指示文。

   プロンプトインジェクション
      AI が処理するデータの中に指示を紛れ込ませ、AI に意図しない操作をさせる攻撃。

   プロンプトエンジニアリング
      指示文を工夫して、意図した出力を得る技術。

   マルチエージェント
      複数のエージェントに作業を分担させる構成。

   ループエンジニアリング
      本書では、「計画・実行・検証・修正」の反復の構造、終了条件、人間の関与点を設計する技術を指す。
