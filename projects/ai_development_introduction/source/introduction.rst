はじめに
==========================================

本書の目的
------------------------------------------

AI を使ったソフトウェア開発は、ここ数年で大きく変わった。当初はエディタがコードの続きを提案する「補完」が中心だったが、現在では AI がリポジトリを調べ、コードを書き、テストを実行し、失敗すれば自ら修正する「エージェント」による開発が広まっている。

それに伴い、AI をうまく使うための技術も「プロンプトエンジニアリング」「コンテキストエンジニアリング」「ハーネスエンジニアリング」など、さまざまな名前で語られるようになった。しかし、これらの言葉は互いにどう関係するのか、どれを学べばよいのかが分かりにくい。

本書の目的は、これらの手法を 1 つの枠組みで整理し、それぞれが「何を対象とし」「何を解決し」「どう実践するか」を説明することである。本書を読み終えたとき、次のことができる状態を目指す。

* 各手法の対象と目的を説明し、互いの関係を図示できる。
* 自分の開発で起きている問題が、どの手法で対処すべきものかを判断できる。
* AI に開発作業を任せるための環境（規約ファイル、テスト、権限、フック）を整えられる。
* AI の出力の品質を、勘ではなく評価によって改善できる。

対象読者と前提知識
------------------------------------------

本書は、次のような読者を想定する。

* Python などのプログラミング言語で開発した経験がある。
* Git、テスト、CI（継続的インテグレーション）など、一般的な開発の道具を使ったことがある。
* ChatGPT や Claude などの対話型 AI を使ったことはあるが、開発手法として体系的には学んでいない。

LLM（大規模言語モデル）の内部構造や機械学習の知識は前提としない。開発者が知っておくべき LLM の性質は :doc:`overview`\ で説明する。

本書の範囲
------------------------------------------

本書は「学習済みの LLM を使って、ソフトウェアを開発する」ための手法を扱う。次の内容は扱わない。

* LLM の学習やファインチューニング
* LLM を組み込んだ製品（チャットボットなど）の設計そのもの

ただし、LLM を組み込んだアプリケーションを作る場合にも、本書の手法の多くはそのまま当てはまる。例えば、:doc:`prompt_engineering`\ や\ :doc:`eval_driven`\ の内容は、AI 機能を持つ製品の開発にも使える。

本書の構成
------------------------------------------

.. list-table:: 本書の構成
   :header-rows: 1
   :widths: 30 70

   * - 章
     - 内容
   * - :doc:`overview`
     - LLM の基本的な性質と、各手法の関係を示す全体像
   * - :doc:`prompt_engineering`
     - 指示文そのものの書き方
   * - :doc:`context_engineering`
     - モデルに渡す情報全体の設計
   * - :doc:`harness_engineering`
     - モデルを動かすための道具・環境・制約の設計
   * - :doc:`loop_engineering`
     - 「計画・実行・検証・修正」の反復の設計
   * - :doc:`spec_driven`
     - 仕様書を起点に AI に実装させる手法
   * - :doc:`eval_driven`
     - 評価によって AI の出力の品質を測り、改善する手法
   * - :doc:`multi_agent`
     - 複数のエージェントに作業を分担させる手法
   * - :doc:`vibe_coding`
     - 雰囲気で AI に任せる開発と、規律ある開発の対比
   * - :doc:`process`
     - 開発工程とチームへの適用
   * - :doc:`practice_claude_code`
     - Claude Code を題材にした実践
   * - :doc:`risks`
     - リスクと品質管理
   * - :doc:`summary`
     - 各手法の比較とまとめ

:doc:`prompt_engineering`\ から\ :doc:`loop_engineering`\ までが本書の中心である。:doc:`spec_driven`\ から :doc:`vibe_coding`\ までは、中心の 4 つの手法を組み合わせた、より具体的な開発の進め方を扱う。

表記とサンプルコード
------------------------------------------

* 本書の情報は 2026 年 10 月時点のものである。AI の分野は変化が速く、製品の機能や名称は変わりうる。最新の情報は\ :doc:`references`\ に挙げた公式文書で確認してほしい。
* 本書の用語は\ :doc:`glossary`\ にまとめた。
* サンプルコードは\ :doc:`examples`\ からダウンロードできる。実際の LLM API の代わりに、応答を模擬するクライアントを使うため、API キーなしで実行できる。
* 「〜エンジニアリング」という呼び名のうち、プロンプトエンジニアリング以外は比較的新しく、定義が定まりきっていないものもある。本書では、各章の冒頭で本書における定義を示す。
