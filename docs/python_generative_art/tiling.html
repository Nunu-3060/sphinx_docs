タイリングパターン

トルシェ・タイル

トルシェ・タイル（Truchet tiles）は、正方形の格子に決まった数種類の「タイル」を 1 枚ずつ並べていくだけの単純な仕組みでありながら、タイルごとの向き（回転）を変えるだけで、迷路のように入り組んだ連続的な模様が生まれる技法である。基礎編：ジェネラティブアート特有の設計方針で触れた「パラメータを格子状に変えながら同じ描画関数を繰り返し呼び出す」というグリッド配置の考え方を、そのまま具体的な作品に落とし込んだものと言える。

古典的なトルシェ・タイルは、正方形の対角線上にある 2 つの角を中心とした、半径がタイルの半分の四分円弧 2 本から成る。弧の両端は必ず辺の中点に来るため、どちらの対角線に弧を配置するか（2 通りの向き）をタイルごとに選ぶだけで、隣り合うタイルの弧がつながり、途切れない曲線の連なりになる。

examples/truchet.py の draw_arc_tile 関数
 1def draw_arc_tile(
 2    draw: ImageDraw.ImageDraw,
 3    x0: float,
 4    y0: float,
 5    size: float,
 6    orientation: int,
 7    color: tuple[int, int, int] = (30, 30, 30),
 8    width: int = 2,
 9) -> None:
10    """四分円弧2本から成る、古典的なトルシェ・タイルを1枚描く。
11
12    タイルは対角線上にある2つの角を中心とした半径 ``size/2`` の
13    四分円弧2本から成る。``orientation`` (0か1) で、どちらの対角線に
14    弧を配置するかが決まる。弧の両端は必ず辺の中点に来るため、
15    隣り合うタイルの向きの組み合わせ次第で弧どうしがつながり、
16    連続した曲線になる。
17    """
18    r: float = size / 2.0
19    if orientation == 0:
20        draw.arc(
21            [x0 - r, y0 - r, x0 + r, y0 + r],
22            start=0,
23            end=90,
24            fill=color,
25            width=width,
26        )
27        draw.arc(
28            [x0 + size - r, y0 + size - r, x0 + size + r, y0 + size + r],
29            start=180,
30            end=270,
31            fill=color,
32            width=width,
33        )
34    else:
35        draw.arc(
36            [x0 + size - r, y0 - r, x0 + size + r, y0 + r],
37            start=90,
38            end=180,
39            fill=color,
40            width=width,
41        )
42        draw.arc(
43            [x0 - r, y0 + size - r, x0 + r, y0 + size + r],
44            start=270,
45            end=360,
46            fill=color,
47            width=width,
48        )

各タイルの向きを一様乱数でランダムに選ぶと、迷路のような、あるいは配管が入り組んだような模様になる。

タイルの中身を変える

タイルの模様そのものを差し替えるだけで、生成される模様の印象はまったく違うものになる。四分円弧の代わりに対角線 1 本だけを引くタイルにすると、弧のようにはなめらかにつながらず、山型・谷型が入り組んだジグザグ模様（ヘリンボーンに近い見た目）になる。

タイルの向きをノイズで決める

向きの選び方を一様乱数からパーリンノイズに変えると、模様の印象が大きく変わる。ノイズを使った表現の fbm2d の値の符号（正か負か）でタイルの向きを決めると、ノイズが近傍でなめらかに変化する性質がそのままタイルの向きの空間的なまとまりに反映され、ランダム配置のような無秩序さではなく、渦を巻いて流れるような有機的な模様になる。

同じ「格子状にタイルを並べる」という骨格でも、(1) タイルの模様そのもの、(2) タイルの向きを決める規則、の 2 つを差し替えるだけで表現の幅は大きく広がる。タイルの種類を増やす（例えば直線・曲線・無地を混在させる）、あるいは向きの選び方に別の規則（例えば距離関数による形状表現のボロノイ図の領域ごとに向きをそろえる）を組み込むといった発展も考えられる。

組み紐模様（編み込み表現）

ここまでの向きの選び方（乱数・ノイズ）は、いずれもタイル 1 枚 1 枚を独立に選んでよかった。しかし、タイルどうしが「上下関係」を持つような模様――例えば編み込みやバスケット編みのような表現――では、隣り合うタイルの選択が独立ではいられない。あるタイルで縦帯が横帯の上を通っていれば、その右隣・下隣のタイルでは、同じ縦帯・横帯が逆に下を通っていないと、編み目としてのつじつまが合わなくなるためである。

そこで、タイルごとに縦横どちらを上にするかを、(row + col) % 2 という市松模様の規則で決め打ちにする。ランダムに選んでしまうと、同じ帯が 2 マス連続で「上」になってしまい、編み込みが破綻する。

正方形以外のタイリング

平面を隙間なく敷き詰められる正多角形は、正方形だけではない。正三角形・正方形・正六角形の 3 種類だけが、単独で平面を隙間なく埋め尽くせる正多角形であることが知られている（内角がそれぞれ 60 度・90 度・120 度で、頂点の周りにちょうど 360 度分並べられるため）。ここではトルシェ・タイルからいったん離れ、三角形・六角形それぞれの格子を作り、セルごとにランダムな色を塗ってみる。

正三角形格子は、上向き・下向きの三角形を交互に並べることで作れる。1 行に cols * 2 枚の三角形を並べ、それを rows 行分積み重ねる。

examples/polygon_tiling.py の triangular_mesh 関数
 1def triangular_mesh(
 2    cols: int, rows: int, size: float
 3) -> list[list[tuple[float, float]]]:
 4    """正三角形格子の、各三角形の頂点リストを返す。
 5
 6    1行につき上向き・下向きの三角形が交互に ``cols * 2`` 枚並び、
 7    それが ``rows`` 行分続く。辺の長さはすべて ``size`` で揃う。
 8    """
 9    height: float = size * (3 ** 0.5) / 2
10    half: float = size / 2
11    triangles: list[list[tuple[float, float]]] = []
12
13    for row in range(rows):
14        y_top: float = row * height
15        y_bot: float = y_top + height
16        for i in range(cols * 2):
17            x_left: float = i * half
18            x_mid: float = x_left + half
19            x_right: float = x_left + size
20            if i % 2 == 0:
21                triangles.append(
22                    [(x_left, y_bot), (x_right, y_bot), (x_mid, y_top)]
23                )
24            else:
25                triangles.append(
26                    [(x_left, y_top), (x_right, y_top), (x_mid, y_bot)]
27                )
28
29    return triangles

正六角形格子は、1 行おきに半セル分ずらして六角形を並べることで作れる（ハニカム構造と同じ配置）。

 2    cols: int, rows: int, size: float

 8

正方形は角が 4 つとも直角で規則正しい反面、やや硬い印象になりやすい。三角形はより鋭く動きのある、六角形はより有機的で自然物（蜂の巣、亀の甲羅など）を思わせる印象になる。トルシェ・タイルの弧や対角線を三角形・六角形のセルに合わせて設計し直せば、この 2 つの技法を組み合わせることもできる。

ワン・タイル（辺の制約充足）

ここまでのタイル選択は、乱数任せか、市松模様のような単純な決め打ちのどちらかだった。ワン・タイル（Wang tiles）は、これとは異なる第 3 の考え方――隣り合うタイルの辺が必ず一致するように配置する、制約充足に基づくタイリングを示す。

本来のワン・タイルは、あらかじめ用意したタイル集合の中から、周囲の制約を満たすタイルを探索して 1 枚ずつ配置していく。ここでは探索を行わない簡単な方法として、格子の内部にある縦線・横線それぞれに先にラベル（色）をランダムに割り当ててしまう。各タイルは、上下左右の境界線のラベルに従って 4 枚の三角形に塗り分けられるため、隣接するタイルの境界では、共有する線のラベルを通じて自動的に色が一致する。

隣接するタイルの同じ色の三角形どうしがつながり、タイルの境界をまたいだひし形の模様が浮かび上がる。トルシェ・タイルが「1 枚のタイルの中で完結する模様」だったのに対し、ワン・タイルは「タイルをまたいで初めて模様が完結する」という違いがある。

Wave Function Collapse（制約の伝播）

ワン・タイルの節では、辺のラベルを先に全て決めてしまうことで、探索をせずに隣接の制約を満たした。しかし、使えるタイルの種類が限られている場合、この方法は使えない。例えば、管が 1 辺にしかつながらない「行き止まり」のタイルを含まない配管タイルの組では、辺のラベルを独立に決めると、行き止まりのタイルが必要なセルが生じてしまう。Wave Function Collapse（WFC）は、Maxim Gumin が 2016 年に公開した手法で、こうした制約を満たすタイルの配置を、セルを 1 つずつ確定させながら求めていく。名前は量子力学の「波動関数の収縮」にちなむが、その中身は、制約充足問題の解法として知られる「制約の伝播」と「選択肢の少ない変数から決める」という工夫の組み合わせである。

WFC では、格子の各セルに、まだ置ける可能性のあるタイルの集合（候補）を持たせる。最初は全てのセルが全てのタイルを候補に持ち、次の 2 つの操作を、全てのセルの候補が 1 つになるまで繰り返す。

観測（observe）

候補がもっとも少ないセルを 1 つ選び、候補の中から 1 枚をランダムに選んで確定させる。選択肢の少ないセルを後回しにすると、周りが先に決まって候補がなくなりやすいため、候補の少ないセルから決めていく。Gumin の実装では、候補の数の代わりに、タイルの重みを考慮したエントロピーがもっとも小さいセルを選ぶ。

伝播（propagate）

確定したセルの隣のセルから、辺がつながらなくなった候補を取り除く。候補が減ると、さらにその隣のセルでも、つながる相手を失う候補が出ることがある。そのため、候補が変化しなくなるまで、この削減を連鎖的に繰り返す。

ここでは、上下左右の各辺に管がつながるかどうか（1 か 0）で決まる配管タイルを使う。4 辺の組み合わせ 16 通りのうち、行き止まりの 4 通りを除いた 12 枚で、隣り合うタイルは、接する辺の値が一致していなければならない。

examples/wfc.py の pipe_tiles 関数
 1def pipe_tiles() -> np.ndarray:
 2    """配管タイルの一覧を、形状 (タイル数, 4) の配列で返す。
 3
 4    各行は上・右・下・左の辺に管がつながっているか(1)いないか(0)を
 5    表す。4辺の 0/1 の組み合わせ16通りのうち、管が1辺にしか
 6    つながらない「行き止まり」の4通りを除いた12枚を使う。
 7    """
 8    tiles: list[list[int]] = []
 9    for code in range(16):
10        edges: list[int] = [(code >> d) & 1 for d in range(4)]
11        if sum(edges) != 1:
12            tiles.append(edges)
13    return np.array(tiles)
examples/wfc.py の compatibility 関数
 1def compatibility(tiles: np.ndarray) -> np.ndarray:
 2    """方向ごとのタイルの隣接可否を、形状 (4, T, T) の真偽値配列で返す。
 3
 4    ``result[d, a, b]`` は、タイル ``a`` の方向 ``d`` の隣にタイル ``b``
 5    を置けるかどうか(``a`` の辺 ``d`` と ``b`` の反対側の辺が一致するか)。
 6    """
 7    return np.stack(
 8        [
 9            tiles[:, d, np.newaxis] == tiles[np.newaxis, :, (d + 2) % 4]
10            for d in range(4)
11        ]
12    )

伝播では、確定したセル（または候補が減ったセル）に残っている候補のどれか 1 つとでもつながるタイルだけを、隣のセルの候補に残す。候補が減ったセルはスタックに積み、スタックが空になるまで同じ処理を続ける。

examples/wfc.py の _propagate 関数
 1def _propagate(
 2    wave: np.ndarray, compat: np.ndarray, stack: list[tuple[int, int]]
 3) -> bool:
 4    """``stack`` のセルから候補の削減を伝播させる。矛盾が起きたら False。"""
 5    rows: int
 6    cols: int
 7    rows, cols = wave.shape[:2]
 8    while stack:
 9        r, c = stack.pop()
10        for d, (dr, dc) in enumerate(_OFFSETS):
11            nr: int = r + dr
12            nc: int = c + dc
13            if not (0 <= nr < rows and 0 <= nc < cols):
14                continue
15            # (r, c) に残っている候補のどれか1つとでもつながるタイルだけ残す。
16            allowed: np.ndarray = compat[d][wave[r, c]].any(axis=0)
17            reduced: np.ndarray = wave[nr, nc] & allowed
18            if not reduced.any():
19                return False
20            if not np.array_equal(reduced, wave[nr, nc]):
21                wave[nr, nc] = reduced
22                stack.append((nr, nc))
23    return True

格子の外周のセルは、外側へ向かう辺に管がつながらないタイルだけを候補として始める。そのため、管は全て画面の中で閉じる。途中で候補が 1 つも残らないセルが出る（矛盾する）と、それ以上は進められないため、本実装では最初からやり直している。この配管タイルの組では、作例と同じ条件で 50 回試しても矛盾は起きなかったが、タイルの組によっては矛盾が起きやすくなる。

examples/wfc.py の wave_function_collapse 関数
 1def wave_function_collapse(
 2    tiles: np.ndarray,
 3    weights: np.ndarray,
 4    rows: int,
 5    cols: int,
 6    rng: np.random.Generator,
 7    max_attempts: int = 20,
 8) -> np.ndarray:
 9    """WFC でタイルを配置し、形状 (rows, cols) のタイル番号配列を返す。
10
11    格子の外周では、外側へ向かう辺に管がつながらないタイルだけを
12    候補として始める。候補が1つも残らないセルが出る(矛盾する)と、
13    それ以上は進められないため、最初からやり直す。
14    """
15    compat: np.ndarray = compatibility(tiles)
16    closed: np.ndarray = tiles == 0  # closed[t, d]: タイル t の辺 d が空き
17
18    for _ in range(max_attempts):
19        wave: np.ndarray = np.ones((rows, cols, len(tiles)), dtype=bool)
20        wave[0, :] &= closed[:, 0]
21        wave[:, -1] &= closed[:, 1]
22        wave[-1, :] &= closed[:, 2]
23        wave[:, 0] &= closed[:, 3]
24        ok: bool = _propagate(
25            wave, compat, [(r, c) for r in range(rows) for c in range(cols)]
26        )
27
28        while ok:
29            counts: np.ndarray = wave.sum(axis=2)
30            if (counts == 1).all():
31                return wave.argmax(axis=2)
32
33            # 観測: 候補がもっとも少ないセル(同数なら乱数で選ぶ)を確定させる。
34            score: np.ndarray = np.where(
35                counts > 1, counts + rng.random((rows, cols)), np.inf
36            )
37            r, c = np.unravel_index(int(np.argmin(score)), (rows, cols))
38            candidates: np.ndarray = np.flatnonzero(wave[r, c])
39            p: np.ndarray = weights[candidates] / weights[candidates].sum()
40            chosen: int = int(rng.choice(candidates, p=p))
41            wave[r, c] = False
42            wave[r, c, chosen] = True
43
44            ok = _propagate(wave, compat, [(int(r), int(c))])
45
46    raise RuntimeError("矛盾が解消できず、タイルを配置できなかった。")

タイルを選ぶときの重みを変えるだけで、同じ制約から印象の異なる模様が得られる。全てのタイルを同じ重みで選ぶと、管が密に入り組んだ網目になる（左）。空白と直線のタイルの重みを大きくし、分岐（T 字と十字）の重みを小さくすると、長い管がまばらに走る模様になる（右）。

Gumin の WFC には、本節で扱ったタイルの辺だけで隣接関係を決める方式（simple tiled model）のほかに、見本の画像から小さな局所パターンを切り出し、その重なり方を制約として使う方式（overlapping model）もある。後者を使うと、見本の画像に似た模様を任意の大きさで生成できる。

迷路生成アルゴリズム

ワン・タイルと WFC は、隣接するタイルの辺が一致するという制約を満たすようにタイルを選んでいた。迷路もまた、「隣り合うセルの間に壁を残すか、通路として開けるか」を、迷路全体が行き止まりなく 1 つにつながるように決める、セル間の関係を無視できないタイリングの一種として捉えられる。ここでは再帰的バックトラッキング法で迷路を生成する。

  1. 全てのセルを未訪問、全ての壁をありとする。

  2. 適当なセルから出発し、隣接する未訪問セルへランダムに移動しながら、通った壁を取り除く。今いるセルをスタックに積んでおく。

  3. 未訪問の隣接セルがなくなったら、スタックを 1 つ戻って続きを探す。

  4. スタックが空になったら終了する。

深さ優先探索でスタックに退避と復帰を繰り返しながら穴を掘り進めるこの手順は、スタックに「後で戻ってくる場所」を記録しながら木構造をたどる探索に共通する骨格を持つ（同じ考え方は、後のフラクタルで扱う L-system が [ ] でタートルの位置を退避・復帰させながら枝分かれを描く場面にも登場する）。実際、この手順は必ず「閉路を持たない、行き止まりのない 1 本道が張り巡らされた木構造の迷路」を作る。

examples/maze.py の generate_maze 関数
 1def generate_maze(
 2    cols: int, rows: int, rng: np.random.Generator
 3) -> np.ndarray:
 4    """再帰的バックトラッキング法で迷路を生成する。
 5
 6    戻り値は ``(rows, cols, 4)`` の真偽値配列で、``walls[r, c, d]`` が
 7    真ならセル ``(r, c)`` の向き ``d`` (北・東・南・西) に壁がある
 8    ことを表す。再帰呼び出しではなく明示的なスタックを使うことで、
 9    セル数が多い場合でも Python の再帰上限に引っかからないようにして
10    いる。
11    """
12    walls: np.ndarray = np.ones((rows, cols, 4), dtype=bool)
13    visited: np.ndarray = np.zeros((rows, cols), dtype=bool)
14
15    stack: list[tuple[int, int]] = [(0, 0)]
16    visited[0, 0] = True
17
18    while stack:
19        r, c = stack[-1]
20        candidates: list[tuple[int, int, int]] = []
21        for d in range(4):
22            nr, nc = r + _DR[d], c + _DC[d]
23            if 0 <= nr < rows and 0 <= nc < cols and not visited[nr, nc]:
24                candidates.append((d, nr, nc))
25
26        if not candidates:
27            stack.pop()
28            continue
29
30        d, nr, nc = candidates[rng.integers(len(candidates))]
31        walls[r, c, d] = False
32        walls[nr, nc, (d + 2) % 4] = False
33        visited[nr, nc] = True
34        stack.append((nr, nc))
35
36    return walls

迷路が閉路を持たない木構造であることから、2 点を結ぶ経路はそもそも 1 本しかない。したがって、幅優先探索でその唯一の経路を見つけるだけで最短経路（かつ唯一の経路）が求まる。

examples/maze.py の solve_maze 関数
 1def solve_maze(
 2    walls: np.ndarray, start: tuple[int, int], goal: tuple[int, int]
 3) -> list[tuple[int, int]]:
 4    """幅優先探索で ``start`` から ``goal`` までの最短経路を求める。
 5
 6    再帰的バックトラッキング法で作った迷路は閉路を持たない木構造なので、
 7    2点を結ぶ経路はそもそも1本しかない。幅優先探索はその唯一の経路を
 8    最短距離として見つけ出す。
 9    """
10    rows, cols, _ = walls.shape
11    came_from: dict[tuple[int, int], tuple[int, int]] = {}
12    visited: set[tuple[int, int]] = {start}
13    queue: deque[tuple[int, int]] = deque([start])
14
15    while queue:
16        r, c = queue.popleft()
17        if (r, c) == goal:
18            break
19        for d in range(4):
20            if walls[r, c, d]:
21                continue
22            nr, nc = r + _DR[d], c + _DC[d]
23            if 0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in visited:
24                visited.add((nr, nc))
25                came_from[(nr, nc)] = (r, c)
26                queue.append((nr, nc))
27
28    path: list[tuple[int, int]] = [goal]
29    while path[-1] != start:
30        path.append(came_from[path[-1]])
31    path.reverse()
32    return path

ワン・タイルや WFC が「隣接するタイルの辺の情報」から模様を決めていたのに対し、迷路生成は「これまでに訪れたセルの履歴」というスタックに依存する点が異なる。同じ格子を土台にしていても、セル間の関係をどう設計するか（独立に選ぶか、ラベルを一致させるか、制約を伝播させるか、訪問履歴を参照するか）によって、生成される構造の性質がまったく変わってくる。

再帰的分割

ここまでのタイリングは、大きさのそろったセルを格子状に並べることを出発点にしていた。再帰的分割（recursive subdivision）は逆に、画面全体を 1 つの領域とみなしてそれを分け、分けた領域それぞれにまた同じ分割を適用する、という再帰的な手続きで画面を区切っていく。分割を続けるか止めるかの規則を変えるだけで、区画の大きさの分布を自由に設計できる。

もっとも単純な例は、矩形を 2 つに分け続ける方法である。本実装では、矩形の長いほうの辺を、その 30〜70% の位置で分割する。分割が深くなるほど分割を止める確率を上げ（ただし最初の 2 段は必ず分割する）、辺が短くなりすぎる場合にも分割を止める。こうすると、大きな矩形と小さな矩形が混ざった構成になる。

examples/subdivision.py の split_rect 関数
 1def split_rect(
 2    rect: Rect,
 3    rng: np.random.Generator,
 4    depth: int = 0,
 5    max_depth: int = 6,
 6    min_size: float = 40.0,
 7) -> list[Rect]:
 8    """矩形を再帰的に2分割し、それ以上分割しなかった矩形のリストを返す。
 9
10    長いほうの辺に垂直な線で、辺の 30〜70% の位置から選んだ場所で
11    分割する。深くなるほど分割を止める確率を上げることで、大きな
12    矩形と小さな矩形が混ざった構成になる(最初の2段は必ず分割する)。
13    分割後の辺が ``min_size``
14    より短くなる場合や、``max_depth`` に達した場合も分割を止める。
15    """
16    left, top, right, bottom = rect
17    width: float = right - left
18    height: float = bottom - top
19    longer: float = max(width, height)
20
21    stop_probability: float = 0.0 if depth < 2 else 0.6 * depth / max_depth
22    too_small: bool = longer < 2 * min_size
23    if depth >= max_depth or too_small or rng.random() < stop_probability:
24        return [rect]
25
26    ratio: float = float(rng.uniform(0.3, 0.7))
27    first: Rect
28    second: Rect
29    if width >= height:
30        x: float = left + width * ratio
31        first, second = (left, top, x, bottom), (x, top, right, bottom)
32    else:
33        y: float = top + height * ratio
34        first, second = (left, top, right, y), (left, y, right, bottom)
35
36    return split_rect(
37        first, rng, depth + 1, max_depth, min_size
38    ) + split_rect(second, rng, depth + 1, max_depth, min_size)

分割を止める規則は、乱数ではなく画像の内容から決めることもできる。正方形を 4 つの小さな正方形に分け続ける四分木（quadtree）で、領域内の値のばらつき（標準偏差）がしきい値を超える間だけ分割を続けると、細部の多い場所ほど細かく、平坦な場所ほど粗く分割される。

examples/subdivision.py の quadtree 関数
 1def quadtree(
 2    values: np.ndarray,
 3    left: int,
 4    top: int,
 5    size: int,
 6    threshold: float,
 7    min_size: int = 4,
 8) -> list[tuple[int, int, int]]:
 9    """正方形の領域を、中の値のばらつきが大きい間だけ4分割し続ける。
10
11    ``values`` は2次元配列で、領域 (``left``, ``top``) から一辺
12    ``size`` の範囲の標準偏差が ``threshold`` を超え、かつ一辺が
13    ``min_size`` の2倍以上なら、4つの小さな正方形に分けて再帰する。
14    戻り値は、分割しなかった正方形の (左, 上, 一辺) のリスト。
15    """
16    block: np.ndarray = values[top:top + size, left:left + size]
17    if size < 2 * min_size or float(block.std()) <= threshold:
18        return [(left, top, size)]
19
20    half: int = size // 2
21    squares: list[tuple[int, int, int]] = []
22    for dy in (0, half):
23        for dx in (0, half):
24            squares += quadtree(
25                values, left + dx, top + dy, half, threshold, min_size
26            )
27    return squares

ペンローズ・タイル（非周期タイリング）

ペンローズ・タイル（Penrose tiling）は、2 種類のひし形だけを使いながら、どれだけ広げても平行移動に対して周期的にはならない、非周期タイリングの代表例である。5 回対称性（星形に象徴される、五角形由来の対称性）を持つ一方、通常の結晶格子のような並進対称性は持たない、という数学的に興味深い性質で知られる。

実装には、黄金比 \(\varphi = (1+\sqrt{5})/2\) に基づく 2 種類の二等辺三角形（Robinson 三角形）を使う。細い三角形・太い三角形それぞれに決まった細分割規則を適用すると、1 枚の三角形が 2〜3 枚のより小さな三角形に分かれる。

\[\varphi = \frac{1 + \sqrt{5}}{2}\]

 1def subdivide_penrose(triangles: list[Triangle]) -> list[Triangle]:

 6    なペンローズ・タイリングに収束していく。
 7    """
 8    result: list[Triangle] = []
 9    for color, a, b, c in triangles:
10        if color == 0:
11            p: complex = a + (b - a) / GOLDEN_RATIO
12            result.append((0, c, p, b))
13            result.append((1, p, c, a))
14        else:
15            q: complex = b + (a - b) / GOLDEN_RATIO
16            r: complex = b + (c - b) / GOLDEN_RATIO
17            result.append((1, q, r, b))
18            result.append((0, r, q, a))
19            result.append((0, c, a, r))
20    return result

原点を囲むように細い三角形 10 枚を並べた「太陽」型の初期状態から出発し、この細分割を数回（作例では 6 回）繰り返すと、細分割のたびに三角形の数が増えながら、全体としては非周期的なペンローズ・タイリングに収束していく。

 1def initial_sun(num_wedges: int = 10) -> list[Triangle]:

15        triangles.append((0, 0j, b, c))
16    return triangles

隣接する同じ色の三角形 2 枚が、ペンローズ・タイルの太いひし形・細いひし形 1 枚に対応する。「小さな単位を規則に従って繰り返し書き換える」という発想は、後のフラクタルで扱う L-system の文字列書き換えとも共通するが、L-system が 1 次元の文字列を書き換えるのに対し、ペンローズ・タイルは 2 次元の三角形を書き換える点が異なる。

座標変換による放射状・渦巻き状パターン

ここまでの模様は、画素を全て直交座標 \((x, y)\) のまま扱ってきた。基礎編：ジェネラティブアート特有の設計方針の「座標系の正規化」で触れた通り、座標をどう解釈するかは自由に設計できる。ある画像の各画素を、中心からの角度 \(\theta\) と距離 \(r\) という極座標に読み替えてから、既存の模様（横方向に継ぎ目なく繰り返せるもの）を読み出すと、横方向の繰り返しが中心の周りをぐるりと取り囲む放射状の模様に化ける。

\[\theta = \operatorname{atan2}(y - c_y,\ x - c_x)\]
\[r = \sqrt{(x - c_x)^2 + (y - c_y)^2}\]
examples/polar_remap.py の polar_remap 関数
 1def polar_remap(
 2    source: Image.Image,
 3    width: int,
 4    height: int,
 5    center: tuple[float, float],
 6    max_radius: float,
 7    log_polar: bool = False,
 8) -> Image.Image:
 9    """ソース画像を極座標(または対数極座標)で読み直した画像を返す。
10
11    出力画像の各画素 (x, y) について、``center`` からの角度 theta と
12    距離 r を求め、theta をソース画像の横方向、r（``log_polar=True``
13    なら log(r)）を縦方向の座標としてソース画像から読み出す。ソース
14    画像が横方向に継ぎ目なく繰り返せる模様であれば、出力は中心から
15    放射状に広がる模様になる。
16    """
17    src_pixels: np.ndarray = np.array(source)
18    src_height: int
19    src_width: int
20    src_height, src_width = src_pixels.shape[:2]
21
22    xs: np.ndarray
23    ys: np.ndarray
24    xs, ys = np.meshgrid(
25        np.arange(width, dtype=float), np.arange(height, dtype=float)
26    )
27    dx: np.ndarray = xs - center[0]
28    dy: np.ndarray = ys - center[1]
29    theta: np.ndarray = np.arctan2(dy, dx)
30    r: np.ndarray = np.hypot(dx, dy)
31
32    u: np.ndarray = (theta + np.pi) / (2.0 * np.pi) * src_width
33    if log_polar:
34        r_safe: np.ndarray = np.clip(r, 1e-3, None)
35        v: np.ndarray = (
36            np.log(r_safe) / np.log(max_radius) * src_height
37        )
38    else:
39        v = r / max_radius * src_height
40
41    u = np.mod(u, src_width).astype(np.int64)
42    v = np.clip(v, 0, src_height - 1).astype(np.int64)
43
44    return Image.fromarray(src_pixels[v, u])

トルシェ・タイルを横に長い帯状に敷き詰めた画像を土台にして、この関数で極座標に読み替えると、中心から放射状に広がる模様になる。

距離 \(r\) の代わりに \(\log r\) を使う対数極座標に切り替えると、印象はさらに変わる。対数を取ると、中心に近い場所ほど \(r\) の小さな変化が \(\log r\) の大きな変化として引き伸ばされるため、中心付近では模様が急激に圧縮され、外周に近づくほど元の模様がそのままの密度で見えるようになる。

対数極座標は「距離が 2 倍になっても模様の見え方が変わらない」という自己相似（拡大縮小しても同じ形が繰り返し現れる性質）を持つ。この性質は、後のフラクタルで扱うフラクタル図形の中心的な特徴でもあり、対数極座標もまた拡大縮小に対して不変な構造を作れる一例だと言える。

対称性・万華鏡表現

polar_remap は、角度をソース画像の横方向にそのまま対応させることで、模様を中心の周りに 1 周分引き伸ばしていた。角度を 2*pi/segments で割った余りに読み替えるだけで、ソース画像の同じ範囲が周囲に segments 回繰り返される回転対称模様になる。これは万華鏡の「筒を回すと同じ模様が繰り返し現れる」効果に対応する。

examples/symmetry.py の kaleidoscope_remap 関数
 1def kaleidoscope_remap(
 2    source: Image.Image,
 3    width: int,
 4    height: int,
 5    center: tuple[float, float],
 6    segments: int,
 7    max_radius: float,
 8    mirror: bool = True,
 9) -> Image.Image:
10    """ソース画像を万華鏡状に読み替えた画像を返す。
11
12    出力画像の各画素について、``center`` からの角度 theta と距離 r を
13    求める。theta を扇形1枚分の角度 ``wedge = 2*pi/segments`` で割った
14    余り ``a`` (``[0, wedge)``) が、ソース画像から読み出す横方向の
15    位置に対応する。``mirror=True`` のときは ``a`` をさらに
16    ``wedge/2`` を頂点とした三角波に折り返す
17    (``a -> wedge/2 - |a - wedge/2|``) ことで、隣り合う扇形が
18    ちょうど鏡に映したように反転してつながる。``mirror=False`` なら
19    折り返さず、同じ模様が回転方向にそのまま繰り返されるだけになる。
20    """
21    src_pixels: np.ndarray = np.array(source)
22    src_height: int
23    src_width: int
24    src_height, src_width = src_pixels.shape[:2]
25
26    xs: np.ndarray
27    ys: np.ndarray
28    xs, ys = np.meshgrid(
29        np.arange(width, dtype=float), np.arange(height, dtype=float)
30    )
31    dx: np.ndarray = xs - center[0]
32    dy: np.ndarray = ys - center[1]
33    theta: np.ndarray = np.arctan2(dy, dx) + np.pi
34    r: np.ndarray = np.hypot(dx, dy)
35
36    wedge: float = 2.0 * np.pi / segments
37    a: np.ndarray = np.mod(theta, wedge)
38    if mirror:
39        a = wedge / 2.0 - np.abs(a - wedge / 2.0)
40        u: np.ndarray = a / (wedge / 2.0) * src_width
41    else:
42        u = a / wedge * src_width
43
44    v: np.ndarray = np.clip(r, 0, max_radius) / max_radius * src_height
45
46    u = np.clip(u, 0, src_width - 1).astype(np.int64)
47    v = np.clip(v, 0, src_height - 1).astype(np.int64)
48
49    return Image.fromarray(src_pixels[v, u])

回転方向に単純に繰り返すだけでは、扇形の境界で模様が急に途切れてしまう。余りをさらに扇形の中点を頂点とした三角波として折り返す（a -> wedge/2 - |a - wedge/2|）と、隣り合う扇形どうしがちょうど鏡に映したように反転してつながり、境界がなめらかにつながる、実物の万華鏡そのものの見た目になる。

同じ「座標を折り返してから模様を評価する」という発想は、平面を鏡映・回転で敷き詰める壁紙群（wallpaper group）の分類とも地続きである。ここでは中心 1 点からの角度を折り返したが、直交する 2 方向の座標をそれぞれ独立に鏡映すれば、正方形タイル 1 枚から市松模様のように敷き詰められる別の対称性も作れる。対称性の軸をどこに置き、何を折り返すかという選択肢の広さが、この技法の面白さになっている。

平面を平行移動で隙間なく敷き詰める模様がどのような対称性を持てるかは、数学的に完全に分類されており、可能な組み合わせはちょうど 17 種類しかないことが知られている（壁紙群、あるいは平面結晶群）。回転・鏡映・映進（鏡映と平行移動を組み合わせたもの）を平行移動と組み合わせられる自由度は無限にあるように思えるが、平面を隙間なく埋め尽くすという制約から、許される回転の対称性は 2 回・3 回・4 回・6 回のいずれかに限られる（5 回や 7 回以上の回転対称は、正五角形や正七角形が単独では平面を隙間なく敷き詰められないのと同じ理由で、周期的な壁紙模様とは両立しない）。この制限（結晶学的制限定理）のおかげで、組み合わせの総数が 17 という有限の数に収まる。

日本の伝統的な和柄には、この 17 種類のうちのいくつかを目で見て確かめられる実例が多い。市松模様は、色の違いを無視すれば正方形の格子がそのまま持つ対称性（4 回回転に加え、鏡映軸を格子線上と対角線上の両方に持つ、正方形格子の中でもっとも対称性の高い壁紙群 p4m）を体現しているし、麻の葉模様や亀甲模様は正六角形格子に由来する 6 回対称の壁紙群（p6m）、青海波のように同じ扇形模様を半個分ずつ横にずらしながら重ねていく模様は、扇形の中心を通る縦の鏡映軸と、その間を通る映進軸を持ち、回転対称を持たない壁紙群（cm）にそれぞれ対応する。どの和柄がどの壁紙群に属するかは、模様の中に回転中心・鏡映軸・映進軸がそれぞれ何種類あるかを数え上げれば判定でき、使う図形（正方形・六角形・扇形など）が違っていても、対称性という尺度で見れば同じ分類に属する模様どうしを結びつけられる。本資料ではこれ以上立ち入らないが、対称性による分類は、後の「双曲タイリング」で触れるコクセター群という、より一般的な鏡映群の枠組みの入り口にあたる。

双曲タイリング（ポアンカレディスク）

ここまでのタイリングは、正方形・正三角形・正六角形のように、1 つの頂点の周りに正多角形の内角がちょうど 360 度分だけ集まることで平面を隙間なく埋め尽くしていた。では、正五角形や正七角形ではどうなるだろうか。正五角形を 3 枚集めても内角の合計は 324 度にしかならず 360 度に届かず、逆に正七角形を 3 枚集めると約 385.7 度で 360 度を超えてしまう。平らな（ユークリッド）平面上では、この過不足はどうやっても解消できない。

しかし、平面を球面のように丸めれば内角の不足分を吸収でき（正五角形 3 枚は正十二面体の頂点に対応する）、逆に平面を鞍型に反らせれば内角の超過分を吸収できる。この「内角が 360 度を超える」タイリングが成り立つ空間が双曲平面であり、ポアンカレディスク模型は、この双曲平面全体を単位円板の内部に押し込めて平面上に描く方法である。円板の中心から境界に近づくほど、同じ双曲的な大きさの図形がユークリッド的にはどんどん小さく見える（境界そのものには到達できない、無限遠にあたる）という特徴があり、双曲的な直線（測地線）は、円板の中心を通る直線か、円板の境界に直交する円弧のどちらかとして現れる。

正 \(p\) 角形を、1 つの頂点に \(q\) 枚集めて双曲的に敷き詰めるタイリング \(\{p, q\}\) を考える。中心・頂点・辺の中点の 3 点がなす直角三角形（角度は中心で \(\pi/p\)、頂点で \(\pi/q\)、辺の中点で直角）に双曲的な余弦定理を適用すると、最初の正多角形の外接円半径（ポアンカレディスク上でのユークリッド距離）が求まる。

\[r = \sqrt{\frac{\cos(\pi/p + \pi/q)}{\cos(\pi/p - \pi/q)}}\]
examples/hyperbolic_tiling.py の polygon_circumradius 関数
 1def polygon_circumradius(p: int, q: int) -> float:
 2    """1つの頂点に ``q`` 枚が集まる正 ``p`` 角形タイリングの、正多角形1枚
 3    の外接円半径(ポアンカレディスク上でのユークリッド距離)を返す。
 4
 5    頂点・辺の中点・中心の3点がなす双曲三角形(角度は順に ``pi/q``・
 6    ``pi/2``・``pi/p``)に双曲的な余弦定理を適用して導ける。``1/p + 1/q``
 7    が ``1/2`` 未満のとき双曲的なタイリングになり、値はちょうど単位円の
 8    内側(半径1未満)に収まる。
 9    """
10    a = math.pi / p
11    b = math.pi / q
12    return math.sqrt(math.cos(a + b) / math.cos(a - b))

\(1/p + 1/q\) が \(1/2\) ちょうどなら平面（正方形や正六角形のタイリング）、\(1/2\) を超えれば球面、\(1/2\) 未満なら双曲平面になることが知られている。上の式は \(1/p+1/q < 1/2\) のとき \(r\) が実数かつ 1 未満になり、単位円板の内側に正しく収まる。

examples/hyperbolic_tiling.py の fundamental_polygon 関数
1def fundamental_polygon(p: int, q: int) -> np.ndarray:
2    """原点を中心とした、最初の正 ``p`` 角形の頂点(複素数)を返す。"""
3    radius = polygon_circumradius(p, q)
4    angles = 2 * np.pi * np.arange(p) / p
5    return radius * np.exp(1j * angles)

最初の正多角形ができたら、あとは先ほどのペンローズ・タイルが細分割によって内側から模様を増やしたのとは対照的に、この多角形を各辺に関して鏡映することでタイリングを中心から外側へ広げていく。円板境界に直交する円弧（または原点を通る直線に退化した特別な場合）に関する鏡映は、その円に関する反転として実装できる。測地線は単位円板に関する反転で不変という性質を使うと、2 頂点だけから鏡映に使う円を決定できる。

examples/hyperbolic_tiling.py の geodesic_reflection 関数
 1def geodesic_reflection(
 2    z1: complex, z2: complex
 3) -> Callable[[np.ndarray], np.ndarray]:
 4    """``z1``・``z2`` を通る測地線に関して点を鏡映する変換を返す。
 5
 6    測地線(円板境界に直交する円弧、またはそれが退化した原点を通る直線)
 7    は単位円板に関する反転で不変なので、``z1`` の反転像 ``1/conj(z1)``
 8    も同じ測地線上に乗る。この3点から円(退化する場合は直線)を決定し、
 9    その円に関する反転として鏡映を実装する。
10    """
11    z3 = 1 / np.conj(z1)
12    x1, y1 = z1.real, z1.imag
13    x2, y2 = z2.real, z2.imag
14    x3, y3 = z3.real, z3.imag
15
16    d = 2 * (x1 * (y2 - y3) + x2 * (y3 - y1) + x3 * (y1 - y2))
17    if abs(d) < 1e-9:
18        theta = np.angle(z1)
19        return lambda z: np.exp(2j * theta) * np.conj(z)
20
21    cx = (
22        (x1**2 + y1**2) * (y2 - y3)
23        + (x2**2 + y2**2) * (y3 - y1)
24        + (x3**2 + y3**2) * (y1 - y2)
25    ) / d
26    cy = (
27        (x1**2 + y1**2) * (x3 - x2)
28        + (x2**2 + y2**2) * (x1 - x3)
29        + (x3**2 + y3**2) * (x2 - x1)
30    ) / d
31    center = complex(cx, cy)
32    radius = abs(z1 - center)
33
34    def reflect(z: np.ndarray) -> np.ndarray:
35        return center + radius**2 / np.conj(z - center)
36
37    return reflect

生成した多角形の重心座標を使って既出の多角形を除きながら、幅優先探索（本章で扱った迷路の経路探索と同じ考え方）で鏡映を繰り返し適用すると、中心から外側へ層状にタイリングが広がっていく。

examples/hyperbolic_tiling.py の generate_tiling 関数
 1def generate_tiling(p: int, q: int, depth: int) -> list[Polygon]:
 2    """最初の正 ``p`` 角形を各辺に関して繰り返し鏡映し、タイリングを広げる。
 3
 4    幅優先探索(:doc:`../tiling` の迷路の解探索と同じ考え方)で、まだ
 5    現れていない多角形だけを重心の座標で見分けながら ``depth`` 段階
 6    先まで広げる。多角形は最初に現れた段階の番号(0が中心の1枚)を
 7    付けて返し、中心からの層の深さを色分けに使えるようにしている。
 8    """
 9    base = fundamental_polygon(p, q)
10    seen: set[tuple[float, float]] = set()
11
12    def key(vertices: np.ndarray) -> tuple[float, float]:
13        centroid = vertices.mean()
14        return (round(centroid.real, 4), round(centroid.imag, 4))
15
16    seen.add(key(base))
17    polygons: list[Polygon] = [(0, base)]
18    frontier: list[np.ndarray] = [base]
19
20    for layer in range(1, depth + 1):
21        next_frontier: list[np.ndarray] = []
22        for vertices in frontier:
23            n = len(vertices)
24            for i in range(n):
25                reflect = geodesic_reflection(
26                    vertices[i], vertices[(i + 1) % n]
27                )
28                neighbor = reflect(vertices)
29                neighbor_key = key(neighbor)
30                if neighbor_key not in seen:
31                    seen.add(neighbor_key)
32                    polygons.append((layer, neighbor))
33                    next_frontier.append(neighbor)
34        frontier = next_frontier
35        if not frontier:
36            break
37
38    return polygons

\(\{7, 3\}\)（七角形を 1 頂点に 3 枚）と \(\{6, 4\}\)（六角形を 1 頂点に 4 枚）を、中心からの層の深さで暖色から寒色へ色を変えながら描画すると、次のようになる。境界に近づくほど多角形が指数的に小さくなっていく様子が、双曲平面をユークリッド平面に押し込めたことの現れである。

正多角形を辺に関して鏡映で敷き詰めるこの操作は、直前の対称性・万華鏡表現で扱った角度の折り返しや、壁紙群による平面の敷き詰めと同じ「鏡映を繰り返して模様を広げる」という発想の延長線上にある。こうした鏡映の繰り返しが生成する対称性の構造は、数学的にはコクセター群（Coxeter group）と呼ばれる枠組みで統一的に扱われる。平面の壁紙群も、双曲平面のこの \(\{p, q\}\) タイリングも、球面上の正多面体の対称性も、いずれも「いくつかの鏡映を生成元とする群」というコクセター群の特別な場合にあたる。
