10. 依存関係の管理

SOLID 原則 の依存性逆転の原則では、上位の方針が抽象に依存し、下位の詳細がその抽象を満たすようにしました。では、上位のオブジェクトは、実際に使う下位のオブジェクトをどうやって手に入れればよいのでしょうか。この章では、その答えである依存性注入と、オブジェクトの組み立てを 1 か所にまとめる方法を説明します。

10.1. 依存するものを内部で作る問題

あるオブジェクトが仕事をするために必要とする別のオブジェクトを、依存オブジェクト と呼びます。次の BadMorningGreeter は、天気の情報を Web API から取得し、現在時刻に応じたあいさつを作ります。

ch10_dependency_injection.py（悪い例）
class BadMorningGreeter:
    """朝の案内を作ります（悪い例）.

    通信先の URL と現在時刻が内部で決まるので、テストのたびに実際に
    通信が発生し、結果も実行した時刻によって変わります。
    """

    def message(self) -> str:
        with urllib.request.urlopen("https://example.com/weather") as res:
            weather = json.load(res)["weather"]
        hour = datetime.now().hour
        greeting = "おはようございます" if hour < 12 else "こんにちは"
        return f"{greeting}。今日の天気は「{weather}」です。"

このクラスは、依存するもの（通信先の URL、HTTP の通信、現在時刻）を、すべて内部で直接決めています。そのため、次のような問題があります。

  • テストのたびに、実際に Web API と通信します。ネットワークにつながっていない環境では、テストが失敗します。

  • 結果が実行した時刻によって変わるので、「午後なら『こんにちは』になる」ことを、午前中にはテストできません。

  • 通信先を開発用のサーバーに変えたいときも、クラスを変更する必要があります。

10.2. 依存性注入

依存性注入（Dependency Injection、DI）とは、オブジェクトが依存するものを、そのオブジェクトの内部で作るのではなく、外から渡す ことです。渡し方には、主に次の 2 つがあります。

方法

説明

向いている場面

コンストラクターによる注入

__init__ の引数として受け取り、属性に保存します。

オブジェクトが、生きている間ずっと同じ依存オブジェクトを使う場合

引数による注入

関数やメソッドの引数として受け取ります。

関数の場合や、呼び出しごとに異なる依存オブジェクトを使う場合

先ほどの例を、コンストラクターによる注入で書き直します。天気の取得元は WeatherClient という Protocol として、現在時刻の取得は「引数なしで datetime を返す関数」として受け取ります。

ch10_dependency_injection.py（良い例）
class WeatherClient(Protocol):
    """天気の取得元のインターフェースです."""

    def today(self) -> str:
        """今日の天気を返します."""
        ...


Clock = Callable[[], datetime]


class MorningGreeter:
    """朝の案内を作ります（良い例）."""

    def __init__(self, weather: WeatherClient, clock: Clock) -> None:
        self._weather = weather
        self._clock = clock

    def message(self) -> str:
        hour = self._clock().hour
        greeting = "おはようございます" if hour < 12 else "こんにちは"
        return f"{greeting}。今日の天気は「{self._weather.today()}」です。"


class HttpWeatherClient:
    """Web API から天気を取得します."""

    def __init__(self, url: str, timeout: float) -> None:
        self._url = url
        self._timeout = timeout

    def today(self) -> str:
        with urllib.request.urlopen(self._url, timeout=self._timeout) as res:
            return str(json.load(res)["weather"])


class FixedWeatherClient:
    """常に同じ天気を返します（開発用、テスト用）."""

    def __init__(self, weather: str) -> None:
        self._weather = weather

    def today(self) -> str:
        return self._weather

MorningGreeter は、天気がどこから来るのか、時刻がどう決まるのかを知りません。テストでは、固定の天気を返す FixedWeatherClient と、固定の時刻を返す関数を渡せば、ネットワークにも実行した時刻にも依存しないテストが書けます。

ch10_dependency_injection.py（時計を固定する例）
# テストでは、取得元と時計を固定した値に差し替えられる
fixed = MorningGreeter(FixedWeatherClient("雨"),
                       lambda: datetime(2026, 4, 1, 15, 0))
print(fixed.message())

時計（現在時刻）のように、メソッドを 1 つしか持たない依存オブジェクトは、Protocol を定義せずに、Callable 型の関数として受け取るのが簡単です。本番では datetime.now を、テストでは固定の時刻を返す lambda を渡します。

10.3. コンポジションルート

依存性注入を使うと、どのオブジェクトにどの依存オブジェクトを渡すかを、どこかで決める必要があります。この組み立ての処理は、プログラムの入口（main 関数の付近）の 1 か所にまとめます。この場所を コンポジションルート と呼びます。

ch10_dependency_injection.py（コンポジションルート）
def build_service(settings: Settings) -> MorningGreeter:
    """設定に従ってオブジェクトを組み立てます（コンポジションルート）."""
    weather: WeatherClient
    if settings.weather_api_url:
        weather = HttpWeatherClient(settings.weather_api_url,
                                    settings.timeout)
    else:
        weather = FixedWeatherClient("晴れ")
    return MorningGreeter(weather, datetime.now)

コンポジションルートは、プログラムの中で、具体的なクラスをすべて知っている唯一の場所です。それ以外の部分は、Protocol などの抽象だけを知っています。「保存先を変える」「通信先を変える」といった変更は、コンポジションルートの変更だけで済みます。

10.3.1. DI コンテナーは必須ではない

Java などの言語では、オブジェクトの組み立てを自動で行う「DI コンテナー」と呼ばれるライブラリがよく使われます。Python にも同様のライブラリがありますが、多くのアプリケーションでは、この例のように普通の関数で組み立てれば十分です。組み立ての処理が長くなってきたら、コンテナーの導入を検討します。

10.4. 設定値の扱い

URL やタイムアウトの秒数のような設定値も、依存オブジェクトの一種です。設定値を扱うときは、次の点に注意します。

  • 環境変数や設定ファイルを読むのは、コンポジションルートの付近だけにします。プログラムのあちこちで os.environ を読むと、どの設定がどこで使われているのかが分からなくなり、テストで設定を変えるのも難しくなります。

  • 読み込んだ設定値は、データクラスなどにまとめ、型を付けて渡します。

ch10_dependency_injection.py（設定）
@dataclass(frozen=True)
class Settings:
    """アプリケーションの設定です."""

    weather_api_url: str | None
    timeout: float

    @classmethod
    def from_env(cls) -> "Settings":
        """環境変数から設定を読み込みます."""
        return cls(
            weather_api_url=os.environ.get("WEATHER_API_URL"),
            timeout=float(os.environ.get("WEATHER_API_TIMEOUT", "5")),
        )

10.5. 何を注入するか

すべての依存オブジェクトを注入すればよいわけではありません。注入を検討すべきなのは、次のような依存オブジェクトです。

  • 外部の世界とやり取りするもの（ファイル、データベース、ネットワーク、画面、メール）

  • 実行するたびに結果が変わるもの（現在時刻、乱数）

  • 実装を差し替える可能性が実際にあるもの

一方、値オブジェクト（Money など）や、標準ライブラリの純粋な関数（math.sqrt など）は、注入する必要はありません。これらは常に同じ結果を返し、テストの妨げにならないからです。何でも注入すると、コンストラクターの引数が増え、かえってコードが読みにくくなります。

10.6. まとめ

  • 依存オブジェクトを内部で作ると、テストや差し替えが難しくなります。

  • 依存オブジェクトは、コンストラクターや引数で外から渡します（依存性注入）。

  • オブジェクトの組み立ては、プログラムの入口の 1 か所（コンポジションルート）にまとめます。

  • 環境変数や設定ファイルは、コンポジションルートの付近だけで読みます。

  • 注入するのは、外部とやり取りするものや、結果が変わるものに絞ります。
