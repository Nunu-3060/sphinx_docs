1. プログラミングとは何か

この章では、本書全体の出発点として「プログラム」と「プログラミング」を定義し、似た言葉との違いを整理する。

1.1. プログラムとは

プログラムとは、コンピュータに実行させる命令を、実行する順序に従って並べたものである。コンピュータは自分で判断して動く機械ではなく、与えられた命令を 1 つずつ忠実に実行するだけの機械である。したがって、コンピュータに仕事をさせるには、その仕事を命令の並びとして書き表す必要がある。

1.2. プログラミングとは

プログラミングとは、解きたい問題を、コンピュータが実行できる手順に落とし込む行為である。この行為は、おおむね次の 3 つの段階に分けられる。

  1. 問題を理解する：何を入力として受け取り、何を出力すべきかを明確にする。

  2. 手順を考える：入力から出力を得るための手順（アルゴリズム）と、途中で扱うデータの形（データ構造）を決める。

  3. 手順を書き表す：プログラミング言語を使って、手順をコンピュータが実行できる形に書き表す。

計算機科学者のニクラウス・ヴィルトは、自著の書名で「アルゴリズム + データ構造 = プログラム」と表現した[Wirth1976]。プログラミングの中心にあるのは、言語の文法ではなく、手順とデータをどう組み立てるかという設計である。

1.3. プログラミングとコーディングとソフトウェア開発

似た言葉に「コーディング」と「ソフトウェア開発」がある。本書では、これらを次のように区別する。

用語

本書での意味

コーディング

決まった手順をプログラミング言語で書き表す作業。前節の 3 番目の段階にあたる。

プログラミング

問題の理解から手順の設計、コーディング、動作の確認までを含む行為。

ソフトウェア開発

要求の整理、設計、プログラミング、テスト、運用、保守までを含む工程全体。複数人で行うことが多い。

ソフトウェア開発の中でプログラミングが占める位置は、ソフトウェア開発の中のプログラミングで改めて扱う。

1.4. 手順書とプログラムの違い

料理のレシピや作業手順書も、手順を書き表したものという点ではプログラムに似ている。しかし、両者には大きな違いがある。人間向けの手順書は、読み手の常識や判断に頼ることができる。「塩を少々」と書けば、読み手は適量を判断する。一方、コンピュータは常識を持たないため、プログラムには次のような性質が求められる。

  • 曖昧さがない：すべての命令が、ただ 1 通りに解釈できなければならない。

  • 例外的な状況も扱う：入力が空の場合や、想定外の値が来た場合にどうするかまで書かなければならない。

  • 書いたとおりに動く：意図と異なる命令を書けば、コンピュータはその誤った命令をそのまま実行する。

プログラムの誤りをバグと呼ぶ。バグの多くは、コンピュータの誤動作ではなく、意図と異なる命令を書いたことによって生じる。

1.5. 最初のプログラム

次のサンプルコードは、画面に Hello, World! と表示するだけのプログラムである。

 1"""最初のプログラム：画面に挨拶を表示する。"""
 2
 3
 4def main() -> None:
 5    """挨拶のメッセージを表示する。"""
 6    print("Hello, World!")
 7
 8
 9if __name__ == "__main__":
10    main()

4〜6 行目で main という関数を定義し、10 行目でそれを呼び出している。6 行目の print は、Python に組み込まれている、文字列を画面に表示する関数である。9 行目の if __name__ == "__main__": は、このファイルが直接実行されたときだけ main を呼び出すための定型の書き方である。

実行すると、次のように表示される。

1$ python hello.py
2Hello, World!

この短いプログラムも、コンピュータはどう動くかで説明する仕組みによって、最終的には CPU が実行できる多数の命令に変換されて実行される。
