7. 抽象化と分割

プログラムが大きくなると、すべての詳細を同時に頭に入れておくことはできなくなる。この章では、大きなプログラムの複雑さを管理するための考え方である抽象化と、プログラムを部品に分ける方法を説明する。

7.1. 抽象化とは

抽象化とは、詳細を隠し、本質だけを扱えるようにすることである。たとえば自動車を運転する人は、エンジンの内部構造を知らなくても、ハンドル、アクセル、ブレーキの使い方を知っていれば運転できる。運転者にとって重要なのは「何ができるか」であり、「どのように実現されているか」ではない。

プログラミングにおける抽象化も同じである。print 関数を使う人は、文字が画面に表示されるまでの処理を知らなくても、文字列を渡せば表示されることを知っていれば十分である。

7.2. 抽象化の階層

コンピュータとプログラミングの歴史で見たように、プログラミングの歴史は抽象化を積み重ねてきた歴史でもある。現在のプログラムは、次のような抽象化の階層の上で動いている。

階層

隠している詳細

アプリケーション

利用者には、プログラムの内部の処理を隠す。

ライブラリ、フレームワーク

通信、ファイル形式、画面表示などの複雑な処理を、関数やクラスとして提供する。

高水準言語

機械語の命令やレジスタの使い方を隠す。

OS

ハードウェアの違いを隠し、ファイルやプロセスといった統一された仕組みを提供する。

機械語

電子回路の動作を、命令という単位にまとめる。

ハードウェア

電気信号を 0 と 1 として扱う。

各階層は、1 つ下の階層が提供する機能だけを使い、さらに下の階層の詳細を意識せずに済む。この仕組みによって、プログラマーは解きたい問題に集中できる。

7.3. 分割の単位

自分で書くプログラムでも、処理を適切な単位に分割し、それぞれに抽象化を施すことが重要である。Python では、次の単位でプログラムを分割できる。

単位

説明

関数

一連の処理をまとめて名前を付けたもの。プログラムの基本要素で説明した。

クラス

データと、そのデータを操作する関数（メソッド）をまとめたもの。

モジュール

関連する関数やクラスを 1 つのファイルにまとめたもの。import 文で読み込んで使う。

パッケージ

関連するモジュールを 1 つのフォルダーにまとめたもの。

アルゴリズムと計算量のサンプルコードでは、linear_search.py と binary_search.py をそれぞれモジュールとし、measure_search.py から import 文で読み込んで使っている。measure_search.py は、探索の詳細を知らなくても、関数の名前と引数だけを知っていれば測定を行える。

7.4. インタフェースと実装の分離

部品の利用者に対して約束する「使い方」をインタフェースと呼び、その約束を実際に果たす処理を実装と呼ぶ。インタフェースと実装を分けておけば、インタフェースを変えない限り、利用者に影響を与えずに実装を改善できる。たとえば、探索の関数の名前、引数、戻り値を変えなければ、内部のアルゴリズムを線形探索から二分探索に変えても、関数を呼び出す側のプログラムを変更する必要はない。

オブジェクト指向プログラミングでは、クラスを使ってインタフェースを表現できる。次のサンプルコードは、図形の面積を求める例である。

 1"""クラスと抽象基底クラスによる抽象化の例。"""
 2
 3import math
 4from abc import ABC, abstractmethod
 5from collections.abc import Iterable
 6
 7
 8class Shape(ABC):
 9    """図形を表す抽象基底クラス。面積を求める方法だけを約束する。"""
10
11    @abstractmethod
12    def area(self) -> float:
13        """図形の面積を返す。"""
14
15
16class Rectangle(Shape):
17    """長方形。"""
18
19    def __init__(self, width: float, height: float) -> None:
20        self.width = width
21        self.height = height
22
23    def area(self) -> float:
24        return self.width * self.height
25
26
27class Circle(Shape):
28    """円。"""
29
30    def __init__(self, radius: float) -> None:
31        self.radius = radius
32
33    def area(self) -> float:
34        return math.pi * self.radius ** 2
35
36
37def total_area(shapes: Iterable[Shape]) -> float:
38    """図形の種類を区別せずに、面積の合計を求める。"""
39    return sum(shape.area() for shape in shapes)
40
41
42def main() -> None:
43    """種類の異なる図形をまとめて扱う。"""
44    shapes: list[Shape] = [Rectangle(3.0, 4.0), Circle(1.0)]
45    print(f"{total_area(shapes):.4f}")  # 15.1416
46
47
48if __name__ == "__main__":
49    main()

8〜13 行目の Shape クラスは、「図形は area メソッドで面積を返す」というインタフェースだけを定める抽象基底クラスである。Rectangle クラス（16〜24 行目）と Circle クラス（27〜34 行目）は、それぞれの図形に応じた方法で area メソッドを実装している。

37〜39 行目の total_area 関数は、受け取った図形が長方形なのか円なのかを区別せず、area メソッドを呼び出すだけで面積の合計を求める。このように、同じインタフェースを持つ異なる種類のオブジェクトを同じ方法で扱えることを、多態性（ポリモーフィズム）と呼ぶ。三角形を扱う必要が生じても、Shape クラスを継承した Triangle クラスを追加するだけでよく、total_area 関数を変更する必要はない。

7.5. よい分割の指針

プログラムを分割するときは、次の点を指針にするとよい。

  • 1 つの部品には 1 つの役割だけを持たせる。役割を一言で説明できない部品は、さらに分割できる可能性がある。

  • 部品の名前で役割が分かるようにする。名前から内容を推測できれば、利用者は実装を読まずに済む。

  • 部品どうしの依存を少なくする。ある部品の変更が、多くの部品の変更を引き起こさないようにする。

  • 同じ処理を複数の場所に書かない。重複した処理は、修正の漏れを生む原因になる。
