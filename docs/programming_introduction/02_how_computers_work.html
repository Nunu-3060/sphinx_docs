2. コンピュータはどう動くか

プログラムを理解するには、それを実行するコンピュータの仕組みを知っておく必要がある。この章では、コンピュータの基本的な構成と、プログラムやデータがコンピュータの内部でどのように表現されるかを説明する。

2.1. コンピュータの構成

現在のコンピュータの多くは、次の装置から構成される。

装置

役割

CPU

命令を読み出して解釈し、演算を実行する。内部にレジスタと呼ばれる小容量で高速な記憶領域を持つ。

メモリ

実行中のプログラムと、そのプログラムが扱うデータを記憶する。主記憶装置とも呼ぶ。電源を切ると内容は失われる。

補助記憶装置

SSD や HDD など。電源を切っても内容が失われないため、プログラムやデータをファイルとして保存しておく。

入出力装置

キーボード、ディスプレイ、ネットワークインタフェースなど。外部とデータをやり取りする。

プログラムを実行するときは、補助記憶装置に保存されたプログラムをメモリに読み込み、CPU がメモリから命令を 1 つずつ読み出して実行する。このように、プログラムをデータと同じくメモリに格納して実行する方式をプログラム内蔵方式と呼ぶ。この方式に基づくコンピュータは、方式を報告書にまとめた数学者ジョン・フォン・ノイマンの名をとってノイマン型コンピュータと呼ばれる。プログラム内蔵方式が生まれた経緯はコンピュータとプログラミングの歴史で扱う。

2.2. 命令の実行

CPU は、次の 3 つの段階を繰り返して命令を実行する。この繰り返しを命令サイクルと呼ぶ。

  1. フェッチ：プログラムカウンタ（次に実行する命令のアドレスを保持するレジスタ）が指すメモリ上の位置から、命令を読み出す。

  2. デコード：読み出した命令が何をする命令なのかを解釈する。

  3. 実行：演算やデータの転送を行い、プログラムカウンタを次の命令に進める。

CPU が直接解釈できる命令の形式を機械語と呼ぶ。機械語の命令は、「メモリからレジスタへ値を読み込む」「2 つのレジスタの値を足す」「レジスタの値をメモリに書き込む」「条件を満たせば別の位置の命令へ移る」といった単純な操作だけを表す。たとえば c = a + b という計算は、次のような命令の並びになる。ここでは説明のために、架空の CPU の命令を人間が読める形で示す。

1LOAD  R1, [a]     ; メモリ上の a の値をレジスタ R1 に読み込む
2LOAD  R2, [b]     ; メモリ上の b の値をレジスタ R2 に読み込む
3ADD   R1, R2      ; R1 と R2 を足し、結果を R1 に格納する
4STORE [c], R1     ; R1 の値をメモリ上の c に書き込む

どれほど複雑なプログラムも、最終的にはこのような単純な命令の並びとして実行される。条件分岐や繰り返しも、「条件を満たせば別の位置の命令へ移る」というジャンプ命令によって実現される。

2.3. データの表現

2.3.1. ビットとバイト

コンピュータの内部では、すべての情報が 0 と 1 の並びで表現される。0 または 1 を表す最小の単位をビットと呼び、8 ビットをまとめたものをバイトと呼ぶ。\(n\) ビットで表せる値は \(2^n\) 通りあり、1 バイトなら \(2^8 = 256\) 通りである。

2.3.2. 2 進数と 16 進数

0 と 1 だけで数を表す方法を 2 進数と呼ぶ。\(n\) 桁の 2 進数 \((b_{n-1} \cdots b_1 b_0)_2\) が表す値は、次の式で求められる。

\[(b_{n-1} \cdots b_1 b_0)_2 = \sum_{i=0}^{n-1} b_i \times 2^i\]

たとえば 2 進数の 1011 は、次のように 10 進数の 11 を表す。

\[(1011)_2 = 1 \times 2^3 + 0 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 = 8 + 0 + 2 + 1 = 11\]

2 進数は桁数が多くなり、人間には読みにくい。そこで、2 進数の 4 桁を 1 桁にまとめた 16 進数がよく使われる。16 進数では 0〜9 と A〜F の 16 種類の記号を使う。たとえば \((1111\,1111)_2 = (\mathrm{FF})_{16} = 255\) である。

負の整数は、多くの場合「2 の補数」と呼ばれる方式で表現される。この方式では、\(n\) ビットで \(-2^{n-1}\) 以上 \(2^{n-1} - 1\) 以下の整数を表せる。たとえば 8 ビットなら -128 以上 127 以下である。なお、Python の整数（int 型）はメモリが許す限り桁数を増やせるため、この範囲の制限を受けない。

2.3.3. 文字

文字も数値として表現される。文字と数値の対応を定めた規則を文字コードと呼ぶ。現在は、世界中の文字に番号を割り当てた Unicode と、その番号をバイト列に変換する方式である UTF-8 の組み合わせが広く使われている。たとえば「あ」には U+3042 という番号が割り当てられており、UTF-8 では 3 バイトの列 E3 81 82 で表現される。

2.3.4. 浮動小数点数

小数を含む数は、多くの場合浮動小数点数として表現される。代表的な規格である IEEE 754 の倍精度（64 ビット）形式では、符号 \(s\) に 1 ビット、指数 \(e\) に 11 ビット、仮数 \(f\) に 52 ビットを割り当て、通常の値を次の式で表す。

\[(-1)^s \times (1.f)_2 \times 2^{e - 1023}\]

この形式で正確に表せるのは、2 進数で有限桁に収まる値だけである。10 進数の 0.1 は 2 進数では無限に続く小数になるため、近似値として記憶される。その結果、次のサンプルコードで示すように 0.1 + 0.2 は 0.3 と等しくならない。浮動小数点数を比較するときは、== ではなく、誤差を許容する math.isclose などを使う。金額のように誤差が許されない計算では、整数で計算するか、10 進数で計算する decimal モジュールを使う。

2.4. サンプルコード

次のサンプルコードは、整数の 2 進数への変換、文字の UTF-8 表現、浮動小数点数の誤差を確かめる。to_binary 関数は、2 で割った余りを下の桁から順に求めることで 2 進数に変換する。from_binary 関数は、上の桁から順に「それまでの値を 2 倍して次の桁を足す」ことで、前述の式の値を求める。

 1"""数値と文字がコンピュータの内部でどう表現されるかを確かめる。"""
 2
 3import math
 4
 5
 6def to_binary(value: int) -> str:
 7    """0 以上の整数を 2 進数の文字列に変換する。"""
 8    if value < 0:
 9        raise ValueError("value は 0 以上でなければならない")
10    if value == 0:
11        return "0"
12    digits: list[str] = []
13    while value > 0:
14        digits.append(str(value % 2))  # 2 で割った余りが下の桁になる
15        value //= 2
16    return "".join(reversed(digits))
17
18
19def from_binary(text: str) -> int:
20    """2 進数の文字列を整数に変換する。"""
21    result = 0
22    for digit in text:
23        result = result * 2 + int(digit)
24    return result
25
26
27def main() -> None:
28    """整数・文字・浮動小数点数の内部表現を表示する。"""
29    print(to_binary(11))  # 1011
30    print(from_binary("1011"))  # 11
31    print(hex(255))  # 0xff（16 進数）
32
33    print("あ".encode("utf-8"))  # b'\xe3\x81\x82'（3 バイト）
34
35    print(0.1 + 0.2)  # 0.30000000000000004
36    print(0.1 + 0.2 == 0.3)  # False
37    print(math.isclose(0.1 + 0.2, 0.3))  # True
38
39
40if __name__ == "__main__":
41    main()
