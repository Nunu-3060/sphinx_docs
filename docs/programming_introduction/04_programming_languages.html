4. プログラミング言語

コンピュータとプログラミングの歴史で見たように、プログラミング言語は、人間が扱う表現と機械が実行する表現との距離を埋めるために発展してきた。この章では、プログラミング言語を分類するための代表的な観点を説明する。

4.1. 言語の水準

プログラミング言語は、機械にどれだけ近いかによって、次のように分類できる。

分類

特徴

機械語

CPU が直接実行できる命令の形式。CPU の種類ごとに異なり、数値の列として表される。

アセンブリ言語

機械語の命令を短い記号で書けるようにした言語。機械語とほぼ 1 対 1 に対応する。

高水準言語

人間の考え方に近い形で処理を書ける言語。CPU の種類に依存せずに書ける。C、Java、Python などが該当する。

高水準言語で書いたプログラムは、そのままでは CPU が実行できない。実行するには、次節で説明する方法で機械語に変換するか、変換しながら実行する必要がある。

4.2. 実行方式

高水準言語のプログラムを実行する方式は、大きく 2 つに分けられる。

コンパイラ

プログラム全体を、実行前に機械語などの別の形式に変換する。この変換をコンパイルと呼ぶ。実行時に変換の手間がかからないため、一般に高速に動作する。C、C++、Go、Rust などが、この方式を主に用いる。

インタプリタ

プログラムを読み込みながら、その場で解釈して実行する。コンパイルの手順が不要なため、書いてすぐに試せる。

実際の言語処理系の多くは、両者を組み合わせている。たとえば Python の標準の処理系である CPython は、プログラムを実行する前に、仮想的な機械向けの命令であるバイトコードにコンパイルし、それをインタプリタで実行する。Java も同様にバイトコードにコンパイルし、Java 仮想マシン（JVM）上で実行する。JVM は、頻繁に実行される部分を実行中に機械語へ変換する JIT（Just-In-Time）コンパイルによって高速化を図っている。

Python のバイトコードは、標準ライブラリの dis モジュールで確認できる。

 1"""Python の関数がどのようなバイトコードに変換されるかを表示する。"""
 2
 3import dis
 4
 5
 6def add(a: int, b: int) -> int:
 7    """2 つの整数の和を返す。"""
 8    return a + b
 9
10
11def main() -> None:
12    """add 関数のバイトコードを逆アセンブルして表示する。"""
13    dis.dis(add)
14
15
16if __name__ == "__main__":
17    main()

Python 3.14 で実行すると、次のように表示される。バイトコードの命令は Python のバージョンによって異なる。

1  6           RESUME                   0
2
3  8           LOAD_FAST_BORROW_LOAD_FAST_BORROW 1 (a, b)
4              BINARY_OP                0 (+)
5              RETURN_VALUE

a + b という 1 つの式が、2 つの変数の値を読み込む命令、足し算の命令、結果を返す命令に分解されていることが分かる。コンピュータはどう動くかで示した機械語の例と、考え方は同じである。

4.3. 型システム

型とは、値の種類と、その値に対して行える操作を定めたものである。たとえば整数どうしは足し算できるが、整数と文字列をそのまま足すことはできない。型を検査する時期によって、言語は次の 2 つに分けられる。

静的型付け

プログラムを実行する前に型を検査する。型の誤りを実行前に発見できる。C、Java、Go、Rust などが該当する。

動的型付け

プログラムを実行しながら型を検査する。変数の型を宣言する必要がなく、簡潔に書ける。一方、型の誤りは、その部分が実行されるまで発見できない。Python、JavaScript、Ruby などが該当する。

Python は動的型付けの言語であるが、変数や関数の引数に型の情報を書き添える型ヒントの仕組みを持つ。型ヒントは実行時には検査されないが、mypy などの静的解析ツールを使えば、実行前に型の誤りを発見できる。本書のサンプルコードには、すべて型ヒントを付けている。

4.4. プログラミングパラダイム

プログラムをどのような考え方で組み立てるかを、プログラミングパラダイムと呼ぶ。代表的なパラダイムを次に示す。

パラダイム

考え方

手続き型

命令を順に実行し、変数の値（状態）を書き換えながら結果を求める。コンピュータはどう動くかで見た CPU の動作に近い。

オブジェクト指向プログラミング

データとそれを操作する手続きを「オブジェクト」としてまとめ、オブジェクトどうしのやり取りとしてプログラムを組み立てる。

関数型

状態の書き換えを避け、値を受け取って値を返す関数の組み合わせとしてプログラムを組み立てる。

多くの言語は、複数のパラダイムを取り入れている。Python も、手続き型、オブジェクト指向、関数型のいずれの書き方もできる。次のサンプルコードは、1 から 10 までの偶数の 2 乗の合計を、手続き型と関数型の 2 通りの書き方で求める。

 1"""同じ計算を手続き型と関数型の書き方で比べる。
 2
 3計算内容：1 から 10 までの整数のうち、偶数だけを 2 乗して合計する。
 4"""
 5
 6
 7def sum_of_even_squares_procedural(limit: int) -> int:
 8    """手続き型：状態（total）を順に書き換えて結果を求める。"""
 9    total = 0
10    for number in range(1, limit + 1):
11        if number % 2 == 0:
12            total += number * number
13    return total
14
15
16def sum_of_even_squares_functional(limit: int) -> int:
17    """関数型：状態を書き換えず、式の組み合わせで結果を求める。"""
18    return sum(n * n for n in range(1, limit + 1) if n % 2 == 0)
19
20
21def main() -> None:
22    """2 つの書き方の結果が一致することを確かめる。"""
23    print(sum_of_even_squares_procedural(10))  # 220
24    print(sum_of_even_squares_functional(10))  # 220
25
26
27if __name__ == "__main__":
28    main()

手続き型の書き方（7〜13 行目）では、変数 total の値を繰り返し書き換えて結果を求める。関数型の書き方（16〜18 行目）では、変数を書き換えず、「偶数だけを選ぶ」「2 乗する」「合計する」という操作を組み合わせた 1 つの式で結果を求める。オブジェクト指向の例は抽象化と分割で示す。
