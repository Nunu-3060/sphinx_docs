6. アルゴリズムと計算量

プログラミングとは何かで、プログラミングの中心は手順の設計であると述べた。この章では、その手順であるアルゴリズムと、アルゴリズムの効率を比べるための計算量を説明する。

6.1. アルゴリズムとは

アルゴリズムとは、問題を解くための明確な手順である。ドナルド・クヌースは、アルゴリズムが満たすべき性質として次の 5 つを挙げている[Knuth1997]。

性質

説明

有限性

有限回の手順で必ず終了する。

明確性

各手順が厳密に、曖昧さなく定められている。

入力

0 個以上の入力を持つ。

出力

1 個以上の出力を持つ。

実効性

各手順が、人間が紙と鉛筆で有限の時間内に実行できる程度に基本的である。

同じ問題を解くアルゴリズムは 1 つとは限らない。そして、どのアルゴリズムを選ぶかによって、処理にかかる時間が大きく変わることがある。

6.2. 例：探索

数値の並びから、目的の値がどこにあるかを探す問題を考える。この問題を探索と呼ぶ。

6.2.1. 線形探索

最も素直な方法は、先頭から順に 1 つずつ調べることである。この方法を線形探索と呼ぶ。

 1"""線形探索の実装。"""
 2
 3from collections.abc import Sequence
 4
 5
 6def linear_search(items: Sequence[int], target: int) -> int:
 7    """先頭から順に調べ、target の位置を返す。見つからなければ -1 を返す。"""
 8    for index, value in enumerate(items):
 9        if value == target:
10            return index
11    return -1
12
13
14def main() -> None:
15    """線形探索を試す。"""
16    numbers = [8, 3, 5, 1, 9, 2]
17    print(linear_search(numbers, 9))  # 4
18    print(linear_search(numbers, 7))  # -1
19
20
21if __name__ == "__main__":
22    main()

8〜10 行目で、先頭から順に要素を取り出し、目的の値と等しければその位置を返す。最後まで見つからなければ、11 行目で -1 を返す。データが \(n\) 個あるとき、最悪の場合（目的の値が末尾にあるか、存在しない場合）は \(n\) 回の比較が必要になる。

6.2.2. 二分探索

データが昇順に並んでいるなら、より効率のよい方法がある。探す範囲の中央の値と目的の値を比べ、目的の値の方が大きければ後半を、小さければ前半を次に探す範囲とする。これを繰り返すと、1 回の比較で探す範囲が半分になる。この方法を二分探索と呼ぶ。

 1"""二分探索の実装。"""
 2
 3from collections.abc import Sequence
 4
 5
 6def binary_search(items: Sequence[int], target: int) -> int:
 7    """昇順に並んだ items から target の位置を返す。見つからなければ -1 を返す。"""
 8    low = 0
 9    high = len(items) - 1
10    while low <= high:
11        middle = (low + high) // 2
12        if items[middle] == target:
13            return middle
14        if items[middle] < target:
15            low = middle + 1  # 探す範囲を後半に絞る
16        else:
17            high = middle - 1  # 探す範囲を前半に絞る
18    return -1
19
20
21def main() -> None:
22    """二分探索を試す。"""
23    numbers = [1, 2, 3, 5, 8, 9]  # 昇順に並んでいる必要がある
24    print(binary_search(numbers, 8))  # 4
25    print(binary_search(numbers, 7))  # -1
26
27
28if __name__ == "__main__":
29    main()

8〜9 行目で探す範囲の両端を low と high に設定し、11 行目で中央の位置を求める。14〜17 行目で、比較の結果に応じて探す範囲を後半または前半に絞る。

範囲が半分ずつになるため、データが \(n\) 個のとき、最悪の場合の比較回数は次のとおりである。

\[\lfloor \log_2 n \rfloor + 1\]

ここで \(\lfloor x \rfloor\) は \(x\) 以下の最大の整数を表す。たとえば \(n = 1{,}000{,}000\) のとき、線形探索では最悪 1,000,000 回の比較が必要だが、二分探索では最悪 20 回で済む。

6.3. 計算量

アルゴリズムの効率は、入力の大きさ \(n\) に対して、処理の手間がどのように増えるかで表す。これを計算量と呼び、処理時間に注目したものを時間計算量、使うメモリの量に注目したものを空間計算量と呼ぶ。

6.3.1. O 記法

計算量は、一般に \(O\) 記法で表す。関数 \(f(n)\) と \(g(n)\) について、ある正の定数 \(c\) と \(n_0\) が存在して、\(n_0\) 以上のすべての \(n\) で次の式が成り立つとき、\(f(n) = O(g(n))\) と書く。

\[0 \leq f(n) \leq c \cdot g(n)\]

つまり \(O\) 記法は、\(n\) が十分に大きいときの増え方の上限を、定数倍の違いを無視して表す。たとえば \(3n^2 + 5n + 2\) は \(O(n^2)\) である。この記法を使うと、線形探索の時間計算量は \(O(n)\)、二分探索の時間計算量は \(O(\log n)\) と表せる。

6.3.3. 実測による確認

次のサンプルコードは、データ数を変えながら、線形探索と二分探索で末尾の要素を探す時間を測定する。measure_search.py は linear_search.py と binary_search.py を読み込むため、3 つのファイルを同じフォルダーに置いて実行する。

 1"""線形探索と二分探索の実行時間を比べる。"""
 2
 3import timeit
 4
 5from binary_search import binary_search
 6from linear_search import linear_search
 7
 8
 9def main() -> None:
10    """データ数を変えながら、末尾の要素を探す時間を測定する。"""
11    print(f"{'データ数':>10} {'線形探索[ms]':>14} {'二分探索[ms]':>14}")
12    for size in [1_000, 10_000, 100_000, 1_000_000]:
13        numbers = list(range(size))
14        target = size - 1  # 線形探索にとって最も不利な位置
15        linear = timeit.timeit(
16            lambda: linear_search(numbers, target), number=10
17        )
18        binary = timeit.timeit(
19            lambda: binary_search(numbers, target), number=10
20        )
21        # 10 回分の合計時間を 1 回あたりのミリ秒に換算する
22        print(f"{size:>10} {linear * 100:>14.4f} {binary * 100:>14.4f}")
23
24
25if __name__ == "__main__":
26    main()

実行結果の一例を次に示す。測定値は実行環境によって異なる。

1      データ数       線形探索[ms]       二分探索[ms]
2      1000         0.1926         0.0086
3     10000         1.7002         0.0065
4    100000         5.5966         0.0038
5   1000000        56.8034         0.0046

データ数が 1,000 倍になると、線形探索の時間はおおむね数百倍に増えるのに対し、二分探索の時間はほとんど変わらない。二分探索の時間がデータ数に応じて増えていないように見えるのは、比較回数の増加がわずかで、測定誤差に埋もれているためである。

6.4. アルゴリズムを選ぶときの注意

計算量が小さいアルゴリズムが、常に最良とは限らない。二分探索は、データが整列されていることを前提とする。データを整列するには \(O(n \log n)\) の時間がかかるため、1 回しか探索しないなら線形探索の方が速い。また、\(n\) が小さい場合は、定数倍の違いや実装の単純さの方が重要になることもある。アルゴリズムは、データの量、データの性質、処理の頻度を考慮して選ぶ。
