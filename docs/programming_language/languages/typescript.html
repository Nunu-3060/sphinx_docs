4.11. TypeScript

4.11.1. 基本情報

登場年

2012 年（2014 年に 1.0）

設計者

アンダース・ヘルスバーグ（マイクロソフト）

標準仕様

公式の言語仕様書は更新されておらず、TypeScript コンパイラ（tsc）の挙動が事実上の仕様である。

主な処理系

TypeScript コンパイラ（tsc）。型の検査をせずに型注釈だけを取り除くツール（esbuild、SWC など）や実行環境（Node.js、Deno、Bun）もある。

2026 年時点の状況

コンパイラを Go で書き直したネイティブ版（TypeScript 7）の開発が進められ、型検査の大幅な高速化が図られている。

4.11.2. 誕生の背景と設計思想

2010 年前後には、Web アプリケーションの大規模化に伴い、動的型付けの JavaScript で数十万行規模のコードを保守することの難しさが問題になっていた。マイクロソフトは、C# の設計者でもあるアンダース・ヘルスバーグを中心に、JavaScript に静的型付けを加えた言語として TypeScript を開発した。

TypeScript は、JavaScript の上位集合（スーパーセット）であることを基本方針としている。正しい JavaScript のコードは、基本的にそのまま TypeScript のコードとしても扱える。TypeScript のコードは型注釈を取り除いた JavaScript に変換されて実行され、実行時の挙動は JavaScript と変わらない。そのため、既存の JavaScript のプロジェクトやライブラリと共存しながら、段階的に導入できる。

4.11.3. 主な特徴

  • 漸進的な静的型付け：型注釈を書いた部分から順に型の検査を行う。型を指定しない部分は any 型として扱うこともできる（漸進的型付け）。

  • 構造的部分型：型の互換性を、名前ではなくプロパティの構造で判定する（構造的部分型）。JavaScript のオブジェクトの使い方に合った方式である。

  • 表現力の高い型システム：ユニオン型（string | number）、交差型、リテラル型、ジェネリクス、条件型、マップ型など、JavaScript の動的な書き方に型を付けるための豊富な機能を持つ。

  • 型の消去：型の情報は実行時には残らない（型消去）。外部から受け取ったデータの検証などには、別途実行時の検査が必要である。

  • null 安全：strict オプションを有効にすると、null と undefined を型で区別して検査する。

TypeScript の型システムは、利便性のために健全性（型検査を通ったプログラムでは型の誤りが起きないこと）を一部犠牲にしている。たとえば any 型や型アサーションを使うと、型検査をすり抜けた誤りが実行時に表面化することがある。

近年は、型注釈を取り除くだけで TypeScript のコードを直接実行できる環境が増えている。Deno と Bun は当初から TypeScript を直接実行でき、Node.js も 23.6 以降は標準で型注釈を取り除いて .ts ファイルを実行できる。

4.11.4. コード例

リスト 4.11 word_count.ts
 1// 文章中の単語の出現回数を数え、上位の単語を表示するサンプル
 2
 3type WordCount = readonly [word: string, count: number];
 4
 5/** 英単語を小文字にそろえて出現回数を数える。 */
 6function countWords(text: string): Map<string, number> {
 7  const counts = new Map<string, number>();
 8  for (const word of text.toLowerCase().match(/[a-z]+/g) ?? []) {
 9    counts.set(word, (counts.get(word) ?? 0) + 1);
10  }
11  return counts;
12}
13
14/** 出現回数の降順、同数なら単語の昇順で上位 limit 件を返す。 */
15function topWords(counts: ReadonlyMap<string, number>, limit: number): WordCount[] {
16  return [...counts]
17    .sort(([w1, c1], [w2, c2]) => c2 - c1 || w1.localeCompare(w2))
18    .slice(0, limit);
19}
20
21const text = "The quick brown fox jumps over the lazy dog. The dog sleeps.";
22for (const [word, count] of topWords(countWords(text), 3)) {
23  console.log(`${word}: ${count}`);
24}

処理の内容は JavaScript のコード例と同じであり、違いは型注釈だけである。3 行目では、単語と出現回数の組を、要素に名前を付けた読み取り専用のタプル型 WordCount として定義している。15 行目の ReadonlyMap は、関数が引数の Map を変更しないことを型で表している。JavaScript では JSDoc のコメントで補っていた型の情報が、TypeScript では言語の構文として記述され、コンパイラによって検査される。

4.11.5. 主な用途

  • 大規模な Web フロントエンド（React、Angular、Vue.js などと組み合わせる）

  • サーバサイド（Node.js、Deno、Bun。NestJS など）

  • 開発ツールやエディタの拡張機能（Visual Studio Code 自体も TypeScript で書かれている）

  • 型定義ファイルによる、JavaScript ライブラリへの型情報の提供

4.11.6. エコシステム

  • パッケージマネージャとリポジトリ：JavaScript と共通（npm、pnpm、Yarn と npm レジストリ）

  • 型定義：DefinitelyTyped（@types パッケージ）により、型定義を持たない JavaScript ライブラリにも型を付けられる。

  • ビルドツール：tsc、esbuild、SWC、Vite

  • 開発環境：Visual Studio Code が TypeScript の言語サーバを内蔵している。

4.11.7. 長所と短所

長所

  • JavaScript の資産をそのまま活用しながら、静的型付けの恩恵を受けられる。

  • エディタによる補完やリファクタリングの支援が強力である。

  • 大規模なコードベースやチームでの開発に向く。

短所

  • 型検査やトランスパイルのためのビルド手順が必要になる（直接実行できる環境では軽減される）。

  • 型システムが複雑で、高度な型の記述は読みにくくなりやすい。

  • 型の情報が実行時に残らず、型の健全性も完全ではない。
