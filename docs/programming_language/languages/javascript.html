4.10. JavaScript

4.10.1. 基本情報

登場年

1995 年

設計者

ブレンダン・アイク（ネットスケープ・コミュニケーションズ）

標準仕様

ECMAScript（ECMA-262）。Ecma International の技術委員会 TC39 が策定する。

主な処理系

V8（Google Chrome、Node.js、Deno）、SpiderMonkey（Firefox）、JavaScriptCore（Safari、Bun）

2026 年時点の状況

ECMAScript は 2015 年以降、毎年 6 月ごろに改訂版が発行される。

4.10.2. 誕生の背景と設計思想

JavaScript は、ネットスケープ社の Web ブラウザ Netscape Navigator で動作する言語として、ブレンダン・アイクがわずか 10 日ほどで最初の版を開発したとされる。当初は Mocha、次に LiveScript と呼ばれていたが、当時注目を集めていた Java にあやかって JavaScript と名付けられた。名称は似ているが、Java とは別の言語である。

JavaScript は、Web ページに手軽に動きを加えるためのスクリプト言語として設計された。構文は Java（すなわち C の系統）に似せつつ、Scheme から第一級関数とクロージャを、Self からプロトタイプによるオブジェクト指向を取り入れた。1997 年には、ブラウザ間の互換性を確保するために ECMAScript として標準化された。

その後、Ajax（2005 年ごろ）による動的な Web アプリケーション、高速な JIT コンパイラを備えた V8 エンジン（2008 年）、サーバサイドの実行環境 Node.js（2009 年）の登場を経て、JavaScript は Web のフロントエンドとバックエンドの両方で使われる言語となった。

4.10.3. 主な特徴

  • ブラウザで動作する唯一の標準的な言語：すべての主要な Web ブラウザが JavaScript の実行環境を備えている（WebAssembly も実行できるが、DOM の操作などは JavaScript を介して行う）。

  • 動的型付けかつ弱い型付け：暗黙の型変換が広く行われる。== による比較は型変換を伴うため、型変換を伴わない === を使うのが一般的である。

  • 第一級関数とクロージャ：関数を値として受け渡し、外側のスコープの変数を捕捉できる（クロージャ）。

  • プロトタイプベースのオブジェクト指向：オブジェクトはほかのオブジェクト（プロトタイプ）から直接性質を受け継ぐ（プロトタイプベース）。ECMAScript 2015 で class 構文が導入されたが、内部ではプロトタイプの仕組みが使われている。

  • イベントループと非同期処理：JavaScript のコードは 1 つのスレッドで実行され、I/O などの完了はイベントループを通じてコールバックとして処理される。Promise（ECMAScript 2015）と async・await （ECMAScript 2017）によって、非同期処理を読みやすく記述できる。

  • ECMAScript 2015 による刷新：let・const、アロー関数、クラス、モジュール、テンプレート文字列、分割代入などが追加され、現在の JavaScript の書き方の基礎となった。

4.10.4. コード例

リスト 4.10 word_count.js
 1// 文章中の単語の出現回数を数え、上位の単語を表示するサンプル
 2
 3/**
 4 * 英単語を小文字にそろえて出現回数を数える。
 5 * @param {string} text
 6 * @returns {Map<string, number>}
 7 */
 8function countWords(text) {
 9  const counts = new Map();
10  for (const word of text.toLowerCase().match(/[a-z]+/g) ?? []) {
11    counts.set(word, (counts.get(word) ?? 0) + 1);
12  }
13  return counts;
14}
15
16/**
17 * 出現回数の降順、同数なら単語の昇順で上位 limit 件を返す。
18 * @param {Map<string, number>} counts
19 * @param {number} limit
20 * @returns {[string, number][]}
21 */
22function topWords(counts, limit) {
23  return [...counts]
24    .sort(([w1, c1], [w2, c2]) => c2 - c1 || w1.localeCompare(w2))
25    .slice(0, limit);
26}
27
28const text = "The quick brown fox jumps over the lazy dog. The dog sleeps.";
29for (const [word, count] of topWords(countWords(text), 3)) {
30  console.log(`${word}: ${count}`);
31}

10 行目の match(/[a-z]+/g) は、正規表現に一致した部分を配列で返す。一致しない場合は null を返すため、Null 合体演算子 ?? で空の配列に置き換えている。出現回数は Map （9 行目）で数えている。23 行目の [...counts] はスプレッド構文で Map を「キーと値の組」の配列に変換し、24 行目の比較関数では分割代入で組の要素を取り出している。c2 - c1 || w1.localeCompare(w2) は、出現回数の差が 0（偽）のときだけ単語を比較する慣用的な書き方である。

3〜7 行目や 16〜21 行目の @param などは JSDoc と呼ばれるコメントの記法であり、型の情報を記述しておくと、エディタの補完や TypeScript による型検査に利用できる。

4.10.5. 主な用途

  • Web ブラウザで動作するフロントエンド（React、Vue.js、Angular、Svelte）

  • サーバサイド（Node.js、Deno、Bun 上の Express、Fastify など）

  • デスクトップアプリ（Electron）、モバイルアプリ（React Native）

  • ブラウザの拡張機能、各種アプリケーションのスクリプト

4.10.6. エコシステム

  • 実行環境：Node.js、Deno、Bun

  • パッケージマネージャ：npm、pnpm、Yarn

  • パッケージリポジトリ：npm レジストリ（公開パッケージの数が最も多いリポジトリの 1 つ）

  • ビルドツール：Vite、webpack、esbuild

  • 静的解析・整形：ESLint、Prettier、Biome

4.10.7. 長所と短所

長所

  • Web ブラウザで動作する唯一の標準的な言語であり、Web 開発には欠かせない。

  • フロントエンドとバックエンドを同じ言語で書ける。

  • V8 などの JIT コンパイラにより、動的言語としては非常に高速である。

  • ライブラリやフレームワーク、情報が非常に豊富である。

短所

  • 暗黙の型変換など、歴史的な経緯による言語仕様の癖が多い。

  • 動的型付けのため、大規模な開発では型の誤りが問題になりやすい（TypeScript が広く使われる理由である）。

  • 依存パッケージの数が膨らみやすく、サプライチェーン攻撃の標的になりやすい。

  • フレームワークやツールの移り変わりが速い。
