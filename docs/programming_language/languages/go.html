4.4. Go

4.4.1. 基本情報

登場年

2009 年（2012 年に Go 1.0）

設計者

ロバート・グリーズマー、ロブ・パイク、ケン・トンプソン（Google）

標準仕様

The Go Programming Language Specification（公式の言語仕様）

主な処理系

gc（公式の処理系。Go で実装）、gccgo

2026 年時点の状況

毎年 2 月と 8 月の年 2 回、新しいバージョンが公開される。Go 1 の互換性の約束により、Go 1.0 向けに書かれたコードの多くが現在も変更なしに動作する。

4.4.2. 誕生の背景と設計思想

Go は 2007 年に Google 社内で設計が始まった。当時の Google では、C++ や Java で書かれた大規模なサーバソフトウェアのビルドに長い時間がかかり、言語の複雑さや依存関係の管理も開発効率を下げていた。マルチコア CPU とネットワークサービスが当たり前になる一方で、それに適した言語がないことも問題であった。

ケン・トンプソン（UNIX と B 言語の開発者）らの設計者は、簡潔さを最も重視した。言語仕様は小さく、機能の追加には慎重である。クラスの継承、例外、演算子のオーバーロードといった機能は意図的に採用されていない。読みやすく保守しやすいコードを、大人数のチームで長期間にわたって書き続けられることを目指している。

4.4.3. 主な特徴

  • 簡潔な言語仕様：キーワードは 25 個と少なく、短期間で習得できる。コードの書式は公式のフォーマッタ gofmt によって統一される。

  • 高速なコンパイルと単一の実行ファイル：依存関係を含めて 1 つの実行ファイルに静的リンクされるため、配布やコンテナ化が容易である。クロスコンパイルも環境変数の指定だけで行える。

  • goroutine とチャネル：go キーワードで軽量な並行処理単位である goroutine を起動し、チャネルで値を受け渡す（CSP）。数十万の goroutine を同時に動かすことも可能であり、ランタイムが複数の OS スレッドに割り当てて並列に実行する。

  • ガベージコレクション：停止時間を短く抑えることを重視した並行 GC を備える。

  • 構造的なインタフェース：型がインタフェースのメソッドを備えていれば、明示的な宣言なしにそのインタフェースを満たす（構造的部分型）。

  • エラー値：エラーは例外ではなく、戻り値の error 型として返し、呼び出し側で if err != nil のように確認する。

  • ジェネリクス：長らく存在しなかったが、Go 1.18（2022 年）で型パラメータとして導入された。

4.4.4. コード例

リスト 4.4 word_count.go
 1// Wordcount は文章中の単語の出現回数を数え、上位の単語を表示するサンプルである。
 2package main
 3
 4import (
 5    "cmp"
 6    "fmt"
 7    "regexp"
 8    "slices"
 9    "strings"
10)
11
12type wordCount struct {
13    word  string
14    count int
15}
16
17var wordPattern = regexp.MustCompile(`[a-z]+`)
18
19// countWords は英単語を小文字にそろえて出現回数を数える。
20func countWords(text string) map[string]int {
21    counts := make(map[string]int)
22    for _, w := range wordPattern.FindAllString(strings.ToLower(text), -1) {
23        counts[w]++
24    }
25    return counts
26}
27
28// topWords は出現回数の降順、同数なら単語の昇順で上位 limit 件を返す。
29func topWords(counts map[string]int, limit int) []wordCount {
30    items := make([]wordCount, 0, len(counts))
31    for w, c := range counts {
32        items = append(items, wordCount{word: w, count: c})
33    }
34    slices.SortFunc(items, func(a, b wordCount) int {
35        if c := cmp.Compare(b.count, a.count); c != 0 {
36            return c
37        }
38        return cmp.Compare(a.word, b.word)
39    })
40    return items[:min(limit, len(items))]
41}
42
43func main() {
44    text := "The quick brown fox jumps over the lazy dog. The dog sleeps."
45    for _, wc := range topWords(countWords(text), 3) {
46        fmt.Printf("%s: %d\n", wc.word, wc.count)
47    }
48}

Go の組込みの map 型（21 行目）を使って出現回数を数えている。counts[w]++ （23 行目）は、キーが存在しない場合にゼロ値（int なら 0）から数え始める。並べ替えには、ジェネリクスを使った標準ライブラリの slices.SortFunc （34 行目）を使っている。40 行目の min は Go 1.21 で追加された組込み関数である。

Go の map の反復順序は意図的にランダム化されているため、31〜33 行目でスライスに詰め替えてから並べ替える必要がある。Go のコードは、ほかの言語のように処理を連鎖させるよりも、for ループと if 文で明示的に書くことが好まれる。

4.4.5. 主な用途

  • クラウドインフラ：Docker、Kubernetes、Terraform、Prometheus、etcd

  • マイクロサービスや API サーバなどのバックエンド

  • コマンドラインツール：GitHub CLI、Hugo など

  • ネットワークプログラミング、プロキシ

4.4.6. エコシステム

  • ビルドツールとパッケージ管理：go コマンドがビルド、テスト、依存関係の管理（Go モジュール）、フォーマット、静的解析（go vet）を一元的に扱う。

  • パッケージの検索：pkg.go.dev。パッケージは中央のリポジトリではなく、Git リポジトリなどの URL を基に取得する。

  • 標準ライブラリ：HTTP サーバやクライアント、暗号、JSON などを含み、標準ライブラリだけで実用的なサーバを書ける。

  • 主要なライブラリ：gRPC、Gin、Echo、Cobra

4.4.7. 長所と短所

長所

  • 言語仕様が小さく、習得が容易で、ほかの人が書いたコードも読みやすい。

  • コンパイルが高速で、単一の実行ファイルとして配布できる。

  • goroutine とチャネルによって並行処理を簡潔に書ける。

  • ツール群が標準で揃っており、書式やビルドの方法がプロジェクト間で統一されている。

短所

  • if err != nil によるエラー処理の記述が冗長になりやすい。

  • 表現力が意図的に抑えられており、抽象化の手段が少ない。

  • GC があるため、厳密なリアルタイム性が求められる用途には向かない。

  • null 安全ではなく、nil ポインタの参照による実行時エラーが起こり得る。
