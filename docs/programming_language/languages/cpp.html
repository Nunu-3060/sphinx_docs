4.2. C++

4.2.1. 基本情報

登場年

1983 年（1979 年に「C with Classes」として開発開始、1985 年に最初の商用版）

設計者

ビャーネ・ストロヴストルップ（ベル研究所）

標準仕様

ISO/IEC 14882。C++98 以降、C++11 からは 3 年ごとに改訂。最新の発行済み規格は C++23

主な処理系

GCC、Clang、MSVC

2026 年時点の状況

次期規格 C++26 の策定が最終段階にあり、静的リフレクションや契約プログラミング（contracts）などが加わる予定である。

4.2.2. 誕生の背景と設計思想

ストロヴストルップは、Simula のクラスによる抽象化の有用性と、C の実行効率を兼ね備えた言語を求めて C++ を開発した。C との高い互換性を保ったことで、既存の C のコードや開発者を取り込みながら普及した。

C++ の中心的な設計原則はゼロオーバーヘッド原則である。これは「使わない機能にはコストを払わない」「使う機能は手で書いた場合と同等以上に効率的である」という考え方である。高水準の抽象化（クラス、テンプレート）を提供しながら、実行性能では C に匹敵することを目指している。

4.2.3. 主な特徴

  • マルチパラダイム：手続き型、オブジェクト指向、ジェネリックプログラミング、関数型の書き方をすべて支援する。

  • テンプレート：型や値を引数に取るテンプレートにより、型ごとに最適化されたコードをコンパイル時に生成する（単相化）。C++20 では、テンプレート引数の制約を記述するコンセプト（concepts）が導入された。

  • RAII とスマートポインタ：オブジェクトの寿命に資源の解放を結び付ける RAII により、メモリやファイルなどの資源を自動的に解放する。std::unique_ptr や std::shared_ptr といったスマートポインタを使うことで、new と delete を直接書く必要はほとんどない。

  • 標準ライブラリ：コンテナ（vector、map など）、アルゴリズム、スレッド、正規表現などを含む。

  • 継続的な進化：C++11 でラムダ式、ムーブセマンティクス、auto、スレッドが加わり、「モダン C++」と呼ばれる書き方が定着した。C++20 ではコンセプト、モジュール、コルーチン、Ranges が、C++23 では std::expected や std::print が加わった。

一方、C との互換性を重視したため、C と同じくメモリ安全ではなく、未定義動作も多い。後方互換性を保ちながら機能を追加し続けた結果、言語仕様は非常に大きく複雑になっている。

4.2.4. コード例

リスト 4.2 word_count.cpp
 1// 文章中の単語の出現回数を数え、上位の単語を表示するサンプル
 2#include <algorithm>
 3#include <cctype>
 4#include <cstddef>
 5#include <cstdlib>
 6#include <exception>
 7#include <iostream>
 8#include <map>
 9#include <regex>
10#include <string>
11#include <utility>
12#include <vector>
13
14namespace {
15
16using WordCount = std::pair<std::string, int>;
17
18// 英単語を小文字にそろえて出現回数を数える
19std::map<std::string, int> count_words(std::string text) {
20    std::ranges::transform(text, text.begin(),
21                           [](unsigned char c) { return static_cast<char>(std::tolower(c)); });
22    std::map<std::string, int> counts;
23    const std::regex word_pattern("[a-z]+");
24    for (auto it = std::sregex_iterator(text.begin(), text.end(), word_pattern);
25         it != std::sregex_iterator(); ++it) {
26        ++counts[it->str()];
27    }
28    return counts;
29}
30
31// 出現回数の降順、同数なら単語の昇順で上位 limit 件を返す
32std::vector<WordCount> top_words(const std::map<std::string, int> &counts, std::size_t limit) {
33    std::vector<WordCount> items(counts.begin(), counts.end());
34    std::ranges::sort(items, [](const WordCount &a, const WordCount &b) {
35        return a.second != b.second ? a.second > b.second : a.first < b.first;
36    });
37    if (items.size() > limit) {
38        items.resize(limit);
39    }
40    return items;
41}
42
43} // namespace
44
45int main() {
46    try {
47        const std::string text = "The quick brown fox jumps over the lazy dog. The dog sleeps.";
48        for (const auto &[word, count] : top_words(count_words(text), 3)) {
49            std::cout << word << ": " << count << '\n';
50        }
51    } catch (const std::exception &e) {
52        std::cerr << "error: " << e.what() << '\n';
53        return EXIT_FAILURE;
54    }
55    return EXIT_SUCCESS;
56}

C と比べると、標準ライブラリの std::map （22 行目）や std::regex （23 行目）を使うことで、記述が大幅に簡潔になっている。std::ranges::sort （34 行目）にはラムダ式で比較の規則を渡している。48 行目の const auto &[word, count] は C++17 の構造化束縛であり、ペアの要素を個別の変数として受け取る。

メモリの確保と解放は std::string や std::vector が内部で行い、スコープを抜けると自動的に解放される（RAII）。そのため、このコードには new や delete が一度も現れない。

4.2.5. 主な用途

  • ゲームエンジン（Unreal Engine）とゲーム開発

  • Web ブラウザ（Chromium、Firefox）

  • データベース（MySQL、MongoDB）

  • 金融取引システムなど低遅延が求められる分野

  • 科学技術計算、機械学習フレームワークの内部実装（PyTorch、TensorFlow）

  • 組込みソフトウェア、自動車の制御ソフトウェア

4.2.6. エコシステム

  • ビルドツール：CMake が事実上の標準であり、Meson、Bazel なども使われる。

  • パッケージマネージャ：vcpkg、Conan

  • 主要なライブラリ：Boost、Qt、Eigen、fmt

  • ガイドライン：C++ Core Guidelines（ストロヴストルップらが中心となって作成）

4.2.7. 長所と短所

長所

  • 高い抽象化と高い実行性能を両立できる。

  • C の資産をそのまま利用できる。

  • ゲーム、ブラウザ、金融など、性能が重要な分野で豊富な実績とライブラリがある。

短所

  • 言語仕様が巨大で複雑であり、習得に時間がかかる。

  • メモリ安全ではなく、未定義動作による不具合や脆弱性が起こり得る。

  • コンパイル時間が長く、エラーメッセージ（特にテンプレート関連）が難解になりやすい。

  • ビルドシステムやパッケージ管理が統一されていない。
