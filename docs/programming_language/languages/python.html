4.9. Python

4.9.1. 基本情報

登場年

1991 年（1989 年末に開発開始）

設計者

グイド・ヴァンロッサム。現在は Python Software Foundation と、選挙で選ばれる運営委員会（Steering Council）が開発を統括する。

標準仕様

The Python Language Reference。言語の変更は PEP（Python Enhancement Proposal）として提案・決定される。

主な処理系

CPython（C で実装された標準の処理系）、PyPy（JIT コンパイラを備えた処理系）

2026 年時点の状況

毎年 10 月に新しいマイナーバージョンが公開される。Python 3.13 で GIL を持たないフリースレッド版のビルドが実験的に導入され、Python 3.14 で正式にサポートされた（標準のビルドは引き続き GIL を持つ）。

4.9.2. 誕生の背景と設計思想

Python は、オランダの研究機関 CWI に在籍していたグイド・ヴァンロッサムが、1989 年の年末に趣味のプロジェクトとして開発を始めた言語である。教育用言語 ABC の読みやすさを受け継ぎながら、ABC の欠点であった拡張性の低さを改め、C で書かれたモジュールで機能を拡張できるようにした。名称は、英国のコメディ番組「空飛ぶモンティ・パイソン」に由来する。

Python の設計思想は、PEP 20「The Zen of Python」にまとめられている。「美しいほうがよい」「明示的なほうがよい」「読みやすさは重要である」「明らかなやり方が 1 つ、できればただ 1 つだけあるべきだ」といった原則に表れているとおり、読みやすさと分かりやすさを最も重視している。インデントによってブロックを表す文法も、誰が書いても同じような見た目のコードになることを狙ったものである。

2008 年に公開された Python 3 は、Python 2 との後方互換性を意図的に断ち切り、文字列の Unicode 化などの整理を行った。移行には 10 年以上を要し、Python 2 は 2020 年 1 月にサポートを終了した。

4.9.3. 主な特徴

  • 動的型付けかつ強い型付け：変数に型の宣言は不要だが、型の異なる値の間での暗黙の変換はほとんど行わない。

  • 型ヒント：Python 3.5 以降、関数の引数や戻り値に型注釈を書けるようになった。処理系は実行時に型ヒントを検査しないが、mypy や Pyright などの型検査ツールで静的に検査できる（漸進的型付け）。

  • 豊富な標準ライブラリ：「バッテリー同梱（batteries included）」と呼ばれるように、ファイル操作、ネットワーク、データ形式、テストなどのライブラリが標準で揃っている。

  • 実行方式：CPython はソースコードをバイトコードにコンパイルし、仮想マシンで解釈実行する。Python 3.13 からは実験的な JIT コンパイラも組み込まれている。

  • メモリ管理：CPython は参照カウントを基本とし、循環参照を回収するための GC を併用する。

  • GIL：CPython には、同時に 1 つのスレッドしか Python のバイトコードを実行できないようにする GIL がある。I/O 待ちの多い処理はスレッドで並行に実行できるが、CPU を多く使う処理の並列化にはマルチプロセスや C 拡張を使うのが一般的である。

4.9.4. コード例

リスト 4.9 word_count.py
 1"""文章中の単語の出現回数を数え、上位の単語を表示するサンプル."""
 2
 3import re
 4from collections import Counter
 5
 6TEXT = "The quick brown fox jumps over the lazy dog. The dog sleeps."
 7
 8
 9def count_words(text: str) -> Counter[str]:
10    """英単語を小文字にそろえて出現回数を数える."""
11    return Counter(re.findall(r"[a-z]+", text.lower()))
12
13
14def top_words(counts: Counter[str], limit: int) -> list[tuple[str, int]]:
15    """出現回数の降順、同数なら単語の昇順で上位 limit 件を返す."""
16    return sorted(counts.items(), key=lambda item: (-item[1], item[0]))[:limit]
17
18
19def main() -> None:
20    """サンプルの文章を集計して上位 3 件を表示する."""
21    for word, count in top_words(count_words(TEXT), 3):
22        print(f"{word}: {count}")
23
24
25if __name__ == "__main__":
26    main()

11 行目では、正規表現で切り出した単語のリストを標準ライブラリの collections.Counter に渡すだけで、出現回数を数えている。16 行目の sorted には、並べ替えのキーとして「出現回数の符号を反転した値と単語の組」を返すラムダ式を渡し、出現回数の降順と単語の昇順を同時に実現している。9 行目や 14 行目のような型ヒントを書いておけば、mypy で型の誤りを実行前に検出できる。

4.9.5. 主な用途

  • データ分析、科学技術計算（NumPy、pandas、SciPy、Jupyter）

  • 機械学習、深層学習（PyTorch、TensorFlow、scikit-learn）

  • Web アプリケーション（Django、Flask、FastAPI）

  • 業務の自動化、システム管理、テストの自動化

  • プログラミング教育

特に機械学習の分野では、計算そのものは C、C++、CUDA などで書かれたライブラリが高速に実行し、Python はそれらを組み合わせて制御する役割を担っている。Python が「遅い」言語でありながらこの分野で主流となったのは、こうした分担が可能なためである。

4.9.6. エコシステム

  • パッケージマネージャ：pip、uv（Rust で実装された高速なツール）、Poetry、conda

  • パッケージリポジトリ：PyPI（Python Package Index）

  • 開発ツール：venv（仮想環境）、mypy・Pyright（型検査）、Ruff・flake8（静的解析）、pytest（テスト）

  • 実行環境：Jupyter Notebook、JupyterLab

4.9.7. 長所と短所

長所

  • 文法が簡潔で読みやすく、習得が容易である。

  • データ分析や機械学習を中心に、ライブラリが非常に豊富である。

  • 試行錯誤しながらの開発（対話的な実行やノートブック）に向く。

短所

  • 実行速度が、コンパイル型の言語と比べて大幅に遅い。

  • GIL により、スレッドによる並列処理が制限される（フリースレッド版で解消されつつある）。

  • 動的型付けのため、型の誤りが実行時まで発見されないことがある。

  • パッケージ管理や仮想環境のツールが乱立している。
