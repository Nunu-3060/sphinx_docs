4.3. Rust

4.3.1. 基本情報

登場年

2010 年（2006 年に個人プロジェクトとして開発開始、2015 年に 1.0）

設計者

グレイドン・ホーア。のちに Mozilla が支援し、現在は Rust Foundation とコミュニティが開発を担う。

標準仕様

公式のリファレンスと、唯一の主要な処理系 rustc の挙動が事実上の仕様である。

主な処理系

rustc（バックエンドに LLVM を使用）

2026 年時点の状況

6 週間ごとに新しいバージョンが公開される。言語の非互換な変更は「エディション」として数年ごとにまとめて導入され、最新は Rust 2024 エディション（Rust 1.85、2025 年 2 月）である。

4.3.2. 誕生の背景と設計思想

Rust は、Mozilla の社員であったグレイドン・ホーアが個人的に始めたプロジェクトである。のちに Mozilla が、Web ブラウザのような大規模で並行性の高いソフトウェアを安全に書くための言語として開発を支援した。C や C++ で書かれたソフトウェアでは、メモリ管理の誤りに起因する脆弱性が後を絶たず、また並行処理におけるデータ競合の検出も困難であった。

Rust の目標は、C や C++ と同等の性能と低水準の制御を保ちながら、メモリ安全性とスレッド安全性をコンパイル時に保証することである。そのために、GC を使わず、所有権と借用という独自の仕組みを型システムに組み込んだ。

4.3.3. 主な特徴

  • 所有権と借用：各値の所有者は常に 1 つであり、所有者がスコープを抜けると値は自動的に解放される。値への参照（借用）は、「共有参照（読み取り専用）は複数同時に存在できるが、可変参照は 1 つだけ」という規則のもとで、借用チェッカがコンパイル時に検査する。これにより、解放後の使用、二重解放、データ競合をコンパイル時に排除する。

  • ゼロコスト抽象化：C++ と同様に、ジェネリクスは単相化され、イテレータなどの高水準の抽象化も実行時のコストなしに使える。

  • 代数的データ型とパターンマッチ：値を持てる列挙型（enum）と match 式によって、状態を型安全に表現できる。null は存在せず、値がないことは Option 型で、失敗し得る処理は Result 型で表す。

  • トレイト：型が備える振る舞いをトレイトとして定義する。クラスの継承はなく、トレイトによってポリモーフィズムを実現する。

  • unsafe：ハードウェアの操作や C との連携など、コンパイラが安全性を検証できない処理は unsafe ブロックの中に限定して記述する。危険な箇所が明示されるため、レビューや監査の範囲を絞り込める。

  • async/await：非同期処理の構文を言語として持つが、実行するランタイム（Tokio など）はライブラリとして選択する。

4.3.4. コード例

リスト 4.3 word_count.rs
 1//! 文章中の単語の出現回数を数え、上位の単語を表示するサンプル
 2
 3use std::collections::HashMap;
 4
 5/// 英単語を小文字にそろえて出現回数を数える
 6fn count_words(text: &str) -> HashMap<String, usize> {
 7    let mut counts = HashMap::new();
 8    let words = text
 9        .split(|c: char| !c.is_ascii_alphabetic())
10        .filter(|w| !w.is_empty());
11    for word in words {
12        *counts.entry(word.to_lowercase()).or_insert(0) += 1;
13    }
14    counts
15}
16
17/// 出現回数の降順、同数なら単語の昇順で上位 limit 件を返す
18fn top_words(counts: &HashMap<String, usize>, limit: usize) -> Vec<(&str, usize)> {
19    let mut items: Vec<(&str, usize)> = counts.iter().map(|(w, &c)| (w.as_str(), c)).collect();
20    items.sort_by(|a, b| b.1.cmp(&a.1).then_with(|| a.0.cmp(b.0)));
21    items.truncate(limit);
22    items
23}
24
25fn main() {
26    let text = "The quick brown fox jumps over the lazy dog. The dog sleeps.";
27    let counts = count_words(text);
28    for (word, count) in top_words(&counts, 3) {
29        println!("{word}: {count}");
30    }
31}

6 行目の &str は文字列への借用であり、count_words は文章の所有権を受け取らずに読み取るだけである。12 行目の entry(...).or_insert(0) は、キーがなければ 0 を挿入したうえで値への可変参照を返す。18 行目の戻り値の型 Vec<(&str, usize)> は、counts が持つ文字列への参照を返すことを表しており、counts より長く参照が生き残らないことをコンパイラが検査する。

8〜10 行目や 19〜20 行目のように、イテレータとクロージャを連ねる関数型の書き方が一般的である。これらはコンパイル時に最適化され、手書きのループと同等の性能になる。

4.3.5. 主な用途

  • システムソフトウェア：Linux カーネル（6.1 から Rust によるコードの取り込みが始まった）、Android、Windows の一部のコンポーネント

  • Web ブラウザ：Firefox の CSS エンジンなど

  • クラウドインフラ：AWS の Firecracker、Cloudflare のプロキシなど

  • コマンドラインツール：ripgrep、fd など

  • 開発ツール：Python のパッケージ管理ツール uv や静的解析ツール Ruff、JavaScript 向けの Biome など、他言語向けの高速なツールの実装

  • WebAssembly、組込みソフトウェア

4.3.6. エコシステム

  • ビルドツールとパッケージマネージャ：Cargo。ビルド、依存関係の管理、テスト、ドキュメント生成を一元的に扱う。

  • パッケージリポジトリ：crates.io

  • 開発ツール：rustup（ツールチェーンの管理）、rustfmt（フォーマッタ）、Clippy（静的解析）、rust-analyzer（言語サーバ）

  • 主要なライブラリ：Tokio（非同期ランタイム）、Serde（シリアライズ）、Axum（Web フレームワーク）

4.3.7. 長所と短所

長所

  • GC なしでメモリ安全性とスレッド安全性をコンパイル時に保証する。

  • C や C++ に匹敵する実行性能を持つ。

  • Cargo を中心とした統一的で使いやすいツール群がある。

  • コンパイラのエラーメッセージが丁寧で分かりやすい。

短所

  • 所有権・借用・ライフタイムの概念の習得に時間がかかる。

  • コンパイル時間が長い。

  • 循環参照を持つデータ構造（グラフなど）の表現が難しい。

  • 非同期処理の仕組みが複雑で、ランタイムの選択も必要である。
