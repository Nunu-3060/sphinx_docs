2. データベースと SQL の概要

2.1. データベースとは

データベースとは、整理された形で保存され、検索や更新を効率よく行えるようにしたデータの集まりです。データベースを管理するソフトウェアを DBMS（Database Management System）と呼びます。

Python のプログラムでも、データを CSV ファイルや JSON ファイルに保存できます。しかし、データの量が増えたり、複数のプログラムが同時に同じデータを読み書きしたりするようになると、ファイルを直接扱う方法では次のような問題が生じます。

  • 必要なデータだけを取り出すには、ファイル全体を読み込む必要があります。

  • 複数のプログラムが同時に書き込むと、データが壊れるおそれがあります。

  • 書き込みの途中でプログラムが異常終了すると、データが中途半端な状態で残ります。

  • 「価格は 0 以上」のような規則を守らせる仕組みがありません。

DBMS は、これらの問題を解決する機能を備えています。

2.2. リレーショナルデータベース

現在最も広く使われているのは、リレーショナルデータベース（関係データベース）です。リレーショナルデータベースでは、データを「テーブル」（表）に格納します。テーブルは「列」と「行」で構成されます。

  • 列は、データの項目を表します。列には名前とデータ型があります。

  • 行は、1 件分のデータを表します。

たとえば、商品を管理する products テーブルは次のような形をしています（一部の行のみ示します）。

product_id

name

category_id

stock

列はカラム、行はレコードと呼ばれることもあります。本資料では「列」と「行」に統一します。

テーブルは pandas の DataFrame とよく似ていますが、次のような違いがあります。

リレーショナルデータベースのテーブル

想定していません

2.3. 主キーと外部キー

テーブルの各行を一意に識別するための列を「主キー」（primary key）と呼びます。products テーブルでは product_id 列が主キーです。主キーの値は重複できず、NULL（値がないこと。5 章で説明します）にもできません。

別のテーブル（または同じテーブル）の主キーを参照する列を「外部キー」（foreign key）と呼びます。たとえば、注文を管理する orders テーブルには、注文した顧客を表す customer_id 列があり、この列は customers テーブルの主キー customer_id を参照します。

顧客の名前や住所を orders テーブルに直接書くのではなく、顧客の番号だけを持たせる理由は、同じ情報を何か所にも書くと、変更するときにすべての箇所を修正しなければならず、修正漏れによる矛盾が起こりやすいためです。このように、情報の重複をなくすようにテーブルを分割することを正規化と呼びます。正規化については 11 章（テーブルの設計と定義）で説明します。分割したテーブルを組み合わせて取り出す方法は、7 章（テーブルの結合）で説明します。

2.4. サンプルデータベース

本資料では、架空のネットショップのデータベースを例として使用します。このデータベースは次の 5 つのテーブルで構成されています。

テーブル名

内容

主な列

categories

商品カテゴリ

category_id（主キー）、name（カテゴリ名）、parent_id（親カテゴリの category_id）

products

商品

product_id（主キー）、name（商品名）、category_id（カテゴリ）、price（価格）、stock（在庫数）

customers

顧客

customer_id（主キー）、name（氏名）、prefecture（都道府県）、email（メールアドレス）、registered_on（登録日）

orders

注文

order_id（主キー）、customer_id（注文した顧客）、ordered_on（注文日）、status（状態）

order_items

注文明細

order_id と product_id の組（主キー）、quantity（数量）、unit_price（注文時の単価）

テーブルどうしの参照関係は次のとおりです。矢印は「外部キーが参照する先」を表します。

customers  <----  orders  <----  order_items  ---->  products  ---->  categories
(顧客)            (注文)         (注文明細)          (商品)           (カテゴリ)
                                                                       |    ^
                                                                       +----+
                                                                  parent_id で自分自身を参照

いくつか補足します。

  • 1 件の注文（orders の 1 行）には、複数の商品を含められます。注文に含まれる商品ごとの数量と単価は、order_items テーブルに 1 行ずつ格納します。

  • order_items テーブルの unit_price 列は、注文した時点の単価です。商品の価格（products テーブルの price 列）は後から変わることがあるため、注文時の単価を別に記録しています。

  • categories テーブルの parent_id 列は、同じテーブルの category_id 列を参照します。これにより「食品」の下に「菓子」、「菓子」の下に「チョコレート」のような階層を表現しています。最上位のカテゴリの parent_id は NULL です。

  • orders テーブルの status 列の値は、「受付済」「発送済」「キャンセル」のいずれかです。

各テーブルの全データは、3 章でデータベースを作成した後に確認します。テーブル定義の全体は、付録 E サンプルファイル一覧 の schema.sql で確認できます。

2.5. SQL とは

SQL は、リレーショナルデータベースを操作するための言語です。SQL の大きな特徴は、「宣言的」な言語であることです。

Python のような手続き的な言語では、結果を得るための手順を記述します。たとえば、価格が 500 円以上の商品の名前を取り出す処理は、Python では次のように書けます。

1result = []
2for product in products:
3    if product["price"] >= 500:
4        result.append(product["name"])

一方、SQL では「何が欲しいか」だけを記述します。

1SELECT name FROM products WHERE price >= 500;

SQL には、行を 1 つずつ調べるループも、結果を格納するリストも現れません。データをどのような手順で探すかは DBMS が判断します。そのため、同じ SQL でも、データ量やインデックス（13 章で説明します）の有無に応じて、DBMS が効率のよい方法を選んで実行します。

なお、pandas で書いた場合は df.loc[df["price"] >= 500, "name"] となり、SQL と同じく「条件」と「取り出す列」を指定する形になっています。pandas を使ったことがある方には、SQL の考え方はなじみやすいはずです。

2.6. SQL の分類

SQL の文は、役割によって次のように分類されます。

分類

役割

主な文

DML（Data Manipulation Language、データ操作言語）

データの取得、追加、更新、削除

SELECT、INSERT、UPDATE、DELETE

DDL（Data Definition Language、データ定義言語）

テーブルなどの作成、変更、削除

CREATE、ALTER、DROP

TCL（Transaction Control Language、トランザクション制御言語）

トランザクションの開始、確定、取り消し

BEGIN、COMMIT、ROLLBACK

DCL（Data Control Language、データ制御言語）

ユーザーへの権限の付与、取り消し

GRANT、REVOKE

SELECT 文だけを DQL（Data Query Language、データ問い合わせ言語）として区別する場合もあります。SQLite にはユーザーや権限の概念がないため、DCL は使用しません。

データベースに対する問い合わせ（主に SELECT 文）のことを「クエリ」と呼びます。

2.7. SQL の方言と SQLite

SQL は ISO/IEC 9075 として国際規格化されています。しかし、実際の DBMS（SQLite、PostgreSQL、MySQL、Oracle Database、Microsoft SQL Server など）は、規格の一部だけを実装していたり、独自の拡張を加えていたりします。このような DBMS ごとの違いを SQL の方言と呼びます。

本資料で使用する SQLite には、次のような特徴があります。

  • データベース全体が 1 つのファイルに格納されます。

  • サーバーを起動する必要がなく、プログラムに組み込んで使用できます。

  • Python に標準で付属しており、sqlite3 モジュールからすぐに利用できます。

  • 列のデータ型の扱いが柔軟です（11 章で説明します）。

本資料では、できるだけ多くの DBMS で共通して使える書き方を採用し、SQLite 特有の動作については、その都度説明します。主な DBMS の違いは 付録 B SQL の方言比較 にまとめています。
