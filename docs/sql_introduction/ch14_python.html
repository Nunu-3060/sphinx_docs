14. Python から SQL を使う

本章では、Python のプログラムから SQL を実行する方法を説明します。前半では標準ライブラリの sqlite3 モジュールを、後半では pandas と SQL を組み合わせる方法を扱います。

本章のサンプルは、examples フォルダーで python ch14_basics.py のように実行します。実行する前に、3 章の手順で shop.db を作成しておいてください。

14.1. DB-API 2.0

Python には、データベースを操作するモジュールが備えるべきインターフェースの仕様として、PEP 249（Python Database API Specification v2.0、DB-API 2.0）があります。sqlite3 モジュールはこの仕様に従っています。PostgreSQL 用の psycopg や MySQL 用の mysqlclient など、他の DBMS 用のモジュールも同じ仕様に従っているため、本章で説明する使い方の多くは、他の DBMS でもほぼ同じです。

DB-API 2.0 の主な要素は次のとおりです。

要素

役割

接続（Connection）

データベースへの接続を表します。commit() と rollback() でトランザクションを制御し、close() で接続を閉じます。

カーソル（Cursor）

SQL の実行と、結果の取り出しを行います。execute() で SQL を実行し、fetchone() や fetchall() で結果を取り出します。

sqlite3 モジュールでは、接続の execute() メソッドを呼ぶと、内部でカーソルが作成されて SQL が実行され、そのカーソルが返されます。本章の例では、この簡略化された書き方を使います。

14.2. 基本的な使い方

14.2.1. 接続と結果の取り出し

ch14_basics.py は、sqlite3 モジュールの基本的な使い方を示すスクリプトです。

ch14_basics.py
 1"""sqlite3 モジュールの基本的な使い方（14 章）.
 2
 3接続、SQL の実行、結果の取り出し、プレースホルダーの使い方を示します。
 4このスクリプトはデータを読み込むだけで、shop.db の内容は変更しません。
 5
 6使い方::
 7
 8    python ch14_basics.py
 9"""
10
11import sqlite3
12from contextlib import closing
13from pathlib import Path
14
15DB_PATH = Path(__file__).resolve().parent / "shop.db"
16
17
18def show_fetch_methods(conn: sqlite3.Connection) -> None:
19    """結果を取り出す 3 つの方法を示します."""
20    print("--- fetchone(): 1 行ずつ取り出す")
21    cursor = conn.execute("SELECT COUNT(*) FROM products")
22    row = cursor.fetchone()
23    print(row)  # 行はタプルとして返されます
24
25    print("--- fetchall(): すべての行をリストとして取り出す")
26    cursor = conn.execute(
27        "SELECT name, price FROM products WHERE category_id = 8"
28    )
29    print(cursor.fetchall())
30
31    print("--- for 文: カーソルから 1 行ずつ取り出す")
32    cursor = conn.execute(
33        "SELECT name, price FROM products WHERE category_id = 6"
34    )
35    for name, price in cursor:
36        print(name, price)
37
38
39def show_placeholders(conn: sqlite3.Connection) -> None:
40    """プレースホルダーを使って値を渡す方法を示します."""
41    print("--- ? を使うプレースホルダー")
42    min_price = 500
43    cursor = conn.execute(
44        "SELECT name, price FROM products WHERE price >= ? ORDER BY price",
45        (min_price,),  # 値が 1 つでもタプルで渡します
46    )
47    print(cursor.fetchall())
48
49    print("--- 名前付きのプレースホルダー")
50    cursor = conn.execute(
51        "SELECT name FROM customers"
52        " WHERE prefecture = :pref AND registered_on >= :since",
53        {"pref": "東京都", "since": "2024-02-01"},
54    )
55    print(cursor.fetchall())
56
57    print("--- IN の値の個数が変わる場合")
58    customer_ids = [1, 3, 5]
59    marks = ", ".join("?" for _ in customer_ids)  # "?, ?, ?" を作ります
60    cursor = conn.execute(
61        f"SELECT name FROM customers WHERE customer_id IN ({marks})",
62        customer_ids,
63    )
64    print(cursor.fetchall())
65
66
67def show_row_factory(conn: sqlite3.Connection) -> None:
68    """sqlite3.Row を使って列名で値を参照する方法を示します."""
69    print("--- sqlite3.Row: 列名で値を参照する")
70    conn.row_factory = sqlite3.Row
71    cursor = conn.execute(
72        "SELECT customer_id, name, email FROM customers WHERE customer_id = ?",
73        (3,),
74    )
75    row = cursor.fetchone()
76    print(row["name"], row["email"])  # NULL は None になります
77    print(dict(row))
78    conn.row_factory = None  # 元の設定（タプルで返す）に戻します
79
80
81def main() -> None:
82    """各機能の例を順に実行します."""
83    # closing() を使うと、with 文を抜けるときに接続が閉じられます。
84    with closing(sqlite3.connect(DB_PATH)) as conn:
85        show_fetch_methods(conn)
86        show_placeholders(conn)
87        show_row_factory(conn)
88
89
90if __name__ == "__main__":
91    main()

ポイントを説明します。

接続を閉じる

sqlite3.connect() で開いた接続は、使い終わったら close() で閉じます。contextlib.closing() を使うと、with 文を抜けるときに自動的に閉じられます。接続オブジェクトをそのまま with 文に渡した場合の動作は、後述します。

結果の取り出し

fetchone() は結果を 1 行ずつ、fetchall() はすべての行をリストとして返します。カーソルを for 文で反復すると、1 行ずつ処理できます。結果の行数が多い場合は、すべての行を一度にメモリに読み込む fetchall() より、for 文で反復するほうがメモリの使用量を抑えられます。

行の形式

既定では、各行はタプルとして返されます。接続の row_factory 属性に sqlite3.Row を設定すると、row["name"] のように列名で値を参照できるようになります。

データ型の対応

14.2.2. プレースホルダー

SQL 文に値を渡すときは、SQL 文の中に ? を書き、値を execute() の第 2 引数にタプルやリストで渡します。この ? をプレースホルダーと呼びます。:pref のように名前を付けたプレースホルダーを使い、値を辞書で渡すこともできます。

値が 1 つだけの場合も、(min_price,) のようにタプルで渡します。(min_price) と書くと、括弧は単なる式の括弧とみなされ、タプルにならないので注意してください。

IN の括弧内の値の個数が実行時に決まる場合は、ch14_basics.py の show_placeholders() 関数のように、値の個数だけ ? を並べた文字列を作ってから SQL 文に埋め込みます。埋め込むのは ? だけであり、値そのものはプレースホルダーで渡している点が重要です。

14.3. SQL インジェクション

プレースホルダーを使わずに、f 文字列などで値を SQL 文に直接埋め込んではいけません。利用者が入力した文字列を埋め込むと、SQL 文の意味が書き換えられてしまうおそれがあるためです。このような攻撃を SQL インジェクションと呼びます。

ch14_injection.py は、SQL インジェクションの危険性を示すスクリプトです。

ch14_injection.py
 1"""SQL インジェクションとその対策の例（14 章）.
 2
 3利用者が入力した文字列を SQL 文に直接埋め込むと、
 4SQL 文の意味が書き換えられてしまうことを示します。
 5このスクリプトはデータを読み込むだけで、shop.db の内容は変更しません。
 6
 7使い方::
 8
 9    python ch14_injection.py
10"""
11
12import sqlite3
13from contextlib import closing
14from pathlib import Path
15
16DB_PATH = Path(__file__).resolve().parent / "shop.db"
17
18
19def find_customers_unsafe(conn: sqlite3.Connection, name: str) -> list[str]:
20    """【危険な例】入力された文字列を SQL 文に直接埋め込んで検索します."""
21    sql = f"SELECT name FROM customers WHERE name = '{name}'"
22    print(f"  実行される SQL: {sql}")
23    return [row[0] for row in conn.execute(sql)]
24
25
26def find_customers_safe(conn: sqlite3.Connection, name: str) -> list[str]:
27    """【安全な例】プレースホルダーを使って値を渡して検索します."""
28    sql = "SELECT name FROM customers WHERE name = ?"
29    return [row[0] for row in conn.execute(sql, (name,))]
30
31
32def main() -> None:
33    """通常の入力と悪意のある入力で、2 つの関数の結果を比べます."""
34    inputs = ["佐藤花子", "' OR '1'='1"]
35    with closing(sqlite3.connect(DB_PATH)) as conn:
36        for text in inputs:
37            print(f"入力: {text}")
38            print(f"  危険な例の結果: {find_customers_unsafe(conn, text)}")
39            print(f"  安全な例の結果: {find_customers_safe(conn, text)}")
40
41
42if __name__ == "__main__":
43    main()

実行結果は次のとおりです。

入力: 佐藤花子
  実行される SQL: SELECT name FROM customers WHERE name = '佐藤花子'
  危険な例の結果: ['佐藤花子']
  安全な例の結果: ['佐藤花子']
入力: ' OR '1'='1
  実行される SQL: SELECT name FROM customers WHERE name = '' OR '1'='1'
  危険な例の結果: ['佐藤花子', '鈴木一郎', '高橋美咲', '田中健太', '伊藤さくら', '渡辺翔', '山本優子', '中村大輔']
  安全な例の結果: []

入力として ' OR '1'='1 を与えると、危険な例では SQL 文が WHERE name = '' OR '1'='1' となり、条件が常に真になるため、すべての顧客の氏名が返されてしまいます。入力によっては、データの削除などの操作が行われるおそれもあります。

プレースホルダーを使った安全な例では、入力された文字列は常に 1 つの値として扱われ、SQL 文の一部として解釈されることはありません。そのため、' OR '1'='1 という氏名の顧客を探すことになり、結果は空になります。

警告

SQL 文に値を渡すときは、必ずプレースホルダーを使用してください。テーブル名や列名はプレースホルダーで渡せないため、実行時に切り替える必要がある場合は、あらかじめ用意した名前の一覧に含まれるかを確認してから埋め込みます。

14.4. トランザクションの制御

14.4.1. autocommit 属性

sqlite3 モジュールのトランザクションの扱いは、sqlite3.connect() の autocommit 引数（Python 3.12 で追加）によって、次のように変わります。

autocommit の値

動作

False

接続した時点と commit() や rollback() を呼んだ直後に、トランザクションが自動的に開始されます。常にトランザクションの中にある状態になり、commit() を呼ぶまで変更は確定しません。PEP 249 に従った動作であり、Python のドキュメントで推奨されています。

True

SQLite の自動コミット（12 章を参照）で動作します。トランザクションは、SQL の BEGIN を実行した場合だけ開始されます。

sqlite3.LEGACY_TRANSACTION_CONTROL

現在の既定値。INSERT、UPDATE、DELETE、REPLACE 文の前に、トランザクションが自動的に開始されます。SELECT 文や CREATE TABLE 文などでは開始されません。

Python のドキュメントでは、既定値は将来のバージョンで False に変更される予定とされています。どの値の場合でも、トランザクションの中で行った変更は、commit() を呼ばずに接続を閉じると失われます。本資料の run_query.py は、SQL の BEGIN や COMMIT を書いたとおりに実行するため、autocommit=True を指定しています。

14.4.2. with 文によるトランザクション

接続オブジェクトを with 文に渡すと、ブロックを正常に抜けたときに commit() が、例外が発生したときに rollback() が自動的に呼ばれます。「一連の処理がすべて成功したら確定し、途中で失敗したらすべて取り消す」処理を簡潔に書けます。

ただし、この with 文は接続を閉じません。接続を閉じるには、別途 close() を呼ぶか、contextlib.closing() を使います。

ch14_transaction.py は、12 章で説明した注文の処理を Python で実装したスクリプトです。在庫が足りない商品が含まれている場合は例外を発生させ、その注文に関するすべての変更を取り消します。

ch14_transaction.py
  1"""Python からトランザクションを制御する例（14 章）.
  2
  3注文の追加、注文明細の追加、在庫数の更新を 1 つのトランザクションで行います。
  4在庫が足りない場合は例外を発生させ、すべての変更を取り消します。
  5
  6shop.db の内容を変更しないよう、メモリ上に複製したデータベースを使います。
  7
  8使い方::
  9
 10    python ch14_transaction.py
 11"""
 12
 13import sqlite3
 14from pathlib import Path
 15
 16DB_PATH = Path(__file__).resolve().parent / "shop.db"
 17
 18
 19class OutOfStockError(Exception):
 20    """在庫が足りないことを表す例外です."""
 21
 22
 23def open_copy(db_path: Path) -> sqlite3.Connection:
 24    """データベースをメモリ上に複製して開きます.
 25
 26    PRAGMA foreign_keys はトランザクションの中では効果がないため、
 27    autocommit=True で接続して設定した後で autocommit を False にします。
 28    autocommit を False にすると、常にトランザクションの中にある状態になり、
 29    commit() または rollback() を呼ぶまで変更は確定しません。
 30    """
 31    conn = sqlite3.connect(":memory:", autocommit=True)
 32    source = sqlite3.connect(db_path)
 33    try:
 34        source.backup(conn)
 35    finally:
 36        source.close()
 37    conn.execute("PRAGMA foreign_keys = ON")
 38    conn.autocommit = False
 39    return conn
 40
 41
 42def place_order(
 43    conn: sqlite3.Connection,
 44    order_id: int,
 45    customer_id: int,
 46    ordered_on: str,
 47    items: list[tuple[int, int]],
 48) -> None:
 49    """注文を登録します. items は (商品番号, 数量) のリストです.
 50
 51    with conn: のブロックを正常に抜けると commit() が、
 52    例外が発生すると rollback() が自動的に呼ばれます。
 53    """
 54    with conn:
 55        conn.execute(
 56            "INSERT INTO orders (order_id, customer_id, ordered_on, status)"
 57            " VALUES (?, ?, ?, '受付済')",
 58            (order_id, customer_id, ordered_on),
 59        )
 60        for product_id, quantity in items:
 61            row = conn.execute(
 62                "SELECT price, stock FROM products WHERE product_id = ?",
 63                (product_id,),
 64            ).fetchone()
 65            if row is None:
 66                raise ValueError(f"商品番号 {product_id} の商品はありません")
 67            price, stock = row
 68            if stock < quantity:
 69                raise OutOfStockError(
 70                    f"商品番号 {product_id} の在庫が足りません"
 71                    f"（在庫 {stock}、注文 {quantity}）"
 72                )
 73            conn.execute(
 74                "INSERT INTO order_items"
 75                " (order_id, product_id, quantity, unit_price)"
 76                " VALUES (?, ?, ?, ?)",
 77                (order_id, product_id, quantity, price),
 78            )
 79            conn.execute(
 80                "UPDATE products SET stock = stock - ? WHERE product_id = ?",
 81                (quantity, product_id),
 82            )
 83
 84
 85def show_state(conn: sqlite3.Connection) -> None:
 86    """注文の件数と、商品番号 1 と 5 の在庫数を表示します."""
 87    (order_count,) = conn.execute("SELECT COUNT(*) FROM orders").fetchone()
 88    stocks = conn.execute(
 89        "SELECT product_id, stock FROM products WHERE product_id IN (1, 5)"
 90    ).fetchall()
 91    print(f"  注文の件数: {order_count}、在庫数（商品番号, 在庫数）: {stocks}")
 92
 93
 94def main() -> None:
 95    """成功する注文と、在庫不足で失敗する注文を登録します."""
 96    conn = open_copy(DB_PATH)
 97    try:
 98        print("初期状態:")
 99        show_state(conn)
100
101        print("注文 13（商品番号 1 を 3 個）を登録します。")
102        place_order(conn, 13, 2, "2025-07-01", [(1, 3)])
103        show_state(conn)
104
105        print("注文 14（商品番号 1 を 2 個、商品番号 5 を 1 個）を登録します。")
106        try:
107            place_order(conn, 14, 3, "2025-07-02", [(1, 2), (5, 1)])
108        except OutOfStockError as error:
109            print(f"  エラー: {error}")
110            print("  注文 14 の変更はすべて取り消されました。")
111        show_state(conn)
112    finally:
113        conn.close()
114
115
116if __name__ == "__main__":
117    main()

実行結果は次のとおりです。

初期状態:
  注文の件数: 12、在庫数（商品番号, 在庫数）: [(1, 50), (5, 0)]
注文 13（商品番号 1 を 3 個）を登録します。
  注文の件数: 13、在庫数（商品番号, 在庫数）: [(1, 47), (5, 0)]
注文 14（商品番号 1 を 2 個、商品番号 5 を 1 個）を登録します。
  エラー: 商品番号 5 の在庫が足りません（在庫 0、注文 1）
  注文 14 の変更はすべて取り消されました。
  注文の件数: 13、在庫数（商品番号, 在庫数）: [(1, 47), (5, 0)]

注文 14 では、商品番号 1 の明細の追加と在庫数の更新が行われた後で、商品番号 5 の在庫不足が見つかっています。with conn: のブロックで例外が発生したため rollback() が呼ばれ、商品番号 1 に関する変更も含めて、注文 14 のすべての変更が取り消されています。

注釈

autocommit=False の場合、接続した時点でトランザクションが開始されます。SQLite の PRAGMA foreign_keys = ON; はトランザクションの中で実行しても効果がないため、ch14_transaction.py の open_copy() 関数では、autocommit=True で接続して設定を行った後で、autocommit 属性を False に変更しています。

14.5. 型ヒントを付けたデータアクセス

アプリケーションでは、SQL を実行する処理を関数にまとめ、結果をデータクラスなどの型の決まったオブジェクトに変換して返すと、呼び出す側のコードが読みやすくなります。また、型ヒントを付けておくと、mypy などの型チェッカーで誤りを見つけやすくなります。

ch14_repository.py
 1"""型ヒントを付けたデータアクセス関数の例（14 章）.
 2
 3SQL の実行を関数にまとめ、結果をデータクラスに変換して返します。
 4呼び出す側は SQL を意識せずに、型の決まったオブジェクトとしてデータを扱えます。
 5このスクリプトはデータを読み込むだけで、shop.db の内容は変更しません。
 6
 7使い方::
 8
 9    python ch14_repository.py
10"""
11
12import sqlite3
13from contextlib import closing
14from dataclasses import dataclass
15from pathlib import Path
16
17DB_PATH = Path(__file__).resolve().parent / "shop.db"
18
19
20@dataclass(frozen=True)
21class Product:
22    """商品を表すデータクラスです."""
23
24    product_id: int
25    name: str
26    category_id: int | None  # カテゴリがない商品は None になります
27    price: int
28    stock: int
29
30
31@dataclass(frozen=True)
32class CustomerSales:
33    """顧客ごとの購入金額を表すデータクラスです."""
34
35    customer_id: int
36    name: str
37    total_amount: int
38
39
40def find_products(
41    conn: sqlite3.Connection, max_price: int, in_stock_only: bool = False
42) -> list[Product]:
43    """価格が max_price 以下の商品を、価格の安い順に返します."""
44    sql = (
45        "SELECT product_id, name, category_id, price, stock"
46        " FROM products WHERE price <= ?"
47    )
48    params: list[int] = [max_price]
49    if in_stock_only:
50        # 条件を追加するときも、値はプレースホルダーで渡します。
51        sql += " AND stock > ?"
52        params.append(0)
53    sql += " ORDER BY price, product_id"
54    return [Product(*row) for row in conn.execute(sql, params)]
55
56
57def top_customers(conn: sqlite3.Connection, limit: int) -> list[CustomerSales]:
58    """購入金額（キャンセルを除く）の多い顧客を limit 人まで返します."""
59    sql = """
60        SELECT c.customer_id, c.name, SUM(oi.quantity * oi.unit_price)
61        FROM customers AS c
62        INNER JOIN orders AS o ON c.customer_id = o.customer_id
63        INNER JOIN order_items AS oi ON o.order_id = oi.order_id
64        WHERE o.status <> 'キャンセル'
65        GROUP BY c.customer_id, c.name
66        ORDER BY SUM(oi.quantity * oi.unit_price) DESC, c.customer_id
67        LIMIT ?
68    """
69    return [CustomerSales(*row) for row in conn.execute(sql, (limit,))]
70
71
72def main() -> None:
73    """関数を呼び出して結果を表示します."""
74    with closing(sqlite3.connect(DB_PATH)) as conn:
75        print("価格が 200 円以下で在庫のある商品:")
76        for product in find_products(conn, 200, in_stock_only=True):
77            print(f"  {product.name}: {product.price} 円（在庫 {product.stock}）")
78
79        print("購入金額の上位 3 人:")
80        for rank, customer in enumerate(top_customers(conn, 3), start=1):
81            print(f"  {rank} 位 {customer.name}: {customer.total_amount} 円")
82
83
84if __name__ == "__main__":
85    main()

find_products() 関数では、引数に応じて条件を追加していますが、追加する条件の値もプレースホルダーで渡しています。SQL 文を組み立てる場合でも、値を直接埋め込まないようにしてください。

fetchone() や fetchall()、カーソルの反復で得られる行の型は Any であるため、型チェッカーは SQL の結果の型を検査できません。データクラスの型ヒントと、SQL 文の列の並びや型が一致しているかは、テストなどで確認する必要があります。

14.6. pandas と組み合わせる

pandas の read_sql_query() 関数を使うと、SQL の結果を DataFrame として読み込めます。また、DataFrame の to_sql() メソッドを使うと、DataFrame をデータベースのテーブルとして書き込めます。

ch14_pandas.py
 1"""pandas と SQL を組み合わせる例（14 章）.
 2
 3SQL で集計した結果を DataFrame として読み込む方法と、
 4DataFrame をデータベースのテーブルとして書き込む方法を示します。
 5書き込みはメモリ上のデータベースに対して行うため、shop.db の内容は変更しません。
 6
 7使い方::
 8
 9    python ch14_pandas.py
10"""
11
12import sqlite3
13from contextlib import closing
14from pathlib import Path
15
16import pandas as pd
17
18DB_PATH = Path(__file__).resolve().parent / "shop.db"
19
20
21def monthly_sales(conn: sqlite3.Connection, status: str) -> pd.DataFrame:
22    """指定した状態の注文について、月ごとの売上金額を DataFrame で返します."""
23    sql = """
24        SELECT strftime('%Y-%m', o.ordered_on) AS month,
25               SUM(oi.quantity * oi.unit_price) AS sales
26        FROM orders AS o
27        INNER JOIN order_items AS oi ON o.order_id = oi.order_id
28        WHERE o.status = ?
29        GROUP BY month
30        ORDER BY month
31    """
32    return pd.read_sql_query(sql, conn, params=(status,))
33
34
35def main() -> None:
36    """読み込みと書き込みの例を実行します."""
37    with closing(sqlite3.connect(DB_PATH)) as conn:
38        print("--- SQL で集計した結果を読み込む")
39        sales = monthly_sales(conn, "発送済")
40        print(sales)
41
42        print("--- テーブルを読み込んで pandas で集計する")
43        products = pd.read_sql_query(
44            "SELECT category_id, price FROM products", conn
45        )
46        print(products.groupby("category_id", dropna=False)["price"].mean())
47
48    print("--- DataFrame をテーブルとして書き込む")
49    targets = pd.DataFrame(
50        {
51            "month": ["2025-01", "2025-02", "2025-03"],
52            "target": [3000, 3000, 4000],
53        }
54    )
55    with closing(sqlite3.connect(":memory:")) as mem:
56        targets.to_sql("sales_targets", mem, index=False)
57        print(pd.read_sql_query("SELECT * FROM sales_targets", mem))
58
59
60if __name__ == "__main__":
61    main()

14.6.1. SQL と pandas の使い分け

SQL と pandas のどちらでも、絞り込みや集計を行えます。一般的には、次のように使い分けます。

  • データベースのデータ量が多い場合は、SQL で必要な行と列に絞り込み、集計してから読み込みます。すべてのデータを読み込んでから pandas で処理すると、転送に時間がかかり、メモリも多く使います。

  • 読み込んだ後のデータの整形、統計処理、可視化は、pandas や NumPy で行います。

14.7. ORM

SQL を直接書く代わりに、Python のクラスとテーブルを対応づけ、オブジェクトの操作としてデータベースを扱う仕組みを ORM（Object-Relational Mapping）と呼びます。Python では SQLAlchemy や Django の ORM がよく使われています。

ORM を使うと、DBMS の方言の違いを意識せずにコードを書けるなどの利点があります。しかし、ORM も内部では SQL を生成して実行しています。性能の問題を調べたり、複雑な集計を行ったりする場面では、SQL の知識が必要になります。
