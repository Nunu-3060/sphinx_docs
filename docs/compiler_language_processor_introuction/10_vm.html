第 10 章 コード生成と仮想マシン

コード生成は、プログラムを実際に実行できる形式に変換する段階です。この章では、Tiny のプログラムをバイトコードに変換するコード生成器（tiny_bytecode.py）と、それを実行する仮想マシン（tiny_vm.py）を作ります。CPython や Java の処理系と同じ方式です。

コード生成の対象

コード生成で出力する形式（目的コード）には、いくつかの選択肢があります。

目的コード

本書では、仮想マシンのバイトコードを生成します。仮想マシンを Python で書けるので、ここまでの章と同じく Python だけで完結し、実行結果を確かめやすいからです。機械語を生成する場合に特有の問題（レジスタ割り当てなど）は第 11 章で扱います。

スタックマシンでは、命令は被演算子をスタックから取り出し、結果をスタックに積みます。式の構文木を帰りがけ順（子を先に、親を後に）にたどって命令を出力するだけで正しい命令列になるため、コード生成がとても簡単です。本書の仮想マシンもスタックマシンにします。

命令セットの設計

命令は「命令の種類」と「整数の引数」の組 (Op, int) で表します。引数の意味は命令によって異なり、定数表の番号、局所変数の番号、ジャンプ先の番地などを表します。

バイトコードの生成

局所変数のスロット

木構造インタプリタでは、変数を名前で探していました。バイトコードでは、コンパイル時に各局所変数に番号（スロット）を割り当て、実行時は番号で直接アクセスします。引数は 0 番から順にスロットを割り当て、let で宣言した変数にはその次の番号を割り当てます。ブロックを抜けたら、そのブロックで宣言した変数のスロットは再利用します。

tiny_bytecode.py（ブロックとスロットの再利用）
142    def compile_block(self, block: A.Block) -> None:
143        # ブロックを抜けたら、そのブロックの変数のスロットを再利用する。
144        self.scopes.append({})
145        saved = self.next_slot
146        for stmt in block.stmts:
147            self.compile_stmt(stmt)
148        self.next_slot = saved
149        self.scopes.pop()

式の生成

compile_expr は「式の値を計算してスタックに 1 つ積む」命令列を生成します。二項演算なら、左辺の命令列、右辺の命令列、演算の命令を順に出力します。

tiny_bytecode.py（式の生成）
200    def compile_expr(self, expr: A.Expr) -> None:
201        """式の値を計算し、スタックに 1 つ積む命令を生成する。"""
202        match expr:
203            case A.IntLit(value) | A.BoolLit(value) | A.StrLit(value):
204                self.emit(Op.CONST, self.constant(value))
205            case A.Name(name):
206                self.emit(Op.LOAD, self.lookup(name))
207            case A.ArrayLit(elements):
208                for e in elements:
209                    self.compile_expr(e)
210                self.emit(Op.BUILD_ARRAY, len(elements))
211            case A.Index(target, index):
212                self.compile_expr(target)
213                self.compile_expr(index)
214                self.emit(Op.INDEX)
215            case A.Unary(op, operand):
216                self.compile_expr(operand)
217                self.emit(Op.NEG if op == "-" else Op.NOT)
218            case A.Binary("&&" | "||" as op, left, right):
219                self.compile_expr(left)
220                jump = Op.JUMP_IF_FALSE_OR_POP if op == "&&" \
221                    else Op.JUMP_IF_TRUE_OR_POP
222                to_end = self.emit(jump)
223                self.compile_expr(right)
224                self.patch(to_end)
225            case A.Binary(op, left, right):
226                self.compile_expr(left)
227                self.compile_expr(right)
228                self.emit(BINARY_OPS[op])
229            case A.Call(callee, args):
230                for arg in args:
231                    self.compile_expr(arg)
232                if callee == "print":
233                    self.emit(Op.PRINT, len(args))
234                elif callee in BUILTIN_OPS:
235                    self.emit(BUILTIN_OPS[callee])
236                else:
237                    self.emit(Op.CALL, self.func_index[callee])
238            case _:
239                raise AssertionError(expr)

&& には JUMP_IF_FALSE_OR_POP 命令を使います。左辺が偽ならその値（false）をスタックに残したまま右辺を飛び越し、真なら左辺の値を捨てて右辺を評価します。どちらの場合も、最後にスタックには式の値が 1 つ残ります。

制御構文とバックパッチ

if 文や while 文では、前に進むジャンプ命令を出力する時点では、飛び先の番地がまだ決まっていません。そこで、とりあえず飛び先を 0 にしてジャンプ命令を出力し、その番地を覚えておきます。飛び先の命令を出力する直前に、覚えておいた命令の飛び先を書き換えます（patch）。この技法をバックパッチと呼びます。

tiny_bytecode.py（バックパッチ）
 98    def patch(self, address: int) -> None:
 99        """address のジャンプ命令の飛び先を、次に生成する命令の番地にする。"""
100        op, _ = self.code.code[address]
101        self.code.code[address] = (op, len(self.code.code))
tiny_bytecode.py（if 文と while 文の生成）
166            case A.If(cond, then_body, else_body):
167                self.compile_expr(cond)
168                to_else = self.emit(Op.JUMP_IF_FALSE)
169                self.compile_block(then_body)
170                if else_body is None:
171                    self.patch(to_else)
172                elif always_returns(then_body):
173                    # then 節が必ず return するなら、飛び越す命令は不要。
174                    self.patch(to_else)
175                    self.compile_stmt(else_body)
176                else:
177                    to_end = self.emit(Op.JUMP)
178                    self.patch(to_else)
179                    self.compile_stmt(else_body)
180                    self.patch(to_end)
181            case A.While(cond, body):
182                start = len(self.code.code)
183                self.compile_expr(cond)
184                to_end = self.emit(Op.JUMP_IF_FALSE)
185                self.compile_block(body)
186                self.emit(Op.JUMP, start)
187                self.patch(to_end)

while 文の末尾から条件の判定に戻るジャンプは後ろ向きなので、飛び先の番地（start）は出力の時点で分かっています。

仮想マシンの実装

値スタックとフレーム

本書の仮想マシンは、すべての関数呼び出しで 1 本の値スタックを共有します。関数を呼び出すと、呼び出し元が積んだ引数の位置をそのまま局所変数の先頭とし、残りの局所変数の領域を確保します。局所変数の先頭位置をベースポインタ（bp）と呼び、局所変数 k 番は stack[bp + k] にあります。

関数呼び出し 1 回分の情報（実行中のコード、次に実行する番地 pc、ベースポインタ bp）をスタックフレームと呼び、フレームのリストで呼び出しの入れ子を管理します。

tiny_vm.py（フレームと関数の呼び出し）
30@dataclass
31class Frame:
32    """関数呼び出し 1 回分の情報（スタックフレーム）。"""
33
34    code: CodeObject
35    pc: int  # 次に実行する命令の番地
36    bp: int  # 局所変数 0 番の値スタック上の位置
37
38
39class VM:
40    def __init__(self, program: CompiledProgram,
41                 out: TextIO = sys.stdout) -> None:
42        self.program = program
43        self.out = out
44        self.stack: list[Value] = []
45        self.frames: list[Frame] = []
46        self.steps = 0  # 実行した命令の数
47
48    def run(self) -> None:
49        self.call(self.program.functions[self.program.main])
50        self.execute()
51
52    def call(self, code: CodeObject) -> None:
53        """引数は値スタックに積まれている。残りの局所変数の領域を確保する。"""
54        if len(self.frames) >= MAX_FRAMES:
55            raise TinyRuntimeError("関数呼び出しが深すぎます")
56        bp = len(self.stack) - code.num_params
57        self.stack.extend([None] * (code.num_locals - code.num_params))
58        self.frames.append(Frame(code, 0, bp))

命令の実行ループ

仮想マシンの中心は、命令を 1 つ取り出しては実行することを繰り返すループです。これを命令のディスパッチループと呼びます。

tiny_vm.py（命令の実行ループ）
 60    def execute(self) -> None:
 61        stack = self.stack
 62        frame = self.frames[-1]
 63        code, constants = frame.code.code, frame.code.constants
 64        while True:
 65            op, arg = code[frame.pc]
 66            frame.pc += 1
 67            self.steps += 1
 68            match op:
 69                case Op.CONST:
 70                    stack.append(constants[arg])
 71                case Op.LOAD:
 72                    stack.append(stack[frame.bp + arg])
 73                case Op.STORE:
 74                    stack[frame.bp + arg] = stack.pop()
 75                case Op.ADD | Op.SUB | Op.MUL | Op.DIV | Op.MOD | Op.EQ \
 76                        | Op.NE | Op.LT | Op.LE | Op.GT | Op.GE:
 77                    right = stack.pop()
 78                    stack[-1] = binary_op(BINARY_SYMBOLS[op], stack[-1], right)
 79                case Op.NEG:
 80                    stack[-1] = unary_op("-", stack[-1])
 81                case Op.NOT:
 82                    stack[-1] = unary_op("!", stack[-1])
 83                case Op.JUMP:
 84                    frame.pc = arg
 85                case Op.JUMP_IF_FALSE:
 86                    if not stack.pop():
 87                        frame.pc = arg
 88                case Op.JUMP_IF_FALSE_OR_POP:
 89                    if stack[-1]:
 90                        stack.pop()
 91                    else:
 92                        frame.pc = arg
 93                case Op.JUMP_IF_TRUE_OR_POP:
 94                    if stack[-1]:
 95                        frame.pc = arg
 96                    else:
 97                        stack.pop()
 98                case Op.BUILD_ARRAY:
 99                    elements = stack[len(stack) - arg:]
100                    del stack[len(stack) - arg:]
101                    stack.append(elements)
102                case Op.INDEX:
103                    index = stack.pop()
104                    stack[-1] = index_value(stack[-1], index)
105                case Op.STORE_INDEX:
106                    value = stack.pop()
107                    index = stack.pop()
108                    store_index(stack.pop(), index, value)
109                case Op.PRINT | Op.LEN | Op.PUSH | Op.TO_STR:
110                    self.builtin(op, arg)
111                case Op.POP:
112                    stack.pop()
113                case Op.CALL:
114                    self.call(self.program.functions[arg])
115                    frame = self.frames[-1]
116                    code, constants = frame.code.code, frame.code.constants
117                case Op.RETURN:
118                    result = stack.pop()
119                    del stack[frame.bp:]  # 引数と局所変数を捨てる
120                    self.frames.pop()
121                    if not self.frames:
122                        return
123                    stack.append(result)
124                    frame = self.frames[-1]
125                    code, constants = frame.code.code, frame.code.constants

CALL 命令は新しいフレームを積み、実行中のコードを呼び出し先に切り替えます。RETURN 命令は戻り値を取り出し、引数と局所変数をスタックから捨て、フレームを降ろして呼び出し元に戻ります。そして戻り値をスタックに積みます。Python の再帰呼び出しを使っていないので、Tiny の関数呼び出しの深さは Python の再帰の上限に制限されません（本書の実装では MAX_FRAMES で上限を設けています）。

性能の比較

tiny_vm.py を引数なしで実行すると、fib(22) の計算にかかった時間を、木構造インタプリタと仮想マシンで比べます。

1$ python tiny_vm.py
217711
3木構造インタプリタ: 0.84 秒
417711
5仮想マシン:         0.64 秒

筆者の環境（Python 3.14）では、仮想マシンのほうが 2 割から 3 割ほど速くなりました。変数の名前による探索がスロット番号によるアクセスに変わったことや、再帰的な評価の呼び出しがなくなったことが効いています。ただし、差はそれほど大きくありません。仮想マシンも Python で書かれているため、命令 1 つの実行にも match 文による分岐やリストの操作など多くの処理がかかるからです。C 言語で書かれた実用的な処理系では、木構造インタプリタと仮想マシンの差はより大きくなります。

ディスパッチの高速化

仮想マシンの性能は、命令のディスパッチの効率に大きく左右されます。代表的な高速化の手法を挙げます。

手法

内容

スレッデッドコード

switch 文の代わりに、各命令の処理の末尾から次の命令の処理へ直接ジャンプする（CPython は C コンパイラの拡張機能 computed goto でこれを行っている）

スーパー命令

よく連続して現れる命令の組を 1 つの命令にまとめ、ディスパッチの回数を減らす（CPython 3.14 の LOAD_FAST_BORROW_LOAD_FAST_BORROW など）

特殊化

実行時に観測した型に応じて、命令をより特殊で高速な命令に書き換える（CPython 3.11 以降の特殊化適応型インタプリタ [PEP659]）

レジスタマシン化

スタックへの積み降ろしを減らし、命令の数を減らす

まとめ

  • スタックマシンでは、構文木を帰りがけ順にたどって命令を出力するだけでコードを生成できます。

  • 局所変数にはコンパイル時にスロット番号を割り当て、実行時は番号でアクセスします。

  • 前に進むジャンプの飛び先は、バックパッチで後から書き込みます。

  • 仮想マシンは値スタックとスタックフレームを持ち、命令を 1 つずつディスパッチして実行します。

  • 仮想マシンの性能はディスパッチの効率に左右され、スレッデッドコードや特殊化などの高速化の手法があります。
