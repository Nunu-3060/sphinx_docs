第 5 章 抽象構文木と Tiny の構文解析器

この章では、構文解析の結果を表す抽象構文木を設計し、第 4 章の手法を組み合わせて Tiny 全体の構文解析器を作ります。

具象構文木と抽象構文木

第 4 章の構文木（具象構文木）は、文法の規則をそのまま反映しているため、後の処理にとって不要な情報を多く含んでいます。たとえば 1 + 2 * 3 の構文木には term や factor といった中間のノードや、括弧のトークンが含まれます。しかし、計算の内容を表すには「1 と、2 と 3 の積との和」が分かれば十分です。

そこで、プログラムの意味に必要な情報だけを残した木を作ります。これを抽象構文木（AST: Abstract Syntax Tree）と呼びます。次の図は、let x = 1 + 2 * 3; の抽象構文木です。

括弧は木の形に反映されるので、抽象構文木には残りません。(1 + 2) * 3 なら、根が * で、その左の子が + の木になります。

抽象構文木の設計

Tiny の抽象構文木は tiny_ast.py にデータクラスで定義します。まず、型を表すクラスです。型はソースコード中の型注釈（[int] など）を表すほか、意味解析で式の型を記録するのにも使います。

41@dataclass(frozen=True)

データクラスは == で値として比較できるので、ArrayType(INT) == ArrayType(INT) は True になります。さらに frozen=True を指定すると、値を変更できなくなる代わりにハッシュ可能になり、辞書のキーにも使えます。

Tiny の構文解析器

構文解析器は tiny_parser.py に実装します。文と関数定義は再帰下降構文解析で、式は Pratt 構文解析で解析します。

文の解析

parse_statement は、最初のトークンを見てどの種類の文かを判断します。let、if、while、return、{ のどれでもなければ、代入文か式文です。この 2 つは先頭を見ただけでは区別できないため、まず式として解析し、その後に = が続くかどうかで判断します。代入文の場合は、左辺が変数か添字式であることを確かめます。

tiny_parser.py（文の解析）
177    def parse_statement(self) -> Stmt:
178        token = self.peek()
179        line = token.line
180        match token.kind:
181            case TokenKind.LBRACE:
182                return self.parse_block()
183            case TokenKind.LET:
184                # "let" IDENT [ ":" type ] "=" expr ";"
185                self.advance()
186                name = self.expect(TokenKind.IDENT, "変数名").text
187                declared: Type | None = None
188                if self.accept(TokenKind.COLON):
189                    declared = self.parse_type()
190                self.expect(TokenKind.ASSIGN, "=")
191                value = self.parse_expr()
192                self.expect(TokenKind.SEMICOLON, ";")
193                return Let(name, declared, value, line=line)
194            case TokenKind.IF:
195                return self.parse_if()
196            case TokenKind.WHILE:
197                # "while" "(" expr ")" block
198                self.advance()
199                self.expect(TokenKind.LPAREN, "(")
200                cond = self.parse_expr()
201                self.expect(TokenKind.RPAREN, ")")
202                return While(cond, self.parse_block(), line=line)
203            case TokenKind.RETURN:
204                # "return" [ expr ] ";"
205                self.advance()
206                result = None
207                if not self.at(TokenKind.SEMICOLON):
208                    result = self.parse_expr()
209                self.expect(TokenKind.SEMICOLON, ";")
210                return Return(result, line=line)
211        # 代入文または式文: expr [ "=" expr ] ";"
212        expr = self.parse_expr()
213        if self.accept(TokenKind.ASSIGN):
214            if not isinstance(expr, (Name, Index)):
215                raise ParseError("代入の左辺が不正です", token.line,
216                                 token.column)
217            value = self.parse_expr()
218            self.expect(TokenKind.SEMICOLON, ";")
219            return Assign(expr, value, line=line)
220        self.expect(TokenKind.SEMICOLON, ";")
221        return ExprStmt(expr, line=line)

else if の連鎖は parse_if を再帰的に呼び出して解析します。

tiny_parser.py（if 文の解析）
223    def parse_if(self) -> If:
224        # "if" "(" expr ")" block [ "else" ( block | if ) ]
225        line = self.expect(TokenKind.IF, "if").line
226        self.expect(TokenKind.LPAREN, "(")
227        cond = self.parse_expr()
228        self.expect(TokenKind.RPAREN, ")")
229        then_body = self.parse_block()
230        else_body: Stmt | None = None
231        if self.accept(TokenKind.ELSE):
232            else_body = (self.parse_if() if self.at(TokenKind.IF)
233                         else self.parse_block())
234        return If(cond, then_body, else_body, line=line)

式の解析

式の解析は第 4 章の Pratt 構文解析と同じ形です。違いは、文字列の代わりに抽象構文木のノードを作ることと、関数呼び出し f(...) と添字 a[...] という後置の演算子を扱うことです。後置の演算子にはどの二項演算子よりも大きな結合力 POSTFIX_POWER を与えているので、-a[0] は -(a[0]) と解釈されます。

tiny_parser.py（式の解析）
238    def parse_expr(self, min_power: int = 0) -> Expr:
239        left = self.parse_prefix()
240        while True:
241            token = self.peek()
242            if token.kind in (TokenKind.LPAREN, TokenKind.LBRACKET):
243                if POSTFIX_POWER < min_power:
244                    return left
245                left = self.parse_postfix(left)
246                continue
247            power = BINARY_POWER.get(token.kind)
248            if power is None or power[0] < min_power:
249                return left
250            self.advance()
251            right = self.parse_expr(power[1])
252            left = Binary(token.text, left, right, line=token.line)
253
254    def parse_postfix(self, left: Expr) -> Expr:
255        token = self.advance()
256        if token.kind is TokenKind.LBRACKET:
257            index = self.parse_expr()
258            self.expect(TokenKind.RBRACKET, "]")
259            return Index(left, index, line=token.line)
260        if not isinstance(left, Name):
261            raise ParseError("関数名以外は呼び出せません", token.line,
262                             token.column)
263        args = self.parse_list(TokenKind.RPAREN, ")")
264        return Call(left.name, args, line=left.line)
265

被演算子になる式（リテラル、変数、単項演算子、括弧、配列リテラル）は parse_prefix で解析します。

tiny_parser.py（被演算子の解析）
276    def parse_prefix(self) -> Expr:
277        token = self.peek()
278        if token.kind not in PREFIX_START:
279            raise self.error("式が必要です")
280        self.advance()
281        line = token.line
282        match token.kind:
283            case TokenKind.INT:
284                assert isinstance(token.value, int)
285                return IntLit(token.value, line=line)
286            case TokenKind.STRING:
287                assert isinstance(token.value, str)
288                return StrLit(token.value, line=line)
289            case TokenKind.TRUE:
290                return BoolLit(True, line=line)
291            case TokenKind.FALSE:
292                return BoolLit(False, line=line)
293            case TokenKind.IDENT:
294                return Name(token.text, line=line)
295            case TokenKind.MINUS | TokenKind.NOT:
296                operand = self.parse_expr(PREFIX_POWER)
297                return Unary(token.text, operand, line=line)
298            case TokenKind.LPAREN:
299                inner = self.parse_expr()
300                self.expect(TokenKind.RPAREN, ")")
301                return inner
302            case TokenKind.LBRACKET:
303                elements = self.parse_list(TokenKind.RBRACKET, "]")
304                return ArrayLit(elements, line=line)
305        raise AssertionError(token.kind)

エラー回復の実装

第 4 章で説明したパニックモードのエラー回復を、parse_block と synchronize で実装しています。文の解析中に構文エラー（ParseError）が起きたら、エラーを記録し、文の区切りまでトークンを読み飛ばして次の文から解析を再開します。

tiny_parser.py（読み飛ばし）
 98    def synchronize(self) -> None:
 99        """エラー回復: 文の区切りまで字句を読み飛ばす。"""
100        while not self.at(TokenKind.EOF):
101            if self.accept(TokenKind.SEMICOLON):
102                return
103            if self.peek().kind in (*STATEMENT_START, TokenKind.RBRACE):
104                return
105            self.advance()
tiny_parser.py（ブロックの解析とエラー回復）
161    def parse_block(self) -> Block:
162        # block = "{" { statement } "}"
163        line = self.expect(TokenKind.LBRACE, "{").line
164        stmts: list[Stmt] = []
165        while not self.at(TokenKind.RBRACE) and not self.at(TokenKind.EOF):
166            start = self.pos
167            try:
168                stmts.append(self.parse_statement())
169            except ParseError as e:
170                self.errors.append(e)
171                self.synchronize()
172                if self.pos == start:  # 1 字句も進まなければ強制的に進める
173                    self.advance()
174        self.expect(TokenKind.RBRACE, "}")
175        return Block(stmts, line=line)

synchronize がトークンを 1 つも読み進めなかった場合は、強制的に 1 つ進めています。そうしないと、同じ位置で同じエラーが起き続けて無限ループになるおそれがあるからです。

次のプログラムには 3 つの誤りがあります。2 行目は初期値がなく、3 行目は ; がなく、4 行目は引数の間に , がありません。

error.tiny
1fn main() {
2    let x = ;
3    let y = 1
4    print(x y);
5}

1$ python tiny.py ast error.tiny
2error.tiny:2:13: 式が必要です（';' があります）
3error.tiny:4:5: ; が必要です（'print' があります）

2 行目と 3 行目の誤りは報告されましたが、4 行目の誤りは報告されていません。3 行目の誤りから回復するときに、print が文の先頭になるキーワードではないため、4 行目の ; まで読み飛ばしてしまったからです。このように、パニックモードは単純ですが、読み飛ばした範囲にある誤りは見逃します。また、; の抜けのエラーは次の行の位置で報告されます。実用的なコンパイラは、「; が抜けているとみなして解析を続ける」といった、より細かな回復の手法を組み合わせています。

構文木をたどる

抽象構文木を使う処理（意味解析、インタプリタ、コード生成など）は、どれも「ノードの種類に応じて処理を変えながら木をたどる」という形になります。オブジェクト指向言語では、これを Visitor パターンで書くのが伝統的な方法です。

Visitor パターンによる評価（概略）
 1class Visitor:
 2    def visit(self, node: Node) -> object:
 3        method = getattr(self, "visit_" + type(node).__name__)
 4        return method(node)
 5
 6
 7class Evaluator(Visitor):
 8    def visit_IntLit(self, node: IntLit) -> object:
 9        return node.value
10
11    def visit_Binary(self, node: Binary) -> object:
12        left = self.visit(node.left)
13        right = self.visit(node.right)
14        ...

Python 3.10 以降では、match 文の構造的パターンマッチを使うと、同じ処理をより直接的に書けます。データクラスは __match_args__ を自動的に定義するので、Binary(op, left, right) のように、フィールドを取り出しながらノードの種類で分岐できます。本書の処理系では、この match 文による書き方を使います。

match 文による評価（概略）
1def evaluate(node: Expr) -> object:
2    match node:
3        case IntLit(value):
4            return value
5        case Binary("+", left, right):
6            return evaluate(left) + evaluate(right)
7        ...

Python の ast モジュール

第 1 章で見たように、Python の ast モジュールを使うと Python のプログラムの抽象構文木を得られます。ast モジュールには Visitor パターンの基底クラス ast.NodeVisitor も用意されており、visit_クラス名 というメソッドを定義すると、そのノードを訪れたときに呼び出されます。次の例は、式の中で読み出している変数の名前を集めます。

ast.NodeVisitor の使用例
 1import ast
 2
 3
 4class NameCollector(ast.NodeVisitor):
 5    """読み出している変数の名前を集める."""
 6
 7    def __init__(self) -> None:
 8        self.names: list[str] = []
 9
10    def visit_Name(self, node: ast.Name) -> None:
11        if isinstance(node.ctx, ast.Load):
12            self.names.append(node.id)
13        self.generic_visit(node)
14
15
16tree = ast.parse("total = price * count + tax")
17collector = NameCollector()
18collector.visit(tree)
19print(collector.names)  # ['price', 'count', 'tax']

Python の Name ノードは、読み出し（Load）か書き込み（Store）かを ctx 属性で区別しています。そのため、代入先の total は集められていません。このような ast モジュールの機能は、flake8 などの静的解析ツールや、コードの自動変換ツールで広く使われています。

まとめ

  • 抽象構文木は、構文木から意味に必要な情報だけを残した木で、後の段階はすべて抽象構文木を入力とします。

  • Tiny の構文解析器は、文を再帰下降構文解析で、式を Pratt 構文解析で解析します。

  • パニックモードのエラー回復では、文の区切りまで読み飛ばして解析を続けます。単純ですが、読み飛ばした範囲の誤りは見逃します。

  • 抽象構文木をたどる処理は、Visitor パターンや match 文で書けます。
