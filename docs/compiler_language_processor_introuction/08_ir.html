第 8 章 中間表現

この章からはコンパイラの「後半」に入ります。まず、抽象構文木を、機械の命令に近い単純な命令の列である中間表現（IR: Intermediate Representation）に変換します。さらに、制御フローグラフ、支配関係、SSA 形式という、現代のコンパイラの最適化を支える概念を実装しながら学びます。

中間表現の役割

抽象構文木はソースコードの構造をよく表していますが、最適化やコード生成には向いていません。たとえば a[i + 1] = a[i] * 2 + f(x) という 1 つの文の中にも、加算、添字の読み出し、乗算、関数呼び出し、添字への書き込みという複数の計算が入れ子になっています。「同じ計算を 2 回していないか」「この値はもう使われないか」といった分析をするには、計算を 1 つずつばらばらにして、順序と値の流れを明示した形のほうが便利です。

中間表現には抽象度の異なるさまざまな種類があります。

三番地コード

本書の IR は三番地コードと呼ばれる形式です。各命令は x = y + z のように、最大 3 つの番地（変数や定数）しか扱いません。入れ子になった式は、一時変数を使って分解します。一時変数は %1、%2 のように % で始まる名前にして、ソースコードの変数と区別します。

基本ブロックと制御フローグラフ

途中に分岐も合流もなく、先頭から末尾まで一直線に実行される命令の列を基本ブロックと呼びます。基本ブロックの末尾には、次にどこへ進むかを表す終端命令（jump、branch、return）を 1 つだけ置きます。基本ブロックを節点とし、実行が移りうる関係を辺としたグラフを制御フローグラフ（CFG: Control Flow Graph）と呼びます。

抽象構文木から IR への変換

抽象構文木から IR への変換は Lowering クラスが行います。Lowering は「組み立て中の基本ブロック」を持ち、emit で命令を追加し、terminate で終端命令を置いてブロックを閉じ、start_block で新しいブロックを始めます。

式の変換

式の変換 lower_expr は、式の値を計算する命令を出力し、その値を表すオペランドを返します。リテラルなら定数を、変数ならその変数を返し、演算なら一時変数に結果を入れる命令を出力してその一時変数を返します。

tiny_ir.py（式の変換）
443    def lower_expr(self, expr: A.Expr) -> Operand:
444        match expr:
445            case A.IntLit(value) | A.BoolLit(value) | A.StrLit(value):
446                return Const(value)
447            case A.Name(name):
448                return Var(self.lookup(name))
449            case A.ArrayLit(elements):
450                values = [self.lower_expr(e) for e in elements]
451                dst = self.new_temp()
452                self.emit(NewArray(dst, values))
453                return Var(dst)
454            case A.Index(target, index):
455                base = self.lower_expr(target)
456                i = self.lower_expr(index)
457                dst = self.new_temp()
458                self.emit(Load(dst, base, i))
459                return Var(dst)
460            case A.Unary(op, operand):
461                src = self.lower_expr(operand)
462                dst = self.new_temp()
463                self.emit(UnOp(dst, op, src))
464                return Var(dst)
465            case A.Binary("&&" | "||" as op, left, right):
466                return self.lower_logical(op, left, right)
467            case A.Binary(op, left, right):
468                lhs = self.lower_expr(left)
469                rhs = self.lower_expr(right)
470                dst = self.new_temp()
471                self.emit(BinOp(dst, op, lhs, rhs))
472                return Var(dst)
473            case A.Call(callee, args):
474                values = [self.lower_expr(a) for a in args]
475                if expr.ty == A.VOID:
476                    self.emit(Call(None, callee, values))
477                    return Const(None)
478                dst = self.new_temp()
479                self.emit(Call(dst, callee, values))
480                return Var(dst)
481        raise AssertionError(expr)

&& と || は、短絡評価を表すために分岐に変換します。a && b では、a が偽なら b を評価せずに終わり、a が真なら b の値が結果になります。結果を入れる一時変数には、2 つのブロックで値を代入しています。

tiny_ir.py（短絡評価の変換）
483    def lower_logical(self, op: str, left: A.Expr, right: A.Expr) -> Operand:
484        """短絡評価: 左辺だけで結果が決まれば右辺を評価しない。"""
485        result = self.new_temp()
486        n = self.new_id()
487        rhs_label, end_label = f"rhs{n}", f"endlogic{n}"
488        lhs = self.lower_expr(left)
489        self.emit(Copy(result, lhs))
490        if op == "&&":
491            self.terminate(Branch(lhs, rhs_label, end_label))
492        else:
493            self.terminate(Branch(lhs, end_label, rhs_label))
494        self.start_block(rhs_label)
495        self.emit(Copy(result, self.lower_expr(right)))
496        self.start_block(end_label)
497        return Var(result)

if 文と while 文は、条件分岐と基本ブロックの組み合わせに変換します。1 つの文から作るラベルには同じ番号を付けて、対応が分かるようにしています（then1、else1、endif1 など）。

内側のブロックで外側と同じ名前の変数を宣言した場合は、x#2 のように名前を変えて区別します。IR には入れ子のスコープがないので、別の変数には別の名前を付ける必要があるからです。また、return 文の後ろに書かれた到達不能な命令は、変換の最後に remove_unreachable で取り除きます。

IR インタプリタ

変換した IR が正しいかを確かめるため、IR を直接実行する IRInterpreter も用意しています。基本ブロックの命令を順に実行し、終端命令に従って次のブロックに移ります。steps には実行した命令の数を数えており、第 9 章で最適化の効果を測るのに使います。

支配関係

制御フローグラフの分析で基本となるのが支配の関係です。

入口から基本ブロック \(n\) に至るすべての経路が基本ブロック \(d\) を通るとき、「\(d\) は \(n\) を支配する」といい、\(d \mathrel{\mathrm{dom}} n\) と書きます。どの基本ブロックも自分自身を支配します。\(n\) 以外で \(n\) を支配するブロックのうち、\(n\) に最も近いものを \(n\) の直接支配ブロック（\(\mathrm{idom}(n)\)）と呼びます。各ブロックからその直接支配ブロックへ辺を張ると木になり、これを支配木と呼びます。

次の関数 sign を例に考えます。

programs/sign.tiny
 1// 整数の符号を返す
 2fn sign(x: int) -> int {
 3    let r = 0;
 4    if (x < 0) {
 5        r = -1;
 6    } else if (x > 0) {
 7        r = 1;
 8    }
 9    return r;
10}
11
12fn main() {
13    print(sign(-5), sign(0), sign(7));
14}

sign の制御フローグラフと支配木は次のようになります。

endif1 には then1 を通る経路と else1 を通る経路があるので、then1 も else1 も endif1 を支配しません。endif1 を支配するのは entry と endif1 自身だけです。一方、endif2 に至る経路はすべて else1 を通るので、else1 は endif2 を支配します。

支配関係を使うと、「ブロック \(d\) で計算した値は、\(d\) が支配するブロックでは必ず計算済みである」と言えます。この性質は、第 9 章の共通部分式除去などで使います。

支配木の計算

本書では、Cooper、Harvey、Kennedy による反復アルゴリズムで直接支配ブロックを求めます [Cooper2001]。基本ブロックを逆後順（深さ優先探索の帰りがけ順の逆）に並べ、各ブロックの直接支配ブロックを「処理済みの先行ブロックたちの、支配木上の共通の祖先」として更新することを、変化がなくなるまで繰り返します。

tiny_ssa.py（直接支配ブロックの計算）
34def immediate_dominators(func: Function) -> dict[str, str]:
35    """各基本ブロックの直接支配ブロックを返す（入口は自分自身）。"""
36    rpo = reverse_postorder(func)
37    index = {label: i for i, label in enumerate(rpo)}
38    preds = func.predecessors()
39    idom: dict[str, str] = {func.entry: func.entry}
40
41    def intersect(a: str, b: str) -> str:
42        # 支配木を上にたどり、a と b の共通の祖先を探す。
43        while a != b:
44            while index[a] > index[b]:
45                a = idom[a]
46            while index[b] > index[a]:
47                b = idom[b]
48        return a
49
50    changed = True
51    while changed:
52        changed = False
53        for label in rpo[1:]:
54            done = [p for p in preds[label] if p in idom]
55            new_idom = done[0]
56            for p in done[1:]:
57                new_idom = intersect(p, new_idom)
58            if idom.get(label) != new_idom:
59                idom[label] = new_idom
60                changed = True
61    return idom

intersect は、2 つのブロックから支配木を上にたどり、合流する点を探します。逆後順の番号が大きいほうを親に置き換えていくと、いずれ共通の祖先で一致します。

SSA 形式

SSA 形式（Static Single Assignment form、静的単一代入形式）は、「すべての変数は、プログラム上でちょうど 1 か所でだけ代入される」という制約を満たす中間表現の形式です。LLVM IR や GCC の GIMPLE をはじめ、現代のほとんどの最適化コンパイラが SSA 形式を使っています。

SSA 形式の利点は、変数の名前を見るだけで、その値がどこで定義されたかが分かることです。通常の IR では、x が使われているか所の値がどの代入から来たのかを知るには、制御フローを分析する必要があります。SSA 形式では x.2 の定義は 1 つしかないので、分析が不要になります。これにより、定数伝播などの最適化を簡単かつ高速に実装できます。

φ 関数

一直線のコードなら、代入のたびに変数の名前を変えるだけで SSA 形式にできます。

1x = 1           x.1 = 1
2x = x + 2   =>  x.2 = x.1 + 2
3y = x * 3       y.1 = x.2 * 3

問題は、制御フローが合流する場所です。関数 sign の endif1 で return r の r は、then1 から来た場合は -1、endif2 から来た場合は 0 または 1 です。どちらの名前を使えばよいかは、実行時にどこから来たかによって決まります。

そこで φ 関数という特別な命令を導入します。r.5 = phi(then1: r.4, endif2: r.3) は、「直前に then1 を実行していたら r.4 を、endif2 を実行していたら r.3 を r.5 とする」という意味です。φ 関数は基本ブロックの先頭に置き、そのブロックの φ 関数はすべて同時に評価します。

φ 関数を置く場所：支配辺境

φ 関数は、異なる定義が合流するブロックに置く必要があります。その場所は支配辺境を使って求められます [Cytron1991]。ブロック \(n\) の支配辺境 \(\mathrm{DF}(n)\) は、「\(n\) が支配する範囲から一歩出たところ」にあたるブロックの集合です。

\[\mathrm{DF}(n) = \{\, m \mid n \text{ が } m \text{ のある先行ブロックを支配し、かつ } n \text{ は } m \text{ を真に支配しない} \,\}\]

ここで「真に支配する」とは、自分自身以外を支配することです。ブロック \(n\) で変数 \(x\) を定義すると、その定義は \(n\) が支配するブロックには必ず届きますが、\(\mathrm{DF}(n)\) のブロックでは別の経路から来た定義と合流します。したがって、\(x\) を定義するすべてのブロックの支配辺境に \(x\) の φ 関数を置けばよいことになります。φ 関数自体も \(x\) の新しい定義なので、置いたブロックの支配辺境にも、さらに φ 関数を置きます（反復支配辺境）。

関数 sign の各ブロックの直接支配ブロックと支配辺境は次のとおりです。

1$ python tiny_ssa.py programs/sign.tiny  # 出力の先頭部分
2function sign
3  entry        idom=entry        DF=[]
4  then1        idom=entry        DF=['endif1']
5  else1        idom=entry        DF=['endif1']
6  then2        idom=else1        DF=['endif2']
7  endif2       idom=else1        DF=['endif1']
8  endif1       idom=entry        DF=[]

r は entry、then1、then2 で定義されています。then1 の支配辺境 endif1 と、then2 の支配辺境 endif2 に φ 関数を置きます。endif2 に置いた φ 関数も r の定義なので、その支配辺境 endif1 にも φ 関数が必要ですが、すでに置いてあります。

支配辺境は、合流するブロックの先行ブロックから、合流するブロックの直接支配ブロックに達するまで支配木をたどることで計算できます。

tiny_ssa.py（支配辺境の計算）
74def dominance_frontiers(func: Function,
75                        idom: dict[str, str]) -> dict[str, set[str]]:
76    """各基本ブロックの支配辺境を返す。"""
77    frontier: dict[str, set[str]] = {label: set() for label in func.blocks}
78    for label, preds in func.predecessors().items():
79        if len(preds) < 2:
80            continue
81        for p in preds:
82            runner = p
83            while runner != idom[label]:
84                frontier[runner].add(label)
85                runner = idom[runner]
86    return frontier

名前の付け替え

φ 関数を置いた後、支配木を根から深さ優先でたどりながら、変数の名前を付け替えます。変数ごとに「現在有効な名前」のスタックを持ち、定義を見つけたら新しい名前（r.1、r.2、…）を作ってスタックに積み、使用を見つけたらスタックの先頭の名前に置き換えます。また、各ブロックの処理の最後に、後続ブロックの φ 関数の引数を、現在有効な名前で埋めます。子ブロックの処理が終わったら、そのブロックで積んだ名前をスタックから降ろします。

tiny_ssa.py（名前の付け替え）
126    # 3. 支配木をたどりながら名前を付け替える。
127    counter: dict[str, int] = {v: 0 for v in targets}
128    stacks: dict[str, list[str]] = {
129        v: [v] if v in func.params else [] for v in targets}
130
131    def current(op: Operand) -> Operand:
132        if isinstance(op, Var) and op.name in targets:
133            stack = stacks[op.name]
134            return Var(stack[-1]) if stack else Const(None)
135        return op
136
137    def rename(label: str) -> None:
138        block = func.blocks[label]
139        pushed: list[str] = []
140        for instr in block.instrs:
141            if not isinstance(instr, Phi):
142                map_operands(instr, current)
143            if isinstance(instr, Store) or instr.dst not in targets:
144                continue
145            dst = instr.dst
146            counter[dst] += 1
147            new_name = f"{dst}.{counter[dst]}"
148            stacks[dst].append(new_name)
149            pushed.append(dst)
150            instr.dst = new_name
151        map_operands(block.terminator, current)
152        for succ in block.successors():
153            for phi in func.blocks[succ].phis():
154                phi.args[label] = current(Var(phi_var[id(phi)]))
155        for child in children[label]:
156            rename(child)
157        for var in pushed:
158            stacks[var].pop()
159
160    rename(func.entry)

本書の実装では、定義が 1 か所しかない変数は名前を付け替えず、φ 関数も置きません。Tiny では変数を宣言してから使うので、定義が 1 か所しかない変数は、その定義がすべての使用を支配しているからです。これにより、ほとんどの一時変数は元の名前のまま残り、出力が読みやすくなります。

ループを含む関数 sum では、ループの先頭 cond1 に φ 関数が置かれます。s.2 は、最初に entry から来たときは s.1（つまり 0）、ループを 1 周して body1 から戻ってきたときは s.3 になります。

ループの中で宣言し、さらに代入し直す変数のように、一部の経路でしか定義されない変数の φ 関数では、定義のない経路の引数が undef（未定義値）になります。このような φ 関数の結果は実際には使われないので、第 9 章の不要コード除去で取り除かれます。必要な場所にだけ φ 関数を置くように、生存変数の情報を使って φ 関数の配置を絞り込む方法（pruned SSA）もあります。

SSA 形式からの復帰

実際の機械には φ 関数がないので、コード生成の前に φ 関数を通常の命令に戻す必要があります。素朴な方法は、x = phi(B1: a, B2: b) に対して、B1 の末尾に x = a を、B2 の末尾に x = b を置くことです。しかし、最適化で SSA 形式の変数どうしのコピーを取り除いた後では、この方法は誤った結果を生むことがあります。たとえば、ループの先頭に a.2 = phi(..., body: b.2) と b.2 = phi(..., body: a.2) という 2 つの φ 関数がある場合（2 つの変数の値を交換するループ）、body の末尾に a.2 = b.2 と b.2 = a.2 を順に置くと、2 つ目のコピーが書き換え後の a.2 を読んでしまいます。これは swap 問題と呼ばれます。

本書では、φ 関数ごとに新しい変数 x' を用意して、2 段階でコピーすることでこの問題を避けます。先行ブロックの末尾で x' = a とし、φ 関数があった位置で x = x' とします。φ 関数の引数はすべて先行ブロックで読み終えてから書き込まれるので、φ 関数を同時に評価するという意味が保たれます。

tiny_ssa.py（SSA 形式からの復帰）
164def from_ssa(func: Function) -> Function:
165    """φ 関数をコピー命令に置き換えて SSA 形式から戻す（直接書き換える）。
166
167    x = phi(B1: a, B2: b) を、B1 の末尾の x' = a と B2 の末尾の x' = b、
168    そして元の位置の x = x' に置き換える。新しい変数 x' を経由するので、
169    φ 関数どうしが互いの値を参照していても正しく動く。
170    """
171    for block in list(func.blocks.values()):
172        for i, phi in enumerate(block.phis()):
173            temp = phi.dst + "'"
174            for pred, value in phi.args.items():
175                func.blocks[pred].instrs.append(Copy(temp, value))
176            block.instrs[i] = Copy(phi.dst, Var(temp))
177    return func

この方法ではコピー命令が増えます。余分なコピーは、レジスタ割り当ての段階でコピー元とコピー先に同じレジスタを割り当てれば取り除けます。この技法をコピーの合併と呼びます（第 11 章で説明します）。

まとめ

  • 中間表現は、入れ子の式を一時変数で分解した単純な命令の列で、最適化とコード生成の対象になります。

  • 命令の列は基本ブロックに分け、制御フローグラフで実行の流れを表します。

  • 入口からのすべての経路が \(d\) を通るとき、\(d\) は \(n\) を支配します。支配関係は支配木で表せます。

  • SSA 形式ではすべての変数の定義が 1 か所になり、合流点では φ 関数で値を選びます。φ 関数は支配辺境に置きます。

  • SSA 形式から戻すときは、φ 関数を先行ブロックでのコピーに置き換えます。
