第 4 章 構文解析

構文解析は、トークンの列が文法に合っているかを調べ、プログラムの構造を木の形で明らかにする段階です。この章では、文法を記述する文脈自由文法と、代表的な構文解析の手法を説明します。題材には、Tiny の文法の一部である算術式を使います。Tiny 全体の構文解析器は第 5 章で作ります。

文脈自由文法

プログラミング言語の文法は、ふつう文脈自由文法で記述します。文脈自由文法は、次の 4 つの要素からなります。

要素

説明

終端記号

文法の最小単位で、構文解析ではトークンがこれにあたる（INT、+ など）

非終端記号

終端記号の並びに展開される記号（expr、term など）

生成規則

非終端記号をどのような記号の並びに展開できるかを表す規則

開始記号

展開を始める非終端記号

整数の四則演算からなる式の文法は、次のように書けます。| は「または」を表します。

算術式の文法（左再帰あり）
1expr   = expr "+" term | expr "-" term | term ;
2term   = term "*" factor | term "/" factor | factor ;
3factor = INT | "(" expr ")" ;

開始記号 expr から始めて、生成規則に従って非終端記号を置き換えていく操作を導出と呼びます。1 + 2 * 3 は次のように導出できます。各段階で、最も左にある非終端記号を置き換えています。

1expr => expr + term
2     => term + term
3     => factor + term
4     => 1 + term
5     => 1 + term * factor
6     => 1 + factor * factor
7     => 1 + 2 * factor
8     => 1 + 2 * 3

導出の過程を木で表したものを構文木（具象構文木）と呼びます。

木の葉を左から読むと元の式になります。2 * 3 が 1 つの部分木（term）にまとまっており、掛け算が先に計算されるという構造が木の形で表現されています。

曖昧な文法と優先順位

同じ式の文法を、次のように書くこともできます。

曖昧な文法
1expr = expr "+" expr | expr "*" expr | INT ;

この文法では、1 + 2 * 3 に対して 2 種類の構文木を作れます。

1 つの文に対して複数の構文木を作れる文法を曖昧な文法と呼びます。構文木によって計算結果が変わるので、曖昧さは解消しなければなりません。解消の方法は 2 つあります。

  • 文法を書き換える：前節の文法のように、優先順位ごとに非終端記号を分けます（expr は足し算、term は掛け算）。強く結び付く演算子ほど、木の下のほうに現れるようにします。

  • 構文解析器に規則を与える：文法は曖昧なままにして、「* は + より優先する」「- は左結合」という規則を構文解析器に別途与えます。後で説明する Pratt 構文解析や、yacc 系の構文解析器生成系はこの方法を使います。

結合性も同様です。10 - 4 - 3 を (10 - 4) - 3 と解釈する左結合の演算子は、expr = expr "-" term のように左側に再帰する規則で表します。

再帰下降構文解析

再帰下降構文解析は、非終端記号ごとに 1 つの関数を用意し、生成規則をそのまま関数の処理として書き下す手法です。手で書きやすく、エラーメッセージも工夫しやすいため、GCC や Clang、Go、Rust など多くの実用的なコンパイラが採用しています。

左再帰の除去

前節の文法をそのまま関数にすると、問題が起きます。expr = expr "+" term を関数にすると、expr の処理が最初に expr を呼び出すため、トークンを 1 つも読まずに無限に再帰してしまいます。このように規則の先頭に自分自身が現れることを左再帰と呼びます。

左再帰は、EBNF の繰り返しを使って書き換えると除去できます。expr = expr "+" term | term は「term の後に "+" term が 0 回以上続く」という意味なので、次のように書けます。

算術式の文法（繰り返しで表現）
1expr   = term { ( "+" | "-" ) term } ;
2term   = factor { ( "*" | "/" | "%" ) factor } ;
3factor = "-" factor | INT | "(" expr ")" ;

繰り返しはループで処理し、ループの中で左側の値に右側の値を順に組み合わせていけば、左結合の計算になります。

電卓の実装

この文法に従って、算術式を計算する電卓を作ります（calc_rd.py）。字句解析には第 3 章の字句解析器をそのまま使います。構文解析をしながら値を計算するので、構文木は作りません。

calc_rd.py（非終端記号に対応するメソッド）
43    def expr(self) -> int:
44        # expr = term { ("+" | "-") term }
45        value = self.term()
46        while self.peek().kind in (TokenKind.PLUS, TokenKind.MINUS):
47            op = self.advance().kind
48            right = self.term()
49            value = value + right if op is TokenKind.PLUS else value - right
50        return value
51
52    def term(self) -> int:
53        # term = factor { ("*" | "/" | "%") factor }
54        value = self.factor()
55        while self.peek().kind in (TokenKind.STAR, TokenKind.SLASH,
56                                   TokenKind.PERCENT):
57            op = self.advance().kind
58            right = self.factor()
59            if op is TokenKind.STAR:
60                value = value * right
61            elif op is TokenKind.SLASH:
62                value = int_div(value, right)
63            else:
64                value = int_mod(value, right)
65        return value
66
67    def factor(self) -> int:
68        # factor = "-" factor | INT | "(" expr ")"
69        token = self.peek()
70        if token.kind is TokenKind.MINUS:
71            self.advance()
72            return -self.factor()
73        if token.kind is TokenKind.INT:
74            self.advance()
75            assert isinstance(token.value, int)
76            return token.value
77        if token.kind is TokenKind.LPAREN:
78            self.advance()
79            value = self.expr()
80            self.expect(TokenKind.RPAREN)
81            return value
82        raise TinyError(f"式が必要ですが {token.text!r} があります",
83                        token.line, token.column)
84
85

各メソッドは、次に読むトークン（self.peek()）を 1 つだけ見て、どの規則を使うかを決めています。たとえば factor は、次のトークンが - なら単項演算子、INT なら整数、( なら括弧で囲まれた式と判断します。このように、次のトークンを 1 つ見るだけで使う規則を決められる文法を LL(1) 文法と呼びます。空になりうる規則がない場合、各規則が最初に読みうるトークンの集合（FIRST 集合）が、選択肢の間で重ならないことが LL(1) 文法の条件です（空になりうる規則があるときは、その後に続きうるトークンの集合 FOLLOW も考慮します）。

1$ python calc_rd.py
21 + 2 * 3 = 7
3(1 + 2) * 3 = 9
410 - 4 - 3 = 3
5-7 / 2 = -3
62 * (3 + 4) % 5 = 4

10 - 4 - 3 が左結合で 3 になり、-7 / 2 が 0 に向かって切り捨てて -3 になっていることが分かります。

Pratt 構文解析

再帰下降構文解析では、優先順位の段階ごとに関数が必要です。Tiny の文法では、or_expr から mul_expr まで、二項演算子の優先順位ごとに 6 つの規則がほとんど同じ形で並んでおり、そのまま関数にすると 6 つの似た関数ができます。Pratt 構文解析（演算子順位構文解析の一種）を使うと、これを 1 つの関数と演算子の表にまとめられます [Pratt1973]。

Pratt 構文解析では、各二項演算子に左右 2 つの結合力を与えます。結合力が大きいほど、その演算子は被演算子と強く結び付きます。

calc_pratt.py（演算子の結合力）
13BINARY_POWER: dict[TokenKind, tuple[int, int]] = {
14    TokenKind.OR: (1, 2),
15    TokenKind.AND: (3, 4),
16    TokenKind.EQ: (5, 6),
17    TokenKind.NE: (5, 6),
18    TokenKind.LT: (7, 8),
19    TokenKind.LE: (7, 8),
20    TokenKind.GT: (7, 8),
21    TokenKind.GE: (7, 8),
22    TokenKind.PLUS: (9, 10),
23    TokenKind.MINUS: (9, 10),
24    TokenKind.STAR: (11, 12),
25    TokenKind.SLASH: (11, 12),
26    TokenKind.PERCENT: (11, 12),
27}
28
29PREFIX_POWER = 13  # 単項演算子 - と ! の結合力

解析の中心は expr(min_power) です。まず被演算子（数値、括弧で囲まれた式、単項演算子の式）を 1 つ読み、続く二項演算子の左の結合力が min_power 以上である間、その演算子を取り込みます。演算子の右側は、右の結合力を min_power として再帰的に解析します。

calc_pratt.py（Pratt 構文解析の中心部分）
53    def expr(self, min_power: int) -> str:
54        """結合力が min_power 以上の演算子だけを取り込んで式を解析する。"""
55        left = self.prefix()
56        while True:
57            op = self.peek()
58            power = BINARY_POWER.get(op.kind)
59            if power is None or power[0] < min_power:
60                return left
61            self.advance()
62            right = self.expr(power[1])
63            left = f"({op.text} {left} {right})"

1 + 2 * 3 を解析する様子を追ってみます。

  1. expr(0) が 1 を読みます。次の + の左の結合力 9 は 0 以上なので取り込み、右側を expr(10) で解析します。

  2. expr(10) が 2 を読みます。次の * の左の結合力 11 は 10 以上なので取り込み、右側を expr(12) で解析します。

  3. expr(12) が 3 を読みます。次はファイルの終わりなので、3 を返します。

  4. expr(10) は (* 2 3) を作り、ファイルの終わりなので返します。

  5. expr(0) は (+ 1 (* 2 3)) を作ります。

a - b - c では、expr(10) が b を読んだ後、次の - の左の結合力 9 が 10 より小さいので取り込まずに返ります。その結果、先に (- a b) が作られ、左結合になります。右の結合力を左の結合力より 1 大きくすることで左結合を表しているわけです。逆に右の結合力を左より小さくすると、右結合の演算子になります。

1$ python calc_pratt.py
21 + 2 * 3              => (+ 1 (* 2 3))
3a - b - c              => (- (- a b) c)
4-x * y                 => (* (- x) y)
5a < b && b < c || !d   => (|| (&& (< a b) (< b c)) (! d))
6(1 + 2) * 3            => (* (+ 1 2) 3)

構文解析の手法は、構文木を作る方向によって大きく 2 つに分類できます。

LR 構文解析は、トークンをスタックに積む「シフト」と、スタックの上部が生成規則の右辺と一致したらそれを左辺の非終端記号に置き換える「還元」を繰り返して構文木を作ります。次の文法で 1 + 2 * 3 を解析する様子を示します（$ は入力の終わりを表します）。

1E = E "+" T | T ;
2T = T "*" F | F ;
3F = INT ;

スタックが E + T で残りの入力が * 3 $ の行では、スタックの上部 E + T が規則 E = E "+" T の右辺と一致していますが、次のトークンが * なので還元せずにシフトしています。どの状況でシフトし、どの状況で還元するかは、文法から機械的に作った表（構文解析表）に従って決めます。表を手で作るのは大変なので、LR 構文解析器はふつう構文解析器生成系で生成します。

もう 1 つの重要な手法に、PEG（Parsing Expression Grammar）に基づく構文解析があります。PEG では選択肢 a | b を「まず a を試し、失敗したら b を試す」と解釈するため、文法が曖昧になりません。CPython は Python 3.9 から PEG に基づく構文解析器を使っています [PEP617]。

エラー回復

構文エラーを見つけたとき、最初のエラーで処理を止めるのではなく、解析を続けて複数のエラーをまとめて報告できると便利です。これをエラー回復と呼びます。最も簡単な方法は、エラーを見つけたら文の区切り（; や }）や文の先頭になるキーワード（let や if）までトークンを読み飛ばし、そこから解析を再開する方法です。これをパニックモードと呼びます。Tiny の構文解析器では、第 5 章でこの方法を実装します。

まとめ

  • プログラミング言語の文法は文脈自由文法で記述し、文の構造は構文木で表されます。

  • 曖昧な文法は、優先順位ごとに規則を分けるか、構文解析器に優先順位と結合性の規則を与えて解消します。

  • 再帰下降構文解析は、非終端記号ごとの関数で文法を書き下す手法で、左再帰は繰り返しに書き換えて除去します。

  • Pratt 構文解析は、演算子の結合力の表を使って、式を 1 つの関数で解析します。

  • LR 構文解析はシフトと還元によって上向きに構文木を作り、構文解析器生成系で生成するのが一般的です。
