第 9 章 最適化

最適化は、プログラムの意味を変えずに、より速く（あるいはより小さく）動くように書き換える処理です。この章では、第 8 章で作った SSA 形式の IR に対して代表的な最適化を実装し（tiny_opt.py）、最後に最適化の基礎となるデータフロー解析を説明します。

最適化の考え方

最適化には、次の 2 つの条件があります。

  • 安全であること：どのような入力に対しても、最適化の前後でプログラムの観測できる振る舞い（出力、実行時エラーなど）が変わってはいけません。

  • 効果があること：実行する命令が減る、メモリの使用量が減るなど、書き換えによって実際に得をする必要があります。

特に安全性は重要です。たとえば x / y の結果が使われていなくても、y が 0 になりうるなら、この命令を削除すると「0 除算エラーで止まる」という振る舞いが変わってしまいます。本書の最適化器も、このような点に注意して実装しています。

最適化は、適用する範囲によって次のように分類されます。

範囲

説明

局所的な最適化

1 つの基本ブロックの中だけを見て行う

大域的な最適化

1 つの関数の制御フローグラフ全体を見て行う

手続き間の最適化

複数の関数にまたがって行う（関数のインライン展開など）

本書で実装する最適化は、いずれも大域的な最適化です。

最適化の例

まず、最適化器がどのような書き換えを行うかを見てみましょう。次の関数 calc には、最適化の機会が多く含まれています。

 1fn calc(n: int) -> int {
 2    let a = 3 * 4;
 3    let b = a + 2;
 4    let unused = n * 100;
 5    let x = n * b + n * b;
 6    if (a > 100) {
 7        print("never");
 8    }
 9    return x;
10}
11
12fn main() {
13    print(calc(5));
14}

tiny_opt.py を引数なしで実行すると、この関数を SSA 形式に変換して最適化した結果を表示します。

 4    %4 = n * 14
 5    %6 = %4 + %4
 6    return %6
 7function main()

 9    %1 = call calc(5)
10    call print(%1)
11    return

13実行した命令数: 最適化前 16、最適化後 6

関数 calc は次のように書き換えられました。

  • 3 * 4 はコンパイル時に 12 に計算され（定数畳み込み）、a の使用は 12 に置き換えられました（定数伝播）。同様に b は 14 になりました。

  • a > 100 は 12 > 100、つまり false と分かるので、if 文の分岐と print("never") が取り除かれました。

  • n * b は 2 回計算されていましたが、2 回目は 1 回目の結果を再利用するようになりました（共通部分式除去）。

  • 使われない変数 unused の計算が取り除かれました（不要コード除去）。

以下、それぞれの最適化を説明します。

定数伝播と定数畳み込み

被演算子がすべて定数の演算を、コンパイル時に計算して結果の定数に置き換えることを定数畳み込みと呼びます。また、定数が代入された変数の使用を、その定数に置き換えることを定数伝播と呼びます。この 2 つは互いに機会を作り合います。定数伝播で被演算子が定数になれば畳み込みができ、畳み込みの結果が定数なら、さらに伝播できます。

SSA 形式では各変数の定義が 1 か所しかないので、定数伝播が簡単です。x.1 = 12 という命令があれば、プログラム中のすべての x.1 を 12 に置き換えてかまいません。同様に、x.1 = y.2 というコピーがあれば、x.1 の使用を y.2 に置き換えられます。これをコピー伝播と呼びます。

propagate_constants は、置き換えの対応表 subst を作りながら、すべての命令を逆後順に 1 回ずつ処理します。

tiny_opt.py（定数伝播・コピー伝播・畳み込み）
 59def propagate_constants(func: Function) -> bool:
 60    """定数伝播・コピー伝播・畳み込みを行う。変更があれば True を返す。"""
 61    changed = False
 62    subst: dict[str, Operand] = {}  # 変数 → 置き換え先
 63
 64    def resolve(op: Operand) -> Operand:
 65        while isinstance(op, Var) and op.name in subst:
 66            op = subst[op.name]
 67        return op
 68
 69    for label in reverse_postorder(func):
 70        block = func.blocks[label]
 71        for i, instr in enumerate(block.instrs):
 72            before = repr(instr)
 73            map_operands(instr, resolve)
 74            replacement: Operand | None = None
 75            match instr:
 76                case Copy(dst, src):
 77                    subst[dst] = src
 78                case BinOp() | UnOp():
 79                    replacement = fold(instr)
 80                    if replacement is None and isinstance(instr, BinOp):
 81                        replacement = simplify_algebra(instr)
 82                case Phi(dst, args):
 83                    # 自分自身と未定義値を除いた値が 1 種類なら、その値と同じ。
 84                    values = {v for v in args.values()
 85                              if v != Var(dst) and v != Const(None)}
 86                    if len(values) <= 1:
 87                        replacement = values.pop() if values else Const(None)
 88            if replacement is not None:
 89                assert not isinstance(instr, Store)
 90                assert instr.dst is not None
 91                block.instrs[i] = Copy(instr.dst, replacement)
 92                subst[instr.dst] = replacement
 93            changed |= before != repr(block.instrs[i])
 94        term = block.terminator
 95        map_operands(term, resolve)
 96        if isinstance(term, Branch) and isinstance(term.cond, Const):
 97            # 条件が定数の分岐は無条件ジャンプにする。
 98            taken = term.if_true if term.cond.value else term.if_false
 99            other = term.if_false if term.cond.value else term.if_true
100            block.terminator = Jump(taken)
101            if other != taken:
102                for phi in func.blocks[other].phis():
103                    phi.args.pop(label, None)
104            changed = True
105    # ループの back edge から来る φ 関数の引数は、後から分かった置き換えを適用する。
106    for block in func.blocks.values():
107        for phi in block.phis():
108            before = repr(phi)
109            map_operands(phi, resolve)
110            changed |= before != repr(phi)
111    if changed:
112        remove_dead_blocks(func)
113    return changed

ポイントをいくつか補足します。

  • 畳み込みの計算には、インタプリタと同じ tiny_runtime.py の関数を使います。コンパイル時の計算と実行時の計算の結果が食い違わないようにするためです。0 除算のように実行時エラーになる演算は畳み込まずに残し、エラーは実行時に任せます。

  • φ 関数の引数がすべて同じ値なら、その φ 関数は単なるコピーです。undef の引数は、その経路では値が使われないので無視できます。ループで値が変わらない変数に現れる、φ 関数自身の結果を引数とするもの（x.2 = phi(entry: 0, body: x.2) など）も無視します。

  • 条件が定数になった branch は jump に置き換えます。選ばれなかった後続ブロックの φ 関数からは、このブロックから来る引数を取り除きます。その後、到達できなくなったブロックを削除します。

  • ループの先頭の φ 関数は、ループの末尾（後で処理するブロック）の値を引数に持つため、1 回の走査では置き換えが届きません。そこで最後に、すべての φ 関数の引数に置き換えを適用し直しています。

定数畳み込みと合わせて、x + 0 や x * 1 を x に、x * 0 を 0 に置き換える代数的な簡約も行っています（simplify_algebra）。

共通部分式除去

同じ計算を 2 回以上行っている場合に、2 回目以降を 1 回目の結果で置き換えることを共通部分式除去と呼びます。

SSA 形式では、同じ演算子と同じ被演算子を持つ 2 つの命令は必ず同じ値を計算します。被演算子の変数が途中で書き換わることがないからです。ただし、1 回目の計算が 2 回目の計算より必ず先に実行されていなければ、その結果を使えません。この条件は、第 8 章の支配関係で表せます。1 回目の計算を含むブロックが、2 回目の計算を含むブロックを支配していればよいのです。

そこで、支配木を根からたどりながら、計算済みの式の表を受け渡していきます。子ブロックには親までの表をコピーして渡すので、表に載っている式は、現在のブロックを支配するブロックで計算済みであることが保証されます。

tiny_opt.py（共通部分式除去）
131def eliminate_common_subexpressions(func: Function) -> bool:
132    """支配木を上からたどり、同じ計算を 2 度目以降はコピーに置き換える。"""
133    children = dominator_tree(func, immediate_dominators(func))
134    changed = False
135
136    def visit(label: str, available: dict[tuple[str, ...], str]) -> None:
137        nonlocal changed
138        table = dict(available)  # 支配ブロックで計算済みの式 → 変数
139        block = func.blocks[label]
140        for i, instr in enumerate(block.instrs):
141            if isinstance(instr, BinOp):
142                operands = [str(instr.left), str(instr.right)]
143                if instr.op in COMMUTATIVE:
144                    operands.sort()
145                key = (instr.op, *operands)
146            elif isinstance(instr, UnOp):
147                key = (instr.op, str(instr.operand))
148            else:
149                continue
150            if key in table:
151                block.instrs[i] = Copy(instr.dst, Var(table[key]))
152                changed = True
153            else:
154                table[key] = instr.dst
155        for child in children[label]:
156            visit(child, table)
157
158    visit(func.entry, {})
159    return changed

*、==、!= は交換法則が成り立つので、被演算子を並べ替えて表のキーを作ります。これにより a * b と b * a も同じ式として扱えます。+ は文字列の連結にも使うため、交換法則が成り立たず、並べ替えていません。

添字の読み出し x = a[i] は対象にしていません。同じ a[i] でも、間に a[i] = ... や配列を変更する関数の呼び出しがあれば値が変わるからです。メモリの読み書きを含む式を扱うには、2 つの参照が同じ場所を指しうるかを調べる別名解析が必要になります。

不要コード除去

結果がどこからも使われない命令を削除することを不要コード除去と呼びます。ただし、結果が使われなくても削除してはいけない命令があります。

  • 関数の呼び出し（print のように出力をしたり、配列を変更したりするかもしれない）

  • 添字への書き込み

  • 添字の読み出し（範囲外ならエラーになる）

  • 0 になりうる値による除算と剰余（0 除算エラーになる）

本書の実装では、まずこれらの副作用のある命令と終端命令を「必要」とし、そこから使われている変数の定義を逆向きにたどって「必要」の印を付けていきます。最後に印のない命令を削除します。ガベージコレクションのマーク & スイープ（第 11 章）と同じ考え方です。

tiny_opt.py（不要コード除去）
164def has_side_effect(instr: Instr) -> bool:
165    """結果を使わなくても削除できない命令か。"""
166    if isinstance(instr, (Call, Store, Load)):  # Load は範囲外エラーがある
167        return True
168    if isinstance(instr, BinOp) and instr.op in ("/", "%"):
169        # 0 除算の可能性があるものは残す。
170        return not (isinstance(instr.right, Const) and instr.right.value != 0)
171    return False
172
173
174def eliminate_dead_code(func: Function) -> bool:
175    """値が使われない命令を削除する。"""
176    definition: dict[str, Instr] = {}
177    for block in func.blocks.values():
178        for instr in block.instrs:
179            dst = defined_var(instr)
180            if dst is not None:
181                definition[dst] = instr
182
183    # 副作用のある命令と終端命令から、使われている変数をたどって印を付ける。
184    live: set[int] = set()
185    worklist: list[str] = []
186    for block in func.blocks.values():
187        for instr in block.instrs:
188            if has_side_effect(instr):
189                live.add(id(instr))
190                worklist += used_vars(instr)
191        worklist += used_vars(block.terminator)
192    while worklist:
193        name = worklist.pop()
194        found = definition.get(name)
195        if found is not None and id(found) not in live:
196            live.add(id(found))
197            worklist += used_vars(found)
198
199    changed = False
200    for block in func.blocks.values():
201        kept = [i for i in block.instrs if id(i) in live]
202        changed |= len(kept) != len(block.instrs)
203        block.instrs = kept
204    return changed
205
206

単純に「使われていない命令を削除する」ことを繰り返す方法では、ループで互いに参照し合っているだけの変数（ループの先頭の φ 関数と、ループ内でのその更新など）を削除できません。必要なものから印を付ける方法なら、このような変数もまとめて削除できます。

制御フローの単純化と最適化の組み合わせ

分岐を畳み込むと、前のブロックからしか到達しないブロックや、引数が 1 つしかない φ 関数ができます。simplify_cfg は、引数が 1 つの φ 関数をコピーに置き換え、一直線につながる 2 つのブロックを 1 つに併合します。

各最適化は、互いに新しい最適化の機会を作ります。定数伝播で分岐が消えれば制御フローが単純になり、それによって φ 関数がコピーになり、コピー伝播で新たな定数が伝播する、といった具合です。そこで、すべての最適化を変化がなくなるまで繰り返し適用します。

tiny_opt.py（最適化の繰り返し）
243def optimize_function(func: Function) -> Function:
244    """SSA 形式の関数を、変化がなくなるまで繰り返し最適化する。"""
245    while True:
246        changed = propagate_constants(func)
247        changed |= eliminate_common_subexpressions(func)
248        changed |= eliminate_dead_code(func)
249        changed |= simplify_cfg(func)
250        if not changed:
251            return func

実用的なコンパイラでは、数十から百を超える最適化を、決められた順序（パスの順序）で適用します。どの順序で何回適用するかは、生成されるコードの質とコンパイル時間の両方に影響します。

データフロー解析

ここまでの最適化は、SSA 形式の「定義が 1 か所」という性質に頼っていました。SSA 形式を使わない場合や、変数の生存範囲のように制御フロー全体にわたる情報が必要な場合には、データフロー解析を使います。データフロー解析は、制御フローグラフの各点で成り立つ事実（「この変数はこの後使われる」「この変数の値は定数 3 である」など）を、方程式を立てて求める手法です。

生存変数解析

代表的なデータフロー解析である生存変数解析を例にします。ある点で変数 \(x\) が生存しているとは、その点から \(x\) の使用に至る経路があり、その途中で \(x\) が再定義されないことをいいます。生存していない変数の値は二度と使われないので、そのレジスタを別の変数に使い回せます。生存変数解析は、第 11 章のレジスタ割り当ての基礎になります。

基本ブロック \(B\) について、次の 2 つの集合を考えます。

  • \(\mathrm{use}[B]\)：\(B\) の中で、定義される前に使われる変数

  • \(\mathrm{def}[B]\)：\(B\) の中で定義される変数

ブロックの入口と出口で生存している変数の集合 \(\mathrm{in}[B]\) と \(\mathrm{out}[B]\) は、次の方程式を満たします。

\[\mathrm{out}[B] = \bigcup_{S \in \mathrm{succ}(B)} \mathrm{in}[S]\]
\[\mathrm{in}[B] = \mathrm{use}[B] \cup (\mathrm{out}[B] - \mathrm{def}[B])\]

1 つ目の式は「後続ブロックのどれかの入口で生存していれば、出口で生存している」、2 つ目の式は「ブロックの中で使われるか、出口で生存していてブロックの中で定義されなければ、入口で生存している」という意味です。情報が制御フローとは逆向きに（後続ブロックから先行ブロックへ）伝わるので、後ろ向きの解析と呼ばれます。

ループがあると、方程式の右辺に自分自身の値が現れるため、一度では解けません。そこで、すべての集合を空集合から始め、方程式に従って値を更新することを、変化がなくなるまで繰り返します。集合は単調に大きくなり、変数の数は有限なので、この繰り返しは必ず終わります。後ろ向きの解析では、逆後順の逆の順にブロックを処理すると、少ない繰り返しで収束します。

tiny_opt.py（生存変数解析）
262def liveness(func: Function) -> tuple[dict[str, set[str]],
263                                      dict[str, set[str]]]:
264    """各基本ブロックの入口と出口で生存している変数を求める。
265
266    live_out[B] = ∪ live_in[S]  （S は B の後続ブロック）
267    live_in[B]  = use[B] ∪ (live_out[B] - def[B])
268    を、値が変化しなくなるまで繰り返し計算する。
269    """
270    use: dict[str, set[str]] = {}
271    defs: dict[str, set[str]] = {}
272    for block in func.blocks.values():
273        u: set[str] = set()  # 定義より前に使われる変数
274        d: set[str] = {phi.dst for phi in block.phis()}  # 定義される変数
275        for instr in block.instrs[len(block.phis()):]:
276            u |= {v for v in used_vars(instr) if v not in d}
277            dst = defined_var(instr)
278            if dst is not None:
279                d.add(dst)
280        u |= {v for v in used_vars(block.terminator) if v not in d}
281        use[block.label], defs[block.label] = u, d
282
283    live_in: dict[str, set[str]] = {b: set() for b in func.blocks}
284    live_out: dict[str, set[str]] = {b: set() for b in func.blocks}
285    order = reverse_postorder(func)[::-1]  # 後ろ向きの解析なので逆順に回す
286    changed = True
287    while changed:
288        changed = False
289        for label in order:
290            out: set[str] = set()
291            for succ in func.blocks[label].successors():
292                block = func.blocks[succ]
293                out |= live_in[succ] - {phi.dst for phi in block.phis()}
294                for phi in block.phis():  # φ 関数の引数は先行ブロックの出口で使う
295                    arg = phi.args.get(label)
296                    if isinstance(arg, Var):
297                        out.add(arg.name)
298            new_in = use[label] | (out - defs[label])
299            if out != live_out[label] or new_in != live_in[label]:
300                live_out[label], live_in[label] = out, new_in
301                changed = True
302    return live_in, live_out

φ 関数を含む関数も扱えるように、φ 関数の引数は、φ 関数のあるブロックではなく、対応する先行ブロックの出口で使われるものとして扱っています。最適化前の関数 sum（SSA 形式にする前）に適用した結果を示します。

データフロー解析の一般形

データフロー解析には、生存変数解析のほかにも、到達定義解析（ある点に届きうる代入の集合）や利用可能式解析（ある点で計算済みの式の集合）などがあります。いずれも「各ブロックの効果を表す関数」と「合流点で情報を合わせる演算（和集合や積集合）」を決めれば、同じ反復のアルゴリズムで解けます。この枠組みは束（lattice）の理論で定式化されており、反復が停止することや、反復で得られる解が方程式の解のうち最も精密なもの（最大不動点、または最小不動点）であることが保証されます。

その他の最適化

本書で実装しなかった代表的な最適化を挙げます。

最適化

内容

関数のインライン展開

関数の呼び出しを、関数の本体で置き換える。呼び出しの手間がなくなるだけでなく、呼び出し元の情報（定数の引数など）を使った最適化が可能になる

ループ不変式の移動

ループの中で毎回同じ値になる計算を、ループの前に移す

強度低減

乗算をより軽い加算に置き換える。たとえばループ変数 i に対する i * 4 を、ループごとに 4 ずつ増える変数で置き換える

疎な条件付き定数伝播（SCCP）

定数伝播と到達不能コードの検出を同時に行い、本書の方法より多くの定数を見つける [Wegman1991]

大域的な値番号付け（GVN）

支配関係にない場所の共通部分式や、形の違う同値な式も見つける

ループ展開

ループの本体を複製して、繰り返しの回数と分岐の数を減らす

まとめ

  • 最適化は安全でなければなりません。実行時エラーの有無も含めて、振る舞いを変えてはいけません。

  • SSA 形式では、定数伝播やコピー伝播を、変数の名前の置き換えだけで実装できます。

  • 共通部分式除去は、支配木に沿って計算済みの式の表を受け渡すことで実装できます。

  • 不要コード除去は、副作用のある命令から使用をたどって印を付け、印のない命令を削除します。

  • 最適化は互いに機会を作り合うので、変化がなくなるまで繰り返し適用します。

  • データフロー解析は、制御フローグラフ上の方程式を反復で解きます。生存変数解析はその代表例です。
