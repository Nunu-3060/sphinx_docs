第 7 章 インタプリタ

ここまでで、Tiny のプログラムを型情報付きの抽象構文木に変換できるようになりました。この章では、抽象構文木を直接たどって実行する木構造インタプリタを作ります。これで Tiny のプログラムを実際に動かせるようになります。

木構造インタプリタ

木構造インタプリタは、抽象構文木の各ノードに対して「そのノードを実行（評価）する」処理を再帰的に適用します。たとえば Binary("+", left, right) を評価するには、left と right をそれぞれ評価し、得られた 2 つの値を足します。構造が単純で、言語の意味をそのままプログラムとして書き下せるため、言語の試作や、意味の定義を確かめる用途に向いています。

インタプリタが扱う対象は、値を返す「式」と、値を返さずに状態を変える「文」の 2 種類です。本書の実装では、式は eval メソッドで評価し、文は exec_stmt メソッドで実行します。

実行時の値と実行時ライブラリ

インタプリタは、Tiny の値を Python のオブジェクトで表します。int、bool、str はそのまま Python の同じ型で表し、配列は Python のリストで表します。Python のリストは参照で扱われるので、「配列は参照で扱う」という Tiny の意味がそのまま実現できます。

tiny_runtime.py（値の型）
14# Tiny の値。配列は Python のリストで表す。None は「値なし」を表す。
15Value = Union[int, bool, str, list["Value"], None]
16
17BUILTINS = ("print", "len", "push", "to_str")

演算の意味は tiny_runtime.py にまとめ、後の章で作る IR インタプリタや仮想マシンからも同じ関数を使います。こうしておけば、どの実行方式でも演算の結果が同じになります。たとえば整数の除算は、Python の //（負の無限大に向かって切り捨てる）ではなく、0 に向かって切り捨てるように実装しています。

tiny_runtime.py（整数の除算と剰余）
24def int_div(a: int, b: int) -> int:
25    """0 に向かって切り捨てる整数除算（C 言語と同じ）。"""
26    if b == 0:
27        raise TinyRuntimeError("0 で除算しました")
28    q = abs(a) // abs(b)
29    return q if (a >= 0) == (b >= 0) else -q
30
31
32def int_mod(a: int, b: int) -> int:
33    """int_div と組になる剰余。a == int_div(a, b) * b + int_mod(a, b) となる。"""
34    return a - int_div(a, b) * b
35
36

添字のアクセスでは、範囲外の添字を実行時エラーにします。Python のリストは負の添字（a[-1]）を末尾からの位置として受け付けますが、Tiny では負の添字もエラーにするため、範囲を明示的に検査しています。

tiny_runtime.py（添字のアクセス）
79def index_value(base: Value, index: Value) -> Value:
80    """base[index] を返す。範囲外ならエラー。"""
81    if not isinstance(index, int) or not isinstance(base, (list, str)):
82        raise TinyRuntimeError("添字演算の型が不正です")
83    if not 0 <= index < len(base):
84        raise TinyRuntimeError(f"添字 {index} が範囲外です")
85    return base[index]

環境

変数の値を保持するしくみを環境と呼びます。意味解析の記号表が「名前 → 型」の対応だったのに対し、環境は「名前 → 値」の対応です。記号表と同様に、ブロックごとに環境を作り、外側の環境への参照を持たせます。

tiny_interp.py（環境）
22class Environment:
23    """変数の値を保持する環境。ブロックごとに 1 つ作る。"""
24
25    def __init__(self, parent: Environment | None = None) -> None:
26        self.parent = parent
27        self.values: dict[str, Value] = {}
28
29    def define(self, name: str, value: Value) -> None:
30        self.values[name] = value
31
32    def find(self, name: str) -> Environment:
33        env: Environment | None = self
34        while env is not None:
35            if name in env.values:
36                return env
37            env = env.parent
38        raise TinyRuntimeError(f"変数 {name} が見つかりません")
39
40    def get(self, name: str) -> Value:
41        return self.find(name).values[name]
42
43    def set(self, name: str, value: Value) -> None:
44        self.find(name).values[name] = value

define は現在のブロックに新しい変数を作り、set は既存の変数を探してその値を書き換えます。let x = ... と x = ... の違いが、この 2 つのメソッドの違いに対応しています。

文の実行

exec_stmt は、文の種類に応じて処理を分けます。if 文と while 文は、Tiny の if と while を Python の if と while でそのまま実行しています。

tiny_interp.py（文の実行）
 79    def exec_stmt(self, stmt: Stmt, env: Environment) -> None:
 80        match stmt:
 81            case Block():
 82                self.exec_block(stmt, Environment(env))
 83            case Let(name, _, value):
 84                env.define(name, self.eval(value, env))
 85            case Assign(Name(name), value):
 86                env.set(name, self.eval(value, env))
 87            case Assign(Index(target, index), value):
 88                base = self.eval(target, env)
 89                i = self.eval(index, env)
 90                store_index(base, i, self.eval(value, env))
 91            case If(cond, then_body, else_body):
 92                if self.eval(cond, env):
 93                    self.exec_block(then_body, Environment(env))
 94                elif else_body is not None:
 95                    self.exec_stmt(else_body, env)
 96            case While(cond, body):
 97                while self.eval(cond, env):
 98                    self.exec_block(body, Environment(env))
 99            case Return(value):
100                result = None if value is None else self.eval(value, env)
101                raise ReturnSignal(result)
102            case ExprStmt(expr):
103                self.eval(expr, env)
104            case _:
105                raise AssertionError(stmt)

return 文の扱いには工夫が必要です。return は、関数の本体のどれほど深い位置にあっても、関数の呼び出し元まで一気に戻らなければなりません。そこで、return 文を実行したら戻り値を持った例外 ReturnSignal を送出し、関数呼び出しの処理でそれを捕まえます。Python の例外の「呼び出しの途中を飛び越えて戻る」性質を利用しているわけです。

tiny_interp.py（関数呼び出し）
63    def call_function(self, func: FuncDef, args: list[Value]) -> Value:
64        env = Environment()
65        for param, arg in zip(func.params, args):
66            env.define(param.name, arg)
67        try:
68            self.exec_block(func.body, Environment(env))
69        except ReturnSignal as signal:
70            return signal.value
71        return None

関数を呼び出すたびに新しい環境を作り、引数を定義しています。呼び出し元の環境は参照しないので、関数の中から呼び出し元の局所変数は見えません。再帰呼び出しでも、呼び出しごとに別の環境ができるため、各呼び出しの n は互いに干渉しません。

式の評価

eval は式を評価して値を返します。

tiny_interp.py（式の評価）
109    def eval(self, expr: Expr, env: Environment) -> Value:
110        match expr:
111            case IntLit(value) | BoolLit(value) | StrLit(value):
112                return value
113            case ArrayLit(elements):
114                return [self.eval(e, env) for e in elements]
115            case Name(name):
116                return env.get(name)
117            case Index(target, index):
118                return index_value(self.eval(target, env),
119                                   self.eval(index, env))
120            case Unary(op, operand):
121                return unary_op(op, self.eval(operand, env))
122            case Binary("&&", left, right):
123                return bool(self.eval(left, env)) and \
124                    bool(self.eval(right, env))
125            case Binary("||", left, right):
126                return bool(self.eval(left, env)) or \
127                    bool(self.eval(right, env))
128            case Binary(op, left, right):
129                return binary_op(op, self.eval(left, env),
130                                 self.eval(right, env))
131            case Call(callee, args):
132                values = [self.eval(a, env) for a in args]
133                if callee in BUILTINS:
134                    return call_builtin(callee, values, self.out)
135                return self.call_function(self.functions[callee], values)
136        raise AssertionError(expr)

&& と || は、ほかの二項演算子より前のパターンで処理しています。Python の and と or は短絡評価を行うので、Tiny の && と || の短絡評価がそのまま実現できます。ほかの二項演算子と同じように両辺を先に評価してしまうと、i < len(a) && a[i] > 0 のような式で範囲外アクセスのエラーが起きてしまいます。

実行例

これで Tiny のプログラムを実行できるようになりました。

programs/sort.tiny
 1// 配列の挿入ソート
 2fn sort(a: [int]) {
 3    let i = 1;
 4    while (i < len(a)) {
 5        let key = a[i];
 6        let j = i - 1;
 7        while (j >= 0 && a[j] > key) {
 8            a[j + 1] = a[j];
 9            j = j - 1;
10        }
11        a[j + 1] = key;
12        i = i + 1;
13    }
14}
15
16fn main() {
17    let data = [5, 2, 9, 1, 7, 3];
18    print("before:", data);
19    sort(data);
20    print("after: ", data);
21}

1$ python tiny.py run programs/sort.tiny
2before: [5, 2, 9, 1, 7, 3]
3after:  [1, 2, 3, 5, 7, 9]

sort 関数の中で変更した配列の内容が、main 関数の data にも反映されています。配列が参照で渡されているからです。

木構造インタプリタの長所と短所

木構造インタプリタは実装が簡単ですが、実行速度の面では不利です。

  • ノードを 1 つ評価するたびに、ノードの種類による分岐、属性の参照、再帰呼び出しが起こります。s = s + i という単純な文でも、多数の Python の関数呼び出しが発生します。

  • 変数を参照するたびに、環境の連鎖を名前でたどって探します。変数の位置はコンパイル時に分かっているにもかかわらず、実行時に毎回探しています。

  • ループの中の式は、実行のたびに同じ解析（ノードの種類の判定など）を繰り返します。

これらの無駄を省くには、実行前にプログラムをより実行しやすい形に変換しておくのが効果的です。第 8 章では最適化しやすい形である中間表現に、第 10 章では実行しやすい形であるバイトコードに変換します。

まとめ

  • 木構造インタプリタは、抽象構文木をたどりながら式を評価し、文を実行します。

  • 変数の値は環境で管理します。環境はブロックや関数呼び出しごとに作り、外側の環境への参照を持ちます。

  • return 文は例外を使って関数の呼び出し元まで戻します。

  • 演算の意味を実行時ライブラリにまとめておくと、複数の実行方式で同じ結果を保証しやすくなります。

  • 木構造インタプリタは簡単に作れますが、実行時の無駄が多くなります。
