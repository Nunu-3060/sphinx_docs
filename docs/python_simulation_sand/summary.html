まとめ

このシミュレーションからわかること

Sand クラスが実装しているルールは非常に単純です。

  • 各セルは自分の堆積量に応じた距離だけ、一定量の砂を風下(横方向)へ飛ばす

  • 飛んだ先の砂は着地先に積もる(複数箇所から集まれば加算される)

  • そのあと、周囲8セルとの重み付き平均で地形を少しだけ滑らかにする

これだけの規則を格子全体に同時に適用し続けるだけで、局所的な凹凸が崩れたり移動したりしながら、時間とともに縞状・砂丘状のパターンが自己組織的に現れていく様子を観察できます。輸送・拡散のいずれのステップも高さ場の合計値(総砂量)を厳密に保存するように設計されているため、「局所的な移動と均しだけで、全体の量を変えずに地形が変化し続ける」という飛砂現象の性質を、シンプルな数値モデルとして体験できる点が本シミュレーションのポイントです。

制約・既知の限界

モデル層: Sand.py で解説したとおり、本モデルにはいくつかの単純化があります。

  • 風は常に列方向(横方向)の一定方向にのみ吹くものとして扱われており、風向きが変化する状況は表現できません。

  • 格子の境界は周期境界(トーラス)であり、有限の地形や壁際の挙動は扱えません。

  • GUI は Tkinter に限定されており、大きいグリッドサイズ(512×512 など)を短い更新間隔で動かすと、輸送・拡散の計算負荷により描画が追いつかなくなる場合があります。

  • 色相・彩度は画像全体で固定値であり、高さ以外の情報(例えば局所的な砂の種類や湿り気など)を色に反映する仕組みはありません。

今後の拡張案

上記の限界を踏まえ、発展させる場合の方向性を提案します。

  • 風向きの多様化: 現在は列方向のみの輸送ですが、風向きをパラメータ化し、斜め方向や時間変化する風にも対応できるようにする。

  • 境界条件の選択肢: トーラス(周期境界)に加えて、砂が境界の外へ抜けていく「開放境界」や、砂が積もり続ける「壁」を選べるようにする。

  • パラメータのプリセット保存・読み込み: L0 / b / q / D の組み合わせを名前付きで保存し、GUI から呼び出せるようにする。

  • 自動テストの追加: 質量保存(高さ場の合計値が変化しないこと)などの性質は、単体テストとして検証しやすい題材です。

  • 表示手段の追加: Tkinter による対話的な GUI に加えて、matplotlib のアニメーションや動画ファイルへの書き出しなど、別の可視化手段を用意する。
