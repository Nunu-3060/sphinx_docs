9. 実践：ToDo アプリの作成

本章では、これまでに学んだ HTML・CSS・JavaScript を組み合わせて、簡単な ToDo アプリを作る。

9.1. 完成形と仕様

完成した ToDo アプリを開き、実際に操作してみるとよい。仕様は次のとおりである。

  • 入力欄にタスクを入力し、「追加」ボタンを押すか Enter キーを押すと、一覧に追加される。

  • チェックボックスをオンにすると、そのタスクは完了済みとなり、取り消し線付きで表示される。

  • 「削除」ボタンを押すと、そのタスクが削除される。

  • 「完了済みを削除」ボタンを押すと、完了済みのタスクがまとめて削除される。

  • 未完了のタスク数と全体のタスク数を表示する。

  • タスクの一覧は localStorage に保存され、ページを再読み込みしたりブラウザを閉じたりしても残る。

ファイルは次の 3 つに分ける。

ToDo アプリのファイル構成

ファイル

役割

index.html

ページの構造（第 2 章・第 3 章）。

style.css

見た目とレイアウト（第 4 章・第 5 章）。

app.js

タスクの追加・完了・削除と保存（第 6 章～第 8 章）。

index.html をダウンロード ／ style.css をダウンロード ／ app.js をダウンロード ／ ブラウザで表示

9.2. HTML で骨組みを作る

まず HTML で、入力フォーム、タスクの一覧、件数表示の 3 つの部分を作る。タスクの一覧は JavaScript で中身を作るため、HTML には空の ul 要素だけを置く。JavaScript から操作する要素には id 属性を付けておく。

examples/ch09/todo/index.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>ToDo アプリ</title>
  <link rel="stylesheet" href="style.css">
  <script src="app.js" defer></script>
</head>
<body>
  <main class="app">
    <h1>ToDo アプリ</h1>

    <!-- タスクの入力欄 -->
    <form id="todo-form" class="todo-form">
      <label for="todo-input" class="visually-hidden">新しいタスク</label>
      <input type="text" id="todo-input" placeholder="やることを入力" autocomplete="off" required>
      <button type="submit">追加</button>
    </form>

    <!-- タスクの一覧 (JavaScript で li 要素を追加する) -->
    <ul id="todo-list" class="todo-list"></ul>

    <!-- 件数の表示と一括削除 -->
    <footer class="todo-footer">
      <span id="todo-count">0 件</span>
      <button id="clear-done-button" type="button">完了済みを削除</button>
    </footer>
  </main>
</body>
</html>

入力欄のラベルは画面には表示しないが、スクリーンリーダーのために label 要素を置いている。visually-hidden クラスは、要素を画面上では見えなくしつつ、読み上げの対象には残すための CSS である。display: none; を使うと読み上げの対象からも外れてしまうため、このような書き方をする。

9.3. CSS で見た目を整える

CSS では、第 5 章で扱った Flexbox を使って、入力欄と「追加」ボタン、各タスクのチェックボックス・文字・「削除」ボタンを横に並べる。flex-grow: 1; を指定した要素が、残りの幅をすべて使う。

完了済みのタスクは、li 要素に done クラスを付けることで、取り消し線付きの表示に切り替える。JavaScript はクラスを付け外しするだけで、見た目の定義は CSS にまとめている。

9.4. JavaScript で機能を実装する

JavaScript の実装は、次の方針で組み立てる。

  • アプリの状態（タスクの一覧）を、配列 todos として 1 か所で管理する。各タスクは { id, text, done } の形のオブジェクトとする。

  • 操作（追加・完了の切り替え・削除）は、画面を直接書き換えるのではなく、todos を変更する。

  • todos を変更したら update 関数を呼び、保存と画面の再描画を行う。画面は常に todos の内容から作り直す（render 関数）。

このように、状態を 1 か所で管理し、画面を状態から作る方針にすると、画面と状態が食い違うことがなくなる。React や Vue などのフレームワークも、この考え方を基本にしている。

examples/ch09/todo/app.js
// ===== 定数と状態 =====
const STORAGE_KEY = "todo-app-items";

// タスクの配列。各要素は { id, text, done } の形のオブジェクト
let todos = loadTodos();

const form = document.querySelector("#todo-form");
const input = document.querySelector("#todo-input");
const list = document.querySelector("#todo-list");
const count = document.querySelector("#todo-count");
const clearDoneButton = document.querySelector("#clear-done-button");

// ===== 保存と読み込み =====
function loadTodos() {
  const json = localStorage.getItem(STORAGE_KEY);
  if (json === null) {
    return [];
  }
  try {
    return JSON.parse(json);
  } catch {
    // 保存内容が壊れている場合は空の一覧から始める
    return [];
  }
}

function saveTodos() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(todos));
}

// ===== 描画 =====
// 状態 (todos) から画面を作り直す。状態を変えたら必ず update を呼ぶ
function createTodoItem(todo) {
  const item = document.createElement("li");
  item.className = "todo-item";
  item.classList.toggle("done", todo.done);
  item.dataset.id = todo.id; // data-id 属性として要素に ID を持たせる

  const checkbox = document.createElement("input");
  checkbox.type = "checkbox";
  checkbox.className = "toggle-checkbox";
  checkbox.checked = todo.done;
  checkbox.setAttribute("aria-label", "完了");

  const text = document.createElement("span");
  text.className = "todo-text";
  text.textContent = todo.text; // innerHTML は使わない (XSS 対策)

  const deleteButton = document.createElement("button");
  deleteButton.type = "button";
  deleteButton.className = "delete-button";
  deleteButton.textContent = "削除";

  item.append(checkbox, text, deleteButton);
  return item;
}

function render() {
  list.replaceChildren(...todos.map(createTodoItem));
  const remaining = todos.filter((todo) => !todo.done).length;
  count.textContent = `未完了 ${remaining} 件 / 全 ${todos.length} 件`;
}

function update() {
  saveTodos();
  render();
}

// ===== 操作 =====
function addTodo(text) {
  todos.push({ id: Date.now().toString(), text, done: false });
  update();
}

function toggleTodo(id) {
  todos = todos.map((todo) =>
    todo.id === id ? { ...todo, done: !todo.done } : todo,
  );
  update();
}

function deleteTodo(id) {
  todos = todos.filter((todo) => todo.id !== id);
  update();
}

function clearDone() {
  todos = todos.filter((todo) => !todo.done);
  update();
}

// ===== イベントの登録 =====
form.addEventListener("submit", (event) => {
  event.preventDefault(); // ページ遷移を止める
  const text = input.value.trim();
  if (text === "") {
    return;
  }
  addTodo(text);
  input.value = "";
  input.focus();
});

// 各 li にリスナーを付ける代わりに、親の ul でまとめて受け取る (イベント委譲)
list.addEventListener("click", (event) => {
  const item = event.target.closest(".todo-item");
  if (item === null) {
    return;
  }
  const id = item.dataset.id;

  if (event.target.classList.contains("toggle-checkbox")) {
    toggleTodo(id);
  } else if (event.target.classList.contains("delete-button")) {
    deleteTodo(id);
  }
});

clearDoneButton.addEventListener("click", clearDone);

// ===== 初期表示 =====
render();

主な処理の要点は次のとおりである。

app.js の要点

処理

要点

createTodoItem

createElement でタスク 1 件分の li 要素を作る。タスクの文字列は textContent で設定し、XSS を防ぐ（第 7 章）。dataset.id に設定した値は、data-id 属性として要素に保持される。

render

replaceChildren で一覧の中身をすべて置き換え、件数を更新する。

toggleTodo

map とスプレッド構文 { ...todo, done: !todo.done } で、対象のタスクだけ done を反転した新しい配列を作る。

deleteTodo ／ clearDone

filter で、条件に合わないタスクだけを残した新しい配列を作る。

submit イベント

preventDefault でページの移動を止めてから、入力値を追加する（第 7 章）。

ul 要素の click イベント

イベント委譲により、すべてのタスクのチェックボックスと「削除」ボタンを 1 つのイベントリスナーで処理する（第 7 章）。closest メソッドは、自分自身から親へと順にたどり、セレクターに一致する最初の要素を返す。

イベント委譲を使わずに、createTodoItem で作る要素ごとにイベントリスナーを登録することもできる。しかし、render のたびに要素が作り直されるため、そのたびにイベントリスナーも登録し直すことになる。親の ul 要素は作り直されないため、イベントリスナーの登録は最初の 1 回だけで済む。

9.5. localStorage でデータを保存する

saveTodos 関数は todos を JSON.stringify で文字列に変換して localStorage に保存し、loadTodos 関数は JSON.parse で元の配列に戻す（第 8 章）。

保存されたデータが無い場合、getItem は null を返すため、空の配列から始める。また、保存された文字列が何らかの理由で JSON として正しくない場合、JSON.parse は例外を発生させる。そのため try...catch で例外を受け取り、空の配列から始めるようにしている。

なお、localStorage はオリジンごとに管理されるため、file:// で開いた場合と、ローカルサーバー経由で開いた場合とでは、別々のデータになる。

9.6. 開発者ツールによるデバッグ

プログラムが思いどおりに動かないときは、開発者ツールを使って原因を調べる。

デバッグに使う開発者ツールの機能

機能

使い方

コンソール

エラーの内容と、エラーが発生したファイル名・行番号を確認する。console.log(todos) のように、確認したい値を出力する処理を一時的に追加するのも有効である。

要素タブ

JavaScript で作った要素が、意図どおりの構造やクラスになっているかを確認する。

ソース（Sources）タブ

JavaScript の行番号をクリックしてブレークポイントを設定すると、その行で実行を一時停止し、変数の値を確認しながら 1 行ずつ実行できる。コードの中に debugger; と書いても、同じ位置で停止する。

アプリケーションタブ

localStorage に保存された内容を確認・削除する（Firefox では「ストレージ」タブ）。

練習として、次の機能を追加してみるとよい。

  • タスクの文字列をダブルクリックすると編集できるようにする（dblclick イベント）。

  • 「すべて」「未完了」「完了済み」の表示を切り替えるボタンを付ける。
