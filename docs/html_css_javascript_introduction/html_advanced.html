3. HTML の応用

3.1. セマンティック要素

HTML には、ページの各部分が持つ役割を表す要素が用意されている。これらをセマンティック要素（意味を持つ要素）と呼ぶ。

主なセマンティック要素

要素

意味

header

ページや記事のヘッダー。サイト名やナビゲーションを置く。

nav

主要なナビゲーション（サイト内のリンクの集まり）。

main

ページの主要な内容。1 ページに 1 つだけ置く。

article

それだけで完結する内容。ブログの記事やニュースの 1 項目など。

section

見出しを持つ内容のまとまり。

aside

本筋から外れた補足的な内容。サイドバーなど。

footer

ページや記事のフッター。著作権表示や関連リンクを置く。

これらの要素は、既定の見た目は div 要素とほとんど変わらない。それでもセマンティック要素を使うのは、検索エンジンやスクリーンリーダーなどのプログラムが、ページの構造を正しく理解できるようにするためである。たとえばスクリーンリーダーは、nav 要素や main 要素の位置へ直接移動する機能を持つ。

意味を持たせる必要がなく、CSS で見た目を整えるためだけに要素をまとめたい場合は、div 要素を使う。

examples/ch03/semantic.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <!-- スマートフォンで画面幅に合わせて表示するための指定 -->
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="セマンティック要素を使ったページの例">
  <title>セマンティック要素の例</title>
</head>
<body>
  <!-- ページ全体のヘッダー -->
  <header>
    <h1>技術ブログ</h1>
    <!-- 主要なナビゲーション -->
    <nav>
      <ul>
        <li><a href="#">ホーム</a></li>
        <li><a href="#">記事一覧</a></li>
        <li><a href="#">お問い合わせ</a></li>
      </ul>
    </nav>
  </header>

  <!-- ページの主要な内容。1 ページに 1 つだけ置く -->
  <main>
    <!-- それだけで完結する内容 (記事など) -->
    <article>
      <h2>HTML のセマンティック要素</h2>
      <p>公開日: <time datetime="2026-04-01">2026 年 4 月 1 日</time></p>

      <!-- 見出しを持つ内容のまとまり -->
      <section>
        <h3>なぜ意味で要素を選ぶのか</h3>
        <p>検索エンジンやスクリーンリーダーが、ページの構造を正しく理解できるようになる。</p>
      </section>

      <section>
        <h3>div との違い</h3>
        <p>div は意味を持たない。見た目を整えるためだけのまとまりには div を使う。</p>
      </section>
    </article>
  </main>

  <!-- ページ全体のフッター -->
  <footer>
    <p><small>&copy; 2026 prometech</small></p>
  </footer>
</body>
</html>

3.2. フォーム

フォームは、利用者からの入力を受け付ける仕組みである。form 要素の中に、入力欄となる要素を置く。

フォームの主な要素

要素

用途

input

1 行の入力欄。type 属性によって種類が変わる（下表）。

textarea

複数行の入力欄。

select と option

選択肢から選ぶドロップダウンリスト。

button

ボタン。type="submit" で送信、type="reset" で入力内容のリセット、type="button" で何もしないボタン（JavaScript で処理を付ける）になる。

label

入力欄の説明。

fieldset と legend

関連する入力欄をまとめ、題名を付ける。
input 要素の主な type 属性

type 属性の値

入力欄の種類

text

文字列（既定値）。

email

メールアドレス。送信時に形式が確認される。

password

パスワード。入力した文字が伏せて表示される。

number

数値。min 属性と max 属性で範囲を指定できる。

date

日付。カレンダーから選択できる。

checkbox

チェックボックス。複数選択できる。

radio

ラジオボタン。同じ name 属性を持つものの中から 1 つだけ選択できる。

3.2.1. label 要素による関連付け

label 要素の for 属性に入力欄の id 属性と同じ値を指定すると、ラベルと入力欄が関連付けられる。関連付けると、ラベルをクリックしたときに入力欄が選択されるようになり、スクリーンリーダーも入力欄の説明としてラベルを読み上げる。label 要素の中に入力欄を入れても、同じように関連付けられる。

3.2.2. 入力値の検証

required 属性を付けた入力欄が空のまま送信しようとすると、ブラウザがメッセージを表示して送信を止める。type="email" や min 属性・ max 属性による確認も同様である。

ただし、これらの確認はブラウザ側で行われるものであり、利用者が無効にすることもできる。サーバー側でも必ず入力値を検証しなければならない。

examples/ch03/form.html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>フォームの例</title>
</head>
<body>
  <h1>お問い合わせ</h1>

  <!--
    action 属性: 送信先の URL (省略すると現在のページに送信される)
    method 属性: GET ではクエリ文字列として URL に付加される
    送信後はアドレスバーの URL を確認すること
  -->
  <form method="get">
    <p>
      <!-- for と id を一致させると、ラベルと入力欄が関連付けられる -->
      <label for="name">お名前 (必須)</label><br>
      <input type="text" id="name" name="name" required>
    </p>

    <p>
      <label for="email">メールアドレス</label><br>
      <input type="email" id="email" name="email" placeholder="user@example.com">
    </p>

    <p>
      <label for="age">年齢</label><br>
      <input type="number" id="age" name="age" min="0" max="150">
    </p>

    <p>
      <label for="category">種別</label><br>
      <select id="category" name="category">
        <option value="question">質問</option>
        <option value="request">要望</option>
        <option value="other">その他</option>
      </select>
    </p>

    <fieldset>
      <legend>連絡方法</legend>
      <!-- 同じ name を持つラジオボタンは、1 つだけ選択できる -->
      <label><input type="radio" name="contact" value="email" checked> メール</label>
      <label><input type="radio" name="contact" value="phone"> 電話</label>
    </fieldset>

    <p>
      <label><input type="checkbox" name="subscribe" value="yes"> お知らせを受け取る</label>
    </p>

    <p>
      <label for="message">内容</label><br>
      <textarea id="message" name="message" rows="5" cols="40"></textarea>
    </p>

    <button type="submit">送信</button>
    <button type="reset">リセット</button>
  </form>
</body>
</html>

3.3. フォームの送信

送信ボタンを押すと、ブラウザは入力内容を form 要素の action 属性で指定した URL に送る。action 属性を省略した場合は、現在のページの URL に送る。送信されるのは name 属性を持つ入力欄だけであり、name 属性の値がキーになる。

送信方法は method 属性で指定し、主に次の 2 つがある。

送信方法

method

送信のされ方

主な用途

get

入力内容をクエリ文字列として URL の末尾に付ける（例：?name=山田&age=30）。既定値である。

検索など、データを取得する処理。

post

入力内容を HTTP リクエストの本体に入れて送る。URL には表示されない。

登録や投稿など、データを変更する処理。

get で送信すると、入力内容がブラウザの履歴やサーバーのログに URL として残る。パスワードなどの機密情報を送るときは post を使う。ただし、post でも通信内容そのものは暗号化されないため、機密情報を扱うページは必ず HTTPS で公開する。

サンプルの form.html は method="get" で自分自身に送信するため、送信後にアドレスバーの URL を見ると、入力内容がクエリ文字列として付加されていることを確認できる。受け取った値を処理するには、Python の Flask や Django などで作ったサーバー側のプログラムが必要になる。本資料ではサーバー側のプログラムは扱わず、第 7 章で JavaScript を使って入力値を処理する方法を扱う。

3.4. メタ情報

head 要素の中には、ページ本体には表示されない情報を書く。

head 要素に書く主な要素

記述

意味

<meta charset="UTF-8">

文字コードの指定。文字化けを防ぐため、head 要素の先頭に書く。

<meta name="viewport" content="width=device-width, initial-scale=1">

スマートフォンで、画面の幅に合わせて表示するための指定。省略すると、PC 向けの幅で描画したページが縮小表示される。

<title>...</title>

ページのタイトル。ブラウザのタブや検索結果、ブックマークに表示される。

<meta name="description" content="...">

ページの説明文。検索結果に表示されることがある。

<link rel="stylesheet" href="style.css">

外部の CSS ファイルを読み込む（第 4 章で扱う）。

<script src="app.js" defer></script>

外部の JavaScript ファイルを読み込む（第 6 章で扱う）。

3.5. アクセシビリティの基本

アクセシビリティとは、障害の有無や利用環境にかかわらず、誰もが Web ページを利用できるようにすることである。特別な技術は必要なく、HTML を正しく書くことが基本になる。

  • 画像には、内容を説明する alt 属性を付ける。装飾のための画像で説明が不要な場合は、alt="" のように空の値を指定する。

  • 入力欄には label 要素を関連付ける。

  • 見出しは h1 から順に、レベルを飛ばさずに使う。見た目の大きさで見出しのレベルを選ばない。

  • クリックして操作するものには button 要素や a 要素を使う。div 要素にクリック時の処理を付けると、キーボードで操作できなくなる。

  • html 要素の lang 属性で言語を指定する。スクリーンリーダーが正しい言語で読み上げるために使われる。

3.6. HTML の検証

前述のとおり、ブラウザは誤った HTML も推測で補って表示するため、見た目だけでは誤りに気付きにくい。しかし、補い方はブラウザによって異なることがあり、CSS や JavaScript が期待どおりに動かない原因になる。

HTML が仕様に沿っているかどうかは、W3C（Web の標準化団体）が提供する Markup Validation Service で確認できる。作成したファイルをアップロードするか、内容を貼り付けると、誤りの箇所と理由が表示される。
