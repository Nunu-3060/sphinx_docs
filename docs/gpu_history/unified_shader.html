6. 統合シェーダアーキテクチャと GPGPU の確立（2005 年〜）

本章では、GPU の内部構造が「描画専用のパイプライン」から「汎用の並列プロセッサの集まり」へと転換した時代について述べる。この転換と、CUDA に代表される汎用計算向けのプログラミング環境の登場によって、GPU は科学技術計算の分野で本格的に使われるようになった。

6.1. 分離型シェーダの問題

前章で述べたように、2000 年代前半の GPU は、頂点シェーダを実行する演算器とピクセルシェーダを実行する演算器を別々に持っていた。両者の数の比率は設計時に固定されるが、実際の描画処理の負荷は場面によって大きく変わる。

たとえば、細かいポリゴンを大量に描く場面では頂点処理の負荷が高くなり、ピクセルシェーダ用の演算器が遊んでしまう。逆に、少ないポリゴンで画面全体に複雑な効果をかける場面では、頂点シェーダ用の演算器が遊んでしまう。このように、分離型の構造では負荷の偏りによってハードウェアを有効に使えないという問題があった。

6.2. 統合シェーダアーキテクチャ

この問題を解決するのが統合シェーダアーキテクチャである。統合シェーダでは、頂点シェーダもピクセルシェーダも同じ汎用の演算器で実行し、その時点の負荷に応じて演算器を動的に割り当てる（図 6.1）。統合シェーダの図では、頂点処理の結果をラスタライズしたあと、生成されたピクセルの処理も同じスケジューラを通じて同じ演算器の集まりに割り当てられる（点線の矢印）。

統合シェーダを最初に採用したのは、2005 年に発売された Microsoft の Xbox 360 である。Xbox 360 には ATI が設計した GPU（開発名 Xenos）が搭載され、48 個の統合シェーダ演算器を持っていた。

PC 向けでは、2006 年 11 月に NVIDIA が発表した GeForce 8800 GTX（開発名 G80）が最初の統合シェーダ GPU である。G80 は 128 個の演算器を持ち、約 6.8 億個のトランジスタを集積していた[Lindholm2008]。G80 の演算器はベクトル演算ではなくスカラー演算を基本とし、「GPU を理解するための基礎知識」で述べた SIMT 方式で多数のスレッドを実行した。この設計は、グラフィックスだけでなく汎用計算にも適したものであった。

API の側でも、2006 年に完成した DirectX 10（Windows Vista とともに提供）が、統合シェーダを前提としたシェーダモデル 4.0 を定義した。DirectX 10 では、すべての種類のシェーダが共通の命令セットを持つようになり、頂点の集合から新たな図形を生成するジオメトリシェーダも追加された。

一方 ATI は、2006 年に AMD に買収された。AMD は 2007 年に、統合シェーダを採用した PC 向けの GPU である Radeon HD 2900 XT を発表した。

6.3. CUDA の登場

G80 の発表と同じ 2006 年 11 月、NVIDIA は GPU で汎用計算を行うためのプラットフォームである CUDA（Compute Unified Device Architecture）を発表し、2007 年にソフトウェア開発キットを公開した[NVIDIA-CUDA]。CUDA は、前章で述べた GPGPU の制約を次のように解消した。

  • C 言語を拡張した言語で GPU 上のプログラム（カーネル）を記述でき、グラフィックス API の知識が不要になった。

  • GPU のメモリの任意の位置に読み書きできるようになった。

  • 同じスレッドブロック内のスレッドが、チップ上の高速な共有メモリを通じてデータを共有し、同期できるようになった。

リスト 6.1 に、前章のリスト 5.1 と同じ配列の加算を CUDA で記述した例を示す。

リスト 6.1 CUDA による配列の加算の例
 1// GPU 上で実行される関数（カーネル）
 2__global__ void add(const float *a, const float *b, float *c, int n)
 3{
 4    // 自分が担当する要素の番号を、ブロック番号とスレッド番号から求める
 5    int i = blockIdx.x * blockDim.x + threadIdx.x;
 6    if (i < n) {
 7        c[i] = a[i] + b[i];
 8    }
 9}
10
11// CPU 側からの呼び出し：1 ブロックあたり 256 スレッドで n 要素を処理する
12int threads = 256;
13int blocks = (n + threads - 1) / threads;
14add<<<blocks, threads>>>(d_a, d_b, d_c, n);

2〜9 行目がカーネルで、各スレッドが配列の 1 要素を担当する。5 行目で、スレッドは自分の担当する要素の番号を、所属するブロックの番号（blockIdx）、ブロックの大きさ（blockDim）、ブロック内での番号（threadIdx）から求める。14 行目の <<<blocks, threads>>> という記法で、起動するスレッドの数を指定してカーネルを実行する。プログラマは 1 要素分の処理を書くだけでよく、それを数百万のスレッドに展開して並列に実行するのは GPU の役割である。

CUDA のプログラミングモデルでは、スレッドをブロックにまとめ、ブロックをグリッドにまとめる階層構造を採用した。ブロック内のスレッドは同じ SM（Streaming Multiprocessor）で実行され、共有メモリを使って協調できる。一方、ブロック同士は独立に実行されるため、SM の数が異なる GPU でも同じプログラムがそのまま動作し、SM が多い GPU ほど高速に処理できる。この拡張性は、その後の世代の GPU でも CUDA のプログラムを使い続けられる基盤となった。

CUDA は NVIDIA の GPU 専用の環境であったが、NVIDIA が継続的に投資を続けたことで、コンパイラ、デバッガ、数値計算ライブラリ（線形代数の cuBLAS、高速フーリエ変換の cuFFT など）を含む充実したソフトウェア群が整備された。このソフトウェアの蓄積は、後に NVIDIA の大きな競争力の源泉となる（「技術トレンドの横断的考察」を参照）。

6.4. OpenCL と DirectCompute

CUDA に対抗する汎用計算の環境も登場した。AMD は 2006 年に、GPU の命令を直接扱う低水準のインタフェースである CTM（Close to Metal）を公開し、その後 Brook を拡張した Brook+ を含む ATI Stream SDK を提供した。

ベンダーに依存しない標準規格としては、Apple が提案し、Khronos Group が 2008 年に仕様を公開した OpenCL がある[Khronos-OpenCL]。OpenCL は GPU だけでなく CPU や DSP なども対象とし、2009 年の Mac OS X Snow Leopard をはじめ、多くのプラットフォームで採用された。また Microsoft は、2009 年に提供を開始した DirectX 11 で、汎用計算用のシェーダである DirectCompute（コンピュートシェーダ）を導入した。DirectX 11 では、ポリゴンを細かく分割して形状を精密にするテッセレーションも導入されている。

これらの標準規格は、特定のベンダーに依存しない点で優れていたが、開発ツールやライブラリの充実度では CUDA が先行し続けた。

6.5. HPC への進出

GPU を科学技術計算（HPC：High Performance Computing）に本格的に使うには、グラフィックスでは重視されなかった性質が必要であった。代表的なものは、科学技術計算で標準的な倍精度（FP64）浮動小数点演算の性能と、メモリのデータ化けを検出・訂正する ECC（Error Correcting Code）である。

NVIDIA は 2007 年に、汎用計算専用の製品ブランドとして Tesla を立ち上げた。2008 年の GT200 世代で倍精度演算に対応し、2010 年の Fermi 世代（GF100）で HPC 向けの機能を大幅に強化した[NVIDIA-Fermi]。Fermi は次のような特徴を持っていた。

  • メモリの ECC に対応した。

  • 倍精度演算の性能を、HPC 向けの製品では単精度の半分まで高めた。

  • L1 キャッシュと L2 キャッシュからなるキャッシュ階層を導入した。

  • IEEE 754-2008 に準拠した浮動小数点演算と FMA 命令を備えた。

  • C++ のプログラムを GPU で実行するための機能を強化した。

GPU の HPC への進出を象徴する出来事が、スーパーコンピュータの性能ランキングである TOP500 での躍進である[TOP500]。2010 年 11 月には、NVIDIA の GPU を搭載した中国の天河一号 A（Tianhe-1A）が 1 位を獲得した。2012 年 11 月には、NVIDIA の Kepler 世代の GPU（Tesla K20X）を搭載した米国オークリッジ国立研究所の Titan が 1 位となった。日本でも、2010 年に稼働した東京工業大学の TSUBAME 2.0 が GPU を大規模に採用した。

GPU は、同じ消費電力で CPU よりも多くの演算を実行できる。スーパーコンピュータの性能向上において消費電力が最大の制約になりつつあったことから、GPU などのアクセラレータを組み合わせる構成は、その後の大規模システムの主流となっていった。

6.6. アーキテクチャの成熟

2010 年代前半には、NVIDIA と AMD の双方が、グラフィックスと汎用計算の両方を前提としたアーキテクチャを確立した。

NVIDIA は、2012 年の Kepler 世代で、GPU 上のカーネルから別のカーネルを起動するダイナミックパラレリズムなどを導入し、2014 年の Maxwell 世代で電力効率を大きく改善した。

AMD は、Radeon HD 2900 XT 以降、5 つの演算を 1 つの命令にまとめて実行する VLIW（Very Long Instruction Word）方式を採用していた。VLIW 方式は、グラフィックス処理のように並列性がはっきりしている処理には効率がよいが、汎用計算では命令に演算を詰め込みきれず、演算器が遊びやすいという弱点があった。AMD は 2012 年に、SIMD を基本とする新しいアーキテクチャ GCN（Graphics Core Next）を採用した Radeon HD 7970 を発売し、汎用計算での効率を高めた。GCN では 64 スレッドを 1 つのウェーブフロントとして実行する。

また、この時期には CPU 側からも並列プロセッサへのアプローチがあった。Intel は、多数の x86 コアで GPU を構成する Larrabee を開発していたが、2009 年にグラフィックス製品としての発売を断念した。その技術は HPC 向けのアクセラレータである Xeon Phi に引き継がれたが、Xeon Phi も 2010 年代後半に開発が終了した。

6.7. 統合シェーダの時代の意義

統合シェーダアーキテクチャによって、GPU は「描画用の回路に汎用計算の機能を付け加えたもの」から「汎用の並列プロセッサに描画用の固定機能を付け加えたもの」へと性格を変えた。そして CUDA の登場によって、GPU は一般のプログラマが C 言語に近い言語で利用できる計算資源になった。

この時代に整備された、大量の演算器、高いメモリ帯域幅、成熟したプログラミング環境という 3 つの要素がそろっていたことが、次章で述べる深層学習の急速な発展を可能にした。
