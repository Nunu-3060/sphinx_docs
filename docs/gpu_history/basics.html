2. GPU を理解するための基礎知識

本章では、後続の章で繰り返し登場する概念をまとめて説明する。歴史の記述を読む際に用語や仕組みが分からなくなったときは、本章に戻って確認してほしい。

2.1. リアルタイム 3D グラフィックスの処理の流れ

GPU はもともと、3D 空間に置かれた物体を 2D の画面に描画する処理を高速化するために生まれた。現在のゲームなどで使われるリアルタイム 3D グラフィックスの多くは、ラスタライズと呼ばれる方式で描画する。物体の表面を三角形（ポリゴン）の集まりで表現し、各三角形を画面上のピクセルに変換して色を決める方式である。

この処理は、図 2.1 に示す一連の段階で構成される。この流れをグラフィックスパイプラインと呼ぶ。

各段階の役割は次のとおりである。

表 2.1 グラフィックスパイプラインの各段階

段階

役割

頂点処理

三角形の頂点の座標を、物体ごとの座標系から画面上の座標系へ変換する。頂点ごとに光の当たり方を計算することもある。座標変換（Transform）と光源計算（Lighting）を合わせて T&L と呼ぶ。

プリミティブ処理

頂点を三角形などの図形（プリミティブ）に組み立て、画面外にはみ出した部分を切り取る（クリッピング）。

ラスタライズ

三角形が覆う画面上のピクセルを求め、頂点の属性（色やテクスチャ座標など）をピクセルごとに補間する。

ピクセル処理

ピクセルごとに最終的な色を計算する。画像を表面に貼り付けるテクスチャマッピングもこの段階で行う。OpenGL ではこの段階をフラグメント処理と呼ぶ。

出力合成

奥行き（深度）を比較して手前の物体だけを残したり、半透明の色を合成したりして、結果をフレームバッファに書き込む。

座標変換は、頂点の座標を同次座標 \(\mathbf{v} = (x, y, z, 1)^\top\) で表し、\(4 \times 4\) の行列を掛けることで行う。物体の配置を表すモデル行列 \(M\)、視点の位置と向きを表すビュー行列 \(V\)、遠近感を表す射影行列 \(P\) を用いると、変換後の座標 \(\mathbf{v}'\) は次の式で求められる。

\[\mathbf{v}' = P \, V \, M \, \mathbf{v}\]

頂点 1 つあたりの計算量は小さいが、1 フレームあたりの頂点数は数十万から数百万に達する。

ここで重要なのは、この処理には膨大な量の独立した計算が含まれるという点である。たとえば 1920 × 1080 ピクセルの画面を毎秒 60 回描き換える場合、1 秒あたりに色を決めるピクセルの数は次のようになる。

\[1920 \times 1080 \times 60 = 124{,}416{,}000\]

実際には 1 ピクセルに複数の三角形が重なるため、計算量はさらに大きい。一方、あるピクセルの色の計算は、原則として隣のピクセルの計算結果に依存しない。頂点処理も同様である。このように、同じ種類の処理を大量のデータに対して独立に適用できる性質をデータ並列性と呼ぶ。GPU の歴史は、このデータ並列性をハードウェアでいかに効率よく処理するかを追求してきた歴史であるといえる。

2.2. CPU と GPU の設計思想の違い

CPU と GPU はどちらもプロセッサであるが、最適化の目標が異なる（図 2.2）。

CPU は、1 つの処理の流れ（スレッド）をできるだけ短い時間で終えること、すなわちレイテンシの短縮を重視して設計されている。そのため、分岐予測やアウトオブオーダー実行といった複雑な制御回路と、メモリアクセスの待ち時間を隠すための大容量キャッシュに多くのチップ面積を割く。

GPU は、単位時間あたりに処理できる仕事の総量、すなわちスループットを重視して設計されている。個々の演算器は単純にし、その代わりに大量の演算器を並べる。メモリアクセスには数百サイクルの待ち時間がかかるが、GPU はこれを大容量キャッシュではなく、大量のスレッドを用意しておき、待ちが発生したスレッドの代わりに別のスレッドを実行することで隠す。この方式をレイテンシ隠蔽と呼ぶ。スレッドの切り替えを低コストで行うため、GPU は多数のスレッドの状態（レジスタ）を同時にチップ上に保持する大容量のレジスタファイルを持つ。

この違いから、逐次的で分岐の多い処理は CPU が得意とし、データ並列性の高い大量の計算は GPU が得意とする。現在のシステムでは、CPU が全体の制御を担い、データ並列性の高い部分を GPU に任せる構成が一般的である。

2.3. SIMD と SIMT

多数の演算器を少ない制御回路で動かすため、GPU は 1 つの命令で複数のデータを同時に処理する。この方式を SIMD（Single Instruction, Multiple Data）と呼ぶ。

現在の GPU の多くは、プログラマに対しては各スレッドが独立したプログラムを実行しているように見せつつ、ハードウェアの内部では一定数のスレッドをまとめて 1 つの命令で実行する。NVIDIA はこの方式を SIMT（Single Instruction, Multiple Threads）と呼ぶ。まとめて実行されるスレッドの集団を、NVIDIA はワープ（32 スレッド）、AMD はウェーブフロント（64 スレッドまたは 32 スレッド）と呼ぶ。

SIMT では、同じワープ内のスレッドが条件分岐で異なる方向に進むと、両方の経路を順番に実行し、該当しないスレッドを無効化する。この現象を分岐発散（ダイバージェンス）と呼び、性能低下の原因になる。GPU 向けのプログラムで分岐をなるべく揃えることが推奨されるのはこのためである。

2.4. 性能を表す指標

GPU の性能を比較する際には、主に演算性能とメモリ帯域幅の 2 つの指標が用いられる。

2.4.1. 演算性能

演算性能は、1 秒あたりに実行できる浮動小数点演算の回数である FLOPS で表す。理論上の最大性能（ピーク性能）は次の式で求められる。

\[\text{ピーク性能 [FLOPS]} = \text{演算器の数} \times \text{クロック周波数 [Hz]} \times \text{1 サイクルあたりの演算回数}\]

GPU の演算器の多くは、\(a \times b + c\) を 1 命令で計算する積和演算（FMA）に対応しており、これを 2 回の演算として数える。たとえば 2006 年の GeForce 8800 GTX は、128 個の演算器が 1.35 GHz で動作し、1 サイクルあたり積和演算を 1 回（2 演算）実行できるため、単精度のピーク性能は次のようになる。

\[128 \times 1.35 \times 10^{9} \times 2 = 345.6 \times 10^{9} \ \text{FLOPS} = 345.6 \ \text{GFLOPS}\]

演算性能は数値の精度によって大きく異なる。64 ビットの倍精度（FP64）、32 ビットの単精度（FP32）、16 ビットの半精度（FP16）など、精度が低いほど 1 つの演算に必要な回路が小さく、データ量も少ないため、高い性能が得られる。どの精度の性能を重視するかは時代と用途によって変わってきた（「深層学習と GPU（2012 年〜）」を参照）。

2.4.2. メモリ帯域幅

メモリ帯域幅は、1 秒あたりにメモリとの間で転送できるデータ量である。GPU に直結されたメモリ（VRAM）の帯域幅は、次の式で求められる。

\[\text{帯域幅 [B/s]} = \frac{\text{メモリバス幅 [bit]}}{8} \times \text{1 ピンあたりのデータ転送速度 [転送/s]}\]

GeForce 8800 GTX は 384 ビットのメモリバスを持ち、1 ピンあたり毎秒 18 億回（1.8 GT/s）のデータ転送を行うため、帯域幅は次のようになる。

\[\frac{384}{8} \times 1.8 \times 10^{9} = 86.4 \times 10^{9} \ \text{B/s} = 86.4 \ \text{GB/s}\]

2.4.3. 演算強度とルーフラインモデル

ある処理が演算性能とメモリ帯域幅のどちらで制約されるかは、メモリから読み書きする 1 バイトあたりの演算回数で判断できる。これを演算強度（単位は FLOP/B）と呼ぶ。演算強度を \(I\)、ピーク性能を \(P_{\text{peak}}\)、メモリ帯域幅を \(B\) とすると、達成できる性能 \(P\) の上限は次の式で表される。この考え方をルーフラインモデルと呼ぶ[Williams2009]。

\[P = \min \left( P_{\text{peak}}, \; B \times I \right)\]

GeForce 8800 GTX の場合、\(P_{\text{peak}} / B = 345.6 / 86.4 = 4\) であるため、演算強度が 4 FLOP/B より低い処理はメモリ帯域幅で、高い処理は演算性能で上限が決まる。後の章で見るように、GPU の演算性能はメモリ帯域幅よりも速いペースで向上してきたため、この境界は年々高くなっている。メモリの技術が GPU の歴史の中で重要な位置を占めるのはこのためである（「技術トレンドの横断的考察」を参照）。
