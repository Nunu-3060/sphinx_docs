4. 「GPU」の誕生：固定機能パイプラインの時代（1999 年〜）

本章では、1999 年の GeForce 256 の登場によって「GPU」という言葉が生まれた経緯と、その時代のハードウェアの特徴である固定機能パイプラインについて述べる。

4.1. GeForce 256 とハードウェア T&L

1999 年 8 月、NVIDIA は GeForce 256 を発表した。GeForce 256 の最大の特徴は、それまで CPU が担っていた頂点処理、すなわち座標変換と光源計算（T&L）をグラフィックスチップ上で実行するハードウェア T&L を搭載したことである。これにより、グラフィックスパイプラインのほぼすべての段階が 1 つのチップで処理されるようになった。

NVIDIA はこのチップを、CPU と対になる新しい種類のプロセッサとして位置付け、「GPU（Graphics Processing Unit）」と名付けた。NVIDIA による GPU の定義は「座標変換、光源計算、三角形のセットアップとクリッピング、レンダリングの各エンジンを 1 つのチップに統合し、毎秒 1,000 万ポリゴン以上を処理できるプロセッサ」というものであった。GPU という言葉は当初はマーケティング上の用語であったが、その後業界全体で使われる一般名詞になった。

GeForce 256 は 220 nm プロセスで製造され、約 2,300 万個のトランジスタを集積していた。4 本のピクセルパイプラインを持ち、メモリには当初 SDR SDRAM を、後に発売された GeForce 256 DDR では DDR SDRAM を採用した。GeForce 256 DDR は、GPU として初めて DDR メモリを採用した製品である。

4.2. ハードウェア T&L の効果

ハードウェア T&L の導入には、次の 2 つの効果があった。

  1. CPU の負荷の軽減：頂点処理を GPU に任せることで、CPU はゲームの進行や物理演算などの処理に専念できるようになった。

  2. ポリゴン数の増加：専用の回路で頂点を処理することで、1 フレームに描画できるポリゴンの数が増え、より精細な 3D モデルを使えるようになった。

ただし、ハードウェア T&L の効果を得るには、アプリケーションが API を通じて頂点処理を GPU に任せる必要があった。Windows では 1999 年の DirectX 7 が、ハードウェア T&L を Direct3D から利用する仕組みを提供した。OpenGL は当初から座標変換や光源計算を API の機能として定義していたため、ドライバが対応すれば既存のアプリケーションでもハードウェア T&L を利用できた。

4.3. 競争の激化と業界の再編

GeForce 256 の登場後、各社はハードウェア T&L を備えた製品で追随した。2000 年には ATI が、DirectX 7 に対応しハードウェア T&L を搭載した Radeon を発表した。同年、NVIDIA は GeForce2 を発表し、性能をさらに向上させた。

一方、ハードウェア T&L への対応が遅れた 3dfx は急速に競争力を失い、2000 年末に主要な資産を NVIDIA に売却した。これ以降、PC 向けの高性能なグラフィックスチップ市場は、NVIDIA と ATI の二社が主導する時代に入った。

ゲーム機では、2000 年に発売されたソニーの PlayStation 2 が独自設計の描画チップ（Graphics Synthesizer）を搭載した。2001 年に発売された Microsoft の Xbox は、NVIDIA の GPU を搭載し、PC 向けの GPU 技術がゲーム機に採用される先駆けとなった。

4.4. 固定機能パイプライン

この時代の GPU は、固定機能パイプラインと呼ばれる構造を持っていた。グラフィックスパイプラインの各段階が専用の回路で実装されており、プログラマはあらかじめ用意された機能の中から使うものを選び、パラメータを設定することしかできなかった。

リスト 4.1 に、OpenGL の固定機能パイプラインで光源を設定して三角形を描画するコードの例を示す。

リスト 4.1 固定機能パイプラインによる描画の例（OpenGL 1.x）
 1/* 光源を有効にし、位置と色を設定する */
 2glEnable(GL_LIGHTING);
 3glEnable(GL_LIGHT0);
 4glLightfv(GL_LIGHT0, GL_POSITION, light_position);
 5glLightfv(GL_LIGHT0, GL_DIFFUSE, light_color);
 6
 7/* 物体の座標変換を設定する */
 8glMatrixMode(GL_MODELVIEW);
 9glLoadIdentity();
10glTranslatef(0.0f, 0.0f, -5.0f);
11glRotatef(angle, 0.0f, 1.0f, 0.0f);
12
13/* 三角形を描画する */
14glBegin(GL_TRIANGLES);
15glNormal3f(0.0f, 0.0f, 1.0f);
16glVertex3f(-1.0f, -1.0f, 0.0f);
17glVertex3f( 1.0f, -1.0f, 0.0f);
18glVertex3f( 0.0f,  1.0f, 0.0f);
19glEnd();

2〜5 行目で光源を、8〜11 行目で座標変換を設定している。光の当たり方の計算方法（光源モデル）は API とハードウェアがあらかじめ決めており、プログラマが変更することはできない。たとえば、金属の質感を表す独自の反射モデルや、輪郭線を強調するアニメ調の表現を実現しようとしても、用意された機能の組み合わせで近似するしかなかった。

この制約を緩和するため、GeForce 256 や GeForce2 には、複数のテクスチャの色を合成する方法をある程度設定できる機能（NVIDIA は Register Combiners と呼んだ）が搭載された。これはプログラマブルとまではいえないものの、ピクセル処理に柔軟性を持たせようとする試みであり、次章で述べるプログラマブルシェーダへの橋渡しとなった。

4.5. 固定機能の時代の意義

固定機能パイプラインの時代は短く、わずか 2 年ほどで次のプログラマブルシェーダの時代に移行した。しかし、この時代に次の 2 つの重要な変化が起きた。

  • グラフィックスパイプライン全体が 1 チップに収まり、GPU が CPU と並ぶ独立したプロセッサとして認識されるようになった。

  • 「描画処理は GPU に任せる」というシステム構成が定着し、CPU と GPU の役割分担の基本形ができた。

一方で、表現の自由度の低さは、ゲーム開発者や映像制作者にとって大きな不満であった。この不満が、GPU にプログラマビリティをもたらす原動力となった。
