第 13 章 数値計算での注意

これまでの章では、NumPy の関数を使えば行列の計算が正確にできるかのように扱ってきた。しかし、コンピューターは実数を有限の桁数で近似して計算するので、結果には必ず誤差が含まれる。この章では、浮動小数点数の誤差、誤差を拡大する悪条件の問題、それを防ぐピボット選択を説明し、大規模な行列を扱うための疎行列と、NumPy の背後にあるライブラリを紹介する。

浮動小数点数の誤差

Python の float や NumPy の float64 は、IEEE 754 [IEEE754] の倍精度の浮動小数点数であり、有効数字は 2 進数で 53 桁（10 進数で約 16 桁）である。0.1 のように 2 進数で有限の桁数で表せない数は、最も近い表せる数に丸められる。この誤差を丸め誤差という。

14    eps = np.finfo(np.float64).eps

17    print("(1 + eps / 2) - 1 =", (1.0 + eps / 2) - 1.0)  # 1 に比べて小さすぎて消える
18
19    # 桁落ち: 近い値どうしの引き算で、有効数字が失われる

21    naive = (1.0 - np.cos(x)) / x**2  # 正しい値は約 0.5
22    stable = 2.0 * np.sin(x / 2) ** 2 / x**2  # 1 - cos x = 2 sin^2(x/2) を使う
23    print("(1 - cos x) / x^2 =", naive)
24    print("2 sin^2(x/2) / x^2 =", stable)
25

27    a = 1e-3 * np.eye(10)  # 対角成分が 0.001 の 10 次の対角行列
28    print("det(0.001 I_10) =", np.linalg.det(a), " 条件数 =", np.linalg.cond(a))

0.1 + 0.2 == 0.3: False
np.isclose(0.1 + 0.2, 0.3): True

実行結果から、次のことが分かる。

  • 0.1 + 0.2 は 0.3 にならない。そのため、浮動小数点数を == で比べてはいけない。誤差の範囲で等しいかを np.isclose()（配列なら np.allclose()）で調べる。

  • 1 に加えたときに結果が 1 と区別できる最小の数を計算機イプシロンといい、倍精度では約 \(2.2 \times 10^{-16}\) である。これより小さい相対的な変化は、丸めで消えてしまう。

  • 近い値どうしの引き算では、有効数字の多くが失われる。これを桁落ちという。\(x = 10^{-8}\) のとき \(\cos x\) は 1 に非常に近いので、\(1 - \cos x\) の有効数字がすべて失われ、正しい値 0.5 の代わりに 0 が得られている。式を \(2\sin^2(x/2)\) に変形すると、引き算がなくなり、正しい値が得られる。

  • 行列式の値の大小で、行列が「ほぼ特異（正則でない）」かを判断してはいけない。\(0.001\,I_{10}\) の行列式は \(10^{-30}\) と非常に小さいが、単位行列の定数倍なので、連立一次方程式は誤差なく解ける。行列の扱いにくさは、次に述べる条件数で測る。浮動小数点数の誤差と数値計算の安定性については、文献 [Higham2002] が詳しい。

条件数と悪条件の問題

連立一次方程式 \(A\bm{x} = \bm{b}\) で、右辺 \(\bm{b}\) にわずかな誤差 \(\Delta\bm{b}\) があると、解にも誤差 \(\Delta\bm{x}\) が生じる。その相対的な大きさについて、次の不等式が成り立つ。

\[\frac{\|\Delta\bm{x}\|}{\|\bm{x}\|} \le \kappa(A) \, \frac{\|\Delta\bm{b}\|}{\|\bm{b}\|}, \qquad \kappa(A) = \frac{\sigma_{\max}}{\sigma_{\min}}\]

\(\kappa(A)\) を \(A\) の条件数といい、最大の特異値と最小の特異値の比である。条件数は、入力の相対誤差が解で最大何倍に拡大されるかを表す。第 12 章の幾何学的な意味で言えば、単位円が移る楕円の長軸と短軸の比である。楕円が細長いほど、短軸の方向の小さな誤差が、元に戻すと大きく拡大される。

条件数が大きい行列を悪条件という。丸め誤差は計算機イプシロン程度の相対誤差を生じるので、大まかに言って、条件数が \(10^k\) なら、解の有効数字は約 \(16 - k\) 桁になる。条件数が \(10^{16}\) 程度に達すると、解の有効数字は残らない。

悪条件の代表例が、\((i, j)\) 成分が \(1/(i + j - 1)\) のヒルベルト行列である。真の解をすべて 1 のベクトルとして右辺を作り、np.linalg.solve() で解き直してみる。

リスト 51 ch13_hilbert.py の report()
20def report() -> None:
21    """次数ごとの条件数と、解の相対誤差を表示する."""
22    print(" n   条件数        解の相対誤差")
23    for n in (2, 4, 6, 8, 10, 12):
24        h = hilbert(n)
25        x_true = np.ones(n)
26        b = h @ x_true
27        x = np.linalg.solve(h, b)
28        error = np.linalg.norm(x - x_true) / np.linalg.norm(x_true)
29        print(f"{n:2d}   {np.linalg.cond(h):10.2e}   {error:10.2e}")

次数が上がると条件数は急激に大きくなり、それに比例して解の誤差が大きくなる。12 次では、条件数が \(10^{16}\) に達し、解の誤差は約 13% になっている。ヒルベルト行列は、多項式 \(1, x, x^2, \ldots\) で最小二乗法を行うときの正規方程式の係数行列に現れる。高い次数の多項式の当てはめで、正規方程式を使うべきでない理由の 1 つである（第 9 章）。

NumPy では、条件数を np.linalg.cond() で求められる。計算結果が疑わしいときは、条件数を確かめるとよい。悪条件の問題に対しては、計算方法を工夫するより、問題の定式化（変数の単位のそろえ方、基底の選び方）を見直すほうが効果的なことが多い。

ピボット選択

行列が悪条件でなくても、計算方法が悪いと誤差が大きくなる。次の連立一次方程式を考える。

\[\begin{split}\begin{aligned} 10^{-20} x + y &= 1 \\ x + y &= 2 \end{aligned}\end{split}\]

係数行列の条件数は約 2.6 で、問題は良条件である。解はほぼ \(x = 1\)、\(y = 1\) である。

第 5 章のガウスの消去法をそのまま使うと、1 行目の \(10^{-20}\) をピボットにして、2 行目から 1 行目の \(10^{20}\) 倍を引く。すると、2 行目は \((1 - 10^{20})y = 2 - 10^{20}\) になるが、丸め誤差で \(-10^{20} y = -10^{20}\) となり、\(y = 1\) が得られる。これを 1 行目に代入すると \(10^{-20} x = 1 - 1 = 0\) なので \(x = 0\) となり、\(x\) が完全に失われる。小さなピボットで割ると大きな倍率が生まれ、他の成分の情報が丸めで消えてしまうのである。

これを防ぐには、各列の消去の前に、その列で絶対値が最大の成分を持つ行をピボットの行に選び、行を入れ替える。これを部分ピボット選択という。この例では、2 行目と 1 行目を入れ替えてから消去するので、倍率は \(10^{-20}\) と小さく、正しい解が得られる。

疎行列

偏微分方程式を有限要素法や差分法で解くと、未知数が数百万に達する連立一次方程式が現れる。\(n = 10^6\) の正方行列を倍精度で普通に保存すると、\(10^{12}\) 個の成分に 8 TB のメモリーが必要であり、LU 分解には \(10^{18}\) 回程度の演算が必要になる。

しかし、このような行列の成分のほとんどは 0 である。例えば、第 11 章で示した 3 重対角の行列は、1 行に 0 でない成分が 3 個しかない。成分のほとんどが 0 の行列を疎行列といい、0 でない成分とその位置だけを保存することで、メモリーと計算量を大幅に減らせる。Python では、SciPy の scipy.sparse で疎行列を扱える。

疎行列の連立一次方程式は、LU 分解ではなく、共役勾配法などの反復法で解くことが多い。反復法は、行列とベクトルの積を繰り返して近似解を改良する方法であり、疎行列では行列とベクトルの積が非常に速く計算できる。反復法は本書の範囲を超えるので、名前の紹介にとどめる。

NumPy の背後にあるライブラリ

NumPy の行列計算は、Python で書かれているわけではない。行列の積などの基本的な演算はBLAS（Basic Linear Algebra Subprograms）、連立一次方程式、固有値、特異値分解などはLAPACK（Linear Algebra PACKage）という、長年にわたって改良されてきた数値計算ライブラリを呼び出している [LAPACK]。どの関数がどの方法を使うかは、NumPy の資料 [NumPyLinalg] に記載されている。

BLAS には、CPU の命令やキャッシュに合わせて最適化された実装（OpenBLAS、Intel MKL など）があり、複数のコアで並列に計算する。行列の計算を自分でループで書くと、これらの最適化の恩恵を受けられず、数十倍から数百倍遅くなることもある。教科書のアルゴリズムを理解するために自分で実装するのはよいが、実用ではライブラリの関数を使うべきである。行列の計算法そのものは、文献 [Golub2013] や [Trefethen1997] で学べる。

この章のまとめ

  • 浮動小数点数の有効数字は約 16 桁であり、丸め誤差や桁落ちが生じる。浮動小数点数は == ではなく np.isclose() で比べる。

  • 条件数 \(\kappa(A) = \sigma_{\max}/\sigma_{\min}\) は、入力の誤差が解で何倍に拡大されるかを表す。行列式の大小では判断できない。

  • 消去法では、部分ピボット選択を行わないと、良条件の問題でも誤差が大きくなることがある。

  • 大規模な問題では、疎行列と反復法を使う。

  • NumPy の行列計算は BLAS と LAPACK を呼び出している。実用ではライブラリの関数を使う。
