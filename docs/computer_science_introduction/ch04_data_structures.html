4. データ構造

プログラムが扱うデータは、メモリ上にどのように並べるかによって、同じ操作でもかかる手間が大きく変わる。この章では、配列、連結リスト、スタックとキュー、ハッシュ表、木、ヒープ、グラフという代表的なデータ構造を取り上げ、それぞれのデータの格納方法と、各操作にかかる計算量を学ぶ。さらに、ハッシュ表と連結リストを組み合わせた LRU キャッシュを例に、複数のデータ構造を組み合わせて目的の計算量を得る考え方を学び、応用的なデータ構造としてトライ、Union-Find、ブルームフィルタを紹介する。また、Python の list、dict、set、collections.deque、heapq がどのデータ構造で実装されているかを知り、日々のコードで適切な型を選べるようになることを目指す。問題を解く手順（アルゴリズム）と計算量の厳密な定義は「アルゴリズムと計算量」で扱う。

4.1. 計算量の表し方

この章では、操作にかかる手間を計算量で表す。計算量は、データの個数 \(n\) が大きくなったときに処理の手間がどのように増えるかを表す尺度である。例えば \(O(n)\) は「手間がおおむね \(n\) に比例して増える」こと、\(O(1)\) は「\(n\) によらず一定の手間で済む」こと、\(O(\log n)\) は「\(n\) が 2 倍になっても手間が一定量しか増えない」ことを表す。この書き方を O 記法と呼ぶ。O 記法の定義と性質は第 5 章の「計算量と O 記法」で詳しく説明するので、ここでは「増え方の目安」として読めば十分である。

以下では、特に断らない限り計算量は最悪の場合の時間計算量を表す。最悪の場合とは、同じ個数のデータのうち最も手間のかかる入力に対する値である。

4.2. 抽象データ型と実装

データ構造を学ぶときには、「どのような操作ができるか」と「それをどのように実現するか」を区別すると見通しが良くなる。前者を抽象データ型（ADT: Abstract Data Type）と呼ぶ。例えば「スタック」は、値を積む操作（push）と、最後に積んだ値を取り出す操作（pop）を持つ抽象データ型である。スタックの利用者は、内部で値がどのように並んでいるかを知らなくてよい。

一方、同じスタックを配列で実現することも、連結リストで実現することもできる。これが実装である。実装が異なれば、各操作の計算量やメモリの使い方が異なる。プログラミング言語でいえば、Java の List インタフェースと ArrayList・LinkedList クラスの関係、Python でいえば collections.abc.Sequence と list・tuple の関係がこれに当たる。

実務でデータ構造を選ぶときは、まず「どの操作を頻繁に行うか」（末尾への追加か、先頭からの取り出しか、キーによる検索か、最小値の取り出しか）を整理し、それらの操作が速い実装を選ぶ。この章の各節は、この観点で読むと理解しやすい。

4.3. 配列

4.3.1. 連続領域とランダムアクセス

配列は、同じ大きさの要素をメモリ上の連続した領域に順に並べたデータ構造である。先頭のアドレスを \(a\)、1 要素の大きさを \(s\) バイトとすると、添字 \(i\) の要素のアドレスは次の式で求まる。

\[a + i \times s\]

この計算は \(i\) の値によらず一定の手間で済むため、配列は任意の位置の要素に \(O(1)\) で読み書きできる。このように位置を指定して直接要素に到達できることをランダムアクセスと呼ぶ。添字が 0 から始まる言語が多いのは、添字が先頭からの距離（オフセット）を表すと考えると、この式が最も簡単になるからである。

連続した領域に並んでいることには、計算量に表れない利点もある。「コンピュータの構成」で見たように、CPU はメモリを一定の大きさの塊（キャッシュライン）単位でキャッシュに読み込む。配列を先頭から順に処理すると、隣の要素がすでにキャッシュに載っている可能性が高く、実際の処理は速くなる。

一方、配列の途中に要素を挿入したり、途中の要素を削除したりするには、それより後ろの要素をすべて 1 つずつずらす必要がある。したがって、挿入・削除の計算量は \(O(n)\) である。また、配列の大きさは確保した時点で決まるため、要素がいくつ入るか分からない用途にはそのままでは使いにくい。

4.3.2. 動的配列と償却計算量

要素数が増えると自動的に領域を広げる配列を動的配列と呼ぶ。動的配列は、実際の要素数より大きめの領域（容量）を確保しておき、末尾への追加では空いている場所に書き込むだけで済ませる。容量が尽きたときは、より大きな領域を新たに確保し、すべての要素をコピーしてから追加する。

コピーが発生する追加は \(O(n)\) かかるが、容量を一定の比率で増やす（例えば 2 倍にする）と、コピーはまれにしか起きない。容量 1 から始めて 2 倍ずつ増やしながら \(n\) 個の要素を追加する場合を考える。コピーが起きるのは、要素数が 1、2、4、…、\(2^k\)（\(2^k < n\)）の状態からさらに追加しようとしたときで、コピーされる要素の総数は次のようになる。

\[1 + 2 + 4 + \cdots + 2^k = 2^{k+1} - 1 < 2n\]

つまり、\(n\) 回の追加全体でコピーの手間は \(2n\) 未満であり、1 回あたりに直すと定数で収まる。このように、一連の操作全体の手間を操作の回数で割って評価した計算量を償却計算量と呼ぶ。動的配列の末尾への追加は、1 回ごとの最悪は \(O(n)\) であるが、償却計算量は \(O(1)\) である。なお、容量を「2 倍」ではなく「10 個ずつ」のように一定数ずつ増やすと、コピーの総数は \(n^2\) に比例してしまい、償却計算量も \(O(n)\) になる。一定の比率で増やすことが重要である。

4.3.3. Python の list

Python の list は動的配列である。CPython の list は、要素のオブジェクトそのものではなく、オブジェクトへの参照（ポインタ）を連続した領域に並べている。そのため、異なる型の値を混在させても、添字による参照は \(O(1)\) で行える。容量の増やし方は 2 倍ではなく、より小さな比率で余裕を持たせる方式であるが、一定の比率で増やす点は同じであり、append() の償却計算量は \(O(1)\) である。

4.4. 連結リスト

連結リストは、値と「次の要素への参照」を組にしたノードを、参照でつないで並べたデータ構造である。各ノードはメモリ上のどこにあってもよく、配列のように連続した領域を必要としない。次の要素への参照だけを持つものを単方向連結リスト、前の要素への参照も持つものを双方向連結リストと呼ぶ。

連結リストでは、位置が分かっているノードの直後に新しいノードを挿入するとき、参照を 2 つ付け替えるだけで済む。後ろの要素をずらす必要がないため、計算量は \(O(1)\) である。一方、添字 \(i\) の要素を得るには先頭から \(i\) 個のノードを順にたどる必要があり、ランダムアクセスは \(O(n)\) かかる。値を探す場合も同様である。また、ノードがメモリ上に散らばるため、配列に比べてキャッシュの効果が得にくく、各ノードが参照を持つ分だけメモリも多く使う。

Python には連結リストの組み込み型は無く、実務で連結リストを自作する機会も少ない。それでも連結リストの考え方は、次節の collections.deque、ハッシュ表のチェイン法、OS のプロセス管理（「オペレーティングシステム」）など、多くの場所で使われている。

4.5. スタックとキュー

スタックは、最後に入れた値を最初に取り出す（LIFO: Last In, First Out）抽象データ型である。関数呼び出しの管理（コールスタック）、括弧の対応の確認、深さ優先探索、エディタの「元に戻す」機能などで使われる。Python では list の append() と pop() がどちらも末尾に対する操作であり、償却 \(O(1)\) で動くため、list をそのままスタックとして使える。

キューは、最初に入れた値を最初に取り出す（FIFO: First In, First Out）抽象データ型である。処理待ちの仕事を到着順にこなす場面（印刷待ち、メッセージキュー、幅優先探索）で使われる。list でキューを作ろうとして pop(0) で先頭から取り出すと、残りの要素をすべてずらすため 1 回ごとに \(O(n)\) かかる。キューには collections.deque を使う。

1from collections import deque
2
3queue: deque[str] = deque()
4queue.append("job1")      # 末尾に追加: O(1)
5queue.append("job2")
6first = queue.popleft()   # 先頭から取り出し: O(1)
7print(first, list(queue))  # job1 ['job2']

deque（double-ended queue、両端キュー）は両端への追加と取り出しがどちらも \(O(1)\) で行える。CPython の deque は、固定長の配列（ブロック）を双方向連結リストでつないだ構造で実装されている。そのため両端の操作は速いが、中央付近の要素への添字アクセスは \(O(n)\) かかる。「両端だけを操作するなら deque、添字で自由にアクセスするなら list」と使い分ける。

4.6. ハッシュ表

4.6.1. ハッシュ関数とバケット

ハッシュ表は、キーから値を平均 \(O(1)\) で検索できるデータ構造である。ハッシュ表は、バケットと呼ぶ格納場所を配列として用意し、キーをバケットの番号に変換してそこに格納する。この変換に使う関数をハッシュ関数と呼ぶ。ハッシュ関数はキーから整数（ハッシュ値）を計算する関数で、バケット数を \(m\) とすると、キー \(k\) を格納するバケットの番号は次のように決める。

\[h(k) \bmod m\]

同じキーからは必ず同じハッシュ値が得られなければならない。また、異なるキーのハッシュ値がなるべく偏らずに散らばるほど良いハッシュ関数である。配列の添字が \(O(1)\) で参照できることと、ハッシュ値の計算の手間がキーの長さだけで決まることから、衝突が少なければ検索は要素数によらない手間で済む。

4.6.2. 衝突の解決

キーの種類はバケット数より多いのが普通なので、異なるキーが同じバケットに割り当てられることは避けられない。これを衝突と呼ぶ。衝突の解決方法には大きく 2 つある。

  • チェイン法: 各バケットにリスト（連結リストや動的配列）を持たせ、同じバケットに割り当てられたキーをそのリストに並べる。検索ではバケットを決めた後、リストの中を順に比較する。

  • オープンアドレス法: すべての要素をバケットの配列に直接格納する。割り当てられたバケットが埋まっていたら、決められた規則で別のバケットを順に調べ（探査）、空いている場所に格納する。最も簡単な規則は隣のバケットを順に調べる線形探査である。削除した場所を単に空にすると、その先に格納された要素が探査で見つからなくなるため、「削除済み」の印を残す必要がある。

4.6.3. 負荷率と再ハッシュ

格納している要素数を \(n\)、バケット数を \(m\) とするとき、\(\alpha = n / m\) を負荷率と呼ぶ。チェイン法では 1 つのバケットに平均 \(\alpha\) 個の要素が並ぶので、ハッシュ値が一様に散らばると仮定すると、検索の平均の手間は \(O(1 + \alpha)\) になる [CLRS]。負荷率が一定値を超えたらバケット数を増やして全要素を入れ直す（再ハッシュする）ことで、\(\alpha\) を定数以下に保ち、平均 \(O(1)\) を維持する。再ハッシュは \(O(n)\) かかるが、動的配列と同じくバケット数を一定の比率で増やせば、挿入の償却計算量は \(O(1)\) になる。

ただし、これは平均の話である。すべてのキーが同じバケットに集まると、検索は \(O(n)\) に悪化する。攻撃者が意図的に衝突するキーを大量に送り込んでサーバを遅くする攻撃（ハッシュフラッディング）も知られており、Python は文字列のハッシュ値の計算に、プロセスごとに変わる乱数を混ぜることでこれを防いでいる。そのため、同じ文字列でも hash() の値は実行のたびに変わる。

4.6.4. チェイン法による実装

チェイン法のハッシュ表を実装した例を次に示す。結果を再現できるよう、組み込みの hash() ではなく自作のハッシュ関数 simple_hash() を使い、負荷率が 1 を超えたらバケット数を 2 倍にする。

ch04_hash_table.py
 1"""チェイン法によるハッシュ表のサンプル。
 2
 3各バケットをリストとして持ち、同じバケットに入る（衝突した）キーを
 4そのリストにつなげて格納する。負荷率が 1 を超えたらバケット数を 2 倍に
 5して全要素を入れ直す（再ハッシュ）。
 6
 7Python の組み込みの hash() は、文字列に対しては実行のたびに値が変わる
 8（ハッシュのランダム化）ため、ここでは結果を再現できるよう簡単な
 9ハッシュ関数を自作している。
10
11実行方法: python ch04_hash_table.py
12関連する章: 第 4 章「データ構造」
13"""

16def simple_hash(key: str) -> int:
17    """文字列から 32 ビットの整数を計算する簡単なハッシュ関数。"""
18    h = 0
19    for ch in key:
20        h = (h * 31 + ord(ch)) % 2**32
21    return h
22
23
24class ChainedHashTable:
25    """文字列のキーと整数の値を格納するチェイン法のハッシュ表。"""
26
27    def __init__(self, capacity: int = 4) -> None:
28        """指定した数の空のバケットを用意する。"""
29        self.buckets: list[list[tuple[str, int]]] = [
30            [] for _ in range(capacity)
31        ]
32        self.count = 0
33
34    def _index(self, key: str) -> int:
35        """キーが入るバケットの番号を求める。"""
36        return simple_hash(key) % len(self.buckets)
37
38    def load_factor(self) -> float:
39        """負荷率（要素数 / バケット数）を返す。"""
40        return self.count / len(self.buckets)
41
42    def put(self, key: str, value: int) -> None:
43        """キーと値を格納する。キーが既にあれば値を上書きする。"""
44        bucket = self.buckets[self._index(key)]
45        for i, (k, _) in enumerate(bucket):
46            if k == key:
47                bucket[i] = (key, value)
48                return
49        bucket.append((key, value))
50        self.count += 1
51        if self.load_factor() > 1.0:
52            self._resize(2 * len(self.buckets))
53
54    def get(self, key: str) -> int | None:
55        """キーに対応する値を返す。無ければ None を返す。"""
56        for k, v in self.buckets[self._index(key)]:
57            if k == key:
58                return v
59        return None
60
61    def _resize(self, new_capacity: int) -> None:
62        """バケット数を変えて、すべての要素を入れ直す。"""
63        print(f"  -- 再ハッシュ: バケット数 {len(self.buckets)}"
64              f" -> {new_capacity}")
65        old_items = [item for bucket in self.buckets for item in bucket]
66        self.buckets = [[] for _ in range(new_capacity)]
67        for k, v in old_items:
68            self.buckets[self._index(k)].append((k, v))
69
70    def dump(self) -> None:
71        """各バケットの中身を表示する。"""
72        for i, bucket in enumerate(self.buckets):
73            keys = [k for k, _ in bucket]
74            print(f"  バケット {i}: {keys}")
75        print(f"  要素数 {self.count}, 負荷率 {self.load_factor():.2f}")
76
77
78def main() -> None:
79    """ハッシュ表に値を格納し、内部の状態と検索結果を表示する。"""
80    table = ChainedHashTable()
81    stock = {"apple": 3, "banana": 5, "cherry": 7, "grape": 2,
82             "lemon": 4, "melon": 1}
83    for name, qty in stock.items():
84        print(f"put({name!r}) ハッシュ値 {simple_hash(name)}")
85        table.put(name, qty)
86    print("最終状態:")
87    table.dump()
88    print("get('cherry') =", table.get("cherry"))
89    print("get('peach') =", table.get("peach"))
90

4.6.5. Python の dict と set

Python の dict と set はハッシュ表である。CPython はオープンアドレス法を採用しており、探査の順序はハッシュ値の上位ビットも使って決めることで、線形探査より偏りにくくしている。キーによる参照・追加・削除と x in d は平均 \(O(1)\)、最悪 \(O(n)\) である。また、Python 3.7 以降の dict は挿入した順序を保つことが言語仕様として保証されている [PythonDocs]。

dict のキーや set の要素にできるのは、ハッシュ可能な（__hash__() を持ち、値が変化しない）オブジェクトに限られる。list をキーにできないのは、格納した後に中身が変わるとハッシュ値も変わり、格納したバケットから見つけられなくなるからである。自作クラスで __eq__() を定義する場合は、「等しいオブジェクトは等しいハッシュ値を持つ」ように __hash__() も定義しなければならない。

4.6.6. 実務での使い分け: 二重ループを避ける

2 つのデータを突き合わせる処理は、実務で頻繁に現れる。次のコードは、注文の一覧から、有効な会員による注文だけを取り出す。

1active_ids: list[int] = load_active_member_ids()  # 会員 m 人
2orders: list[tuple[int, int]] = load_orders()      # 注文 n 件
3
4# 遅い: in が list を先頭から調べるので全体で O(nm)
5valid = [o for o in orders if o[0] in active_ids]
6
7# 速い: set に変換すれば in は平均 O(1) で、全体で O(n + m)

9valid = [o for o in orders if o[0] in active_set]

5 行目は for が 1 つしか無いように見えるが、in の中に隠れたループがあるため、実質は二重ループである。会員が 1 万人、注文が 10 万件なら、最悪で \(10^9\) 回程度の比較になる。8 行目で set に変換すると、変換に \(O(m)\)、検索が 1 件あたり平均 \(O(1)\) で済む。データベースが索引を使って検索を高速化するのも、同じ発想である（「データベース」）。

4.7. 木

4.7.1. 用語

木は、ノードとそれらを結ぶ親子関係からなり、階層構造を表すデータ構造である。ファイルシステムのフォルダ、HTML の DOM、組織図、プログラムの構文木など、身の回りの多くのデータが木の形をしている。木に関する基本的な用語を次の表にまとめる。

4.7.2. 二分探索木

二分探索木は、すべてのノードについて「左の部分木のキーはすべてそのノードのキーより小さく、右の部分木のキーはすべて大きい」という性質を満たす二分木である。キーを探すときは根から始め、探すキーが小さければ左へ、大きければ右へ進む。1 回の比較ごとに一方の部分木を候補から外せるので、比較の回数は木の高さ \(h\) 以下であり、探索・挿入・削除の計算量は \(O(h)\) である。

また、二分探索木を「左の部分木、自分、右の部分木」の順に走査（中間順の走査）すると、キーが小さい順に得られる。ハッシュ表ではキーの順序が失われるが、二分探索木では「ある範囲のキーをすべて列挙する」「指定したキー以上で最小のキーを求める」といった順序に基づく操作もできる。

二分探索木を実装した例を次に示す。木の形が深くなっても Python の再帰の上限に達しないよう、再帰を使わずにループで書いている。

ch04_bst.py
  1"""二分探索木のサンプル。
  2
  3挿入・探索・中間順の走査を実装し、同じ値の集合でも挿入する順序によって
  4木の高さが大きく変わることを示す。整列済みの順に挿入すると木は一直線に
  5なり、探索が連結リストと同じ O(n) になる。
  6
  7実行方法: python ch04_bst.py
  8関連する章: 第 4 章「データ構造」
  9"""
 10
 11from __future__ import annotations
 12
 13import random
 14from dataclasses import dataclass
 15
 16
 17@dataclass
 18class TreeNode:
 19    """二分探索木のノード。左の子孫は key より小さく、右の子孫は大きい。"""
 20
 21    key: int
 22    left: TreeNode | None = None
 23    right: TreeNode | None = None
 24
 25
 26class BinarySearchTree:
 27    """重複しない整数のキーを格納する（平衡化しない）二分探索木。"""
 28
 29    def __init__(self) -> None:
 30        """空の木を作る。"""
 31        self.root: TreeNode | None = None
 32
 33    def insert(self, key: int) -> None:
 34        """キーを挿入する。根から比較しながら下り、空いた位置に置く。"""
 35        if self.root is None:
 36            self.root = TreeNode(key)
 37            return
 38        node = self.root
 39        while True:
 40            if key < node.key:
 41                if node.left is None:
 42                    node.left = TreeNode(key)
 43                    return
 44                node = node.left
 45            elif key > node.key:
 46                if node.right is None:
 47                    node.right = TreeNode(key)
 48                    return
 49                node = node.right
 50            else:
 51                return  # 既にあるキーは挿入しない
 52
 53    def search(self, key: int) -> int:
 54        """キーを探し、比較したノードの数を返す（見つからなければ負の値）。"""
 55        node = self.root
 56        visited = 0
 57        while node is not None:
 58            visited += 1
 59            if key == node.key:
 60                return visited
 61            node = node.left if key < node.key else node.right
 62        return -visited
 63
 64    def inorder(self) -> list[int]:
 65        """中間順（左の子孫、自分、右の子孫）に走査したキーの列を返す。"""
 66        result: list[int] = []
 67        stack: list[TreeNode] = []
 68        node = self.root
 69        while stack or node is not None:
 70            while node is not None:
 71                stack.append(node)
 72                node = node.left
 73            node = stack.pop()
 74            result.append(node.key)
 75            node = node.right
 76        return result
 77
 78    def height(self) -> int:
 79        """木の高さ（根から最も深い葉までのノード数）を返す。"""
 80        best = 0
 81        stack: list[tuple[TreeNode | None, int]] = [(self.root, 1)]
 82        while stack:
 83            node, depth = stack.pop()
 84            if node is not None:
 85                best = max(best, depth)
 86                stack.append((node.left, depth + 1))
 87                stack.append((node.right, depth + 1))
 88        return best
 89

 92    """キーを与えられた順に挿入した木を作る。"""
 93    tree = BinarySearchTree()
 94    for k in keys:
 95        tree.insert(k)
 96    return tree

4.7.3. 平衡木の必要性

実行結果から分かるように、二分探索木の高さは挿入の順序によって大きく変わる。1023 個のノードをすき間なく詰めた二分木の高さは 10 であり、一般に \(n\) 個のノードを持つ二分木の高さは少なくとも \(\lceil \log (n+1) \rceil\) である。ランダムな順に挿入すると高さは \(O(\log n)\) 程度に収まることが知られており、この例でも 24 にとどまった。一方、整列済みの順に挿入すると、新しいキーは常に右の子になり、木は一直線に伸びて高さが \(n\) になる。これは連結リストと同じ形であり、探索は \(O(n)\) かかる。実務のデータは、日付順や ID 順のようにすでに整列していることが多いため、この最悪の場合は決して珍しくない。

そこで、挿入や削除のたびに木の形を調整し、高さを常に \(O(\log n)\) に保つ二分探索木が考案されている。これを平衡木と呼ぶ。代表的なものに AVL 木と赤黒木があり、どちらも回転と呼ぶ局所的な付け替えによって左右の偏りを直す。平衡木では探索・挿入・削除が最悪でも \(O(\log n)\) で行える。Java の TreeMap は赤黒木で実装されており、C++ の std::map も一般的な処理系では赤黒木で実装されている。また、データベースの索引で広く使われる B 木（B+ 木）は、1 つのノードに多数のキーを持たせて高さを低くした平衡木で、補助記憶からの読み込み回数を減らすよう工夫されている。平衡化の具体的な手順は本書では扱わないので、詳しくは [CLRS] を参照。

Python の標準ライブラリには平衡木が無い。順序付きのデータを扱いたい場合は、整列済みの list に対して bisect モジュールで二分探索する方法がよく使われる（「アルゴリズムと計算量」）。

4.8. ヒープと優先度付きキュー

優先度付きキューは、値を追加する操作と、最も優先度の高い（例えば最小の）値を取り出す操作を持つ抽象データ型である。タスクのスケジューリング、イベント駆動のシミュレーション、次章で扱うダイクストラ法などで使われる。整列済みの配列で実現すると取り出しは速いが追加が \(O(n)\)、整列していない配列では追加は速いが取り出しが \(O(n)\) になる。両方を \(O(\log n)\) で行えるのがヒープである。

ここでいうヒープ（二分ヒープ）は、次の 2 つの性質を満たす二分木である。なお、プログラムが動的に確保するメモリ領域も「ヒープ」と呼ぶが、それとは無関係である。

  • 形の性質: 最下段以外はすべて埋まっており、最下段は左から詰めて並ぶ（完全二分木）。

  • 順序の性質: どのノードも、その子以下の値を持つ（最小ヒープの場合）。したがって根が最小値である。

完全二分木はすき間が無いので、ノードを上の段から左から順に配列に並べれば、参照を持たずに表せる。添字 \(i\) のノードの子は \(2i+1\) と \(2i+2\)、親は \(\lfloor (i-1)/2 \rfloor\) の位置にある。値を追加するときは配列の末尾に置き、親より小さい間は親と交換していく（上方移動）。最小値を取り出すときは、根を取り除いて末尾の値を根に移し、子のうち小さい方より大きい間は交換していく（下方移動）。どちらも木の高さ \(O(\log n)\) 回の交換で済む。

二分ヒープを自作し、標準ライブラリの heapq と比較した例を次に示す。

ch04_heap.py
 1"""二分ヒープ（最小ヒープ）のサンプル。
 2
 3配列で表した二分ヒープを自作し、標準ライブラリの heapq と同じ順序で
 4値を取り出せることを確かめる。後半では heapq を優先度付きキューとして
 5使う。
 6
 7実行方法: python ch04_heap.py
 8関連する章: 第 4 章「データ構造」
 9"""
10
11import heapq
12import random
13
14
15class MinHeap:
16    """最小の値を常に先頭（添字 0）に置く二分ヒープ。
17
18    添字 i のノードの子は 2i+1 と 2i+2、親は (i-1)//2 である。
19    """
20
21    def __init__(self) -> None:
22        """空のヒープを作る。"""
23        self.data: list[int] = []
24
25    def push(self, value: int) -> None:
26        """値を末尾に追加し、親より小さい間は親と交換する（上方移動）。"""
27        self.data.append(value)
28        i = len(self.data) - 1
29        while i > 0:
30            parent = (i - 1) // 2
31            if self.data[parent] <= self.data[i]:
32                break
33            self.data[parent], self.data[i] = self.data[i], self.data[parent]
34            i = parent
35
36    def pop(self) -> int:
37        """最小値を取り出す。末尾の値を根に移し、下方移動で整える。"""
38        top = self.data[0]

43        return top

47        n = len(self.data)
48        while True:
49            smallest = i
50            for child in (2 * i + 1, 2 * i + 2):
51                if child < n and self.data[child] < self.data[smallest]:
52                    smallest = child
53            if smallest == i:
54                return
55            self.data[i], self.data[smallest] = (
56                self.data[smallest], self.data[i])
57            i = smallest
58
59    def __len__(self) -> int:
60        """格納している値の数を返す。"""
61        return len(self.data)

4.9. グラフの表現

グラフは、頂点の集合と、頂点同士を結ぶ辺の集合からなるデータ構造である。鉄道の路線図（駅が頂点、線路が辺）、SNS のフォロー関係、Web ページのリンク、パッケージの依存関係、ネットワークの経路など、「ものとものの関係」を表すあらゆる場面で使われる。辺に向きがあるものを有向グラフ、無いものを無向グラフと呼ぶ。また、辺に距離や費用などの数値（重み）を持たせたものを重み付きグラフと呼ぶ。木は、閉路（同じ頂点に戻ってくる経路）を持たない連結なグラフの一種である。

頂点数を \(V\)、辺数を \(E\) とする。グラフをプログラムで表す代表的な方法は次の 2 つである。

  • 隣接行列: \(V \times V\) の 2 次元配列を用意し、頂点 \(u\) から \(v\) への辺があれば \(u\) 行 \(v\) 列を 1（重み付きなら重み）、無ければ 0 にする。

  • 隣接リスト: 頂点ごとに、辺でつながった頂点の一覧を持つ。Python では dict[str, list[str]] のように辞書とリストで表すのが手軽である。

例えば、頂点 A、B、C があり、A と B、A と C が辺で結ばれた無向グラフは、隣接リストでは次のように表せる。

1graph: dict[str, list[str]] = {
2    "A": ["B", "C"],
3    "B": ["A"],
4    "C": ["A"],
5}

4.10. LRU キャッシュ: データ構造を組み合わせる

4.10.1. LRU キャッシュに求められる操作

ここまでのデータ構造は、それぞれ得意な操作と苦手な操作を持っていた。実務では、複数のデータ構造を組み合わせて、どれか 1 つでは実現できない計算量を得ることがよくある。その代表例が LRU キャッシュである。

キャッシュは、計算や読み込みに時間のかかる結果を手元に保存しておき、次に同じものを求められたときに再利用する仕組みである。保存できる量には限りがあるので、いっぱいになったら何かを捨てなければならない。このとき「最も長い間使われていないもの」を捨てる方式を LRU（Least Recently Used）と呼び、この方式で管理するキャッシュを LRU キャッシュと呼ぶ。最近使われたものはまたすぐ使われやすい、という時間的局所性を前提にした方式である。第 3 章の「コンピュータの構成」で見た CPU のキャッシュも、セットアソシアティブ方式でセットが埋まったときにどのラインを追い出すかを決める必要があり、LRU やそれを簡略化した方式が使われている。主記憶が足りないときにどのページを補助記憶に追い出すかという OS のページ置換（「オペレーティングシステム」）でも、同じ考え方が使われる。ハードウェアでは厳密な LRU の管理は回路が大きくなるため近似で済ませることが多いが、ソフトウェアでは次に述べる方法で厳密な LRU を効率よく実現できる。

LRU キャッシュには次の操作が必要である。

  • 取得: キーに対応する値を返し、そのキーを「最も最近使われた」ものとして記録する。

  • 追加: キーと値を格納し、そのキーを「最も最近使われた」ものとする。容量を超えたら、最も長い間使われていないキーを追い出す。

キーによる検索だけならハッシュ表で平均 \(O(1)\) であるが、ハッシュ表は使われた順序を記録しない。一方、使われた順にキーを並べたリストを持てば、追い出す対象は先頭を見るだけで分かるが、取得のたびにそのキーをリストから探して末尾に移すと \(O(n)\) かかる。

4.10.2. ハッシュ表と双方向連結リストの組み合わせ

そこで、使われた順にキーを並べた双方向連結リストと、キーからそのリストのノードへの参照を引くハッシュ表を組み合わせる。リストの先頭は最も長い間使われていないキー、末尾は最も最近使われたキーである。

  • 取得: ハッシュ表でキーからノードを平均 \(O(1)\) で見つける。そのノードをリストから外して末尾につなぎ直す操作は、前後のノードの参照を付け替えるだけなので \(O(1)\) である。

  • 追加: 新しいノードを末尾につなぎ、ハッシュ表に登録する。容量を超えたら、先頭のノードをリストから外し、そのキーをハッシュ表からも削除する。どちらも \(O(1)\) である。

単方向連結リストでは、あるノードを外すために 1 つ前のノードを先頭からたどって探す必要があり、\(O(n)\) かかってしまう（「連結リスト」の節の実行結果で、末尾の削除に時間がかかったのと同じ理由である）。各ノードが前のノードへの参照も持つ双方向連結リストにすることで、ハッシュ表から直接たどり着いたノードを \(O(1)\) で外せる。ハッシュ表が「どこにあるか」を、連結リストが「どの順序か」を受け持つことで、取得と追加の両方が平均 \(O(1)\) になる。

4.10.3. OrderedDict による実装

Python の collections.OrderedDict は、まさにこの組み合わせで実装された辞書であり、キーの順序を保ったまま、指定したキーを末尾に移す move_to_end() と、先頭（または末尾）の要素を取り出す popitem() を \(O(1)\) で行える [PythonDocs]。通常の dict も挿入順を保つが、既存のキーを末尾に移す操作を持たないため、LRU キャッシュには OrderedDict が適している。OrderedDict を使った LRU キャッシュの例を次に示す。

4.10.4. functools.lru_cache

関数の結果をキャッシュするだけなら、自分で実装する必要はない。標準ライブラリの functools.lru_cache デコレータを関数に付けると、引数をキーとし、戻り値を値とする LRU キャッシュが自動的に用意される。maxsize で容量を指定し（既定は 128）、cache_info() でヒット（キャッシュにあった回数）とミス（実際に計算した回数）を確認できる。サンプルの 47〜50 行目では容量 2 の square() を定義し、引数 1、2、1、3、2 の順に呼び出している。3 回目の 1 はヒットするが、4 回目の 3 で最も長い間使われていない 2 が追い出されるので、5 回目の 2 は再びミスになる。実行結果の 9 行目の hits=1, misses=4 はこの動作を表している。

第 5 章の「アルゴリズムと計算量」で使う functools.cache は、容量に上限の無い lru_cache(maxsize=None) と同じものである。メモ化のように同じ引数が繰り返し現れることが分かっている場合は cache で十分であるが、Web アプリケーションで外部への問い合わせ結果を保存するような、引数の種類に際限が無い場面では、lru_cache で容量を制限しないとメモリを使い果たすおそれがある。なお、キャッシュのキーにするため、引数はハッシュ可能でなければならない。

4.11. 応用的なデータ構造

ここまでの基本的なデータ構造を土台に、特定の操作に特化したデータ構造が数多く考案されている。この節では、実務でよく出会う 3 つ、トライ、Union-Find、ブルームフィルタを紹介する。なお、補助記憶上の大量のデータを扱うための平衡木である B 木（B+ 木）は、データベースの索引として第 11 章の「データベース」で扱う。

4.11.1. トライ

トライ（trie、接頭辞木とも呼ぶ）は、文字列の集合を、文字を 1 つずつたどる木として表すデータ構造である。根から下向きの各辺に 1 文字が対応し、根からあるノードまでたどった文字を並べると、そのノードが表す文字列になる。単語の終わりに当たるノードには印を付けておく。例えば car、card、care、cat を格納すると、4 つの単語は根から c、a までの経路を共有し、そこから r と t に分かれる。

トライで文字列を探すには、根から 1 文字ずつ子をたどればよい。各ノードの子をハッシュ表で持てば、1 文字あたり平均 \(O(1)\) で次のノードに進めるので、長さ \(L\) の文字列の検索・挿入は \(O(L)\) であり、格納している単語の数によらない。トライの最大の特徴は接頭辞検索が得意なことである。ある接頭辞で始まる単語をすべて求めるには、接頭辞の文字をたどって着いたノードの下にある単語を列挙すればよく、手間は接頭辞の長さと結果の量で決まる。ハッシュ表では、接頭辞が同じキーがどこに格納されているかに規則が無いので、すべてのキーを調べるしかない。

この性質から、トライは検索窓のオートコンプリート（入力途中の文字列から候補を示す機能）、辞書や綴りの検査、ルータの経路表で宛先 IP アドレスに最も長く一致する経路を選ぶ処理（最長一致、「コンピュータネットワーク」）などに使われる。一方、1 文字ごとにノードを作るのでメモリを多く使う。子が 1 つしかないノードの連なりを 1 つの辺にまとめた基数木（パトリシア木）は、この無駄を減らした変種である。

4.11.2. Union-Find

Union-Find（素集合データ構造）は、要素を互いに重ならないグループ（素集合）に分けて管理し、次の 2 つの操作を高速に行うデータ構造である。

  • find: 要素が属するグループの代表を返す。2 つの要素の代表が等しければ、同じグループに属する。

  • union: 2 つの要素が属するグループを 1 つに併合する。

グラフに辺を 1 本ずつ加えながら「頂点 \(u\) と \(v\) はつながっているか」を判定する問題は、Union-Find で効率よく解ける。辺 \((u, v)\) を加えるたびに union(u, v) を行えば、各グループがそのときの連結成分（互いに経路でつながった頂点の集まり）になる。ネットワークの機器の接続状況の把握、画像の同じ色の領域の検出、最小全域木を求めるクラスカル法の閉路判定などに使われる。

Union-Find は、各グループを 1 本の木で表し、木の根をグループの代表とする。各要素は親への参照だけを持てばよいので、要素を 0 から \(n-1\) の整数とすれば、親を格納する配列 1 つで表せる。find は親をたどって根を求め、union は一方の根をもう一方の根の子にする。このままでは木が一直線に伸びて find が \(O(n)\) かかることがあるので、次の 2 つの工夫を組み合わせる。

  • ランクによる併合: 各根に木の高さの上限（ランク）を記録し、union ではランクの低い木の根を、ランクの高い木の根の子にする。これにより木の高さは \(O(\log n)\) に抑えられる。

  • 経路圧縮: find で根までたどった後、途中のすべての要素の親を根に付け替える。次に同じ要素で find すると、1 回で根に着く。

両方を組み合わせると、\(m\) 回の操作全体の手間は \(O(m \, \alpha(n))\) になることが知られている [CLRS]。ここで \(\alpha(n)\) は逆アッカーマン関数と呼ばれる、極めてゆっくり増える関数で、宇宙に存在する原子の数ほどの \(n\) に対しても 4 を超えない。したがって、実用上は 1 回の操作の償却計算量が「ほぼ定数」であると考えてよい。ただし、Union-Find は併合しかできず、一度併合したグループを分ける操作は効率よく行えない。

  1"""トライと Union-Find のサンプル。
  2
  3前半では、単語をトライに格納し、接頭辞で始まる単語を列挙する
  4（オートコンプリートの基本となる操作）。後半では、Union-Find
  5（素集合データ構造）で辺を順に併合し、頂点同士が連結かを判定する。
  6

  8関連する章: 第 4 章「データ構造」

 10
 11
 12class TrieNode:
 13    """トライのノード。子ノードを文字ごとに辞書で持つ。"""
 14
 15    def __init__(self) -> None:
 16        """子を持たず、単語の終わりでないノードを作る。"""
 17        self.children: dict[str, TrieNode] = {}
 18        self.is_word = False
 19
 20
 21class Trie:
 22    """文字列の集合を格納するトライ。"""
 23
 24    def __init__(self) -> None:
 25        """根だけを持つ空のトライを作る。"""
 26        self.root = TrieNode()
 27
 28    def insert(self, word: str) -> None:
 29        """単語を 1 文字ずつたどり、無いノードは作りながら格納する。"""
 30        node = self.root
 31        for ch in word:
 32            node = node.children.setdefault(ch, TrieNode())
 33        node.is_word = True
 34
 35    def starts_with(self, prefix: str) -> list[str]:
 36        """接頭辞 prefix で始まる単語を辞書順にすべて返す。"""
 37        node = self.root
 38        for ch in prefix:  # 接頭辞の長さだけたどる
 39            if ch not in node.children:
 40                return []
 41            node = node.children[ch]
 42        result: list[str] = []
 43        self._collect(node, prefix, result)
 44        return result
 45
 46    def _collect(self, node: TrieNode, path: str, out: list[str]) -> None:
 47        """node 以下の単語を深さ優先で out に集める。"""
 48        if node.is_word:
 49            out.append(path)
 50        for ch in sorted(node.children):
 51            self._collect(node.children[ch], path + ch, out)
 52
 53
 54class UnionFind:
 55    """経路圧縮とランクによる併合を行う Union-Find。"""
 56
 57    def __init__(self, n: int) -> None:
 58        """0 から n-1 までの要素を、それぞれ 1 要素の集合として作る。"""
 59        self.parent = list(range(n))
 60        self.rank = [0] * n
 61
 62    def find(self, x: int) -> int:
 63        """x が属する集合の代表（根）を返し、経路を圧縮する。"""
 64        root = x
 65        while self.parent[root] != root:
 66            root = self.parent[root]
 67        while self.parent[x] != root:  # たどった要素を根に直接つなぐ
 68            self.parent[x], x = root, self.parent[x]
 69        return root
 70
 71    def union(self, a: int, b: int) -> bool:
 72        """a と b の集合を併合する。すでに同じ集合なら False を返す。"""
 73        ra, rb = self.find(a), self.find(b)
 74        if ra == rb:
 75            return False
 76        if self.rank[ra] < self.rank[rb]:  # 低い木を高い木の下につなぐ
 77            ra, rb = rb, ra
 78        self.parent[rb] = ra
 79        if self.rank[ra] == self.rank[rb]:
 80            self.rank[ra] += 1
 81        return True
 82

 85    """トライの接頭辞検索と Union-Find の連結判定を実行する。"""

 96        status = "併合した" if merged else "すでに連結（閉路になる辺）"
 97        print(f"辺 ({a}, {b}): {status}")
 98    for a, b in [(0, 3), (0, 4), (4, 5)]:
 99        print(f"{a} と {b} は連結か: {uf.find(a) == uf.find(b)}")
100    groups: dict[int, list[int]] = {}
101    for v in range(6):
102        groups.setdefault(uf.find(v), []).append(v)
103    print(f"連結成分: {list(groups.values())}")

4.11.4. ブルームフィルタ

ブルームフィルタは、「ある要素が集合に含まれるか」を、ごく少ないメモリで判定するデータ構造である [Bloom1970]。ハッシュ表と違って要素そのものを格納しないので、要素がどれほど長くても、1 要素あたり数ビットから十数ビットで済む。その代わり、判定に誤りが生じることを許す。

ブルームフィルタは、\(m\) ビットのビット配列（初期値はすべて 0）と、\(k\) 個の異なるハッシュ関数からなる。各ハッシュ関数は、要素を 0 から \(m-1\) のビット位置に対応付ける。

  • 追加: 要素の \(k\) 個のハッシュ値が示すビットをすべて 1 にする。

  • 判定: 要素の \(k\) 個のビットを調べ、1 つでも 0 があれば「含まれない」、すべて 1 なら「含まれるかもしれない」と答える。

追加した要素のビットは必ず 1 になっているので、追加した要素を「含まれない」と誤ること（偽陰性）は決して無い。一方、追加していない要素でも、その \(k\) 個のビットがたまたま他の要素によってすべて 1 にされていれば、「含まれるかもしれない」と答えてしまう。これを偽陽性と呼ぶ。また、あるビットが複数の要素で共有されているかもしれないので、ビットを 0 に戻して要素を削除することはできない。

\(n\) 個の要素を追加した後の偽陽性率は、次のように見積もれる。ハッシュ値が一様に散らばると仮定すると、1 回のビットの設定で特定のビットが 1 にならない確率は \(1 - 1/m\) であり、\(kn\) 回の設定の後もそのビットが 0 のままである確率は \((1 - 1/m)^{kn} \approx e^{-kn/m}\) である。追加していない要素の \(k\) 個のビットがすべて 1 である確率、つまり偽陽性率は、おおよそ次の式で表せる。

\[\left(1 - e^{-kn/m}\right)^k\]

ハッシュ関数を増やす（\(k\) を大きくする）と、判定で調べるビットが増えて偽陽性になりにくくなる一方、1 にするビットも増えて配列が埋まりやすくなる。この 2 つの効果がつり合う \(k = (m/n) \ln 2\) のとき、偽陽性率は最小になる。

ブルームフィルタは「含まれない」と分かれば高価な処理を省ける場面で使われる。例えば、多くのキーバリューストアは、補助記憶上のファイルごとにブルームフィルタを主記憶に持ち、目的のキーが無いことが分かったファイルは読まずに済ませる。偽陽性で無駄な読み込みが起きることはあるが、結果が誤ることはない。他にも、Web のクローラが訪問済みの URL を記録する処理や、キャッシュに入れる価値のある（2 回以上要求された）データの選別などに使われる。

ブルームフィルタを実装し、偽陽性率を実測した例を次に示す。結果が毎回同じになるよう、ハッシュ値は組み込みの hash()（文字列に対しては実行のたびに値が変わる）ではなく、hashlib の SHA-256 から計算している。

ch04_bloom_filter.py
 1"""ブルームフィルタのサンプル。
 2
 3m ビットのビット配列と k 個のハッシュ関数を使うブルームフィルタを実装し、
 4n 個の要素を追加した後、追加していない要素で偽陽性率を実測して
 5理論値の近似 (1 - e^(-kn/m))^k と比較する。
 6
 7結果を再現できるよう、ハッシュ値は hashlib.sha256 から計算する
 8（組み込みの hash() は文字列に対して実行のたびに値が変わるため使わない）。
 9
10実行方法: python ch04_bloom_filter.py
11関連する章: 第 4 章「データ構造」
12"""
13
14import hashlib
15import math
16
17
18class BloomFilter:
19    """文字列の集合を表すブルームフィルタ。"""
20
21    def __init__(self, m: int, k: int) -> None:
22        """m ビットのビット配列と k 個のハッシュ関数を持つフィルタを作る。"""
23        self.m = m
24        self.k = k
25        self.bits = bytearray((m + 7) // 8)  # 全ビット 0 で始める
26
27    def _positions(self, item: str) -> list[int]:
28        """item に対する k 個のビット位置を返す。
29
30        SHA-256 の値から 2 つの 64 ビット整数 h1, h2 を取り出し、
31        h1 + i * h2 (i = 0, 1, ..., k-1) で k 個のハッシュ値を作る。
32        """
33        digest = hashlib.sha256(item.encode("utf-8")).digest()
34        h1 = int.from_bytes(digest[:8], "big")
35        h2 = int.from_bytes(digest[8:16], "big") | 1
36        return [(h1 + i * h2) % self.m for i in range(self.k)]
37
38    def add(self, item: str) -> None:
39        """item の k 個の位置のビットを 1 にする。"""
40        for p in self._positions(item):
41            self.bits[p // 8] |= 1 << (p % 8)
42
43    def might_contain(self, item: str) -> bool:
44        """k 個の位置がすべて 1 なら True（含むかもしれない）を返す。"""
45        return all(
46            self.bits[p // 8] & (1 << (p % 8)) for p in self._positions(item)
47        )
48
49
50def theoretical_rate(m: int, n: int, k: int) -> float:
51    """偽陽性率の近似値 (1 - e^(-kn/m))^k を返す。"""
52    return (1 - math.exp(-k * n / m)) ** k
53
54
55def main() -> None:
56    """いくつかの k について偽陽性率を実測し、理論値と比べる。"""
57    m, n, trials = 10_000, 1_000, 100_000
58    members = [f"user{i}" for i in range(n)]
59    others = [f"guest{i}" for i in range(trials)]  # 追加しない要素
60    print(f"m = {m} ビット, n = {n} 個, 確認する非要素 {trials} 個")
61    for k in [1, 3, 7, 10]:
62        bf = BloomFilter(m, k)
63        for item in members:
64            bf.add(item)
65        missed = sum(not bf.might_contain(x) for x in members)
66        false_pos = sum(bf.might_contain(x) for x in others)
67        measured = false_pos / trials
68        expected = theoretical_rate(m, n, k)
69        print(
70            f"k = {k:2d}: 偽陰性 {missed} 個, 偽陽性率 実測 {measured:.4f}"
71            f" 理論 {expected:.4f}"
72        )
73    best_k = m / n * math.log(2)
74    print(f"偽陽性率を最小にする k は約 {best_k:.1f}")
75    print(f"ビット配列の大きさ: {len(BloomFilter(m, 1).bits)} バイト")
76
77
78if __name__ == "__main__":
79    main()

4.13. まとめ

  • 抽象データ型は「どのような操作ができるか」を定め、実装は「それをどう実現するか」を定める。同じ抽象データ型でも実装によって各操作の計算量が異なる。

  • 配列は連続した領域に要素を並べ、添字による参照が \(O(1)\) である。途中への挿入・削除は \(O(n)\) かかる。

  • 動的配列は容量を一定の比率で増やすことで、末尾への追加を償却 \(O(1)\) にしている。Python の list は動的配列であり、pop(0) や x in a は \(O(n)\) である。

  • 連結リストは位置が分かっていれば挿入・削除が \(O(1)\) であるが、添字による参照や検索は \(O(n)\) かかる。

  • スタックは LIFO、キューは FIFO の抽象データ型である。Python ではスタックに list、キューに collections.deque を使う。

  • ハッシュ表はハッシュ関数でキーをバケットに割り当て、検索・挿入・削除を平均 \(O(1)\) で行う。衝突はチェイン法かオープンアドレス法で解決し、負荷率を一定以下に保つ。Python の dict と set はハッシュ表である。

  • ループの中で list に in を使うと隠れた二重ループになる。検索を繰り返すなら set や dict に変換する。

  • 二分探索木の操作は木の高さに比例する。挿入順によっては高さが \(n\) になるため、高さを \(O(\log n)\) に保つ平衡木が使われる。

  • 二分ヒープは配列で表した完全二分木で、優先度付きキューの追加と最小値の取り出しを \(O(\log n)\) で行う。Python では heapq を使う。

  • グラフは隣接行列か隣接リストで表す。多くの実際のグラフは疎なので、通常は隣接リストを使う。

  • LRU キャッシュは、ハッシュ表でキーからノードを引き、双方向連結リストで使われた順序を管理することで、取得と追加を平均 \(O(1)\) で行う。Python では OrderedDict で実装でき、関数の結果のキャッシュには functools.lru_cache を使う。

  • トライは文字列を 1 文字ずつたどる木で、検索が文字列の長さだけで決まり、接頭辞検索が得意である。

  • Union-Find は経路圧縮とランクによる併合により、グループの併合と同じグループかの判定を実用上ほぼ定数の償却計算量で行う。

  • ブルームフィルタはビット配列と複数のハッシュ関数で集合を表し、偽陽性を許す代わりに非常に少ないメモリで「含まれない」ことを確実に判定する。
