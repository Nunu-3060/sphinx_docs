5. アルゴリズムと計算量

「データ構造」では、データの格納方法と、各操作にかかる手間を学んだ。この章では、そのデータ構造を使って問題を解く手順、すなわちアルゴリズムを扱う。まず、アルゴリズムの効率を比べるための尺度である計算量と O 記法を定義する。次に、探索とソートという基本的な問題を例に、計算量の異なるアルゴリズムを比べる。さらに、再帰と分割統治、動的計画法、貪欲法という代表的な設計手法を学び、最後にグラフ上の探索と最短経路の求め方を扱う。

5.1. アルゴリズムとは

アルゴリズムとは、問題を解くための明確な手順を、有限の長さで記述したものである。例えば「整列済みの名簿から目的の名前を探す」「荷物の配送経路のうち最も短いものを求める」といった問題に対して、どのような順に何を計算すれば答えが得られるかを定めたものがアルゴリズムである。アルゴリズムには次の性質が求められる。

  • 各手順が曖昧さなく定められており、機械的に実行できる。

  • どのような入力に対しても、有限回の手順で終了する。

  • 正しい出力（問題の答え）を返す。

アルゴリズムはプログラミング言語とは独立した概念であり、同じアルゴリズムを Python でも C でも書ける。逆に、同じ問題を解く複数のアルゴリズムがあり、それらの効率は大きく異なることがある。データが少ないうちはどのアルゴリズムでも一瞬で終わるが、データが 100 万件、1 億件と増えたとき、選んだアルゴリズムの違いが数秒と数日の差になって現れる。

なお、「どのようなアルゴリズムでも解けない問題」も存在する。これについては「計算理論」で扱う。

5.2. 計算量と O 記法

5.2.1. 計算量を何で測るか

アルゴリズムの効率を実行時間の秒数で比べると、CPU の性能、プログラミング言語、他に動いているプロセスなどの影響を受けてしまう。そこで、アルゴリズムが実行する基本的な操作（比較、代入、算術演算など）の回数を、入力の大きさ \(n\) の関数として数える。これを時間計算量と呼ぶ。同様に、アルゴリズムが使う記憶領域の量を \(n\) の関数として表したものを空間計算量と呼ぶ。両者を合わせて計算量と呼び、単に計算量といえば時間計算量を指すことが多い。入力の大きさは、配列なら要素数、文字列なら文字数、グラフなら頂点数と辺数で表す。

操作の回数を正確に数えるのは難しく、また正確な値にはあまり意味がない。例えば、ある処理の回数が \(3n^2 + 5n + 2\) 回だったとしても、\(n\) が大きくなると \(3n^2\) の項が圧倒的に大きくなり、係数の 3 も CPU や言語によって変わる。重要なのは「\(n\) が 2 倍になると手間がおよそ 4 倍になる」という増え方である。そこで、最も増え方の大きい項だけを残し、定数倍を無視して増え方を表す。

5.2.2. O 記法・Ω 記法・Θ 記法

増え方を表す記法が O 記法（オー記法、ビッグオー記法）である。関数 \(f(n)\) と \(g(n)\) について、ある正の定数 \(c\) と \(n_0\) が存在し、\(n \ge n_0\) を満たすすべての \(n\) に対して次の不等式が成り立つとき、\(f(n) = O(g(n))\) と書く。

\[0 \le f(n) \le c \cdot g(n)\]

これは「\(n\) が十分大きければ、\(f(n)\) は \(g(n)\) の定数倍を超えない」こと、すなわち \(g(n)\) が \(f(n)\) の増え方の上界であることを表す。例えば \(n \ge 1\) のとき \(3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2\) なので、\(c = 10\)、\(n_0 = 1\) とすれば \(3n^2 + 5n + 2 = O(n^2)\) である。この定義から、次の規則が導かれる。

  • 定数倍は無視できる。\(100n = O(n)\) である。

  • 和では増え方の大きい項だけが残る。\(n^2 + n \log n = O(n^2)\) である。

  • 対数の底は無視できる。底の変換公式 \(\log_a n = \log_b n / \log_b a\) より、底の違いは定数倍の違いにすぎないからである。そのため、本書では O 記法の中で底を書かない。O 記法の外で底を省略した \(\log n\) は、底 2 の対数 \(\log_2 n\) を表す。

同様に、下界と、上下からの評価を表す記法がある。

  • \(f(n) = \Omega(g(n))\)（オメガ記法）: ある正の定数 \(c\) と \(n_0\) が存在し、\(n \ge n_0\) で \(f(n) \ge c \cdot g(n) \ge 0\) が成り立つ。\(g(n)\) が下界であることを表す。

  • \(f(n) = \Theta(g(n))\)（シータ記法）: \(f(n) = O(g(n))\) かつ \(f(n) = \Omega(g(n))\) である。増え方がちょうど \(g(n)\) であることを表す。

厳密には、\(O\) は上界にすぎないので、\(O(\log n)\) で終わるアルゴリズムは \(O(n)\) でもある。しかし実務や多くの文献では、\(O\) を「ちょうどその増え方」という \(\Theta\) の意味で使うことが多い。本書でも、誤解の無い範囲で \(O\) を使う。より厳密な扱いは [CLRS] を参照。

5.2.3. 最悪・平均・最良

同じ大きさの入力でも、入力の内容によって手間は変わる。例えば配列の先頭から値を探す場合、目的の値が先頭にあれば 1 回の比較で済むが、存在しなければ \(n\) 回の比較が必要である。そこで、次の 3 つを区別する。

  • 最悪計算量: 大きさ \(n\) の入力のうち、最も手間のかかる入力に対する計算量。

  • 平均計算量: 入力の現れ方に確率分布（例えばすべての並び順が等確率）を仮定したときの計算量の期待値。

  • 最良計算量: 最も手間の少ない入力に対する計算量。

特に断らない限り、計算量は最悪計算量を指す。最悪計算量は「どんな入力が来てもこれ以上はかからない」という保証になるからである。ただし、後で扱うクイックソートや第 4 章のハッシュ表のように、最悪の場合はまれで平均が実用上の性能をよく表すものもある。また、第 4 章の「動的配列と償却計算量」で扱った償却計算量は、一連の操作全体の最悪の手間を操作の回数で割ったもので、確率の仮定を置かない点で平均計算量とは異なる。

5.2.5. 実務での見積もり

実務でコードを読むときは、ループの入れ子の深さと、ループの中で呼び出している操作の計算量に注目すると、おおよその計算量を見積もれる。\(n\) 件のデータに対する 1 重のループは \(O(n)\)、2 重のループは \(O(n^2)\) である。注意したいのは、ループが目に見えない形で隠れている場合である。

  • ループの中で list に対して in、index()、remove()、pop(0) を使うと、それぞれが \(O(n)\) のため全体が \(O(n^2)\) になる（「データ構造」）。

  • ループの中で文字列を += で連結し続けると、処理系によっては毎回新しい文字列へのコピーが発生し、全体で \(O(n^2)\) になる。"".join() を使えば \(O(n)\) で済む。

  • データベースの検索をループの中で 1 件ずつ発行すると、\(n\) 件のデータに対して \(1 + n\) 回の問い合わせが発生する。これは N+1 問題と呼ばれ、1 回ごとの通信の遅延が積み重なって大きな遅れになる。まとめて 1 回で取得するか、結合を使う（「データベース」）。

目安として、Python で単純な操作を繰り返すと 1 秒間に \(10^7\) 回程度（環境によって大きく異なる）実行できる。\(n\) と計算量から操作の回数を見積もり、この値と比べると、書く前にそのアルゴリズムが実用的かどうかを判断できる。

5.3. 探索

配列の中から目的の値を探す問題を探索と呼ぶ。

5.3.1. 線形探索

線形探索は、先頭から順に 1 つずつ目的の値と比較していく方法である。データが整列していなくても使えるが、最悪の場合（値が末尾にあるか存在しない場合）は \(n\) 回の比較が必要で、計算量は \(O(n)\) である。値が存在し、どの位置にあるかが等確率なら、平均の比較回数は約 \(n/2\) 回であり、これも \(O(n)\) である。Python の list に対する in 演算子や index() メソッドは線形探索である。

5.3.2. 二分探索

データが整列済みなら、より速く探せる。二分探索は、探す範囲の中央の要素と目的の値を比較し、目的の値が小さければ左半分、大きければ右半分に範囲を絞り込む方法である。辞書を引くとき、真ん中あたりを開いて前か後ろかを判断する作業を繰り返すのと同じである。

1 回の比較で範囲が半分になるので、\(n\) 個の要素は \(k\) 回の比較で \(n / 2^k\) 個以下に絞られる。範囲が 1 個になるまでの比較回数は \(\log n\) 程度で、最悪の比較回数は \(\lfloor \log n \rfloor + 1\) 回である。したがって計算量は \(O(\log n)\) である。

5.3.3. bisect モジュール

Python では、整列済みの list に対する二分探索に標準ライブラリの bisect モジュールを使う。bisect_left(a, x) は「x を挿入しても整列が保たれる最も左の位置」、すなわち x 以上の最初の要素の位置を返し、bisect_right(a, x) は x より大きい最初の要素の位置を返す。サンプルの後半のように、2 つを組み合わせると「ある範囲の値がいくつあるか」を \(O(\log n)\) で求められる。時刻順に並んだログから指定した期間のものを取り出す、点数から評価の段階を決める、といった処理に使える。

insort() は整列を保ったまま値を挿入するが、挿入位置を探すのが \(O(\log n)\) でも、list の途中への挿入で後ろの要素をずらすため、全体では \(O(n)\) かかる。挿入と検索を大量に繰り返す場合は、平衡木（第 4 章）のようなデータ構造が必要になる。

また、整列には次節で見るように \(O(n \log n)\) かかる。1 回だけ探すなら、整列してから二分探索するより、線形探索の方が速い。何度も探す場合に、整列の手間を多くの探索で分け合うことで二分探索が有利になる。キーによる検索だけで十分なら、set や dict で平均 \(O(1)\) の検索をする方が簡単である。

5.4. 再帰と分割統治

5.4.1. 再帰

関数が自分自身を呼び出すことを再帰と呼ぶ。再帰を使うと、「問題を同じ形の小さな問題に分けて解く」手順を素直に書ける。例えば \(n\) の階乗 \(n!\) は、\(0! = 1\) および \(n! = n \times (n-1)!\) と定義でき、そのまま次のように書ける。

1def factorial(n: int) -> int:
2    if n == 0:
3        return 1                   # 基底部: これ以上分けずに答えを返す
4    return n * factorial(n - 1)    # 再帰部: 小さな問題に帰着する

再帰関数には、それ以上自分を呼ばずに答えを返す基底部と、より小さな問題について自分を呼ぶ再帰部が必要である。再帰部が必ず基底部に近づくように書かないと、呼び出しが無限に続く。

関数を呼び出すたびに、引数や局所変数を保存する領域（スタックフレーム）がコールスタックに積まれる（「プログラミング言語処理系」）。そのため再帰の深さに比例した空間計算量が必要であり、深すぎるとスタックがあふれる。Python は既定で再帰の深さを 1000 程度に制限しており（sys.getrecursionlimit() で確認できる）、超えると RecursionError になる。深さが \(n\) に比例する再帰は、Python ではループに書き直すのが安全である。

5.4.2. 分割統治法

問題を同じ形のいくつかの小さな問題に分割し（分割）、それぞれを再帰的に解き（統治）、その結果を組み合わせて元の問題の答えを得る設計手法を分割統治法と呼ぶ。前節の二分探索は、問題を半分に分けて片方だけを解く、最も簡単な分割統治法である。次節のマージソートとクイックソートも分割統治法である。

5.5. ソート

データを決められた順序に並べ替えることをソート（整列）と呼ぶ。ソートは、二分探索の前処理、重複の除去、順位付け、データベースの結合など、多くの処理の基礎となる。ここでは要素同士の比較によって並べ替える 3 つのアルゴリズムを取り上げる。

5.5.1. 挿入ソート

挿入ソートは、配列の先頭側を「整列済みの部分」とし、その次の要素を整列済みの部分の適切な位置に挿入することを繰り返す方法である。トランプの手札を並べるときの方法に近い。挿入する要素より大きい要素を 1 つずつ右にずらしながら、挿入位置を探す。

最悪の場合（逆順に並んでいる場合）、\(i\) 番目の要素の挿入に \(i\) 回の比較が必要で、比較の総数は \(1 + 2 + \cdots + (n-1) = n(n-1)/2\) 回、計算量は \(O(n^2)\) である。一方、すでに整列している場合は各要素で 1 回比較するだけで済み、\(O(n)\) で終わる。このため、ほぼ整列済みのデータや要素数の少ないデータに対しては高速であり、後述の Timsort の内部でも使われている。

5.5.2. マージソート

マージソートは、配列を半分に分け、それぞれを再帰的にソートし、2 つの整列済みの列を 1 つに併合（マージ）する分割統治法である。2 つの整列済みの列の併合は、それぞれの先頭を比べて小さい方を取り出すことを繰り返せばよく、\(O(n)\) でできる。したがって計算量は次の漸化式で表せる（\(c\) は定数）。

\[T(n) = 2T(n/2) + cn\]

これを展開すると次のようになる。

\[\begin{split}T(n) &= 2T(n/2) + cn \\ &= 4T(n/4) + 2cn \\ &= 2^k T(n/2^k) + kcn\end{split}\]

\(k = \log n\) のとき \(n/2^k = 1\) となるので、\(T(n) = nT(1) + cn \log n = O(n \log n)\) である。分割を繰り返すと \(\log n\) 段になり、各段の併合の手間の合計が \(cn\) であると考えてもよい。マージソートは入力の並びによらず常に \(O(n \log n)\) であるが、併合のために \(O(n)\) の作業領域が必要である。

5.5.3. クイックソート

クイックソートは、配列から 1 つの要素（ピボット）を選び、ピボット以下の要素を左に、大きい要素を右に集める分割を行い、左右をそれぞれ再帰的にソートする方法である。分割が終わった時点でピボットは最終的な位置に確定するので、併合の手間は要らない。

ピボットによって配列がほぼ半分に分かれれば、マージソートと同じく \(O(n \log n)\) になる。しかし、ピボットが常に最小値や最大値になると、分割のたびに要素が 1 つ減るだけになり、漸化式 \(T(n) = T(n-1) + cn\) から \(O(n^2)\) になる。例えば末尾の要素を常にピボットに選ぶ実装に整列済みの配列を与えると、この最悪の場合になる。ピボットをランダムに選べば、どのような入力に対しても平均 \(O(n \log n)\) になる。クイックソートは作業領域が少なく、内側のループが単純でキャッシュの効果も得やすいため、実用上は高速なことが多い。C++ の std::sort() の多くの実装は、クイックソートを基に、再帰が深くなりすぎたらヒープソートに切り替えるなどして最悪の場合を避ける工夫（イントロソート）を加えたものである。

5.5.5. 比較ソートの下限

要素同士の比較だけを使うソートは、どれほど工夫しても最悪の場合に \(\Omega(n \log n)\) 回の比較が必要であることが知られている。\(n\) 個の異なる要素の並び方は \(n!\) 通りあり、ソートはこのうちどれが入力されたかを比較の結果だけから見分けなければならない。1 回の比較の結果は「以下」か「より大きい」の 2 通りなので、\(k\) 回の比較で見分けられるのは高々 \(2^k\) 通りである。したがって \(2^k \ge n!\)、すなわち次が必要である。

\[k \ge \log (n!)\]

\(n!\) には \(n/2\) 以上の数が \(n/2\) 個以上含まれるので \(n! \ge (n/2)^{n/2}\) であり、\(\log (n!) \ge (n/2) \log (n/2) = \Omega(n \log n)\) となる。実行結果の 1 行目の「下限」はこの \(\log (n!)\) の値であり、マージソートの 3,837 回はこの下限に近い。マージソートは比較ソートとして漸近的に最適である。

なお、この下限は比較だけを使う場合のものである。値が小さな範囲の整数であることが分かっていれば、値ごとの個数を数える計数ソートや、桁ごとに分類する基数ソートによって \(O(n)\) でソートできる場合がある。

5.5.6. 安定性と Python の sorted

ソートの前後で、等しいキーを持つ要素の相対的な順序が保たれるソートを安定ソートと呼ぶ。例えば、受付順に並んだ応募者を点数でソートしたとき、同じ点数の人が受付順のまま並ぶのが安定ソートである。安定ソートを使えば、「部署順、同じ部署なら入社順」のような複数のキーによる並べ替えを、優先度の低いキーから順にソートを重ねることで実現できる。挿入ソートとマージソート（併合で等しいときに左を先に出す場合）は安定であり、クイックソートは一般に安定ではない。

Python の sorted() と list.sort() は Timsort と呼ばれるアルゴリズムを使っている。Timsort はマージソートと挿入ソートを組み合わせたもので、入力の中にすでに整列している区間（ラン）を見つけて活用する。最悪の場合も \(O(n \log n)\) であり、整列済みやほぼ整列済みのデータでは \(O(n)\) に近い手間で終わる。また、安定ソートであることが保証されている [PythonDocs]。実行結果の最後の行では、点数の高い順に並べたとき、同じ 90 点の「鈴木」と「田中」、同じ 80 点の「佐藤」と「高橋」が元の順序を保っている。reverse=True を指定しても安定性は保たれる。

実務では、ソートアルゴリズムを自作する必要はほとんどなく、sorted() に key 引数を渡して使えばよい。自作のソートより速く、安定性も保証されている。

5.6. 動的計画法

問題を小さな部分問題に分けて解く点は分割統治法と同じであるが、部分問題が互いに重なり合い、同じ部分問題が何度も現れる場合には、別の工夫が有効である。部分問題の答えを表に記録しておき、同じ部分問題が現れたら記録を再利用する設計手法を動的計画法（DP: Dynamic Programming）と呼ぶ。動的計画法が使えるのは、元の問題の最適解が部分問題の最適解から組み立てられる（最適部分構造を持つ）場合である。

5.6.1. フィボナッチ数とメモ化

フィボナッチ数は次の漸化式で定義される。

\[F(0) = 0, \quad F(1) = 1, \quad F(n) = F(n-1) + F(n-2) \quad (n \ge 2)\]

これを定義どおりに再帰で書くと、\(F(n-1)\) の計算の中でも \(F(n-2)\) が計算されるため、同じ値が何度も計算される。関数の呼び出し回数は \(F(n)\) 自体と同じく指数関数的に増え、計算量は \(O(\phi^n)\)（\(\phi = (1 + \sqrt{5})/2 \approx 1.618\) は黄金比）になる。

一度計算した結果を記録しておき、同じ引数で呼ばれたら記録を返す方法をメモ化と呼ぶ。メモ化すると、\(F(0)\) から \(F(n)\) までをそれぞれ 1 回だけ計算するので、計算量は \(O(n)\) になる。Python では functools.cache デコレータを付けるだけでメモ化できる。

5.6.2. 最長共通部分列

動的計画法の典型的な例として、2 つの文字列の最長共通部分列（LCS: Longest Common Subsequence）を求める問題を取り上げる。部分列とは、文字列からいくつかの文字を取り除いて（順序は変えずに）得られる列である。例えば ACA は AGCAT の部分列であり、GACTA の部分列でもあるので、両者の共通部分列である。2 つのファイルの差分を表示する diff コマンドや Git の差分表示も、この問題と密接に関係する問題を解いている。

文字列 \(a\) の先頭 \(i\) 文字と、文字列 \(b\) の先頭 \(j\) 文字の LCS の長さを \(L(i, j)\) とする。\(a\) の \(i\) 文字目を \(a_i\) と書くと、\(L(i, j)\) は次の漸化式で求まる。

\[\begin{split}L(i, j) = \begin{cases} 0 & (i = 0 \lor j = 0) \\ L(i-1, j-1) + 1 & (a_i = b_j) \\ \max(L(i-1, j), L(i, j-1)) & (a_i \ne b_j) \end{cases}\end{split}\]

末尾の文字が等しければ、その文字を LCS に含めて残りの LCS に 1 を足せばよい。等しくなければ、どちらか一方の末尾の文字を捨てた 2 つの部分問題のうち、長い方が答えになる。\(L(i, j)\) を \(i\) と \(j\) の小さい順に表に埋めていけば、各要素は定数の手間で求まり、計算量は文字列の長さを \(m\)、\(n\) として \(O(mn)\) である。すべての部分列を列挙する方法では \(O(2^m)\) 個の部分列を調べることになるので、大きな改善である。

35def lcs(a: str, b: str) -> str:
36    """文字列 a と b の最長共通部分列の 1 つを返す。"""
37    m, n = len(a), len(b)
38    # t[i][j] は a[:i] と b[:j] の LCS の長さ
39    t = [[0] * (n + 1) for _ in range(m + 1)]
40    for i in range(1, m + 1):
41        for j in range(1, n + 1):
42            if a[i - 1] == b[j - 1]:
43                t[i][j] = t[i - 1][j - 1] + 1
44            else:
45                t[i][j] = max(t[i - 1][j], t[i][j - 1])
46    # 表を右下から逆にたどって部分列を復元する
47    chars: list[str] = []
48    i, j = m, n
49    while i > 0 and j > 0:
50        if a[i - 1] == b[j - 1]:
51            chars.append(a[i - 1])
52            i, j = i - 1, j - 1
53        elif t[i - 1][j] >= t[i][j - 1]:
54            i -= 1
55        else:
56            j -= 1
57    return "".join(reversed(chars))

39〜45 行目で表 t を埋め、47〜57 行目で表を右下から逆にたどって、実際の共通部分列を 1 つ復元している。AGCAT と GACTA に対する結果は ACA であり、長さ 3 の共通部分列である（LCS は 1 つとは限らず、例えば GCA も長さ 3 の共通部分列である）。

5.7. 貪欲法

貪欲法は、各段階でその時点で最も良く見える選択を行い、後から選び直さない設計手法である。手順が単純で高速なことが多いが、常に最適解が得られるとは限らない。貪欲法で最適解が得られるかどうかは、問題ごとに証明が必要である。

例として、指定した金額をできるだけ少ない枚数の硬貨で支払う問題を考える。貪欲法では「支払える範囲で額の最も大きい硬貨を使う」ことを繰り返す。日本の硬貨（1、5、10、50、100、500 円）では、この方法で常に最小枚数になる。しかし、硬貨の種類が 1、3、4 円の場合に 6 円を支払うと、貪欲法は 4 + 1 + 1 の 3 枚を選ぶが、最適解は 3 + 3 の 2 枚である。最初に 4 円を選んだ時点で、最適解への道が閉ざされている。

この問題は、金額 \(x\) を支払う最小枚数を \(B(x)\) とすると、硬貨の額面の集合を \(C\) として次の漸化式で表せるので、動的計画法で確実に解ける。

\[B(0) = 0, \quad B(x) = \min_{c \in C,\ c \le x} \bigl( B(x - c) + 1 \bigr)\]
ch05_dp.py（硬貨の問題と main）
 60def coins_greedy(coins: list[int], amount: int) -> list[int]:
 61    """額の大きい硬貨から使えるだけ使う（貪欲法）。"""
 62    result: list[int] = []
 63    for c in sorted(coins, reverse=True):
 64        while amount >= c:
 65            result.append(c)
 66            amount -= c
 67    return result

 70def coins_dp(coins: list[int], amount: int) -> list[int]:
 71    """金額 0 から amount までの最小枚数を順に求める（動的計画法）。"""
 72    inf = amount + 1
 73    best = [0] + [inf] * amount  # best[x] は金額 x の最小枚数
 74    last = [0] * (amount + 1)  # 金額 x の最適解で最後に使った硬貨
 75    for x in range(1, amount + 1):
 76        for c in coins:
 77            if c <= x and best[x - c] + 1 < best[x]:
 78                best[x] = best[x - c] + 1
 79                last[x] = c
 80    result: list[int] = []
 81    while amount > 0:
 82        result.append(last[amount])
 83        amount -= last[amount]
 84    return result

貪欲法が最適解を与える問題も多い。次節のダイクストラ法は、「まだ確定していない頂点のうち最も近いものを確定する」という貪欲法の一種であり、辺の重みが非負なら正しい最短距離が得られることが証明されている。また、データ圧縮に使われるハフマン符号の構成も貪欲法である。

5.8.1. 幅優先探索

幅優先探索（BFS: Breadth-First Search）は、出発点に近い頂点から順に訪問する方法である。キューを使い、取り出した頂点に隣接する未訪問の頂点をキューの末尾に追加することを繰り返す。こうすると、出発点から辺 1 本で行ける頂点をすべて訪問してから、辺 2 本で行ける頂点に進む。したがって、すべての辺の重みが等しいグラフでは、各頂点を初めて発見したときの辺の数がそのまま出発点からの最短距離になる。

ch05_graph.py（幅優先探索）
16def bfs(graph: Graph, start: str) -> dict[str, int]:
17    """start からの辺の数で数えた最短距離を返す（幅優先探索）。"""
18    dist = {start: 0}
19    queue = deque([start])
20    while queue:
21        u = queue.popleft()  # 先に見つけた頂点から順に取り出す
22        for v in graph[u]:
23            if v not in dist:
24                dist[v] = dist[u] + 1
25                queue.append(v)
26    return dist

キューには第 4 章で学んだ collections.deque を使っている。list の pop(0) を使うと取り出しのたびに \(O(V)\) かかってしまう。各頂点はキューに 1 回だけ入り、各頂点の隣接リストを 1 回ずつ調べるので、計算量は \(O(V + E)\) である。隣接行列で表した場合は、各頂点の隣接する頂点を列挙するのに \(O(V)\) かかるため \(O(V^2)\) になる。SNS で「友達の友達」を求める処理や、迷路の最短手数を求める処理は幅優先探索である。

5.8.2. 深さ優先探索

深さ優先探索（DFS: Depth-First Search）は、行けるところまで先へ進み、行き止まりになったら戻って別の道を進む方法である。キューの代わりにスタックを使う（または再帰で書く）点が幅優先探索と異なる。計算量は幅優先探索と同じく \(O(V + E)\) である。

ch05_graph.py（深さ優先探索）
29def dfs(graph: Graph, start: str) -> list[str]:
30    """深さ優先探索で訪問した順に頂点を返す。"""
31    order: list[str] = []
32    visited: set[str] = set()
33    stack = [start]
34    while stack:
35        u = stack.pop()  # 最後に見つけた頂点から取り出す
36        if u in visited:
37            continue
38        visited.add(u)
39        order.append(u)
40        # 隣接リストの先頭の頂点から訪問するよう、逆順に積む
41        for v in reversed(graph[u]):
42            if v not in visited:
43                stack.append(v)
44    return order

隣接リストの先頭の頂点から訪問するよう、スタックには逆順に積んでいる。深さ優先探索は、グラフが連結かどうかの判定、閉路の検出、依存関係を満たす順序の決定（トポロジカルソート）などに使われる。ビルドツールやパッケージ管理ツールが、依存するものから順にビルドやインストールを行う順序を決めるのは、トポロジカルソートの応用である。再帰で書くと簡潔になるが、Python では頂点数が多いと再帰の深さの制限に達するため、この例のように明示的なスタックを使う方が安全である。

5.8.3. ダイクストラ法

辺に距離や所要時間などの重みがある場合、辺の数が少ない経路が最短とは限らない。辺の重みが非負のグラフで、出発点から各頂点への最短距離を求める代表的なアルゴリズムがダイクストラ法である [Dijkstra1959]。

ダイクストラ法は、各頂点について「現時点で分かっている最短距離（暫定距離）」を持ち、まだ確定していない頂点のうち暫定距離が最小の頂点を確定させる。そして、確定した頂点から出る辺をたどって、隣接する頂点の暫定距離をより短くできれば更新する（緩和）。辺の重みが非負なので、暫定距離が最小の頂点には、他の未確定の頂点を経由してもより短く到達できない。これがこの貪欲な選択が正しい理由である。

暫定距離が最小の頂点を効率よく選ぶために、第 4 章で学んだ優先度付きキュー（heapq）を使う。

ch05_graph.py（ダイクストラ法）
47def dijkstra(graph: WeightedGraph,
48             start: str) -> tuple[dict[str, int], dict[str, str]]:
49    """辺の重みが非負のグラフで、start からの最短距離と直前の頂点を返す。"""
50    dist = {start: 0}
51    prev: dict[str, str] = {}
52    heap = [(0, start)]  # (暫定距離, 頂点) の優先度付きキュー
53    while heap:
54        d, u = heapq.heappop(heap)
55        if d > dist[u]:
56            continue  # より短い距離で既に確定した古い候補は捨てる
57        for v, w in graph[u]:
58            nd = d + w
59            if v not in dist or nd < dist[v]:
60                dist[v] = nd
61                prev[v] = u
62                heapq.heappush(heap, (nd, v))
63    return dist, prev

heapq には要素の優先度を下げる操作が無いため、暫定距離を更新するたびに新しい組を追加し、取り出したときに確定済みの距離より長い古い組は捨てている（55〜56 行目）。prev には各頂点に最短距離で到達する直前の頂点を記録し、経路の復元に使う。ヒープへの追加と取り出しは辺の数に比例する回数だけ行われ、それぞれ \(O(\log V)\) 程度なので、計算量は \(O((V + E) \log V)\) である。

ch05_graph.py の main() では、BFS と DFS を 6 頂点の無向グラフに、ダイクストラ法を 5 頂点の有向グラフに適用する。後者の辺は S→A（7）、S→B（2）、B→A（3）、B→C（8）、A→G（1）、C→G（2）である。

辺の重みに負の値があると、確定した頂点に後からより短く到達できる可能性があり、ダイクストラ法は正しい答えを返さない。その場合はベルマン・フォード法などの別のアルゴリズムを使う [CLRS]。カーナビの経路探索や、ルータの経路表を自動で作る OSPF などのルーティングプロトコル（ルーティングは「コンピュータネットワーク」で扱う）では、ダイクストラ法やそれを改良したアルゴリズムが使われている。

5.9. まとめ

  • アルゴリズムは問題を解くための明確で有限の手順であり、同じ問題でもアルゴリズムによって効率が大きく異なる。

  • 計算量は基本的な操作の回数を入力の大きさ \(n\) の関数として表したもので、O 記法で定数倍と低次の項を無視した増え方を表す。\(O\) は上界、\(\Omega\) は下界、\(\Theta\) は上下両方からの評価である。

  • 特に断らない限り計算量は最悪計算量を指す。平均計算量や償却計算量が実用上の性能をよく表す場合もある。

  • ループの入れ子や、ループ内の in、データベースへの問い合わせなど、隠れたループに注意すると、コードの計算量を見積もれる。

  • 線形探索は \(O(n)\)、整列済みの配列に対する二分探索は \(O(\log n)\) である。Python では bisect を使う。

  • 挿入ソートは最悪 \(O(n^2)\) であるが、ほぼ整列済みのデータには速い。マージソートは常に \(O(n \log n)\)、クイックソートは平均 \(O(n \log n)\)、最悪 \(O(n^2)\) である。比較ソートには \(\Omega(n \log n)\) の下限がある。

  • Python の sorted() は Timsort による安定ソートである。

  • 分割統治法は問題を分割して再帰的に解き、計算量は漸化式で表せる。Python では再帰の深さに制限がある。

  • 動的計画法は重なり合う部分問題の答えを記録して再利用する。フィボナッチ数のメモ化や最長共通部分列が典型例である。

  • 貪欲法は各段階で最良に見える選択をする。単純で高速であるが、硬貨の問題のように最適解を出さない場合がある。

  • 幅優先探索と深さ優先探索は \(O(V + E)\) でグラフをたどる。重みの無いグラフの最短距離は幅優先探索で、重みが非負のグラフの最短距離はダイクストラ法で求める。
