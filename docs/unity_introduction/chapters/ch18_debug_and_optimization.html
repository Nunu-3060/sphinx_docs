第 18 章 デバッグと最適化

この章では、ゲームが思いどおりに動かないときの原因の調べ方と、ゲームが重いときの改善の基本を説明します。

この章のサンプルコードは、examples/chapter18 フォルダーにあります。

デバッガーの使用

Debug.Log で値を表示する方法（第 7 章 C# スクリプトの基礎 を参照）は手軽ですが、調べたい値が多い場合や、処理の流れを追いたい場合は、コードエディターの デバッガー を使うと効率的です。デバッガーを使うと、指定した行で処理を一時停止し（ブレークポイント）、その時点の変数の値を確認したり、1 行ずつ処理を進めたりできます。

Visual Studio での手順は次のとおりです。Visual Studio Code や Rider でも、同様の手順でデバッグできます。

  1. コードエディターで、処理を止めたい行の左端をクリックして、ブレークポイント（赤い丸）を設定します。

  2. Visual Studio のツールバーの Unity にアタッチ（英語版では Attach to Unity）をクリックします。

  3. Unity Editor に、デバッグ用のモードに切り替えるかどうかを確認するメッセージが表示された場合は、切り替えを選びます。

  4. Unity Editor で再生します。ブレークポイントを設定した行が実行されると、処理が一時停止し、コードエディターで変数の値を確認できます。

Unity Editor のコードの実行モードは、ウィンドウの右下にある虫のアイコンで確認、切り替えできます。Debug モードではデバッガーを接続できますが、スクリプトの実行が遅くなります。Release モードでは実行は速くなりますが、デバッガーを接続できません。

Profiler による性能の計測

ゲームが重い（フレームレートが低い）ときは、推測で修正するのではなく、まず何に時間がかかっているのかを計測します。計測には Profiler を使います。

  1. Window ‣ Analysis ‣ Profiler で Profiler ウィンドウを開きます。

  2. Unity Editor で再生すると、フレームごとの処理時間がグラフで表示されます。

  3. グラフの中で処理時間が長いフレームをクリックすると、ウィンドウの下部に、そのフレームの処理の内訳が表示されます。

Profiler ウィンドウの主な項目は次のとおりです。

項目

内容

CPU Usage

CPU の処理時間の内訳です。スクリプト、描画、物理演算などに分けて表示されます。ウィンドウの下部を Hierarchy 表示にすると、どのメソッドにどれだけ時間がかかったかを確認できます。

Rendering

描画に関する情報です。ドローコールの回数などが表示されます。

Memory

メモリの使用量です。

GC Alloc（CPU Usage の Hierarchy 表示の列）

そのフレームで確保したメモリの量です。後述するガベージコレクションの原因を調べるのに使います。

Unity Editor の中での計測結果には、Unity Editor 自体の処理も含まれます。正確に計測したい場合は、Development Build を有効にしてビルドしたアプリケーションに、Profiler を接続して計測します（第 17 章 ビルドと配布 を参照）。

描画の調査

描画の処理を調べるには、次の機能を使います。

機能

内容

Statistics

Game ビューの右上にある Stats をクリックすると表示されます。フレームレート、描画の命令の回数（Batches）、三角形の数などを確認できます。

Frame Debugger

Window ‣ Analysis ‣ Frame Debugger で開きます。1 フレームの描画を、描画の命令ごとに 1 つずつ確認できます。何がどの順番で描画されているかを調べるのに使います。

最適化の基本

計測によって原因がわかったら、それに応じて改善します。初心者が取り組みやすい改善の方法を紹介します。

オブジェクトプール

弾やエフェクトのように、頻繁に生成と破棄を繰り返す GameObject があると、Instantiate と Destroy の処理が負担になります。このような場合は、オブジェクトプール を使います。オブジェクトプールは、使い終わった GameObject を破棄せずに非表示にして保管しておき、次に必要になったときに再利用するしくみです。

Unity には、オブジェクトプールを実装するための UnityEngine.Pool.ObjectPool<T> クラスが用意されています。

BulletSpawner.cs
 1using UnityEngine;
 2using UnityEngine.Pool;
 3
 4namespace UnityIntroduction.Chapter18
 5{
 6    /// <summary>
 7    /// オブジェクトプールを使って、弾を一定間隔で発射します。
 8    /// </summary>
 9    /// <remarks>
10    /// 弾を毎回 Instantiate と Destroy で生成、破棄する代わりに、使い終わった弾を再利用します。
11    /// </remarks>
12    public class BulletSpawner : MonoBehaviour
13    {
14        [SerializeField]
15        private PooledBullet _bulletPrefab;
16
17        [SerializeField, Tooltip("発射する間隔（秒）")]
18        private float _fireInterval = 0.1f;
19
20        private ObjectPool<PooledBullet> _pool;
21        private float _elapsed;
22
23        private void Awake()
24        {
25            _pool = new ObjectPool<PooledBullet>(
26                createFunc: CreateBullet,
27                actionOnGet: bullet => bullet.gameObject.SetActive(true),
28                actionOnRelease: bullet => bullet.gameObject.SetActive(false),
29                actionOnDestroy: bullet => Destroy(bullet.gameObject),
30                collectionCheck: true,
31                defaultCapacity: 20,
32                maxSize: 100);
33        }
34
35        private void Update()
36        {
37            _elapsed += Time.deltaTime;
38            if (_elapsed < _fireInterval)
39            {
40                return;
41            }
42
43            _elapsed -= _fireInterval;
44
45            // プールから弾を取り出します。空きが無ければ createFunc で新しく生成されます。
46            PooledBullet bullet = _pool.Get();
47            bullet.transform.SetPositionAndRotation(transform.position, transform.rotation);
48        }
49
50        private PooledBullet CreateBullet()
51        {
52            PooledBullet bullet = Instantiate(_bulletPrefab);
53            bullet.SetPool(_pool);
54            return bullet;
55        }
56    }
57}

PooledBullet.cs
 1using UnityEngine;
 2using UnityEngine.Pool;
 3
 4namespace UnityIntroduction.Chapter18
 5{
 6    /// <summary>
 7    /// まっすぐ飛び、一定時間が経過するとプールに戻る弾です。
 8    /// </summary>
 9    public class PooledBullet : MonoBehaviour
10    {
11        [SerializeField, Tooltip("1 秒あたりの移動量（m/s）")]
12        private float _speed = 20f;
13
14        [SerializeField, Tooltip("プールに戻るまでの時間（秒）")]
15        private float _lifetime = 2f;
16
17        private IObjectPool<PooledBullet> _pool;
18        private float _elapsed;
19
20        /// <summary>
21        /// 戻り先のプールを設定します。
22        /// </summary>
23        public void SetPool(IObjectPool<PooledBullet> pool)
24        {
25            _pool = pool;
26        }
27
28        private void OnEnable()
29        {
30            // 再利用されるたびに呼ばれるので、ここで状態を初期化します。
31            _elapsed = 0f;
32        }
33
34        private void Update()
35        {
36            transform.Translate(Vector3.forward * _speed * Time.deltaTime);
37
38            _elapsed += Time.deltaTime;
39            if (_elapsed >= _lifetime)
40            {
41                // Destroy する代わりにプールへ戻します。
42                _pool.Release(this);
43            }
44        }
45    }
46}

PooledBullet.cs をダウンロード

使い方は次のとおりです。

  1. 小さな球などを作成して PooledBullet を付け、Prefab にします。

  2. 空の GameObject を作成して BulletSpawner を付け、Bullet Prefab に作成した Prefab を設定します。

  3. 再生すると、BulletSpawner の前方（Z 軸の方向）に弾が次々と発射されます。Hierarchy ウィンドウを見ると、弾の GameObject が破棄されずに、表示と非表示を繰り返しながら再利用されていることがわかります。

ObjectPool<T> のコンストラクターには、プールの動作を決める次の処理を渡します。

引数

内容

createFunc

プールに空きがないときに、新しいオブジェクトを生成する処理です。

actionOnGet

プールからオブジェクトを取り出すとき（Get）の処理です。ここでは GameObject を表示します。

actionOnRelease

プールにオブジェクトを戻すとき（Release）の処理です。ここでは GameObject を非表示にします。

actionOnDestroy

プールの上限（maxSize）を超えて戻されたオブジェクトを破棄する処理です。

collectionCheck

true にすると、同じオブジェクトを 2 回戻そうとしたときに例外を発生させます。開発中の誤りの発見に役立ちます。

ドローコールの削減

CPU が GPU に描画を命令する回数を ドローコール と呼びます。ドローコールが多いと、CPU の負担が大きくなります。ドローコールを減らすには、次のような方法があります。

  • 動かない GameObject の Static を有効にします。静的バッチングにより、同じマテリアルを使う複数の GameObject の描画がまとめられます。

  • カメラから遠くにある GameObject は、詳細度を下げたモデルに切り替えます（LOD Group コンポーネント）。

なお、URP では SRP Batcher が初期設定で有効になっています。SRP Batcher は、ドローコールの回数そのものは減らしませんが、同じシェーダーを使うマテリアルであれば、マテリアルが異なっていても、ドローコールごとの CPU の負担を小さくします。

ガベージコレクションの抑制

C# では、使われなくなったメモリは ガベージコレクション（GC）によって自動的に解放されます。ガベージコレクションは処理の負担が大きく、実行されたフレームで画面が一瞬かくつくことがあります。Unity 6 では、ガベージコレクションの処理を複数のフレームに分散するインクリメンタル GC が初期設定で有効になっていますが、確保するメモリが多いと負担は避けられません。ガベージコレクションの頻度を下げるには、毎フレーム新しいメモリを確保しないようにします。

メモリを確保する処理の例

対策

Update の中での文字列の連結や $"..." による文字列の作成

値が変わったときだけ文字列を作り直す。

Update の中での配列やリストの new

フィールドに保持して使い回す。

Update の中での GetComponents や FindObjectsByType などの、配列を返すメソッドの呼び出し

Awake や Start で 1 回だけ呼び、結果を保持する。

Instantiate と Destroy の繰り返し

オブジェクトプールを使う。

最適化の考え方

最適化を行うと、コードが複雑になり、読みにくくなることがあります。最初からすべてを最適化しようとせず、次の順番で進めてください。

  1. まずはわかりやすいコードで、ゲームを動く状態にします。

  2. 対象のプラットフォームで動かし、目標のフレームレートが出ているかを確認します。

  3. 目標に届かない場合は、Profiler で計測して、最も時間がかかっている箇所を特定します。

  4. その箇所だけを改善し、改善できたことを再び計測して確認します。
