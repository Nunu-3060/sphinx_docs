4. ゲームエンジンの選定

ゲームを作る道具は数多くあり、どれを選ぶかで作業の進め方や公開できるプラットフォームが大きく変わる。この章では、道具の種類と選定の基準を説明し、主な製品を紹介する。

4.1. ゲームエンジンとフレームワーク

ゲームを作る道具は、大きくゲームエンジンとフレームワークに分けられる。

ゲームエンジンは、ゲーム制作に必要な機能を一式そろえた統合環境である。描画、物理演算、音声、入力、アニメーションなどの実行時の機能に加え、オブジェクトを画面上に配置するエディター、素材を取り込む仕組み、各プラットフォーム向けの書き出し機能を備える。Unity、Unreal Engine、Godot などがこれに当たる。

フレームワーク（またはライブラリー）は、描画や入力などの基本機能をプログラムから呼び出せる形で提供するものである。エディターは無いか最小限で、ゲームの構造はプログラマーが自分で組み立てる。本書で使う pygame-ce はこちらに当たる。

表 4.1 ゲームエンジンとフレームワークの比較

観点

ゲームエンジン

フレームワーク

制作の進め方

エディター上で配置・設定し、必要な部分をスクリプトで書く

ほぼすべてをコードで書く

学習の対象

ゲームプログラミングの基礎そのもの

大規模・3D の制作

向いている

仕組みの見通し

書き出し先

PC、モバイル、家庭用ゲーム機など多数

どちらが優れているということではない。商業規模の 3D ゲームを作るならゲームエンジンを使うのが現実的である。一方、ゲームループや当たり判定といった基礎を理解する目的では、フレームワークで一から組み立てる経験が役に立つ。基礎を理解していれば、ゲームエンジンのエディターの裏で何が起きているかを推測できるようになる。

4.2. 選定の基準

道具を選ぶときは、次の観点で比較する。

表 4.2 選定の観点

観点

確認すること

2D か 3D か

2D 専用の機能が充実しているか、3D の描画性能や表現力が必要か

公開するプラットフォーム

Windows、macOS、ブラウザー、スマートフォン、家庭用ゲーム機のうち、どこに書き出せるか

使用する言語

自分やチームが使える言語か。Python、C#、C++、GDScript、JavaScript など

迷った場合は、作りたいゲームに近い作品がそのツールで作られているかを調べるとよい。実例があれば、そのツールで実現できることの裏付けになる。

4.3. 汎用のゲームエンジン

ジャンルを問わず使える代表的なゲームエンジンを次の表に示す。いずれも無料で使い始められる。

表 4.3 汎用のゲームエンジン（2026 年 10 月時点）

名称

主な言語

特徴

費用の概要

Unity

C#

2D・3D の両方に対応し、モバイルゲームでの採用例が多い。資料と追加素材（アセットストア）が豊富

直近 12 か月の収益と調達資金が一定額（執筆時点では 20 万米ドル）未満なら無料の Personal プランを使える。超えると有料プランが必要

Unreal Engine

C++、Blueprint（ビジュアルスクリプト）

高品質な 3D 表現に強く、大規模な商業タイトルで多く使われる

無料で使える。ゲームの総売上が製品ごとに 100 万米ドルを超えると、超えた分に 5 % のロイヤリティーがかかる

Godot

GDScript、C#

オープンソース（MIT ライセンス）。軽量で 2D に強い。GDScript は Python に似た文法を持つ

完全に無料。ロイヤリティーも無い

2D 専用。インディーゲームでの採用実績が多い

4.4. Python で使えるライブラリー

Python でゲームを作る場合は、次のライブラリーが候補になる。

表 4.4 Python 向けのゲーム制作ライブラリー

名称

特徴

向いている用途

pygame-ce

長い歴史を持つ pygame から 2023 年に分かれたコミュニティー版。SDL というマルチメディアライブラリーを Python から使えるようにしたもので、描画、入力、音声の基本機能を提供する

ゲームプログラミングの基礎の学習、小規模な 2D ゲーム

レトロゲーム風のゲームエンジン。16 色のパレットや 4 チャンネルの音源などの制約があり、画像と音を作るエディターも内蔵する

ドット絵のレトロゲーム、ゲームジャム

スプライトの多い 2D ゲーム

Python のライブラリーは、手軽に始められて学習に向く一方、スマートフォンや家庭用ゲーム機への書き出しは基本的にできない。PC とブラウザー向けの小規模なゲームが主な守備範囲である。

4.5. ジャンル特化型のツール

特定のジャンルを作ることに特化したツールもある。ジャンルの定番の仕組み（RPG のマップ移動・戦闘・メニュー、ノベルゲームの文章表示・選択肢・セーブなど）が最初から用意されており、プログラムをほとんど書かずに作品を完成させられる。

表 4.5 ジャンル特化型のツールの例

名称

ジャンル

特徴

RPG ツクール

RPG

1990 年代から続く国内で非常に有名なシリーズ。ツール自体は有償だが、作ったゲームを販売することもできる。最近の版（RPG ツクール MZ）は JavaScript のプラグインで機能を拡張できる

WOLF RPG エディター

RPG

通称ウディタ。無料で使え、商用利用も可能。システムの自由度が高い

ティラノビルダー

ノベルゲーム

画面上の操作でノベルゲームを作れる有償ツール。基盤のエンジン（ティラノスクリプト）は無料で公開されている

Ren'Py

ノベルゲーム

Python を基にしたスクリプトでノベルゲームを作るオープンソースのエンジン。海外での採用例が多い

これらのツールは、作りたいジャンルが合っていれば最短で完成にたどり着ける、非常に有力な選択肢である。RPG ツクールで作られた作品が商業的に成功した例も少なくない。一方で、ジャンルの枠から外れた仕組みを作ろうとすると、かえって手間がかかる。また、ツールが用意した仕組みの上で作るため、ゲームループや当たり判定といった汎用的なプログラミングの基礎を学ぶ機会は少ない。

本書は、プログラミング経験を活かして、ジャンルを問わず応用できる基礎を身に付けることを目的としている。そのため、前の節までは汎用のゲームエンジンと Python のライブラリーを中心に紹介した。作りたいものが RPG やノベルゲームと決まっているなら、ジャンル特化型のツールから始めることを積極的に勧める。

4.7. 選定の流れ

ここまでの内容を、選定の流れとしてまとめる。あくまで目安であり、最終的には候補を 2、3 個に絞って実際に触り、小さなものを作ってみてから決めるのがよい。

4.8. 本書での選択

本書の実践では pygame-ce を使う。理由は次のとおりである。

  • 読者がすでに知っている Python で書ける。

  • エディターの操作を覚える必要が無く、コードを読めばゲームの仕組みがすべて分かる。

  • ゲームループ、デルタタイム、当たり判定、シーン管理など、どのゲームエンジンでも通用する基礎を自分の手で実装できる。

本書で 1 本完成させた後、より大きなゲームやスマートフォン向けのゲームを作りたくなったら、Godot や Unity に進むとよい。特に Godot の GDScript は Python に似ているため、移行しやすい。
