5. 開発環境の準備

この章では、制作実践：ブロック崩しを作るのサンプルコードを動かすための環境を整える。Python 自体のインストール方法は扱わない。python.org のインストーラーなどで、Python 3.10 以降を用意してほしい。

5.1. 作業用のフォルダーと仮想環境

プロジェクトごとに仮想環境（venv）を作り、ライブラリーをその中にインストールする。こうすると、ほかのプロジェクトとライブラリーのバージョンが衝突しない。PowerShell で次のように実行する。

リスト 5.1 仮想環境の作成と有効化
1mkdir breakout
2cd breakout
3py -m venv .venv
4.venv\Scripts\Activate.ps1

4 行目で仮想環境を有効にする。スクリプトの実行が禁止されているというエラーが出た場合は、Set-ExecutionPolicy -Scope CurrentUser RemoteSigned を実行して、自分で作成したスクリプトの実行を許可する。コマンドプロンプトでは、4 行目の代わりに .venv\Scripts\activate.bat を実行する。

仮想環境が有効な間は、py コマンドで仮想環境の Python が起動する。

5.2. pygame-ce のインストール

pygame-ce を pip でインストールし、付属のサンプルゲームを起動して動作を確認する。

リスト 5.2 pygame-ce のインストールと動作確認
1py -m pip install pygame-ce
2py -m pygame.examples.aliens

ウィンドウが開いてゲームが動けば成功である。

pygame-ce はパッケージ名こそ pygame-ce だが、プログラムからは元の pygame と同じく import pygame で読み込む。そのため、元の pygame パッケージと同じ環境に入れると互いに上書きし合って正しく動かない。すでに pygame が入っている場合は、py -m pip uninstall pygame で削除してから pygame-ce をインストールする。

5.3. エディター

コードを書くエディターは使い慣れたものでよい。Visual Studio Code に Python 拡張機能を入れると、補完、デバッガー、型チェックが使えて便利である。pygame-ce は型ヒントの情報を同梱しているため、pygame.Rect などの補完も効く。

5.4. コードの検査

本書のサンプルコードは、スタイルを flake8、型を mypy で検査している。自分でコードを書く場合も、これらを使うと誤りに早く気付ける。

リスト 5.3 検査ツールのインストールと実行
1py -m pip install flake8 mypy
2py -m flake8
3py -m mypy .

設定は、検査するファイルと同じフォルダーに置いた setup.cfg に書く。本書のサンプルコードでは、行の長さを 120 文字まで許し、mypy を最も厳しい strict モードで動かしている。

リスト 5.4 examples/setup.cfg
 1# Settings for checking the sample code in this directory.
 2# Run the following commands in this directory:
 3#   py -m flake8
 4#   py -m mypy .
 5# Keep this file ASCII only: mypy reads it with the locale encoding
 6# (cp932 on Japanese Windows), so non-ASCII characters break it.
 7
 8[flake8]
 9max-line-length = 120
10exclude = .mypy_cache,__pycache__,build,dist
11
12[mypy]
13strict = True

5.5. バージョン管理

小さなゲームでも、最初から Git でバージョン管理をしておく。調整を重ねて「前の版のほうが面白かった」と感じたときに戻れるからである。ゲーム制作に特有の注意点として、画像や音声などの大きなバイナリーファイルの扱いがある。Git はテキストファイルの差分管理に向いており、大きなバイナリーファイルを何度も更新するとリポジトリーが急速に肥大化する。これを避けるには、Git LFS（Large File Storage）を使い、バイナリーファイルの実体をリポジトリーの外に保存する。

リスト 5.5 Git LFS で画像と音声を管理する設定
1git init
2git lfs install
3git lfs track "*.png" "*.wav" "*.ogg"
4git add .gitattributes

3 行目で、LFS で管理するファイルの種類を指定している。この設定は .gitattributes ファイルに記録されるので、4 行目でそれをコミットの対象に加える。

また、仮想環境やビルド結果はリポジトリーに含めないよう、.gitignore に書いておく。

リスト 5.6 .gitignore の例
1.venv/
2__pycache__/
3.mypy_cache/
4build/
5dist/

build/ と dist/ は、ビルドと配布物の作成で使う PyInstaller が出力するフォルダーである。
