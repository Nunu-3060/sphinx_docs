第 3 章 開発環境の準備

この章では、本書のサンプルがどのような構成になっているかを説明し、画面に三角形を 1 枚描く最小のプログラムを動かします。

必要なもの

サンプルを動かして書き換えるために必要なものは、次の 2 つだけです。

  • WebGL 2.0 に対応したブラウザー

  • テキストエディター（Visual Studio Code、メモ帳など、任意のもの）

サンプルの HTML ファイルは、ブラウザーで直接開くだけで動作します。Web サーバーを用意する必要はありません。

サンプルの構成

各サンプルの HTML ファイルは、次の 3 つの部分からできています。

部分

内容

<canvas> 要素

WebGL が描画する領域です。サンプルでは幅 600 ピクセル、高さ 400 ピクセルにしています。

シェーダーのソースコード

<script type="x-shader/x-vertex"> と <script type="x-shader/x-fragment"> の中に書いています。ブラウザーはこの type の <script> 要素を実行しないので、シェーダーのソースコードを文字列として置いておけます。

JavaScript

シェーダーをコンパイルし、頂点データを GPU に転送して、描画を指示します。

本文に掲載しているシェーダーは、HTML ファイルから取り出した .vert と .frag のファイルを表示したものです（第 1 章の「サンプルコード」）。

WebGL で描画する手順

JavaScript から WebGL を使って描画するまでの手順は、次のとおりです。

  1. キャンバスから WebGL 2.0 のコンテキスト（描画の命令を受け付けるオブジェクト）を取得する。

  2. 頂点シェーダーとフラグメントシェーダーのソースコードをコンパイルする。

  3. 2 つのシェーダーをリンクして、1 つのプログラムにする。

  4. 頂点データをバッファーに入れて GPU に転送し、シェーダーの入力との対応を設定する。

  5. 使うプログラムを選び、描画の命令を出す。

シェーダーは、JavaScript の実行中にブラウザー（実際には GPU のドライバー）によってコンパイルされます。C 言語のように事前にコンパイルしておく必要はありません。

三角形を描く

最初のサンプルとして、画面にオレンジ色の三角形を 1 枚描きます。

サンプル 01：三角形の描画

ブラウザーで開く／ダウンロード／シェーダー：01_triangle.vert、01_triangle.frag

頂点シェーダー

01_triangle.vert（頂点シェーダー）
#version 300 es

// 頂点属性：JavaScript から渡される頂点の位置 (x, y)
layout(location = 0) in vec2 aPosition;

void main() {
    // 頂点の位置をクリップ座標として出力する（z = 0.0、w = 1.0）
    gl_Position = vec4(aPosition, 0.0, 1.0);
}

各行の意味は次のとおりです。

  • #version 300 es は、このシェーダーが GLSL ES 3.00 で書かれていることを示します。この行は、シェーダーの先頭行に書く必要があります。前に空行やコメントを置くことはできません。

  • layout(location = 0) in vec2 aPosition; は、頂点ごとに JavaScript から渡される入力（頂点属性）の宣言です。vec2 は 2 個の float からなるベクトルの型、in は入力であることを表します。layout(location = 0) は、この入力に 0 番という番号を割り当てています。JavaScript からはこの番号を指定してデータを渡します。

  • main 関数が、頂点ごとに 1 回実行される処理の本体です。引数も戻り値もありません。

  • gl_Position は、頂点の位置を出力するための組み込み変数です。4 成分のベクトル（vec4）で、vec4(aPosition, 0.0, 1.0) は、aPosition の 2 成分に z = 0.0 と w = 1.0 を加えて 4 成分にしています。

gl_Position に書き込んだ座標は、x と y がそれぞれ -1 から 1 の範囲にある場合に画面内に表示されます。x = -1 がキャンバスの左端、x = 1 が右端、y = -1 が下端、y = 1 が上端です。この座標系と w の意味は第 7 章で詳しく説明します。

フラグメントシェーダー

01_triangle.frag（フラグメントシェーダー）
#version 300 es

// フラグメントシェーダーでは float の精度を必ず指定する
precision highp float;

// 出力変数：このフラグメントの色 (R, G, B, A)。各成分は 0.0 から 1.0
out vec4 outColor;

void main() {
    outColor = vec4(1.0, 0.5, 0.2, 1.0);  // オレンジ色
}

  • precision highp float; は、float 型の計算精度を指定します。フラグメントシェーダーでは float の精度に既定値がないため、この指定を省略するとコンパイルエラーになります（第 4 章）。

  • out vec4 outColor; は、フラグメントシェーダーの出力変数の宣言です。この変数に代入した値が、フラグメントの色になります。変数名は自由に付けられます。

  • 色は赤（R）、緑（G）、青（B）、不透明度（A）の 4 成分で表し、各成分は 0.0 から 1.0 の範囲で指定します。vec4(1.0, 0.5, 0.2, 1.0) は、赤が強く、緑が中くらい、青が弱い不透明な色、つまりオレンジ色です。

JavaScript の処理

シェーダーをコンパイルしてリンクする関数は、次のとおりです。以降のサンプルでも同じ関数を使います。

シェーダーのコンパイルとリンク
// シェーダーのソースコードをコンパイルする
function compileShader(gl, type, source) {
    const shader = gl.createShader(type);
    gl.shaderSource(shader, source);
    gl.compileShader(shader);
    if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
        const message = gl.getShaderInfoLog(shader);
        gl.deleteShader(shader);
        throw new Error("シェーダーのコンパイルに失敗しました。\n" + message);
    }
    return shader;
}

// 頂点シェーダーとフラグメントシェーダーをリンクして、プログラムを作る
function createProgram(gl, vertexSource, fragmentSource) {
    const vertexShader = compileShader(gl, gl.VERTEX_SHADER, vertexSource);
    const fragmentShader = compileShader(gl, gl.FRAGMENT_SHADER, fragmentSource);
    const program = gl.createProgram();
    gl.attachShader(program, vertexShader);
    gl.attachShader(program, fragmentShader);
    gl.linkProgram(program);
    // リンクが終わればシェーダーオブジェクトは不要になる
    gl.deleteShader(vertexShader);
    gl.deleteShader(fragmentShader);
    if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
        throw new Error("プログラムのリンクに失敗しました。\n" + gl.getProgramInfoLog(program));
    }
    return program;
}

// <script> 要素からシェーダーのソースコードを取り出す。
// "#version 300 es" を先頭行にするため、前後の空白と改行を取り除く。
function getShaderSource(id) {
    return document.getElementById(id).textContent.trim();
}

コンパイルやリンクに失敗した場合は、getShaderInfoLog と getProgramInfoLog でエラーの内容を取得できます。サンプルでは、この内容をキャンバスの下に表示します。

getShaderSource 関数では、<script> 要素の文字列の前後の空白と改行を trim で取り除いています。<script> タグの直後の改行が残っていると、#version 300 es が先頭行ではなくなり、コンパイルエラーになるためです。

頂点データの準備と描画は、次のとおりです。

頂点データの準備と描画
// 三角形の 3 つの頂点の位置 (x, y)。画面の中央が (0, 0)、端が -1 と 1 になる
const positions = new Float32Array([
     0.0,  0.6,  // 上
    -0.6, -0.6,  // 左下
     0.6, -0.6,  // 右下
]);

// 頂点配列オブジェクト (VAO)：頂点属性の設定をまとめて記録する
const vao = gl.createVertexArray();
gl.bindVertexArray(vao);

// 頂点バッファー：頂点データを GPU のメモリに転送する
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW);

// location = 0 の頂点属性 (aPosition) に、float 2 個を 1 組として読み込ませる
gl.enableVertexAttribArray(0);
gl.vertexAttribPointer(0, 2, gl.FLOAT, false, 0, 0);

// ---- (4) 描画 ----
gl.viewport(0, 0, canvas.width, canvas.height);
gl.clearColor(0.1, 0.1, 0.1, 1.0);  // 背景色
gl.clear(gl.COLOR_BUFFER_BIT);

gl.useProgram(program);
gl.bindVertexArray(vao);
gl.drawArrays(gl.TRIANGLES, 0, 3);  // 3 頂点で三角形を 1 枚描く

  • バッファー（createBuffer）は、GPU のメモリ上に確保するデータの領域です。bufferData で頂点データを転送します。

  • vertexAttribPointer(0, 2, gl.FLOAT, false, 0, 0) は、「0 番の頂点属性には、バッファーから float を 2 個ずつ読み込む」という設定です。これにより、頂点シェーダーの aPosition にデータが渡されます。引数の詳しい意味は第 6 章で説明します。

  • 頂点配列オブジェクト（VAO、Vertex Array Object）は、頂点属性の設定をまとめて記録するオブジェクトです。描画の前に bindVertexArray で VAO を選ぶだけで、記録した設定が使われます。

  • drawArrays(gl.TRIANGLES, 0, 3) は、0 番目から 3 個の頂点を使って三角形を描く命令です。この命令により、頂点シェーダーが 3 回実行され、続いて三角形が覆う画素の数だけフラグメントシェーダーが実行されます。

注釈

キャンバスの幅は 600 ピクセル、高さは 400 ピクセルなので、x 方向の 1 と y 方向の 1 は画面上の長さが異なります。そのため、三角形は横に引き伸ばされて表示されます。縦横比を正しく扱う方法は、第 7 章と第 8 章で説明します。

試してみよう

ダウンロードしたサンプルを次のように書き換え、ブラウザーで再読み込みして結果を確かめてください。

  • フラグメントシェーダーの outColor の値を変えて、三角形の色を変える。

  • JavaScript の positions の値を変えて、三角形の形を変える。x や y に 1 より大きい値を指定すると、三角形の一部が画面の外に出て切り取られることを確かめる。

  • フラグメントシェーダーの precision highp float; の行を削除して、キャンバスの下にエラーメッセージが表示されることを確かめる。

うまく動かない場合

キャンバスに何も表示されない場合は、次の点を確認してください。

  • キャンバスの下にエラーメッセージが表示されていないか。シェーダーのコンパイルエラーの場合は、エラーのある行の番号が表示されます。

  • ブラウザーの開発者ツール（多くのブラウザーでは F12 キーで開きます）のコンソールに、エラーや警告が表示されていないか。

  • 「このブラウザーは WebGL 2.0 に対応していません。」と表示される場合は、第 1 章の「動作環境」を確認してください。

エラーの調べ方は、第 15 章で詳しく説明します。
