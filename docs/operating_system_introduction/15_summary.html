15. まとめ

本書では、OS が何を抽象化し、どのように資源を管理しているかを軸に、OS の仕組みを説明してきました。最後に、各章の要点を振り返り、さらに学ぶための道筋を示します。

15.1. 各章の要点

表 15.1 各章の要点

章

要点

OS とは何か

OS は、ハードウェアを使いやすく抽象化する拡張機械であり、資源を公平かつ効率よく割り当てる資源管理者である。中核のカーネルはカーネルモードで動き、アプリケーションはシステムコールで処理を依頼する

OS の歴史

OS の機能の多くは、計算機を遊ばせない、利用者を待たせない、互いに干渉させない、といった各時代の問題への答えとして生まれた

ハードウェアとカーネル

特権モード、割り込み、タイマーといったハードウェアの機能が OS を支えている。システムコールは関数呼び出しより費用が大きい

プロセス

プロセスは実行中のプログラムで、独立したアドレス空間を持つ。fork と exec、または CreateProcess で作られ、プロセス間通信でデータをやり取りする

スレッドと並行性

スレッドはアドレス空間を共有するため、競合状態を排他制御で防ぐ必要がある。排他制御はデッドロックを招くことがある

CPU スケジューリング

スケジューリングの方式には、それぞれ得意な指標と不得意な指標がある。実際の OS は公平性や応答性のバランスをとった方式を使っている

メモリ管理

ページングと TLB でアドレスを変換し、仮想記憶で物理メモリより大きなメモリを提供する。ワーキングセットが収まらないとスラッシングが起きる

ストレージとファイルシステム

ファイルシステムは inode やディレクトリでファイルを管理する。ページキャッシュで高速化し、ジャーナリングなどでクラッシュに備える

入出力とデバイス

デバイスドライバが装置の違いを吸収する。多数の接続を扱うには I/O 多重化や非同期 I/O を使う

OS とネットワーク

アプリケーションはソケットで通信し、プロトコルの処理はカーネルのプロトコルスタックが担う

セキュリティと保護

最小権限の原則、アクセス制御、多層的な防御機構、サンドボックス、起動の検証によって計算機を守る

仮想化とコンテナ

仮想マシンはハードウェアを、コンテナはカーネルの資源の見え方を仮想化する。隔離の強さと軽さのトレードオフがある

OS を観察する

OS の状態は多くの道具で観察できる。性能の問題は資源ごとに体系的に切り分ける

15.2. 本書を貫く考え方

個々の仕組みの背後には、OS 全体に共通する考え方があります。

  • 抽象化：OS は、CPU をプロセスやスレッドに、メモリを仮想アドレス空間に、ストレージをファイルに、ネットワークをソケットに置き換え、「資源を占有しているかのような幻想」を各プログラムに与えます。仮想マシンやコンテナも、同じ考え方の延長にあります。

  • 間接参照：論理アドレスと物理アドレス、ファイルディスクリプタとファイル、ファイル名と inode のように、OS は間に 1 段の対応表を挟むことで、配置の自由、共有、保護を実現しています。

  • キャッシュと局所性：TLB、ページキャッシュ、CPU のキャッシュのように、よく使うものを速い場所に置いておく工夫が、OS の性能を支えています。そして、その効果はプログラムの局所性に依存しています。

  • トレードオフ：性能と保護、応答性とスループット、公平性と効率、隔離の強さと軽さなど、OS の設計は常に相反する目標のバランスをとる作業です。どの方式にも、得意な場面と不得意な場面があります。

これらの考え方は、OS だけでなく、データベース、分散システム、プログラミング言語の実行環境など、他の多くのソフトウェアの設計にも共通しています。

15.3. 次に学ぶべきこと

本書は入門書であり、多くの話題を簡単に紹介するにとどめています。さらに理解を深めるための方向性を挙げます。

  • 教科書で体系的に学ぶ：「参考文献」に挙げた OS の教科書は、本書の各章の内容をより詳しく、厳密に扱っています。特に OSTEP（Operating Systems: Three Easy Pieces）は、Web で無償で読むことができます。

  • システムプログラミングを学ぶ：C 言語でシステムコールを直接使うプログラムを書くと、OS のふるまいをより直接的に体験できます。Linux であれば、The Linux Programming Interface が詳しい解説書です。

  • 実際のカーネルを読む：Linux のソースコードは公開されています。最初は全体を読もうとせず、fork や read のような 1 つのシステムコールの処理を追ってみるのがよいでしょう。教育用の小さな OS（MIT の xv6 など）は、全体を読み通せる規模で書かれています。

  • OS を作ってみる：教育用の OS を自分で作る書籍や講座も多くあります。ブートローダーから始めて、割り込み、メモリ管理、プロセスの切り替えを自分で実装すると、本書で学んだ仕組みが確かな理解に変わります。

  • 性能分析を学ぶ：実務では、OS の知識は性能の問題の解決に最も役立ちます。perf や eBPF を使った分析の手法を学ぶと、本書の知識を実際の問題に活かせるようになります。

OS は、計算機の上で動くすべてのソフトウェアの土台です。OS の中で何が起きているかを想像できるようになれば、ソフトウェアのふるまいを、より深く、より正確に理解できるようになるはずです。
