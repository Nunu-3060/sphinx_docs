3. OS の歴史

この章では、OS がどのような問題を解決するために生まれ、どのように発展してきたかをたどります。現在の OS が持つ機能の多くは、過去のある時点で、その時代の切実な問題に対する答えとして導入されたものです。歴史を知ることで、「なぜ OS はこうなっているのか」という問いに答えられるようになります。

3.2. OS 以前の時代

1940 年代から 1950 年代前半の初期の電子計算機には、OS と呼べるものはありませんでした。計算機は非常に高価で、1 台を多くの利用者が共有していました。

当時の計算機の使い方は、およそ次のようなものでした。

  1. 利用者は計算機の使用時間を予約する。

  2. 予約した時間になると計算機室に入り、プログラムをパンチカードや紙テープから読み込ませる。

  3. 操作卓のスイッチやランプを使って、プログラムの実行を開始し、結果を確かめる。

  4. 時間が来たら、次の利用者に交代する。

この方式には大きな無駄がありました。利用者がカードを準備したり、結果を確かめたりしている間、計算機は何もせずに待っています。計算機の価格に比べて人間の時間ははるかに安かったため、計算機が遊んでいる時間を減らすことが最大の課題でした。

また、カードを読み込む処理やプリンターに出力する処理は、どのプログラムにも共通して必要です。こうした共通の処理をまとめたサブルーチンのライブラリが作られ、各プログラムから呼び出して使うようになりました。これが、OS が提供する入出力機能の原型です。

3.3. バッチ処理の時代

計算機の遊んでいる時間を減らすために考え出されたのが、バッチ処理です。

利用者は計算機を直接操作する代わりに、プログラムとデータをパンチカードの束にして、オペレーターと呼ばれる専門の係員に渡します。オペレーターは、複数の利用者の仕事（ジョブ）をまとめて計算機に読み込ませ、順に実行させます。

ジョブからジョブへの切り替えを自動化するために、常駐モニタと呼ばれるプログラムが作られました。常駐モニタは計算機のメモリに常に置かれ、次の仕事を行います。

  • ジョブを 1 つ読み込み、実行を開始する。

  • ジョブが終了したら、制御を取り戻して次のジョブを読み込む。

  • ジョブが異常終了したら、それを記録して次のジョブに進む。

ジョブには、どのコンパイラを使うか、どのデータを読むかといった指示を、特別な制御カードで書き加えました。この指示を記述する言語はジョブ制御言語（JCL）と呼ばれます。JCL は、現在のシェルスクリプトの遠い祖先といえます。

1956 年に、ゼネラルモーターズ社と北米航空社が IBM 704 のために作った GM-NAA I/O は、こうした常駐モニタの初期の例で、最初期の OS の 1 つとされています。その後、FORTRAN のプログラムを連続して処理する FMS（Fortran Monitor System）や、IBM が提供した IBSYS など、バッチ処理の OS が次々に作られました。

バッチ処理は計算機の利用率を高めましたが、利用者にとっては不便な方式でした。ジョブを提出してから結果を受け取るまでに数時間から 1 日かかることもあり、プログラムにわずかな誤りがあれば、また 1 からやり直しです。

3.3.1. 保護の必要性

常駐モニタが現れると、新しい問題が生じました。ジョブのプログラムに誤りがあり、常駐モニタのメモリ領域を書き換えてしまうと、後続のすべてのジョブが実行できなくなります。また、無限ループに陥ったジョブは、計算機を永遠に占有してしまいます。

この問題に対処するため、ハードウェアに次のような機能が追加されていきました。

  • メモリ保護：ジョブが常駐モニタの領域にアクセスできないようにする。

  • タイマー：一定時間が経過すると割り込みを起こし、常駐モニタに制御を戻す。

  • 特権命令：入出力装置の操作など、危険な命令は常駐モニタだけが実行できるようにする。

これらは、現在の CPU が持つメモリ保護、タイマー割り込み、カーネルモードとユーザーモードの区別の原型です。OS とハードウェアは、このように互いに影響し合いながら発展してきました。

3.4. マルチプログラミング

バッチ処理によって人間の操作による待ち時間は減りましたが、まだ大きな無駄が残っていました。入出力の待ち時間です。

当時の入出力装置（カード読み取り装置、磁気テープ、プリンター）は、CPU に比べて桁違いに低速でした。1 つのジョブだけを実行している場合、ジョブが入出力の完了を待っている間、CPU は何もできません。科学技術計算のように計算が中心のジョブはまだしも、事務処理のように入出力が中心のジョブでは、CPU の時間の大部分が待ちに費やされていました。

そこで考え出されたのが、マルチプログラミングです。メモリに複数のジョブを同時に置いておき、あるジョブが入出力を待っている間は、別のジョブに CPU を使わせます。こうすれば、CPU が遊ぶ時間を大きく減らせます。

マルチプログラミングを実現するには、OS に次の機能が必要です。

  • 複数のジョブにメモリを分けて割り当て、互いに保護する機能（メモリ管理）

  • 次にどのジョブに CPU を使わせるかを決める機能（CPU スケジューリング）

  • 入出力の完了を割り込みで知り、待っていたジョブを再開させる機能（割り込み処理）

これらは、現在の OS の中核機能そのものです。マルチプログラミングは、OS が単なる「ジョブの切り替え係」から「資源の管理者」へと変わる転換点でした。

また、遅い入出力装置を効率よく使うために、スプーリング（SPOOL：Simultaneous Peripheral Operations On-Line）という技術も使われるようになりました。カードの読み込みやプリンターへの出力を、高速な磁気ディスクを介して計算と並行して行う技術です。現在でも、プリンターへの出力を一時的に溜めておく仕組みをスプーラーと呼ぶのは、この名残です。

3.4.1. OS/360 とソフトウェア開発の難しさ

1964 年、IBM は System/360 という計算機のシリーズを発表しました。System/360 は、小型機から大型機までが同じ命令セットを持ち、同じソフトウェアが動くという画期的な製品でした。そのすべての機種で動く OS として開発されたのが OS/360 です。

OS/360 はマルチプログラミングを含む多くの機能を備えた野心的な OS でしたが、その開発は困難を極めました。開発には数千人の人員が投入され、予定は大幅に遅れ、出荷後も大量の不具合が見つかりました。開発の責任者だったブルックス（Frederick P. Brooks, Jr.）は、この経験をもとに著書『人月の神話』を書き、「遅れているソフトウェアプロジェクトに人員を追加すると、さらに遅れる」という有名な法則を述べました。OS の開発は、大規模なソフトウェア開発の難しさが初めて広く認識された分野でもあります。

3.5. タイムシェアリング

マルチプログラミングによって計算機の利用率は高まりましたが、利用者がジョブを提出してから結果を受け取るまでの時間は相変わらず長いままでした。プログラムを書きながら試行錯誤したい利用者にとって、これは大きな不満でした。

そこで考え出されたのが、タイムシェアリング（時分割）です。計算機に複数の端末（キーボードと表示装置）をつなぎ、多数の利用者が同時に対話的に計算機を使えるようにします。OS は、CPU の時間を短い時間（タイムスライス）に区切り、各利用者のプログラムに順番に割り当てます。切り替えが十分に速ければ、各利用者は計算機を独占しているように感じられます。

マルチプログラミングとタイムシェアリングの違いは、何を重視するかにあります。

タイマーによって実行中のプログラムから強制的に CPU を取り上げる方式は、プリエンプション（横取り）と呼ばれます。プリエンプションは、現在のほぼすべての汎用 OS で使われています。詳しくは「CPU スケジューリング」で説明します。

3.5.1. CTSS

タイムシェアリングの最初の本格的な実証は、1961 年にマサチューセッツ工科大学（MIT）のコルバト（Fernando J. Corbató）らが開発した CTSS（Compatible Time-Sharing System）です。CTSS は IBM の 709 や 7094 の上で動き、複数の利用者が端末から同時にプログラムを編集、実行できました。

CTSS は、パスワードによる利用者の認証、利用者ごとのファイルの保存、テキストエディタ、さらには利用者間で送り合う電子メールの原型など、現在の OS につながる多くの機能を持っていました。コルバトは、タイムシェアリングの研究への貢献により、1990 年にチューリング賞を受賞しています。

3.5.2. Multics

CTSS の成功を受けて、1965 年に MIT、ゼネラル・エレクトリック社（GE）、ベル研究所の共同プロジェクトとして Multics（Multiplexed Information and Computing Service）の開発が始まりました。Multics は、電気や水道のように、誰もがいつでも利用できる「計算の公共サービス」を実現することを目指していました。

Multics は、次のような先進的な機能を備えていました。

  • 階層的なファイルシステム（ディレクトリの中にディレクトリを置ける）

  • セグメンテーションとページングを組み合わせた仮想記憶

  • リング構造による多段階の保護（第 12 章で説明する保護リングの原型）

  • 実行中のプログラムに外部のプログラムを結合する動的リンク

  • 高級言語（PL/I）による OS の記述

一方で、Multics は非常に複雑で、開発は予定どおりに進みませんでした。ベル研究所は 1969 年にプロジェクトから撤退します。Multics 自体は商用化されて 2000 年まで使われましたが、広く普及することはありませんでした。しかし、その設計思想は後の多くの OS に受け継がれており、特に次に述べる UNIX に大きな影響を与えました。

3.5.3. THE とダイクストラ

同じ時期、オランダのアイントホーフェン工科大学では、ダイクストラ（Edsger W. Dijkstra）らが THE マルチプログラミングシステムを開発していました。1968 年に発表されたこの OS は、規模は小さいものの、OS の設計方法に大きな影響を与えました。

THE は、OS を複数の層に分け、各層は自分より下の層の機能だけを使うという階層構造で設計されていました。このような構造は、各層を独立して設計、検証できるという利点があります。また、ダイクストラは複数のプロセスの協調のためにセマフォという同期機構を考案しました。セマフォは現在でも使われている基本的な同期機構で、「スレッドと並行性」で説明します。

3.5.4. 仮想記憶の誕生

仮想記憶も、この時代に生まれた重要な技術です。1962 年に稼働したイギリスのマンチェスター大学の Atlas は、主記憶（磁気コア）と補助記憶（磁気ドラム）を組み合わせ、プログラムからは大きな 1 つのメモリがあるように見せる仕組みを実現しました。これが仮想記憶の始まりです。

仮想記憶以前は、主記憶に入りきらない大きなプログラムを動かすには、プログラマ自身がプログラムを分割し、必要な部分を補助記憶から読み込むように書く必要がありました（オーバーレイと呼ばれる手法です）。仮想記憶は、この面倒な作業を OS とハードウェアに肩代わりさせるものです。その後、仮想記憶は 1970 年代に IBM の System/370 などの商用機に採用され、広く普及しました。仮想記憶の仕組みは「メモリ管理」で詳しく説明します。

3.6. UNIX の誕生

Multics から撤退したベル研究所のトンプソン（Ken Thompson）は、1969 年、研究所で使われずにいた小型計算機 PDP-7 の上で、小さな OS を作り始めました。これが UNIX です。名前は、複雑な Multics（Multi-）に対して、単純な（Uni-）システムを目指すという洒落から付けられたといわれています。

その後、トンプソンにリッチー（Dennis M. Ritchie）らが加わり、UNIX は PDP-11 に移植されて研究所内で使われるようになりました。

3.6.1. C 言語による書き直し

当時の OS は、ハードウェアの性能を引き出すため、機種ごとのアセンブリ言語で書くのが普通でした。そのため、OS を別の機種に移すことは、ほとんど作り直すことに等しい作業でした。

リッチーは、OS を記述するのに適した高級言語として C 言語を開発し、1973 年に UNIX のカーネルの大部分を C 言語で書き直しました。これにより、UNIX は C コンパイラさえ用意すれば、比較的少ない手間で別の機種に移植できるようになりました。OS の移植性という考え方は、ここから広まりました。

3.6.2. UNIX の設計思想

UNIX は、Multics の多くのアイデアを受け継ぎながら、それらを単純な形にまとめ直しました。UNIX の主な特徴は次のとおりです。

  • 階層的なファイルシステム：すべてのファイルを、ルートディレクトリ / から始まる 1 つの木構造で管理する。

  • すべてはファイル：通常のファイルだけでなく、装置（デバイスファイル）やプロセス間の通信路（パイプ）も、ファイルと同じ操作で読み書きできる。

  • プロセスの生成：fork で自分自身の複製を作り、exec で別のプログラムに置き換えるという単純な仕組みでプロセスを作る（第 5 章で説明します）。

  • シェル：コマンドを解釈するシェルが、カーネルの外の普通のプログラムとして実装されている。

  • パイプ：あるプログラムの出力を、別のプログラムの入力につなげる。

特にパイプは、UNIX の設計思想を象徴する機能です。1 つのことだけをうまくこなす小さなプログラムを多数用意し、パイプでつないで複雑な処理を実現します。例えば次のコマンドは、アクセスログからアクセス元の IP アドレスを取り出し、アクセス数の多い順に 5 件を表示します。

1$ cut -d ' ' -f 1 access.log | sort | uniq -c | sort -rn | head -n 5

この考え方は、UNIX の哲学として今日まで語り継がれています。リッチーとトンプソンは 1974 年に UNIX の論文を発表し、1983 年にチューリング賞を受賞しました。

3.6.3. UNIX の普及と分裂

当時、AT&T（ベル研究所の親会社）は独占禁止法の制約からコンピュータ事業を営めなかったため、UNIX のソースコードを大学などにわずかな費用で提供しました。ソースコードが読めて、しかも小さく理解しやすい UNIX は、大学での OS 教育や研究に広く使われるようになりました。

なかでも重要なのが、カリフォルニア大学バークレー校による改良版です。バークレー校は 1978 年から BSD（Berkeley Software Distribution）として独自の改良版を配布し始め、仮想記憶への対応や、高速なファイルシステムなどを加えていきました。特に 1983 年の 4.2BSD は、TCP/IP の実装と、それを使うためのソケット API を搭載していました。ソケット API はその後、ネットワークプログラミングの事実上の標準となり、現在では Windows を含むほぼすべての OS で使われています（「OS とネットワーク」で説明します）。

一方、1980 年代に入ると AT&T も UNIX を商用化し、System V と呼ばれる系統を販売しました。こうして UNIX は BSD 系と System V 系に分かれ、さらに各コンピュータメーカーが独自の UNIX（Sun Microsystems の SunOS と Solaris、IBM の AIX、HP の HP-UX など）を開発しました。各社の UNIX の間には少しずつ違いがあり、アプリケーションの移植に手間がかかるようになりました。この時期の UNIX のメーカー間の対立は、UNIX 戦争と呼ばれることもあります。

この問題を解決するため、UNIX 系 OS の API を標準化する取り組みが進められ、1988 年に IEEE によって POSIX（IEEE 1003.1）が制定されました。POSIX は現在も改訂が続けられており、Linux や macOS は POSIX にほぼ従っています。

3.7. パーソナルコンピュータの OS

1970 年代半ばにマイクロプロセッサが普及すると、個人が所有できるパーソナルコンピュータ（パソコン）が登場しました。初期のパソコンの OS は、大型計算機の OS に比べるとずっと単純なものでした。

3.7.1. CP/M と MS-DOS

1974 年に、キルドール（Gary Kildall）がマイクロプロセッサ向けの OS である CP/M を開発しました。CP/M は、機種に依存する部分を BIOS（Basic Input/Output System）と呼ばれる部分に分離したことで、多くのメーカーのパソコンに移植され、普及しました。

1981 年、IBM は自社のパソコン IBM PC を発売し、その OS としてマイクロソフト社の MS-DOS（IBM 版の名称は PC DOS）を採用しました。MS-DOS は、シアトル・コンピュータ・プロダクツ社の 86-DOS をもとにしたもので、CP/M とよく似た使い勝手を持っていました。IBM PC とその互換機の普及とともに、MS-DOS はパソコンの標準的な OS となりました。

MS-DOS は、同時に 1 つのプログラムしか実行できないシングルタスクの OS で、メモリ保護の機能もありませんでした。当時のパソコンの CPU（Intel 8086 や 8088）にはメモリ保護の機能がなく、また 1 人が 1 つのプログラムを使うだけなら保護は不要と考えられていたからです。大型計算機で 1960 年代に確立した技術が、パソコンの世界では一度捨てられ、その後のパソコンの性能向上とともに改めて取り入れられていったことは、OS の歴史の興味深い点です。

3.7.2. GUI の登場

利用者インターフェースの面では、ゼロックス社のパロアルト研究所（PARC）が 1973 年に開発した Alto が大きな転換点となりました。Alto は、ウィンドウ、アイコン、マウスを使って操作する GUI を備えていました。

Alto に影響を受けたアップル社は、1983 年に Lisa を、1984 年に Macintosh を発売し、GUI を一般の利用者に広めました。マイクロソフト社も 1985 年に MS-DOS の上で動く GUI 環境として Windows 1.0 を発売し、1990 年の Windows 3.0 で広く普及させました。1995 年の Windows 95 は、32 ビットのアプリケーションへの対応、プリエンプティブなマルチタスク、スタートメニューなどを備え、大きな成功を収めました。

3.7.3. Windows NT

MS-DOS の系譜を引く Windows は、互換性を重視するあまり、信頼性や保護の面で限界を抱えていました。マイクロソフト社は、これとは別に、一から設計し直した新しい OS の開発を進めました。開発を率いたのは、ディジタル・イクイップメント社（DEC）で VMS という OS を設計したカトラー（Dave Cutler）です。

こうして 1993 年に発売されたのが Windows NT 3.1 です。Windows NT は、メモリ保護、プリエンプティブなマルチタスク、マルチプロセッサへの対応、複数の CPU アーキテクチャへの移植性、NTFS ファイルシステム、きめ細かなアクセス制御などを最初から備えていました。

当初、Windows NT は主に業務用とサーバー用でしたが、2001 年の Windows XP で一般向けの Windows も NT 系に一本化されました。現在の Windows 10 や Windows 11 も、Windows NT のカーネルの子孫です。

3.7.4. macOS

アップル社の Macintosh の OS（Mac OS）も、初期にはメモリ保護やプリエンプティブなマルチタスクを持っておらず、1990 年代には限界が明らかになっていました。

一方、アップル社を離れたジョブズ（Steve Jobs）が設立したネクスト社は、1989 年に NeXTSTEP という OS を発表していました。NeXTSTEP は、カーネギーメロン大学（CMU）で開発された Mach と BSD を組み合わせたカーネルの上に、オブジェクト指向の開発環境を載せた OS でした。1997 年にアップル社がネクスト社を買収すると、NeXTSTEP をもとに新しい OS が開発され、2001 年に Mac OS X として発売されました。

Mac OS X の中核部分は Darwin と呼ばれ、そのカーネル XNU は Mach と BSD を組み合わせたものです。現在の macOS も、iPhone の iOS も、この Darwin の上に作られています。そのため macOS は、Linux と同じく UNIX 系 OS に分類されます。

3.8. オープンソースの OS

3.8.1. GNU プロジェクト

1980 年代に入ると、UNIX の商用化が進み、ソースコードは自由に入手できなくなっていきました。これに異を唱えたのが MIT のストールマン（Richard M. Stallman）です。

ストールマンは 1983 年に GNU プロジェクトを発表し、利用者が自由に使い、調べ、改良し、再配布できる、UNIX 互換の OS を作ることを目指しました。GNU は「GNU's Not Unix」の略です。GNU プロジェクトは、コンパイラの GCC、エディタの Emacs、シェルの bash、C 標準ライブラリの glibc、基本的なコマンド群など、OS に必要なソフトウェアを次々に開発しました。また、こうした自由を保証するためのライセンスとして、GPL（GNU General Public License）を作りました。

しかし、OS の中核であるカーネル（GNU Hurd）の開発は難航し、1990 年代初頭になっても実用的な段階に達していませんでした。

3.8.2. MINIX と Linux

1987 年、オランダのタネンバウム（Andrew S. Tanenbaum）は、OS の教育用に小さな UNIX 互換の OS である MINIX を公開しました。MINIX はソースコードが教科書に掲載されており、多くの学生が OS の仕組みを学ぶのに使いました。

フィンランドのヘルシンキ大学の学生だったトーバルズ（Linus Torvalds）も、MINIX を使っていた 1 人でした。トーバルズは、自分のパソコン（Intel 80386 を搭載したもの）の機能を活かすための OS を趣味で作り始め、1991 年にインターネットのニュースグループでその公開を告知しました。これが Linux です。

Linux はカーネルだけで、それ自体では OS として使えませんでしたが、GNU プロジェクトのソフトウェアと組み合わせることで、完全な UNIX 互換の OS となりました。Linux は 1992 年から GPL で配布され、インターネットを通じて世界中の開発者が開発に参加するようになりました。こうした開発の仕方は、それまでの OS 開発とは大きく異なるもので、オープンソース開発の代表例となりました。

なお、Linux の公開直後の 1992 年には、タネンバウムとトーバルズの間で、カーネルの構成（マイクロカーネルかモノリシックカーネルか）をめぐる有名な論争が起きています。この論点は「ハードウェアとカーネル」で扱います。

Linux はその後、Slackware、Debian、Red Hat などのディストリビューションによって利用しやすい形で配布されるようになり、1990 年代後半からはインターネットのサーバーで急速に普及しました。現在では、Web サーバー、クラウド、スーパーコンピュータ、組込み機器、スマートフォン（Android）など、非常に幅広い分野で使われています。

3.8.3. BSD 系 OS

BSD も、AT&T のコードを含まない形に書き直され、1990 年代にオープンソースの OS として再出発しました。現在では、FreeBSD、NetBSD、OpenBSD などが開発されています。BSD 系 OS のライセンスは GPL よりも制約が緩く、商用製品に組み込みやすいという特徴があります。そのため、macOS の一部や、ゲーム機、ネットワーク機器などで BSD 系 OS のコードが使われています。

3.9. 日本の OS：TRON

日本で生まれた OS として、TRON（The Real-time Operating system Nucleus）を紹介しておきます。TRON プロジェクトは、1984 年に東京大学の坂村健によって始められました。TRON プロジェクトは、身の回りのあらゆる機器に計算機が組み込まれ、ネットワークでつながる社会（現在でいう IoT の考え方）を見据え、そのための OS の仕様を定めることを目指していました。

TRON プロジェクトから生まれた仕様のうち、最も広く普及したのが、組込み機器向けのリアルタイム OS の仕様である ITRON です。ITRON は、仕様を公開し、誰でも自由に実装できるという方針をとったため、多くの企業が採用しました。その小型機器向けの版である μITRON は、携帯電話、デジタルカメラ、自動車の制御装置、家電製品など、非常に多くの機器に組み込まれています。

TRON 系の OS は、利用者が意識することはほとんどありませんが、搭載された機器の数でいえば、世界で最も多く使われている OS の 1 つといわれています。

3.10. モバイル OS

2000 年代後半になると、計算機の主役の 1 つがスマートフォンに移りました。

2007 年、アップル社は iPhone を発売しました。その OS（後に iOS と呼ばれます）は、Mac OS X と同じ Darwin をもとに作られています。翌 2008 年には、Google 社が中心となって開発した Android を搭載したスマートフォンが発売されました。Android は Linux カーネルの上に、独自のアプリケーション実行環境を載せた OS です。

モバイル OS は、デスクトップ OS とは異なる要求に応える必要がありました。

  • 電力消費：バッテリーで長時間動かすため、使っていない装置やアプリケーションを積極的に休止させる。

  • アプリケーションの隔離：利用者が入手したさまざまなアプリケーションを安全に動かすため、各アプリケーションをサンドボックスに閉じ込め、カメラや位置情報などへのアクセスには利用者の許可を必要とする。

  • メモリの制約：スワップ領域を持たない、または小さいことが多いため、メモリが不足するとバックグラウンドのアプリケーションを OS が終了させる。

  • タッチ操作と応答性：画面の操作に遅れなく反応することを重視する。

これらの工夫の多くは、その後デスクトップ OS にも取り入れられています。例えば、アプリケーションの権限を細かく制限する仕組みは、現在の Windows や macOS にも備わっています。

3.11. 仮想化とクラウドの時代

3.11.1. 仮想化の起源

1 台の計算機の上で、複数の OS を同時に動かす技術を仮想化と呼びます。仮想化の歴史は古く、1960 年代後半の IBM の CP-67 にさかのぼります。CP-67 は、1 台の計算機の上に、利用者ごとに独立した仮想的な計算機（仮想マシン）を作り出しました。各利用者は、自分専用の計算機の上で、CMS という対話型の OS を使えました。この方式は 1972 年に VM/370 として製品化され、メインフレームの世界では仮想化が一般的な技術となりました。

1974 年には、ポペック（Gerald J. Popek）とゴールドバーグ（Robert P. Goldberg）が、効率よく仮想化できる計算機が満たすべき条件を理論的に示しました。

3.11.2. x86 の仮想化

パソコンやサーバーで使われる x86 系の CPU は、もともとポペックとゴールドバーグの条件を満たしておらず、効率よく仮想化するのが難しいとされていました。この問題をソフトウェアの工夫で解決したのが、1999 年に VMware 社が発売した製品です。その後、ソースコードを変更した OS を仮想マシン上で動かす準仮想化の手法を用いた Xen（2003 年）が登場し、さらにインテル社の VT-x（2005 年）や AMD 社の AMD-V（2006 年）といった、CPU による仮想化の支援機能が導入されました。2007 年には、この支援機能を使う KVM が Linux カーネルに取り込まれています。

3.11.3. クラウドとコンテナ

仮想化の普及は、クラウドコンピューティングを生み出しました。2006 年に Amazon Web Services（AWS）が仮想マシンを時間単位で貸し出すサービスを始めると、利用者は物理的なサーバーを所有せずに、必要なときに必要なだけ計算機の資源を使えるようになりました。これは、Multics が目指した「計算の公共サービス」が、40 年の時を経て形を変えて実現したものともいえます。

さらに、仮想マシンよりも軽量な隔離の方式として、コンテナが普及しました。コンテナは、OS 全体を仮想化するのではなく、1 つのカーネルを共有したまま、プロセスから見えるファイルシステムやネットワーク、プロセスの一覧などを分離する技術です。Linux カーネルには 2000 年代に namespace や cgroup といった機能が順次追加され、2013 年に公開された Docker によって、コンテナは一気に普及しました。仮想化とコンテナについては「仮想化とコンテナ」で詳しく説明します。

ここまで見てきた OS の歴史には、いくつかの共通する流れがあります。

流れ

内容

計算機の時間から人間の時間へ

初期の OS は高価な計算機を遊ばせないことを最優先したが、計算機が安くなるにつれて、利用者の待ち時間を減らすこと（応答性）が重視されるようになった

技術の再発見

メモリ保護やマルチタスクなど、大型計算機で確立した技術が、パソコン、さらにはスマートフォンや組込み機器でも、性能の向上とともに改めて採用されてきた

ハードウェアとの協調

特権モード、タイマー、メモリ保護、仮想化支援など、OS の要求に応じてハードウェアに機能が追加されてきた

標準化とオープン化

互換性の問題から POSIX などの標準化が進み、GNU や Linux によってソースコードが公開された OS が主流の 1 つになった

隔離の単位の多様化

プロセス、仮想マシン、コンテナ、サンドボックスと、プログラムを互いに隔離する方法が増え、用途に応じて使い分けられるようになった

現在の OS が持つ機能のほとんどは、これらの流れの中で、具体的な問題を解決するために生まれたものです。次章からは、これらの機能の仕組みを 1 つずつ見ていきます。

3.13. まとめ

  • 初期の計算機には OS がなく、計算機が遊ぶ時間を減らすためにバッチ処理と常駐モニタが生まれました。

  • 入出力の待ち時間を有効に使うためにマルチプログラミングが、利用者の応答時間を短くするためにタイムシェアリングが生まれ、CPU スケジューリングやメモリ管理といった OS の中核機能が形作られました。

  • Multics の思想を単純な形にまとめ直した UNIX は、C 言語による移植性と簡潔な設計で広く普及し、BSD、System V、POSIX、Linux、macOS へとつながりました。

  • パソコンでは MS-DOS から Windows NT へ、Mac OS から macOS へと、大型計算機で確立した保護やマルチタスクの技術が改めて取り入れられました。

  • モバイル OS、仮想化、クラウド、コンテナによって、OS に求められる役割は今も広がり続けています。
