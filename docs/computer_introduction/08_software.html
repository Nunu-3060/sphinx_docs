8. ソフトウェアと計算機

「計算機の構成」までで、機械語のプログラムを実行するハードウェアができあがりました。しかし、私たちが普段書いているのは機械語ではなく、Python や C のような言語のプログラムです。また、プログラムはオペレーティングシステムの上で、他の多くのプログラムと同時に動いています。この章では、私たちが書いたプログラムがハードウェアの上で実行されるまでの仕組みを説明します。

8.1. 機械語とアセンブリ言語

CPU が直接実行できるのは、命令セットアーキテクチャで定められたビット列の命令、すなわち機械語だけです。機械語は人間には読み書きしにくいため、命令を ADD や LOAD のような短い英単語（ニーモニック）で表したアセンブリ言語が使われます。アセンブリ言語のプログラムは、アセンブラと呼ばれるプログラムによって機械語に変換されます。アセンブリ言語の命令と機械語の命令は、原則として 1 対 1 に対応します。

「計算機の構成」の簡易 CPU では、LOAD 21 というアセンブリ言語の命令が、機械語の 121 に対応していました。実際の CPU の例として、2 つの整数を足す C 言語の関数を見てみます。

1int add(int a, int b) {
2    return a + b;
3}

この関数を、64 ビットの RISC-V 向けに最適化を有効にしてコンパイルすると、次のようなアセンブリ言語のプログラムになります。

1add:
2    addw a0, a0, a1
3    ret

RISC-V では、関数の引数は a0、a1 などのレジスタで渡し、戻り値は a0 で返すという約束（呼び出し規約）があります。addw は 32 ビットの整数を加算する命令で、a0 と a1 を足して a0 に格納します。ret は呼び出し元に戻る命令です。

addw a0, a0, a1 を機械語にすると、「計算機の構成」で紹介した R 形式に従って、次の 32 ビットになります。a0 はレジスタ x10、a1 はレジスタ x11 の別名です。

8.2. 高級言語

アセンブリ言語は機械語と 1 対 1 に対応するため、CPU の命令セットアーキテクチャごとに異なり、大きなプログラムを書くのは大変です。そこで、CPU の詳細から独立して、人間にとって分かりやすい形で処理を記述できる高級言語（高水準言語）が使われます。FORTRAN、COBOL、C、Java、Python などが高級言語です。

高級言語のプログラムを実行する方法には、大きく分けてコンパイラ方式とインタプリタ方式があります。

8.2.1. コンパイラ

コンパイラは、高級言語のプログラム（ソースコード）を、実行前にまとめて機械語のプログラムに変換します。コンパイラは、一般に次の段階で処理を行います。

表 8.2 コンパイラの処理の流れ

段階

処理内容

字句解析

ソースコードの文字の並びを、識別子、数値、演算子などの単位（トークン）に区切る。

構文解析

トークンの並びが文法に合っているかを調べ、プログラムの構造を表す木（構文木）を作る。

意味解析

変数の宣言や型が正しいかを調べる。

中間コード生成

特定の CPU に依存しない中間表現に変換する。

最適化

不要な計算の削除や、ループの変形などにより、プログラムを高速化する。

コード生成

対象の CPU の機械語を生成する。

中間表現を使うことで、言語ごとの解析部分と CPU ごとのコード生成部分を独立して作れます。例えば、コンパイラ基盤の LLVM は、C、C++、Rust、Swift などの言語から、x86-64、ARM、RISC-V などの CPU 向けの機械語を生成できます。

コンパイラが生成した機械語は、ライブラリなどの他の機械語のプログラムと結合（リンク）されて、実行可能なファイルになります。実行時には変換の手間がかからないので、高速に動作します。C、C++、Rust、Go などがこの方式を主に使っています。

8.2.2. インタプリタ

インタプリタは、ソースコードを機械語に変換せず、命令を 1 つずつ解釈しながら実行するプログラムです。インタプリタ自体は機械語で動作しており、ソースコードを「データ」として読み込んで、その意味に従った処理を行います。これは、「計算の理論」で説明した万能チューリングマシンが、テープに書かれた遷移規則を読み込んで実行するのと同じ構図です。

インタプリタ方式は、コンパイルの手間がなく、すぐに実行して結果を確かめられる一方、解釈の手間がかかるため、一般にコンパイラ方式よりも実行速度が遅くなります。

8.2.3. 仮想マシンと JIT コンパイラ

実際の言語処理系の多くは、両方の方式を組み合わせています。Java や Python（CPython）は、ソースコードをまずバイトコードと呼ばれる仮想的な命令列にコンパイルし、それを仮想マシン（ソフトウェアで作られた架空の CPU）で解釈して実行します。

Python では、標準ライブラリの dis モジュールでバイトコードを確認できます。

1import dis
2
3
4def add(a: int, b: int) -> int:
5    return a + b
6
7
8dis.dis(add)

Python 3.14 で実行すると、次のように表示されます。バイトコードの命令は Python のバージョンによって異なります。

4           RESUME                   0

5           LOAD_FAST_BORROW_LOAD_FAST_BORROW 1 (a, b)
            BINARY_OP                0 (+)

左端の数字はソースコードの行番号です。変数 a と b の値を読み込み、加算し、結果を返すという処理が、仮想マシンの命令で表されていることが分かります。

さらに、Java の仮想マシンや JavaScript の処理系などは、実行中に頻繁に使われる部分のバイトコードを、その場で機械語にコンパイルする JIT コンパイラ（Just-In-Time コンパイラ）を備えています。これにより、インタプリタの柔軟性とコンパイラの速度を両立しています。

8.3. オペレーティングシステム

計算機の上では、Web ブラウザ、エディタ、音楽プレイヤーなど、多数のプログラムが同時に動いています。これらのプログラムが、限られた CPU、主記憶、入出力装置を安全かつ効率よく共有できるように管理するソフトウェアがオペレーティングシステム（OS）です。Windows、macOS、Linux、Android、iOS などが代表的な OS です。

OS の中心となる部分をカーネルと呼びます。OS の主な役割は、ハードウェアの管理と、ハードウェアの違いを隠して、アプリケーションが使いやすい共通の機能を提供すること（抽象化）です。

8.3.1. カーネルモードとシステムコール

アプリケーションが自由にハードウェアを操作できると、1 つのプログラムの誤りや悪意によって、他のプログラムや計算機全体が壊れてしまう恐れがあります。そこで CPU は、少なくとも 2 つの動作モードを持っています。

カーネルモード（特権モード）

すべての命令を実行でき、すべてのハードウェアにアクセスできるモードです。カーネルはこのモードで動作します。

ユーザモード

入出力装置の直接操作など、一部の命令が禁止されたモードです。アプリケーションはこのモードで動作します。

ユーザモードのアプリケーションがファイルの読み書きなどを行いたい場合は、システムコールと呼ばれる専用の命令でカーネルに処理を依頼します。システムコールが実行されると、CPU はカーネルモードに切り替わり、カーネルが処理を行った後、ユーザモードに戻ってアプリケーションの実行を再開します。Python の open() や print() も、内部ではシステムコールを使っています。

8.3.2. プロセスとスレッド

実行中のプログラムをプロセスと呼びます。OS は、プロセスごとに独立した記憶領域を割り当て、プロセス同士が互いの記憶領域を勝手に読み書きできないようにします。

CPU のコアが 1 個しかなくても、OS は数ミリ秒程度の短い時間ごとに実行するプロセスを切り替えることで、多数のプロセスが同時に動いているように見せます。これをタイムシェアリングと呼び、どのプロセスをどれだけ実行するかを決める OS の機能をスケジューラと呼びます。プロセスを切り替えるときは、実行中のプロセスのレジスタの値などを保存し、次のプロセスの値を復元します。これをコンテキストスイッチと呼びます。プロセスの切り替えのきっかけには、「計算機の構成」で説明した割り込み（タイマーによる定期的な割り込み）が使われます。

1 つのプロセスの中で、記憶領域を共有しながら並行して動く実行の流れをスレッドと呼びます。スレッドを使うと、1 つのプログラムの処理を複数の CPU コアで並列に実行できます。並列処理については「現代の計算機」で説明します。

8.3.3. 仮想記憶

仮想記憶は、各プロセスに、あたかも自分専用の広大な主記憶があるかのように見せる仕組みです。

プロセスが使うアドレス（仮想アドレス）は、CPU の中の MMU（Memory Management Unit）と呼ばれる回路によって、実際の主記憶のアドレス（物理アドレス）に変換されます。変換は、ページと呼ばれる一定の大きさ（例えば 4 KB）の単位で行い、その対応表をページテーブルと呼びます。アドレス変換を高速にするため、最近使った変換結果は TLB（Translation Lookaside Buffer）と呼ばれる専用のキャッシュに保持されます。

仮想記憶には次の利点があります。

  • プロセスごとにページテーブルを分けることで、各プロセスの記憶領域を隔離し、保護できます。

  • 主記憶上で連続していない領域を、プロセスからは連続した領域として見せられます。

  • 使用頻度の低いページを SSD などの補助記憶に退避させることで、物理的な主記憶の容量よりも大きな記憶領域を使えます。プロセスが補助記憶に退避されたページにアクセスすると、ページフォルトと呼ばれる割り込みが発生し、OS がそのページを主記憶に読み戻します。

8.3.4. ファイルシステムとデバイスドライバ

SSD や HDD は、本来は番号の付いたブロックの並びにすぎません。OS のファイルシステムは、これを名前の付いたファイルと、階層的なディレクトリ（フォルダ）として見せる機能です。

また、入出力装置の種類や製品ごとの違いは、デバイスドライバと呼ばれるソフトウェアが吸収します。アプリケーションは、どのメーカーの SSD であっても、同じシステムコールでファイルを読み書きできます。

論理回路

抽象化のおかげで、Python のプログラマはトランジスタの動作を意識せずにプログラムを書けますし、CPU の設計者はどんなアプリケーションが動くかを知らなくても CPU を設計できます。

一方で、性能の問題や不具合の原因は、しばしば階層の境界に潜んでいます。キャッシュを意識したデータ配置で処理が何倍も速くなったり、浮動小数点数の丸め誤差が計算結果を狂わせたりするのはその例です。下の階層の仕組みを知っておくことは、上の階層で良いソフトウェアを作るための助けになります。

8.5. この章のまとめ

  • CPU が直接実行できるのは機械語だけです。アセンブリ言語は機械語を人間が読める形で表したものです。

  • 高級言語のプログラムは、コンパイラで機械語に変換するか、インタプリタや仮想マシンで解釈して実行します。

  • OS は、プロセス、仮想記憶、ファイルシステムなどの抽象化を提供し、ハードウェアを安全かつ効率よく共有できるようにします。

  • 計算機は、トランジスタからアプリケーションまでの抽象化の階層でできています。
