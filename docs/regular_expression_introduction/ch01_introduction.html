1. はじめに

1.1. 正規表現とは

正規表現は、文字列の「形」を記述するための小さな言語である。たとえば「数字が 3 個、ハイフン、数字が 4 個」という形は、正規表現では \d{3}-\d{4} と書ける。この記述をパターンと呼ぶ。パターンを使うと、文字列の中からその形に一致する部分を探したり、文字列全体がその形になっているかを確かめたりできる。

正規表現の起源は、1950 年代に数学者スティーヴン・クリーネが考案した形式言語の理論にある。1960 年代後半にケン・トンプソンがテキストエディター QED に実装し、その後 ed や grep などの UNIX のツールを通じて広まった。現在では、ほとんどのプログラミング言語、テキストエディター、データベース、コマンドラインツールが正規表現に対応している。

1.2. 何に使うのか

正規表現の用途は、大きく次の 4 つに分けられる。

表 1.1 正規表現の主な用途

用途

内容

例

検索

文字列の中にパターンに一致する部分があるかを調べる

ログから ERROR を含む行を探す

検証

文字列全体がパターンの形になっているかを調べる

入力された郵便番号が 123-4567 の形かを確かめる

抽出

一致した部分や、その一部を取り出す

ログの各行から日時とメッセージを取り出す

置換

一致した部分を別の文字列に置き換える

2026/10/19 を 2026-10-19 に書き換える

正規表現を使わなくても、Python の文字列メソッドだけで同じ処理を書くことはできる。たとえば「数字 3 個、ハイフン、数字 4 個」かどうかを調べる処理は次のようになる。

リスト 1.1 文字列メソッドだけで郵便番号の形を調べる
1def is_postal_code(s: str) -> bool:
2    if len(s) != 8 or s[3] != "-":
3        return False
4    digits = s[:3] + s[4:]
5    return all(c in "0123456789" for c in digits)

正規表現を使うと、同じ処理を 1 行で書ける。

リスト 1.2 正規表現で郵便番号の形を調べる
1import re
2
3
4def is_postal_code(s: str) -> bool:
5    return re.fullmatch(r"[0-9]{3}-[0-9]{4}", s) is not None

形が複雑になるほど、この差は大きくなる。一方で、正規表現は短く書ける反面、読みにくくなりやすく、使い方を誤ると性能上の問題も起こす。本書ではその両面を扱う。

1.3. 本書の構成

本書は次の順に進む。

  • 第 2 章から第 8 章では、正規表現の構文を 1 つずつ説明する。

  • 第 9 章では、Python の re モジュールが提供する関数と、その使い分けを説明する。

  • 第 10 章では、ログの解析や入力値の検証など、実務でよく使うパターンを紹介する。

  • 第 11 章では、性能上の問題（ReDoS）やよくある間違い、正規表現を使うべきでない場面を説明する。

  • 第 12 章では、grep、sed、JavaScript など、Python 以外の実装との違いをまとめる。

付録には、構文の早見表、用語集、参考文献を収めた。

1.4. 前提とする環境

本書は Python 3.11 以降を前提とする。Python 3.11 で、強欲量指定子とアトミックグループが re モジュールに追加されたためである。本書のサンプルコードは Python 3.14 で動作を確認した。re は標準ライブラリなので、追加のインストールは不要である。

1.5. 本書の表記

本文中のパターンは \d+ のように等幅フォントで示す。Python のコードでは、表示を行う行の末尾に # -> で始まるコメントを付け、その行を実行したときに表示される内容を示す。

リスト 1.3 表記の例
1print(re.findall(r"\d+", "a1b22"))  # -> ['1', '22']

ループの中で表示する場合など、表示内容が複数行になるときは、ループの後に # -> のコメントを並べて示す。

本書では、パターンと文字列の関係を「一致する」と表現する。ただし、貪欲マッチや最短マッチなど、一般に定着している用語には「マッチ」をそのまま使う。
