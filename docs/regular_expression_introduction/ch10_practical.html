10. 実践パターン集

この章では、これまでに説明した構文と関数を組み合わせて、実務でよく出会う処理を書く。

10.1. ログを解析する

次のようなログファイルを解析し、エラーの行を表示して、ログレベルごとの件数を数える。6 行目のように、形式に合わない行も混ざっているものとする。

リスト 10.1 解析するログファイル（sample.log）
12026-10-19 09:00:01 INFO  [web] GET /index.html 200 12ms
22026-10-19 09:00:05 WARN  [web] GET /old-page 301 3ms
32026-10-19 09:01:10 ERROR [db] connection timeout after 30s
42026-10-19 09:02:00 INFO  [web] POST /api/login 200 85ms
52026-10-19 09:02:30 ERROR [web] GET /api/users 500 120ms
6this line is broken
72026-10-19 09:03:15 INFO  [batch] job finished: 1520 records

まず、1 行の形式を名前付きグループと re.VERBOSE で記述する。

リスト 10.2 ログ 1 行のパターン
 1LOG_PATTERN = re.compile(
 2    r"""
 3    (?P<date>\d{4}-\d{2}-\d{2})     # 日付
 4    \s+
 5    (?P<time>\d{2}:\d{2}:\d{2})     # 時刻
 6    \s+
 7    (?P<level>[A-Z]+)               # ログレベル
 8    \s+
 9    \[(?P<component>\w+)\]          # コンポーネント名
10    \s+
11    (?P<message>.*)                 # 残りはすべてメッセージ
12    """,
13    flags=re.VERBOSE,
14)
15
16

各部分にコメントを付けておくと、ログの形式が変わったときにどこを直せばよいかが分かりやすい。ログレベルの後の空白は、INFO の後のように 2 個以上になる場合があるので \s+ としている。[ と ] はメタ文字なので、9 行目ではエスケープしている。

このパターンを使って、1 行を辞書に変換する関数を作る。

リスト 10.3 ログ 1 行を解析する関数
1def parse_log_line(line: str) -> dict[str, str] | None:
2    """ログ 1 行を解析して辞書を返す。形式に合わない行は None を返す。"""
3    m = LOG_PATTERN.fullmatch(line.rstrip("\n"))
4    return m.groupdict() if m else None

行全体が形式に合っているかを確かめるため、fullmatch() を使う。ファイルから読み込んだ行は末尾に改行を含むので、あらかじめ rstrip("\n") で取り除いている。groupdict() を使うと、名前付きグループの名前がそのまま辞書のキーになる。

この関数を使ってファイル全体を処理する。

リスト 10.4 ログファイル全体の解析
 1def demo_parse_log() -> None:
 2    """ログファイルを解析してログレベルごとに件数を数える。"""
 3    levels: Counter[str] = Counter()
 4    with LOG_FILE.open(encoding="utf-8") as f:
 5        for line in f:
 6            entry = parse_log_line(line)
 7            if entry is None:
 8                print("skip:", line.strip())
 9                continue
10            levels[entry["level"]] += 1
11            if entry["level"] == "ERROR":
12                print(entry["time"], entry["component"], entry["message"])
13    print(dict(levels))

形式に合わない行は None が返るので、7 行目で判定して読み飛ばしている。

10.2. ログから特定の情報を取り出す

ファイル全体を 1 つの文字列として読み込み、finditer() で必要な部分だけを取り出すこともできる。次の例では、HTTP のステータスコードが 300 以上のリクエストを表示する。

リスト 10.5 ステータスコードと応答時間の抽出
1def demo_http_status() -> None:
2    """HTTP のステータスコードと応答時間を取り出す。"""
3    pattern = re.compile(r"(?P<method>GET|POST) (?P<path>\S+) (?P<status>\d{3}) (?P<ms>\d+)ms")
4    text = LOG_FILE.read_text(encoding="utf-8")
5    for m in pattern.finditer(text):
6        if int(m["status"]) >= 300:
7            print(m["status"], m["path"], m["ms"])

(?P<method>GET|POST) のように選択をグループで囲むと、どの選択肢に一致したかを取り出せる。取り出した値は文字列なので、数値として比較するには 6 行目のように int() で変換する。

10.3. 日付の表記をそろえる

2026/4/1、2026年7月15日、2027-3-31 のように表記がばらばらな日付を、YYYY-MM-DD 形式にそろえる。

リスト 10.6 日付の表記の統一
 1def demo_normalize_date() -> None:
 2    """表記がばらばらな日付を YYYY-MM-DD 形式にそろえる。"""
 3    pattern = re.compile(r"(\d{4})[/年-](\d{1,2})[/月-](\d{1,2})日?")
 4
 5    def to_iso(m: re.Match[str]) -> str:
 6        year, month, day = (int(g) for g in m.groups())
 7        return f"{year:04d}-{month:02d}-{day:02d}"
 8
 9    text = "開始 2026/4/1、中間 2026年7月15日、終了 2027-3-31"
10    print(pattern.sub(to_iso, text))  # -> 開始 2026-04-01、中間 2026-07-15、終了 2027-03-31

区切り文字の違いは [/年-] のような文字クラスで、桁数の違いは \d{1,2} で吸収している。月と日を 2 桁にそろえる処理は置換文字列だけでは書けないので、関数で置換している。

このパターンは形だけを見ているので、2026/13/45 のような存在しない日付にも一致する。日付として正しいかどうかまで確かめる場合は、取り出した値を datetime.date() に渡して検証する。

10.4. key=value 形式を解析する

設定やコマンドの引数でよく見る key=value 形式の文字列を、辞書に変換する。値が空白を含む場合は " で囲まれているものとする。

リスト 10.7 key=value 形式の解析
1def demo_key_value() -> None:
2    """key=value 形式の文字列を辞書に変換する。値は引用符で囲まれている場合がある。"""
3    text = 'host=example.com port=8080 user="John Smith" debug=true'
4    pairs = re.findall(r'(\w+)=("[^"]*"|\S+)', text)
5    config = {key: value.strip('"') for key, value in pairs}
6    print(config)  # -> {'host': 'example.com', 'port': '8080', 'user': 'John Smith', 'debug': 'true'}

4 行目の値の部分 ("[^"]*"|\S+) は、「" で囲まれた文字列」または「空白以外の文字の並び」に一致する。引用符で囲まれた場合を先に書いているので、"John Smith" は空白で途切れずに 1 つの値になる。第 6 章で説明したとおり、選択肢は左から順に試されるためである。

10.5. 空白を正規化する

連続する空白、タブ、改行を 1 つの半角空白にまとめる。

リスト 10.8 空白の正規化
1def demo_normalize_space() -> None:
2    """連続する空白 (改行やタブを含む) を 1 つの半角空白にまとめる。"""
3    text = "  Hello,\t\tregular   \n expression!  "
4    print(repr(re.sub(r"\s+", " ", text).strip()))  # -> 'Hello, regular expression!'

\s+ は全角空白にも一致するので、全角空白も半角空白にそろえられる。前後の空白は strip() で取り除いている。

10.6. 入力値を検証する

郵便番号のように形式の決まった入力値は、fullmatch() で検証する。

リスト 10.9 郵便番号の検証
1def demo_validate() -> None:
2    """入力値の形式を検証する。検証では fullmatch() と re.ASCII を使う。"""
3    postal_code = re.compile(r"\d{3}-\d{4}", flags=re.ASCII)
4    for value in ("100-0001", "1000001", "１００-０００１", "100-00012"):
5        print(value, bool(postal_code.fullmatch(value)))

検証では次の 2 点が重要である。

  • search() ではなく fullmatch() を使う。search() では、100-00012 の一部が一致してしまう。

  • re.ASCII を指定するか [0-9] を使う。指定しないと、\d が全角数字にも一致し、１００-０００１ を受け付けてしまう。

全角数字も受け付けたい場合は、検証の前に unicodedata.normalize("NFKC", value) で半角に変換しておく方法がある。

10.7. メールアドレスと URL について

メールアドレスや URL を正規表現で厳密に検証しようとすると、パターンは非常に複雑になる。メールアドレスの形式を定めた規格（RFC 5322 など）を忠実に表現しようとした正規表現には数千文字に及ぶものもあり、それでも実際のメールサービスの制約とは一致しない。

実務では、正規表現では「明らかにおかしいもの」を弾く程度にとどめるのが現実的である。

リスト 10.10 メールアドレスの簡易的な検査
1def demo_email_rough_check() -> None:
2    """メールアドレスは「明らかにおかしいものを弾く」程度の検査にとどめる。"""
3    rough = re.compile(r"[^@\s]+@[^@\s]+\.[^@\s]+")
4    for value in ("user@example.com", "user.name+tag@example.co.jp", "user@localhost", "a b@example.com"):
5        print(value, bool(rough.fullmatch(value)))

3 行目のパターンは、「@ と空白を含まない文字列、@、ドメイン部分（. を 1 つ以上含む）」という最低限の形だけを調べる。メールアドレスが実際に使えるかどうかは、確認メールを送って確かめるのが確実である。URL の場合は、urllib.parse.urlparse() で分解してから各部分を確かめるとよい。

10.8. まとめ

  • 複雑なパターンは re.VERBOSE と名前付きグループで書き、groupdict() で辞書として取り出す。

  • 置換文字列で表現できない変換は、関数による置換で行う。

  • 入力値の検証には fullmatch() を使い、必要に応じて re.ASCII を指定する。

  • 正規表現で調べられるのは形だけである。値の正しさは別の方法で確かめる。
