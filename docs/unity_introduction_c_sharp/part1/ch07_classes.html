第 7 章 クラスとオブジェクト

この章では、データとそれを扱う処理をひとまとめにするクラスについて学びます。C# のプログラムはクラスを組み合わせて作ります。Unity のスクリプトも、1 つ 1 つがクラスです。

クラスとインスタンス

クラスは、オブジェクトの設計図です。たとえば「キャラクター」というクラスには、「名前」や「HP」というデータと、「ダメージを受ける」「回復する」という処理をまとめて定義します。

設計図であるクラスから、new を使って実際のオブジェクトを作ります。クラスから作ったオブジェクトを、そのクラスのインスタンスと呼びます。1 つのクラスから、いくつでもインスタンスを作れます。

Character hero = new Character("勇者", 30);
Character slime = new Character("スライム", 8);

hero と slime は同じ Character クラスのインスタンスですが、それぞれが別の名前と HP を持ちます。

クラスのメンバー

クラスの中に定義するものをメンバーと呼びます。主なメンバーは次のとおりです。

メンバー

説明

フィールド

クラスが持つデータ（変数）です。

プロパティ

フィールドのように読み書きできるが、中身はメソッドのように処理を書けるメンバーです。

メソッド

クラスが持つ処理です（第 6 章）。

コンストラクター

new でインスタンスを作るときに呼ばれる、初期化のための特別なメソッドです。

メンバーには、hero.Name や hero.TakeDamage(12) のように、.（ドット）でアクセスします。

アクセス修飾子

アクセス修飾子は、メンバーをどこから使えるかを決めます。

修飾子

使える範囲

public

どこからでも使えます。

private

そのクラスの中でだけ使えます。

protected

そのクラスと、そのクラスを継承したクラスの中で使えます（第 8 章）。

internal

同じアセンブリ（Unity では、通常は同じプロジェクトのスクリプト）の中で使えます。

アクセス修飾子を省略すると、クラスのメンバーは private になります。本書では、省略せずに書きます。

フィールドは、原則として private にします。クラスの外から自由に書き換えられると、HP が負の値になるなど、不正な状態になるのを防げないためです。外部に公開したい値は、次に説明するプロパティを通して公開します。

フィールドの名前

本書では、private なフィールドの名前は _hp のように _ で始まる camelCase にします。こうすると、ローカル変数や引数と区別しやすくなります。命名規則の一覧は、付録 A コーディング規約 を参照してください。

プロパティ

プロパティは、値を読み取るときの処理（get）と、値を設定するときの処理（set）を持つメンバーです。

private int _hp;

public int Hp
{
    get { return _hp; }
    private set { _hp = Mathf.Clamp(value, 0, MaxHp); }
}

set の中の value は、設定しようとしている値を表します。この例では、Mathf.Clamp を使って、値が 0 以上 MaxHp 以下になるように制限しています。また、set に private を付けているため、クラスの外からは値を読み取ることしかできません。

自動実装プロパティ

値を読み書きするだけのプロパティは、フィールドを自分で定義せずに、短く書けます。これを自動実装プロパティと呼びます。

public string Name { get; }                  // 読み取り専用（値はコンストラクターで設定する）
public int Score { get; private set; }       // 外からは読み取り専用

計算した結果を返すだけのプロパティは、第 6 章の式形式のメンバーと同じく => を使って書けます。

public bool IsAlive => Hp > 0;

コンストラクター

コンストラクターは、クラスと同じ名前を持ち、戻り値の型を書かない特別なメソッドです。new でインスタンスを作るときに 1 回だけ呼ばれ、フィールドやプロパティに最初の値を設定します。

public Character(string name, int maxHp)
{
    Name = name;
    MaxHp = maxHp;
    _hp = maxHp;
}

警告

MonoBehaviour を継承したクラス（Unity のスクリプト）は、new でインスタンスを作ってはいけません。また、コンストラクターも定義しません。インスタンスは、GameObject にアタッチしたときに Unity が作ります。初期化の処理は、Awake や Start に書きます（第 11 章）。この章で扱う Character クラスは MonoBehaviour を継承していない普通のクラスなので、new で作れます。

static メンバー

static を付けたメンバーは、インスタンスごとではなく、クラス全体で 1 つだけ存在します。static メンバーには、Character.CreatedCount のように「クラス名.メンバー名」でアクセスします。

これまでに使ってきた Debug.Log や Mathf.Clamp も、static メソッドです。そのため、インスタンスを作らずに呼び出せます。

値型と参照型

C# の型は、値型と参照型の 2 種類に分けられます。

種類

例

代入したときにコピーされるもの

値型

int、float、bool、構造体（struct）、列挙型（第 9 章）

値そのもの

参照型

クラス（class）、string、配列

インスタンスへの参照（インスタンスの場所を示す情報）

参照型の変数には、インスタンスそのものではなく、インスタンスへの参照が入っています。そのため、Character sameHero = hero; と代入すると、hero と sameHero は同じインスタンスを指します。sameHero を通して HP を減らすと、hero の HP も減ります。メソッドの引数にクラスのインスタンスを渡した場合も、参照がコピーされるため、メソッドの中でインスタンスのデータを変更すると、呼び出し元から見ても変更されています。

一方、値型の変数には値そのものが入っています。代入すると値がコピーされるため、コピー先を変更しても、元の変数は変わりません。

構造体

構造体は、struct キーワードで定義する値型です。クラスと同じようにフィールドやメソッドを持てますが、値型として扱われます。Unity では、座標や向きを表す Vector3 が構造体です。

注釈

string は参照型ですが、内容を変更できないように作られているため、値型のように扱えます。

null

参照型の変数には、「何も指していない」ことを表す null を代入できます。null が入っている変数のメンバーにアクセスすると、NullReferenceException という例外が発生します。これは Unity で最もよく目にするエラーの 1 つです（第 20 章）。

サンプルコード

2 つのファイルを同じプロジェクトに置いて使います。

Character.cs
// 第 7 章 クラスとオブジェクト
// キャラクターの名前と HP を管理するクラスです。MonoBehaviour を継承しない、普通の C# のクラスです。
// ClassSample.cs から利用します。
using UnityEngine;

public class Character
{
    // フィールド: クラスの外から直接書き換えられないように private にします。
    private int _hp;

    // コンストラクター: new でインスタンスを作るときに 1 回だけ呼ばれます。
    public Character(string name, int maxHp)
    {
        Name = name;
        MaxHp = maxHp;
        _hp = maxHp;
        CreatedCount++;
    }

    // static プロパティ: インスタンスごとではなく、クラス全体で 1 つだけ存在します。
    public static int CreatedCount { get; private set; }

    // 読み取り専用の自動実装プロパティ: 値を設定できるのはコンストラクターの中だけです。
    public string Name { get; }

    public int MaxHp { get; }

    // 値の範囲を制限するプロパティ: クラスの外からは読み取りだけができます。
    public int Hp
    {
        get { return _hp; }
        private set { _hp = Mathf.Clamp(value, 0, MaxHp); }
    }

    // 計算結果を返すだけのプロパティ
    public bool IsAlive => Hp > 0;

    public void TakeDamage(int amount)
    {
        Hp -= amount;
    }

    public void Heal(int amount)
    {
        Hp += amount;
    }
}

ClassSample.cs
// 第 7 章 クラスとオブジェクト
// Character クラスのインスタンスを作って使い、クラス（参照型）と構造体（値型）の違いを確認するスクリプトです。
// 使い方: Character.cs と同じプロジェクトに置き、シーン内の GameObject にアタッチして Play ボタンを押します。
using UnityEngine;

public class ClassSample : MonoBehaviour
{
    private void Start()
    {
        // new でインスタンスを作ります。
        Character hero = new Character("勇者", 30);
        Character slime = new Character("スライム", 8);

        hero.TakeDamage(12);
        Debug.Log($"{hero.Name}: HP {hero.Hp} / {hero.MaxHp}");

        // Hp は MaxHp を超えないように制限されています。
        hero.Heal(100);
        Debug.Log($"{hero.Name}: HP {hero.Hp} / {hero.MaxHp}");

        // Hp は 0 未満にもなりません。
        slime.TakeDamage(20);
        Debug.Log($"{slime.Name}: HP {slime.Hp}, 生存: {slime.IsAlive}");

        // static メンバーは「クラス名.メンバー名」で使います。
        Debug.Log($"作成したキャラクターの数: {Character.CreatedCount}");

        // ---- クラスは参照型 ----
        // 代入するとインスタンスへの参照がコピーされ、2 つの変数が同じインスタンスを指します。
        Character sameHero = hero;
        sameHero.TakeDamage(5);
        Debug.Log($"hero.Hp = {hero.Hp}, sameHero.Hp = {sameHero.Hp}");

        // ---- 構造体は値型 ----
        // Vector3 は構造体です。代入すると値そのものがコピーされるため、コピー先を変えても元の値は変わりません。
        Vector3 original = new Vector3(1f, 2f, 3f);
        Vector3 copy = original;
        copy.x = 10f;
        Debug.Log($"original.x = {original.x}, copy.x = {copy.x}");
    }
}

まとめ

  • クラスは設計図で、new で作ったオブジェクトをインスタンスと呼びます。

  • フィールドは private にし、外部にはプロパティやメソッドを通して公開します。

  • コンストラクターは、インスタンスを作るときに呼ばれます。ただし、MonoBehaviour を継承したクラスでは使いません。

  • static メンバーは、クラス全体で 1 つだけ存在します。

  • クラスは参照型、構造体は値型です。代入したときの動きが異なります。
