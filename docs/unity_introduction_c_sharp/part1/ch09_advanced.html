第 9 章 C# の発展的な機能

この章では、Unity のスクリプトでよく使う C# の機能として、列挙型、ジェネリクス、デリゲートとイベント、例外処理、null を扱うための演算子について学びます。

列挙型

列挙型（enum）は、決まった選択肢の中から 1 つを選ぶ値を表す型です。ゲームの状態（タイトル、プレイ中、ゲームオーバー）や、武器の種類などを表すのに使います。

public enum GameState
{
    Title,
    Playing,
    GameOver,
}

GameState state = GameState.Playing;

状態を 0 や 1 のような整数や、"Playing" のような文字列で表すこともできますが、列挙型を使うと、存在しない値を代入するような誤りをコンパイルの時点で見つけられます。また、Unity では、列挙型のフィールドが Inspector ウィンドウでドロップダウンとして表示されます。

列挙型の値は内部的には整数で、最初の値から順に 0、1、2 と割り当てられます。(int)GameState.GameOver のようにキャストすると、整数値を取り出せます。

EnumSample.cs
// 第 9 章 C# の発展的な機能
// 列挙型（enum）の定義と使い方を確認するスクリプトです。
// 使い方: シーン内の GameObject にアタッチし、Inspector ウィンドウで State の値を変えて試します。
using UnityEngine;

public class EnumSample : MonoBehaviour
{
    // ゲームの状態を表す列挙型です。クラスの中に定義することもできます。
    public enum GameState
    {
        Title,
        Playing,
        GameOver,
    }

    // 列挙型のフィールドは、Inspector ウィンドウではドロップダウンで表示されます。
    [SerializeField] private GameState _state = GameState.Playing;

    private void Start()
    {
        Debug.Log($"現在の状態: {_state}");

        // 列挙型の値は、内部的には 0 から始まる整数です。
        Debug.Log($"GameOver の整数値: {(int)GameState.GameOver}");

        string message = _state switch
        {
            GameState.Title => "タイトル画面を表示する。",
            GameState.Playing => "ゲームを進める。",
            GameState.GameOver => "ゲームオーバー画面を表示する。",
            _ => "不明な状態。",
        };
        Debug.Log(message);
    }
}

ジェネリクス

第 5 章で使った List<T> の T のように、型をパラメーターとして受け取る仕組みをジェネリクスと呼びます。ジェネリクスを使うと、型だけが異なる同じ処理を 1 つにまとめられます。

メソッドもジェネリクスにできます。メソッド名の後に <T> と書くと、T を型として使えます。T には、呼び出すときに実際の型が当てはめられます。

private void Swap<T>(ref T x, ref T y)
{
    T temp = x;
    x = y;
    y = temp;
}

where T : IComparable<T> のように型制約を付けると、T に当てはめられる型を制限できます。この例では、大小を比較できる型（CompareTo メソッドを持つ型）だけを受け付けます。

Unity でも、GetComponent<Rigidbody>() のように、ジェネリクスのメソッドを頻繁に使います（第 13 章）。

GenericSample.cs
// 第 9 章 C# の発展的な機能
// ジェネリクス（型をパラメーターとして受け取る仕組み）を確認するスクリプトです。
// 使い方: シーン内の GameObject にアタッチし、Play ボタンを押して Console ウィンドウを確認します。
using System;
using UnityEngine;

public class GenericSample : MonoBehaviour
{
    private void Start()
    {
        // 同じ Swap メソッドを、int にも string にも使えます。
        int a = 1;
        int b = 2;
        Swap(ref a, ref b);
        Debug.Log($"a = {a}, b = {b}");

        string first = "前";
        string second = "後";
        Swap(ref first, ref second);
        Debug.Log($"first = {first}, second = {second}");

        // 型制約（where T : IComparable<T>）により、大小比較ができる型だけを受け付けます。
        int[] numbers = { 3, 9, 4 };
        string[] fruits = { "りんご", "みかん", "ぶどう" };
        Debug.Log($"最大値: {Max(numbers)}");
        Debug.Log($"辞書順で最後: {Max(fruits)}");
    }

    // T には、呼び出し時に実際の型（int や string など）が当てはめられます。
    private void Swap<T>(ref T x, ref T y)
    {
        T temp = x;
        x = y;
        y = temp;
    }

    private T Max<T>(T[] values) where T : IComparable<T>
    {
        T max = values[0];
        foreach (T value in values)
        {
            if (value.CompareTo(max) > 0)
            {
                max = value;
            }
        }
        return max;
    }
}

デリゲートとイベント

デリゲート

デリゲートは、メソッドを入れておける型です。メソッドを変数に入れたり、ほかのメソッドの引数として渡したりできます。C# には、よく使う形のデリゲートとして Action と Func が用意されています。使うには、ファイルの先頭に using System; を書きます。

型

入れられるメソッド

Action

引数も戻り値もないメソッド

Action<T>

T 型の引数を 1 つ受け取り、戻り値がないメソッド

Func<TResult>

引数がなく、TResult 型の値を返すメソッド

Func<T1, T2, TResult>

T1 型と T2 型の引数を受け取り、TResult 型の値を返すメソッド

ラムダ式

ラムダ式を使うと、名前のないメソッドをその場で定義できます。=> の左側に引数を、右側に処理を書きます。

Func<int, int, int> multiply = (x, y) => x * y;
int result = multiply(6, 7);    // 42

引数が 1 つだけの場合は、score => Debug.Log(score) のように、引数のかっこを省略できます。

イベント

イベントは、何かが起きたことをほかのクラスに知らせる仕組みです。デリゲート型のフィールドに event を付けて定義します。

public event Action<int> ScoreChanged;

イベントを受け取りたい側は、+= で呼び出してほしいメソッドを登録し、不要になったら -= で解除します。イベントを発生させる側は、ScoreChanged?.Invoke(Score); のように書いて、登録されたメソッドをすべて呼び出します。?. については、この章の後半で説明します。

サンプルコードでは、DelegateSample クラスの中に ScoreCounter クラスを定義しています。このように、クラスの中に別のクラスを定義することもできます（入れ子のクラス）。

イベントを使うと、スコアを管理するクラスは「スコアが変わった」ことを知らせるだけでよく、それを受けて画面の表示を更新するのか、効果音を鳴らすのかを知る必要がありません。このように、クラスどうしの依存関係を減らせます。

DelegateSample.cs
// 第 9 章 C# の発展的な機能
// デリゲート（Action と Func）、ラムダ式、イベントを確認するスクリプトです。
// 使い方: シーン内の GameObject にアタッチし、Play ボタンを押して Console ウィンドウを確認します。
using System;
using UnityEngine;

public class DelegateSample : MonoBehaviour
{
    private void Start()
    {
        // ---- Action: 戻り値のないメソッドを入れる変数 ----
        Action<string> say = ShowMessage;
        say("メソッドを変数に入れて呼び出した。");

        // ---- Func: 戻り値のあるメソッドを入れる変数（<> の中の最後の型が戻り値の型）----
        // ラムダ式を使うと、その場でメソッドを定義できます。
        Func<int, int, int> multiply = (x, y) => x * y;
        Debug.Log($"multiply(6, 7) = {multiply(6, 7)}");

        // ---- イベント ----
        ScoreCounter counter = new ScoreCounter();

        // += で、イベントが発生したときに呼び出してほしいメソッドを登録します。
        counter.ScoreChanged += score => Debug.Log($"スコアが {score} になった。");
        counter.ScoreChanged += CheckHighScore;

        counter.Add(50);
        counter.Add(80);

        // -= で登録を解除すると、それ以降は呼び出されません。
        counter.ScoreChanged -= CheckHighScore;
        counter.Add(10);
    }

    private void ShowMessage(string message)
    {
        Debug.Log(message);
    }

    private void CheckHighScore(int score)
    {
        if (score >= 100)
        {
            Debug.Log("ハイスコア達成！");
        }
    }

    // スコアを管理し、スコアが変わったことをイベントで知らせるクラスです。
    // DelegateSample の中でだけ使うため、クラスの中に private なクラスとして定義しています。
    private class ScoreCounter
    {
        public event Action<int> ScoreChanged;

        public int Score { get; private set; }

        public void Add(int points)
        {
            Score += points;

            // 登録されたメソッドがなければ ScoreChanged は null なので、?. で null のときは呼び出さないようにします。
            ScoreChanged?.Invoke(Score);
        }
    }
}

例外処理

プログラムの実行中に、処理を続けられない問題が起きることがあります。たとえば、int.Parse("abc") は "abc" を数値に変換できないため、FormatException という例外を発生させます。例外が発生すると、その後の処理は実行されません。

例外に対処するには、try、catch、finally を使います。

ブロック

説明

try

例外が発生する可能性のある処理を書きます。

catch

try の中で例外が発生したときに実行されます。かっこの中に、受け取る例外の型を書きます。

finally

例外の有無にかかわらず、最後に必ず実行されます。省略できます。

注釈

失敗することが予想できる処理は、例外に頼らず、int.TryParse のように失敗を戻り値で知らせるメソッドを使うのが一般的です。例外の処理は、通常の処理に比べて時間がかかるためです。

null を扱うための演算子

null 許容値型

int などの値型の変数には、通常は null を代入できません。型名の後に ? を付けて int? とすると、「値がない」ことを null で表せるようになります。値があるかどうかは HasValue で調べられます。

null 合体演算子と null 条件演算子

演算子

意味

例

??

左辺が null なら右辺の値を使います。

bestTime ?? 999

?.

左辺が null ならメンバーにアクセスせず、null を返します。

playerName?.Length

is null

左辺が null なら true を返します。

playerName is null

警告

??、?.、is null は、C# の普通のオブジェクトには便利ですが、GameObject やコンポーネントなどの Unity のオブジェクトには使ってはいけません。理由は 第 18 章 Unity 固有の注意点 で説明します。

ExceptionSample.cs
// 第 9 章 C# の発展的な機能
// 例外処理（try、catch、finally）と、null を扱うための演算子を確認するスクリプトです。
// 使い方: シーン内の GameObject にアタッチし、Play ボタンを押して Console ウィンドウを確認します。
using System;
using UnityEngine;

public class ExceptionSample : MonoBehaviour
{
    private void Start()
    {
        // ---- 例外処理 ----
        try
        {
            int value = int.Parse("abc");
            Debug.Log($"変換結果: {value}");    // 例外が発生するので、この行は実行されない
        }
        catch (FormatException e)
        {
            Debug.Log($"数値に変換できなかった: {e.GetType().Name}");
        }
        finally
        {
            Debug.Log("finally ブロックは、例外の有無にかかわらず実行される。");
        }

        // 失敗することが予想できる処理は、例外を使わずに TryParse で書くのが一般的です。
        if (int.TryParse("123", out int parsed))
        {
            Debug.Log($"TryParse の結果: {parsed}");
        }

        // ---- null 許容値型 ----
        // int? は「int の値」か「値なし（null）」のどちらかを持てる型です。
        int? bestTime = null;
        Debug.Log($"記録あり: {bestTime.HasValue}");

        // ?? 演算子: 左辺が null のときに右辺の値を使います。
        int displayTime = bestTime ?? 999;
        Debug.Log($"表示する記録: {displayTime}");

        // ---- null 条件演算子 ----
        // ?. は、左辺が null ならメンバーにアクセスせずに null を返します。
        string playerName = null;
        int? length = playerName?.Length;
        Debug.Log($"名前の長さ: {length ?? 0}");
    }
}

まとめ

  • 列挙型は、決まった選択肢の中から 1 つを選ぶ値を表します。

  • ジェネリクスを使うと、型だけが異なる処理を 1 つにまとめられます。

  • デリゲートはメソッドを入れる型で、イベントはデリゲートを使って出来事を知らせる仕組みです。

  • 例外は try と catch で処理できますが、予想できる失敗には TryParse などを使います。

  • ??、?.、is null は、Unity のオブジェクトには使いません。
