第 11 章 イベント関数とライフサイクル

Start や Update のように、Unity が決まったタイミングで自動的に呼び出すメソッドを、イベント関数と呼びます。この章では、主なイベント関数が呼ばれる順番と、それぞれの使い分けを学びます。

主なイベント関数

イベント関数

呼ばれるタイミング

主な用途

Awake

インスタンスが作られた直後に 1 回

自分自身の初期化、コンポーネントの取得

OnEnable

コンポーネントが有効になるたび

C# のイベント（第 9 章）への登録

Start

最初の Update の直前に 1 回

ほかのオブジェクトを使う初期化

FixedUpdate

一定の時間間隔ごと（既定では 0.02 秒ごと）

物理演算に関わる処理（第 16 章）

Update

毎フレーム 1 回

入力の読み取り、移動など、ほとんどの処理

LateUpdate

毎フレーム、すべての Update が終わった後に 1 回

カメラの追従など、ほかの処理の結果を使う処理

OnDisable

コンポーネントが無効になるたび

C# のイベントへの登録の解除

OnDestroy

GameObject やコンポーネントが破棄される直前に 1 回

後片付け

イベント関数は、Unity が名前で探して呼び出します。そのため、名前の大文字と小文字を間違える（update と書くなど）と、エラーにはならずに、単に呼ばれなくなります。

実行の順番

GameObject が作られてから破棄されるまでの流れを、ライフサイクルと呼びます。イベント関数は、次の順番で呼ばれます。

段階

イベント関数

説明

初期化

Awake → OnEnable → Start

Awake と OnEnable はオブジェクトが作られたときに、Start は最初のフレームの Update の前に呼ばれます。

物理演算

FixedUpdate → 衝突の判定と通知

前回からの経過時間に応じて、1 フレームの間に 0 回、1 回、または複数回くり返されます。

ゲームの処理

Update → LateUpdate

毎フレーム 1 回ずつ呼ばれます。

描画

（なし）

画面が描画されます。その後、次のフレームの物理演算の段階に戻ります。

終了

OnDisable → OnDestroy

オブジェクトが無効になったとき、破棄されたとき、Play モードを終了したときに呼ばれます。

詳しい順番は、Unity のマニュアルの Event function execution order で確認できます。

Awake と Start の使い分け

シーンに置かれたすべてのオブジェクトの Awake が呼ばれた後で、それぞれの Start が呼ばれます。ただし、異なるオブジェクトの間で、どちらの Awake が先に呼ばれるかは決まっていません。

そのため、次のように使い分けます。

  • Awake: 自分自身の初期化（自分のコンポーネントの取得など）を行います。

  • Start: ほかのオブジェクトの初期化が終わっていることを前提とする処理を行います。

注釈

Awake は、コンポーネントが無効（Inspector ウィンドウでチェックを外した状態）でも、GameObject が有効であれば呼ばれます。Start は、コンポーネントが有効になるまで呼ばれません。GameObject 自体が無効の場合は、どちらも呼ばれません。

サンプルコード

主なイベント関数が呼ばれた順番を表示するスクリプトです。

LifecycleLogger.cs
// 第 11 章 イベント関数とライフサイクル
// 主なイベント関数が呼ばれた順番を Console ウィンドウに表示するスクリプトです。
// 使い方: シーン内の GameObject にアタッチして Play ボタンを押します。
//         Play モード中に Inspector ウィンドウでコンポーネントのチェックを外したり、Play モードを終了したりして、
//         OnDisable や OnDestroy が呼ばれる様子も確認してください。
using UnityEngine;

public class LifecycleLogger : MonoBehaviour
{
    // 毎フレーム呼ばれる関数は、最初の 1 回だけ表示するためのフラグです。
    private bool _isFirstFixedUpdate = true;
    private bool _isFirstUpdate = true;
    private bool _isFirstLateUpdate = true;

    private void Awake()
    {
        Debug.Log("Awake: インスタンスが作られた直後に 1 回");
    }

    private void OnEnable()
    {
        Debug.Log("OnEnable: 有効になるたびに");
    }

    private void Start()
    {
        Debug.Log("Start: 最初の Update の直前に 1 回");
    }

    private void FixedUpdate()
    {
        if (_isFirstFixedUpdate)
        {
            Debug.Log($"FixedUpdate: 一定間隔（{Time.fixedDeltaTime} 秒）ごと");
            _isFirstFixedUpdate = false;
        }
    }

    private void Update()
    {
        if (_isFirstUpdate)
        {
            Debug.Log("Update: 毎フレーム");
            _isFirstUpdate = false;
        }
    }

    private void LateUpdate()
    {
        if (_isFirstLateUpdate)
        {
            Debug.Log("LateUpdate: 毎フレーム、すべての Update の後");
            _isFirstLateUpdate = false;
        }
    }

    private void OnDisable()
    {
        Debug.Log("OnDisable: 無効になるたびに");
    }

    private void OnDestroy()
    {
        Debug.Log("OnDestroy: 破棄される直前に 1 回");
    }
}

LifecycleLogger.cs をダウンロード

Play ボタンを押してから Play モードを終了すると、Console ウィンドウに次のように表示されます。FixedUpdate は時間の経過に応じて呼ばれるため、Update との順番が前後することがあります。

実行結果（例）
Awake: インスタンスが作られた直後に 1 回
OnEnable: 有効になるたびに
Start: 最初の Update の直前に 1 回
FixedUpdate: 一定間隔（0.02 秒）ごと
Update: 毎フレーム
LateUpdate: 毎フレーム、すべての Update の後
OnDisable: 無効になるたびに
OnDestroy: 破棄される直前に 1 回

フレームレートと Time.deltaTime

1 秒間に画面が更新される回数を、フレームレートと呼びます。単位は fps（frames per second）です。フレームレートは、コンピューターの性能や処理の重さによって変わります。

Update は毎フレーム呼ばれるため、Update の中で毎回同じ距離だけ動かすと、フレームレートが高いコンピューターほど速く動いてしまいます。たとえば、毎フレーム 0.1 m 動かすと、60 fps では 1 秒間に 6 m、30 fps では 1 秒間に 3 m 進みます。

これを防ぐには、Time.deltaTime を使います。Time.deltaTime は、前のフレームから現在のフレームまでの経過時間（秒）です。速さを \(v\)（m/s）、経過時間を \(\Delta t\)（s）とすると、1 フレームの移動量は次の式で求められます。

\[\Delta x = v \times \Delta t\]

60 fps のとき \(\Delta t\) は約 \(1/60\) 秒、30 fps のとき約 \(1/30\) 秒です。速さ \(v = 2\) m/s で 1 秒間に進む距離は、どちらの場合も次のように同じになります。

\[2 \times \frac{1}{60} \times 60 = 2 \times \frac{1}{30} \times 30 = 2\]
MoveForward.cs
// 第 11 章 イベント関数とライフサイクル
// Time.deltaTime を使って、フレームレートに関係なく一定の速さで前進するスクリプトです。
// 使い方: シーンに Cube を作成してアタッチし、Play ボタンを押します。
using UnityEngine;

public class MoveForward : MonoBehaviour
{
    // 1 秒あたりに進む距離（m）です。
    [SerializeField] private float _speed = 2f;

    private void Update()
    {
        // 移動量 = 速さ × 前のフレームからの経過時間
        // Vector3.forward は (0, 0, 1)、つまりワールド座標の Z 軸の正の向きです。
        transform.position += Vector3.forward * _speed * Time.deltaTime;
    }
}

MoveForward.cs をダウンロード

なお、Time.time を使うと、Play モードを開始してからの経過時間（秒）を取得できます。

注釈

FixedUpdate の中で Time.deltaTime を使うと、FixedUpdate の呼び出し間隔（Time.fixedDeltaTime）が返されます。

まとめ

  • Unity は、決まったタイミングでイベント関数を自動的に呼び出します。

  • 初期化は Awake と Start で、毎フレームの処理は Update で行います。

  • LateUpdate は、すべての Update が終わった後に呼ばれます。

  • Update で移動量を計算するときは、Time.deltaTime を掛けて、フレームレートに左右されないようにします。
