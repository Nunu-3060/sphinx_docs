第 13 章 頂点アニメーション

頂点シェーダーでは、頂点の位置を自由に変えられる。この章では、この性質を使って、メッシュを波打たせる表現と、オブジェクトを常にカメラの方に向ける表現（ビルボード）を作る。

この章のサンプルコードは、examples/chapter13 フォルダーにある。

頂点アニメーションの特徴

頂点アニメーションは、C# のスクリプトでメッシュの頂点を書き換える方法と比べて、次の特徴がある。

  • GPU で計算するため、頂点の数が多くても高速である。

  • メッシュのデータ自体は変わらないため、物理演算の当たり判定（Collider）には反映されない。

  • 頂点を動かした結果は、カメラの視錐台によるカリングに反映されない。メッシュの元の範囲（バウンディングボックス）が画面の外にあると、動かした頂点が画面の中にあっても描画されないことがある。

波打つ表面

次のシェーダーは、頂点の y 座標を、x 座標と時間から求めた正弦波で上下に動かす。

Wave.shader
 1// 第 13 章：頂点シェーダーで頂点を上下に動かし、波打つ表面を作るシェーダー。
 2// 頂点の多いメッシュ（Plane など）に使う。
 3Shader "Introduction/Chapter13/Wave"
 4{
 5    Properties
 6    {
 7        [MainColor] _BaseColor ("Base Color", Color) = (0.2, 0.5, 1, 1)
 8        // 波の高さ（オブジェクト空間の単位）
 9        _Amplitude ("Amplitude", Float) = 0.3
10        // 1 単位の距離あたりの波の数（値が大きいほど波が細かくなる）
11        _Frequency ("Frequency", Float) = 2
12        // 波の進む速さ
13        _Speed ("Speed", Float) = 2
14    }
15
16    SubShader
17    {
18        Tags
19        {
20            "RenderType" = "Opaque"
21            "Queue" = "Geometry"
22            "RenderPipeline" = "UniversalPipeline"
23        }
24
25        Pass
26        {
27            Name "Wave"
28            Tags { "LightMode" = "UniversalForward" }
29
30            HLSLPROGRAM
31            #pragma vertex Vert
32            #pragma fragment Frag
33
34            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
35            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"
36
37            struct Attributes
38            {
39                float4 positionOS : POSITION;
40            };
41
42            struct Varyings
43            {
44                float4 positionCS : SV_POSITION;
45                float3 normalWS : TEXCOORD0;
46            };
47
48            CBUFFER_START(UnityPerMaterial)
49                half4 _BaseColor;
50                float _Amplitude;
51                float _Frequency;
52                float _Speed;
53            CBUFFER_END
54
55            Varyings Vert(Attributes input)
56            {
57                Varyings output;
58                float3 positionOS = input.positionOS.xyz;
59
60                // x 座標と時間から、正弦波（sin）で y 方向の変位を求める
61                float phase = positionOS.x * _Frequency + _Time.y * _Speed;
62                positionOS.y += sin(phase) * _Amplitude;
63
64                // 頂点を動かすと元の法線は使えなくなるため、
65                // 波の傾きから法線を計算し直す。
66                // y = A sin(fx + st) の x での微分は A f cos(fx + st) なので、
67                // 接線は (1, A f cos, 0)、法線はそれに垂直な (-A f cos, 1, 0) になる。
68                float slope = _Amplitude * _Frequency * cos(phase);
69                float3 normalOS = normalize(float3(-slope, 1.0, 0.0));
70
71                output.positionCS = TransformObjectToHClip(positionOS);
72                output.normalWS = TransformObjectToWorldNormal(normalOS);
73                return output;
74            }
75
76            half4 Frag(Varyings input) : SV_Target
77            {
78                float3 normalWS = normalize(input.normalWS);
79                Light mainLight = GetMainLight();
80
81                half3 ambient = SampleSH(normalWS) * _BaseColor.rgb;
82                half nDotL = saturate(dot(normalWS, mainLight.direction));
83                half3 diffuse = _BaseColor.rgb * mainLight.color * nDotL;
84
85                return half4(ambient + diffuse, 1.0);
86            }
87            ENDHLSL
88        }
89    }
90}

Wave.shader をダウンロード

GameObject ‣ 3D Object ‣ Plane で Plane を作成し、このシェーダーのマテリアルを設定すると、表面が波打つ。Plane は 10×10 単位の大きさで、縦横 11 個ずつ（121 個）の頂点を持つ。

頂点の変位

頂点の変位は、次の式で求めている。\(A\) は振幅（_Amplitude）、\(f\) は周波数（_Frequency）、\(s\) は速さ（_Speed）、\(t\) は経過時間（_Time.y）である。

\[y = A \sin(f x + s t)\]

\(t\) が増えるにつれて波の形が x の負の方向へ移動し、波が流れているように見える。

法線の再計算

頂点を動かすと、面の向きが変わるため、メッシュに記録された元の法線は使えなくなる。そのまま使うと、形は波打っているのに陰影は平らなままになる。そこで、波の傾きから法線を計算し直している。

波の式を x で微分すると、傾きは \(\frac{dy}{dx} = A f \cos(f x + s t)\) になる。x 方向に 1 進むと y が傾きの分だけ変わるので、表面に沿った方向（接線）は \((1,\ \frac{dy}{dx},\ 0)\) である。法線はこれに垂直な方向なので、次のようになる。

\[\mathbf{n} = \mathrm{normalize}\left(-\frac{dy}{dx},\ 1,\ 0\right)\]

接線との内積を計算すると \(-\frac{dy}{dx} + \frac{dy}{dx} = 0\) となり、垂直であることが確かめられる。

注釈

Plane の頂点は 1 単位ごとにしかないため、_Frequency を大きくすると、波の山と谷の間に頂点がなくなり、波の形が崩れる。細かい波を表現するには、頂点の多いメッシュを使う必要がある。テッセレーションで実行時に頂点を増やす方法もあるが、動作する環境が限られるため、本資料では扱わない（第 4 章を参照）。

ビルボード

ビルボードは、板ポリゴンを常にカメラの方に向けて描画する技法である。木や草、炎、パーティクルなどを、少ない頂点で表現するときに使う。

Billboard.shader
 1// 第 13 章：オブジェクトがいつもカメラの方を向くようにする（ビルボード）シェーダー。
 2// XY 平面上に作られた Quad メッシュに使う。
 3Shader "Introduction/Chapter13/Billboard"
 4{
 5    Properties
 6    {
 7        [MainTexture] _BaseMap ("Base Map", 2D) = "white" {}
 8        [MainColor] _BaseColor ("Base Color", Color) = (1, 1, 1, 1)
 9        _Cutoff ("Alpha Cutoff", Range(0, 1)) = 0.5
10    }
11
12    SubShader
13    {
14        // DisableBatching：
15        // 複数のメッシュが 1 つにまとめられるとオブジェクトの中心が分からなくなるため、
16        // バッチングを無効にする
17        Tags
18        {
19            "RenderType" = "TransparentCutout"
20            "Queue" = "AlphaTest"
21            "RenderPipeline" = "UniversalPipeline"
22            "DisableBatching" = "True"
23        }
24
25        Pass
26        {
27            Name "Billboard"
28            Tags { "LightMode" = "UniversalForward" }
29
30            HLSLPROGRAM
31            #pragma vertex Vert
32            #pragma fragment Frag
33
34            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
35
36            struct Attributes
37            {
38                float4 positionOS : POSITION;
39                float2 uv : TEXCOORD0;
40            };
41
42            struct Varyings
43            {
44                float4 positionCS : SV_POSITION;
45                float2 uv : TEXCOORD0;
46            };
47
48            TEXTURE2D(_BaseMap);
49            SAMPLER(sampler_BaseMap);
50
51            CBUFFER_START(UnityPerMaterial)
52                float4 _BaseMap_ST;
53                half4 _BaseColor;
54                half _Cutoff;
55            CBUFFER_END
56
57            Varyings Vert(Attributes input)
58            {
59                Varyings output;
60
61                // オブジェクトの中心（原点）をビュー空間に変換する
62                float3 centerWS = TransformObjectToWorld(float3(0.0, 0.0, 0.0));
63                float3 centerVS = TransformWorldToView(centerWS);
64
65                // ビュー空間では x 軸が画面の右、y 軸が画面の上を向いている。
66                // 中心から頂点の xy 分だけずらすと、頂点が常に画面と平行な面に並ぶ。
67                // ワールド行列を通らないため、Transform の Scale は反映されない。
68                float3 positionVS = centerVS + float3(input.positionOS.xy, 0.0);
69
70                output.positionCS = TransformWViewToHClip(positionVS);
71                output.uv = TRANSFORM_TEX(input.uv, _BaseMap);
72                return output;
73            }
74
75            half4 Frag(Varyings input) : SV_Target
76            {
77                half4 color = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, input.uv) * _BaseColor;
78                clip(color.a - _Cutoff);
79                return half4(color.rgb, 1.0);
80            }
81            ENDHLSL
82        }
83    }
84}

GameObject ‣ 3D Object ‣ Quad で Quad を作成し、このシェーダーのマテリアルを設定する。Scene ビューでカメラを回り込ませても、Quad は常にこちらを向いて表示される。

ビルボードのしくみ

ビュー空間では、x 軸が画面の右、y 軸が画面の上を向いている（第 3 章を参照）。そのため、ビュー空間で頂点を xy 方向にずらすと、頂点は常に画面と平行な面に並ぶ。

サンプルでは、次の手順で頂点の位置を求めている。

  1. オブジェクトの中心（オブジェクト空間の原点）を、ワールド空間を経由してビュー空間に変換する。

  2. ビュー空間の中心の位置に、頂点のオブジェクト空間の xy 座標を加える。Quad の頂点は、オブジェクト空間の XY 平面上にあるため、これで画面と平行な Quad になる。

  3. TransformWViewToHClip 関数で、ビュー空間からクリップ空間に変換する。

モデル変換の行列を頂点に直接適用しないため、Transform の Rotation と Scale は反映されない。大きさを変えたい場合は、シェーダーにプロパティを追加して、xy 座標に掛ける必要がある。

バッチングの無効化

サブシェーダーのタグで "DisableBatching" = "True" を指定している。Unity の静的バッチングなどは、複数のオブジェクトのメッシュを 1 つにまとめ、頂点をワールド空間の座標にして描画する。その場合、オブジェクト空間の原点が各オブジェクトの中心ではなくなるため、ビルボードの計算が正しく行えない。このタグを指定すると、このシェーダーを使うオブジェクトはバッチングの対象から外れる。
