第 5 章 Unity の描画のしくみ

この章では、Unity がシーンをどのように描画しているかを、シェーダーを書く立場から説明する。

レンダーパイプライン

レンダーパイプラインは、シーンのどのオブジェクトを、どの順番で、どのような方法で描画するかを決めるしくみである。第 4 章の GPU のレンダリングパイプラインが 1 回のドローコールの中の処理であるのに対し、Unity のレンダーパイプラインは、1 フレーム全体の描画の手順を決める。

Unity には、次の 3 つのレンダーパイプラインがある。

レンダーパイプライン

特徴

ビルトインレンダーパイプライン

以前からある標準のパイプライン。カスタマイズできる範囲が限られている。

Universal Render Pipeline（URP）

スマートフォンから PC、家庭用ゲーム機まで、幅広い環境で動作するパイプライン。

High Definition Render Pipeline（HDRP）

高性能な PC や家庭用ゲーム機で、写実的な表現を行うためのパイプライン。

URP と HDRP は、Scriptable Render Pipeline（SRP）と呼ばれるしくみの上に作られている。SRP では、描画の手順が C# で書かれており、利用者が拡張できる。

本資料では URP を対象とする。URP は Unity 6 の新規プロジェクトのテンプレート（Universal 3D など）で使われており、最も多くの環境で動作するためである。

重要

シェーダーの書き方は、レンダーパイプラインごとに異なる。ビルトインレンダーパイプライン向けのシェーダー（UnityCG.cginc を読み込むものや、Surface Shader と呼ばれる書き方のもの）は、URP では正しく動作しない。インターネット上のシェーダーを参考にするときは、どのレンダーパイプライン向けのものかを確認してほしい。

メッシュ、マテリアル、シェーダーの関係

3D のオブジェクトを描画するには、次の要素が必要である。

要素

役割

Mesh Filter

描画するメッシュ（頂点と三角形のデータ）を指定するコンポーネント。

Mesh Renderer

メッシュを、指定したマテリアルで描画するコンポーネント。

マテリアル

使うシェーダーと、そのシェーダーに渡すプロパティの値（色、テクスチャー、数値など）の組み合わせ。

シェーダー

頂点とピクセルの処理を記述したプログラム。

同じシェーダーを使う複数のマテリアルを作り、プロパティの値だけを変えることで、見た目の異なるオブジェクトを作れる。例えば、赤い床と青い壁は、同じシェーダーを使う 2 つのマテリアルで表現できる。

URP の描画の流れ

URP は、カメラごとに次の順で描画を行う。

  1. カリング：カメラの視錐台に入っていないオブジェクトを、描画の対象から外す。

  2. シャドウマップの描画：影を落とすライトから見たシーンの深度を描画する（第 11 章を参照）。

  3. 不透明なオブジェクトの描画：手前から奥の順に描画する。手前のものを先に描くと、奥のフラグメントが深度テストで破棄され、無駄な処理が減る。

  4. スカイボックスの描画

  5. 半透明なオブジェクトの描画：奥から手前の順に描画する（第 12 章を参照）。

  6. ポストエフェクト：描画した画面全体に、色調補正などの処理を行う（第 15 章を参照）。

描画の順序は、レンダーキューと呼ばれる値で決まる。レンダーキューは、シェーダーの Queue タグで指定し、マテリアルごとに変更することもできる（第 6 章を参照）。

レンダリングパス

URP では、ライトの計算方法として、次のレンダリングパスを選べる。レンダリングパスは、URP Asset から参照される Universal Renderer Data アセットの Rendering Path で設定する。

レンダリングパス

特徴

Forward

オブジェクトを描画するときに、そのオブジェクトに当たるライトをすべて計算する。1 つのオブジェクトに影響するライトの数に上限がある。

Forward+

Forward と同じくオブジェクトを描画するときにライトを計算するが、画面を小さな領域に分け、領域ごとに影響するライトだけを計算する。ライトの数の上限が大きい。

Deferred

先に全オブジェクトの法線や色などを複数のテクスチャー（G バッファー）に書き出し、あとでまとめてライトを計算する。

本資料のサンプルは、Forward と Forward+ で動作するように書いている。Deferred では、LightMode が UniversalForward のパスが使われないため、サンプルのオブジェクトは表示されない。Deferred に対応するには、G バッファーを書き出すためのパスを追加するか、パスの LightMode を UniversalForwardOnly（Deferred でも Forward で描画するパス）にする必要がある。本資料では Deferred は扱わない。

パスと LightMode タグ

1 つのシェーダーは、複数のパスを持てる。パスは、1 回の描画の処理の単位である。URP は、描画の段階ごとに、パスの LightMode タグを見て、その段階で使うパスを選ぶ。本資料で使う LightMode タグの値を、次の表に示す。

LightMode の値

用途

UniversalForward

Forward と Forward+ で、オブジェクトの色を描画するパス。

SRPDefaultUnlit

UniversalForward と同じ段階で描画される追加のパス。LightMode タグを書かないパスも、この値として扱われる。

ShadowCaster

シャドウマップに深度を書き込むパス（第 11 章を参照）。

DepthOnly

カメラの深度テクスチャーに深度を書き込むパス（第 11 章を参照）。

シェーダーの記述は、パスごとに分かれている。例えば、画面に色を描くパスと、影を落とすためのパスは、それぞれ別の頂点シェーダーとフラグメントシェーダーを持つ。

SRP Batcher

ドローコールを送るたびに、CPU はマテリアルのプロパティの値を GPU に送る準備をする。オブジェクトの数が多いと、この準備にかかる時間が描画の速度を下げる原因になる。

SRP Batcher は、マテリアルのプロパティの値を GPU のメモリに保持し、値が変わったときだけ更新することで、この準備の時間を減らすしくみである。URP では、既定で SRP Batcher が有効になっている。

シェーダーを SRP Batcher に対応させるには、次の条件を満たす必要がある。

  • マテリアルのプロパティ（テクスチャーを除く）を、UnityPerMaterial という名前の定数バッファーにまとめて宣言する。

  • シェーダーのすべてのパスで、UnityPerMaterial の内容を同じにする。

本資料のサンプルは、すべて SRP Batcher に対応するように書いている。具体的な書き方は第 7 章で説明する。シェーダーが SRP Batcher に対応しているかどうかは、シェーダーアセットを選択したときの Inspector ウィンドウの SRP Batcher の項目で確認できる。
