第 3 章 座標変換

メッシュの頂点の位置は、モデルを作ったときの座標で保存されている。この位置を画面上のピクセルの位置にするには、いくつかの座標空間を順に変換する必要がある。この章では、その流れと、各段階で使う行列を説明する。

座標空間の流れ

頂点の位置は、次の順に変換される。

座標空間

変数名の接尾辞

内容

オブジェクト空間

OS

メッシュごとの座標。モデルの中心（ピボット）が原点になる。ローカル空間、モデル空間とも呼ぶ。

ワールド空間

WS

シーン全体で共通の座標。Transform の Position、Rotation、Scale を適用した位置。

ビュー空間

VS

カメラを原点とし、カメラの向きを基準にした座標。カメラ空間とも呼ぶ。

クリップ空間

CS

投影変換を適用した 4 次元の同次座標。画面に映る範囲かどうかの判定（クリッピング）に使う。

正規化デバイス座標（NDC）

なし

クリップ空間の座標を \(w\) で割った座標。画面に映る範囲が一定の範囲に収まる。

スクリーン空間

なし

画面上のピクセルの位置。

URP のシェーダーでは、変数名の末尾に座標空間を表す接尾辞を付ける習慣がある。例えば positionOS はオブジェクト空間の位置、normalWS はワールド空間の法線である。本資料のサンプルも、この習慣に従う。

モデル変換

オブジェクト空間からワールド空間への変換を、モデル変換という。モデル変換の行列 \(M\) は、Transform の Scale（拡大縮小 \(S\)）、Rotation（回転 \(R\)）、Position（平行移動 \(T\)）の順に適用する行列を掛け合わせたものである。

\[M = T R S\]

第 2 章で説明したとおり、先に適用する変換ほど右側に置くため、式の上では \(S\) が最も右になる。親を持つ GameObject の場合は、親のモデル変換の行列がさらに左から掛けられる。

URP のシェーダーでは、TransformObjectToWorld 関数でモデル変換を行う。

ビュー変換

ワールド空間からビュー空間への変換を、ビュー変換という。ビュー変換の行列 \(V\) は、カメラを原点に移動し、カメラの向きが座標軸に合うように回転させる行列である。カメラのモデル変換の逆行列に相当する。

Unity のビュー空間は、x 軸が画面の右、y 軸が画面の上を向く右手系で、カメラは z 軸の負の向きを見る。そのため、カメラの前にある点のビュー空間での z 座標は負になる。これは OpenGL の慣習に合わせたものである。

URP のシェーダーでは、TransformWorldToView 関数でビュー変換を行う。

投影変換

ビュー空間からクリップ空間への変換を、投影変換という。投影変換の行列 \(P\) には、次の 2 種類がある。

投影の種類

内容

透視投影

遠くのものほど小さく見える投影。カメラの Projection が Perspective のときに使われる。

平行投影

距離に関係なく同じ大きさで見える投影。カメラの Projection が Orthographic のときに使われる。

透視投影では、カメラの視野角（Field of View）と、描画する距離の範囲（Clipping Planes の Near と Far）で決まる四角錐台（視錐台）の中が、画面に映る範囲になる。

URP のシェーダーでは、TransformWViewToHClip 関数で投影変換を行う。

MVP 行列

モデル変換、ビュー変換、投影変換の 3 つの行列をまとめたものを、MVP 行列という。オブジェクト空間の位置 \(\mathbf{p}_{OS}\) からクリップ空間の位置 \(\mathbf{p}_{CS}\) への変換は、次の式で表される。

\[\mathbf{p}_{CS} = P V M \mathbf{p}_{OS}\]

頂点シェーダーの最も重要な仕事は、この変換を行ってクリップ空間の位置を出力することである。URP のシェーダーでは、TransformObjectToHClip 関数で、オブジェクト空間からクリップ空間まで一度に変換できる。

透視除算と正規化デバイス座標

クリップ空間の座標 \((x, y, z, w)\) を \(w\) で割ることを、透視除算という。透視投影では、\(w\) にカメラからの距離に比例した値が入るため、\(w\) で割ると遠くの点ほど画面の中心に近づき、小さく見えるようになる。

\[\mathbf{p}_{NDC} = \left(\frac{x}{w},\ \frac{y}{w},\ \frac{z}{w}\right)\]

透視除算のあとの座標を、正規化デバイス座標（NDC）という。NDC では、画面に映る範囲の x と y が -1～1 に収まる。z の範囲はグラフィックス API によって異なり、Direct3D、Vulkan、Metal では 0～1、OpenGL では -1～1 である。

透視除算は GPU が自動的に行うため、頂点シェーダーではクリップ空間の座標を出力するだけでよい。

注釈

Direct3D、Vulkan、Metal では、Unity は深度の値を反転して、手前を 1、奥を 0 として扱う（Reversed Z）。浮動小数点数の精度を遠くの深度に多く割り当て、遠くのオブジェクトどうしが重なって見える現象を減らすためである。シェーダーの中では、Reversed Z が有効かどうかを UNITY_REVERSED_Z マクロで判定できる。

ビューポート変換

NDC の x と y を、画面のピクセルの位置に変換することをビューポート変換という。例えば、幅 1920 ピクセル、高さ 1080 ピクセルの画面では、NDC の x の -1～1 が 0～1920 に、y の -1～1 が 0～1080 に対応する。ビューポート変換も GPU が自動的に行う。

法線の変換

法線は、位置とは異なる方法で変換する必要がある。拡大縮小が軸ごとに異なる場合（例えば Scale が (2, 1, 1) の場合）に、法線を位置と同じ行列 \(M\) で変換すると、法線が面に垂直でなくなるためである。

面の上の方向（接線）を \(\mathbf{t}\)、法線を \(\mathbf{n}\) とすると、両者は垂直なので \(\mathbf{n} \cdot \mathbf{t} = 0\) である。変換後の接線は \(M\mathbf{t}\) になるので、変換後の法線 \(\mathbf{n}'\) は \(\mathbf{n}' \cdot (M\mathbf{t}) = 0\) を満たす必要がある。この条件を満たすのが、\(M\) の逆行列の転置行列（逆転置行列）で変換した法線である。

\[\mathbf{n}' = (M^{-1})^{\mathsf{T}} \mathbf{n}\]

実際に内積を計算すると、\(\mathbf{n}' \cdot (M\mathbf{t}) = \mathbf{n}^{\mathsf{T}} M^{-1} M \mathbf{t} = \mathbf{n} \cdot \mathbf{t} = 0\) となり、垂直な関係が保たれることが分かる。なお、法線の変換には \(M\) の左上の 3×3 の部分だけを使う。法線は方向なので、平行移動の影響を受けないためである。

URP のシェーダーでは、TransformObjectToWorldNormal 関数で法線をワールド空間に変換できる。この関数は、逆転置行列による変換と正規化を行う。

座標変換の関数

URP のシェーダーライブラリで使う主な座標変換の関数を、次の表にまとめる。これらは Core.hlsl を読み込むと使えるようになる。

関数

変換

TransformObjectToWorld

オブジェクト空間の位置 → ワールド空間の位置

TransformWorldToView

ワールド空間の位置 → ビュー空間の位置

TransformWViewToHClip

ビュー空間の位置 → クリップ空間の位置

TransformWorldToHClip

ワールド空間の位置 → クリップ空間の位置

TransformObjectToHClip

オブジェクト空間の位置 → クリップ空間の位置

TransformObjectToWorldNormal

オブジェクト空間の法線 → ワールド空間の法線（正規化済み）

TransformObjectToWorldDir

オブジェクト空間の方向 → ワールド空間の方向（正規化済み）
