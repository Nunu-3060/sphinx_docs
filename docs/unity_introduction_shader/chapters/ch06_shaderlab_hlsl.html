第 6 章 ShaderLab と HLSL の基礎

Unity のシェーダーファイル（.shader）は、2 つの言語を組み合わせて書く。

  • ShaderLab：Unity 独自の言語。シェーダーの構造、マテリアルのプロパティ、描画の設定（ブレンドや深度テストなど）を記述する。

  • HLSL（High-Level Shading Language）：GPU で実行されるプログラムを記述する言語。Microsoft が Direct3D 向けに開発した言語で、C 言語に似た文法を持つ。

ShaderLab の中に HLSL のコードを埋め込む形で、1 つのシェーダーファイルを書く。この章では、両方の言語の基本を説明する。実際に動くシェーダーは第 7 章で作る。

シェーダーファイルの構造

シェーダーファイルは、次のような入れ子の構造になっている。

Shader "Introduction/Example"
{
    Properties
    {
        // マテリアルのプロパティ
    }

    SubShader
    {
        Tags { /* サブシェーダーのタグ */ }

        Pass
        {
            Tags { /* パスのタグ */ }
            // 描画の設定（ブレンドや深度テストなど）

            HLSLPROGRAM
            // HLSL のコード
            ENDHLSL
        }
    }
}

各ブロックの役割を、次の表に示す。

ブロック

役割

Shader

シェーダー全体。後ろの文字列は、マテリアルの Shader のドロップダウンに表示される名前である。/ で区切ると階層になる。

Properties

マテリアルの Inspector ウィンドウに表示するプロパティを宣言する。

SubShader

描画の方法を記述する。1 つのシェーダーに複数のサブシェーダーを書くと、Unity は使っている環境で動作する最初のサブシェーダーを選ぶ。

Pass

1 回の描画の処理。1 つのサブシェーダーに複数のパスを書ける。

HLSLPROGRAM ～ ENDHLSL

HLSL のコードを書く範囲。

HLSLINCLUDE ～ ENDHLSL

サブシェーダーの中のすべてのパスで共通に使う HLSL のコードを書く範囲。

Properties ブロック

Properties ブロックでは、マテリアルで値を設定できるプロパティを、次の形式で宣言する。

変数名 ("表示名", 型) = 既定値

主なプロパティの型を、次の表に示す。

型

宣言の例

HLSL での宣言の例

Float

_Speed ("Speed", Float) = 1

float _Speed;

Range(min, max)

_Cutoff ("Cutoff", Range(0, 1)) = 0.5

half _Cutoff;

Color

_BaseColor ("Base Color", Color) = (1, 1, 1, 1)

half4 _BaseColor;

Vector

_ScrollSpeed ("Scroll Speed", Vector) = (0, 0, 0, 0)

float4 _ScrollSpeed;

2D

_BaseMap ("Base Map", 2D) = "white" {}

TEXTURE2D(_BaseMap);

2D 型の既定値には、テクスチャーが設定されていないときに使う色を "white"、"black"、"gray"、"bump" などで指定する。"bump" は法線マップ用の既定値である（第 10 章を参照）。

Properties ブロックで宣言しただけでは、HLSL のコードから値を参照できない。HLSL のコードの中でも、同じ名前の変数を宣言する必要がある。URP では、変数名の先頭に _ を付け、_BaseColor や _BaseMap のような名前にする習慣がある。

プロパティの前に [属性] を書くと、Inspector ウィンドウでの表示方法などを変えられる。

属性

効果

[MainColor]

C# の Material.color でこのプロパティを読み書きできるようにする。

[MainTexture]

C# の Material.mainTexture でこのプロパティを読み書きできるようにする。

[HDR]

色の各成分に 1 より大きい値を設定できるようにする。

[Normal]

法線マップ以外のテクスチャーが設定されたときに警告を表示する。

[NoScaleOffset]

テクスチャーの Tiling と Offset の入力欄を表示しない。

[KeywordEnum(A, B)]

ドロップダウンで選んだ項目に応じて、シェーダーのキーワードを切り替える（第 17 章を参照）。

タグ

タグは、"名前" = "値" の組で、サブシェーダーやパスの情報を Unity に伝える。

サブシェーダーのタグ

タグ

意味

RenderPipeline

このサブシェーダーを使うレンダーパイプライン。URP では "UniversalPipeline" を指定する。

Queue

描画の順序を表す値（レンダーキュー）。値の小さいものから先に描画される（次の「レンダーキュー」を参照）。

RenderType

シェーダーの分類。"Opaque"、"TransparentCutout"、"Transparent" などを指定する。一部の機能が、描画するオブジェクトを選ぶために使う。

レンダーキュー

Queue タグで指定する描画の順序の値を、レンダーキューという。レンダーキューには、次の名前の付いた値がある。

名前

値

用途

Background

1000

最初に描画するもの。背景など。

Geometry

2000

不透明なオブジェクト。Queue タグを書かない場合の既定値。

AlphaTest

2450

アルファテストを使うオブジェクト（第 12 章を参照）。

Transparent

3000

半透明のオブジェクト（第 12 章を参照）。

Overlay

4000

最後に描画するもの。レンズフレアなど、すべての上に重ねる表現。

値が 2500 以下のものは不透明として扱われ、URP は原則として手前から奥の順に並べて描画する。2500 より大きいものは半透明として扱われ、奥から手前の順に並べて描画する（第 5 章と第 12 章を参照）。

"Transparent+1" のように、名前の後ろに数を足して細かい順序を指定することもできる。また、マテリアルの Inspector ウィンドウの Render Queue で、マテリアルごとにレンダーキューを変更することもできる。

サブシェーダーの LOD

サブシェーダーの中に LOD 300 のように書くと、サブシェーダーに LOD（Level of Detail、詳細度）の値を割り当てられる。LOD の値は、そのサブシェーダーの処理の重さの目安である。

C# で Shader.maximumLOD や Shader.globalMaximumLOD を設定すると、Unity は LOD の値がその上限以下のサブシェーダーだけを使う。1 つのシェーダーに、重くて見た目のよいサブシェーダーと、軽いサブシェーダーを LOD の値の大きい順に書いておくと、性能の低い環境では軽いサブシェーダーに切り替えられる。本資料のサンプルは、サブシェーダーを 1 つしか持たないため、LOD を書いていない。

パスのタグ

パスのタグで最も重要なのは LightMode である。URP は LightMode の値を見て、そのパスをどの段階で使うかを決める（第 5 章を参照）。

描画の設定

パスの中（HLSLPROGRAM の外）には、GPU の固定機能の段階の設定を書ける。サブシェーダーの中に書くと、すべてのパスに適用される。

コマンド

意味

Cull Back / Front / Off

裏面を描画しない（既定）／表面を描画しない／両面を描画する。

ZWrite On / Off

深度バッファーに書き込む（既定）／書き込まない。

ZTest LEqual / Always など

深度テストの比較方法。LEqual（既定）は、深度バッファーの値と同じか手前のときに描画する。Always は常に描画する。

Blend SrcAlpha OneMinusSrcAlpha など

ブレンドの方法（第 12 章を参照）。

ColorMask 0 など

色を書き込むチャンネル。0 にすると色を書き込まない。

HLSL の基本

データ型

HLSL の主なデータ型を、次の表に示す。

型

内容

float

32 ビットの浮動小数点数。位置や UV 座標など、精度が必要な値に使う。

half

16 ビットの浮動小数点数。色や正規化した方向など、精度がそれほど必要ない値に使う。スマートフォンなどでは float より高速に計算できる。

int / uint

32 ビットの整数／符号なし整数。

bool

真偽値。

float2、float3、float4

2～4 個の float を持つベクトル。half にも half2 などがある。

float3x3、float4x4

3×3、4×4 の行列。

注釈

PC の多くの GPU では、half は float と同じ 32 ビットで計算される。そのため、PC で正しく表示されても、スマートフォンでは精度が足りずに表示が崩れることがある。迷ったときは float を使えばよい。

ベクトルの成分は、.x、.y、.z、.w または .r、.g、.b、.a で取り出せる。成分の名前を並べると、複数の成分をまとめて取り出したり、並べ替えたりできる（スウィズル）。

float4 color = float4(1.0, 0.5, 0.2, 1.0);
float3 rgb = color.rgb;   // (1.0, 0.5, 0.2)
float2 uv = color.xy;     // (1.0, 0.5)
float3 bgr = color.bgr;   // (0.2, 0.5, 1.0)
float3 gray = color.rrr;  // (1.0, 1.0, 1.0)

ベクトルどうしの四則演算は、成分ごとに行われる。例えば、float3(1, 2, 3) * float3(2, 2, 2) は float3(2, 4, 6) になる。

組み込み関数

HLSL には、シェーダーでよく使う計算が関数として用意されている。

関数

内容

dot(a, b)

内積

cross(a, b)

外積

normalize(v)

正規化したベクトル

length(v)

ベクトルの長さ

mul(m, v)

行列とベクトルの積

lerp(a, b, t)

線形補間

saturate(x)

0～1 の範囲に切り詰めた値

clamp(x, min, max)

指定した範囲に切り詰めた値

step(edge, x)

x が edge 以上なら 1、そうでなければ 0

smoothstep(a, b, x)

x が a から b に変わる間に、0 から 1 へ滑らかに変化する値

frac(x)

小数部分

pow(x, y)

べき乗

sin(x)、cos(x)

三角関数（引数の単位はラジアン）

セマンティクス

HLSL では、頂点シェーダーの入力や、シェーダーの出力の変数に、そのデータの意味を表すセマンティクスを : の後ろに付ける。

struct Attributes
{
    float4 positionOS : POSITION;  // 頂点の位置
    float3 normalOS : NORMAL;      // 頂点の法線
    float2 uv : TEXCOORD0;         // 1 つ目の UV 座標
};

主なセマンティクスを、次の表に示す。

セマンティクス

意味

POSITION

頂点シェーダーの入力：メッシュの頂点の位置

NORMAL

頂点シェーダーの入力：メッシュの頂点の法線

TANGENT

頂点シェーダーの入力：メッシュの頂点の接線（第 10 章を参照）

TEXCOORD0、TEXCOORD1 など

頂点シェーダーの入力では UV 座標。頂点シェーダーの出力では、フラグメントシェーダーに渡す任意のデータ

COLOR

頂点シェーダーの入力：メッシュの頂点カラー

SV_POSITION

頂点シェーダーの出力：クリップ空間の位置

SV_Target

フラグメントシェーダーの出力：描画先に書き込む色

SV_ で始まるセマンティクスは、GPU にとって特別な意味を持つ値（システム値）である。

プリプロセッサー

# で始まる行は、コンパイルの前に処理される命令である。

命令

意味

#pragma vertex 関数名

頂点シェーダーとして使う関数を指定する。

#pragma fragment 関数名

フラグメントシェーダーとして使う関数を指定する。

#include "ファイル名"

ほかのファイルの内容を読み込む。

#pragma multi_compile、#pragma shader_feature

シェーダーのバリアントを作るキーワードを宣言する（第 11 章と第 17 章を参照）。

#if、#else、#endif

条件によってコードを切り替える。

URP のシェーダーライブラリ

URP には、シェーダーを書くための関数やマクロをまとめたライブラリが用意されている。本資料で読み込む主なファイルを、次の表に示す。

ファイル

内容

Core.hlsl

座標変換の関数、テクスチャーのマクロ、Unity が設定する変数（時間、カメラの位置など）

Lighting.hlsl

ライトの情報を取得する関数、環境光や影の関数

Shadows.hlsl

影に関する関数（Lighting.hlsl からも読み込まれる）

これらのファイルは、Packages/com.unity.render-pipelines.universal/ShaderLibrary/ の下にある。Project ウィンドウの Packages の下の Universal RP から、実際のコードを読むこともできる。関数の正確な動作を知りたいときは、ライブラリのコードを直接読むのが確実である。
