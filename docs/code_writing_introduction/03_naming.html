3. 名前の付け方

変数、関数、クラスなどの名前は、コードを読む人が最初に目にする情報である。適切な名前が付いていれば、中身を細かく読まなくても何をしているのかが分かる。逆に、名前が不適切だと、読む人は中身をすべて追わなければならない。

3.1. 悪い例

次のコードは、点数の一覧から合格者の人数を数え、ある点数が満点かどうかを調べる。

リスト 3.1 ch03_naming_bad.py
 1"""第 3 章「名前の付け方」の悪い例。"""
 2
 3
 4def calc(d: list[int]) -> int:
 5    r = 0
 6    for x in d:
 7        if x >= 60:
 8            r += 1
 9    return r
10
11
12def chk(s: int) -> bool:
13    return s == 100
14
15
16if __name__ == "__main__":
17    lst = [72, 45, 100, 60, 38]
18    print(calc(lst))
19    print(chk(lst[2]))

ch03_naming_bad.py をダウンロードする

このコードには次の問題がある。

  • 関数名 calc と chk からは、何を計算し、何を確認するのかが分からない。

  • 変数名 d、r、x、s、lst からは、何が入っているのかが分からない。

  • 60 と 100 が何を意味する数なのか、コードを読んだだけでは分からない。

このような意味の分からない数値を マジックナンバー と呼ぶ。

3.2. 良い例

リスト 3.2 ch03_naming_good.py
 1"""第 3 章「名前の付け方」の良い例。"""
 2
 3PASSING_SCORE = 60
 4PERFECT_SCORE = 100
 5
 6
 7def count_passed(scores: list[int]) -> int:
 8    passed_count = 0
 9    for score in scores:
10        if score >= PASSING_SCORE:
11            passed_count += 1
12    return passed_count
13
14
15def is_perfect(score: int) -> bool:
16    return score == PERFECT_SCORE
17
18
19if __name__ == "__main__":
20    test_scores = [72, 45, 100, 60, 38]
21    print(count_passed(test_scores))
22    print(is_perfect(test_scores[2]))

ch03_naming_good.py をダウンロードする

関数名 count_passed から「合格者を数える」ことが、is_perfect から「満点かどうかを調べる」ことが分かる。60 と 100 には PASSING_SCORE（合格点）と PERFECT_SCORE（満点）という名前を付けた。合格点を変えたくなったときも、PASSING_SCORE の 1 か所を直すだけで済む。

3.3. 名前で役割を伝える

名前は、それが「何であるか」「何をするか」を表すように付ける。

表 3.1 名前の付け方の目安

対象

付け方

例

変数

中に入っている値を表す名詞にする。

score、user_name、total_price

リストなどの集まり

複数形にする。

scores、users

関数

処理の内容を表す動詞から始める。

count_passed、calculate_total、load_config

真偽値（True か False）

is_、has_、can_ などで始め、「はい」か「いいえ」で答えられる形にする。

is_perfect、has_permission、can_edit

リストを複数形にしておくと、for score in scores: のように、1 つずつ取り出す変数に単数形を使える。これにより「集まり」と「その中の 1 つ」の区別が付きやすくなる。

3.4. 具体的な名前を選ぶ

data、info、value、tmp、result のような名前は、どんな値にも当てはまってしまうため、ほとんど情報を持たない。できるだけ具体的な名前を選ぶ。

リスト 3.3 悪い例
1data = load("users.csv")
2tmp = data[0]
リスト 3.4 良い例
1users = load("users.csv")
2first_user = users[0]

3.5. 単位や種類を名前に含める

数値に単位がある場合は、名前に単位を含めると誤解を防げる。

リスト 3.5 悪い例
1timeout = 30     # 秒なのかミリ秒なのか分からない
2size = 2048      # バイトなのかキロバイトなのか分からない
リスト 3.6 良い例
1timeout_seconds = 30
2file_size_bytes = 2048

3.6. 省略しすぎない

usr、cnt、calc_ttl_prc のような省略形は、書く人にとっては短くて便利だが、読む人には意味が伝わりにくい。名前は多少長くなっても、省略せずに書く方がよい。

ただし、広く知られた略語（id、url、html など）は使ってよい。また、数行で終わる短いループの中だけで使う変数であれば、i のような短い名前でも問題にならないことが多い。目安として、変数を使う範囲が広いほど、説明的な名前を付ける。

3.7. マジックナンバーを定数にする

コードの中に直接書かれた数値は、その意味が読み取れないことが多い。意味のある数値には名前を付けて 定数 にする。Python には変更できない定数の仕組みは無いが、すべて大文字の名前を付けて「この値は変更しない」ことを示す習慣がある。

リスト 3.7 悪い例
1if len(password) < 8:
2    print("パスワードが短すぎる")
リスト 3.8 良い例
1MIN_PASSWORD_LENGTH = 8
2
3if len(password) < MIN_PASSWORD_LENGTH:
4    print("パスワードが短すぎる")

定数にすると、次の利点がある。

  • 数値の意味が名前から分かる。

  • 同じ数値を複数の場所で使っていても、値を変更するときは 1 か所を直すだけで済む。

なお、0 や 1 のように意味が明らかな数値まで、すべて定数にする必要はない。

3.8. Python の命名規則

Python には、コーディングスタイルの指針である PEP 8 があり、名前の書き方についても次のように定めている。

表 3.2 PEP 8 の主な命名規則

対象

書き方

例

変数、関数

小文字の単語を _ でつなぐ（スネークケース）。

user_name、count_passed

定数

大文字の単語を _ でつなぐ。

MAX_SIZE、PASSING_SCORE

クラス

各単語の先頭を大文字にしてつなぐ（パスカルケース）。

Book、OrderStatus

決まった書き方にそろえておくと、名前を見ただけで、それが変数なのか、定数なのか、クラスなのかが区別できる。

3.9. まとめ

  • 名前は、それが何であるか、何をするかが伝わるように付ける。

  • data や tmp のようなあいまいな名前を避け、具体的な名前を選ぶ。

  • 必要に応じて、単位や種類を名前に含める。

  • 意味のある数値には名前を付けて定数にする。

  • PEP 8 の命名規則に従う。
