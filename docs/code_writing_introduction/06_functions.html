6. 関数を小さく分ける

1 つの関数にたくさんの処理を詰め込むと、その関数は長く、複雑になる。長い関数は、全体を理解するのに時間がかかり、一部を変更したときの影響も分かりにくい。この章では、関数を小さく分ける方法を説明する。

6.1. 悪い例

次のコードは、商品の一覧（商品名、単価、個数の組）を受け取り、レシートを表示する。合計金額が 5000 円以上の場合は 10% 割り引く。

リスト 6.1 ch06_functions_bad.py
 1"""第 6 章「関数を小さく分ける」の悪い例。"""
 2
 3
 4def process(items: list[tuple[str, int, int]]) -> None:
 5    total = 0
 6    lines: list[str] = []
 7    for item in items:
 8        if item[1] < 0 or item[2] <= 0:
 9            print("不正な商品: " + item[0])
10            continue
11        subtotal = item[1] * item[2]
12        total += subtotal
13        lines.append(item[0] + " x" + str(item[2]) + " = " + str(subtotal) + "円")
14    if total >= 5000:
15        discount = total // 10
16    else:
17        discount = 0
18    total -= discount
19    for line in lines:
20        print(line)
21    print("割引: " + str(discount) + "円")
22    print("合計: " + str(total) + "円")
23
24
25if __name__ == "__main__":
26    process([("ノート", 150, 10), ("ペン", 120, 30), ("消しゴム", 80, 0)])

実行結果は次のとおりである。

1不正な商品: 消しゴム
2ノート x10 = 1500円
3ペン x30 = 3600円
4割引: 510円
5合計: 4590円

関数 process は、次の 5 つの役割を 1 つの関数で担っている。

  1. 商品のデータが正しいかを確認する（8 行目から 10 行目）。

  2. 小計と合計を計算する（11 行目と 12 行目）。

  3. 表示用の文字列を作る（13 行目）。

  4. 割引額を計算する（14 行目から 18 行目）。

  5. 結果を表示する（19 行目から 22 行目）。

このように役割が混ざっていると、例えば「割引の条件を変えたい」ときに、関数全体を読んで割引に関係する部分を探さなければならない。また、関数名 process（処理する）からは、何をする関数なのかが分からない。

6.2. 良い例

リスト 6.2 ch06_functions_good.py
 1"""第 6 章「関数を小さく分ける」の良い例。"""
 2
 3Item = tuple[str, int, int]  # (商品名, 単価, 個数)
 4
 5DISCOUNT_THRESHOLD = 5000
 6DISCOUNT_RATE_PERCENT = 10
 7
 8
 9def is_valid_item(item: Item) -> bool:
10    _, unit_price, quantity = item
11    return unit_price >= 0 and quantity > 0
12
13
14def subtotal_of(item: Item) -> int:
15    _, unit_price, quantity = item
16    return unit_price * quantity
17
18
19def calculate_discount(total: int) -> int:
20    if total >= DISCOUNT_THRESHOLD:
21        return total * DISCOUNT_RATE_PERCENT // 100
22    return 0
23
24
25def format_item_line(item: Item) -> str:
26    name, _, quantity = item
27    return f"{name} x{quantity} = {subtotal_of(item)}円"
28
29
30def print_receipt(items: list[Item]) -> None:
31    for item in items:
32        if not is_valid_item(item):
33            print(f"不正な商品: {item[0]}")
34
35    valid_items = [item for item in items if is_valid_item(item)]
36    total = sum(subtotal_of(item) for item in valid_items)
37    discount = calculate_discount(total)
38
39    for item in valid_items:
40        print(format_item_line(item))
41    print(f"割引: {discount}円")
42    print(f"合計: {total - discount}円")
43
44
45if __name__ == "__main__":
46    print_receipt([("ノート", 150, 10), ("ペン", 120, 30), ("消しゴム", 80, 0)])

それぞれの役割を、名前の付いた小さな関数に分けた。関数どうしの呼び出し関係を 図 6.1 に示す。

関数 print_receipt を読むと、「正しくない商品を報告し、合計と割引額を求め、結果を表示する」という処理の流れが分かる。細かい計算の方法を知りたいときだけ、それぞれの関数を読めばよい。割引の条件を変えたいときは、calculate_discount と定数だけを見ればよい。

6.3. 1 つの関数には 1 つの役割を持たせる

関数を分けるときの基本は、1 つの関数には 1 つの役割だけを持たせることである。役割が 1 つであれば、その役割を表す名前を付けやすい。逆に、関数に良い名前が付けられないときは、その関数が複数の役割を持っている可能性がある。名前に「and」が入ってしまう場合も同様である。

関数を小さく分けると、次の利点がある。

  • 関数の名前が、処理の内容の説明になる。

  • 1 つの関数が短くなり、理解しやすくなる。

  • 変更が必要なとき、直す場所を特定しやすく、影響の範囲も限られる。

  • 同じ処理を別の場所でも使える。例えば subtotal_of は print_receipt と format_item_line の両方から使われている。

  • 関数ごとに動作を確かめられるため、テストしやすい（第 11 章を参照）。

関数の長さについて決まった基準は無いが、画面をスクロールせずに全体を見渡せる長さが 1 つの目安になる。

6.4. 計算と表示を分ける

悪い例の process は、計算と表示を 1 つの関数で行っている。このような関数は、計算結果を画面に表示する以外の用途（ファイルへの保存など）に使えず、計算が正しいかどうかを確かめるには、表示された文字を目で確認するしかない。

良い例では、calculate_discount は値を受け取って値を返すだけで、画面への表示は print_receipt にまとめている。関数の外の状態を変える動作（画面への表示、ファイルへの書き込み、グローバル変数の変更など）を 副作用 と呼ぶ。副作用を持つ処理と持たない処理を分けておくと、副作用の無い関数は、同じ引数に対して必ず同じ値を返すため、動作を理解しやすく、テストもしやすい。

6.5. 引数は少なくする

引数が多い関数は、呼び出すときに引数の順番や意味を間違えやすい。

リスト 6.3 悪い例
1create_user("山田", "太郎", 20, True, False, "東京都")

この呼び出しを見ても、True と False が何を意味するのか分からない。次のような方法で改善できる。

  • 関数が多くの役割を持っていないか見直し、分けられないか考える。

  • 関係の深い引数を 1 つのデータにまとめる（第 9 章を参照）。

  • キーワード引数を使って呼び出し、引数の意味を明示する。

リスト 6.4 キーワード引数を使った例
1create_user(
2    family_name="山田",
3    given_name="太郎",
4    age=20,
5    is_admin=True,
6    receives_newsletter=False,
7    prefecture="東京都",
8)

6.6. 型ヒントを書く

本書のサンプルコードでは、関数の引数と戻り値に 型ヒント を付けている。

1def calculate_discount(total: int) -> int:
2    ...

total: int は「引数 total は整数」であることを、-> int は「戻り値は整数」であることを表す。型ヒントを書くと、関数の使い方がコードから分かるようになる。また、第 11 章で紹介する mypy などの道具を使えば、型の誤りを実行前に見つけられる。

型ヒントは Python の実行時には検査されない。間違った型の値を渡しても、そのまま実行される点に注意が必要である。

6.7. まとめ

  • 1 つの関数には 1 つの役割を持たせ、その役割を表す名前を付ける。

  • 良い名前が付けられない関数は、役割が多すぎないか見直す。

  • 計算などの処理と、表示などの副作用を持つ処理を分ける。

  • 引数が多くなりすぎないようにし、必要に応じてキーワード引数を使う。

  • 引数と戻り値には型ヒントを書く。
