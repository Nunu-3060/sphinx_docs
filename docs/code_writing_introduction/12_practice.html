12. 実践：悪いコードを直してみる

この章では、1 つの悪いプログラムを、第 3 章から第 10 章で学んだ方法を使って、段階的に書き直す。一度にすべてを直すのではなく、少しずつ直し、そのたびに動作が変わっていないことを確かめながら進める。

12.1. 元のコード

次のコードは、生徒ごとに 3 科目の点数を受け取り、合計点、平均点、評価（A、B、C）を表示する。最後に、全員の全科目の平均点を表示する。評価は、平均点が 80 点以上なら A、60 点以上なら B、それ以外は C とする。

リスト 12.1 ch12_step0_original.py
 1"""第 12 章「実践：悪いコードを直してみる」の元のコード。"""
 2
 3
 4def main(d: list[tuple[str, int, int, int]]) -> None:
 5    t2 = 0
 6    for s in d:
 7        t = s[1] + s[2] + s[3]
 8        a = t / 3
 9        if a >= 80:
10            g = "A"
11        else:
12            if a >= 60:
13                g = "B"
14            else:
15                g = "C"
16        print(s[0] + ": 合計 " + str(t) + " 点, 平均 " + str(round(a, 1)) + " 点, 評価 " + g)
17    for s in d:
18        t2 += s[1] + s[2] + s[3]
19    print("全体の平均: " + str(round(t2 / (len(d) * 3), 1)) + " 点")
20

12.2. 手順 1: 名前と定数を直す

まず、名前を意味の分かるものに変え、マジックナンバーを定数にする。また、表示する文字列を f 文字列で組み立て、表示される形を読み取りやすくする。

リスト 12.2 ch12_step1_naming.py
 1"""第 12 章「実践：悪いコードを直してみる」の手順 1（名前と定数）の結果。"""
 2
 3EXCELLENT_THRESHOLD = 80
 4PASSING_THRESHOLD = 60
 5SUBJECT_COUNT = 3
 6
 7
 8def main(records: list[tuple[str, int, int, int]]) -> None:
 9    grand_total = 0
10    for record in records:
11        total = record[1] + record[2] + record[3]
12        average = total / SUBJECT_COUNT
13        if average >= EXCELLENT_THRESHOLD:
14            grade = "A"
15        else:
16            if average >= PASSING_THRESHOLD:
17                grade = "B"
18            else:
19                grade = "C"
20        print(f"{record[0]}: 合計 {total} 点, 平均 {average:.1f} 点, 評価 {grade}")
21    for record in records:
22        grand_total += record[1] + record[2] + record[3]
23    print(f"全体の平均: {grand_total / (len(records) * SUBJECT_COUNT):.1f} 点")
24
25
26if __name__ == "__main__":
27    main([("佐藤", 85, 90, 78), ("鈴木", 60, 55, 70), ("高橋", 40, 52, 38)])

名前を変えただけだが、20 行目の print を読めば何を表示しているのかが分かり、13 行目の average >= EXCELLENT_THRESHOLD からは「平均点が A の基準以上か」を調べていることが分かるようになった。

12.3. 手順 2: 関数に分け、処理の流れを整理する

次に、関数 main が担っていた役割を、小さな関数に分ける。

リスト 12.3 ch12_step2_functions.py
 1"""第 12 章「実践：悪いコードを直してみる」の手順 2（関数の分割と処理の流れ）の結果。"""
 2
 3EXCELLENT_THRESHOLD = 80
 4PASSING_THRESHOLD = 60
 5SUBJECT_COUNT = 3
 6
 7Record = tuple[str, int, int, int]  # (名前, 科目 1 の点数, 科目 2 の点数, 科目 3 の点数)
 8
 9
10def total_score(record: Record) -> int:
11    _, score1, score2, score3 = record
12    return score1 + score2 + score3
13
14
15def grade_of(average: float) -> str:
16    if average >= EXCELLENT_THRESHOLD:
17        return "A"
18    if average >= PASSING_THRESHOLD:
19        return "B"
20    return "C"
21
22
23def format_record_line(record: Record) -> str:
24    name = record[0]
25    total = total_score(record)
26    average = total / SUBJECT_COUNT
27    return f"{name}: 合計 {total} 点, 平均 {average:.1f} 点, 評価 {grade_of(average)}"
28
29
30def print_report(records: list[Record]) -> None:
31    for record in records:
32        print(format_record_line(record))
33    grand_total = sum(total_score(record) for record in records)
34    print(f"全体の平均: {grand_total / (len(records) * SUBJECT_COUNT):.1f} 点")
35
36
37if __name__ == "__main__":
38    print_report([("佐藤", 85, 90, 78), ("鈴木", 60, 55, 70), ("高橋", 40, 52, 38)])

ch12_step2_functions.py をダウンロードする

この手順では、次の変更を行った。

  • 合計点を求める処理を関数 total_score にまとめた。手順 1 では 2 か所にあった合計点の計算が、1 か所になった。

  • 評価を決める処理を関数 grade_of にまとめ、早期リターンを使ってネストをなくした。

  • 生徒 1 人分の表示用の文字列を作る処理を関数 format_record_line にまとめた。

  • 全体を表示する関数の名前を、main から、役割を表す print_report に変えた。

  • タプルの型に Record という名前を付け、何を表すタプルなのかをコメントで説明した。

print_report を読むと、「生徒ごとの行を表示し、全体の平均を表示する」という処理の流れが分かる。

12.4. 手順 3: データをまとめ、エラーに備える

最後に、生徒のデータをデータクラスにまとめ、docstring を書き、不正なデータへの対処を加える。

リスト 12.4 ch12_step3_data.py
 1"""第 12 章「実践：悪いコードを直してみる」の手順 3（データとエラー処理）の結果。"""
 2
 3from dataclasses import dataclass
 4
 5EXCELLENT_THRESHOLD = 80
 6PASSING_THRESHOLD = 60
 7
 8
 9@dataclass
10class Student:
11    """生徒 1 人分の成績。"""
12
13    name: str
14    scores: list[int]
15
16    def __post_init__(self) -> None:
17        if not self.scores:
18            raise ValueError(f"{self.name} の点数が 1 つも無い")
19
20    @property
21    def total(self) -> int:
22        return sum(self.scores)
23
24    @property
25    def average(self) -> float:
26        return self.total / len(self.scores)
27
28
29def grade_of(average: float) -> str:
30    """平均点から評価（A, B, C）を決める。"""
31    if average >= EXCELLENT_THRESHOLD:
32        return "A"
33    if average >= PASSING_THRESHOLD:
34        return "B"
35    return "C"
36
37
38def format_student_line(student: Student) -> str:
39    """生徒 1 人分の成績を 1 行の文字列にする。"""
40    return f"{student.name}: 合計 {student.total} 点, 平均 {student.average:.1f} 点, 評価 {grade_of(student.average)}"
41
42
43def overall_average(students: list[Student]) -> float:
44    """全生徒・全科目の点数の平均を返す。
45
46    Raises:
47        ValueError: 生徒が 1 人もいない場合。
48    """
49    if not students:
50        raise ValueError("生徒が 1 人もいない")
51    score_sum = sum(student.total for student in students)
52    score_count = sum(len(student.scores) for student in students)
53    return score_sum / score_count
54
55
56def print_report(students: list[Student]) -> None:
57    """生徒ごとの成績と全体の平均を表示する。"""
58    for student in students:
59        print(format_student_line(student))
60    print(f"全体の平均: {overall_average(students):.1f} 点")
61
62
63if __name__ == "__main__":
64    print_report([
65        Student("佐藤", [85, 90, 78]),
66        Student("鈴木", [60, 55, 70]),
67        Student("高橋", [40, 52, 38]),
68    ])

ch12_step3_data.py をダウンロードする

この手順では、次の変更を行った。

  • 生徒の名前と点数の一覧をデータクラス Student にまとめた。record[0] のような添字の代わりに、student.name のように名前で値を取り出せる。

  • 点数をリストで持つようにしたため、科目の数が 3 つに限られなくなった。これに伴い、定数 SUBJECT_COUNT は不要になった。

  • 合計点と平均点を、Student の total と average として定義した。@property を付けたメソッドは、student.total のように、かっこを付けずに属性と同じ形で呼び出せる。

  • 点数が 1 つも無い生徒を作ろうとすると、__post_init__ で ValueError を送出するようにした。__post_init__ は、データクラスのオブジェクトが作られた直後に自動で呼ばれるメソッドである。

  • 全体の平均を求める処理を関数 overall_average にまとめ、生徒が 1 人もいない場合は、分かりやすいメッセージ付きの ValueError を送出するようにした。

  • 関数とクラスに docstring を書いた。

完成したコードと元のコードを比べてほしい。実行結果はまったく同じだが、コードを読んだときの分かりやすさは大きく違う。また、「評価の基準を変える」「科目を増やす」「表示の形を変える」といった変更が必要になったとき、どこを直せばよいのかがすぐに分かる。

12.5. さらに改善するには

完成したコードにも、まだ改善の余地はある。例えば、次のような改善が考えられる。

  • grade_of や overall_average のテストを書く（第 11 章を参照）。テストがあれば、今後の変更で動作が壊れていないかをすぐに確かめられる。

  • 評価を文字列 "A"、"B"、"C" ではなく、列挙型で表す（第 9 章を参照）。

どこまで改善するかは、プログラムの規模や、今後どれだけ変更される見込みがあるかによって判断する。数回しか使わない小さなプログラムに、大がかりな改善は必要無い。一方で、長く使われ、多くの人が手を加えるプログラムでは、改善にかけた手間は将来の保守の手間を減らす形で返ってくる。

12.6. まとめ

  • 悪いコードは、一度にすべて直そうとせず、少しずつ段階的に直す。

  • 1 つの段階を終えるたびに、動作が変わっていないことを確かめる。テストがあれば、この確認を自動で行える。

  • 名前、関数の分け方、処理の流れ、データの扱い方、エラーの扱い方という観点を組み合わせることで、コードは大きく読みやすくなる。

  • どこまで改善するかは、プログラムの使われ方に応じて判断する。
