4. 見た目を整える

インデント、空白、空行の入れ方は、プログラムの動作にはほとんど影響しない。しかし、見た目がそろっていないコードは読みにくく、読む人の注意を本来の内容からそらしてしまう。

4.1. 悪い例

次のコードは、円の面積を求める関数と、数値の一覧から平均と最大値を求める関数である。正しく動作するが、見た目が整っていない。

リスト 4.1 悪い例
1import statistics,math
2def circle_area( radius ):
3    return math.pi*radius**2
4def summarize(values):
5  average=statistics.mean(values)
6  maximum = max( values )
7  return f"平均: {average:.1f}, 最大: {maximum:.1f}"

このコードには次の問題がある。

  • 1 行目で、2 つのモジュールを 1 行で import している。

  • 関数と関数の間に空行が無く、どこで関数が区切られているのか分かりにくい。

  • 関数 circle_area はインデントが 4 文字、関数 summarize は 2 文字で、そろっていない。

  • average=... では = の前後に空白が無いが、maximum = ... では空白がある。

  • ( radius ) や max( values ) のように、かっこの内側に不要な空白がある。

1 つ 1 つは小さな問題だが、書き方がそろっていないと「この違いには何か意味があるのか」と読む人を迷わせる。

4.2. 良い例

4.3. PEP 8 に従う

Python には、コーディングスタイルの指針として PEP 8 がある。多くの Python プログラマーが PEP 8 に従ってコードを書いているため、PEP 8 に従えば、他の人にとっても読みやすいコードになる。PEP 8 の主な内容を次に示す。

表 4.1 PEP 8 の主な規則

項目

規則

インデント

1 段につき空白 4 文字を使う。

行の長さ

1 行を最大 79 文字にする。

空行

トップレベルの関数やクラスの定義の前後には 2 行、クラス内のメソッドの間には 1 行の空行を入れる。

import

1 行に 1 つのモジュールを書く。ファイルの先頭に、標準ライブラリ、サードパーティーのライブラリ、自作のモジュールの順に、グループごとに空行で区切って並べる。

演算子の前後の空白

代入（=）、累算代入（+= など）、比較（==、< など）、ブール演算（and、or、not）の演算子の前後には、空白を 1 つずつ入れる。

かっこの内側の空白

( )、[ ]、{ } の内側の直後と直前には空白を入れない。

カンマの後の空白

カンマの直前には空白を入れず、直後には空白を 1 つ入れる。

行の長さの上限は、PEP 8 では 79 文字だが、チームで合意すれば 99 文字まで延ばしてもよいとされている。行の長さの上限はプロジェクトごとに決めることが多く、本書のサンプルコードでは 120 文字を上限としている。

PEP 8 のすべてを覚える必要はない。第 11 章で紹介する flake8 などの道具を使えば、PEP 8 に違反している箇所を自動で見つけられる。

4.4. 空行で意味のまとまりを区切る

文章を段落に分けるように、コードも空行で意味のまとまりに区切ると読みやすくなる。

1def print_report(scores: list[int]) -> None:
2    total = sum(scores)
3    average = total / len(scores)
4
5    print(f"合計: {total}")
6    print(f"平均: {average:.1f}")

この例では、1 行目から 3 行目で値を計算し、空行を挟んで 5 行目と 6 行目で結果を表示している。空行によって「計算」と「表示」という 2 つのまとまりが見て分かるようになる。

4.5. 一貫性を保つ

見た目について最も大切なのは、一貫性である。PEP 8 は、PEP 8 との一貫性よりもプロジェクト内での一貫性が、さらにそれよりも 1 つのモジュールや関数の中での一貫性が重要だとしている。また、規則に従うとかえって読みにくくなる場合は、規則よりも読みやすさを優先してよいとも書いている。

既存のプロジェクトに手を加えるときは、そのプロジェクトの書き方に合わせる。新しく始めるときは、PEP 8 に従うのがよい。

4.6. まとめ

  • 見た目がそろっていないコードは、読む人の注意をそらし、迷わせる。

  • Python では PEP 8 に従って書く。

  • 空行を使って、意味のまとまりを区切る。

  • 1 つのプロジェクトの中では、書き方をそろえる。
