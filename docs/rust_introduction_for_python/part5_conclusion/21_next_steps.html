はじめに

ここまでで、変数・制御フローといった基礎から、所有権システム、エラーハンドリング、ジェネリクスとトレイト、ライフタイム、スマートポインタ、並行処理、そして Cargo によるプロジェクト管理まで、Rust の主要な機能を一通り学び終えました。前章では、それらを組み合わせて実際に動く CLI ツールも作成しました。

本章では、本書を読み終えたあとにどこへ進めばよいか、公式ドキュメントやコミュニティ、応用分野、そして本書では扱いきれなかった発展的なトピックを紹介します。

公式ドキュメント

Rust は公式ドキュメントが非常に充実している言語です。本書の内容をさらに深めたい場合は、まず次の3つを手元に置いておくとよいでしょう。

  • The Rust Programming Language いわゆる「The Book」と呼ばれる公式の入門書です。本書と重なる内容も多いですが、より詳細な解説や、本書では扱わなかったトピックも含まれています。英語ですが、Rust 学習者であればいずれ読んでおきたい定番の資料です。

  • Rust by Example コード例を中心に構成されたドキュメントです。「この機能を実際にどう書くのか」をすぐに確認したいときに便利です。ブラウザ上でコードを編集して実行できるのも特徴です。

  • 標準ライブラリドキュメント String、Vec、HashMap、Option、Result など、本書で扱った型の正確な仕様やメソッド一覧はここで確認できます。Rust を書く際には常に開いておきたいリファレンスです。

コミュニティ・フォーラム

分からないことがあったときや、書いたコードについて意見が欲しいときは、コミュニティに質問するのもよい方法です。

  • 公式のユーザーフォーラムである Rust Users Forum では、初心者向けの質問から高度な設計相談まで幅広く議論されています。

  • バグ報告や言語仕様の議論には Rust 公式の GitHub リポジトリ が使われています。

  • 日本語では、Rust 関連の情報をまとめたブログや Qiita の記事、日本語の Rust コミュニティ(Rust.Tokyo などの勉強会・カンファレンス)も増えてきています。日本語で検索する際は「Rust」に加えて具体的なエラーメッセージやクレート名を組み合わせると、有益な情報が見つかりやすくなります。

応用分野の広がり

Rust は汎用言語ですが、特に次のような分野で強みを発揮します。本書で学んだ基礎があれば、どの分野に進んでも読み進められるはずです。

  • Web バックエンド: axum や actix-web といった非同期対応の Web フレームワークを使うと、高性能な Web API サーバーを構築できます。これらのフレームワークは tokio という非同期ランタイムの上に成り立っており、多数のネットワーク接続を効率よくさばくために async/await という仕組みを使います。いずれも本書で学んだトレイトやジェネリクスの知識が前提になります。

  • CLI ツール: 前章では標準ライブラリだけで引数を処理しましたが、実務では clap というクレートを使うことで、ヘルプメッセージの自動生成やオプションの検証などを簡単に実装できます。

  • WebAssembly: wasm-pack などのツールを使うと、Rust のコードを WebAssembly にコンパイルし、ブラウザ上で高速に実行できます。性能が求められるフロントエンド処理との相性が良い分野です。

  • 組み込み(embedded): embedded-hal のような抽象化レイヤーを使うことで、マイコンなどのハードウェアを安全に制御できます。Rust の所有権システムはメモリが限られた組み込み環境でも大きな強みになります。

  • ゲーム開発: bevy に代表されるゲームエンジンを使うと、Rust の速度と安全性を活かしたゲームを作成できます。エンティティ・コンポーネント・システム(ECS)という設計を採用しているものが多く、パフォーマンスと保守性を両立しやすいのが特徴です。

  • システムプログラミング・データ処理: OS やドライバ、コマンドラインツールの高速化といった低レイヤーのシステムプログラミングは Rust の伝統的な得意分野です。近年では polars のようなデータ処理向けクレートも登場しており、Python の pandas に親しんだデータ分析寄りの読者にとっても身近な入り口になっています。

次に挑戦したい小さなプロジェクト

応用分野を眺めるだけでなく、実際に手を動かして小さなプログラムを作ってみることが、Rust を身につける一番の近道です。ここでは、本書で学んだ章と結び付けながら取り組める題材をいくつか紹介します。

  • TODO リスト管理 CLI: タスクを表す構造体と、状態(未着手・完了など)を表す列挙型を定義し、コマンドライン引数で追加・完了・削除ができるようにします。結果をファイルに保存・読み込みするところまで作れば、構造体・enum・エラーハンドリングの章の復習になります。

  • 簡単な HTTP クライアント: reqwest というクレートを使って Web API にリクエストを送り、返ってきた JSON を取得・表示するツールです。非同期関数の呼び出しに触れることになるため、非同期プログラミングへ進むための入り口としても手頃です。

  • ファイル整理・重複検出ツール: 指定したディレクトリ以下のファイルを走査し、内容が同じファイルを見つけて報告します。std::fs によるファイル操作と、イテレータの章で学んだ filter や collect などのメソッドを組み合わせる練習になります。ただし、ディレクトリを再帰的にたどる処理や、内容比較のためのハッシュ計算(標準ライブラリには汎用のハッシュ関数がないため、外部クレートが必要になります)が必要になるため、ここに挙げた題材の中ではやや難易度の高い部類です。

  • ミニ電卓: 四則演算を表す列挙型を定義し、文字列として入力された式を解釈して計算します。列挙型とパターンマッチングの章で学んだ内容を、より複雑な条件分岐の中で使う練習になります。

いずれも、本書のどれか1つの章だけでなく、複数の章の知識を組み合わせて初めて完成する題材です。まずは動くものを小さく作り、そこから機能を1つずつ追加していくとよいでしょう。

発展的なトピック

本書では、初学者が最短で Rust の基礎を身につけられるよう、あえて扱わなかったトピックもあります。興味を持った方は、ぜひ公式ドキュメントで学びを深めてください。

  • 非同期プログラミング (async/await): 関数を async にすることで、処理を一時停止・再開できる「Future」を返せるようになります。tokio が事実上の標準として広く使われており、ほかに async-std などの選択肢もあります。

  • unsafe Rust: unsafe はコンパイラの安全性チェックの一部を無効化し、生ポインタの操作やFFI(他言語との連携)などを可能にする機能です。強力ですが、正しく使うには本書で学んだ所有権や借用の仕組みをより深く理解している必要があります。

  • マクロ: macro_rules! による宣言的マクロや、独自の #[derive] を作成できる手続き的マクロは、繰り返しの多いコードを簡潔に書くための強力な機能です。

コンパイラのエラーメッセージの読み方

Rust を書いていると、コンパイルエラーに出会う機会は決して少なくありません。むしろ、実行時に初めて発覚したかもしれない不具合をコンパイル時に教えてくれる点こそが Rust の強みです。ここで、これまで何度も目にしてきたであろうエラーメッセージの読み方を簡単に整理しておきましょう。

たとえば、所有権の章で見た「ムーブ済みの値を使おうとした」コードは、実際には次のようなエラーメッセージを出力します。

error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:5:25
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s1; // s1 の所有権が s2 に移動する
  |              -- value moved here
4 |
5 |     println!("s1 = {}", s1);
  |                         ^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
3 |     let s2 = s1.clone(); // s1 の所有権が s2 に移動する
  |                ++++++++

このメッセージには、いくつか読み方のポイントがあります。

  • error[E0382] の E0382 の部分はエラーコードと呼ばれ、エラーの種類ごとに番号が割り振られています。

  • --> の行には、エラーが発生した実際のファイル名・行番号・列番号が示されます。

  • help: から始まる行では、多くの場合、具体的な修正案が提示されます。この例では clone を呼び出す修正が提案されています。

  • note: から始まる行が追加されることもあり、エラーの背景や関連する補足情報を伝えてくれます。

エラーコードが分かっている場合は、ターミナルで rustc --explain E0382 のように実行すると、そのエラーコードについてのより詳しい解説をまとめて読むことができます。エラーメッセージだけでは意図がつかみにくいときに活用してみてください。

なお、本書でも紹介した cargo clippy は、コンパイルエラーにはならないものの改善の余地があるコードに対して提案をしてくれるツールでした。コンパイラのエラーが「このままではコンパイルできない」という指摘であるのに対し、clippy の指摘は「コンパイルは通るが、こう書いた方がよい」という助言である点は異なりますが、どちらも具体的な help: 付きで改善案を示してくれるという点ではよく似た役割を果たしています。

まとめ

本書では、Rust の基本文法から始まり、所有権システムという Rust ならではの考え方、エラーハンドリングやジェネリクス・トレイト、ライフタイムや並行処理といった中級以上のトピックまでを扱い、最後に簡単な CLI ツールとして実際に動くコードにまとめました。

Rust は学習コストが高い言語だとよく言われますが、その分、コンパイラがバグの多くを実行前に指摘してくれるという大きな利点があります。最初はコンパイラのエラーメッセージに苦労することも多いでしょうが、本書で学んだ所有権・借用・トレイトといった考え方は、書けば書くほど自然に身についていきます。

ぜひ本章で紹介した公式ドキュメントやコミュニティを活用しながら、自分の興味のある分野で小さなプロジェクトを作り続けてみてください。それが、Rust を本当の意味で身につける一番の近道です。
