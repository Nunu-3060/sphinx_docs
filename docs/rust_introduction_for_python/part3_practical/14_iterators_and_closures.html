イテレータとクロージャ

コレクションの要素を1つずつ処理したり、その場限りの小さな関数を渡して処理をカスタマイズしたりすることは、Python でも lambda やリスト内包表記としてよく使われます。Rust にも同様の目的で使われる「クロージャ」と「イテレータ」という機能があり、これらを組み合わせることで、ループを直接書くよりも簡潔で読みやすいコードを書けます。

クロージャの定義と環境のキャプチャ

クロージャは、変数に代入できる無名の関数です。引数を縦棒 | で囲んで書きます。

fn main() {
    let add_one = |x: i32| x + 1;
    println!("{}", add_one(5)); // 6

    let multiplier = 3;
    // クロージャは周囲の変数 multiplier をキャプチャできる
    let multiply = |x: i32| x * multiplier;
    println!("{}", multiply(4)); // 12
}

通常の関数(fn)と異なり、クロージャは定義された場所の変数を「キャプチャ」して、その中で使うことができます。上の multiply は、外側のスコープにある multiplier を暗黙のうちに借用して利用しています。関数の引数として渡したり、他の関数から返したりすることもできる点も、Python の関数オブジェクトの扱いに近い感覚です。

クロージャは通常、周囲の変数を借用してキャプチャしますが、move キーワードを付けると、借用ではなく所有権ごとキャプチャします。

fn main() {
    let s = String::from("hello");
    let closure = move || println!("{}", s);
    closure();
}

move を付けると変数の所有権がクロージャ側に移るため、以降は元の変数 s を使うことはできません。move は、特に後の並行処理の章でスレッドに処理を渡す際、必要なデータの所有権ごとクロージャに渡すためによく使われます。

なお、クロージャは環境をどのように使うかによって、Fn/FnMut/FnOnce という3種類のトレイトを実装します。これらは互いに排他的ではなく、Fn を実装するクロージャは FnMut と FnOnce も、FnMut を実装するクロージャは FnOnce も、それぞれ自動的に実装しているという包含関係になっています(値をキャプチャして消費するクロージャは FnOnce のみ、値を可変で借用するクロージャは FnMut と FnOnce、値を不変で借用するかキャプチャしないクロージャは3つすべてを実装します)。詳細を意識しなくても大抵の場面では問題なく使えるため、ここでは「クロージャが環境をどう使うかによって、これらのうち実装するトレイトが変わる」という程度に覚えておけば十分です。

Fn/FnMut/FnOnce は、ジェネリクスとトレイトの章で学んだ他のトレイトと同じように、トレイト境界として使うこともできます。これにより、クロージャを引数に取る関数をジェネリクスで書けます。

fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(x)
}

fn main() {
    let double = |x: i32| x * 2;
    println!("{}", apply(double, 5)); // 10
}

apply は、i32 を受け取って i32 を返す Fn を実装した型なら何でも受け取れるジェネリック関数です。クロージャを引数として渡す関数を自分で書きたくなったときは、この形を思い出すとよいでしょう。

イテレータアダプタ: map / filter / collect / sum

Rust では、Vec などのコレクションから iter() を呼ぶことでイテレータを作れます。イテレータの正体は、next(&mut self) -> Option<Self::Item> というメソッドを持つ Iterator トレイトを実装した値です。next() を呼ぶたびに次の要素が Some に包まれて返り、要素が尽きると None が返ります。for ループは、内部で IntoIterator によってイテレータを取り出し、next() が None を返すまで繰り返し呼び出す処理へと展開(デシュガー)されています。Self::Item はジェネリクスとトレイトの章で紹介した関連型で、Iterator を実装する側が「自分が返す要素の型は何か」を決める仕組みです。イテレータには、map や filter のように、別のイテレータを生成する「アダプタ」メソッドが多数用意されています。

fn main() {
    let numbers = vec![1, 2, 3, 4, 5];

    // 偶数だけを取り出し、2倍にする
    let doubled_evens: Vec<i32> = numbers
        .iter()
        .filter(|&&x| x % 2 == 0)
        .map(|x| x * 2)
        .collect();

    println!("{:?}", doubled_evens); // [4, 8]

    // 合計値を求める
    let total: i32 = numbers.iter().sum();
    println!("合計: {}", total); // 15
}

filter は条件を満たす要素だけを残し、map は各要素にクロージャを適用して変換します。これらは自分自身ではイテレータを最後まで進めないため、最終的に collect で Vec などのコレクションに変換したり、sum で合計を求めたりすることで初めて結果が確定します。

ここで、filter のクロージャ引数が |&&x| という二重参照のパターンになっているのに対し、直後の map は |x| という単一のパターンで受けている点に気づいたかもしれません。iter() は要素への参照(&T)を生成するため、filter のクロージャは &Item、つまりこの場合は &&i32 (&i32 への参照)を引数として受け取ります。|&&x| というパターンで参照を2段階剥がすことで、中身の x: i32 を取り出し、x % 2 のように値同士の比較ができるようにしています。一方 filter は要素そのものは変更せず &i32 のまま次に渡すため、map は |x| で x: &i32 を受け取ります。標準ライブラリは &i32 同士の四則演算も実装しているため、x * 2 は明示的に *x と参照を外さなくてもそのまま計算できます。

よく使うその他のイテレータメソッド

map/filter/collect/sum 以外にも、実務でよく使われるイテレータメソッドがあります。代表的なものを紹介します。

enumerate() は、各要素にインデックス(添字)を付けて反復します。

fn main() {
    let fruits = vec!["apple", "banana", "cherry"];

    for (i, fruit) in fruits.iter().enumerate() {
        println!("{}: {}", i, fruit);
    }
}

fold() は、初期値から始めて各要素を使って値を畳み込んでいきます。sum を汎用化したようなメソッドです。

fn main() {
    let numbers = vec![1, 2, 3, 4];
    let product = numbers.iter().fold(1, |acc, x| acc * x);
    println!("{}", product); // 24
}

any()/all() は、条件を満たす要素が1つでもあるか(any)、すべての要素が条件を満たすか(all)を調べ、bool を返します。

fn main() {
    let numbers = vec![1, 2, 3, 4];

    println!("{}", numbers.iter().any(|&x| x % 2 == 0)); // true
    println!("{}", numbers.iter().all(|&x| x % 2 == 0)); // false
}

zip()/chain()/take()/skip() も、複数のイテレータを組み合わせたり、要素数を絞り込んだりする際によく使われます。

  • zip(): 2つのイテレータの要素を1つずつペアにした新しいイテレータを作ります。どちらか短い方の要素数で終わります。

  • chain(): 2つのイテレータを、前後につなげた1つのイテレータにします。

  • take(n): 先頭から n 個の要素だけを取り出すイテレータにします。

  • skip(n): 先頭から n 個の要素を読み飛ばすイテレータにします。

fn main() {
    let names = vec!["Alice", "Bob"];
    let ages = vec![30, 25];

    // 名前と年齢をペアにする
    for (name, age) in names.iter().zip(ages.iter()) {
        println!("{}: {}歳", name, age);
    }

    let a = vec![1, 2];
    let b = vec![3, 4];

    // 2つのベクタを連結したイテレータ
    let combined: Vec<i32> = a.iter().chain(b.iter()).cloned().collect();
    println!("{:?}", combined); // [1, 2, 3, 4]

    let numbers = vec![1, 2, 3, 4, 5];

    // 先頭2個だけ取り出す / 先頭2個を読み飛ばす
    let first_two: Vec<&i32> = numbers.iter().take(2).collect();
    let rest: Vec<&i32> = numbers.iter().skip(2).collect();
    println!("{:?} / {:?}", first_two, rest); // [1, 2] / [3, 4, 5]
}

遅延評価の考え方

イテレータアダプタの重要な特徴は、それ自体を作った時点では何も処理が実行されないという点です。これを「遅延評価」と呼びます。

fn main() {
    let numbers = vec![1, 2, 3];

    // この時点では filter や map の中身はまだ実行されない
    let iter = numbers.iter().filter(|&&x| x > 1).map(|x| x * 10);

    // collect が呼ばれた瞬間に、要素ごとの処理がまとめて走る
    let result: Vec<i32> = iter.collect();
    println!("{:?}", result); // [20, 30]
}

filter や map は、内部的には「次の要素を求められたときにどう処理するか」を記述しているだけで、collect・sum・ for ループなど、イテレータを実際に「消費」する操作が呼ばれて初めて要素ごとの処理が実行されます。これにより、途中で不要なイテレータアダプタを重ねても、余分な中間コレクションを作らずに効率よく処理できます。

iter()、into_iter()、iter_mut() の違い

ここまで使ってきた iter() は、要素への不変参照(&T)を生成するイテレータを作ります。元のコレクションはそのまま残るため、後で再び使うことができます。

このほかにも、目的に応じて使い分けられる2つのメソッドがあります。

  • into_iter(): 要素の所有権そのものを移動するイテレータを作ります。呼び出した後、元のコレクションは使えなくなります。

  • iter_mut(): 要素への可変参照(&mut T)を生成するイテレータを作ります。イテレータを通じて要素の中身を書き換えられます。

fn main() {
    let mut numbers = vec![1, 2, 3];

    // 可変参照で各要素を書き換える
    for n in numbers.iter_mut() {
        *n *= 10;
    }
    println!("{:?}", numbers); // [10, 20, 30]

    // 所有権を移動しながら反復する(numbers はこの後使えなくなる)
    let doubled: Vec<i32> = numbers.into_iter().map(|n| n * 2).collect();
    println!("{:?}", doubled); // [20, 40, 60]
}

所有権の章で学んだ「借用するか、所有権を移動するか、可変参照にするか」という考え方は、イテレータにもそのまま現れています。iter()/into_iter()/iter_mut() の使い分けは、まさにこの3パターンに対応しています。

Python 経験者向けメモ

Rust の map/filter は、Python のリスト内包表記や lambda と組み合わせた map/filter 関数に近い役割を果たします。例えば先ほどの例は Python では [x * 2 for x in numbers if x % 2 == 0] のように書けます。

ただし評価のタイミングが異なります。Python のリスト内包表記はその場で全要素を処理し、即座にリストを作る「即時評価」です。一方 Rust のイテレータアダプタは、collect などで消費されるまで実際の処理が走らない「遅延評価」です。この性質は、Python のリスト内包表記よりもむしろジェネレータ式((x * 2 for x in numbers))や yield を使ったジェネレータ関数の動作に近いといえます。

まとめ

  • クロージャは |引数| 式 の形で定義する無名関数で、周囲の変数を環境としてキャプチャできます。

  • move を付けると、クロージャは変数を借用するのではなく所有権ごとキャプチャします。並行処理でスレッドにデータを渡す際によく使われます。

  • クロージャは環境の使い方に応じて Fn/FnMut/FnOnce トレイトを実装します。これらは排他的ではなく、Fn は FnMut/FnOnce を、FnMut は FnOnce を自動的に含む関係になっていますが、詳細を意識しなくても大抵の場面では問題なく使えます。

  • map/filter などのイテレータアダプタを使うと、ループを直接書かずにコレクションの変換や絞り込みを表現できます。

  • enumerate()/fold()/any()/all() なども、map/filter と並んでよく使われるイテレータメソッドです。

  • collect/sum などでイテレータを「消費」した時点で初めて要素ごとの処理が実行される「遅延評価」の性質を持つため、複数のアダプタを連結しても無駄な中間コレクションを作らずに効率よく処理できます。この性質は、Python のリスト内包表記よりもジェネレータの動作に近いといえます。

  • iter() は不変参照、into_iter() は所有権の移動、iter_mut() は可変参照のイテレータを作ります。所有権の章で学んだ考え方が、そのままイテレータの使い分けにも現れています。
