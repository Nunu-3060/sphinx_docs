並行処理の基礎

Rust は「恐れるものがない並行処理(fearless concurrency)」を掲げる言語です。所有権システムとその借用ルールは、コンパイル時にデータ競合を防ぐ役割も担っています。この章では、スレッドの生成から排他制御、スレッド間通信までの基本を見ていきます。

スレッドの生成

新しいスレッドを立ち上げるには std::thread::spawn を使います。戻り値の JoinHandle に対して join を呼び出すと、そのスレッドの終了を待つことができます。

use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..5 {
            println!("子スレッド: {}", i);
        }
    });

    for i in 1..3 {
        println!("メインスレッド: {}", i);
    }

    // 子スレッドの終了を待つ
    handle.join().unwrap();
}

join を呼ばないと、メインスレッドが先に終了した時点でプログラム全体が終わってしまい、子スレッドの処理が完了しないことがあります。なお join() は Result を返し、スレッドがパニックした場合には Err になります。unwrap() はその Result を展開し、もし子スレッドがパニックしていれば、その失敗を呼び出し側のスレッドで改めて発生させる働きをしています。

Mutex<T> による排他制御

複数のスレッドから同じデータを書き換えたい場合には Mutex<T> (mutual exclusion、相互排他)を使います。lock() を呼ぶとロックを取得でき、戻り値のガードを通じて中のデータにアクセスできます。ガードがスコープを抜けると自動的にロックが解放されます。

use std::sync::Mutex;

fn main() {
    let counter = Mutex::new(0);

    {
        let mut num = counter.lock().unwrap();
        *num += 1;
    }

    println!("カウンタ: {}", *counter.lock().unwrap());
}

Mutex を使う際には、デッドロックに注意が必要です。たとえば同じスレッドの中で lock() をすでに保持したまま、解放する前に再度同じ Mutex を lock() しようとすると、そのスレッドは永遠に待ち続けてしまいます。同様に、複数の Mutex を異なる順序でロックするコードが複数のスレッドに存在すると、互いに相手のロック解放を待ち合ってしまい、デッドロックに陥ることがあります。なお、単純なカウンタのように扱うデータが単一の整数程度であれば、std::sync::atomic モジュールの AtomicUsize などを使うことで、Mutex よりも軽量に排他制御を行える場合もあります。

Arc<T> によるスレッド間共有

前章で紹介した Rc<T> はスレッドセーフではないため、複数のスレッドで共有することはできません。スレッドをまたいでデータを共有したい場合は、その代わりに Arc<T> (atomically reference counted)を使います。Arc<T> は Rc<T> と同じ参照カウント方式ですが、カウントの増減をアトミック(不可分)な操作で行うため、複数スレッドから安全に clone できます。

なお、次のコード例では thread::spawn に渡すクロージャの先頭に move というキーワードが付いています。thread::spawn に渡すクロージャは 'static ライフタイムを持つ必要があるため、外部の変数を借用するのではなく、所有権ごとクロージャの中に取り込まなければなりません。move はそのためのキーワードで、「クロージャの外にある変数の所有権を、クロージャの内側に移動させる」という意味を持ちます。

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..5 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("結果: {}", *counter.lock().unwrap());
}

このように Arc<Mutex<T>> は、「複数のスレッドで共有し、かつ排他的に書き換える」というパターンでよく使われる組み合わせです。

この安全性の背後には、Send と Sync という2つのマーカートレイトがあります。Send は「その型の値の所有権をスレッドをまたいで移動しても安全である」こと、Sync は「その型への参照を複数のスレッドから共有しても安全である」ことを表し、コンパイラはこれらのトレイトが実装されている型だけをスレッド間でやり取りできるようにチェックしています。Rc<T> がスレッド間で使えないのは、この Send/Sync が実装されていないためです。普段はこれらのトレイトを意識する必要はほとんどありませんが、スレッドをまたいだ安全性が型システムによって裏付けられている、という点は覚えておくとよいでしょう。

チャネルによるスレッド間通信

共有メモリを直接ロックする代わりに、メッセージを送り合うことでスレッド間のやり取りを行う方法もあります。標準ライブラリの std::sync::mpsc (multi-producer, single-consumer)モジュールがチャネルを提供します。

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let message = String::from("こんにちは、スレッドから");
        tx.send(message).unwrap();
    });

    let received = rx.recv().unwrap();
    println!("受信: {}", received);
}

tx (送信側)で send したデータの所有権は、そのままチャネルを通じて rx (受信側)へ移動します。そのため、送信後に送信側でそのデータを使おうとすると、所有権のルールによってコンパイルエラーになります。この仕組みにより、複数スレッドが同じデータを同時に書き換えるような事態を、言語レベルで防ぐことができます。

「multi-producer」の名前が示すとおり、mpsc は複数の送信側を持つこともできます。tx.clone() で送信側を複製すれば、複数のスレッドから同じ受信側 rx に向けてメッセージを送ることができます。

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    for i in 0..3 {
        let tx = tx.clone();
        thread::spawn(move || {
            tx.send(format!("スレッド {} から", i)).unwrap();
        });
    }
    drop(tx); // 元の送信側も忘れずに drop する

    for received in rx {
        println!("受信: {}", received);
    }
}

元の tx を含め、すべての送信側が drop されるまで rx は受信待ちを続けます。そのため、複製した tx だけでなく元の tx も使い終わったら手放す必要があり、ここでは明示的に drop(tx) しています。

Python 経験者向けメモ

Python(正確には CPython という標準実装)には GIL(グローバルインタプリタロック)があり、複数のスレッドを立ち上げても、CPU バウンドな処理は同時には実行されません(そのため Python では multiprocessing を使うことも多いです)。一方 Rust には GIL のような仕組みは存在せず、スレッドは実際に並列実行されます。それでいて安全性が損なわれないのは、所有権システムのおかげでコンパイル時にデータ競合が起こらないことを保証できるからです。たとえば Mutex を経由せずに複数スレッドから同じデータを書き換えようとするコードは、そもそもコンパイルが通りません。

なお、本章で扱ったのは std::thread による OS スレッドを使った並行処理です。Rust にはこれとは別に async/await という非同期処理の仕組みもありますが、これはスレッドとは異なる考え方に基づく別の機能であり、非同期プログラミングについては次のステップとして学ぶとよいテーマです。

まとめ

  • std::thread::spawn で新しいスレッドを生成し、join で終了を待ちます。

  • Mutex<T> は lock() によって排他制御を行い、複数スレッドからの安全な書き換えを可能にします。

  • Arc<T> はスレッドセーフな参照カウント型で、Arc<Mutex<T>> の形で複数スレッド間のデータ共有によく使われます。

  • std::sync::mpsc のチャネルを使うと、値の所有権を移動させながらスレッド間でメッセージをやり取りできます。

  • Rust には GIL が無く、所有権システムによってデータ競合をコンパイル時に防ぎながら真の並列実行を実現できます。

  • 本章の内容は OS スレッドによる並行処理であり、async/await による非同期処理は別の仕組みです。
