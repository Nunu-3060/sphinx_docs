第 10 章 Python による計算と描画

本書の図と計算結果は、すべて Python のサンプルで作成している。この章では、サンプルの共通モジュール hg.py の設計を説明し、双曲平面を数値計算するときの注意点を述べる。自分で双曲幾何学の計算や作図を行うときの出発点として使ってほしい。

点の表し方

hg.py では、上半平面モデル、円板モデル、クラインモデルの点を Python の複素数（complex）で表す。複素数で表すと、メビウス変換などの式を、数式とほぼ同じ形でコードに書ける。たとえば円板モデルの距離の公式 \(d = 2 \artanh |(z - w) / (1 - \bar{w} z)|\) は、次のようになる。

リスト 17 hg.py の disk_distance()
44def disk_distance(z: complex, w: complex) -> float:
45    """ポアンカレ円板モデルの距離. d = 2 artanh |(z - w) / (1 - conj(w) z)|."""
46    return 2.0 * math.atanh(abs((z - w) / (1.0 - w.conjugate() * z)))

双曲面モデルの点は、成分 \((x_0, x_1, x_2)\) を持つ NumPy の配列で表す。距離はミンコフスキーの双線形形式 \(B\) から求める。

リスト 18 hg.py の hyperboloid_distance()
60def hyperboloid_distance(x: Point3, y: Point3) -> float:
61    """双曲面モデルの距離. cosh d = B(x, y)."""
62    return math.acosh(max(minkowski(x, y), 1.0))  # 丸め誤差で 1 をわずかに下回る場合に備える

\(B(x, y)\) は理論上 1 以上だが、丸め誤差でわずかに 1 を下回ると \(\arcosh\) が計算できない（ValueError になる）。そのため、max() で 1 以上に切り上げている。数値計算では、このような小さな防御が欠かせない。

中心に移して考える

円板モデルでは、任意の点を中心に移す等長変換がある（第 5 章）。hg.py の作図の関数は、すべて「中心に移して簡単な計算をし、元に戻す」という同じ考え方で書かれている。中心 \(0\) を点 \(a\) に移す変換 \(z \mapsto (z + a) / (1 + \bar{a} z)\) を disk_translate() とし、\(a\) を中心に移すときは disk_translate(-a, z) を使う。

リスト 19 hg.py の disk_translate()
107def disk_translate(a: complex, z: complex) -> complex:
108    """原点を点 a に移す円板の等長変換 z -> (z + a) / (1 + conj(a) z)."""
109    return (z + a) / (1.0 + a.conjugate() * z)

2 点 \(a\)、\(b\) を結ぶ測地線分を描くには、\(a\) を中心に移す。すると測地線分は中心から出る線分になり、その上に点を並べるのは簡単である。最後に、並べた点を元の位置に戻す。

リスト 20 hg.py の disk_geodesic()
112def disk_geodesic(a: complex, b: complex, n: int = 64) -> NDArray[np.complex128]:
113    """円板モデルで点 a と点 b を結ぶ測地線分の上に、双曲的な長さで等間隔に並ぶ n 個の点を返す.
114
115    a を原点に移すと、測地線分は原点からの線分になる。その線分の上に点を取り、
116    a を原点に移した変換の逆変換で元に戻す。
117    """
118    w = disk_translate(-a, b)  # a を原点に移したときの b の位置
119    length = disk_distance(0j, w)
120    direction = w / abs(w) if abs(w) > 0.0 else 1.0 + 0j
121    points = np.tanh(np.linspace(0.0, length, n) / 2.0) * direction
122    return (points + a) / (1.0 + a.conjugate() * points)

中心から距離 \(t\) の点は、ユークリッドの半径 \(\tanh(t/2)\) の位置にある（第 4 章）。np.linspace(0.0, length, n) で双曲的な長さを等分してから \(\tanh(t/2)\) に変換しているので、点は双曲的に等間隔に並ぶ。境界に近い部分でも点が粗くならず、きれいな曲線が描ける。

測地線に関する鏡映（第 8 章のタイリングで使う）と、2 本の測地線のなす角（第 6 章の検証で使う）も同じ考え方で計算できる。測地線が直径になれば鏡映は直線に関する折り返しであり、交点が中心にあれば角度は 2 本の直線の角度である。

リスト 21 hg.py の disk_reflect()
133def disk_reflect(z: complex, p: complex, q: complex) -> complex:
134    """円板モデルで、点 p と点 q を通る測地線に関する点 z の鏡映（対称な点）."""
135    w = disk_translate(-p, q)  # p を原点に移すと、測地線は原点を通る直線になる
136    u = w / abs(w)
137    moved = disk_translate(-p, z)
138    reflected = u * u * moved.conjugate()  # 原点を通る直線に関する鏡映
139    return disk_translate(p, reflected)
リスト 22 hg.py の disk_angle()
142def disk_angle(vertex: complex, p: complex, q: complex) -> float:
143    """円板モデルで、vertex から p へ向かう測地線と vertex から q へ向かう測地線のなす角（0 から pi）.
144
145    円板モデルは角度を正しく表すので、vertex を原点に移してから直線どうしの角度を測ればよい。
146    """
147    u = disk_translate(-vertex, p)
148    v = disk_translate(-vertex, q)
149    return abs(cmath.phase(v / u))

この方法の利点は、測地線の円弧の中心や半径を求める必要がないことである。円弧の中心と半径を直接求める方法では、測地線が直径に近いとき（円弧の半径が非常に大きいとき）に、直径との場合分けや桁落ちの処理が必要になる。中心に移す方法では、そのような場合分けがいらない。

数値計算の注意点

双曲平面の数値計算では、浮動小数点数の丸め誤差に特有の問題がある。次の 2 つの例で確かめる。

リスト 23 ch10_precision.py の実行結果
1. 原点から距離 d の点を円板モデルで表し、距離を計算し直す
     d      |z| = tanh(d / 2)       計算し直した距離
    5.0   0.98661429815143031   5.000000
   10.0   0.99990920426259511   10.000000
   20.0   0.99999999587769273   20.000000
   30.0   0.99999999999981282   29.999834
   36.0   0.99999999999999956   36.043653
   38.0   0.99999999999999989   37.429948
   40.0   1.00000000000000000   計算できない（|z| = 1 になった）
2. 円板の原点と、そこから距離 h の点の距離を 2 通りの公式で計算する
     h         arcosh の公式         artanh の公式
  1e-03   9.999999999255622e-04   1.000000000000000e-03
  1e-06   1.000044449303258e-06   1.000000000000000e-06
  1e-08   0.000000000000000e+00   9.999999999999999e-09
  1e-10   0.000000000000000e+00   1.000000000000000e-10

サンプルの全体：ch10_precision.py

1 つ目は、円板モデルで原点から遠い点を表す例である。原点から距離 \(d\) の点は \(|z| = \tanh(d/2)\) の位置にあり、\(1 - |z| \approx 2 e^{-d}\) である。倍精度の浮動小数点数（有効数字およそ 16 桁）では、\(1 - |z|\) が \(10^{-16}\) 程度より小さくなると表せない。そのため \(d = 30\) あたりから距離の精度が落ち始め、\(d \approx 37\) を超えると \(|z| = 1\) に丸められて、境界上の点（無限遠点）になってしまう。

2 つ目は、近い 2 点の距離を \(\arcosh\) の公式で計算する例である。距離 \(h\) が小さいとき \(\cosh h \approx 1 + h^2 / 2\) なので、\(h = 10^{-8}\) では \(h^2/2 = 5 \times 10^{-17}\) が 1 に埋もれ、\(\cosh h\) が 1 に丸められて距離が 0 になる。同じ距離を \(\artanh\) の公式で計算すると、\(h = 10^{-10}\) でも正確に求まる。

これらを踏まえた指針を挙げる。

  • 近い点どうしの距離には、\(\arcosh(1 + \cdots)\) の形を避け、\(\artanh\) の公式（または \(\arsinh\) の公式）を使う。hg.py の disk_distance() は \(\artanh\) の公式を使っている。

  • 原点から遠い点（距離が 30 程度以上）を扱う場合は、円板モデルを避け、双曲面モデルや、原点からの距離と偏角による極座標（第 9 章のランダムグラフで使った表現）で表す。

  • 双曲面モデルでは、座標が \(e^d\) 程度まで大きくなり、計算を繰り返すと \(B(x, x) = 1\) の条件が丸め誤差で崩れていく。ときどき \(x_0 = \sqrt{1 + x_1^2 + x_2^2}\) で計算し直して、双曲面の上に戻すとよい。

  • 機械学習の双曲埋め込みで、円板（球体）モデルの点を境界のすぐ内側に戻す射影（第 9 章）を行うのも、同じ理由による。

コードの品質の検査

サンプルは PEP 8 に従って書き、すべての関数に型ヒントを付けている。examples フォルダーの setup.cfg に flake8（コーディング規約の検査、行長は 120 文字まで）と mypy（型ヒントの検査、strict モード）の設定があり、次のコマンドで違反がないことを確認できる。

1$ cd examples
2$ python -m flake8 .
3$ python -m mypy .

この章のまとめ

  • 2 次元のモデルの点は複素数で表すと、数式をそのままコードに書ける。

  • 円板モデルでは、点を中心に移してから計算し、元に戻すと、作図と角度の計算が簡単になる。

  • 円板モデルは原点から遠い点（距離が 30 程度以上）を正確に表せない。近い点の距離は \(\arcosh\) の公式で桁落ちする。用途に応じて、モデルと公式を選ぶ。
