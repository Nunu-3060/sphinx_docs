3. 暗号技術の基礎

暗号技術は、通信の保護、パスワードの保存、ソフトウェアの改ざん検知など、多くのセキュリティ対策の土台になっています。この章では、暗号技術の種類と用途、正しい使い方を説明します。

最初に強調しておきたいのは、暗号アルゴリズムや暗号プロトコルを自作してはいけないということです。暗号は、専門家が長年にわたって攻撃を試みても破られなかったことで信頼されています。自作の暗号は、見た目では安全に見えても、専門家にはすぐに破られることがほとんどです。実務では、広く使われている実績のあるライブラリを、推奨された方法で使います。

3.1. エンコード・暗号化・ハッシュの違い

最初に、混同されやすい 3 つの処理の違いを整理します。

エンコード・暗号化・ハッシュの違い

処理

目的

元に戻せるか

例

エンコード

データを別の形式で表現します（例: バイナリーを文字列で表す）。

誰でも戻せます（鍵は不要です）。

「Base64 でエンコードしたので安全」という誤解はよく見られますが、エンコードには機密性を守る効果がまったくありません。次のサンプルで確認します。

13import base64
14import hashlib
15
16
17def encode(text: str) -> str:

21

23    """Base64 の文字列を元に戻す（鍵は不要）."""
24    return base64.b64decode(encoded).decode("utf-8")

3.2. 共通鍵暗号

共通鍵暗号は、暗号化と復号に同じ鍵を使う方式です。処理が高速なため、データ本体の暗号化に使われます。現在の標準は AES（Advanced Encryption Standard）で、鍵の長さは 128 ビット、192 ビット、256 ビットから選べます。

AES は 16 バイト（128 ビット）単位のブロックを暗号化する方式です。それより長いデータを暗号化するときの、ブロックのつなぎ方を暗号利用モードと呼びます。利用モードの選択を誤ると、AES 自体が安全でも暗号文から情報が漏れます。

3.2.1. ECB モードの問題

最も単純な ECB モードは、各ブロックを独立に暗号化します。そのため、同じ内容の平文ブロックは、常に同じ暗号文ブロックになります。次のサンプルで、同じブロックを 3 回繰り返した平文を暗号化すると、ECB モードでは暗号文にも同じパターンが現れることを確認します。

ecb_pattern.py
 1"""ECB モードの問題点を確認するサンプル.
 2
 3ECB モードでは同じ平文ブロックが同じ暗号文ブロックになるため、
 4暗号文から平文の繰り返しパターンが分かってしまいます。
 5
 6実行方法:
 7    python ecb_pattern.py
 8
 9必要なライブラリ:
10    cryptography（python -m pip install cryptography）
11"""
12
13import os
14
15from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
16
17BLOCK_SIZE = 16  # AES のブロック長（バイト）
18
19
20def encrypt_ecb(key: bytes, plaintext: bytes) -> bytes:
21    """ECB モードで暗号化する（悪い例。実際には使わないこと）."""
22    encryptor = Cipher(algorithms.AES(key), modes.ECB()).encryptor()
23    return encryptor.update(plaintext) + encryptor.finalize()
24
25
26def encrypt_ctr(key: bytes, plaintext: bytes) -> bytes:
27    """CTR モードで暗号化する（比較用）."""
28    nonce = os.urandom(BLOCK_SIZE)
29    encryptor = Cipher(algorithms.AES(key), modes.CTR(nonce)).encryptor()
30    return encryptor.update(plaintext) + encryptor.finalize()
31
32
33def show_blocks(label: str, data: bytes) -> None:
34    """データをブロックごとに 16 進数で表示する."""
35    print(label)
36    for i in range(0, len(data), BLOCK_SIZE):
37        print(f"  {data[i:i + BLOCK_SIZE].hex()}")
38
39
40def main() -> None:
41    key = os.urandom(32)
42    # 16 バイトの同じブロックを 3 回繰り返した平文
43    plaintext = b"ATTACK AT DAWN!!" * 3
44
45    show_blocks("[ECB モード] 同じブロックが並ぶ", encrypt_ecb(key, plaintext))
46    show_blocks("[CTR モード] パターンが現れない", encrypt_ctr(key, plaintext))
47
48
49if __name__ == "__main__":
50    main()

3.2.2. 認証付き暗号

CTR モードはパターンを隠せますが、暗号文の改ざんは検知できません。攻撃者が暗号文の特定のビットを反転させると、復号結果の対応するビットも反転します。そこで現在は、暗号化と同時に改ざん検知用のタグを付ける認証付き暗号を使います。代表的なものが AES-GCM と ChaCha20-Poly1305 です。

AES-GCM では、暗号化のたびにナンス（一度だけ使う値）を指定します。同じ鍵で同じナンスを 2 回使うと、暗号の安全性が大きく損なわれます。ナンスは暗号化のたびに乱数で生成するのが簡単で確実です。

次のサンプルでは、cryptography ライブラリを使って AES-GCM で暗号化と復号を行い、暗号文を 1 ビット書き換えると復号に失敗することを確認します。

aes_gcm.py
 1"""認証付き暗号 AES-GCM による暗号化と復号のサンプル.
 2
 3AES-GCM は暗号化と同時に改ざん検知用のタグを付けます。
 4暗号文が 1 ビットでも書き換えられると復号に失敗します。
 5
 6実行方法:
 7    python aes_gcm.py
 8
 9必要なライブラリ:
10    cryptography（python -m pip install cryptography）
11"""
12
13import os
14
15from cryptography.exceptions import InvalidTag
16from cryptography.hazmat.primitives.ciphers.aead import AESGCM
17
18NONCE_SIZE = 12  # GCM で推奨されるナンスの長さ（バイト）
19
20
21def encrypt(key: bytes, plaintext: bytes, associated: bytes) -> bytes:
22    """平文を暗号化し、ナンスと暗号文を連結して返す.
23
24    ナンスは同じ鍵で絶対に再利用してはいけないため、毎回生成します。
25    """
26    nonce = os.urandom(NONCE_SIZE)
27    ciphertext = AESGCM(key).encrypt(nonce, plaintext, associated)
28    return nonce + ciphertext
29
30
31def decrypt(key: bytes, data: bytes, associated: bytes) -> bytes:
32    """encrypt() の出力を復号する。改ざんされていれば InvalidTag."""
33    nonce, ciphertext = data[:NONCE_SIZE], data[NONCE_SIZE:]
34    return AESGCM(key).decrypt(nonce, ciphertext, associated)
35
36
37def main() -> None:
38    key = AESGCM.generate_key(bit_length=256)
39    # 暗号化はしないが改ざんは検知したい付随データ（例: レコードの ID）
40    associated = b"user_id=42"
41
42    data = encrypt(key, "口座番号: 1234-5678".encode("utf-8"), associated)
43    print(f"暗号文（16 進数）: {data.hex()}")
44    print(f"復号結果: {decrypt(key, data, associated).decode('utf-8')}")
45
46    # 暗号文の最後の 1 バイトを書き換える
47    tampered = data[:-1] + bytes([data[-1] ^ 0x01])
48    try:
49        decrypt(key, tampered, associated)
50    except InvalidTag:
51        print("改ざんを検知したため、復号に失敗しました。")
52
53
54if __name__ == "__main__":
55    main()

3.3. 公開鍵暗号

共通鍵暗号には、通信相手と事前に安全な方法で鍵を共有しておく必要がある、という課題があります。この課題を解決するのが公開鍵暗号です。公開鍵暗号では、対になる 2 つの鍵を使います。

  • 公開鍵: 誰に公開してもよい鍵。暗号化や署名の検証に使います。

  • 秘密鍵: 持ち主だけが保管する鍵。復号や署名の作成に使います。

3.3.1. RSA の原理

代表的な公開鍵暗号である RSA の原理を、数式で簡単に示します。まず、2 つの大きな素数 \(p\) と \(q\) を選び、次の値を計算します。

\[n = pq, \qquad \varphi(n) = (p - 1)(q - 1)\]

次に、\(\varphi(n)\) と互いに素な整数 \(e\) を選び、次の式を満たす \(d\) を求めます。

\[ed \equiv 1 \pmod{\varphi(n)}\]

\((n, e)\) が公開鍵、\(d\) が秘密鍵です。平文を整数 \(m\)（ただし \(0 \le m < n\)）で表すと、暗号化と復号は次のように計算します。

\[c = m^{e} \bmod n, \qquad m = c^{d} \bmod n\]

例えば、\(p = 61\)、\(q = 53\) とすると、\(n = 3233\)、\(\varphi(n) = 3120\) です。\(e = 17\) とすると \(d = 2753\) となり、平文 \(m = 65\) は暗号文 \(c = 65^{17} \bmod 3233 = 2790\) になります。\(2790^{2753} \bmod 3233\) を計算すると、元の 65 に戻ります。

\(n\) から \(p\) と \(q\) を求める（素因数分解する）ことができれば \(d\) も計算できますが、\(n\) が十分に大きければ、現在のコンピューターでは現実的な時間で素因数分解できません。これが RSA の安全性の根拠です。実際の RSA では、2048 ビット以上の \(n\) を使い、平文をそのまま暗号化するのではなく、OAEP などのパディング方式と組み合わせます。

3.3.2. ハイブリッド暗号

公開鍵暗号は共通鍵暗号に比べて処理が遅いため、データ本体の暗号化には使いません。実際には、公開鍵暗号の仕組みを使って共通鍵を安全に共有し、データ本体はその共通鍵で暗号化します。この組み合わせをハイブリッド暗号と呼びます。ネットワークセキュリティで説明する TLS も、この方式を使っています。

3.4. ハッシュ関数

ハッシュ関数は、任意の長さのデータから、固定長の値（ハッシュ値）を計算する関数です。セキュリティの用途に使うハッシュ関数（暗号学的ハッシュ関数）には、次の性質が求められます。

暗号学的ハッシュ関数に求められる性質

性質

意味

原像計算困難性

ハッシュ値から、元のデータを求めることが困難です。

第 2 原像計算困難性

あるデータと同じハッシュ値を持つ、別のデータを見つけることが困難です。

衝突困難性

同じハッシュ値を持つ 2 つのデータの組を見つけることが困難です。

衝突困難性の強さには、出力の長さによって決まる上限があります。\(N\) 通りの値をとるハッシュ関数に、ランダムなデータを \(k\) 個入力したとき、どれか 2 つのハッシュ値が一致する確率は、近似的に次の式で表されます。

\[P(k) \approx 1 - \exp\left(-\frac{k^{2}}{2N}\right)\]

\(P(k) = 1/2\) となる \(k\) は約 \(1.18\sqrt{N}\) です。これは「23 人集まると、同じ誕生日の人がいる確率が 50 % を超える」という誕生日のパラドックスと同じ現象で、衝突を探す攻撃を誕生日攻撃と呼びます。出力が \(n\) ビットのハッシュ関数（\(N = 2^{n}\)）では、約 \(2^{n/2}\) 回の計算で衝突が見つかる計算になります。SHA-256 では \(2^{128}\) 回程度となり、現実的には不可能です。

MD5 と SHA-1 は、この理論値よりもはるかに少ない計算で衝突を見つける攻撃が発見されています。SHA-1 については 2017 年に実際に衝突する 2 つの PDF ファイルが公開されました。これらはセキュリティの用途に使ってはいけません。

注釈

ハッシュ関数をパスワードの保存にそのまま使ってはいけません。SHA-256 は非常に高速なため、総当たりで元のパスワードを短時間で見つけられてしまいます。パスワードの保存方法は認証と認可で説明します。

3.5. メッセージ認証コード

ハッシュ値は誰でも計算できるため、ハッシュ値だけでは改ざんを防げません。攻撃者はデータを書き換えたうえで、ハッシュ値も計算し直せるからです。改ざんを検知するには、共有の秘密鍵を使う MAC（メッセージ認証コード）を使います。代表的なものが、ハッシュ関数を使って MAC を構成する HMAC です。

次のサンプルで、ハッシュ値と HMAC の違いを確認します。

hash_and_hmac.py
 1"""ハッシュ関数とメッセージ認証コード（HMAC）の違いを確認するサンプル.
 2
 3ハッシュ値だけでは改ざんを検知できない場合があることと、
 4共有鍵を使う HMAC なら改ざんを検知できることを示します。
 5
 6実行方法:
 7    python hash_and_hmac.py
 8
 9必要なライブラリ:
10    なし（標準ライブラリのみ）
11"""
12
13import hashlib
14import hmac
15import secrets
16
17
18def sha256_hex(message: bytes) -> str:
19    """メッセージの SHA-256 ハッシュ値を返す."""
20    return hashlib.sha256(message).hexdigest()
21
22
23def hmac_sha256_hex(key: bytes, message: bytes) -> str:
24    """メッセージの HMAC-SHA256 を返す."""
25    return hmac.new(key, message, hashlib.sha256).hexdigest()
26
27
28def verify_hmac(key: bytes, message: bytes, tag: str) -> bool:
29    """HMAC を定数時間で比較して検証する."""
30    expected = hmac_sha256_hex(key, message)
31    return hmac.compare_digest(expected, tag)
32
33
34def main() -> None:
35    message = b"amount=1000&to=alice"
36    tampered = b"amount=9999&to=mallory"
37
38    # ハッシュ値は誰でも計算できるため、攻撃者はメッセージを
39    # 書き換えたうえでハッシュ値も計算し直せる
40    print("[ハッシュ値のみの場合]")
41    print(f"  元のメッセージ    : {sha256_hex(message)}")
42    print(f"  改ざん後に再計算  : {sha256_hex(tampered)}")
43    print("  -> 受信者には改ざんを見分ける手段がありません。")
44
45    # HMAC は鍵を知らないと正しい値を計算できない
46    key = secrets.token_bytes(32)
47    tag = hmac_sha256_hex(key, message)
48    print("[HMAC の場合]")
49    print(f"  元のメッセージの検証: {verify_hmac(key, message, tag)}")
50    print(f"  改ざん後の検証      : {verify_hmac(key, tampered, tag)}")
51
52
53if __name__ == "__main__":
54    main()

3.6. デジタル署名

MAC は送信者と受信者が同じ鍵を共有するため、受信者も正しい MAC を作れます。そのため、第三者に対して「このデータは確かに送信者が作った」と証明することはできません。

デジタル署名は、公開鍵暗号の仕組みを使い、秘密鍵で署名を作成し、公開鍵で検証します。署名を作れるのは秘密鍵の持ち主だけなので、完全性に加えて真正性と否認防止も実現できます。ソフトウェアの配布、ネットワークセキュリティで説明する証明書、認証と認可で説明するパスキーなどで使われています。

次のサンプルでは、Ed25519 という署名方式を使います。

digital_signature.py
 1"""Ed25519 によるデジタル署名と検証のサンプル.
 2
 3秘密鍵で署名し、公開鍵で検証します。公開鍵は誰に渡しても
 4問題ありませんが、署名を作れるのは秘密鍵の持ち主だけです。
 5
 6実行方法:
 7    python digital_signature.py
 8
 9必要なライブラリ:
10    cryptography（python -m pip install cryptography）
11"""
12
13from cryptography.exceptions import InvalidSignature
14from cryptography.hazmat.primitives.asymmetric.ed25519 import (
15    Ed25519PrivateKey,
16    Ed25519PublicKey,
17)
18
19
20def verify(public_key: Ed25519PublicKey, signature: bytes,
21           message: bytes) -> bool:
22    """署名を検証し、正しければ True を返す."""
23    try:
24        public_key.verify(signature, message)
25    except InvalidSignature:
26        return False
27    return True
28
29
30def main() -> None:
31    private_key = Ed25519PrivateKey.generate()
32    public_key = private_key.public_key()
33
34    message = "リリース 1.0 のファイル一式".encode("utf-8")
35    signature = private_key.sign(message)
36    print(f"署名（16 進数）: {signature.hex()}")
37
38    print(f"元のメッセージの検証: {verify(public_key, signature, message)}")
39    tampered = "リリース 1.0 のファイル一式（改変）".encode("utf-8")
40    print(f"改変後の検証        : {verify(public_key, signature, tampered)}")
41
42
43if __name__ == "__main__":
44    main()

3.7. 暗号論的擬似乱数

鍵、ナンス、セッション ID、パスワード再設定用のトークンなどは、攻撃者に予測できない乱数で作る必要があります。Python の random モジュールは、シミュレーションなどのための擬似乱数生成器で、出力をいくつか観測すると以降の出力を予測できます。セキュリティの用途には、OS が提供する暗号論的に安全な乱数を使う secrets モジュールを使います。

secure_random.py
 1"""セキュリティ用途の乱数生成を確認するサンプル.
 2
 3random モジュールは再現可能な擬似乱数であり、トークンや鍵の生成には
 4使えません。セキュリティ用途には secrets モジュールを使います。
 5
 6実行方法:
 7    python secure_random.py
 8
 9必要なライブラリ:
10    なし（標準ライブラリのみ）
11"""
12
13import random
14import secrets
15import string
16
17
18def predictable_token(seed: int, length: int = 16) -> str:
19    """random モジュールでトークンを作る（悪い例）."""
20    rng = random.Random(seed)
21    alphabet = string.ascii_letters + string.digits
22    return "".join(rng.choice(alphabet) for _ in range(length))
23
24
25def secure_password(length: int = 16) -> str:
26    """secrets モジュールでランダムなパスワードを作る."""
27    alphabet = string.ascii_letters + string.digits + string.punctuation
28    return "".join(secrets.choice(alphabet) for _ in range(length))
29
30
31def main() -> None:
32    # 同じシードからは同じ値が生成される。シードが推測されると
33    # 生成されたトークンもすべて推測されてしまう
34    print("[random モジュール（悪い例）]")
35    print(f"  1 回目: {predictable_token(seed=2026)}")
36    print(f"  2 回目: {predictable_token(seed=2026)}")
37
38    print("[secrets モジュール（良い例）]")
39    print(f"  URL に使えるトークン: {secrets.token_urlsafe(32)}")
40    print(f"  16 進数のトークン   : {secrets.token_hex(16)}")
41    print(f"  パスワード          : {secure_password()}")
42
43
44if __name__ == "__main__":
45    main()

3.8. 鍵管理

暗号の安全性は、鍵の安全性に依存します。アルゴリズムが強くても、鍵が漏えいすれば意味がありません。鍵の管理では、次の点に注意します。

  • 鍵をソースコードに書かないでください。リポジトリに登録された鍵は、履歴から削除しても複製されている可能性があります。シークレットの扱いはセキュアコーディングで説明します。

  • 専用の仕組みで保管してください。クラウドの鍵管理サービス（KMS）やシークレット管理サービス、ハードウェアセキュリティモジュール（HSM）を使うと、鍵そのものをアプリケーションに渡さずに暗号化や署名ができます。

  • 用途ごとに鍵を分けてください。暗号化用と署名用、本番環境と開発環境で、別の鍵を使います。

  • 鍵を定期的に、また漏えいの疑いがあるときはすぐに更新してください。更新できるように、暗号文や署名にどの鍵を使ったかを記録しておきます。

3.9. アルゴリズムの選び方と危殆化

計算機の性能向上や新しい攻撃手法の発見によって、かつて安全とされたアルゴリズムが安全でなくなることを危殆化と呼びます。アルゴリズムは、最新の推奨に従って選び、危殆化したものは使わないようにします。

日本では、CRYPTREC（暗号技術評価委員会）が、電子政府での利用を推奨する暗号の一覧を公開しています。米国の NIST も、アルゴリズムと鍵長の推奨を公開しています。

また、将来アルゴリズムを入れ替えられるように設計しておくことも重要です。この性質を暗号の俊敏性（クリプトアジリティ）と呼びます。例えば、保存するデータにアルゴリズムの識別子を含めておけば、新旧のアルゴリズムを併存させながら移行できます。

3.10. 耐量子計算機暗号

大規模な量子コンピューターが実用化されると、RSA や楕円曲線暗号は、Shor のアルゴリズムによって現実的な時間で破られると考えられています。共通鍵暗号やハッシュ関数への影響は比較的小さく、鍵長や出力長を十分に取れば対応できるとされています。

これに備えて、量子コンピューターでも解読が困難と考えられる耐量子計算機暗号（PQC）の標準化が進められています。NIST は 2024 年に、次の 3 つの標準を公開しました。
