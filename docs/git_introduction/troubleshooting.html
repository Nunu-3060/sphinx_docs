よくあるトラブルと対処法

Git を使い始めたころに遭遇しやすいトラブルと、その対処法をまとめます。

コミット時にユーザー情報を求められる

Author identity unknown

*** Please tell me who you are.

ユーザー名とメールアドレスが設定されていません。インストールと初期設定 の手順で user.name と user.email を設定してください。

プッシュが拒否される

! [rejected]        main -> main (fetch first)

リモートリポジトリに、ローカルリポジトリにないコミットがあります。git pull でリモートリポジトリの変更を取り込んでから、もう一度プッシュしてください。取り込み時にコンフリクトが発生した場合は、ブランチ の「コンフリクトの解消」を参照してください。

HEAD がブランチを指していない

You are in 'detached HEAD' state.

git switch --detach や git checkout <コミット ID> で特定のコミットを取り出すと、HEAD がブランチではなくコミットを直接指す状態になります。この状態を detached HEAD と呼びます。過去のコードを確認するだけなら問題ありませんが、この状態で作成したコミットはどのブランチにも属さないため、ブランチを切り替えるとたどれなくなります。

元のブランチに戻るには、git switch main のようにブランチを指定して切り替えます。detached HEAD の状態で作成したコミットを残したい場合は、ブランチを切り替える前に git switch -c <新しいブランチ名> で新しいブランチを作成してください。

日本語のファイル名が文字化けする

"\343\203\241\343\203\242.txt"

git status などで日本語のファイル名が上のように表示される場合は、次のコマンドを実行してください。

$ git config --global core.quotepath false

.gitignore に書いたファイルが除外されない

.gitignore に書いたファイルが git status に表示され続ける場合は、次の 2 つの原因が考えられます。

  • そのファイルが既にコミットされている。.gitignore は、まだ管理対象になっていないファイルにだけ効果があります。基本操作 の「管理対象から除外するファイルの指定」の手順で、git rm --cached を実行して管理対象から外してください。

  • .gitignore の文字コードが UTF-16 になっている。Windows PowerShell 5.1 で echo "*.log" > .gitignore のように作成すると、このようになります。エディターで UTF-8 として保存し直してください。詳しくは PowerShell での実行例 を参照してください。

改行コードに関する警告が表示される

warning: in the working copy of 'hello.py', LF will be replaced by CRLF the next time Git touches it

改行コードの自動変換が行われることを知らせる警告です。詳しくは インストールと初期設定 の「改行コードの設定」を参照してください。

コミットメッセージの入力画面から抜け出せない

-m を付けずに git commit を実行すると、エディターが起動します。エディターを設定していない場合は Vim が起動することがあります。Vim では、i キーを押すと入力できるようになります。メッセージを入力したら、Esc キーを押してから :wq と入力して Enter キーを押すと、保存してコミットできます。コミットを中止する場合は、Esc キーを押してから :q! と入力して Enter キーを押します。

使い慣れたエディターを使うには、インストールと初期設定 の手順で core.editor を設定してください。

誤ったブランチでコミットしてしまった

main ブランチで作業するつもりのなかった変更をコミットしてしまった場合は、そのコミットをまだプッシュしていなければ、次の手順で作業用のブランチに移せます。

$ git branch feature/new-work
$ git reset --hard HEAD~1
$ git switch feature/new-work

1 行目で現在のコミットを指す新しいブランチを作成し、2 行目で main ブランチを 1 つ前のコミットに戻します。コミットは feature/new-work ブランチに残っているため、3 行目で切り替えて作業を続けられます。git reset --hard はコミットしていない変更を破棄するため、実行する前に git status で、コミットしていない変更がないことを確認してください。
