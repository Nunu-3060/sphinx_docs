2. ネットワークの歴史

この章では、コンピューターネットワークがどのような問題を解決するために生まれ、どのように発展してきたかをたどります。パケット交換、TCP/IP、DNS、輻輳制御、Web、NAT、QUIC など、現在のネットワークを支える技術の多くは、その時代に直面した具体的な問題への答えとして生まれました。歴史を知ることで、「なぜネットワークはこう作られているのか」という問いに答えられるようになり、以降の章で扱う個々の技術の意味もつかみやすくなります。

2.2. 電信と電話の時代

電気を使った遠距離通信は、19 世紀の電信に始まります。1844 年、モールス（Samuel Morse）はワシントンとボルティモアの間に敷いた電信線で通信に成功しました。電信は、文字を短点と長点の組み合わせ（モールス符号）に置き換えて送るもので、情報を記号の列に符号化して送るという点で、デジタル通信の祖先といえます。1866 年には大西洋を横断する海底ケーブルが実用化され、大陸の間の通信にかかる時間は、船で運ぶ数週間から数分にまで縮まりました。

1876 年にはベル（Alexander Graham Bell）が電話の特許を取得しました。電話は、音声を電気信号の波形のまま送るアナログの通信です。電話が普及すると、すべての家庭の間に専用の線を引くわけにはいかないため、各家庭の線を交換局に集め、通話のたびに線と線をつなぎ替える交換の仕組みが作られました。最初は交換手が手作業でつなぎ替えていましたが、19 世紀末からは自動交換機が導入されていきます。

電話網の交換は、「ネットワークの全体像」で説明した回線交換です。通話の間は発信者から着信者までの回線を専有し、音声を遅れなく一定の速さで届けます。電話網は 20 世紀を通じて世界中に張り巡らされ、通信といえば電話網を指す時代が長く続きました。

2.2.1. コンピューターと電話回線

1950 年代から 1960 年代になると、コンピューターどうし、あるいは端末とコンピューターを結ぶ必要が生まれました。1950 年代にアメリカで作られた防空システム SAGE は、各地のレーダーの情報を電話回線でコンピューターに送るため、デジタルのデータを音声帯域の信号に変換する装置（モデム）を使いました。1960 年代にタイムシェアリングのコンピューターが登場すると、離れた場所の端末から電話回線とモデムを介してコンピューターを使う形態も広まりました。

しかし、電話網はもともと音声のために作られたものです。コンピューターの通信は、キーを打ったときだけ短いデータを送るように断続的で、回線を専有する回線交換ではほとんどの時間が無駄になります。また、回線をつなぐまでに時間がかかるため、短いデータを送るたびに接続し直すこともできません。コンピューターの通信に合った、新しい通信網の考え方が求められていました。

2.3. パケット交換の発想

パケット交換の考え方は、1960 年代前半から半ばにかけて、アメリカとイギリスで独立に生まれました。

2.3.1. バランと分散型の通信網

アメリカのランド研究所のバラン（Paul Baran）は、冷戦下で、核攻撃を受けて一部の施設が破壊されても通信を続けられる通信網を研究していました。当時の電話網は、少数の交換局に回線が集中する構造をしており、交換局が破壊されると広い範囲の通信が途絶えます。

バランは、多数のノードが網の目のように互いに接続された分散型の通信網を提案しました。メッセージは小さなブロックに分けて送り、各ノードはブロックを受け取るたびに、その時点で使える経路から次の送り先を選んで転送します。一部のノードやリンクが失われても、残った経路を通ってブロックが宛先にたどり着けます。中央の交換局に頼らず、各ノードが自律的に転送を判断するという考え方は、現在のインターネットのルーターに受け継がれています。バランは、この研究を 1964 年に一連の報告書としてまとめました。ただし、当時の通信業界には受け入れられず、バランの構想がそのまま実現することはありませんでした。

2.3.2. デービスとパケット

イギリスの国立物理学研究所（NPL）のデービス（Donald Davies）は、1965 年ごろ、バランとは独立に同様の方式を考案しました。デービスの関心は、軍事的な生存性よりも、断続的なコンピューターの通信を効率よく運ぶことにありました。データを短い固定長の単位に区切り、多数の利用者の通信を 1 本の回線に混ぜて送れば、回線を無駄なく使えます。デービスはこの単位を「パケット」と名付け、この方式をパケット交換と呼びました。今日まで使われている「パケット」という言葉は、デービスに由来します。デービスの構想に基づいて、NPL では研究所内のパケット交換網が作られました。

同じころ、アメリカでは MIT のクラインロック（Leonard Kleinrock）が、メッセージを蓄積交換で転送する通信網の性能を待ち行列の理論で分析していました。こうした理論的な研究も、パケット交換が実用になるという見通しを支えました。

2.4. ARPANET

パケット交換を大規模に実現した最初のネットワークが、アメリカ国防総省の高等研究計画局（ARPA）が資金を出した ARPANET です。

2.4.1. 資源の共有という目的

ARPA は、全米の大学や研究所のコンピューター研究を支援していました。当時のコンピューターは非常に高価で、機種ごとにソフトウェアもデータも異なっていました。研究所ごとに同じコンピューターを買いそろえるのではなく、ネットワークでつないで互いのコンピューターや資源を共有できれば、研究の効率が上がります。

ARPA の情報処理技術部を最初に率いたリックライダー（J. C. R. Licklider）は、1960 年代前半、世界中のコンピューターと利用者がつながるネットワークの構想を語っていました。この構想を具体的な計画にしたのが、1966 年に ARPA に加わったロバーツ（Lawrence Roberts）です。ロバーツは 1967 年にネットワークの計画を発表し、その過程でデービスやバランの研究を知って、パケット交換を採用しました。

2.4.2. IMP と最初の接続

ARPANET の設計では、各研究所のコンピューター（ホスト）を直接つなぐのではなく、IMP（Interface Message Processor）と呼ばれる専用の小型コンピューターを各拠点に置き、IMP どうしを専用回線で結んでパケットを転送させました。ホストは自分の拠点の IMP にデータを渡すだけで、経路の選択や転送は IMP が担います。機種の異なる多数のホストに転送の機能をそれぞれ実装する代わりに、転送を IMP に任せたこの設計は、ホストとルーターを分ける現在の構成の原型です。IMP は BBN 社が受注し、ハネウェル社の小型コンピューター DDP-516 を使って作られました。

1969 年、最初の IMP がカリフォルニア大学ロサンゼルス校（UCLA）に、続いてスタンフォード研究所（SRI）に設置されました。同年 10 月、UCLA から SRI へ最初の通信が試みられました。「LOGIN」と送ろうとしたところ、「LO」の 2 文字を送った時点でシステムが停止したという逸話が残っています。1969 年末には、カリフォルニア大学サンタバーバラ校とユタ大学を加えた 4 拠点が結ばれました。

2.4.3. RFC と NCP

ARPANET の上でホストどうしがどう通信するかは、各拠点の大学院生らによる Network Working Group で議論されました。議論の記録は、1969 年 4 月にクロッカー（Steve Crocker）が書いた RFC 1 から始まる RFC（Request for Comments）という文書の形で公開されました。「意見を求む」という控えめな名前には、決定事項を押し付けるのではなく、誰でも意見を出せる開かれた議論にしたいという意図が込められていました。RFC は現在もインターネットの標準を記す文書として使われ続けています。

ホストどうしの通信のために最初に作られたプロトコルは、NCP（Network Control Program）と呼ばれ、1970 年代初めに ARPANET の各ホストに実装されました。NCP の上には、遠隔ログインの Telnet やファイル転送の FTP といったアプリケーションのプロトコルが作られました。1971 年には、BBN 社のトムリンソン（Ray Tomlinson）が、ネットワークを越えて別のホストの利用者にメッセージを送る電子メールを実現しました。利用者名とホスト名を「@」でつなぐ表記は、このときに始まりました。電子メールは、計画した人々の予想を超えて ARPANET で最も使われるアプリケーションになりました。

1972 年、カーン（Robert Kahn）らはワシントンで開かれた国際会議 ICCC（International Conference on Computer Communication）で ARPANET の公開デモンストレーションを行い、パケット交換が実際に機能することを多くの研究者や技術者に示しました。

2.5. ネットワークの相互接続：TCP/IP の誕生

ARPANET が成功すると、パケット交換の考え方はほかのネットワークにも広がりました。ARPA 自身も、移動する車両などを無線で結ぶパケット無線網や、大西洋を越えてヨーロッパと結ぶ衛星を使ったパケット網の研究を進めていました。フランスでは、プザン（Louis Pouzin）が率いる CYCLADES という研究用のネットワークが作られていました。

2.5.1. NCP の限界

ここで新しい問題が生じました。ネットワークごとに、パケットの大きさの上限、伝送速度、誤りの起こりやすさ、アドレスの形式が異なります。ARPANET 上の NCP は、IMP の網がパケットを確実に順序どおり届けることを前提に作られており、パケットが失われやすい無線網や衛星網をまたいで使うことはできませんでした。また、NCP にはネットワークの外のホストを指定する仕組みもありませんでした。性質の異なる複数のネットワークを相互に接続し、その全体を 1 つのネットワークのように使える仕組みが必要になりました。

2.5.2. サーフとカーンの設計

この問題に取り組んだのが、カーンとスタンフォード大学のサーフ（Vinton Cerf）です。2 人は 1974 年、IEEE の論文誌に「A Protocol for Packet Network Intercommunication」という論文を発表し、ネットワークを相互接続するためのプロトコルを提案しました。これが TCP の原型です。

この設計の要点は次のとおりです。

  • 各ネットワークの内部には手を加えず、ネットワークとネットワークの境界にゲートウェイ（現在のルーター）を置いて、パケットを中継します。

  • ゲートウェイは、パケットを届けることに最善を尽くすだけで、確実に届けることは保証しません。

  • パケットの紛失、重複、順序の入れ替わりへの対処は、通信の両端のホストが行います。

  • すべてのネットワークに共通のアドレスの形式を定め、どのネットワークのホストでも同じ方法で指定できるようにします。

ネットワークにはできるだけ少ない機能だけを求め、信頼性の確保は両端のホストに任せるというこの考え方は、CYCLADES の設計の影響も受けたもので、後にエンドツーエンド原理として整理されました。どんなネットワークでも「パケットをとりあえず運べる」ことさえ満たせば相互接続に参加できるため、この設計は、その後に登場する Ethernet、無線 LAN、携帯電話網など、あらゆるネットワークを取り込むことを可能にしました。サーフとカーンは、この業績により 2004 年にチューリング賞を受賞しています。

1977 年には、ARPANET、パケット無線網、衛星網の 3 つのネットワークをまたいで TCP で通信する実験が行われ、異なるネットワークの相互接続が実際に可能であることが示されました。

2.5.3. TCP と IP の分割

当初の TCP は、パケットの中継と信頼性のある配送の両方を 1 つのプロトコルで扱っていました。しかし、音声のように、多少のパケットが失われても再送を待つより遅れずに届くことを優先したい通信には、確実な配送の仕組みはかえって邪魔になります。

そこで 1978 年ごろ、TCP は 2 つに分割されました。ネットワークをまたいでパケットを届ける部分が IP（Internet Protocol）、その上で信頼性のある配送を行う部分が TCP（Transmission Control Protocol）です。再送などを行わずに IP の機能をほぼそのままアプリケーションに提供するプロトコルとして UDP（User Datagram Protocol）も作られ、1980 年に RFC 768 として仕様が公開されました。IP と TCP の仕様は、1981 年に RFC 791 と RFC 793 として公開されています。こうして、IP の上に用途に応じたトランスポートのプロトコルを載せるという、現在まで続く TCP/IP の階層構造ができあがりました。

2.5.4. 1983 年の切り替え

ARPANET では、1983 年 1 月 1 日を期限として、すべてのホストを NCP から TCP/IP に切り替えることが決められました。この日を境に NCP は使えなくなるため、各拠点は期限までに TCP/IP を実装する必要がありました。この一斉の切り替えは「フラグデー」と呼ばれます。現在、インターネットで使われているプロトコルを一斉に切り替えることは、規模の大きさから事実上不可能です。後の IPv6 への移行が何十年もかかっていることと比べると、この時代のネットワークがまだ小さかったことが分かります。

同じ 1983 年、カリフォルニア大学バークレー校が配布した 4.2BSD には、TCP/IP の実装と、それをアプリケーションから使うためのソケット API が含まれていました。4.2BSD は多くの大学や研究所のコンピューターで使われたため、TCP/IP は ARPANET の外にも急速に広まりました。ソケット API は、現在でもネットワークプログラミングの標準的なインターフェースです（「ソケットプログラミング」で説明します）。

2.6. Ethernet と LAN

ARPANET が離れた拠点どうしを結ぶネットワークだったのに対し、同じ建物の中のコンピューターを結ぶネットワーク（LAN）も 1970 年代に生まれました。

2.6.1. ALOHAnet から Ethernet へ

1971 年、ハワイ大学のエイブラムソン（Norman Abramson）らは、島々に散らばるキャンパスを無線で結ぶ ALOHAnet を稼働させました。ALOHAnet では、各端末は 1 つの無線の周波数を共有し、送りたいときに勝手に送ります。2 つの端末が同時に送るとデータが衝突して壊れるため、応答が返ってこなければ、ランダムな時間だけ待ってから送り直します。中央で送信の順番を管理しなくても共有の媒体を使えるという、この方式の考え方が Ethernet に引き継がれました。

1973 年、ゼロックス社のパロアルト研究所（PARC）のメトカーフ（Robert Metcalfe）は、ALOHAnet の方式を改良し、研究所の多数のコンピューター Alto やレーザープリンターを 1 本の同軸ケーブルで結ぶネットワークを考案しました。これが Ethernet です。Ethernet では、送信の前にケーブルが使われていないかを確かめ（キャリア検知）、送信中に衝突を検知したら直ちに送信をやめて、ランダムな時間の後に送り直します。この方式を CSMA/CD（Carrier Sense Multiple Access with Collision Detection）と呼びます。1976 年には、メトカーフとボッグス（David Boggs）が Ethernet の論文を発表しました。

2.6.2. 標準化と発展

1980 年、DEC 社、インテル社、ゼロックス社の 3 社は、10 Mbps の Ethernet の仕様を共同で公開しました。3 社の頭文字から DIX 仕様と呼ばれます。この仕様をもとに、1983 年に IEEE 802.3 として標準化されました。メトカーフは 1979 年に 3Com 社を設立し、Ethernet の製品を広めました。

当初の Ethernet は、太い同軸ケーブルに機器をつなぐ方式で、配線の変更や障害の切り分けが大変でした。1990 年には、電話線に近いより対線（ツイストペアケーブル）とハブを使う 10BASE-T が標準化され、配線が容易になります。さらに、衝突が起きる共有の媒体の代わりに、フレームを宛先のポートにだけ転送するスイッチが普及し、衝突そのものが起こらなくなりました。速度も、1995 年の 100 Mbps（Fast Ethernet）、1998 年の 1 Gbps、2002 年の 10 Gbps と向上を続け、現在ではさらに高速な規格も使われています。Ethernet は、方式を大きく変えながらも、フレームの形式と MAC アドレスを引き継ぐことで、50 年にわたって LAN の標準であり続けています。

無線 LAN は、1997 年に IEEE 802.11 として最初の規格が定められました。1999 年に 11 Mbps の IEEE 802.11b が登場し、相互接続性を認証する Wi-Fi のブランドとともに普及しました。Ethernet と無線 LAN の仕組みは「リンク層」で説明します。

2.7. OSI と TCP/IP の標準化競争

1970 年代後半から 1980 年代にかけて、コンピューターメーカー各社は、それぞれ独自のネットワークのアーキテクチャを持っていました。IBM 社の SNA や DEC 社の DECnet がその例です。異なるメーカーのコンピューターどうしは通信できず、利用者は 1 つのメーカーに縛られていました。

また、各国の電話会社は、1976 年に CCITT（現在の ITU-T）が勧告した X.25 という規格に基づいて、公衆のパケット交換網を提供していました。X.25 は、網の内部で仮想的な回線を設定し、確実な配送を網が保証する方式で、ネットワークの内部を単純にしておく TCP/IP とは対照的な設計でした。

2.7.1. OSI の登場

メーカーに依存しない国際標準のネットワークを作るため、国際標準化機構（ISO）は 1970 年代後半に OSI（Open Systems Interconnection）の標準化を始めました。1984 年には、通信の機能を 7 つの層に分けた OSI 参照モデルが ISO 7498 として成立し、各層のプロトコルの標準化が進められました。

OSI は国際機関による正式な標準であり、多くの国の政府や大企業が支持しました。政府機関が調達するネットワーク製品に OSI への対応を求める方針を打ち出した国もあり、1980 年代には「将来のネットワークは OSI になり、TCP/IP は過渡的な研究用のプロトコルにすぎない」と考える人も少なくありませんでした。

2.7.2. TCP/IP が普及した理由

しかし、実際に普及したのは TCP/IP でした。その理由として、次のような点が挙げられます。

  • すでに動く実装がありました。4.2BSD などに無償で使える実装があり、多くのコンピューターで実際に運用されていました。

  • 仕様が誰でも無償で読めました。RFC は自由に入手できたのに対し、ISO の規格文書は有償でした。

  • 仕様が比較的単純でした。OSI は多くの関係者の要望を取り込んだ結果、選択肢の多い複雑な仕様になり、実装も相互接続も困難でした。

  • 実装と運用の経験をもとに仕様を改良する仕組みがありました。机上の議論よりも動く実装を重視する IETF の文化は、この時期に形作られました。

1986 年には、TCP/IP の標準化を担う組織として IETF（Internet Engineering Task Force）が最初の会合を開きました。1990 年代に入ってインターネットが爆発的に広がると、OSI の製品はほとんど使われないまま姿を消し、競争は TCP/IP の勝利で決着しました。ただし、「ネットワークの全体像」で説明したように、OSI 参照モデルの 7 層の区分は、通信を説明する共通の言葉として今も使われています。

2.8. 規模の拡大がもたらした問題

1980 年代半ば、TCP/IP のネットワークにつながるホストの数は急速に増え始めました。規模が大きくなると、小さなネットワークでは表に出なかった問題が次々に現れました。

2.8.1. 名前の管理：DNS

ARPANET の初期には、ホストの名前と IP アドレスの対応は、SRI の NIC（Network Information Center）が管理する HOSTS.TXT という 1 つのファイルにまとめられていました。各ホストは、このファイルを定期的にダウンロードして使います。

ホストの数が数百、数千と増えると、この方式は破綻しました。ファイルが大きくなって配布の負担が増え、変更が全体に行き渡るまでに時間がかかり、名前の重複を防ぐための登録作業も NIC に集中します。

この問題を解決するために、モカペトリス（Paul Mockapetris）は DNS（Domain Name System）を設計し、1983 年に RFC 882 と RFC 883 として公開しました。DNS は、名前を「www.example.com」のように階層に分け、階層ごとに管理を委任することで、1 か所に集中していた管理の負担を分散させます。また、名前の情報も 1 つのファイルではなく、世界中に分散したサーバーに置かれます。DNS の仕様は 1987 年に RFC 1034 と RFC 1035 として改訂され、現在の DNS の基礎となっています。DNS の仕組みは「名前解決と DNS」で説明します。

2.8.2. 輻輳崩壊と輻輳制御

1986 年 10 月、インターネットで輻輳崩壊と呼ばれる現象が観測されました。ローレンス・バークレー研究所とカリフォルニア大学バークレー校の間の通信のスループットが、32 kbps から 40 bps へと、およそ 1,000 分の 1 に落ち込んだのです。

原因は、当時の TCP がネットワークの混雑を考慮せずにデータを送っていたことにありました。ネットワークが混雑してパケットが捨てられると、各ホストはタイムアウトの後にそれを再送します。再送されたパケットがさらに混雑を悪化させ、捨てられるパケットが増え、それがさらに再送を呼ぶという悪循環に陥ります。回線は再送されたパケットで埋め尽くされているのに、有用なデータはほとんど届かない状態です。

ジェイコブソン（Van Jacobson）らは、この問題を分析し、1988 年に TCP の輻輳制御の仕組みを論文として発表しました。送信の速さを少しずつ上げていくスロースタートや、パケットの損失を混雑の兆候とみなして送信の速さを下げる仕組みなどです。これらは 4.3BSD の TCP に実装されて広まり、インターネットが崩壊せずに成長を続けられる土台となりました。ネットワークの内部に頼らず、両端のホストが協調して混雑を避けるこの仕組みは、エンドツーエンド原理の典型的な例です。輻輳制御は「トランスポート層」で詳しく説明します。

2.8.3. セキュリティへの意識

インターネットの初期の利用者は、互いに顔の見える研究者どうしで、プロトコルの設計でも悪意のある利用者はほとんど想定されていませんでした。1988 年 11 月に発生したモリスワームは、ソフトウェアの脆弱性を突いて自己を複製しながらインターネット上のコンピューターに広がり、多数のコンピューターを停止させました。この事件をきっかけに、セキュリティ事故に対応する組織として CERT/CC が設立されるなど、インターネットのセキュリティへの意識が高まりました。セキュリティについては「ネットワークセキュリティ」で扱います。

2.9. NSFNET と商用化

1980 年代、インターネットの利用者は軍事や一部の研究機関から、大学全体へと広がっていきました。

2.9.1. NSFNET

ARPANET に接続できたのは、ARPA の資金を受けた一部の研究機関に限られていました。より多くの大学がネットワークを使えるように、全米科学財団（NSF）は 1981 年に計算機科学の研究者向けのネットワーク CSNET を支援し、さらに 1986 年には、全米のスーパーコンピューターセンターと地域のネットワークを結ぶ NSFNET のバックボーンの運用を始めました。NSFNET は TCP/IP を採用し、当初 56 kbps だったバックボーンの回線は、利用の急増に合わせて 1.5 Mbps、45 Mbps と増速されました。

NSFNET が新しいバックボーンとなり、役目を終えた ARPANET は 1990 年に運用を終了しました。

2.9.2. 商用化

NSFNET は公的な資金で運営されていたため、利用規程によって、研究と教育に関係しない商用の通信を流すことが制限されていました。しかし、企業からもインターネットを使いたいという需要が高まり、1990 年代初めには、商用のインターネット接続事業者（ISP）が現れます。1991 年には、商用の ISP どうしが相互に接続して通信を交換するための CIX（Commercial Internet Exchange）が作られました。

こうして商用のネットワークが十分に育つと、NSFNET のバックボーンは 1995 年に運用を終了し、インターネットのバックボーンは完全に民間の ISP の手に移りました。複数の ISP が互いに接続し、IX で通信を交換し、BGP で経路を交換するという、「ネットワークの全体像」で説明した現在のインターネットの構造は、この商用化の過程で形作られました。

2.9.3. アドレスと経路表の問題：CIDR

インターネットの急成長は、IP アドレスの割り当て方にも問題を生じさせました。当初の IPv4 では、アドレスをクラス A、B、C という固定の大きさのブロックで割り当てていました。クラス C は 256 個、クラス B は 65,536 個のアドレスを含み、その中間の大きさはありません。数百台のホストを持つ組織にはクラス C では足りず、クラス B を割り当てるとアドレスの大部分が使われずに残ります。このため、クラス B のアドレスが急速に足りなくなりました。また、組織ごとに多数のクラス C を割り当てると、ルーターの経路表の項目が爆発的に増えるという問題もありました。

この 2 つの問題に対処するため、1993 年に CIDR（Classless Inter-Domain Routing）が導入されました。CIDR では、アドレスのブロックの大きさを 2 のべき乗で自由に決められ、また、連続した複数のブロックを 1 つの経路にまとめて広告（集約）できます。「192.0.2.0/24」のようにアドレスの後ろに「/」と長さを付ける表記は、CIDR に由来します。CIDR については「インターネット層」で説明します。

2.10. Web の誕生

1990 年代のインターネットの爆発的な普及を引き起こしたのが、Web（World Wide Web）です。

2.10.1. CERN での発明

1989 年、スイスの欧州原子核研究機構（CERN）にいたバーナーズ＝リー（Tim Berners-Lee）は、研究所の中に散らばる文書や情報を、ハイパーテキストで結んで共有するシステムを提案しました。CERN には世界中から研究者が集まり、使うコンピューターも文書の形式もばらばらで、情報を探すのが困難だったためです。

バーナーズ＝リーは 1990 年末までに、Web を実現する 3 つの要素を作り上げました。

  • 資源の場所を表す URL（Uniform Resource Locator）

  • 文書を記述する言語 HTML（HyperText Markup Language）

  • 文書を取得するためのプロトコル HTTP

最初の Web サーバーとブラウザー（兼エディター）は、NeXT 社のコンピューターの上で作られました。Web は 1991 年に一般に公開され、1993 年には CERN が Web の技術を誰でも無償で使えるようにすることを表明しました。Web が特定の企業の製品ではなく、誰でも自由にサーバーやブラウザーを作れる開かれた技術だったことは、その急速な普及の大きな理由です。バーナーズ＝リーは、この業績により 2016 年にチューリング賞を受賞しています。

2.10.2. ブラウザーの普及

Web を一般の人々に広めたのは、使いやすいブラウザーの登場でした。1993 年、イリノイ大学の NCSA（National Center for Supercomputing Applications）でアンドリーセン（Marc Andreessen）らが開発した Mosaic は、文章の中に画像を表示でき、Windows や Macintosh でも動いたため、爆発的に利用者を増やしました。アンドリーセンらは翌 1994 年に Netscape 社の前身となる会社を設立し、Netscape Navigator を公開しました。続いてマイクロソフト社が 1995 年に Internet Explorer を出し、両社がブラウザーの機能を競い合う「ブラウザー戦争」が起こります。

各社が独自の拡張を競った結果、ブラウザーによって Web ページの表示が異なるという問題も生じました。1994 年には、Web の技術を標準化する組織として W3C（World Wide Web Consortium）が設立され、HTML などの標準化が進められました。

2.10.3. HTTP と暗号化

Web の普及とともに、HTTP の仕様も整えられました。1996 年には当時使われていた HTTP/1.0 が RFC 1945 として文書化され、1997 年には、1 つの TCP のコネクションで複数のリクエストを送れるようにするなどの改良を加えた HTTP/1.1 が RFC 2068 として公開されました（その後 1999 年に RFC 2616 として改訂されました）。

Web で買い物をするようになると、クレジットカードの番号などを盗聴や改ざんから守る必要が生まれます。Netscape 社は、TCP の上で通信を暗号化する SSL（Secure Sockets Layer）を開発しました。SSL は IETF に引き継がれ、1999 年に TLS（Transport Layer Security）1.0 として RFC 2246 で標準化されました。HTTP を TLS で保護したものが HTTPS です。

Web の利用者が世界中に広がると、遠くのサーバーからデータを取り寄せる遅延が問題になりました。この問題に対処するため、世界各地にキャッシュサーバーを置き、利用者の近くからコンテンツを配信する CDN（Content Delivery Network）が登場しました。代表的な CDN 事業者の Akamai 社は 1998 年に設立されています。HTTP と CDN は「HTTP と Web」で説明します。

2.11. 日本のインターネット

日本でも、1980 年代から大学の研究者を中心にネットワークの構築が始まりました。

2.11.1. JUNET

1984 年、東京大学、東京工業大学、慶應義塾大学の 3 つの大学を結ぶネットワーク JUNET（Japan University NETwork）が始まりました。中心となったのは村井純です。JUNET は専用回線ではなく、電話回線とモデムを使い、UUCP という方式でコンピューターどうしが定期的に電話をかけ合って電子メールやネットニュースを中継するものでした。JUNET はその後、全国の多くの大学や企業の研究所に広がりました。

JUNET では、電子メールで日本語を扱うための方式が工夫されました。ここで使われた文字コードの方式は、後に ISO-2022-JP として 1993 年に RFC 1468 で文書化され、長く日本語の電子メールの標準として使われました。

2.11.2. WIDE プロジェクト

1988 年には、村井らを中心に WIDE プロジェクト（Widely Integrated Distributed Environment）が始まりました。WIDE プロジェクトは、大学と企業が参加する研究プロジェクトとして、専用回線による TCP/IP のネットワークを国内に構築し、海外のインターネットとの接続も実現しました。WIDE プロジェクトは、日本のインターネットの研究と運用の中心となり、DNS のルートサーバーの 1 つ（M ルートサーバー）の運用や IPv6 の研究開発など、国際的にも重要な役割を果たしています。

2.11.3. 商用化と普及

日本でも 1990 年代初めに商用化が始まりました。1992 年には日本で最初の商用インターネット接続事業者として IIJ（インターネットイニシアティブ）が設立され、1993 年から接続サービスを始めました。その後、多くの ISP が生まれ、1995 年の Windows 95 の発売をきっかけに、家庭でもインターネットが使われ始めます。当時の家庭からの接続は、電話回線とモデムを使ったダイヤルアップ接続が中心で、通信時間に応じて電話料金がかかりました。このため、深夜から早朝にかけての特定の番号への通話が定額になる NTT のサービス「テレホーダイ」（1995 年開始）が広く使われ、深夜にアクセスが集中するという日本独特の現象も生まれました。

2.12. ブロードバンドとモバイル

1990 年代後半から 2000 年代にかけて、Web ページは画像や音声、動画を含むようになり、ダイヤルアップ接続の数十 kbps の速度では足りなくなりました。また、使った時間だけ料金がかかる接続では、常時接続を前提とした使い方ができません。高速で定額の常時接続、すなわちブロードバンドが求められるようになりました。

2.12.1. ブロードバンドの普及

ブロードバンドの技術として最初に広く普及したのは、既存の電話線で高速なデータ通信を行う ADSL（Asymmetric Digital Subscriber Line）と、ケーブルテレビの回線を使う方式でした。日本では 2001 年ごろから、安価な定額料金の ADSL のサービスが相次いで始まり、ブロードバンドが急速に普及しました。その後、光ファイバーを家庭まで引き込む FTTH（Fiber To The Home）が広がり、現在では 1 Gbps 以上の家庭向けの回線も一般的になっています。

常時接続が当たり前になると、家庭でも複数の機器をインターネットにつなぐようになり、家庭用のルーターと無線 LAN が普及しました。また、常に接続されている家庭の機器は、外部からの攻撃にさらされる機会も増えました。

2.12.2. モバイルインターネット

1999 年、NTT ドコモは携帯電話からインターネットのサービスを利用できる i モードを始めました。i モードは、携帯電話で電子メールや Web に似た情報サービスを使えるようにしたもので、日本で多くの利用者を獲得しました。2001 年には、同社が W-CDMA 方式の第 3 世代携帯電話（3G）の商用サービスを始め、携帯電話でのデータ通信が高速になりました。

2007 年に発売された iPhone は、パソコンと同じような Web ブラウザーを持ち、スマートフォンの普及のきっかけとなりました。スマートフォンが普及すると、モバイル回線を流れるデータの量は急増し、通信方式も 2010 年に日本で商用サービスが始まった LTE、2020 年に始まった 5G と高速化が続いています。

モバイル回線は、有線の回線に比べて遅延が大きく、移動に伴って電波の状態や接続先の基地局、さらには IP アドレスが変わることがあります。こうした性質は、後に述べる QUIC の設計にも影響を与えました。

2.13. IPv4 アドレスの枯渇と IPv6

IPv4 のアドレスは 32 ビットで、約 43 億個しかありません。インターネットの設計当初には十分な数と考えられていましたが、1990 年代初めには、このままでは遠からず枯渇するという見通しが明らかになっていました。

2.13.1. 延命策：NAT とプライベートアドレス

アドレスの消費を抑えるため、いくつかの延命策がとられました。先に述べた CIDR もその 1 つです。さらに、1994 年には NAT（Network Address Translation）の仕様が RFC 1631 として公開され、1996 年には組織の内部で自由に使えるプライベートアドレスが RFC 1918 で定められました。NAT は、組織や家庭の内部ではプライベートアドレスを使い、インターネットとの境界で少数のグローバルなアドレスに変換する仕組みです。家庭用のルーターの普及とともに NAT は広く使われ、アドレスの消費を大きく抑えました。

一方で、NAT はインターネットの外から内部の機器に直接接続することを難しくし、すべてのホストが対等に通信できるという、もともとのインターネットの性質を損なう面もありました。NAT については「インターネット層」で説明します。

2.13.2. IPv6

根本的な解決策として、アドレスを 128 ビットに拡張した新しいバージョンの IP である IPv6 が設計されました。IPv6 の最初の仕様は 1995 年に RFC 1883 として公開され、1998 年の RFC 2460 を経て、2017 年に RFC 8200 としてインターネット標準になりました。

しかし、IPv6 は IPv4 と互換性がなく、IPv4 しか使えない機器とは直接通信できません。利用者が少ないうちは IPv6 に対応する利点が小さく、NAT による延命もあって、移行はなかなか進みませんでした。

2011 年 2 月、IANA が地域のレジストリに割り当てる IPv4 アドレスの在庫が枯渇しました。同年 4 月には、日本を含むアジア太平洋地域を担当する APNIC でも、通常の割り当てができなくなりました。2012 年 6 月には、大手の Web サービスや ISP が IPv6 を恒久的に有効にする World IPv6 Launch が行われ、IPv6 の利用はその後少しずつ増えています。1983 年の NCP から TCP/IP への切り替えとは対照的に、IPv6 への移行は、IPv4 と IPv6 を長期間併用しながら進められています。

2.14. Web の高速化と暗号化

2000 年代後半になると、1 つの Web ページが数十から数百ものファイル（HTML、スタイルシート、スクリプト、画像など）で構成されるのが普通になりました。「ネットワークの全体像」で見たように、小さなデータのやり取りでは、転送時間は帯域幅よりも遅延で決まります。回線が高速になっても、ページの表示はそれほど速くならないという問題が目立つようになりました。

2.14.1. HTTP/2

HTTP/1.1 では、1 つの TCP のコネクションで同時に処理できるリクエストは実質的に 1 つで、前のレスポンスが終わるまで次のレスポンスを受け取れません。ブラウザーはこれを補うために、1 つのサーバーに対して複数のコネクションを並行して張っていましたが、コネクションごとに確立のための往復の時間がかかり、ネットワークの資源も多く消費します。

2009 年、Google 社は、1 つのコネクションの上で複数のリクエストとレスポンスを並行してやり取り（多重化）する実験的なプロトコル SPDY を発表しました。SPDY の成果をもとに IETF で標準化が進められ、2015 年に HTTP/2 が RFC 7540 として公開されました。

2.14.2. QUIC と HTTP/3

HTTP/2 にも残された問題がありました。HTTP/2 は 1 つの TCP のコネクションで多重化を行うため、TCP のレベルで 1 つのパケットが失われると、その再送を待つ間、他のすべてのリクエストのデータも止まってしまいます（ヘッドオブラインブロッキング）。また、TCP のハンドシェイクと TLS のハンドシェイクを順に行うため、通信を始めるまでに何往復もの時間がかかります。

TCP の仕組みを変えれば解決できますが、TCP は OS のカーネルに実装されており、さらに経路上のファイアウォールや NAT などの機器も TCP の振る舞いを前提にしているため、新しい機能を広く使えるようにするには長い年月がかかります。

そこで Google 社は、UDP の上に、多重化、再送、輻輳制御、暗号化をまとめて実装する新しいトランスポートのプロトコル QUIC を開発し、2013 年に公表しました。QUIC はアプリケーションと同じユーザー空間で実装できるため、改良を素早く展開できます。また、TCP の上で TLS を使う場合よりも少ない往復で通信を始められ、IP アドレスが変わってもコネクションを維持できます。QUIC は IETF で標準化され、2021 年に RFC 9000 として公開されました。2022 年には、QUIC の上で動く HTTP/3 が RFC 9114 として公開されています。QUIC の仕組みは「トランスポート層」で、HTTP/3 は「HTTP と Web」で説明します。

2.14.3. すべての通信の暗号化

2010 年代には、通信の暗号化も大きく進みました。2013 年に大規模な通信の監視が報道されたことをきっかけに、IETF は 2014 年に、広範な監視は攻撃であるとする RFC 7258 を公開し、プロトコルの設計では監視への対策を考慮する方針を示しました。証明書を無償で自動的に発行する Let's Encrypt などの取り組みもあって、現在では Web の通信の大部分が HTTPS で暗号化されています。2018 年には、ハンドシェイクを高速化し、古く安全でない暗号方式を取り除いた TLS 1.3 が RFC 8446 として公開されました。QUIC も、暗号化を省略できない設計になっています。TLS については「ネットワークセキュリティ」で説明します。

2.16. まとめ

  • 電話網の回線交換は断続的なコンピューターの通信には効率が悪く、1960 年代にバランとデービスがそれぞれパケット交換を考案しました。

  • 1969 年に始まった ARPANET はパケット交換を大規模に実現し、RFC による開かれた議論の文化と、電子メールなどのアプリケーションを生み出しました。

  • 性質の異なるネットワークを相互接続するため、サーフとカーンが TCP/IP を設計し、ARPANET は 1983 年に TCP/IP へ一斉に移行しました。ネットワークを単純にして信頼性を両端のホストに任せる設計が、その後の発展の土台となりました。

  • 規模の拡大に伴って、DNS、輻輳制御、CIDR、NAT、IPv6 などの仕組みが、それぞれの時代の問題を解決するために導入されました。

  • 1990 年代の Web の誕生と商用化によってインターネットは社会の基盤となり、その後のブロードバンドとモバイルの普及、HTTP/2、QUIC、HTTP/3 による高速化と暗号化へと発展が続いています。
