ネットワーク・分散システム入門
  • 用語集

用語集

本書に登場する主な用語をまとめます。数字と英字で始まる用語を先に、その後に五十音順に並べています。

2 相コミット

準備（投票）と決定の 2 つのフェーズで、複数のノードにまたがるトランザクションを、全体としてコミットするか全体として取り消すかのどちらかにするプロトコルです。2PC（Two-Phase Commit）とも呼びます。

3 ウェイハンドシェイク

SYN、SYN+ACK、ACK の 3 つのセグメントをやり取りして、TCP のコネクションを確立する手順です。

5 タプル

送信元と宛先の IP アドレス、送信元と宛先のポート番号、プロトコルの 5 つの組です。コネクションを識別するのに使います。

AEAD

Authenticated Encryption with Associated Data の略で、認証付き暗号のことです。暗号化と改ざんの検出を一体にした暗号方式で、AES-GCM や ChaCha20-Poly1305 があります。

AIMD

Additive Increase Multiplicative Decrease の略です。損失がなければ送信量を線形に増やし、損失を検出したら一定の割合で減らす、輻輳制御の基本方式です。

ARP

Address Resolution Protocol の略です。IPv4 アドレスから MAC アドレスを求めるプロトコルで、ブロードキャストで問い合わせます。

AS

Autonomous System の略です。1 つの組織が一貫した方針で運用するネットワークのまとまりで、AS 番号で識別されます。AS の間では BGP で経路を交換します。

at-least-once

メッセージが少なくとも 1 回は届くことを保証する配信保証です。同じメッセージが重複して届くことがあります。

at-most-once

メッセージが多くとも 1 回しか届かないことを保証する配信保証です。メッセージが失われることがあります。

BGP

Border Gateway Protocol の略です。AS の間で経路の情報を交換する経路制御プロトコルで、インターネット全体の経路を形作っています。

C10K 問題

1 台のサーバーで 1 万のクライアントを同時に扱う難しさを指す言葉です。I/O 多重化やイベントループによる設計が広まるきっかけになりました。

CAP 定理

ネットワーク分断が起きたとき、一貫性（線形化可能性）と可用性を同時には満たせないという定理です。

CDN

Content Delivery Network の略です。世界中の拠点にキャッシュのサーバーを置き、利用者に近い拠点からコンテンツを配信する仕組みです。

CIDR

Classless Inter-Domain Routing の略です。IP アドレスのネットワーク部の長さを、192.0.2.0/24 のように任意のプレフィックス長で表す方式です。

CLOSE_WAIT

TCP のコネクションの状態の 1 つで、相手から FIN を受け取った後、自分のアプリケーションがまだソケットを閉じていない状態です。増え続ける場合は、ソケットの閉じ忘れの不具合が疑われます。

CRDT

Conflict-free Replicated Data Type の略です。複数のレプリカで並行に更新しても、すべてのレプリカが同じ状態に収束するように設計されたデータ構造です。

CSMA/CA

Carrier Sense Multiple Access with Collision Avoidance の略です。無線 LAN で使われる媒体アクセスの方式で、キャリアセンスとランダムな待ち時間で衝突を避けます。

DHCP

Dynamic Host Configuration Protocol の略です。ネットワークに接続したホストに、IP アドレスやデフォルトゲートウェイ、DNS サーバーなどの設定を自動で配布するプロトコルです。

DNS

Domain Name System の略です。ドメイン名と IP アドレスなどの対応を、木構造の名前空間と委任によって世界中で分散して管理する仕組みです。

DNSSEC

DNS の応答にデジタル署名を付け、応答が改ざんされていないことを検証できるようにする DNS の拡張です。

Ethernet

有線 LAN で最も広く使われているリンク層の規格です。IEEE 802.3 として標準化されています。

exactly-once

メッセージがちょうど 1 回処理されたのと同じ結果になることです。実際には、at-least-once のリトライと、冪等性や重複の排除を組み合わせて実現します。

FLP 不可能性

非同期のシステムモデルでは、1 台のノードがクラッシュし得るだけで、必ず停止する決定的な合意アルゴリズムは存在しないという定理です。フィッシャー、リンチ、パターソンの 3 人の頭文字から名付けられています。

FQDN

Fully Qualified Domain Name の略です。ルートを表す末尾のドットまで含めて、省略せずに書いたドメイン名です。

gRPC

Google が開発した RPC のフレームワークです。インターフェースの定義とシリアライズに Protocol Buffers を、通信に HTTP/2 を使います。

happened-before 関係

同じプロセス内の実行順序と、メッセージの送信と受信の関係から定まる、イベント間の因果的な順序の関係です。ランポートが定義しました。

HPACK

HTTP/2 のヘッダーの圧縮方式です。送ったヘッダーを両端で表として覚えておき、同じヘッダーを短い番号で送ります。

HTTP

HyperText Transfer Protocol の略です。Web で使われる、リクエストとレスポンスからなるアプリケーション層のプロトコルです。

I/O 多重化

1 つのスレッドで、多数のソケットのうち読み書きの準備ができたものを OS に問い合わせて処理する方法です。select、poll、epoll、kqueue などの仕組みがあります。

ICMP

Internet Control Message Protocol の略です。IP の配送で起きた問題の通知や、ネットワークの診断に使うプロトコルです。ping や traceroute が利用します。

IETF

Internet Engineering Task Force の略です。インターネットのプロトコルを標準化する、誰でも参加できる組織です。

IP

Internet Protocol の略です。ネットワークをまたいでパケットを宛先のホストまで届ける、インターネット層のプロトコルです。配送は保証しないベストエフォートです。

IPv6

128 ビットのアドレスを持つ IP の新しい版です。IPv4 のアドレスの不足を解消するために作られました。

ISP

Internet Service Provider の略です。利用者や組織をインターネットに接続する事業者です。

IX

Internet Exchange の略です。多数の ISP などが集まって相互に接続し、通信を交換する施設です。

LWW

Last Write Wins の略です。並行な書き込みが競合したとき、タイムスタンプの最も新しい書き込みを残し、ほかを捨てる解決方法です。

MAC アドレス

LAN の中でネットワークインターフェースを識別する 48 ビットの番号です。

MTU

Maximum Transmission Unit の略です。1 つのフレームで運べるペイロード（IP パケット）の最大の大きさで、Ethernet では 1,500 バイトです。

NAPT

Network Address Port Translation の略です。IP アドレスとポート番号を書き換えて、1 つのグローバルアドレスを多数のホストで共有させる技術です。家庭のルーターなどで NAT と呼ばれているものの多くは NAPT です。

NTP

Network Time Protocol の略です。ネットワーク越しに時計を同期させるプロトコルです。

OSI 参照モデル

ISO が定めた、通信の機能を 7 つの層に分けたモデルです。

Outbox パターン

送信するイベントを業務データと同じローカルトランザクションで表に書き込み、別のプロセスがその表から読み出して送信する方式です。データの更新とイベントの送信の食い違いを防ぎます。

PACELC

ネットワーク分断があるとき（P）は可用性（A）と一貫性（C）のどちらを選ぶか、ないとき（E）は遅延（L）と一貫性（C）のどちらを選ぶかで、分散データストアを分類する考え方です。

Path MTU Discovery

IP ヘッダーの DF フラグと ICMP のエラーを使って経路の途中の最小の MTU を調べ、断片化を避ける方法です。

Paxos

ランポートが考案した、過半数の受理に基づく合意アルゴリズムです。

pub/sub

Publish/Subscribe の略です。トピックに発行されたメッセージを、そのトピックを購読しているすべての受信側に届ける方式です。

QUIC

UDP の上に作られたトランスポートプロトコルです。TLS 1.3 による暗号化を組み込み、ストリームの多重化によって TCP のヘッドオブラインブロッキングを避けます。HTTP/3 で使われます。

Raft

理解しやすさを重視して設計された合意アルゴリズムです。リーダー選出、ログ複製、安全性の 3 つに分けて設計されています。

RFC

Request for Comments の略です。IETF などが公開する、インターネットの技術文書の通し番号付きの系列で、多くのプロトコルの仕様が RFC として公開されています。

RPC

Remote Procedure Call の略です。別のコンピューターにある手続きを、手元の関数と同じような書き方で呼び出せるようにする仕組みです。

RTT

Round Trip Time の略です。データを送ってから、その応答が戻ってくるまでの往復の時間です。

Saga

ローカルトランザクションの列と、途中で失敗したときに実行する補償トランザクションによって、複数のサービスにまたがる処理を実現する方式です。

SLI

Service Level Indicator の略です。成功したリクエストの割合や応答時間など、サービスの品質を表す測定値です。

SLO

Service Level Objective の略です。SLI について定める目標値です。

TCP

Transmission Control Protocol の略です。コネクションを確立し、再送、順序の整列、フロー制御、輻輳制御によって、信頼性のあるバイトストリームを提供するトランスポートプロトコルです。

TCP/IP モデル

インターネットのプロトコル群に合わせた、リンク層、インターネット層、トランスポート層、アプリケーション層の 4 層のモデルです。

term

Raft で時間を区切る、単調に増加する番号です。1 つの term には、リーダーは多くとも 1 台しか存在しません。

TIME_WAIT

TCP で先に切断した側が、最後の ACK を送った後、しばらくの間（2MSL）コネクションの情報を保持して待つ状態です。

TLS

Transport Layer Security の略です。通信の暗号化、改ざんの検出、相手の認証を提供するプロトコルです。HTTPS は HTTP を TLS で保護したものです。

TrueTime

Google の Spanner が使う時刻の API です。真の時刻を含む区間を返し、その誤差の分だけコミットを待つことで、実際の時間の順序を保証します。

TTL

Time To Live の略です。IP では、パケットが通過できるルーターの残りの数を表し、ルーティングのループからネットワークを守ります。DNS では、レコードをキャッシュしてよい時間（秒）を表します。

UDP

User Datagram Protocol の略です。ポート番号による宛先の区別とチェックサムだけを提供する、単純なトランスポートプロトコルです。再送や順序の保証はありません。

VLAN

Virtual LAN の略です。1 台のスイッチの中に、論理的に分かれた複数の LAN を作る技術です。IEEE 802.1Q のタグで識別します。

VPN

Virtual Private Network の略です。インターネットなどの共有のネットワークの上に、暗号化した通信路で仮想的な専用のネットワークを作る技術です。

アンチエントロピー

バックグラウンドでレプリカどうしのデータを比較し、差分を修復する仕組みです。

一貫性モデル

複数のレプリカや並行な操作があるとき、読み込みがどの値を返し得るかについての、システムとプログラムの間の約束事です。

イベントループ

asyncio などで、入出力の準備ができたタスクを順に再開させて、1 つのスレッドで多数の処理を進める仕組みです。

因果一貫性

因果関係のある操作については、すべてのノードが同じ順序で観測することを保証する一貫性モデルです。因果関係のない並行な操作の順序は問いません。

エラーバジェット

SLO の範囲内で許容される失敗の量です。使い切りそうになったら、新しい機能のリリースより信頼性の改善を優先する、といった判断に使います。

エンドツーエンド原理

ネットワークの内部は単純に保ち、信頼性などの機能は通信の両端のホストに置くという設計の考え方です。

回線交換

通信の前に経路上の回線を予約し、通信が終わるまで専有する方式です。従来の電話網で使われてきました。

カオスエンジニアリング

本番に近い環境に意図的に障害を注入し、システムが障害に耐えられるかを実験で確かめる手法です。

仮想ノード

コンシステントハッシュで、1 台の物理的なノードをリング上の複数の位置に置く手法です。負荷の偏りを小さくします。

カプセル化

送信側で、各層が上の層から受け取ったデータに自分のヘッダーなどを付けて、下の層へ渡すことです。

可用性

システムが利用可能だった時間の割合です。99.9% のように、9 の数で表すことがあります。

キープアライブ

HTTP で、1 本の TCP コネクションを使って、複数のリクエストとレスポンスを順にやり取りする方式です。持続的接続とも呼びます。

キャッシュポイズニング

偽の DNS の応答をフルリゾルバーのキャッシュに入れ、利用者を偽のサーバーに誘導する攻撃です。

クォーラム

どの 2 つを選んでも必ず重なるように選んだレプリカの集合です。リーダーレスレプリケーションでは、レプリカの数 N、書き込みの数 W、読み込みの数 R が R + W > N を満たすように選びます。

グレースフルデグラデーション

障害や過負荷のときに、一部の機能や品質を落としてでも、中心となる機能を提供し続けることです。

クロックドリフト

コンピューターの時計が進む速さのずれです。ずれが積み重なると、時計どうしの時刻がずれていきます。

結果整合性

新しい更新が止まれば、最終的にすべてのレプリカが同じ値に収束することだけを保証する一貫性モデルです。

権威サーバー

あるゾーンの情報の正本を持ち、そのゾーンの名前についての問い合わせに答える DNS サーバーです。

合意

複数のノードが、提案された値の中から 1 つを選び、全員がその値に同意する問題です。リーダー選出やレプリケーションの土台になります。

コンシステントハッシュ

ハッシュ値の空間をリング状に並べ、キーをリング上で時計回りに最初に出会うノードに割り当てる方式です。ノードの増減で移動するキーを少なくできます。

サーキットブレーカー

失敗が続く呼び出し先への呼び出しを一時的に遮断し、障害の連鎖を防ぐ仕組みです。Closed、Open、Half-Open の 3 つの状態を持ちます。

最長一致

ルーティングテーブルの経路のうち、宛先に一致し、かつプレフィックス長が最も長い経路を選ぶ規則です。

サブネットマスク

IPv4 アドレスのネットワーク部のビットを 1、ホスト部のビットを 0 にした 32 ビットの値です。

指数バックオフ

リトライのたびに、待ち時間を 2 倍、4 倍のように指数的に延ばす方法です。

ジッター

多数のクライアントのリトライの時刻がそろわないよう、待ち時間に加える乱数の揺らぎです。

障害検知器

ノードが故障したかどうかを判定する仕組みです。多くはハートビートとタイムアウトで実現されます。非同期のシステムでは、遅いだけの正常なノードを故障と誤判定する可能性を排除できません。

障害モデル

クラッシュ停止、オミッション、ビザンチン障害など、システムの設計で想定する障害の種類を定めたものです。

証明書

公開鍵とその持ち主の対応を、認証局がデジタル署名で保証したデータです。

シリアライズ

メモリ上のデータ構造を、送信や保存のできるバイト列に変換することです。逆の変換をデシリアライズと呼びます。

スイッチ

受け取ったフレームの送信元 MAC アドレスを学習し、宛先の MAC アドレスがつながっているポートにだけフレームを転送する装置です。L2 スイッチとも呼びます。

スケールアウト

同程度のコンピューターの台数を増やして、システムの処理能力を高める方法です。コンピューターを高性能なものに置き換えるスケールアップと対比されます。

スタブリゾルバー

OS に組み込まれた簡単なリゾルバーです。フルリゾルバーに問い合わせて名前解決の答えを得ます。

スプリットブレイン

複数のノードが同時に自分がリーダーだと思い込み、それぞれが書き込みを受け付けてしまう状態です。

スループット

実際に 1 秒あたりに届けられたデータの量です。

ゼロトラスト

ネットワーク上の位置によって信頼を与えず、すべてのアクセスをその都度検証するセキュリティの考え方です。

線形化可能性

データのコピーが 1 つしかないかのように振る舞い、操作の実時間の順序も守る、最も強い一貫性モデルです。

前方秘匿性

長期間使う秘密鍵が後で漏れても、過去の通信の内容を復号されない性質です。

ソケット

OS がアプリケーションに提供する、ネットワーク通信のためのインターフェースです。

阻塞

2 相コミットで、Yes と投票した参加者が、コーディネーターの故障によって最終的な決定を知ることができず、ロックを保持したまま待ち続ける状態です。

帯域幅

リンクが 1 秒あたりに送り出せるデータの量です。単位は bps です。

帯域幅遅延積

帯域幅と RTT の積です。回線を使い切るために、応答を待たずに送信中にしておく必要があるデータの量を表します。

単一障害点

そこが故障するとシステム全体が止まってしまう、冗長化されていない構成要素です。SPOF（Single Point of Failure）とも呼びます。

単調時計

決して巻き戻らない、経過時間の計測用の時計です。Python では time.monotonic() で読み取れます。

遅延

データが送信元を出てから宛先に届くまでの時間です。レイテンシとも呼びます。伝搬遅延、送信遅延、処理遅延、キューイング遅延からなります。

逐次一貫性

すべての操作が、各クライアントの実行順序を保った 1 つの順序に並べられることを保証する一貫性モデルです。実時間の順序は問いません。

デフォルトルート

ルーティングテーブルの他のどの経路にも一致しない宛先に使う経路です。IPv4 では 0.0.0.0/0 で表します。

トークンバケット

一定の速度で補充されるトークンを消費してリクエストを通す、レート制限のアルゴリズムです。

名前解決

ホスト名などの名前を、通信に使う IP アドレスに変換することです。

認証局

申請者を確認して証明書を発行する、信頼された第三者です。CA（Certificate Authority）とも呼びます。

ネットワーク分断

ネットワークの障害によって、ノードの集まりが互いに通信できない複数のグループに分かれてしまうことです。

パーティショニング

データを互いに重ならない部分（パーティション）に分け、それぞれを別々のノードに受け持たせる技術です。シャーディングとも呼びます。

ハイブリッド論理時計

物理的な時刻に近い値と論理的なカウンターを組み合わせ、因果関係を保つタイムスタンプを作る時計です。HLC（Hybrid Logical Clock）とも呼びます。

パケット

ネットワークで送るデータを一定の大きさ以下に区切り、宛先などの情報を持つヘッダーを付けたものです。

パケット交換

データをパケットに分割し、中継機器がヘッダーの宛先に基づいて転送する方式です。1 本のリンクを多数の通信で共有します。

バックプレッシャー

下流の処理が追いつかないことを上流に伝えて、データの流量を抑える仕組みです。

バルクヘッド

スレッドや接続などの資源を区画に分け、1 か所の問題が全体に広がらないようにする設計です。

ビザンチン障害

ノードが矛盾したメッセージを送るなど、任意の誤った振る舞いをする障害です。

ファイアウォール

あらかじめ定めた規則に従って、通信を許可したり遮断したりする仕組みです。

フェイルオーバー

リーダーなどの役割を持つノードが停止したとき、別のノードにその役割を引き継がせることです。

フェンシングトークン

ロックを与えるたびに増加する番号です。資源の側で、古いロックの持ち主からの書き込みを拒否するのに使います。

輻輳ウィンドウ

ネットワークの混雑の度合いに応じて送信側が調整する、確認応答を待たずに送れるデータの量の上限です。cwnd とも書きます。

輻輳制御

ネットワークの混雑を検出し、送信の速さを調整して、混雑による性能の低下を防ぐ仕組みです。

部分障害

システムの一部が故障し、残りは動き続けている状態です。分散システムでは普通に起こります。

部分同期

ほとんどの時間は通信や処理の遅延の上限が守られるものの、ときどき上限を超える期間があるという、時間についてのシステムモデルです。

フルリゾルバー

利用者に代わって、ルートサーバーから順に権威サーバーをたどって答えを探し、その結果をキャッシュする DNS サーバーです。

フレーミング

TCP のようなバイトストリームの中に、メッセージの区切りを設けるための約束です。区切り文字や長さの前置などの方法があります。

フレーム

リンク層が運ぶデータの単位です。Ethernet では、ヘッダー、ペイロード、誤り検出用の FCS からなります。

ブロードキャストドメイン

ブロードキャストのフレームが届く範囲です。ルーターや VLAN で区切られます。

フロー制御

受信側が処理しきれない量のデータを送らないよう、受信側の空き容量に合わせて送信側の送信量を抑える仕組みです。

プロトコル

通信する機器やプログラムが従う約束事です。メッセージの形式、意味、手順を定めます。

分散コンピューティングの誤謬

「ネットワークは信頼できる」「遅延はゼロである」など、分散システムの開発者が陥りがちな 8 つの誤った思い込みです。

分散システム

ネットワークでつながった複数のコンピューターが、メッセージをやり取りして協調し、利用者からは 1 つのシステムに見えるように動くものです。

冪等キー

操作ごとに一意な値をリクエストに付け、サーバーが同じキーを持つ重複したリクエストを検出できるようにするものです。

冪等性

同じ操作を何回繰り返しても、1 回行ったときと結果が同じになる性質です。

ベクトル時計

プロセスごとの要素を持つベクトルで、2 つのイベントの関係が「前」「後」「並行」のどれかを正確に判定できる論理時計です。

ヘッドオブラインブロッキング

先頭のデータが届かないために、後続のデータがすでに届いていても処理できない現象です。

ホットスポット

アクセスや負荷が極端に集中したパーティションやノードです。

メッセージキュー

送信側と受信側の間でメッセージを一時的に蓄え、両者を疎結合にする仕組みです。

読み込み修復

読み込みのときに古い値を返したレプリカを見つけ、最新の値を書き戻すことです。

ランポート時計

イベント a がイベント b より前に起きたならば、a の値が b の値より小さくなるように、各イベントに整数を割り当てる論理時計です。

リース

有効期限付きのロックです。持ち主が故障しても、期限が来れば自動的に解放されます。

リトライストーム

過負荷のサーバーに対してクライアントが一斉にリトライし、負荷がさらに高まって回復できなくなる悪循環です。

リバースプロキシ

サーバー側に置かれ、外部からのリクエストを受けて内部のサーバーに振り分ける中継サーバーです。

リバランス

データと負荷をノードの間で移し替えて、均等な状態に戻すことです。

ルーティング

パケットを宛先に届けるために、次にどの機器へ転送するかを決めることです。

レプリケーション

同じデータの複製（レプリカ）を複数のノードに置くことです。可用性の向上、読み込みの負荷分散、遅延の短縮のために使います。

レプリケーション遅延

非同期レプリケーションで、フォロワーの内容がリーダーより遅れている時間です。
