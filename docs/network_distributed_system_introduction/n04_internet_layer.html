4. インターネット層

この章では、インターネット層の中心となるプロトコルである IP（Internet Protocol）を説明します。リンク層が 1 つのリンクの中でフレームを届けるのに対し、IP は多数のネットワークをまたいで、パケットを送信元から最終的な宛先まで届けます。IPv4 アドレスとサブネット、CIDR の考え方から始めて、ルーターがパケットの転送先を決めるルーティングの仕組み、経路の情報を交換する経路制御のプロトコル、IP を補助する ICMP、パケットの断片化、NAT と DHCP を順に見ていきます。最後に、IPv4 の後継である IPv6 を取り上げます。

4.1. IP の役割

IP の役割は、ホストを IP アドレスで識別し、そのアドレスを宛先としてパケットを届けることです。送信元から宛先までの間には多数のルーターがあり、各ルーターはパケットを受け取るたびに宛先の IP アドレスを見て、次にどのルーターへ渡すかを決めます。この「次の 1 歩（ホップ）」の判断を繰り返すことで、パケットは最終的に宛先に届きます。

IP の配送は、ベストエフォート型です。IP はパケットを届けるよう努力しますが、次のことは保証しません。

  • パケットが必ず届くこと（途中のルーターのキューがあふれれば捨てられます）。

  • 送った順番どおりに届くこと（パケットごとに別の経路を通ることがあります）。

  • 1 つのパケットが 1 回だけ届くこと（まれに重複して届きます）。

また、IP はコネクションレス型で、通信を始める前に経路を予約したり、相手と打ち合わせたりしません。各パケットは独立して扱われます。信頼性が必要な場合は、上の層の TCP が再送や順序の並べ替えを行います（「トランスポート層」で説明します）。

これは「ネットワークの全体像」で説明したエンドツーエンド原理に基づく設計です。ネットワークの中の機器が単純な配送だけを行うおかげで、ルーターは高速かつ単純に作れ、新しいアプリケーションはネットワークを変えずに両端だけで実現できます。

4.2. IPv4 アドレスとサブネット

IPv4 アドレスは 32 ビットの番号で、8 ビットずつ 10 進数で表して「.」で区切った 192.168.1.10 のような形（ドット付き 10 進表記）で書きます。32 ビットなので、アドレスの総数は \(2^{32}\)、約 43 億個です。

IP アドレスは、ホストそのものではなく、ホストのネットワークインターフェースに割り当てられます。複数のインターフェースを持つルーターは、インターフェースの数だけ IP アドレスを持ちます。

4.2.1. ネットワーク部とホスト部

IP アドレスは、上位のネットワーク部と下位のホスト部に分かれます。ネットワーク部は「どのネットワーク（サブネット）か」を、ホスト部は「そのネットワークの中のどのホストか」を表します。同じネットワーク部を持つアドレスの集まりがサブネットで、通常はリンク層の 1 つのブロードキャストドメインに対応します。

ルーターは、宛先のアドレスのネットワーク部だけを見て転送先を決めます。個々のホストごとではなく、ネットワーク単位で経路を管理できるため、世界中のホストの数に比べてはるかに少ない経路の情報で済みます。電話番号の市外局番だけを見て、どの地域へつなぐかを決めるのと似た考え方です。

ネットワーク部が何ビットかを示すのが、プレフィックス長とサブネットマスクです。

  • CIDR 表記：アドレスの後に「/」とネットワーク部のビット数（プレフィックス長）を書きます。例えば 192.168.1.10/24 は、上位 24 ビットがネットワーク部であることを表します。

  • サブネットマスク：ネットワーク部のビットを 1、ホスト部のビットを 0 にした 32 ビットの値です。/24 は 255.255.255.0、/26 は 255.255.255.192 です。

アドレスとサブネットマスクのビットごとの論理積（AND）をとると、ネットワーク部だけが残ったネットワークアドレスが得られます。

サブネットの中で、ホスト部がすべて 0 のアドレスはネットワークそのものを表すネットワークアドレス、すべて 1 のアドレスはサブネットのすべてのホスト宛てのブロードキャストアドレスです。これらはホストに割り当てられないため、プレフィックス長が \(n\) のサブネットでホストに割り当てられるアドレスの数は次のとおりです。

\[\text{ホスト数} = 2^{32 - n} - 2\]

例えば /24 なら 254 個、/26 なら 62 個です。なお、ルーターどうしを 1 対 1 で結ぶリンクでは、2 つのアドレスだけを持つ /31 が使えるように定められています（RFC 3021）。また、/32 は 1 つのアドレスだけを表します。

4.2.2. CIDR

初期の IPv4 では、アドレスの先頭のビットによってネットワーク部の長さが 8 ビット（クラス A）、16 ビット（クラス B）、24 ビット（クラス C）のいずれかに決まっていました。この方式をクラスフルアドレッシングと呼びます。しかし、クラス C では 254 台しか収容できず、クラス B では約 6 万 5 千台と大きすぎるなど、組織の規模に合わせた割り当てができず、アドレスの無駄が大きくなりました。また、インターネットの成長とともに、ルーターが持つ経路の数も急増しました。

そこで 1993 年に導入されたのが CIDR（Classless Inter-Domain Routing）です。CIDR では、ネットワーク部の長さをクラスに縛られず任意のビット数にできます。例えば、500 台程度の組織には /23（ホスト数 510）を割り当てられます。また、連続する複数のネットワークを 1 つの短いプレフィックスにまとめて経路の数を減らすこともできます（経路集約）。例えば、192.168.0.0/24 から 192.168.3.0/24 までの 4 つのネットワークは、192.168.0.0/22 という 1 つの経路にまとめられます。現在の IPv4 はすべて CIDR に基づいて運用されています。

4.2.3. プライベートアドレス

IPv4 アドレスの中には、特別な用途のために予約された範囲があります。特に重要なのが、組織の中のネットワークで自由に使えるプライベートアドレス（RFC 1918）です。プライベートアドレスはインターネット上では経路が広告されず、別々の組織が同じアドレスを重複して使えます。インターネットと通信するときは、後で説明する NAT によってグローバルアドレスに変換します。

4.3. ルーティング

ホストやルーターが、受け取ったパケットを次にどこへ送るかを決めて送り出す処理を、フォワーディング（転送）と呼びます。転送先の判断には、ルーティングテーブル（経路表）を使います。ルーティングテーブルの各行は 1 つの経路で、主に次の情報を持ちます。

  • 宛先ネットワーク：経路が対象とするアドレスの範囲（プレフィックス）です。

  • ネクストホップ：次にパケットを渡すルーターの IP アドレスです。宛先が直接つながったネットワークにある場合は、ネクストホップを経由せず宛先に直接送ります。

  • インターフェース：パケットを送り出すネットワークインターフェースです。

  • メトリック：同じ宛先への経路が複数あるときに、どれを優先するかを決める値です。

ルーターだけでなく、一般のホストもルーティングテーブルを持っています。ホストのルーティングテーブルは、通常、自分のサブネットへの直結の経路と、それ以外のすべての宛先をデフォルトゲートウェイ（既定のルーター）に送るデフォルトルートからなる簡単なものです。デフォルトルートは、すべてのアドレスに一致するプレフィックス 0.0.0.0/0 として表されます。ルーティングテーブルは、次のコマンドで確かめられます（1 行目は Windows、2 行目は Linux）。

1route print
2ip route

4.3.1. 最長一致

宛先のアドレスが、ルーティングテーブルの複数の経路に一致することがあります。例えば、宛先 10.20.30.40 は 10.0.0.0/8 にも 10.20.0.0/16 にも 10.20.30.0/24 にも含まれ、デフォルトルート 0.0.0.0/0 にも一致します。このような場合、IP のルーティングでは、一致した経路のうちプレフィックス長が最も長い経路を選びます。これを最長一致（longest prefix match）と呼びます。プレフィックス長が長いほど対象の範囲が狭く、宛先について具体的な情報を持っていると考えられるためです。

最長一致のおかげで、「10.0.0.0/8 はこちら、ただしその中の 10.20.30.0/24 だけは別の経路」という例外を含む経路を、簡潔に表現できます。デフォルトルートはプレフィックス長が 0 なので、他のどの経路にも一致しなかった場合にだけ使われます。デフォルトルートもなく、どの経路にも一致しなければ、パケットは捨てられ、送信元に ICMP の到達不能メッセージが返されます。

サンプルコード routing_table.py は、ルーティングテーブルを最長一致で検索する簡単な実装です。

リスト 4.2 routing_table.py

17def pad(text: str, width: int) -> str:
18    """全角文字を幅 2 として数え、表示幅が width になるよう空白を足す。"""
19    used = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1
20               for c in text)
21    return text + " " * max(width - used, 0)

24@dataclass(frozen=True)
25class Route:
26    """ルーティングテーブルの 1 行（経路）。"""
27
28    network: ipaddress.IPv4Network  # 宛先ネットワーク
29    next_hop: str  # 次に転送するルーター（直結なら "直結"）

35    return Route(ipaddress.IPv4Network(cidr), next_hop, interface)

38class RoutingTable:
39    """経路を保持し、最長一致で検索するルーティングテーブル。"""
40
41    def __init__(self, routes: list[Route]) -> None:
42        self.routes = routes
43
44    def matches(self, dest: ipaddress.IPv4Address) -> list[Route]:
45        """宛先を含むすべての経路を返す。"""
46        return [r for r in self.routes if dest in r.network]
47
48    def lookup(self, dest: ipaddress.IPv4Address) -> Route | None:
49        """最長一致で経路を 1 つ選ぶ。一致する経路がなければ None。"""
50        candidates = self.matches(dest)
51        if not candidates:
52            return None
53        # プレフィックス長が最も長い経路を選ぶ
54        return max(candidates, key=lambda r: r.network.prefixlen)
55

59              + "インターフェース")

4.3.2. 経路の決定とパケットの転送の流れ

ホスト A（192.168.1.10）が、インターネット上のサーバーにパケットを送る場合の流れをまとめます。

  1. A は宛先の IP アドレスでルーティングテーブルを検索し、デフォルトルートに一致したので、デフォルトゲートウェイ 192.168.1.1 に送ると決めます。

  2. A は ARP で 192.168.1.1 の MAC アドレスを求め（「リンク層」を参照してください）、ルーター宛てのフレームに、宛先がサーバーのままの IP パケットを入れて送ります。

  3. ルーターはフレームから IP パケットを取り出し、TTL を 1 減らし、自分のルーティングテーブルで次のルーターを決めて、次のリンク用の新しいフレームに入れて送り出します。

  4. この手順を経路上の各ルーターが繰り返し、最後のルーターが、宛先のサーバーが直接つながったネットワークにパケットを送り出します。

4.4. 経路制御

ルーティングテーブルの経路をどのように用意するかを、経路制御（ルーティング）と呼びます。

4.4.1. 静的ルーティング

管理者が経路を手作業で設定する方法を、静的ルーティング（スタティックルーティング）と呼びます。家庭のネットワークのように経路が単純な場合や、特定の宛先だけ別の経路を使わせたい場合に使われます。設定が分かりやすい反面、ネットワークの構成が変わったり、リンクが故障したりしても経路は自動では変わりません。

4.4.2. 動的ルーティング

ルーターどうしがプロトコルで経路の情報を交換し、ルーティングテーブルを自動的に作る方法を、動的ルーティングと呼びます。リンクが故障すると、その情報が伝わって別の経路に切り替わります。

インターネットは、AS（Autonomous System、自律システム）と呼ばれる、1 つの組織が一貫した方針で運用するネットワークの集まりです（「ネットワークの全体像」を参照してください）。経路制御のプロトコルは、AS の内部で使う IGP（Interior Gateway Protocol）と、AS の間で使う EGP（Exterior Gateway Protocol）に分けられます。

4.5. TTL と ICMP

4.5.1. TTL

経路の設定の誤りなどでルーティングのループが起きると、パケットはルーターの間を永遠に回り続けてしまいます。これを防ぐのが IP ヘッダーの TTL（Time To Live）です。送信元はパケットに TTL の初期値（Linux では 64、Windows では 128 が一般的）を設定し、ルーターはパケットを転送するたびに TTL を 1 減らします。TTL が 0 になったパケットは捨てられ、送信元に ICMP の時間超過メッセージが返されます。名前は「生存時間」ですが、実際には通過できるルーターの数を表しています。IPv6 では、実態に合わせてホップリミットという名前になっています。

4.5.2. ICMP

ICMP（Internet Control Message Protocol、RFC 792）は、IP の配送で起きた問題を送信元に知らせたり、ネットワークの診断を行ったりするためのプロトコルです。ICMP のメッセージは、IP パケットのデータ部分に入れて運ばれます（プロトコル番号 1）。

4.6. 断片化と Path MTU Discovery

4.6.1. 断片化

「リンク層」で見たように、リンクごとに MTU が決まっています。IPv4 では、ルーターが次のリンクの MTU より大きなパケットを受け取ると、パケットを複数の断片（フラグメント）に分割して送れます。これを断片化（フラグメンテーション）と呼びます。各断片には元のパケットと同じ識別子が付けられ、フラグメントオフセットに元のデータの中での位置が 8 バイト単位で記録されます。最後の断片以外には MF（More Fragments）フラグが立てられます。

例えば、データ部分が 3,980 バイトの IPv4 パケットを MTU 1,500 バイトのリンクに送る場合、各断片には 20 バイトの IP ヘッダーが必要なので、次の 3 つの断片に分かれます。

断片を元のパケットに組み立て直すのは、途中のルーターではなく最終的な宛先のホストです。断片化には次のような問題があります。

  • 断片が 1 つでも失われると、パケット全体が失われたことになります。再送は TCP などの上位の層が、元のパケットの単位で行う必要があります。

  • ルーターでの分割と、宛先での組み立てに処理の負担がかかります。

  • 2 つ目以降の断片には TCP や UDP のヘッダーが含まれないため、ポート番号を見るファイアウォールや NAT が正しく扱えません。

4.6.2. Path MTU Discovery

断片化を避けるために、送信元が経路 MTU を調べ、それ以下の大きさのパケットだけを送る方法が Path MTU Discovery（PMTUD、RFC 1191）です。

  1. 送信元は、IP ヘッダーの DF（Don't Fragment）フラグを立ててパケットを送ります。

  2. 次のリンクの MTU より大きいパケットを受け取ったルーターは、断片化せずにパケットを捨て、ICMP の宛先到達不能（コード 4）を送信元に返します。このメッセージには次のリンクの MTU が含まれています。

  3. 送信元は、その MTU に合わせてパケットを小さくして送り直します。

現在の OS は、TCP の通信で通常この方法を使います。しかし、経路上のファイアウォールが ICMP を遮断していると、送信元は MTU が小さいことを知る手段がなく、大きなパケットだけが黙って捨てられ続けます。この状態を PMTUD ブラックホールと呼びます。コネクションは確立でき、小さなデータは届くのに、大きなデータを送るとタイムアウトするという、原因の分かりにくい障害になります。対策として、PPPoE やトンネルの区間の入り口のルーターが、通過する TCP の SYN セグメントに含まれる MSS の値を小さく書き換える方法（MSS クランプ）がよく使われます。

なお、IPv6 ではルーターによる断片化は行われず、必要なら送信元だけが断片化します。そのため、IPv6 では Path MTU Discovery と、その通知に使う ICMPv6 の Packet Too Big メッセージが欠かせません。

4.7. NAT と NAPT

NAT（Network Address Translation）は、ルーターがパケットを転送するときに、IP ヘッダーの IP アドレスを書き換える技術です。主に、プライベートアドレスを使う組織の中のネットワークから、グローバルアドレスを使うインターネットへ通信するために使われます。

アドレスだけを 1 対 1 で変換する NAT では、同時にインターネットと通信できるホストの数がグローバルアドレスの数に限られます。そこで、IP アドレスに加えてポート番号も書き換え、1 つのグローバルアドレスを多数のホストで共有する NAPT（Network Address Port Translation）が広く使われています。IP マスカレードとも呼ばれ、家庭用のルーターが行う「NAT」は、ほぼすべてこの NAPT です。

NAPT のルーターは、内側のホストが外へパケットを送ると、送信元の IP アドレスとポート番号を自分のグローバルアドレスと未使用のポート番号に書き換え、その対応を変換テーブルに記録します。応答が返ってくると、宛先のポート番号から変換テーブルを引いて、元の内側のホストのアドレスとポート番号に戻します。

  • 外側から内側のホストへ通信を始められません。内側でサーバーを公開するには、特定のポートへの通信を内側のホストに転送する設定（ポートフォワーディング）が必要です。

  • IP アドレスがホストを一意に表すという、本来のエンドツーエンドの性質が失われます。P2P の通信やビデオ通話では、STUN などの技術で NAT を越える工夫（NAT 越え）が必要になります。

  • 通信事業者がさらに大規模な NAPT（CGN：Carrier-Grade NAT）を行う場合、多数の契約者が同じグローバルアドレスを共有します。

4.8. DHCP

ホストが IP の通信を行うには、IP アドレス、サブネットマスク、デフォルトゲートウェイ、DNS サーバーのアドレスなどの設定が必要です。これらを自動的に配布するプロトコルが DHCP（Dynamic Host Configuration Protocol、RFC 2131）です。

DHCP では、まだ IP アドレスを持たないホストが設定を得るため、ブロードキャストを使いながら次の 4 つのメッセージをやり取りします。メッセージは UDP で運ばれ、サーバーはポート番号 67、クライアントは 68 を使います。

  1. DHCPDISCOVER：クライアントが、DHCP サーバーを探すメッセージをブロードキャストで送ります。送信元の IP アドレスはまだないので 0.0.0.0 を使います。

  2. DHCPOFFER：DHCP サーバーが、割り当てる候補の IP アドレスと設定を提示します。

  3. DHCPREQUEST：クライアントが、提示されたアドレスの使用を申し込みます。複数のサーバーから提示があった場合に、どれを選んだかを全員に知らせるため、ブロードキャストで送ります。

  4. DHCPACK：サーバーが割り当てを確定します。

割り当てられたアドレスには使用期限（リース期間）があり、クライアントは期限の半分を過ぎると更新を申し込みます。使われなくなったアドレスは、期限が切れると他のホストに再び割り当てられます。DHCP のメッセージはブロードキャストなのでルーターを越えられませんが、ルーターに DHCP リレーの機能を設定すると、別のネットワークにある DHCP サーバーを使えます。

4.9. IPv6

IPv6 は、IPv4 アドレスの枯渇に対応するために設計された IP の新しい版で、現在の仕様は RFC 8200 で定められています。経緯は「ネットワークの歴史」を参照してください。

4.9.1. IPv6 アドレス

IPv6 アドレスは 128 ビットで、アドレスの総数は \(2^{128}\)、約 \(3.4 \times 10^{38}\) 個です。16 ビットずつ 16 進数で表して「:」で区切り、2001:0db8:0000:0000:0000:0000:0000:0001 のように書きます。各グループの先頭の 0 は省略でき、0 だけのグループが連続する部分は 1 か所に限り「::」で省略できるので、このアドレスは 2001:db8::1 と書けます（2001:db8::/32 は文書の例示用のアドレスです）。

IPv6 のサブネットは、通常プレフィックス長 /64 で、上位 64 ビットがネットワークを、下位 64 ビットがインターフェースを表します。1 つのサブネットに \(2^{64}\) 個のアドレスがあり、アドレスの数を節約する必要はありません。

4.9.2. IPv4 との違い

IPv6 は、アドレスが長くなっただけでなく、IPv4 の運用の経験を踏まえていくつかの点が整理されています。

  • ヘッダーが 40 バイトの固定長になり、ルーターの処理が単純になりました。ヘッダーチェックサムはなくなり、オプションは必要なときだけ拡張ヘッダーとして後ろに連結します。

  • ブロードキャストはなくなり、マルチキャストで置き換えられました。ARP の役割は、ICMPv6 を使う近隣探索プロトコル（NDP）が担います。

  • ルーターによる断片化はなくなり、すべてのリンクの MTU は 1,280 バイト以上と定められました。

  • ルーターが広告するプレフィックスから、ホストが自分でアドレスを生成するステートレスアドレス自動設定（SLAAC）があり、DHCP がなくてもアドレスを設定できます。プライバシーを守るため、インターフェースの部分を一時的なランダムな値にする方式も広く使われています。

  • アドレスが十分にあるため、原理的には NAT を使わずに、すべての機器にグローバルなアドレスを割り当てられます。ただし、外部からの通信を制限するには、ファイアウォールが必要です。

IPv4 と IPv6 には互換性がなく、IPv6 だけを持つホストは IPv4 だけを持つホストと直接通信できません。そのため、現在は 1 台の機器が両方のアドレスを持つデュアルスタックが一般的です。デュアルスタックのクライアントは、IPv6 での接続を先に試み、短い時間のうちに成功しなければ IPv4 での接続も並行して試み、先に成功した方を使う Happy Eyeballs と呼ばれる方法で、IPv6 の経路に問題がある場合の遅延を避けています。

4.10. まとめ

  • IP は、IP アドレスを宛先として、パケットを多数のネットワークをまたいで届けます。配送はベストエフォート型で、損失や順序の入れ替わりは上の層が扱います。

  • IPv4 アドレスは 32 ビットで、ネットワーク部とホスト部に分かれます。CIDR では、プレフィックス長でネットワーク部の長さを任意に決められ、プレフィックス長 \(n\) のサブネットのホスト数は \(2^{32-n}-2\) です。

  • ルーターは、ルーティングテーブルの中から宛先に一致するプレフィックス長が最も長い経路を選んで転送します（最長一致）。

  • 経路は、静的に設定するほか、AS の内部では OSPF など、AS の間では BGP によって動的に交換されます。

  • TTL はルーティングのループからネットワークを守り、ICMP は配送の問題の通知や診断に使われます。ICMP を遮断すると Path MTU Discovery が働かなくなることがあります。

  • NAPT は 1 つのグローバルアドレスを多数のホストで共有させますが、外側からの通信の開始ができないなどの制約があります。

  • IPv6 は 128 ビットのアドレスを持ち、固定長のヘッダー、ルーターによる断片化の廃止、アドレスの自動設定などの特徴があります。
