10. よくあるトラブルと対処

この章では、Sphinx でドキュメントを作るときによく起きるトラブルと、その対処方法を説明します。

10.1. 警告の読み方

ソースファイルに問題があると、ビルド時に警告が表示されます。警告は次の形式で表示されます。

1C:\docs\source\install.rst:12: WARNING: undefined label: 'sec-instal' [ref.ref]

先頭から順に、問題のあるファイル、行番号、警告の種類（WARNING または ERROR）、内容が表示されます。末尾の角括弧の中は警告の分類を表す名前で、conf.py の suppress_warnings に指定すると、その種類の警告を表示しないようにできます。

警告が出てもビルドは完了し、HTML も出力されます。しかし、警告の箇所は意図どおりに表示されていないことが多いため、警告はすべて解消するようにします。よく見る警告と原因を表 10.1 に示します。

表 10.1 よく見る警告と原因

警告

主な原因

undefined label

ref ロールで指定したラベルが存在しません。ラベル名の誤りを確認します。

document isn't included in any toctree

どの toctree にも含まれていないソースファイルがあります。toctree に追加するか、ファイルの先頭に :orphan: と書きます。

toctree contains reference to nonexisting document

toctree に書いたソースファイルが存在しません。パスの誤りを確認します。

Title underline too short

見出しの下の記号の行が短すぎます。全角文字は 2 文字分として数えます（見出し）。

Unexpected indentation

字下げの位置が正しくありません。リストやディレクティブの前後の空行と、字下げの幅を確認します。

Inline literal start-string without end-string

インライン記法の終わりが認識されていません。記号の直後に空白や句読点があるかを確認します（インライン記法）。

Explicit markup ends without a blank line

ディレクティブの内容の後に空行がありません。

duplicate label

同じ名前のラベルが複数あります。

failed to import

autodoc がモジュールを import できません。sys.path の設定や、依存するライブラリのインストールを確認します（モジュールの読み込み場所の設定）。

10.2. 日本語のドキュメントで表示が崩れる例

日本語のドキュメントでは、reST の記法の性質から、次のような表示の崩れが起きやすくなります。

文章の途中に空白が入る

段落の途中で改行すると、改行が半角空白に置き換えられます。日本語の段落は途中で改行せずに書きます（段落と改行）。

インライン記法が認識されない

``conf.py`` のような記法の前後に日本語の文字が直接続いていると、記法として認識されません。前後に半角空白を入れるか、バックスラッシュと半角空白の組み合わせを入れます（インライン記法）。

表が崩れる

grid 形式や simple 形式の表では、全角文字を含むセルの幅をそろえるのが難しく、表が崩れる原因になります。list-table を使うと、この問題を避けられます（表）。

数式が崩れる

Python の docstring に数式を書くと、\frac の \f などがエスケープシーケンスとして解釈され、数式が壊れることがあります。数式を含む docstring は raw 文字列にします。なお、reST のソースファイルの math ディレクティブの中では、バックスラッシュをそのまま書けます。

10.3. リンク切れの確認

ドキュメントの中の相互参照は、参照先がなければビルド時に警告されます。一方、外部の Web ページへのリンクは、通常のビルドでは確認されません。外部へのリンクが有効かどうかは、linkcheck ビルダーで確認します。

1sphinx-build -b linkcheck source build/linkcheck

リンクごとの結果が表示され、無効なリンクがあるとビルドが失敗します。結果は build/linkcheck/output.txt と output.json にも書き出されます。認証が必要なページなど、確認の対象から外したい URL は、conf.py の linkcheck_ignore に正規表現で指定します。

10.4. 変更が反映されないときの対処

Sphinx は、2 回目以降のビルドでは変更のあったソースファイルだけを読み込み直します（Sphinx とは）。この仕組みのため、次のような場合に、変更が一部のページに反映されないことがあります。

  • 見出しを変更したのに、ほかのページのサイドバーの目次が古いままになっている。

  • テーマのテンプレートや CSS を変更したのに、表示が変わらない。

  • 拡張機能のコードを変更したのに、出力が変わらない。

このような場合は、次のいずれかの方法で、すべてのファイルを処理し直します。

表 10.2 すべてのファイルを処理し直す方法

方法

説明

-E オプション

保存されている中間ファイルを使わず、すべてのソースファイルを読み込み直します。

-a オプション

変更の有無にかかわらず、すべてのファイルを出力し直します。

build ディレクトリの削除

中間ファイルと出力をすべて削除してからビルドします。本書のバッチファイル（ビルド用のバッチファイル）は、この方法を使っています。

公開する前の最終的なビルドは、build ディレクトリを削除してから行うと確実です。
