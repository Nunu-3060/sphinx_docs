2. インストールと最初のプロジェクト

この章では、Sphinx をインストールし、最小構成のプロジェクトを作って HTML をビルドするまでの手順を説明します。

2.1. インストール

Sphinx は PyPI で公開されているため、pip でインストールできます。プロジェクトごとに仮想環境を作り、その中にインストールすることをお勧めします。

Windows では、次のコマンドを実行します。

1python -m venv .venv
2.venv\Scripts\activate
3python -m pip install sphinx

macOS や Linux では、2 行目を次のように読み替えます。

1source .venv/bin/activate

インストールできたかどうかは、次のコマンドで確認できます。バージョン番号が表示されれば成功です。

1sphinx-build --version

注釈

sphinx-build コマンドが見つからない場合は、python -m sphinx で代用できます。本書のバッチファイル（ビルド用のバッチファイル）も、この形で Sphinx を呼び出しています。

2.2. プロジェクトの作成

sphinx-quickstart コマンドを使うと、プロジェクトに必要なファイル一式を作成できます。ドキュメントを置きたいディレクトリで、次のコマンドを実行します。

1sphinx-quickstart

コマンドを実行すると、いくつかの質問が表示されます。主な質問の意味を表 2.1 に示します。

表 2.1 sphinx-quickstart の主な質問

質問

説明

ソースとビルドのディレクトリを分けるか

y を選ぶと、ソースファイルを source、出力を build に分けて置きます。ファイルの管理がしやすくなるため、本書では y を選びます。

プロジェクト名

ドキュメントのタイトルなどに使われます。

著者名

著作権表示などに使われます。

リリース

ドキュメントの対象とするソフトウェアのバージョンです。空欄でも構いません。

ドキュメントの言語

日本語のドキュメントでは ja を指定します。検索機能や画面の文言が日本語向けになります。

-q オプションを付けると質問を省略し、コマンドの引数で値を指定できます。次の例は、上の質問にすべて答えたものと同じ結果になります。最後の引数 docs は、プロジェクトを作成するディレクトリです。

1sphinx-quickstart -q --sep -p demo -a author -r 0.1 -l ja docs

2.3. 生成されるファイル

ソースとビルドのディレクトリを分けた場合、次のファイルが生成されます。

1docs/
2├── Makefile
3├── make.bat
4├── build/
5└── source/
6    ├── _static/
7    ├── _templates/
8    ├── conf.py
9    └── index.rst

各ファイルとディレクトリの役割を表 2.2 に示します。

表 2.2 sphinx-quickstart が生成するファイル

ファイル

役割

source/conf.py

プロジェクトの設定ファイルです。詳しくは conf.py による設定で説明します。

source/index.rst

ドキュメントのトップページになるソースファイルです。ここに書いた toctree から、ほかのソースファイルをたどります。

source/_static/

CSS や画像など、出力先にそのままコピーするファイルを置くディレクトリです。

source/_templates/

HTML のテンプレートを上書きするときに使うディレクトリです。

build/

ビルドの結果を出力するディレクトリです。

Makefile、make.bat

ビルドを簡単に実行するためのファイルです。make.bat は Windows 用です。

生成された conf.py の中身は次のとおりです。本書のサンプルでは、それぞれの設定値に型ヒントを追加しています。

 1# sphinx-quickstart が生成する conf.py に、型ヒントを追加したものです。
 2#
 3# 設定値の一覧は次のページを参照してください。
 4# https://www.sphinx-doc.org/ja/master/usage/configuration.html
 5
 6# -- プロジェクト情報 --------------------------------------------------------
 7
 8project: str = "demo"
 9copyright: str = "2026, author"
10author: str = "author"
11release: str = "0.1"
12
13# -- 一般設定 ----------------------------------------------------------------
14
15extensions: list[str] = []
16
17templates_path: list[str] = ["_templates"]
18exclude_patterns: list[str] = []
19
20language: str = "ja"
21
22# -- HTML 出力の設定 ---------------------------------------------------------
23
24html_theme: str = "alabaster"
25html_static_path: list[str] = ["_static"]

sphinx-quickstart で作成したプロジェクトに、ページを 1 つ追加したものを minimal_project.zip として用意しています。以降の説明を試すときに使ってください。

2.4. ビルド

プロジェクトのディレクトリで次のコマンドを実行すると、HTML が build/html に出力されます。

1sphinx-build -M html source build

sphinx-build の基本的な書式は sphinx-build -b ビルダー名 ソースディレクトリ 出力ディレクトリ です。-M を指定すると、Makefile から実行するときと同じ動作になり、出力先が build/html、中間ファイルの保存先が build/doctrees になります。次のように -b を使っても、同じ場所に HTML を出力できます。

1sphinx-build -b html source build/html

Makefile や make.bat を使う場合は、次のコマンドで同じ結果になります。Windows の PowerShell では .\make html と入力します。

1make html

ビルドが終わったら、build/html/index.html をブラウザで開くと、生成されたドキュメントを確認できます。

2.5. ビルド用のバッチファイル

ビルドのたびにコマンドを入力するのは手間がかかるため、手順をバッチファイルにまとめておくと便利です。本書のプロジェクトでは、次の build_html_example.bat を使っています。

リスト 2.2 build_html_example.bat
 1@echo off
 2rem Build the Sphinx documentation as HTML and open it in the default browser.
 3
 4setlocal
 5cd /d "%~dp0"
 6
 7rem Remove the previous build results.
 8if exist build rmdir /s /q build
 9
10rem Build HTML into build\html.
11python -m sphinx -b html source build\html
12if errorlevel 1 (
13    echo Build failed.
14    exit /b 1
15)
16
17rem Open the top page in the default browser.
18start "" "%~dp0build\html\index.html"
19
20endlocal

このバッチファイルは、次の処理を順に行います。

  1. バッチファイルのあるディレクトリに移動します（5 行目）。

  2. 前回のビルド結果が残らないよう、build ディレクトリがあれば削除します（8 行目）。

  3. HTML をビルドします。ビルドに失敗した場合は、メッセージを表示して終了します（11〜15 行目）。

  4. 生成された index.html を既定のブラウザで開きます（18 行目）。

build ディレクトリを削除してからビルドすることで、差分ビルドによる表示の食い違い（変更が反映されないときの対処）を防げます。
