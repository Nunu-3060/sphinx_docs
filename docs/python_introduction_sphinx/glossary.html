11. 用語集

本書で使う用語を説明します。

autodoc

Python のモジュールを import し、docstring から API ドキュメントを生成する拡張機能です。

docstring

Python のモジュール、クラス、関数の先頭に書く、説明のための文字列です。

doctree

ソースファイルを解析して作られる、ドキュメントの内容を表す木構造のデータです。ビルダーは doctree を特定の形式に変換して出力します。

intersphinx

Python の公式ドキュメントなど、Sphinx で作られた外部のドキュメントの要素を相互参照できるようにする拡張機能です。

MyST

Markdown に、ディレクティブやロールなどの reST の機能を追加した記法です。MyST-Parser という拡張機能を使うと、Sphinx で使えるようになります。

reStructuredText
reST

Sphinx のソースファイルを書くための軽量マークアップ言語です。Python の Docutils というライブラリが解釈します。

toctree

複数のソースファイルの親子関係を定義し、ドキュメント全体の構造を決めるディレクティブです。目次やページ間のリンクの生成にも使われます。

ソースディレクトリ

conf.py とソースファイルを置くディレクトリです。本書のプロジェクトでは source ディレクトリです。

ディレクティブ

図、表、コードなどのブロック単位の要素を作る reST の仕組みです。.. 名前:: の形で書きます。

テーマ

HTML の見た目を決める、テンプレートと CSS などのファイルの集まりです。conf.py の html_theme で指定します。

ドメイン

プログラミング言語ごとに、オブジェクトを記述するディレクティブと、それを参照するロールをまとめたものです。Python のほかに、C、C++、JavaScript などのドメインがあります。

ビルダー

doctree を HTML や LaTeX などの特定の形式に変換して出力する部品です。sphinx-build の -b オプションで指定します。

ビルドディレクトリ

ビルドの結果と中間ファイルを出力するディレクトリです。本書のプロジェクトでは build ディレクトリです。

ラベル

章や図表などに付ける、相互参照のための名前です。プロジェクトの中で一意にする必要があります。

ロール

文章の一部に意味を持たせる reST の仕組みです。:名前:`文字列` の形で書きます。

拡張機能

Sphinx に機能を追加する Python のモジュールです。conf.py の extensions で有効にします。

相互参照

ラベルや名前を指定して、ドキュメントの別の場所にリンクすることです。参照先の見出しや番号が自動で埋め込まれます。
