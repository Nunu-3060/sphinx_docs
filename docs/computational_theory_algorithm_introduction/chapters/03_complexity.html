第 3 章 アルゴリズムと計算量

アルゴリズムとは、問題を解くための手順を、曖昧さなく有限の長さで記述したものである。同じ問題を解くアルゴリズムが複数あるとき、それらを比べる物差しが必要になる。本章では、アルゴリズムの効率を計算量として測る方法を説明する。

計算モデル

実行時間を秒で測ると、計算機の性能やプログラミング言語、実装の細部によって結果が変わってしまう。そこでアルゴリズムの解析では、抽象化した計算機（計算モデル）を考え、その上での基本操作の回数を数える。

本書の第 2 部では、次のような RAM モデル（Random Access Machine）を用いる。

  • メモリは番号付きのセルの列であり、どのセルにも一定時間で読み書きできる。

  • 四則演算、比較、代入、配列の添字によるアクセス、関数呼び出しといった基本操作は、それぞれ一定時間（1 ステップ）で実行できる。

  • 1 つのセルに入る整数の大きさは、入力サイズ \(n\) に対して \(O(\log n)\) ビット程度とする。

最後の仮定は、巨大な整数の演算を 1 ステップで行うという非現実的な状況を避けるためのものである。Python の int は任意の大きさの整数を扱えるが、桁数が大きくなるとその演算は一定時間では終わらない。

第 3 部では、より単純な計算モデルであるチューリング機械を扱う。RAM モデルとチューリング機械の実行時間は多項式の範囲で互いに変換できることが知られており、第 11 章で扱う「多項式時間で解けるか」という区別はどちらのモデルで考えても変わらない。

時間計算量と空間計算量

入力サイズ \(n\) の入力に対してアルゴリズムが実行する基本操作の回数を、\(n\) の関数として表したものを時間計算量と呼ぶ。同様に、使用するメモリの量を空間計算量と呼ぶ。入力サイズは問題に応じて決める。例えば整列ならリストの要素数、グラフの問題なら頂点数 \(V\) と辺の数 \(E\) を使う。

例として、リストの最大値を求める関数を考える。

1def maximum(values: list[int]) -> int:
2    best = values[0]
3    for v in values[1:]:
4        if v > best:
5            best = v
6    return best

2 行目は 1 回、3 行目から 5 行目は \(n - 1\) 回繰り返され、各回の操作数は定数で抑えられる。したがって時間計算量は \(\Theta(n)\) である。3 行目の values[1:] は長さ \(n - 1\) のリストのコピーを作るため、空間計算量は \(\Theta(n)\) になる。添字でループすれば追加の領域は \(O(1)\) で済む。このように、Python では 1 行に見える処理が一定時間で終わるとは限らない点に注意が必要である（後述の表を参照）。

最悪計算量・平均計算量・償却計算量

同じ入力サイズでも、入力の内容によって実行時間が変わることがある。例えばリストを先頭から調べて値を探す線形探索は、目的の値が先頭にあれば 1 回の比較で終わるが、存在しなければ \(n\) 回の比較が必要になる。そこで計算量は次のように区別して述べる。

表 7 計算量の種類

種類

意味

最悪計算量

サイズ \(n\) の全ての入力の中で、最も時間がかかる場合の計算量。単に「計算量」と言えば通常はこれを指す。

平均計算量

入力が何らかの確率分布に従うと仮定したときの、計算量の期待値。

償却計算量

一連の操作の合計時間を操作の回数で割った、1 操作あたりの計算量。ときどき重い操作が起きても、それが全体に占める割合が小さければ償却計算量は小さくなる。

最悪計算量は、どんな入力に対しても性能を保証できる点で最も重要である。平均計算量は、入力の分布についての仮定が現実に合っているかどうかに依存する。乱択アルゴリズム（第 5 章、第 12 章）では、入力ではなくアルゴリズム自身が使う乱数について期待値をとった期待計算量を考える。

償却計算量の例：Python のリストの append

Python の list は、内部に確保した配列が一杯になると、より大きな配列を確保して要素を全てコピーする。コピーには \(O(n)\) 時間がかかるが、配列の容量を毎回定数倍（例えば 2 倍）に増やしておけば、コピーが起きる頻度は次第に下がる。容量を 2 倍ずつ増やす場合、\(n\) 回の append で行われるコピーの総数は高々

\[1 + 2 + 4 + \cdots + 2^{\lfloor \log n \rfloor} < 2n\]

である（第 2 章の等比級数の性質）。したがって \(n\) 回の append の合計は \(O(n)\) 時間であり、1 回あたりの償却計算量は \(O(1)\) となる。なお、CPython の実際の増加率は約 1.125 倍だが、定数倍で増やす限り同じ結論が得られる。

漸化式とマスター定理

再帰的なアルゴリズムの計算量は、漸化式で表すと見通しがよくなる。例えば、サイズ \(n\) の問題をサイズ \(n/2\) の部分問題 2 つに分け、結果を \(O(n)\) 時間で統合するアルゴリズム（第 5 章のマージソートなど）の計算量 \(T(n)\) は次の式を満たす。

\[T(n) = 2T(n/2) + cn, \quad T(1) = c\]

この式を展開すると、再帰の各段で合計 \(cn\) の仕事があり、段数は \(\log n\) なので、\(T(n) = cn \log n + cn = \Theta(n \log n)\) となる。

より一般に、次の形の漸化式にはマスター定理が使える。

\[T(n) = a T(n/b) + f(n) \quad (a \ge 1,\ b > 1)\]

これは、サイズ \(n\) の問題をサイズ \(n/b\) の部分問題 \(a\) 個に分け、分割と統合に \(f(n)\) 時間かかるアルゴリズムを表す。\(n^{\log_b a}\) と \(f(n)\) を比べて、次のように \(T(n)\) が決まる。

表 8 マスター定理（簡略版）

計算量の違いを計測する

計算量の違いが実際の実行時間にどう現れるかを確かめよう。次のサンプルコードは、リストに重複する要素があるかを 3 通りの方法で判定し、入力サイズ \(n\) を 2 倍にしたときの実行時間を計測する。

ch03_complexity_measure.py

リスト 1 ch03_complexity_measure.py
 1"""第 3 章: 計算量の違いを実行時間で確かめる。
 2
 3「リストに重複する要素があるか」を判定する 3 つの関数を用意し、
 4入力サイズ n を 2 倍にしたときに実行時間がどう増えるかを計測する。
 5
 6* has_duplicate_quadratic: 全ての組を比べる。O(n^2)
 7* has_duplicate_sort: 整列してから隣同士を比べる。O(n log n)
 8* has_duplicate_set: 集合を使う。平均 O(n)
 9
10実行例::
11
12    python ch03_complexity_measure.py
13"""
14
15from __future__ import annotations
16
17import random
18import time
19from collections.abc import Callable
20
21
22def has_duplicate_quadratic(values: list[int]) -> bool:
23    """全ての組 (i, j) を調べて重複の有無を判定する。"""
24    n = len(values)
25    for i in range(n):
26        for j in range(i + 1, n):
27            if values[i] == values[j]:
28                return True
29    return False
30
31
32def has_duplicate_sort(values: list[int]) -> bool:
33    """整列すると等しい要素は隣り合うことを利用する。"""
34    ordered = sorted(values)
35    return any(a == b for a, b in zip(ordered, ordered[1:]))
36
37
38def has_duplicate_set(values: list[int]) -> bool:
39    """集合 (ハッシュテーブル) に要素を入れながら重複を探す。"""
40    seen: set[int] = set()
41    for value in values:
42        if value in seen:
43            return True
44        seen.add(value)
45    return False
46
47
48def measure(func: Callable[[list[int]], bool], values: list[int]) -> float:
49    """func(values) の実行にかかった秒数を返す。"""
50    start = time.perf_counter()
51    func(values)
52    return time.perf_counter() - start
53
54
55def main() -> None:
56    random.seed(0)
57    funcs: list[Callable[[list[int]], bool]] = [
58        has_duplicate_quadratic,
59        has_duplicate_sort,
60        has_duplicate_set,
61    ]
62    print(f"{'n':>6} {'O(n^2)':>10} {'O(n log n)':>12} {'O(n)':>10}")
63    for n in (1000, 2000, 4000):
64        # 重複がない入力は、どの関数にとっても最後まで調べる最悪の入力になる。
65        values = random.sample(range(10 * n), n)
66        times = [measure(func, values) for func in funcs]
67        print(f"{n:>6} {times[0]:>10.4f} {times[1]:>12.4f} {times[2]:>10.4f}")
68
69
70if __name__ == "__main__":
71    main()

実行結果の例を示す（時間の単位は秒で、計算機によって値は異なる）。

1     n     O(n^2)   O(n log n)       O(n)
2  1000     0.0304       0.0002     0.0001
3  2000     0.1398       0.0005     0.0003
4  4000     0.4578       0.0009     0.0004

\(n\) が 2 倍になると、\(O(n^2)\) の方法は約 4 倍に増えている。他の 2 つは実行時間が短すぎて測定誤差の影響が大きいが、\(O(n^2)\) の方法との差は桁違いであることが分かる。\(n\) が小さいうちは測定誤差の影響が大きいが、\(n\) を大きくするほど計算量の差がはっきり現れる。

章末のまとめ

  • アルゴリズムの効率は、計算モデル上の基本操作の回数（時間計算量）と使用メモリ（空間計算量）で測る。

  • 計算量は通常、最悪計算量を漸近記法で表す。償却計算量は、一連の操作全体で見た 1 操作あたりのコストである。

  • 分割統治型の再帰アルゴリズムの計算量は、漸化式とマスター定理で求められる。

  • Python の組み込み型の操作には、一定時間で終わらないものがある。
