第 12 章 困難な問題への対処

第 11 章で見たように、実務で出会う最適化問題の多くは NP 困難である。しかし、問題が NP 困難だと分かっても、解かなくてよいことにはならない。本章では、NP 困難な問題に現実的に対処するための代表的な方法を紹介する。

対処の方針は、何を諦めるかによって次のように分けられる。

近似アルゴリズム

最小化問題に対して、常に最適解の値の \(\alpha\) 倍以下の値を持つ解を多項式時間で出力するアルゴリズムを、近似比 \(\alpha\) の近似アルゴリズム（\(\alpha\) 近似アルゴリズム）と呼ぶ。最大化問題では、最適解の値の \(1/\alpha\) 倍以上の解を出力するものをいう。近似アルゴリズムの価値は、最適解が分からなくても、得られた解が最適解からどれだけ離れているかを保証できる点にある。

頂点被覆の 2 近似アルゴリズム

頂点被覆問題は、グラフの頂点をできるだけ少なく選んで、全ての辺の少なくとも一方の端点が選ばれているようにする問題である。判定版は NP 完全である（第 11 章）。

次の単純なアルゴリズムは 2 近似アルゴリズムである。

  1. まだ覆われていない（どちらの端点も選ばれていない）辺 \((u, v)\) を 1 本選ぶ。

  2. \(u\) と \(v\) を両方とも被覆に加える。

  3. 覆われていない辺がなくなるまで 1 と 2 を繰り返す。

近似比の証明：1 で選んだ辺の集合を \(M\) とする。\(M\) の辺は互いに端点を共有しない（ある辺を選ぶと、その端点に接続する辺は全て覆われるので、以後選ばれない）。任意の頂点被覆は \(M\) の各辺の端点を少なくとも 1 つ含み、\(M\) の辺は端点を共有しないので、最適解の大きさ \(\mathrm{OPT}\) は \(|M|\) 以上である。一方、アルゴリズムの出力の大きさは \(2|M|\) なので、\(2|M| \le 2\,\mathrm{OPT}\) となる。

この証明では、最適解そのものを知らずに、最適解の値の下界（\(|M|\)）と比べることで近似比を示している。これは近似アルゴリズムの解析で一般的に使われる方法である。

 2

 4選んだ辺は互いに端点を共有しない (極大マッチング) ので、最適解はそれぞれの

 6

10"""

12from __future__ import annotations
13
14from itertools import combinations
15
16Edge = tuple[int, int]
17
18
19def approx_vertex_cover(edges: list[Edge]) -> set[int]:
20    """サイズが最適解の 2 倍以下の頂点被覆を O(E) で返す。"""
21    cover: set[int] = set()
22    for u, v in edges:
23        if u not in cover and v not in cover:  # まだ覆われていない辺
24            cover.add(u)
25            cover.add(v)
26    return cover
27
28
29def exact_vertex_cover(edges: list[Edge]) -> set[int]:
30    """小さい順に全ての頂点集合を試して最小の頂点被覆を返す (指数時間)。"""
31    vertices = sorted({x for edge in edges for x in edge})
32    for size in range(len(vertices) + 1):
33        for group in combinations(vertices, size):
34            chosen = set(group)
35            if all(u in chosen or v in chosen for u, v in edges):
36                return chosen
37    return set(vertices)
38
39
40def main() -> None:
41    edges: list[Edge] = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4), (4, 5),
42                         (4, 6), (5, 6)]
43    approx = approx_vertex_cover(edges)
44    exact = exact_vertex_cover(edges)
45    print(f"近似解: {sorted(approx)} (サイズ {len(approx)})")
46    print(f"最適解: {sorted(exact)} (サイズ {len(exact)})")
47    print("近似比:", len(approx) / len(exact))

巡回セールスマン問題の 2 近似アルゴリズム

巡回セールスマン問題（TSP: Traveling Salesman Problem）は、全ての都市をちょうど 1 回ずつ訪れて出発点に戻る巡回路のうち、最短のものを求める問題である。都市間の距離が三角不等式 \(d(a, c) \le d(a, b) + d(b, c)\) を満たす場合（平面上の直線距離など）には、次の 2 近似アルゴリズムがある。

  1. 都市を頂点、距離を辺の重みとする完全グラフの最小全域木 \(T\) を求める（第 7 章）。

  2. \(T\) を深さ優先で前順（行きがけ順）にたどり、初めて訪れた順に都市を並べて巡回路とする。

近似比の証明：最適な巡回路から辺を 1 本取り除くと全域木になるので、\(T\) の重み \(w(T)\) は最適な巡回路の長さ \(\mathrm{OPT}\) 以下である。\(T\) の各辺を往復して全ての頂点を回る経路の長さは \(2w(T)\) である。この経路から既に訪れた都市を飛ばしても、三角不等式により経路は長くならない。したがって、得られる巡回路の長さは \(2w(T)\) 以下であり、\(2w(T) \le 2\,\mathrm{OPT}\) である。

最小全域木と最小重みの完全マッチングを組み合わせると、近似比を 1.5 に改善できる（クリストフィードのアルゴリズム）。一方、三角不等式を満たさない一般の TSP では、P ≠ NP である限り、どのような定数 \(\alpha\) についても \(\alpha\) 近似アルゴリズムは存在しないことが知られている。近似のしやすさは問題によって大きく異なる。

局所探索

局所探索は、適当な解から始めて、解を少し変更して改善することを、改善できなくなるまで繰り返す方法である。TSP に対する代表的な局所探索が 2-opt 法であり、巡回路の 2 本の辺 \((a, b)\) と \((c, d)\) を \((a, c)\) と \((b, d)\) につなぎ替えて（間の区間を逆順にして）短くなるなら採用する。

局所探索で得られる解は、少しの変更では改善できない局所最適解であり、全体の最適解とは限らない。また、近似比の保証もない。しかし実用上はよい解が得られることが多く、近似アルゴリズムの出力を初期解として改善するといった使い方をする。局所最適解から抜け出すために、ときどき悪くなる変更も受け入れる焼きなまし法なども広く使われている。

リスト 26 ch12_tsp_approx.py
 1"""第 12 章: 巡回セールスマン問題の近似と局所探索。
 2
 3平面上の点 (距離が三角不等式を満たす) について、次の 3 つを比べる。
 4
 5* mst_tour: 最小全域木を深さ優先でたどった順に回る 2 近似アルゴリズム。
 6* two_opt: 経路の 2 辺をつなぎ替えて短くなる限り改善を続ける局所探索。
 7* exact_tour: 全ての順列を試す厳密解法 (点が少ないときだけ使える)。
 8
 9実行例::
10
11    python ch12_tsp_approx.py
12"""
13
14from __future__ import annotations
15
16import math
17import random
18from itertools import permutations
19
20Point = tuple[float, float]
21
22
23def tour_length(points: list[Point], tour: list[int]) -> float:
24    """巡回路 tour (最後に出発点へ戻る) の長さを返す。"""
25    return sum(math.dist(points[tour[i]], points[tour[i - 1]])
26               for i in range(len(tour)))
27
28
29def mst_tour(points: list[Point]) -> list[int]:
30    """プリム法で最小全域木を作り、その前順 (行きがけ順) を巡回路とする。"""
31    n = len(points)
32    in_tree = [False] * n
33    best = [math.inf] * n  # 木に最も近い頂点までの距離
34    parent = [-1] * n
35    children: list[list[int]] = [[] for _ in range(n)]
36    best[0] = 0.0
37    for _ in range(n):
38        u = min((i for i in range(n) if not in_tree[i]), key=lambda i: best[i])
39        in_tree[u] = True
40        if parent[u] >= 0:
41            children[parent[u]].append(u)
42        for v in range(n):
43            d = math.dist(points[u], points[v])
44            if not in_tree[v] and d < best[v]:
45                best[v], parent[v] = d, u
46    order: list[int] = []
47    stack = [0]
48    while stack:  # 深さ優先でたどり、初めて訪れた順に並べる
49        u = stack.pop()
50        order.append(u)
51        stack.extend(reversed(children[u]))
52    return order
53
54
55def two_opt(points: list[Point], tour: list[int]) -> list[int]:
56    """辺 (a, b) と (c, d) を (a, c) と (b, d) に替えて短くなれば採用する。"""
57    tour = list(tour)
58    improved = True
59    while improved:
60        improved = False
61        for i in range(1, len(tour) - 1):
62            for j in range(i + 1, len(tour)):
63                a, b = points[tour[i - 1]], points[tour[i]]
64                c, d = points[tour[j]], points[tour[(j + 1) % len(tour)]]
65                delta = (math.dist(a, c) + math.dist(b, d)
66                         - math.dist(a, b) - math.dist(c, d))
67                if delta < -1e-12:
68                    tour[i:j + 1] = reversed(tour[i:j + 1])
69                    improved = True
70    return tour
71
72
73def exact_tour(points: list[Point]) -> list[int]:
74    """点 0 を出発点に固定し、残りの (n - 1)! 通りの順序を全て試す。"""
75    rest = range(1, len(points))
76    best = min(permutations(rest),
77               key=lambda p: tour_length(points, [0, *p]))
78    return [0, *best]
79
80
81def main() -> None:
82    random.seed(3)
83    points = [(random.random(), random.random()) for _ in range(9)]
84    approx = mst_tour(points)
85    improved = two_opt(points, approx)
86    exact = exact_tour(points)
87    print(f"2 近似 (最小全域木): {tour_length(points, approx):.4f}")
88    print(f"2-opt で改善      : {tour_length(points, improved):.4f}")
89    print(f"厳密解            : {tour_length(points, exact):.4f}")
90
91
92if __name__ == "__main__":
93    main()

実行結果の例を示す。この例では、2 近似アルゴリズムの解を 2-opt 法で改善すると最適解に一致したが、常に最適解が得られるわけではない。

乱択アルゴリズム

乱択アルゴリズムは、実行中に乱数を使うアルゴリズムである。乱択アルゴリズムは、誤りの性質によって次の 2 種類に分けられる。

  • ラスベガス法：答えは常に正しいが、実行時間が乱数によって変わる。第 5 章の乱択クイックソートがこれに当たる。

  • モンテカルロ法：実行時間は一定の範囲に収まるが、小さな確率で誤った答えを返す。

モンテカルロ法でも、独立に何回も実行すれば誤り確率を指数的に小さくできる。誤り確率が 1/4 以下の試行を 20 回繰り返せば、誤り確率は \(4^{-20} \approx 10^{-12}\) 以下になる。これは計算機のハードウェアが故障する確率よりも小さい。

ミラー-ラビン素数判定法

RSA 暗号などの公開鍵暗号では、数百桁の素数を大量に生成する必要がある。素数判定は P に属する（第 11 章の AKS 素数判定法）が、実用上は高速なモンテカルロ法であるミラー-ラビン素数判定法が使われている。

奇数 \(n\) について、\(n - 1 = d \cdot 2^s\)（\(d\) は奇数）と分解する。\(n\) が素数ならば、フェルマーの小定理と「\(x^2 \equiv 1 \pmod n\) の解は \(x \equiv \pm 1\) だけ」という性質から、\(n\) と互いに素な任意の \(a\) について、次のどちらかが成り立つ。

  • \(a^d \equiv 1 \pmod n\)

  • ある \(0 \le r < s\) について \(a^{d \cdot 2^r} \equiv -1 \pmod n\)

どちらも成り立たない \(a\) が見つかれば、\(n\) は合成数であると確定する。このような \(a\) を合成数であることの証拠（witness）と呼ぶ。第 11 章の証拠と同様に、これがあれば「合成数である」という答えを効率よく確かめられる。\(n\) が 9 より大きい奇数の合成数ならば、\(2 \le a \le n - 2\) のうち少なくとも 3/4 が証拠になることが証明されている。そこで \(a\) を無作為に選んで調べることを繰り返し、証拠が見つからなければ「素数である」と答える。

\(a^d \bmod n\) は、第 6 章の繰り返し二乗法により \(O(\log d)\) 回の乗算で計算できる。Python では組み込み関数 pow(a, d, n) がこの計算を行う。

17def is_probable_prime(n: int, rounds: int = 20) -> bool:
18    """n が素数らしければ True、合成数と確定すれば False を返す。"""
19    if n < 2:
20        return False
21    for p in (2, 3, 5, 7, 11, 13):
22        if n % p == 0:
23            return n == p
24    d, s = n - 1, 0
25    while d % 2 == 0:  # n - 1 = d * 2^s (d は奇数) と分解する
26        d //= 2
27        s += 1
28    for _ in range(rounds):
29        a = random.randrange(2, n - 1)
30        x = pow(a, d, n)
31        if x in (1, n - 1):
32            continue
33        for _ in range(s - 1):
34            x = x * x % n
35            if x == n - 1:
36                break
37        else:
38            return False  # a は n が合成数であることの証拠
39    return True

42def is_prime_trial_division(n: int) -> bool:
43    """試し割りによる確定的な判定 (比較用)。O(√n) 回の割り算を行う。"""
44    if n < 2:
45        return False
46    i = 2
47    while i * i <= n:
48        if n % i == 0:
49            return False
50        i += 1
51    return True

SAT ソルバ

SAT は NP 完全だが、実用上の SAT の問題は、変数が数百万個あっても解けることが多い。現代の SAT ソルバは、ハードウェアやソフトウェアの検証、スケジューリング、パズルの求解など、幅広い分野で使われている。NP 完全な問題は互いに多項式時間で還元できるので、多くの問題は SAT に変換して SAT ソルバで解くことができる。

DPLL アルゴリズム

SAT ソルバの基礎となるのが DPLL アルゴリズム（Davis-Putnam-Logemann-Loveland アルゴリズム）である。DPLL アルゴリズムは変数の値を 1 つずつ決めていくバックトラッキング（第 6 章）だが、次の 2 つの規則で探索を大幅に減らす。

  • 単位伝播：リテラルが 1 つしか残っていない節（単位節）があれば、そのリテラルを真にするしかない。値を決めると他の節が単位節になり、連鎖的に値が決まることが多い。

  • 純リテラル除去：ある変数が肯定（\(x_i\)）か否定（\(\neg x_i\)）の一方でしか現れないなら、そのリテラルを真にしても充足可能性は変わらない。

この 2 つの規則を適用できなくなったら、変数を 1 つ選んで真と偽の両方を試す（分岐）。

 3総当たりと同じく変数の値を順に決めていくが、次の 2 つの規則で探索を減らす。

21CNF = list[list[int]]

24def simplify(cnf: CNF, literal: int) -> CNF | None:
25    """literal を真としたときの式を返す。空の節ができたら None (矛盾)。"""
26    result: CNF = []
27    for clause in cnf:
28        if literal in clause:
29            continue  # 節が真になったので取り除く
30        reduced = [lit for lit in clause if lit != -literal]
31        if not reduced:
32            return None
33        result.append(reduced)
34    return result
35
36
37def dpll(cnf: CNF, assignment: dict[int, bool] | None = None
38         ) -> dict[int, bool] | None:
39    """式を満たす割り当てを返す。充足不能なら None を返す。"""
40    assignment = dict(assignment or {})
41    while True:  # 単位伝播と純リテラル除去を、適用できなくなるまで繰り返す
42        unit = next((c[0] for c in cnf if len(c) == 1), None)
43        if unit is None:
44            literals = {lit for clause in cnf for lit in clause}
45            unit = next((lit for lit in literals if -lit not in literals),
46                        None)
47        if unit is None:
48            break
49        assignment[abs(unit)] = unit > 0
50        simplified = simplify(cnf, unit)
51        if simplified is None:
52            return None
53        cnf = simplified
54    if not cnf:
55        return assignment  # 全ての節が満たされた
56    literal = cnf[0][0]  # 分岐: まず真を試し、だめなら偽を試す
57    for choice in (literal, -literal):
58        simplified = simplify(cnf, choice)
59        if simplified is not None:
60            result = dpll(simplified, {**assignment, abs(choice): choice > 0})
61            if result is not None:
62                return result
63    return None
64

66def pigeonhole(n: int) -> CNF:
67    """n + 1 羽の鳩を n 個の巣に 1 羽ずつ入れる問題 (常に充足不能)。
68
69    変数 p(i, j) は「鳩 i が巣 j に入る」ことを表す。
70    """
71    def var(i: int, j: int) -> int:
72        return i * n + j + 1
73
74    cnf: CNF = [[var(i, j) for j in range(n)] for i in range(n + 1)]
75    for j in range(n):
76        for i in range(n + 1):
77            for k in range(i + 1, n + 1):
78                cnf.append([-var(i, j), -var(k, j)])
79    return cnf
80

83    print("充足可能な例:", dpll([[1, -2], [2, 3], [-1, -3]]))
84    for n in range(1, 9):

87        elapsed = time.perf_counter() - start

現代の SAT ソルバ

現代の SAT ソルバは、DPLL アルゴリズムに次のような改良を加えた CDCL（Conflict-Driven Clause Learning）と呼ばれる方式を採用している。

  • 節学習：矛盾が起きたとき、その原因を分析して新しい節として式に追加し、同じ原因の矛盾を二度と起こさないようにする。

  • 非時系列バックトラック：矛盾の原因となった分岐まで一気に戻る。

  • 変数の選び方の工夫、探索の定期的なやり直し（リスタート）、効率的なデータ構造など。

Python からは、PySAT などのライブラリを通じて既存の SAT ソルバを利用できる。また、整数計画ソルバや制約プログラミングのソルバも、NP 困難な最適化問題に対する実用的な選択肢である。

章末のまとめ

  • 近似アルゴリズムは、最適解との差を保証しつつ多項式時間で解を求める。頂点被覆や三角不等式を満たす TSP には 2 近似アルゴリズムがある。

  • 局所探索は保証のない方法だが、実用上はよい解を得られることが多い。

  • 乱択アルゴリズムは乱数を使って単純かつ高速に問題を解く。ミラー-ラビン素数判定法は、誤り確率を指数的に小さくできるモンテカルロ法である。

  • SAT ソルバは、指数時間の探索を工夫によって実用的な速さにしたものであり、NP に属する多くの問題（NP 完全問題を含む）を SAT に還元して解くことができる。

本書のまとめ

本書では、第 2 部で問題を効率よく解くための道具（データ構造、整列、設計技法、グラフアルゴリズム）を学び、第 3 部でその限界（計算可能性と計算複雑性）を学んだ。新しい問題に出会ったときは、次の順に考えるとよい。

  1. 既知の効率的なアルゴリズムで解ける問題に帰着できないか（第 2 部）。

  2. 帰着できなければ、問題は NP 困難ではないか。既知の NP 完全問題から還元できないか（第 11 章）。

  3. NP 困難であれば、近似、ヒューリスティクス、SAT ソルバなどの対処法を検討する（本章）。

  4. 問題がプログラムの振る舞いに関するものであれば、そもそも決定不能ではないか（第 10 章）。
