第 5 章 探索と整列

データの中から目的の値を見つける探索と、データを順序どおりに並べ替える整列（ソート）は、最も基本的な計算である。整列済みのデータに対しては探索が速くなるため、両者は密接に関係している。本章では代表的なアルゴリズムを紹介し、「比較だけを使う整列は \(\Omega(n \log n)\) 時間より速くできない」という下界を証明する。

本章のアルゴリズムは全て次のサンプルコードに含まれている。

ch05_sorting.py

線形探索と二分探索

線形探索は、リストの要素を先頭から順に調べる方法であり、最悪 \(O(n)\) 時間かかる。Python の x in a（a が list の場合）は線形探索である。

リストが整列済みであれば、二分探索により \(O(\log n)\) 時間で探索できる。探索範囲の中央の要素と目的の値を比べ、目的の値が中央より小さければ左半分、大きければ右半分に範囲を絞ることを繰り返す。1 回の比較で範囲が半分になるので、比較の回数は約 \(\log_2 n\) 回である。

リスト 3 二分探索（ch05_sorting.py より）
 1def binary_search(values: list[int], target: int) -> int:
 2    """整列済みの values から target の位置を探す。無ければ -1 を返す。"""
 3    lo, hi = 0, len(values)  # 探す範囲は values[lo:hi]
 4    while lo < hi:
 5        mid = (lo + hi) // 2
 6        if values[mid] == target:
 7            return mid
 8        if values[mid] < target:
 9            lo = mid + 1
10        else:
11            hi = mid
12    return -1

二分探索は単純だが、範囲の端の扱いを誤りやすい。このコードでは探索範囲を半開区間 values[lo:hi] として扱い、ループの間「目的の値があるとすれば values[lo:hi] の中にある」という性質（ループ不変条件）が保たれるように lo と hi を更新している。ループ不変条件を明確にすることは、ループを含むアルゴリズムの正しさを示す基本的な方法である。

Python の標準ライブラリでは、bisect.bisect_left などが二分探索を提供している。

単純な整列：挿入ソート

挿入ソートは、先頭から順に、要素をそれより前の整列済みの部分の適切な位置に挿入していく方法である。トランプの手札を並べるときの方法に近い。

リスト 4 挿入ソート（ch05_sorting.py より）
 1def insertion_sort(values: list[int]) -> list[int]:
 2    """挿入ソート。最悪 O(n^2)、ほぼ整列済みの入力には速い。"""
 3    a = list(values)
 4    for i in range(1, len(a)):
 5        key = a[i]
 6        j = i - 1
 7        while j >= 0 and a[j] > key:
 8            a[j + 1] = a[j]
 9            j -= 1
10        a[j + 1] = key
11    return a

逆順に並んだ入力では、\(i\) 番目の要素を挿入するのに \(i\) 回の比較と移動が必要になり、合計 \(1 + 2 + \cdots + (n - 1) = \Theta(n^2)\) 時間かかる。一方、ほぼ整列済みの入力では、各要素の移動が少ないので \(O(n)\) に近い時間で終わる。この性質から、挿入ソートは要素数の少ない部分の整列に使われることがある。Python の sorted が採用している Timsort も、短い区間の整列に挿入ソートを利用している。

分割統治による整列：マージソート

マージソートは、リストを半分に分けてそれぞれを再帰的に整列し、整列済みの 2 つのリストを併合（マージ）する方法である。このように問題を小さな部分問題に分けて解き、その結果を組み合わせる方法を分割統治法と呼ぶ（第 6 章で詳しく扱う）。

リスト 5 マージソート（ch05_sorting.py より）
 1def merge_sort(values: list[int]) -> list[int]:
 2    """マージソート。常に O(n log n)、安定。"""
 3    if len(values) <= 1:
 4        return list(values)
 5    mid = len(values) // 2
 6    left = merge_sort(values[:mid])
 7    right = merge_sort(values[mid:])
 8    merged: list[int] = []
 9    i = j = 0
10    while i < len(left) and j < len(right):
11        if left[i] <= right[j]:  # <= にすることで安定になる
12            merged.append(left[i])
13            i += 1
14        else:
15            merged.append(right[j])
16            j += 1
17    merged.extend(left[i:])
18    merged.extend(right[j:])
19    return merged

整列済みの 2 つのリストの併合は、それぞれの先頭の小さい方を取り出すことを繰り返せばよく、\(O(n)\) 時間で行える。したがって計算量は漸化式 \(T(n) = 2T(n/2) + \Theta(n)\) を満たし、第 3 章で見たとおり \(T(n) = \Theta(n \log n)\) である。この計算量は入力の内容によらない。一方、併合のために \(O(n)\) の追加の領域が必要になる。

等しいキーを持つ要素の相対的な順序が整列の前後で変わらないとき、その整列を安定であるという。マージソートは、併合のときに左側の要素を優先する（11 行目の <=）ことで安定になる。安定な整列を使うと、「まず第 2 キーで整列し、次に第 1 キーで整列する」という方法で複数のキーによる整列が実現できる。

平均的に速い整列：クイックソート

クイックソートは、ピボットと呼ぶ要素を 1 つ選び、ピボットより小さい要素を左に、それ以外を右に集めてから（分割）、左右をそれぞれ再帰的に整列する方法である。

リスト 6 乱択クイックソート（ch05_sorting.py より）
 1def quick_sort(values: list[int]) -> list[int]:
 2    """乱択クイックソート。期待 O(n log n)、最悪 O(n^2)。"""
 3    a = list(values)
 4
 5    def sort(lo: int, hi: int) -> None:  # a[lo:hi + 1] を整列する
 6        if lo >= hi:
 7            return
 8        p = random.randint(lo, hi)  # ピボットを無作為に選ぶ
 9        a[p], a[hi] = a[hi], a[p]
10        pivot = a[hi]
11        i = lo
12        for j in range(lo, hi):  # pivot 未満の要素を左側に集める
13            if a[j] < pivot:
14                a[i], a[j] = a[j], a[i]
15                i += 1
16        a[i], a[hi] = a[hi], a[i]
17        sort(lo, i - 1)
18        sort(i + 1, hi)
19
20    sort(0, len(a) - 1)
21    return a

分割によってリストがほぼ半分ずつに分かれれば、計算量はマージソートと同じ \(\Theta(n \log n)\) になる。しかし、ピボットとして常に最小値や最大値を選んでしまうと、分割のたびに要素が 1 つしか減らず、計算量は \(\Theta(n^2)\) になる。例えば「常に末尾の要素をピボットにする」という規則では、整列済みの入力がこの最悪の場合に当たる。

このコードではピボットを無作為に選んでいる（8 行目）。こうすると、どんな入力に対しても、比較の回数の期待値は \(O(n \log n)\) になる。ここでの期待値は入力についてではなく、アルゴリズムが使う乱数についてとったものである。したがって、特定の入力で必ず遅くなるということはない。このように乱数を使うアルゴリズムを乱択アルゴリズムと呼び、第 12 章で再び扱う。

クイックソートは、追加の領域が再帰呼び出しのスタック分（期待 \(O(\log n)\)）で済み、内側のループが単純であるため、実用上は非常に速い。ただし安定ではない。

最悪でも速い整列：ヒープソート

ヒープソートは、第 4 章の二分ヒープを使った整列である。まずリスト全体を最大ヒープに変換し、根（最大値）を末尾の要素と交換してヒープの範囲を 1 つ縮める操作を繰り返す。

リスト 7 ヒープソート（ch05_sorting.py より）
 1def heap_sort(values: list[int]) -> list[int]:
 2    """ヒープソート。常に O(n log n)、追加の領域は O(1)。"""
 3    a = list(values)
 4    n = len(a)
 5
 6    def sift_down(root: int, end: int) -> None:  # a[:end] の範囲で調整
 7        while 2 * root + 1 < end:
 8            child = 2 * root + 1
 9            if child + 1 < end and a[child + 1] > a[child]:
10                child += 1
11            if a[root] >= a[child]:
12                return
13            a[root], a[child] = a[child], a[root]
14            root = child
15
16    for i in range(n // 2 - 1, -1, -1):  # 最大ヒープを作る
17        sift_down(i, n)
18    for end in range(n - 1, 0, -1):  # 最大値を末尾へ移していく
19        a[0], a[end] = a[end], a[0]
20        sift_down(0, end)
21    return a

最大ヒープの構築は、葉に近いノードから順に sift_down を行うことで \(O(n)\) 時間で行える。その後の \(n - 1\) 回の取り出しはそれぞれ \(O(\log n)\) なので、全体の計算量は最悪でも \(O(n \log n)\) である。追加の領域は \(O(1)\) で済むが、安定ではない。

比較ソートの下界

ここまでの整列アルゴリズムは、要素どうしの比較（< や <=）の結果だけを使って要素の順序を決めている。このような整列を比較ソートと呼ぶ。比較ソートは、どのように工夫しても最悪 \(\Omega(n \log n)\) 回の比較が必要である。

定理：任意の比較ソートは、要素数 \(n\) の入力に対して、最悪の場合に \(\Omega(n \log n)\) 回の比較を行う。

証明：相異なる \(n\) 個の要素の並べ方は \(n!\) 通りあり、比較ソートはその全てを区別して正しく並べ替えなければならない。比較ソートの動作を、各内部ノードが 1 回の比較を、各葉が最終的な並べ替え方を表す二分木（決定木）として表す。入力ごとに比較の結果が決まり、根から葉への 1 本の経路が定まる。異なる並べ方の入力には異なる並べ替えを施す必要があるので、決定木は少なくとも \(n!\) 枚の葉を持つ。高さ \(h\) の二分木の葉は高々 \(2^h\) 枚なので、\(2^h \ge n!\) すなわち \(h \ge \log n!\) である。最悪の場合の比較の回数は \(h\) に等しく、第 2 章で述べたように \(\log n! = \Theta(n \log n)\) なので、\(h = \Omega(n \log n)\) となる。

この定理から、マージソートとヒープソートは比較ソートとして漸近的に最適である。このように「どんなアルゴリズムでもこれ以上速くはできない」という下界を示すことは、計算理論の重要な目標の 1 つであり、第 11 章の議論につながる。

比較を使わない整列

要素が小さな範囲の整数であるなど、比較以外の情報を使えるときは、\(O(n \log n)\) より速く整列できる。

計数ソートは、\(0\) 以上 \(k\) 以下の整数を整列する方法である。各値が何回現れるかを数えてから、小さい値から順に、数えた回数だけ並べる。計算量は \(O(n + k)\) である。

リスト 8 計数ソート（ch05_sorting.py より）
1def counting_sort(values: list[int], max_value: int) -> list[int]:
2    """計数ソート。0 以上 max_value 以下の整数を O(n + max_value) で整列。"""
3    counts = [0] * (max_value + 1)
4    for v in values:
5        counts[v] += 1
6    result: list[int] = []
7    for v, c in enumerate(counts):
8        result.extend([v] * c)
9    return result

基数ソートは、整数を下の桁から 1 桁ずつ見て、その桁の値で安定に振り分けることを繰り返す方法である。各段階が安定なので、上の桁の振り分けが終わった時点で、下の桁の順序も正しく保たれている。\(d\) 桁の整数を基数 \(b\) で扱うと、計算量は \(O(d(n + b))\) になる。

リスト 9 基数ソート（ch05_sorting.py より）
 1def radix_sort(values: list[int], base: int = 10) -> list[int]:
 2    """基数ソート (LSD)。0 以上の整数を下の桁から安定に振り分ける。"""
 3    a = list(values)
 4    if not a:
 5        return a
 6    place = 1
 7    while place <= max(a):
 8        buckets: list[list[int]] = [[] for _ in range(base)]
 9        for v in a:
10            buckets[(v // place) % base].append(v)
11        a = [v for bucket in buckets for v in bucket]
12        place *= base
13    return a

これらの方法は比較ソートの下界に矛盾しない。下界は「比較だけを使う」アルゴリズムについての主張であり、計数ソートや基数ソートは要素の値そのものを配列の添字として使っているからである。
