第 9 章 文脈自由文法とプッシュダウンオートマトン

第 8 章で見たように、有限オートマトンは \(\{0^n 1^n\}\) や対応のとれた括弧の列のような入れ子構造を扱えない。本章では、入れ子構造を表現できる文脈自由文法と、それに対応する計算モデルであるプッシュダウンオートマトンを扱う。文脈自由文法は、プログラミング言語の構文の定義や、コンパイラの構文解析の理論的な基礎になっている。

文脈自由文法

文脈自由文法（CFG: Context-Free Grammar）は、次の 4 つ組 \(G = (V, \Sigma, R, S)\) で定義される。

  • \(V\)：変数（非終端記号）の有限集合

  • \(\Sigma\)：終端記号の有限集合（\(V\) と共通部分を持たない）

  • \(R\)：生成規則の有限集合。各規則は \(A \to \alpha\) の形をしており、\(A \in V\)、\(\alpha\) は変数と終端記号からなる文字列（空列でもよい）である。

  • \(S \in V\)：開始記号

開始記号から始めて、文字列中の変数を、その変数を左辺に持つ生成規則の右辺で置き換えることを繰り返す。この過程を導出と呼ぶ。終端記号だけからなる文字列が得られたら導出は終わる。文法 \(G\) から導出できる終端記号の文字列全体を \(G\) が生成する言語と呼び、\(L(G)\) で表す。文脈自由文法で生成できる言語を文脈自由言語と呼ぶ。

「文脈自由」という名前は、変数を置き換えるときに、その変数の前後に何があるか（文脈）に関係なく規則を適用できることに由来する。

例

次の文法は \(\{0^n 1^n \mid n \ge 0\}\) を生成する。複数の規則の右辺を | でまとめて書いている。

\[S \to 0 S 1 \mid \varepsilon\]

例えば \(S \Rightarrow 0S1 \Rightarrow 00S11 \Rightarrow 0011\) と導出できる。規則 \(S \to 0S1\) が、\(0\) と \(1\) を対にして内側に入れ子を作っていく様子を表している。

対応のとれた括弧の列は、次の文法で生成できる。

\[S \to (S) \mid SS \mid \varepsilon\]

構文木と曖昧性

導出の過程は、開始記号を根とし、各変数のノードの子を適用した規則の右辺の記号とする木で表せる。この木を構文木（導出木）と呼ぶ。コンパイラは、ソースコードから構文木（を簡略化した抽象構文木）を作り、それをもとに意味の解析やコード生成を行う。

ある文字列に対して構文木が 2 通り以上存在するとき、その文法は曖昧であるという。例えば四則演算の式を次の文法で表すと、

\[E \to E + E \mid E * E \mid (E) \mid \mathit{num}\]

1 + 2 * 3 には「(1 + 2) * 3」と「1 + (2 * 3)」に対応する 2 つの構文木があり、計算結果が変わってしまう。曖昧さをなくすには、演算子の優先順位ごとに変数を分けた次の文法を使う。

\[\begin{split}E &\to E + T \mid T \\ T &\to T * F \mid F \\ F &\to (E) \mid \mathit{num}\end{split}\]

この文法では * が + より深い位置（構文木の葉に近い位置）でしか生成されないため、* が先に結合する。また \(E \to E + T\) のように左側で再帰しているため、1 + 2 + 3 のような式は (1 + 2) + 3 として左から結合する。減算や除算を加える場合も、\(E \to E - T\) のように左再帰の規則を加えれば、10 - 4 - 3 が (10 - 4) - 3 と解釈される。

チョムスキー標準形

文脈自由文法の全ての生成規則が、次のいずれかの形であるとき、その文法はチョムスキー標準形であるという。

  • \(A \to BC\)（\(B\)、\(C\) は変数）

  • \(A \to a\)（\(a\) は終端記号）

  • \(S \to \varepsilon\)（\(S\) は開始記号。言語が空列を含む場合に限り、このとき \(S\) はどの規則の右辺にも現れないものとする）

任意の文脈自由文法は、同じ言語を生成するチョムスキー標準形の文法に変換できる。変換は、空列を生成する規則の除去、\(A \to B\) の形の規則の除去、長さ 2 以上の右辺に含まれる終端記号の新しい変数への置き換え、右辺の長い規則の分割、という手順で機械的に行える。チョムスキー標準形では、長さ \(n \ge 1\) の文字列の導出はちょうど \(2n - 1\) 回の規則の適用からなり、構文木は二分木になる。この性質は、後で述べる CYK 法で利用する。

例えば \(\{0^n 1^n \mid n \ge 1\}\)（\(n \ge 1\) に限る）は、記号を \(a\)、\(b\) に替えて書くと、次のチョムスキー標準形の文法で生成できる。

\[\begin{split}S &\to AB \mid AC \\ C &\to SB \\ A &\to a \\ B &\to b\end{split}\]

プッシュダウンオートマトン

プッシュダウンオートマトン（PDA: Pushdown Automaton）は、NFA に 1 本のスタックを加えた計算モデルである。各ステップで、現在の状態、読んだ入力記号（または空列）、スタックの先頭の記号に応じて、次の状態に移り、スタックの先頭を別の記号列に置き換える（プッシュやポップを行う）。スタックの大きさに上限はないので、有限オートマトンと異なり、際限なく情報を蓄えられる。ただし、取り出せるのはスタックの先頭だけである。

例えば \(\{0^n 1^n \mid n \ge 0\}\) は、次のように動く PDA で認識できる。

  1. \(0\) を読むたびに、スタックに記号をプッシュする。

  2. \(1\) を読むたびに、スタックから記号を 1 つポップする。スタックが空ならば拒否する。また、\(1\) を読んだ後に \(0\) が来たら拒否する。

  3. 入力を読み終えたときにスタックが空なら受理する。

定理：言語が文脈自由言語であることと、ある PDA で認識できることは同値である。

文脈自由文法から PDA を作るには、スタック上で導出を模倣すればよい。スタックの先頭が変数なら生成規則を非決定的に選んで右辺に置き換え、終端記号なら入力の記号と照合してポップする。

なお、有限オートマトンと異なり、PDA では非決定性が本質的な意味を持つ。決定性の PDA で認識できる言語は、文脈自由言語全体より真に狭い。例えば偶数長の回文の言語 \(\{w w^R \mid w \in \{0, 1\}^*\}\)（\(w^R\) は \(w\) の逆順）は、文字列の中央がどこかを推測する必要があるため、決定性の PDA では認識できない。プログラミング言語の文法の多くは、決定性の PDA で効率よく解析できるように設計されている。

文脈自由言語の性質

文脈自由言語は、和集合、連接、スター閉包について閉じている。しかし正規言語と異なり、共通部分と補集合については閉じていない。

文脈自由言語にもポンピング補題がある。

補題（文脈自由言語のポンピング補題）：\(L\) が文脈自由言語ならば、ある正の整数 \(p\) が存在して、長さが \(p\) 以上の任意の \(w \in L\) は、次の 3 条件を満たすように \(w = uvxyz\) と分割できる。

  1. 全ての \(i \ge 0\) について \(u v^i x y^i z \in L\)

  2. \(|vy| \ge 1\)

  3. \(|vxy| \le p\)

証明の考え方は、正規言語の場合と同様である。十分長い文字列の構文木は十分高くなり、根から葉への経路上に同じ変数が 2 回現れる。その変数を根とする部分木を繰り返したり取り除いたりすることで、\(v\) と \(y\) を同時に増減できる。

例：\(\{a^n b^n c^n \mid n \ge 0\}\) は文脈自由言語ではない。\(w = a^p b^p c^p\) を考えると、条件 3 より \(vxy\) の長さは \(p\) 以下なので、\(vxy\) は \(a\)、\(b\)、\(c\) の 3 種類全てを含むことはできない。したがって \(uv^2xy^2z\) では、増えない種類の記号が少なくとも 1 つあり、3 種類の記号の個数が等しくなくなる。

この言語は文脈自由言語 \(\{a^n b^n c^m\}\) と \(\{a^m b^n c^n\}\) の共通部分なので、文脈自由言語が共通部分について閉じていないことも分かる。

構文解析

文字列が文法から導出できるかを判定し、構文木を作る処理を構文解析と呼ぶ。

CYK 法

CYK 法（Cocke-Younger-Kasami 法）は、チョムスキー標準形の文法について、任意の文字列の構文解析を行う動的計画法である。長さ \(n\) の文字列 \(w\) について、部分問題を次のように定義する。

  • \(T[i][\ell]\)：\(w\) の位置 \(i\) から始まる長さ \(\ell\) の部分文字列を導出できる変数の集合

長さ 1 の部分文字列については、\(A \to a\) の形の規則から求まる。長さ \(\ell \ge 2\) の部分文字列については、チョムスキー標準形では最初の規則が必ず \(A \to BC\) の形なので、部分文字列を 2 つに分ける位置を全て試し、左側を \(B\) が、右側を \(C\) が導出できれば \(A\) を加える。最後に、文字列全体を導出できる変数の集合 \(T[0][n]\) に開始記号が含まれていれば \(w \in L(G)\) である。計算量は \(O(n^3 |G|)\) である（\(|G|\) は文法の大きさ）。

ch09_cyk.py

リスト 19 ch09_cyk.py
 1"""第 9 章: CYK 法による文脈自由言語の所属判定。
 2
 3チョムスキー標準形の文法 G と文字列 w が与えられたとき、w が G から
 4導出できるかを動的計画法で O(n^3 |G|) 時間で判定する。
 5
 6例として、言語 { a^n b^n | n >= 1 } を生成する次の文法を使う。
 7
 8    S -> A B | A C
 9    C -> S B
10    A -> a
11    B -> b
12
13実行例::
14
15    python ch09_cyk.py
16"""
17
18from __future__ import annotations
19
20# 生成規則: 左辺 -> 右辺の候補のリスト。右辺は (変数, 変数) か (終端記号,)。
21Grammar = dict[str, list[tuple[str, ...]]]
22
23AN_BN: Grammar = {
24    "S": [("A", "B"), ("A", "C")],
25    "C": [("S", "B")],
26    "A": [("a",)],
27    "B": [("b",)],
28}
29
30
31def cyk(grammar: Grammar, start: str, word: str) -> bool:
32    """word が start 記号から導出できれば True を返す。"""
33    n = len(word)
34    if n == 0:
35        return False  # この実装では空列を生成する規則を扱わない
36    # table[i][j]: 部分文字列 word[i:i + j + 1] を導出できる変数の集合
37    table: list[list[set[str]]] = [[set() for _ in range(n)] for _ in range(n)]
38    for i, ch in enumerate(word):
39        for head, bodies in grammar.items():
40            if (ch,) in bodies:
41                table[i][0].add(head)
42    for length in range(2, n + 1):  # 部分文字列の長さ
43        for i in range(n - length + 1):  # 開始位置
44            for split in range(1, length):  # 左側の長さ
45                left = table[i][split - 1]
46                right = table[i + split][length - split - 1]
47                for head, bodies in grammar.items():
48                    for body in bodies:
49                        if (len(body) == 2 and body[0] in left
50                                and body[1] in right):
51                            table[i][length - 1].add(head)
52    return start in table[0][n - 1]
53
54
55def main() -> None:
56    for word in ["ab", "aabb", "aaabbb", "aab", "abab", "ba"]:
57        result = "受理" if cyk(AN_BN, "S", word) else "拒否"
58        print(f"{word:>6}: {result}")
59
60
61if __name__ == "__main__":
62    main()

サンプルコードでは、添字を 0 から始めるために table[i][length - 1] に長さ length の部分文字列の結果を格納している。

再帰下降構文解析

CYK 法は任意の文脈自由文法を扱えるが、\(O(n^3)\) 時間はプログラムのソースコードのような長い入力には遅すぎる。実際のコンパイラでは、文法に制限を加えて \(O(n)\) 時間で解析できるようにしている。

その代表的な方法が再帰下降構文解析である。文法の各変数に対応する関数を用意し、関数の中で生成規則の右辺に従って、終端記号なら入力と照合し、変数なら対応する関数を呼び出す。入力の次のトークンを 1 つ見るだけで適用する規則が決まるように文法を設計しておけば、バックトラッキングなしで解析できる。このような文法を LL(1) 文法と呼ぶ。

再帰下降構文解析では、\(E \to E + T\) のような左再帰の規則をそのまま関数にすると、expr が自分自身を無限に呼び出してしまう。そこで、この規則を同じ言語を表す繰り返しの形 \(E \to T\,(\,+\,T\,)^*\) に書き換えて、ループで実装する。次のサンプルコードは、四則演算の式を解析して値を計算する電卓である。

 17import re

 21
 22def tokenize(text: str) -> list[str]:
 23    """文字列を数値と記号のトークンに分ける。"""
 24    tokens: list[str] = []
 25    for number, symbol in TOKEN_PATTERN.findall(text):
 26        if number:
 27            tokens.append(number)
 28        elif symbol.strip():
 29            tokens.append(symbol)
 30    return tokens
 31
 32
 33class Parser:
 34    """トークン列を左から読み、式の値を計算する。"""
 35
 36    def __init__(self, text: str) -> None:
 37        self.tokens = tokenize(text)
 38        self.pos = 0
 39
 40    def peek(self) -> str | None:
 41        """次のトークンを返す (読み進めない)。"""
 42        return self.tokens[self.pos] if self.pos < len(self.tokens) else None
 43
 44    def take(self) -> str:
 45        """次のトークンを読み進めて返す。"""
 46        token = self.peek()
 47        if token is None:
 48            raise SyntaxError("式が途中で終わっている")
 49        self.pos += 1
 50        return token
 51
 52    def parse(self) -> float:
 53        """式全体を解析して値を返す。"""
 54        value = self.expr()
 55        if self.peek() is not None:
 56            raise SyntaxError(f"余分なトークン: {self.peek()}")
 57        return value
 58
 59    def expr(self) -> float:
 60        value = self.term()
 61        while self.peek() in ("+", "-"):
 62            if self.take() == "+":
 63                value += self.term()
 64            else:
 65                value -= self.term()
 66        return value
 67
 68    def term(self) -> float:
 69        value = self.factor()
 70        while self.peek() in ("*", "/"):
 71            if self.take() == "*":
 72                value *= self.factor()
 73            else:
 74                value /= self.factor()
 75        return value
 76
 77    def factor(self) -> float:
 78        token = self.take()
 79        if token == "(":
 80            value = self.expr()
 81            if self.take() != ")":
 82                raise SyntaxError("')' が必要")
 83            return value
 84        if token == "-":
 85            return -self.factor()
 86        try:
 87            return float(token)
 88        except ValueError:
 89            raise SyntaxError(f"予期しないトークン: {token}") from None
 90
 91
 92def main() -> None:
 93    for text in ["1 + 2 * 3", "(1 + 2) * 3", "10 - 4 - 3", "2 * -(3 + 4)",
 94                 "8 / 4 / 2", "1 + * 2"]:
 95        try:
 96            print(f"{text} = {Parser(text).parse()}")
 97        except SyntaxError as error:
 98            print(f"{text}: 構文エラー ({error})")
 99
100
101if __name__ == "__main__":
102    main()

実行結果は次のとおりである。1 + 2 * 3 では乗算が先に、10 - 4 - 3 では左側の減算が先に計算されている。

11 + 2 * 3 = 7.0
2(1 + 2) * 3 = 9.0
310 - 4 - 3 = 3.0
42 * -(3 + 4) = -14.0
58 / 4 / 2 = 1.0
61 + * 2: 構文エラー (予期しないトークン: *)

関数の呼び出しは、内部的には呼び出しスタックで管理されている。再帰下降構文解析は、PDA のスタックを Python の呼び出しスタックで実現していると見ることができる。

章末のまとめ

  • 文脈自由文法は入れ子構造を表現でき、プログラミング言語の構文の定義に使われる。

  • 文脈自由言語は、PDA（NFA にスタックを加えた計算モデル）で認識できる言語と一致する。

  • \(\{a^n b^n c^n\}\) のように、文脈自由言語でない言語もある。

  • CYK 法は任意の文脈自由文法の構文解析を \(O(n^3)\) 時間で行う。実際のコンパイラは、制限した文法を再帰下降構文解析などで線形時間で解析する。
