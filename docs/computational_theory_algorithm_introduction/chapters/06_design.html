第 6 章 アルゴリズム設計技法

新しい問題に出会ったとき、アルゴリズムを一から考えるのは難しい。しかし多くのアルゴリズムは、少数の典型的な考え方の組み合わせで作られている。本章では、分割統治法、貪欲法、動的計画法、バックトラッキングという 4 つの設計技法を紹介する。

分割統治法

分割統治法は、問題を同じ形の小さな部分問題に分割し、部分問題を再帰的に解いて、その結果を統合する技法である。第 5 章のマージソートとクイックソートはその典型例であり、計算量は第 3 章の漸化式とマスター定理で解析できる。

もう 1 つの例として、\(x^n\) を計算する問題を考える。素朴に \(x\) を \(n\) 個掛け合わせると \(n - 1\) 回の乗算が必要だが、\(x^n = (x^{n/2})^2\)（\(n\) が偶数のとき）を利用すると、問題のサイズを半分にできる。

1def power(x: int, n: int) -> int:
2    """x の n 乗を O(log n) 回の乗算で求める。"""
3    if n == 0:
4        return 1
5    half = power(x, n // 2)
6    if n % 2 == 0:
7        return half * half
8    return half * half * x

乗算の回数は漸化式 \(T(n) = T(n/2) + O(1)\) を満たし、\(O(\log n)\) 回で済む。この方法は繰り返し二乗法と呼ばれ、第 12 章のミラー-ラビン素数判定法で使う Python の組み込み関数 pow(a, d, n) の内部でも使われている。

分割統治法が有効なのは、部分問題が互いに独立しており、統合が効率よく行える場合である。部分問題が重なり合っている場合は、次に述べる動的計画法を検討する。

貪欲法

貪欲法は、解を少しずつ組み立てる際に、各段階でその時点で最もよく見える選択を行い、その選択を後から取り消さない技法である。実装が簡単で高速だが、常に最適解が得られるとは限らない。貪欲法を使うときは、それが最適解を与えることを証明する必要がある。

区間スケジューリング

会議室の利用申請が複数あり、各申請は開始時刻と終了時刻を持つ。時間が重ならないように、できるだけ多くの申請を受け付けたい。この問題を区間スケジューリング問題と呼ぶ。

「開始時刻が早い順」「長さが短い順」に選ぶ貪欲法は、反例があり最適ではない。例えば開始時刻が早い順では、最初に非常に長い区間を選んでしまうと他の区間を全く選べなくなる。正しいのは「終了時刻が早い順に、既に選んだ区間と重ならないものを選ぶ」という貪欲法である。

証明：貪欲法が選んだ区間を終了時刻の順に \(g_1, g_2, \ldots, g_k\)、ある最適解の区間を終了時刻の順に \(o_1, o_2, \ldots, o_m\) とする（\(k \le m\)）。帰納法により、全ての \(i \le k\) について「\(g_i\) の終了時刻は \(o_i\) の終了時刻以下」であることを示す。\(i = 1\) では、\(g_1\) は全区間の中で終了時刻が最も早いので成り立つ。\(i - 1\) で成り立つとすると、\(o_i\) は \(o_{i-1}\) の終了後に始まるので、\(g_{i-1}\) の終了後にも始まる。したがって \(o_i\) は貪欲法が \(i\) 番目を選ぶときの候補に含まれており、貪欲法はその中で終了時刻が最も早いものを選ぶので、\(g_i\) の終了時刻は \(o_i\) の終了時刻以下になる。最後に、\(k < m\) と仮定すると、\(o_{k+1}\) は \(g_k\) の終了後に始まるので貪欲法はまだ区間を選べたことになり、矛盾する。よって \(k = m\) である。

このように、貪欲法の解が最適解に「常に遅れをとらない」ことを示す論法や、最適解の一部を貪欲法の選択に置き換えても悪くならないことを示す論法（交換論法）が、貪欲法の正しさを示す典型的な方法である。

貪欲法が失敗する例：硬貨の両替

ある金額を、できるだけ少ない枚数の硬貨で支払う問題を考える。日本の硬貨（1、5、10、50、100、500 円）では、大きい額面から使えるだけ使う貪欲法で最小の枚数になる。しかし額面が 1、3、4 円の場合、6 円を支払うのに貪欲法は 4 + 1 + 1 の 3 枚を選ぶが、最適解は 3 + 3 の 2 枚である。この問題は一般には次に述べる動的計画法で解く。

14def interval_scheduling(
15    intervals: list[tuple[int, int]],
16) -> list[tuple[int, int]]:
17    """互いに重ならない区間 [start, end) をできるだけ多く選ぶ。"""
18    chosen: list[tuple[int, int]] = []
19    last_end = float("-inf")
20    for start, end in sorted(intervals, key=lambda iv: iv[1]):
21        if start >= last_end:
22            chosen.append((start, end))
23            last_end = end
24    return chosen

27def greedy_coin_change(coins: list[int], amount: int) -> list[int]:
28    """大きい額面から順に使えるだけ使う。最適とは限らない。"""
29    used: list[int] = []
30    for coin in sorted(coins, reverse=True):
31        while amount >= coin:
32            amount -= coin
33            used.append(coin)
34    if amount != 0:
35        raise ValueError("この額面では支払えない")
36    return used

39def optimal_coin_count(coins: list[int], amount: int) -> int:
40    """動的計画法で最小の硬貨枚数を求める (比較用)。"""
41    inf = amount + 1
42    best = [0] + [inf] * amount  # best[x] は x 円を払う最小枚数
43    for x in range(1, amount + 1):
44        for coin in coins:
45            if coin <= x and best[x - coin] + 1 < best[x]:
46                best[x] = best[x - coin] + 1
47    return best[amount] if best[amount] < inf else -1

動的計画法

動的計画法は、問題を部分問題に分割し、各部分問題の答えを表に記録して再利用する技法である。英語の Dynamic Programming から DP と略されることもある。分割統治法と異なり、同じ部分問題が何度も現れる（部分問題が重なり合う）場合に威力を発揮する。

動的計画法が使えるのは、問題の最適解が部分問題の最適解から組み立てられる場合である。この性質を最適部分構造と呼ぶ。動的計画法でアルゴリズムを設計するときは、次の手順で考えるとよい。

  1. 部分問題を定義する（表の各セルが何を表すかを決める）。

  2. 部分問題の間の関係を漸化式で表す。

  3. 小さい部分問題から順に表を埋める（ボトムアップ）か、再帰呼び出しの結果を記録する（トップダウン、メモ化）。

  4. 必要なら、表を逆にたどって最適解そのものを復元する。

メモ化：フィボナッチ数

フィボナッチ数 \(F_n = F_{n-1} + F_{n-2}\)（\(F_0 = 0, F_1 = 1\)）を定義どおりに再帰で計算すると、同じ \(F_k\) を何度も計算するため、呼び出し回数は \(\Theta(\varphi^n)\)（\(\varphi \approx 1.618\) は黄金比）に増える。計算済みの値を記録しておけば、各 \(F_k\) は 1 回ずつしか計算されず、\(O(n)\) 回の呼び出しで済む。Python では functools.lru_cache（または functools.cache）を関数に付けるだけでメモ化できる。

0-1 ナップサック問題

\(n\) 個の品物があり、品物 \(i\) の重さは \(w_i\)、価値は \(v_i\) である。重さの合計が \(W\) 以下になるように品物を選び（各品物は選ぶか選ばないかのどちらか）、価値の合計を最大にしたい。これを 0-1 ナップサック問題と呼ぶ。

全ての選び方を試すと \(2^n\) 通りになる。そこで、部分問題を次のように定義する。

  • \(dp[i][w]\)：品物 \(0, 1, \ldots, i - 1\) の中から、重さの合計が \(w\) 以下になるように選んだときの価値の最大値

品物 \(i - 1\) を選ぶか選ばないかで場合分けすると、次の漸化式が得られる。

\[\begin{split}dp[i][w] = \begin{cases} dp[i-1][w] & (w_{i-1} > w) \\ \max(dp[i-1][w],\ dp[i-1][w - w_{i-1}] + v_{i-1}) & (w_{i-1} \le w) \end{cases}\end{split}\]

表の大きさは \((n + 1) \times (W + 1)\) で、各セルを \(O(1)\) 時間で埋められるので、計算量は \(O(nW)\) である。

この計算量は \(n\) と \(W\) の多項式に見えるが、\(W\) は入力の中では \(\log W\) ビットで表される数値である。入力の長さに対しては指数時間であり、このようなアルゴリズムを擬多項式時間アルゴリズムと呼ぶ。第 11 章で見るように、ナップサック問題（の判定版）は NP 完全であり、この区別が重要な意味を持つ。

最長共通部分列

文字列から 0 個以上の文字を取り除いて得られる文字列を、元の文字列の部分列と呼ぶ（取り除く文字は連続していなくてもよい）。2 つの文字列 \(s\) と \(t\) に共通する部分列のうち最長のものを最長共通部分列（LCS: Longest Common Subsequence）と呼ぶ。LCS は diff コマンドによるファイルの差分表示などに使われている。

\(dp[i][j]\) を \(s\) の先頭 \(i\) 文字と \(t\) の先頭 \(j\) 文字の LCS の長さとすると、次の漸化式が成り立つ。

\[\begin{split}dp[i][j] = \begin{cases} 0 & (i = 0 \text{ または } j = 0) \\ dp[i-1][j-1] + 1 & (s_{i-1} = t_{j-1}) \\ \max(dp[i-1][j],\ dp[i][j-1]) & (s_{i-1} \ne t_{j-1}) \end{cases}\end{split}\]

\(s\) と \(t\) の長さをそれぞれ \(m\)、\(n\) とすると、計算量は \(O(mn)\) である。

18def fib(n: int) -> int:

25def knapsack(
26    weights: list[int], values: list[int], capacity: int
27) -> tuple[int, list[int]]:
28    """容量 capacity に収まる価値の最大値と、選ぶ品物の番号を返す。"""
29    n = len(weights)
30    # dp[i][w]: 品物 0..i-1 から重さの合計 w 以下で選んだときの価値の最大値
31    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
32    for i in range(1, n + 1):
33        wt, val = weights[i - 1], values[i - 1]
34        for w in range(capacity + 1):
35            dp[i][w] = dp[i - 1][w]  # 品物 i - 1 を選ばない
36            if wt <= w and dp[i - 1][w - wt] + val > dp[i][w]:
37                dp[i][w] = dp[i - 1][w - wt] + val  # 選ぶ
38    chosen: list[int] = []
39    w = capacity
40    for i in range(n, 0, -1):  # 表を逆にたどって選んだ品物を復元する
41        if dp[i][w] != dp[i - 1][w]:
42            chosen.append(i - 1)
43            w -= weights[i - 1]
44    return dp[n][capacity], sorted(chosen)
45
46
47def lcs(s: str, t: str) -> str:
48    """文字列 s と t の最長共通部分列の 1 つを返す。"""
49    m, n = len(s), len(t)
50    # dp[i][j]: s[:i] と t[:j] の LCS の長さ
51    dp = [[0] * (n + 1) for _ in range(m + 1)]
52    for i in range(1, m + 1):
53        for j in range(1, n + 1):
54            if s[i - 1] == t[j - 1]:
55                dp[i][j] = dp[i - 1][j - 1] + 1
56            else:
57                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
58    chars: list[str] = []
59    i, j = m, n
60    while i > 0 and j > 0:
61        if s[i - 1] == t[j - 1]:
62            chars.append(s[i - 1])
63            i -= 1
64            j -= 1
65        elif dp[i - 1][j] >= dp[i][j - 1]:
66            i -= 1
67        else:
68            j -= 1
69    return "".join(reversed(chars))

ナップサック問題の例では、品物 0（重さ 2、価値 3）と品物 2（重さ 3、価値 4）を選んで重さ 5、価値 7 となる。品物 0、1、3 を選んでも価値は 7 であり、最適解が複数ある場合はそのうちの 1 つが復元される。

動的計画法は第 7 章のベルマン-フォード法やワーシャル-フロイド法、第 9 章の CYK 法でも使われる。

バックトラッキングと分枝限定法

効率のよいアルゴリズムが見つからない問題では、可能な解を全て調べる全探索に頼ることになる。バックトラッキングは、解を 1 要素ずつ決めていき、途中で条件を満たさないことが分かった時点でその先の探索を打ち切って（枝刈り）、直前の選択に戻って別の候補を試す技法である。

N クイーン問題

\(n \times n\) の盤面に、縦・横・斜めのいずれの方向にも互いに取り合わないように \(n\) 個のクイーンを置く問題を考える。各行にクイーンはちょうど 1 個置かれるので、1 行目から順に列を決めていく。既に置いたクイーンと同じ列または同じ斜線上には置けないので、その候補はすぐに捨てる。

ch06_backtracking.py

リスト 12 ch06_backtracking.py
 1"""第 6 章: バックトラッキングによる N クイーン問題。
 2
 3n x n の盤面に、互いに取り合わないように n 個のクイーンを置く方法を数える。
 41 行ずつクイーンを置き、矛盾が生じた時点でその先の探索を打ち切る (枝刈り)。
 5
 6実行例::
 7
 8    python ch06_backtracking.py
 9"""
10
11from __future__ import annotations
12
13
14def count_n_queens(n: int) -> int:
15    """n クイーン問題の解の個数を返す。"""
16    cols: set[int] = set()
17    diag1: set[int] = set()  # row + col が等しいマスは同じ斜線上にある
18    diag2: set[int] = set()  # row - col が等しいマスは同じ斜線上にある
19
20    def place(row: int) -> int:
21        if row == n:
22            return 1
23        count = 0
24        for col in range(n):
25            if col in cols or row + col in diag1 or row - col in diag2:
26                continue  # 枝刈り: この先を調べても解は無い
27            cols.add(col)
28            diag1.add(row + col)
29            diag2.add(row - col)
30            count += place(row + 1)
31            cols.remove(col)  # 状態を元に戻して次の候補を試す
32            diag1.remove(row + col)
33            diag2.remove(row - col)
34        return count
35
36    return place(0)
37
38
39def main() -> None:
40    for n in range(1, 9):
41        print(f"n = {n}: {count_n_queens(n)} 通り")
42

45    main()

同じ斜線上のマスは「行番号 + 列番号」または「行番号 - 列番号」が等しいので、集合を使えば矛盾の判定を \(O(1)\) 時間で行える。\(n = 8\) の場合、解は 92 通りある。

分枝限定法

最適化問題に対しては、バックトラッキングをさらに強化した分枝限定法が使える。探索の途中で、「この先をどのように選んでも得られる解の値の上限（最大化問題の場合）」を見積もり、その上限がこれまでに見つかった最良の解の値以下であれば、その先の探索を打ち切る。例えばナップサック問題では、残りの品物を分割して入れてもよいと緩めた問題（貪欲法で最適に解ける）の値を上限として使える。

バックトラッキングや分枝限定法は、最悪の場合には指数時間かかる。しかし枝刈りがよく効けば、実用的な大きさの問題を解けることも多い。第 12 章の DPLL アルゴリズムは、充足可能性問題に対するバックトラッキングである。
