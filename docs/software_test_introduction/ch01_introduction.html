1. はじめに

1.1 本書の目的

プログラムを書いたら、思いどおりに動くかを確かめる。多くのエンジニアは、関数を呼び出して結果を表示したり、画面を操作して動きを見たりして、これを日常的に行っている。しかし、何をどこまで確かめれば十分なのか、確かめる作業をどうすれば繰り返し行えるのかを、体系的に学ぶ機会は多くない。

本書の目的は、ソフトウェアテストの基本的な考え方と、それを実際の開発で使うための技術を身に付けることである。具体的には、読み終えたときに次のことができるようになることを目指す。

  • テストの目的と限界を説明できる。

  • 仕様やコードの構造から、少ない数で効果の高いテストケースを設計できる。

  • pytest を使って、自動で繰り返し実行できるテストを書ける。

  • テストしやすいようにコードを設計し直せる。

  • テストを開発の流れに組み込み、継続的に運用できる。

1.2 対象読者と前提知識

本書は、Python の基本的な文法（関数、クラス、例外、モジュールの import など）を理解しているエンジニアを対象とする。Python 以外の言語が主な仕事の言語であっても、第 I 部と第 III 部の内容はそのまま役立つ。

テストについての予備知識は必要ない。一方で、Python の文法の説明は省略する。型ヒント（list[int] や str | None など）もサンプルコード全体で使うが、読めれば十分である。

1.6 サンプルコードの使い方

サンプルコードは、examples.zip から一括でダウンロードできる。個別のファイルは、付録 C の一覧からダウンロードできる。展開すると、次の構成のフォルダーができる。

examples/
├── pyproject.toml         pytest、mypy、coverage.py の設定
├── setup.cfg              flake8 の設定
├── shop/                  題材のパッケージ
├── ch06_unittest/         6 章のテスト
├── ch07_pytest_basics/    7 章のテスト
└── ...                    以降の章のテスト

テストは examples フォルダーで実行する。pyproject.toml の設定により、examples フォルダーが import の起点になるため、どの章のテストからも shop パッケージを読み込める。

1$ cd examples
2$ python -m pytest

1.7 本書の表記

本書では、次の表記を用いる。

  • コマンドの入力例は、先頭に $ を付けて示す。$ は入力しない。Windows の PowerShell やコマンドプロンプトでも、同じコマンドを実行できる。

  • コードとコマンドの例には行番号を付ける。説明の中で「3 行目」のように行番号で参照することがある。

  • 実行結果は、行番号を付けずに示す。実行結果の中のパスの区切り文字やメモリー上のアドレスなどは、環境によって異なることがある。

  • 用語集に載せた用語は、本文の初出などで付録 A の用語集へのリンクを付ける。
