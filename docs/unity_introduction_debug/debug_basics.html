2. デバッグの基礎

2.1. デバッグとは

デバッグとは、プログラムが期待どおりに動作しない原因（バグ）を突き止め、修正する作業です。バグの症状には、「エラーが表示されて処理が止まる」ものだけでなく、「エラーは表示されないが結果がおかしい」「特定の条件のときだけ発生する」ものもあります。後者は原因の特定に時間がかかる傾向があるため、思いつきでコードを書き換えるのではなく、手順を踏んで調査することが重要です。

2.2. デバッグの手順

デバッグは、一般に次の手順で進めます。

#

手順

内容

1

再現

不具合が発生する操作手順を特定し、確実に再現できるようにします。再現手順は、修正後の確認にも使います。

2

切り分け

原因がありそうな範囲を絞り込みます。機能の一部を無効にする、別のシーンで試すなどして、どこまでが正常でどこからが異常かを調べます。

3

仮説

観察した結果から、原因の候補を考えます。

4

検証

ログやデバッガーを使って、仮説が正しいかを確かめます。仮説が誤っていた場合は、手順 2 に戻ります。

5

修正

原因を取り除きます。例外を catch して無視するなど、症状を隠すだけの修正は避けます。

6

確認と再発防止

手順 1 の再現手順で不具合が直ったことを確認します。また、同じ不具合が再び起きないように、アサーションやテストを追加します。

Tip

「いつから発生するようになったか」も重要な手がかりです。Git などのバージョン管理システムを使っていれば、正常に動作していた時点との差分を調べることで、原因を効率よく絞り込めます。

2.3. Console ウィンドウの使い方

Console ウィンドウは、スクリプトから出力したログや、Unity が出力するエラーと警告を表示するウィンドウです。メニューの Window ‣ General ‣ Console で開きます。

ツールバーの主な機能は次のとおりです。

項目

機能

Clear

表示されているログをすべて消去します。右側の ▼ から、再生開始時（Clear on Play）、ビルド時（Clear on Build）、再コンパイル時（Clear on Recompile）に自動で消去するかを設定できます。

Collapse

同じ内容のログを 1 行にまとめ、出力された回数を表示します。毎フレーム出力されるログが多い場合に便利です。

Error Pause

スクリプトからエラーが出力されたときに、再生を一時停止します。エラー発生時の状態をそのまま調べられます。

Editor

ログの取得元を切り替えます。実機で動作しているアプリケーションのログを表示する場合に使います（実機でのデバッグ）。

検索ボックス

入力した文字列を含むログだけを表示します。

ログの種類のボタン

右端の 3 つのボタンで、通常のログ、警告、エラーの表示・非表示を切り替えます。各ボタンには、その種類のログの件数が表示されます。

2.3.1. スタックトレースの読み方

エラーのログを選択すると、ウィンドウ下部にスタックトレースが表示されます。スタックトレースは、エラーが発生した時点で、どのメソッドがどのメソッドから呼び出されていたかを示す情報です。

NullReferenceException: Object reference not set to an instance of an object
PlayerController.Attack () (at Assets/Scripts/PlayerController.cs:42)
PlayerController.Update () (at Assets/Scripts/PlayerController.cs:25)

1 行目は、発生した例外の種類とメッセージです。2 行目以降が呼び出しの履歴で、上にあるほど新しい呼び出しです。この例では、Update メソッドの 25 行目から呼び出された Attack メソッドの 42 行目で例外が発生したことが分かります。ファイル名と行番号の部分をクリックすると、コードエディターで該当の行を開けます。

2.4. Debug クラスによるログ出力

ログ出力は、最も手軽で基本的なデバッグ手法です。変数の値や、処理がどこまで進んだかを Console ウィンドウに出力して、プログラムの動作を確認します。

2.4.1. 主なメソッド

メソッド

用途

Debug.Log

通常のログを出力します。

Debug.LogWarning

警告を出力します。処理は続けられるものの、注意が必要な状態を知らせるために使います。

Debug.LogError

エラーを出力します。本来起きてはいけない状態を知らせるために使います。

Debug.LogException

例外を、スタックトレースを含めて出力します。catch した例外を記録するために使います。

Debug.Assert

条件が false のときだけエラーを出力します。「ここでは必ずこの条件が成り立つはず」という前提を確認するために使います。

これらのメソッドには、第 2 引数として UnityEngine.Object（GameObject やコンポーネント）を渡せます。この引数を context と呼びます。context を渡したログを Console ウィンドウでクリックすると、そのオブジェクトが Hierarchy ウィンドウでハイライトされます。同じスクリプトを追加した GameObject が複数ある場合に、どのオブジェクトがログを出力したかをすぐに特定できます。

次のサンプルは、各メソッドの使い方を示しています。

LogExample.cs
using System;
using UnityEngine;

/// <summary>
/// Debug クラスによるログ出力の基本を示すサンプルです。
/// 任意の GameObject に追加して再生すると、Console ウィンドウにログが出力されます。
/// </summary>
public class LogExample : MonoBehaviour
{
    [SerializeField]
    private int hitPoint = 100;

    private void Start()
    {
        // 通常のログです。Console ウィンドウに白いアイコンで表示されます。
        Debug.Log("ゲームを開始しました。");

        // 警告です。黄色いアイコンで表示されます。
        if (hitPoint > 1000)
        {
            Debug.LogWarning("HP の初期値が大きすぎる可能性があります。");
        }

        // 第 2 引数に this を渡すと、Console ウィンドウでこのログをクリックしたときに
        // この GameObject が Hierarchy ウィンドウでハイライトされます。
        Debug.Log($"{name} の HP は {hitPoint} です。", this);

        // 条件が false のときだけエラーとして出力します。
        // Debug.Assert はエディターと Development Build でのみ実行されます。
        Debug.Assert(hitPoint > 0, "HP は 1 以上である必要があります。", this);
    }

    /// <summary>
    /// Inspector ウィンドウでこのコンポーネントを右クリックし、
    /// メニューから「エラーを出力する」を選ぶと実行されます。
    /// </summary>
    [ContextMenu("エラーを出力する")]
    private void OutputError()
    {
        // エラーです。赤いアイコンで表示されます。
        Debug.LogError("エラーのテストです。", this);
    }

    /// <summary>
    /// Inspector ウィンドウでこのコンポーネントを右クリックし、
    /// メニューから「例外を出力する」を選ぶと実行されます。
    /// </summary>
    [ContextMenu("例外を出力する")]
    private void OutputException()
    {
        try
        {
            int[] values = new int[3];

            // 配列の範囲外にアクセスするため、例外が発生します。
            values[5] = 1;
        }
        catch (IndexOutOfRangeException e)
        {
            // 例外を無視せず、スタックトレース付きで出力します。
            Debug.LogException(e, this);
        }
    }
}

注釈

Debug.Assert は UNITY_ASSERTIONS シンボルが定義されている場合にだけ実行されます。このシンボルはエディターと Development Build で定義されるため、リリースビルドでは呼び出し自体が取り除かれます。

2.4.2. リリースビルドでのログの扱い

Debug.Log は、リリースビルドでも実行されます。ログはログファイルに書き込まれ（ログファイルの場所）、ログの文字列を生成する処理やスタックトレースを取得する処理のコストもかかります。毎フレーム呼び出されるようなログは、処理負荷の原因になります。

Debug.unityLogger.logEnabled を false にするとログの出力は止まりますが、Debug.Log に渡す引数の文字列は生成されるため、その分のコストは残ります。

呼び出しそのものを取り除くには、C# の [Conditional] 属性を使ったラッパークラスを作ります。[Conditional] 属性が付いたメソッドは、指定したシンボルが定義されていない場合、呼び出し箇所ごとコンパイル結果から削除されます。引数の文字列を生成する処理も実行されません。

DebugLogger.cs
using System.Diagnostics;
using UnityEngine;

/// <summary>
/// リリースビルドでログ出力を呼び出し箇所ごと取り除くためのラッパークラスです。
/// </summary>
/// <remarks>
/// <para>
/// [Conditional] 属性が付いたメソッドは、指定したシンボルがどれも定義されていない場合、
/// 呼び出し箇所ごとコンパイル結果から削除されます。
/// このとき、引数に渡す文字列の生成処理も実行されません。
/// </para>
/// <para>
/// UNITY_EDITOR はエディター上で常に定義されるシンボルです。
/// ENABLE_LOG は独自のシンボルで、ビルドでもログを出力したい場合に
/// Project Settings の Player > Other Settings > Scripting Define Symbols で定義します。
/// </para>
/// <para>
/// 使用例: DebugLogger.Log($"スコア: {score}", this);
/// </para>
/// </remarks>
public static class DebugLogger
{
    // System.Diagnostics にも Debug クラスがあるため、UnityEngine.Debug と明記しています。

    [Conditional("UNITY_EDITOR")]
    [Conditional("ENABLE_LOG")]
    public static void Log(object message, Object context = null)
    {
        UnityEngine.Debug.Log(message, context);
    }

    [Conditional("UNITY_EDITOR")]
    [Conditional("ENABLE_LOG")]
    public static void LogWarning(object message, Object context = null)
    {
        UnityEngine.Debug.LogWarning(message, context);
    }

    // エラーは製品版でも原因の調査に必要になることが多いため、
    // このクラスには含めず、UnityEngine.Debug.LogError を直接使います。
}

このクラスを使う場合は、Debug.Log の代わりに DebugLogger.Log を呼び出します。エディターでは常にログが出力され、ビルドでは ENABLE_LOG シンボルを定義した場合だけログが出力されます。
