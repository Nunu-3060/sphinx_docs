10. メモリとアセットの最適化

スマートフォンなどでは、アプリケーションが使えるメモリの量が限られており、使用量が多すぎると OS によってアプリケーションが強制終了されることがあります。本章では、メモリの使用量を減らす手法を紹介します。

10.1. Unity のメモリの構成

Unity のアプリケーションが使うメモリは、大きく次の 2 つに分けられます。

種類

説明

マネージドメモリ

C# のスクリプトで生成したオブジェクトや配列が置かれるメモリです。ガベージコレクターが管理します（ガベージコレクションと GC アロケーションの削減）。マネージドヒープは必要に応じて拡張されますが、一度拡張されると、ほとんど縮小されません。

ネイティブメモリ

Unity のエンジンが使うメモリです。テクスチャ、メッシュ、オーディオなどのアセットのデータの多くはここに置かれます。

多くのゲームでは、メモリの使用量の大部分をアセットが占めます。どのアセットがどれだけメモリを使っているかは、Memory Profiler で確認できます（プロファイリング）。

10.2. テクスチャ

テクスチャは、メモリの使用量が特に大きくなりやすいアセットです。圧縮しないテクスチャのメモリの使用量 \(M\) は、幅を \(W\)、高さを \(H\)、1 ピクセルあたりのバイト数を \(B\) とすると、次の式で求められます。

\[M = W \times H \times B\]

たとえば、2048 × 2048 ピクセルの RGBA32 形式（1 ピクセルあたり 4 バイト）のテクスチャは、\(2048 \times 2048 \times 4 = 16{,}777{,}216\) バイト、つまり 16 MiB を使います。同じテクスチャを ASTC 6x6 形式（1 ピクセルあたり約 3.56 ビット）で圧縮すると、約 1.78 MiB になります。

また、ミップマップ（縮小表示用に、あらかじめ縮小した画像）を生成すると、縦横が半分ずつ小さい画像が追加されます。各段階の画像の面積は 1 つ前の段階の 1/4 になるため、全体の大きさは次のように元の約 4/3 倍、つまり約 33% 増えます。

\[1 + \frac{1}{4} + \frac{1}{16} + \frac{1}{64} + \cdots = \frac{1}{1 - \frac{1}{4}} = \frac{4}{3}\]

テクスチャのインポート設定で、次の項目を見直します。

設定項目

説明

Max Size

テクスチャの最大の解像度です。画面での表示の大きさに対して、必要以上に大きくしないようにします。

Format、Compression

圧縮形式です。スマートフォンでは ASTC、パソコンでは BC7 や DXT（BC1、BC3）が一般的です。プラットフォームごとのタブで、個別に設定できます。

Generate Mipmaps

ミップマップを生成するかどうかです。3D 空間に配置するテクスチャでは、表示の品質と描画の効率のために有効にします。UI など、常に同じ大きさで表示するテクスチャでは無効にします。

Read/Write

スクリプトからピクセルを読み書きできるようにします。有効にすると、GPU 用のデータに加えて CPU 用のコピーがメモリに残るため、使用量がほぼ 2 倍になります。スクリプトからピクセルを読み書きしない場合は無効にします。

10.3. メッシュとアニメーション

10.3.1. メッシュ

設定項目・手法

説明

Read/Write

テクスチャと同様に、有効にすると CPU 用のコピーがメモリに残ります。スクリプトからメッシュの頂点を読み書きしない場合は無効にします。

不要な頂点データを読み込まない

法線や接線を使わないメッシュでは、インポート設定の Normals や Tangents を None にします。

Mesh Compression

メッシュのデータを圧縮します。ただし、減るのはビルドしたファイルのサイズで、実行時のメモリの使用量は減りません。

ポリゴン数を減らす

画面で見える大きさに対して、必要以上に細かいメッシュを使わないようにします。LOD も有効です（描画（GPU）の最適化）。

10.3.2. アニメーション

アニメーションのインポート設定の Anim. Compression を Keyframe Reduction や Optimal にすると、見た目への影響が小さいキーフレームが削減され、メモリの使用量が減ります。

10.4. オーディオ

オーディオクリップのインポート設定では、音声の長さや用途に応じて Load Type を選びます。

Load Type

動作

適した用途

Decompress On Load

読み込み時に展開して、非圧縮のデータをメモリに保持します。再生時の CPU の負荷は小さいものの、メモリの使用量は大きくなります。

短い効果音

Compressed In Memory

圧縮したままメモリに保持し、再生時に展開します。メモリの使用量は小さいものの、再生時に CPU の負荷がかかります。

中程度の長さの音声

Streaming

ファイルから少しずつ読み込みながら再生します。メモリの使用量は最も小さいものの、読み込みと展開の負荷がかかります。

BGM など長い音声

このほか、Compression Format で圧縮形式（PCM、ADPCM、Vorbis など）を選べます。ステレオである必要のない効果音は、Force To Mono を有効にするとデータ量が半分になります。

10.5. アセットの読み込みと解放

10.5.1. Resources フォルダーの問題点

Resources という名前のフォルダーに置いたアセットは、Resources.Load でスクリプトから読み込めます。手軽な方法ですが、次の問題があります。

  • Resources フォルダー内のアセットは、実際に使われているかどうかに関係なく、すべてビルドに含まれます。

  • アプリケーションの起動時に、Resources フォルダー内のアセットの一覧を作成する処理が行われるため、アセットが多いほど起動が遅くなります。

  • 読み込んだアセットを解放するには、Resources.UnloadUnusedAssets などを呼び出す必要があります。Resources.UnloadUnusedAssets は処理が重いため、シーンの切り替え時など、処理が一時的に止まっても問題のないタイミングで呼び出します。

10.5.2. Addressables

Addressables パッケージを使うと、アセットにアドレス（名前）を付けて、必要なときに非同期で読み込み、不要になったら解放できます。アセットをアプリケーションとは別にダウンロードする仕組みにも対応しています。

// アドレスを指定して非同期で読み込みます。
AsyncOperationHandle<GameObject> handle = Addressables.LoadAssetAsync<GameObject>("Enemy");
GameObject enemyPrefab = await handle.Task;

// 使い終わったら解放します。
Addressables.Release(handle);

Addressables は、アセットが何か所から使われているかを数えて管理し、どこからも使われなくなったアセットを解放します。そのため、読み込みと解放は必ず対にしてください。解放を忘れると、アセットがメモリに残り続けます。
