9. 描画（GPU）の最適化

本章では、描画に関する処理の改善手法を紹介します。描画の処理には、GPU に描画を指示する CPU 側の処理と、実際に描画する GPU 側の処理があります。どちらがボトルネックかを確認してから対処してください（CPU バウンドと GPU バウンドの見分け方）。

9.1. 描画処理の流れとドローコール

Unity は、フレームごとに次のような流れで描画を行います。

  1. カメラに映らないオブジェクトを描画の対象から外します（カリング）。

  2. 描画するオブジェクトを、描画する順序に並べ替えます。

  3. オブジェクトごとに、使用するシェーダーやマテリアルの設定を GPU に送り、描画を指示します。

  4. GPU が、指示に従ってポリゴンを画面のピクセルに変換し、色を計算します。

手順 3 で GPU に送る描画の指示をドローコールと呼びます。また、ドローコールの前に、使用するシェーダーなどの描画の設定を切り替える処理を SetPass コールと呼びます。SetPass コールは特に CPU の負荷が大きいため、その数を減らすことが CPU 側の描画の負荷を下げる鍵になります。

ドローコールや SetPass コールの数は、Profiler の Rendering モジュールのほか、Game ビューのツールバーにある Stats ボタンで表示される統計情報でも確認できます。統計情報の Batches がドローコールの数、SetPass calls が SetPass コールの数です。

9.2. バッチング

バッチングとは、複数のオブジェクトの描画をまとめて、ドローコールや SetPass コールの数、またはその処理のコストを減らす仕組みです。URP で使える主なバッチングは次のとおりです。

注意点

SRP Batcher

同じシェーダーのバリアントを使うオブジェクトの描画をまとめ、マテリアルの切り替えのコストを減らします。マテリアルが異なっていても効果があります。URP では既定で有効です。

SRP Batcher に対応したシェーダーが必要です。URP の標準のシェーダーは対応しています。

GPU インスタンシング

同じメッシュと同じマテリアルを使う多数のオブジェクトを、1 回のドローコールで描画します。マテリアルの Enable GPU Instancing を有効にして使います。

SRP Batcher が使えるオブジェクトでは、SRP Batcher が優先されます。

Static Batching

動かないオブジェクトのメッシュを、ビルド時などに結合します。Inspector ウィンドウの Static のうち、Batching Static を有効にして使います。

結合したメッシュの分だけメモリの使用量が増えます。対象のオブジェクトは動かせません。

Dynamic Batching

頂点数の少ない小さなメッシュを、毎フレーム CPU で結合します。

URP では既定で無効です。結合の処理自体に CPU の負荷がかかるため、現在のハードウェアではほとんどの場合、効果がありません。

Unity 6 では、GPU Resident Drawer という機能も追加されました。GPU Resident Drawer を有効にすると、多数のオブジェクトが自動的にインスタンシングで描画されるようになります。利用するには、URP Asset の GPU Resident Drawer を有効にし、レンダリングパスに Forward+ を使うなどの条件を満たす必要があります。

バッチングが期待どおりに行われているかは、Frame Debugger で確認できます（Frame Debugger による描画処理の確認）。

9.3. カリングと LOD

描画する必要のないものを描画しないことも、重要な最適化です。

手法

説明

視錐台カリング

カメラの視野の外にあるオブジェクトを描画しない仕組みです。Unity が自動的に行います。カメラの Far（描画する最大距離）を必要以上に大きくしないことで、描画の対象を減らせます。

オクルージョンカリング

壁や建物など、他のオブジェクトに隠れて見えないオブジェクトを描画しない仕組みです。遮る側のオブジェクトに Occluder Static、遮られる側に Occludee Static を設定し、Window ‣ Rendering ‣ Occlusion Culling でデータを事前に計算（ベイク）して使います。

LOD（Level of Detail）

カメラから遠いオブジェクトほど、ポリゴン数の少ないメッシュで描画する仕組みです。LOD Group コンポーネントに、詳細度の異なる複数のメッシュを登録して使います。

オクルージョンカリングは、屋内や街中など、見通しが悪く遮るものが多いシーンで特に効果があります。見通しのよい屋外のシーンでは、効果が小さい割に計算の負荷がかかることがあります。

9.4. オーバードローと半透明

同じピクセルが 1 フレームの中で何度も描画されることを、オーバードローと呼びます。オーバードローが多いと、GPU の負荷が高くなります。特に、半透明のオブジェクトは後ろにあるものと色を混ぜ合わせる必要があるため、重なるほど負荷が増えます。

オーバードローが起こりやすいのは、次のようなものです。

  • 大きなパーティクルを大量に重ねたエフェクト

  • 画面全体を覆う半透明の UI やエフェクト

  • 半透明のマテリアルを使った大きなオブジェクト

オーバードローの量は、Window ‣ Analysis ‣ Rendering Debugger で開く Rendering Debugger で可視化できます。対策としては、パーティクルの数や大きさを減らす、半透明にする必要のないオブジェクトは不透明のマテリアルを使う、といった方法があります。

9.5. ライティングと影

リアルタイムのライトと影は、描画の負荷が大きい処理です。

手法

説明

ライトのベイク

動かないオブジェクトの照明と影を、あらかじめ計算してテクスチャ（ライトマップ）に保存しておく手法です。ライトの Mode を Baked または Mixed にし、Window ‣ Rendering ‣ Lighting で計算します。実行時の計算が不要になります。

ライトプローブ

動くオブジェクトに、ベイクした照明の情報を反映する仕組みです。リアルタイムのライトを使わずに、周囲の明るさに合った見た目にできます。

リアルタイムのライトの数を減らす

URP の Forward レンダリングでは、1 つのオブジェクトに影響するリアルタイムのライトの数に上限があり、ライトが増えるほど負荷も増えます。

影の設定を見直す

URP Asset の Max Distance（影を描画する最大距離）、カスケードの数、影のテクスチャの解像度を下げると負荷が減ります。小さなオブジェクトは、Mesh Renderer の Cast Shadows を Off にして影を落とさないようにします。

9.6. 解像度、ポストエフェクト、シェーダー

9.6.1. 解像度

GPU の負荷は、描画するピクセルの数にほぼ比例します。スマートフォンには非常に高解像度の画面を持つものがあり、画面の解像度のまま描画すると GPU の負荷が大きくなります。URP Asset の Render Scale を 1 より小さくすると、低い解像度で描画してから画面の大きさに拡大するため、負荷を減らせます。

9.6.2. ポストエフェクト

Bloom、被写界深度（Depth of Field）、アンビエントオクルージョンなどのポストエフェクトは、画面全体のピクセルに対して処理を行うため、GPU の負荷が大きくなります。特にスマートフォンでは、効果と負荷を比較して、使用するポストエフェクトを厳選してください。

9.6.3. シェーダー

複雑なシェーダーほど、1 ピクセルあたりの計算量が増えます。スマートフォンなど性能の低い端末では、URP の Lit シェーダーの代わりに、計算の少ない Simple Lit シェーダーや、ライティングを行わない Unlit シェーダーを使うことも検討します。
