18. Python によるシステム管理の自動化

この章では、Python を使ってシステム管理の作業を自動化する方法を説明します。シェルスクリプトでは書きにくい、データの集計や条件の複雑な処理も、Python を使うと読みやすく書けます。

18.1. Rocky Linux の Python

Rocky Linux 10 には Python 3.12 が含まれており、python3 コマンドで実行できます。この Python は、dnf をはじめとする OS のツールも使っている「システムの Python」です。

1$ python3 --version
2Python 3.12.9

システムの Python に sudo pip install で直接ライブラリを導入すると、dnf で導入したライブラリと衝突し、OS のツールが動かなくなるおそれがあります。外部のライブラリを使う場合は、次に説明する仮想環境を使ってください。

18.2. 仮想環境（venv）

venv は、プロジェクトごとに独立した Python の環境（仮想環境）を作る標準の機能です。仮想環境の中で導入したライブラリは、システムの Python や他の仮想環境に影響しません。

1$ python3 -m venv ~/venvs/tools
2$ source ~/venvs/tools/bin/activate
3(tools) $ pip install --upgrade pip
4(tools) $ pip install flake8 mypy
5(tools) $ deactivate

1 行目で ~/venvs/tools に仮想環境を作成し、2 行目で有効にしています。有効にすると、プロンプトの先頭に仮想環境の名前が表示され、python や pip がこの仮想環境のものになります。5 行目の deactivate で元に戻ります。

仮想環境を有効にせずに、仮想環境の Python を直接指定して実行することもできます。systemd のサービスやタイマーから実行する場合は、この方法が便利です。

1$ ~/venvs/tools/bin/python3 script.py

本章のサンプルは標準ライブラリだけで書かれているため、仮想環境を使わずにシステムの python3 で実行できます。

18.3. サンプル 1: サーバー情報の収集

OS のバージョン、カーネル、CPU、メモリ、ディスクの使用量を 1 画面にまとめて表示するスクリプトです。/etc/os-release や /proc/meminfo など、これまでの章で扱ったファイルから情報を読み取っています。

リスト 18.1 system_info.py
  1#!/usr/bin/env python3
  2"""サーバーの基本情報を収集して表示するスクリプト.
  3
  4OS のバージョン、カーネル、CPU、メモリ、ディスク使用量を 1 画面にまとめて
  5表示します。標準ライブラリのみを使用しているため、Rocky Linux 10 に
  6標準で導入されている python3 でそのまま実行できます。
  7
  8使い方:
  9    python3 system_info.py           # 人間向けの表形式で表示
 10    python3 system_info.py --json    # JSON 形式で表示 (他のツールとの連携用)
 11"""
 12
 13from __future__ import annotations
 14
 15import argparse
 16import json
 17import os
 18import platform
 19import shutil
 20import socket
 21from dataclasses import asdict, dataclass, field
 22from pathlib import Path
 23
 24OS_RELEASE_PATH = Path("/etc/os-release")
 25MEMINFO_PATH = Path("/proc/meminfo")
 26UPTIME_PATH = Path("/proc/uptime")
 27
 28# 使用量を調べるマウントポイント
 29DEFAULT_MOUNT_POINTS = ["/", "/boot", "/home", "/var"]
 30
 31
 32@dataclass
 33class DiskUsage:
 34    """1 つのマウントポイントのディスク使用量."""
 35
 36    mount_point: str
 37    total_gib: float
 38    used_gib: float
 39    free_gib: float
 40    used_percent: float
 41
 42
 43@dataclass
 44class SystemInfo:
 45    """収集したサーバー情報."""
 46
 47    hostname: str
 48    os_name: str
 49    kernel: str
 50    architecture: str
 51    cpu_count: int
 52    memory_total_gib: float
 53    memory_available_gib: float
 54    uptime_hours: float
 55    disks: list[DiskUsage] = field(default_factory=list)
 56
 57
 58def bytes_to_gib(value: int) -> float:
 59    """バイト数を GiB 単位に変換し、小数点以下 1 桁に丸める."""
 60    return round(value / 1024**3, 1)
 61
 62
 63def read_os_name(path: Path = OS_RELEASE_PATH) -> str:
 64    """/etc/os-release から PRETTY_NAME を読み取る."""
 65    try:
 66        for line in path.read_text(encoding="utf-8").splitlines():
 67            if line.startswith("PRETTY_NAME="):
 68                return line.split("=", 1)[1].strip().strip('"')
 69    except OSError:
 70        pass
 71    return "unknown"
 72
 73
 74def read_meminfo(path: Path = MEMINFO_PATH) -> dict[str, int]:
 75    """/proc/meminfo を読み取り、項目名と値 (バイト) の辞書を返す."""
 76    result: dict[str, int] = {}
 77    try:
 78        text = path.read_text(encoding="utf-8")
 79    except OSError:
 80        return result
 81    for line in text.splitlines():
 82        # 例: "MemTotal:        3836604 kB"
 83        name, _, rest = line.partition(":")
 84        parts = rest.split()
 85        if parts and parts[0].isdigit():
 86            result[name] = int(parts[0]) * 1024
 87    return result
 88
 89
 90def read_uptime_hours(path: Path = UPTIME_PATH) -> float:
 91    """/proc/uptime から稼働時間 (時間) を読み取る."""
 92    try:
 93        seconds = float(path.read_text(encoding="utf-8").split()[0])
 94    except (OSError, IndexError, ValueError):
 95        return 0.0
 96    return round(seconds / 3600, 1)
 97
 98
 99def collect_disks(mount_points: list[str]) -> list[DiskUsage]:
100    """指定したマウントポイントのディスク使用量を収集する.
101
102    存在しないマウントポイントは読み飛ばします。同じファイルシステム上の
103    ディレクトリ (例: /home が / と同じ) も、そのまま表示します。
104    """
105    disks: list[DiskUsage] = []
106    for mount_point in mount_points:
107        if not os.path.isdir(mount_point):
108            continue
109        usage = shutil.disk_usage(mount_point)
110        disks.append(
111            DiskUsage(
112                mount_point=mount_point,
113                total_gib=bytes_to_gib(usage.total),
114                used_gib=bytes_to_gib(usage.used),
115                free_gib=bytes_to_gib(usage.free),
116                used_percent=round(usage.used / usage.total * 100, 1),
117            )
118        )
119    return disks
120
121
122def collect(mount_points: list[str]) -> SystemInfo:
123    """サーバー情報を収集する."""
124    meminfo = read_meminfo()
125    uname = platform.uname()
126    return SystemInfo(
127        hostname=socket.gethostname(),
128        os_name=read_os_name(),
129        kernel=uname.release,
130        architecture=uname.machine,
131        cpu_count=os.cpu_count() or 0,
132        memory_total_gib=bytes_to_gib(meminfo.get("MemTotal", 0)),
133        memory_available_gib=bytes_to_gib(meminfo.get("MemAvailable", 0)),
134        uptime_hours=read_uptime_hours(),
135        disks=collect_disks(mount_points),
136    )
137
138
139def format_text(info: SystemInfo) -> str:
140    """人間向けの表形式の文字列を作成する."""
141    lines = [
142        f"ホスト名      : {info.hostname}",
143        f"OS            : {info.os_name}",
144        f"カーネル      : {info.kernel} ({info.architecture})",
145        f"CPU 数        : {info.cpu_count}",
146        f"メモリ        : {info.memory_available_gib} GiB 利用可能"
147        f" / {info.memory_total_gib} GiB",
148        f"稼働時間      : {info.uptime_hours} 時間",
149        "ディスク      :",
150    ]
151    for disk in info.disks:
152        lines.append(
153            f"  {disk.mount_point:<10} {disk.used_gib:>7} GiB 使用"
154            f" / {disk.total_gib:>7} GiB ({disk.used_percent}%)"
155        )
156    return "\n".join(lines)
157
158
159def parse_args() -> argparse.Namespace:
160    """コマンドライン引数を解析する."""
161    parser = argparse.ArgumentParser(description="サーバーの基本情報を表示します。")
162    parser.add_argument(
163        "--json",
164        action="store_true",
165        help="JSON 形式で出力する",
166    )
167    parser.add_argument(
168        "--mount",
169        action="append",
170        metavar="PATH",
171        help="使用量を調べるマウントポイント (複数指定可)",
172    )
173    return parser.parse_args()
174
175
176def main() -> None:
177    """エントリーポイント."""
178    args = parse_args()
179    mount_points: list[str] = args.mount or DEFAULT_MOUNT_POINTS
180    info = collect(mount_points)
181    if args.json:
182        print(json.dumps(asdict(info), ensure_ascii=False, indent=2))
183    else:
184        print(format_text(info))
185
186
187if __name__ == "__main__":
188    main()

18.4. サンプル 2: ログの集計

journald のログを発生元と優先度ごとに集計し、エラーや警告の多い発生元を一覧表示するスクリプトです。journalctl -o json の出力（「ログと監視」を参照）を 1 行ずつ JSON として解析しています。

リスト 18.2 journal_summary.py
  1#!/usr/bin/env python3
  2"""journalctl のログを集計して、エラーの多い発生元を一覧表示するスクリプト.
  3
  4journalctl の JSON 出力 (1 行 1 エントリー) を読み込み、
  5発生元 (SYSLOG_IDENTIFIER) ごとの件数を優先度別に集計します。
  6
  7使い方:
  8    # 直近 24 時間の warning 以上のログを集計する (journalctl を内部で実行)
  9    python3 journal_summary.py --since "24 hours ago"
 10
 11    # 保存済みの JSON ファイルを集計する
 12    journalctl -o json --since today > today.json
 13    python3 journal_summary.py --file today.json
 14
 15注意:
 16    他のユーザーやシステムのログを読むには、root 権限か
 17    systemd-journal グループ (または wheel グループ) への所属が必要です。
 18"""
 19
 20from __future__ import annotations
 21
 22import argparse
 23import json
 24import subprocess
 25import sys
 26from collections import Counter
 27from collections.abc import Iterable, Iterator
 28from pathlib import Path
 29
 30# journald の優先度 (数値が小さいほど重大)
 31PRIORITY_NAMES: dict[int, str] = {
 32    0: "emerg",
 33    1: "alert",
 34    2: "crit",
 35    3: "err",
 36    4: "warning",
 37    5: "notice",
 38    6: "info",
 39    7: "debug",
 40}
 41
 42
 43def run_journalctl(since: str, max_priority: int) -> Iterator[str]:
 44    """journalctl を実行し、JSON 形式の出力を 1 行ずつ返す."""
 45    command = [
 46        "journalctl",
 47        "--output=json",
 48        "--no-pager",
 49        f"--since={since}",
 50        f"--priority={max_priority}",
 51    ]
 52    try:
 53        completed = subprocess.run(
 54            command,
 55            capture_output=True,
 56            text=True,
 57            check=True,
 58        )
 59    except FileNotFoundError:
 60        sys.exit("journalctl が見つかりません。Linux 上で実行してください。")
 61    except subprocess.CalledProcessError as error:
 62        sys.exit(f"journalctl の実行に失敗しました: {error.stderr.strip()}")
 63    yield from completed.stdout.splitlines()
 64
 65
 66def read_file(path: Path) -> Iterator[str]:
 67    """保存済みの JSON ファイルを 1 行ずつ返す."""
 68    with path.open(encoding="utf-8") as file:
 69        for line in file:
 70            yield line
 71
 72
 73def summarize(
 74    lines: Iterable[str], max_priority: int
 75) -> Counter[tuple[str, str]]:
 76    """(発生元, 優先度名) ごとの件数を数える.
 77
 78    JSON として解釈できない行や、max_priority より重要度の低い行は
 79    読み飛ばします。
 80    """
 81    counter: Counter[tuple[str, str]] = Counter()
 82    for line in lines:
 83        line = line.strip()
 84        if not line:
 85            continue
 86        try:
 87            entry = json.loads(line)
 88        except json.JSONDecodeError:
 89            continue
 90        try:
 91            priority = int(entry.get("PRIORITY", 6))
 92        except (TypeError, ValueError):
 93            continue
 94        if priority > max_priority:
 95            continue
 96        source = str(
 97            entry.get("SYSLOG_IDENTIFIER") or entry.get("_COMM") or "unknown"
 98        )
 99        counter[(source, PRIORITY_NAMES.get(priority, str(priority)))] += 1
100    return counter
101
102
103def print_report(counter: Counter[tuple[str, str]], top: int) -> None:
104    """集計結果を件数の多い順に表示する."""
105    if not counter:
106        print("該当するログはありません。")
107        return
108    print(f"{'COUNT':>8}  {'PRIORITY':<10}  SOURCE")
109    for (source, priority), count in counter.most_common(top):
110        print(f"{count:>8}  {priority:<10}  {source}")
111
112
113def parse_args() -> argparse.Namespace:
114    """コマンドライン引数を解析する."""
115    parser = argparse.ArgumentParser(
116        description="journald のログを発生元と優先度ごとに集計します。"
117    )
118    parser.add_argument(
119        "--since",
120        default="24 hours ago",
121        help='集計を開始する日時 (journalctl の --since 形式、既定値: "24 hours ago")',
122    )
123    parser.add_argument(
124        "--priority",
125        type=int,
126        default=4,
127        choices=range(0, 8),
128        help="集計対象とする最も低い優先度 (0-7、既定値: 4 = warning)",
129    )
130    parser.add_argument(
131        "--top",
132        type=int,
133        default=20,
134        help="表示する件数の上限 (既定値: 20)",
135    )
136    parser.add_argument(
137        "--file",
138        type=Path,
139        help="journalctl -o json の出力を保存したファイル",
140    )
141    return parser.parse_args()
142
143
144def main() -> None:
145    """エントリーポイント."""
146    args = parse_args()
147    if args.file is not None:
148        lines = read_file(args.file)
149    else:
150        lines = run_journalctl(args.since, args.priority)
151    print_report(summarize(lines, args.priority), args.top)
152
153
154if __name__ == "__main__":
155    main()

subprocess.run で journalctl を実行し、その出力を処理しています。外部のコマンドを実行する場合は、この例のように引数をリストで渡してください。文字列で渡して shell=True を指定すると、引数に含まれる記号がシェルに解釈され、意図しないコマンドが実行される危険があります。

18.5. サンプル 3: サービスの監視

指定した systemd のサービスが稼働しているかを確認し、停止しているサービスがあれば終了コード 1 で終了するスクリプトです。--restart を指定すると、停止しているサービスの再起動を試みます。

リスト 18.3 service_monitor.py
  1#!/usr/bin/env python3
  2"""systemd サービスの稼働状態を確認するスクリプト.
  3
  4指定したサービスが active (稼働中) かどうかを systemctl で確認し、
  5結果を一覧表示します。1 つでも停止しているサービスがあれば
  6終了コード 1 で終了するため、systemd タイマーや cron から定期実行し、
  7監視の仕組みと組み合わせて利用できます。
  8
  9使い方:
 10    python3 service_monitor.py sshd chronyd nginx
 11    python3 service_monitor.py --restart nginx   # 停止していたら再起動を試みる
 12
 13注意:
 14    --restart を指定する場合は root 権限 (sudo) が必要です。
 15"""
 16
 17from __future__ import annotations
 18
 19import argparse
 20import logging
 21import subprocess
 22import sys
 23from dataclasses import dataclass
 24
 25logger = logging.getLogger("service_monitor")
 26
 27
 28@dataclass
 29class ServiceStatus:
 30    """サービスの確認結果."""
 31
 32    name: str
 33    state: str
 34
 35    @property
 36    def is_active(self) -> bool:
 37        """サービスが稼働中かどうか."""
 38        return self.state == "active"
 39
 40
 41def get_state(service: str) -> str:
 42    """systemctl is-active でサービスの状態を取得する.
 43
 44    戻り値は active, inactive, failed, activating などの文字列です。
 45    サービスが存在しない場合は inactive が返ります。
 46    """
 47    try:
 48        completed = subprocess.run(
 49            ["systemctl", "is-active", service],
 50            capture_output=True,
 51            text=True,
 52            check=False,
 53        )
 54    except FileNotFoundError:
 55        sys.exit("systemctl が見つかりません。systemd 環境で実行してください。")
 56    # is-active は停止中のとき終了コードが 0 以外になるため、
 57    # 終了コードではなく標準出力の文字列で判定する
 58    return completed.stdout.strip() or "unknown"
 59
 60
 61def restart(service: str) -> bool:
 62    """サービスを再起動し、成功したかどうかを返す."""
 63    completed = subprocess.run(
 64        ["systemctl", "restart", service],
 65        capture_output=True,
 66        text=True,
 67        check=False,
 68    )
 69    if completed.returncode != 0:
 70        logger.error(
 71            "%s の再起動に失敗しました: %s", service, completed.stderr.strip()
 72        )
 73        return False
 74    logger.info("%s を再起動しました", service)
 75    return True
 76
 77
 78def check_services(
 79    services: list[str], do_restart: bool
 80) -> list[ServiceStatus]:
 81    """サービスの状態を確認し、必要に応じて再起動する."""
 82    results: list[ServiceStatus] = []
 83    for service in services:
 84        status = ServiceStatus(name=service, state=get_state(service))
 85        if not status.is_active and do_restart and restart(service):
 86            status = ServiceStatus(name=service, state=get_state(service))
 87        results.append(status)
 88    return results
 89
 90
 91def parse_args() -> argparse.Namespace:
 92    """コマンドライン引数を解析する."""
 93    parser = argparse.ArgumentParser(
 94        description="systemd サービスの稼働状態を確認します。"
 95    )
 96    parser.add_argument(
 97        "services",
 98        nargs="+",
 99        metavar="SERVICE",
100        help="確認するサービス名 (例: sshd nginx)",
101    )
102    parser.add_argument(
103        "--restart",
104        action="store_true",
105        help="停止しているサービスの再起動を試みる",
106    )
107    return parser.parse_args()
108
109
110def main() -> int:
111    """エントリーポイント. 全サービスが稼働中なら 0、それ以外は 1 を返す."""
112    logging.basicConfig(
113        level=logging.INFO, format="%(levelname)s: %(message)s"
114    )
115    args = parse_args()
116    results = check_services(args.services, args.restart)
117
118    for status in results:
119        mark = "OK  " if status.is_active else "NG  "
120        print(f"{mark}{status.name:<24}{status.state}")
121
122    stopped = [status.name for status in results if not status.is_active]
123    if stopped:
124        logger.warning("停止しているサービス: %s", ", ".join(stopped))
125        return 1
126    return 0
127
128
129if __name__ == "__main__":
130    sys.exit(main())

このスクリプトを「systemd タイマー」で説明したタイマーから定期的に実行すると、簡易的な監視の仕組みになります。終了コードが 0 以外の場合、サービスは「失敗」として記録されるため、systemctl --failed や journalctl で確認できます。

18.6. コードの品質の確認

Python のコードは、PEP 8 というスタイルガイドに従って書くと、他の人にも読みやすくなります。本章のサンプルは、次のツールで問題がないことを確認しています。

ツール

内容

flake8

PEP 8 への違反や、使っていない変数などの問題を検出する

型ヒントに基づいて、型の誤りを検出する

--strict は、型ヒントの付け忘れなども含めて厳しく検査するオプションです。運用で使うスクリプトは長期間にわたって使われ、多くの人が修正することになるため、型ヒントを付けて検査しておくと、修正による誤りを早期に発見できます。
