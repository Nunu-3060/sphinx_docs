2. Rocky Linux の概要

この章では、Rocky Linux がどのような経緯で生まれ、どのような特徴を持つディストリビューションなのかを説明します。

2.1. Rocky Linux とは

Rocky Linux は、RHEL （Red Hat Enterprise Linux）と互換性を持つように開発されている、無償で利用できる Linux ディストリビューションです。RHEL と同じソースコードからビルドされているため、RHEL 向けに作られたソフトウェアや手順の多くを、そのまま Rocky Linux で利用できます。

Rocky Linux はサーバー用途を主な対象としており、次のような特徴があります。

  • 1 つのメジャーバージョンを約 10 年間使い続けられる、長いサポート期間

  • RHEL との高い互換性

  • 商用サブスクリプションが不要で、誰でも無償で利用できること

  • 特定の企業ではなく、コミュニティと財団によって運営されていること

2.2. 誕生の経緯

Rocky Linux の誕生には、CentOS Linux の方針転換が深く関係しています。

CentOS Linux は、RHEL のソースコードからビルドされた無償のディストリビューションとして、長年にわたりサーバー用途で広く使われてきました。しかし 2020 年 12 月、CentOS プロジェクトは開発の中心を CentOS Linux から CentOS Stream へ移すことを発表しました。CentOS Stream は RHEL の次のマイナーバージョンの開発版に当たるもので、RHEL と完全に同じ内容ではありません。この発表により、CentOS Linux 8 のサポートは当初の予定より大幅に早い 2021 年 12 月 31 日で終了しました。

これを受けて、CentOS の創設者の 1 人である Gregory Kurtzer 氏が、CentOS Linux の役割を引き継ぐ新しいディストリビューションとして Rocky Linux の開発を始めました。名前は CentOS の共同創設者で、すでに亡くなっていた Rocky McGaugh 氏にちなんで付けられています。最初の安定版である Rocky Linux 8.4 は 2021 年 6 月に公開されました。

2.3. RHEL との互換性

Rocky Linux は、RHEL と「バグまで含めて同じ動作をする」ことを目標に開発されています。具体的には、RHEL と同じソースコードを使い、Red Hat の商標やロゴなどを取り除いたうえでビルドしています。このため、次のような RHEL 向けの資産を Rocky Linux でも利用できます。

  • RHEL 向けに提供されている RPM パッケージやソフトウェア

  • RHEL の公式ドキュメントに書かれた手順

  • RHEL の資格試験（RHCSA など）のための学習内容

2023 年に Red Hat は RHEL のソースコードの公開方法を変更しましたが、Rocky Linux は互換性を維持したまま開発を続けています。

2.4. RHEL との違い

技術的には RHEL とほぼ同じですが、利用条件やサポートの面では次のような違いがあります。

表 2.1 RHEL と Rocky Linux の違い

項目

業務システムで利用する場合は、使用するミドルウェアやハードウェアが Rocky Linux での動作をサポートしているかを事前に確認してください。

2.5. 運営体制

Rocky Linux は、RESF （Rocky Enterprise Software Foundation）が運営しています。RESF は公益を目的とする法人として設立されており、特定の企業の方針によって Rocky Linux の開発が左右されないようにしています。開発作業は世界中のボランティアと、スポンサー企業から派遣された技術者によって行われています。

2.6. バージョン番号とサポート期間

Rocky Linux のバージョン番号は「メジャーバージョン.マイナーバージョン」の形式です。

  • メジャーバージョン（例: 9、10）は、RHEL のメジャーバージョンに対応します。カーネルや主要なライブラリのバージョンが大きく変わるため、メジャーバージョン間では互換性が保証されません。

  • マイナーバージョン（例: 10.0、10.1）は、RHEL のマイナーバージョンの公開から少し遅れて、約 6 か月ごとに公開されます。同じメジャーバージョン内では互換性が保たれ、dnf によるパッケージの更新でマイナーバージョンが上がります。

現在のバージョンは次のコマンドで確認できます。

1$ cat /etc/rocky-release
2Rocky Linux release 10.2 (Red Quartz)

各メジャーバージョンのサポート期間は次のとおりです。「通常サポート」の期間中は不具合の修正と機能の追加が行われ、その後の「セキュリティサポート」の期間中はセキュリティの修正のみが提供されます。

2.7. 他のディストリビューションとの比較

Rocky Linux と関係の深い、主なディストリビューションを比較します。

表 2.3 主なディストリビューションの比較

ディストリビューション

特徴

Rocky Linux との関係

RHEL

Red Hat が開発する商用のディストリビューション

Rocky Linux の互換の対象

CentOS Stream

RHEL の次のマイナーバージョンの開発版。RHEL より先に変更が反映される

RHEL 系のディストリビューションは、Fedora → CentOS Stream → RHEL → Rocky Linux などの互換ディストリビューション、という流れで開発されています。

2.8. Rocky Linux 10 の主な変更点

Rocky Linux 10 では、RHEL 10 に合わせて多くの変更が加えられました。インターネット上の情報の多くは Rocky Linux 8 や 9 を前提にしているため、次の変更点を知っておくと混乱を避けられます。

表 2.4 Rocky Linux 10 の主な変更点

項目

内容

CPU の要件

x86_64 版は x86-64-v3 以上の命令セットに対応した CPU が必要になりました。古い CPU や、CPU の機能を十分に公開しない仮想化環境ではインストールできません（「インストール」を参照）。

対応アーキテクチャ

x86_64、aarch64、ppc64le、s390x に加えて、RISC-V（riscv64）に対応しました。

32 ビットのパッケージ

x86_64 版で、32 ビットのアプリケーションを動かすための互換ライブラリ（i686 のパッケージ）が提供されなくなりました。

主要なソフトウェアのバージョン

カーネル 6.12、Python 3.12、GNOME 47 などに更新されました。

モジュールストリームの廃止

Rocky Linux 8 と 9 にあった、dnf module コマンドで同じソフトウェアの別バージョンを切り替える仕組みが廃止されました（「パッケージ管理」を参照）。

ネットワーク設定ファイルの形式

/etc/sysconfig/network-scripts/ の ifcfg 形式と、ifup / ifdown コマンドが使用できなくなり、keyfile 形式に一本化されました（「ネットワーク」を参照）。

デスクトップ環境

X.Org サーバーが削除され、Wayland に一本化されました。X11 用のアプリケーションは Xwayland 上で動作します（「デスクトップ環境の利用」を参照）。

インストーラーの既定値

root アカウントは既定で無効になり、インストール時に作成する一般ユーザーを管理者として使います（「インストール」を参照）。また、インストーラーをリモートから GUI で操作する手段が VNC から RDP に変わりました。

メジャーバージョンをまたぐアップグレードはサポートされていないため、Rocky Linux 8 や 9 から移行する場合は、新しくインストールする必要があります（「更新とアップグレードの方針」を参照）。

これらのほかにも細かな変更が多数あります。詳細は Rocky Linux 10 のリリースノートと、RHEL 10 のドキュメントを参照してください（「付録 D 参考文献」を参照）。
