17. 総合演習: nginx による Web サーバーの構築

この章では、これまでの章で学んだ内容を組み合わせて、nginx による Web サーバーを構築します。パッケージの導入、サービスの管理、firewalld、SELinux、ログの確認を、実際の作業の流れの中で使います。

17.1. 構築する環境

この章では、次の 3 つの機能を持つ Web サーバーを構築します。

表 17.1 構築する Web サーバーの機能

機能

内容

静的コンテンツの配信

/srv/www/example に置いた HTML ファイルを http://www.example.com/ で配信する

HTTPS 化

Let's Encrypt の証明書を使い、https://www.example.com/ で配信する

リバースプロキシ

http://app.example.com/ へのアクセスを、同じサーバーで動くアプリケーション（127.0.0.1:8000）に転送する

ホスト名 www.example.com と app.example.com は、実際に使うホスト名に置き換えてください。社内のネットワークで試す場合は、クライアント PC の hosts ファイル（Windows では C:\Windows\System32\drivers\etc\hosts）に、サーバーの IP アドレスとホスト名を登録すると、DNS を設定しなくても名前でアクセスできます。

17.2. nginx の導入と起動

nginx を導入し、起動と自動起動の設定を行います（「パッケージ管理」、「プロセスとサービスの管理」を参照）。

1$ sudo dnf install nginx
2$ sudo systemctl enable --now nginx
3$ systemctl status nginx
4$ curl -I http://localhost/

curl の結果に HTTP/1.1 200 OK と表示されれば、nginx は動作しています。この時点では、nginx に付属するテストページが表示されます。

17.3. ファイアウォールの設定

クライアント PC からアクセスできるよう、firewalld で HTTP と HTTPS を許可します（「セキュリティ」を参照）。

1$ sudo firewall-cmd --permanent --add-service=http --add-service=https
2$ sudo firewall-cmd --reload
3$ sudo firewall-cmd --list-services

クライアント PC の Web ブラウザーで http://<サーバーの IP アドレス>/ にアクセスし、テストページが表示されることを確認します。

17.4. コンテンツの配置と SELinux の設定

Web コンテンツを /srv/www/example に配置します。nginx の既定の公開ディレクトリは /usr/share/nginx/html ですが、パッケージが管理するディレクトリと分けておくと、管理しやすくなります。

1$ sudo mkdir -p /srv/www/example
2$ echo '<h1>nginx on Rocky Linux 10</h1>' | sudo tee /srv/www/example/index.html
3$ ls -Z /srv/www/example/index.html
4unconfined_u:object_r:var_t:s0 /srv/www/example/index.html

3 行目の結果のとおり、/srv の配下に作成したファイルには var_t タイプのラベルが付いています。nginx（httpd_t タイプのプロセス）はこのラベルのファイルを読めないため、このままでは nginx が 403 Forbidden のエラーを返します。Web コンテンツ用の httpd_sys_content_t タイプを設定します（「SELinux」を参照）。

1$ sudo dnf install policycoreutils-python-utils
2$ sudo semanage fcontext -a -t httpd_sys_content_t "/srv/www(/.*)?"
3$ sudo restorecon -Rv /srv/www
4$ ls -Z /srv/www/example/index.html
5unconfined_u:object_r:httpd_sys_content_t:s0 /srv/www/example/index.html

17.5. nginx の設定

nginx の設定ファイルは /etc/nginx/nginx.conf です。このファイルは /etc/nginx/conf.d/*.conf を読み込むようになっているため、サイトごとの設定は /etc/nginx/conf.d/ にファイルを作成して記述します。

次に、/srv/www/example のコンテンツを配信する設定の例を示します。

リスト 17.1 /etc/nginx/conf.d/example.conf
 1# ------------------------------------------------------------
 2# example.conf - 静的コンテンツを配信する nginx の設定例
 3#
 4# 第 17 章で使用します。/etc/nginx/conf.d/ に配置します。
 5# server_name は実際のホスト名に変更してください。
 6# ------------------------------------------------------------
 7server {
 8    listen       80;
 9    listen       [::]:80;
10    server_name  www.example.com;
11
12    # コンテンツの配置場所
13    root         /srv/www/example;
14    index        index.html;
15
16    # アクセスログとエラーログ
17    access_log   /var/log/nginx/example.access.log;
18    error_log    /var/log/nginx/example.error.log;
19
20    # レスポンスヘッダーに nginx のバージョンを出さない
21    server_tokens off;
22
23    location / {
24        try_files $uri $uri/ =404;
25    }
26}

表 17.2 設定の主な項目

項目

意味

server

1 つのサイト（仮想ホスト）の設定のまとまり

listen

待ち受けるポート。[::]:80 は IPv6 での待ち受け

server_name

このサイトとして応答するホスト名。リクエストの Host ヘッダーと照合される

root

コンテンツを置くディレクトリ

location

URL のパスごとの処理。try_files は、指定した順にファイルを探し、見つからなければ 404 を返す

設定ファイルを配置したら、文法を検査してから再読み込みします。

1$ sudo nginx -t
2nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
3nginx: configuration file /etc/nginx/nginx.conf test is successful
4$ sudo systemctl reload nginx
5$ curl -H "Host: www.example.com" http://localhost/
6<h1>nginx on Rocky Linux 10</h1>

5 行目では、DNS を設定していなくても動作を確認できるよう、-H で Host ヘッダーを指定しています。

ここまでの手順をまとめて実行するスクリプトを次に示します。

リスト 17.2 setup_nginx.sh
 1#!/usr/bin/env bash
 2# ------------------------------------------------------------
 3# setup_nginx.sh - nginx による Web サーバーを構築するスクリプト
 4#
 5# 第 17 章「総合演習: nginx による Web サーバーの構築」の手順
 6# (HTTPS 化を除く) をまとめて実行します。
 7#   1. nginx を導入して自動起動を有効にする
 8#   2. firewalld で HTTP と HTTPS を許可する
 9#   3. /srv/www/example にコンテンツを配置し、SELinux のラベルを設定する
10#   4. examples/nginx/example.conf を /etc/nginx/conf.d/ に配置する
11#   5. 設定を検査して nginx を再読み込みする
12#
13# 使い方:
14#   本スクリプトと example.conf を同じディレクトリに置き、次を実行します。
15#   sudo bash setup_nginx.sh
16# ------------------------------------------------------------
17set -euo pipefail
18
19if [[ $EUID -ne 0 ]]; then
20    echo "root 権限で実行してください" >&2
21    exit 1
22fi
23
24SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
25CONF_SOURCE="${SCRIPT_DIR}/example.conf"
26DOC_ROOT="/srv/www/example"
27
28if [[ ! -f "${CONF_SOURCE}" ]]; then
29    echo "${CONF_SOURCE} が見つかりません" >&2
30    exit 1
31fi
32
33echo "=== 1. nginx を導入します ==="
34dnf -y install nginx policycoreutils-python-utils
35systemctl enable --now nginx
36
37echo "=== 2. ファイアウォールで HTTP と HTTPS を許可します ==="
38firewall-cmd --permanent --add-service=http --add-service=https
39firewall-cmd --reload
40
41echo "=== 3. コンテンツを配置します ==="
42mkdir -p "${DOC_ROOT}"
43cat > "${DOC_ROOT}/index.html" << 'EOF'
44<!DOCTYPE html>
45<html lang="ja">
46<head><meta charset="utf-8"><title>Rocky Linux 入門</title></head>
47<body><h1>nginx on Rocky Linux 10</h1></body>
48</html>
49EOF
50# /srv 配下は既定で Web サーバーから読めないラベルのため、ラベルを設定する
51semanage fcontext -a -t httpd_sys_content_t "/srv/www(/.*)?" \
52    || semanage fcontext -m -t httpd_sys_content_t "/srv/www(/.*)?"
53restorecon -Rv /srv/www
54
55echo "=== 4. 設定ファイルを配置します ==="
56install -m 644 "${CONF_SOURCE}" /etc/nginx/conf.d/example.conf
57
58echo "=== 5. 設定を検査して再読み込みします ==="
59nginx -t
60systemctl reload nginx
61
62echo "完了しました。curl -I http://localhost/ で動作を確認してください。"

17.6. HTTPS 化

Web サイトを HTTPS で配信するには、サーバー証明書が必要です。ここでは、無償で証明書を発行する認証局である Let's Encrypt の証明書を、certbot というツールで取得します。

17.6.1. 前提条件

Let's Encrypt の証明書を取得するには、次の条件を満たす必要があります。

  • www.example.com が、インターネットの DNS でこのサーバーのグローバル IP アドレスに名前解決できること

  • インターネットからこのサーバーの 80 番ポートにアクセスできること（Let's Encrypt がドメインの所有を確認するために使う）

社内のネットワークだけで使うサーバーなど、この条件を満たせない場合は、社内の認証局で発行した証明書や、自己署名の証明書を使ってください。その場合の nginx の設定は、次の「証明書の取得」で certbot が自動で追加する設定と同じ形式で、証明書のファイルの場所を指定します。

17.6.2. 証明書の取得

certbot と nginx 用のプラグインは EPEL で提供されています（「EPEL の導入」を参照）。

1$ sudo dnf install certbot python3-certbot-nginx
2$ sudo certbot --nginx -d www.example.com

certbot を実行すると、メールアドレスの入力と利用規約への同意を求められます。証明書の取得に成功すると、certbot は /etc/nginx/conf.d/example.conf に HTTPS の設定と、HTTP から HTTPS へ転送する設定を自動で追加し、nginx を再読み込みします。取得した証明書は /etc/letsencrypt/live/www.example.com/ に保存されます。

17.6.3. 証明書の自動更新

Let's Encrypt の証明書の有効期間は短いため、定期的に更新する必要があります。EPEL の certbot パッケージには、更新を行う systemd タイマーが含まれています。

1$ sudo systemctl enable --now certbot-renew.timer
2$ systemctl list-timers certbot-renew.timer
3$ sudo certbot renew --dry-run

3 行目の --dry-run は、実際には更新せずに、更新の手順が正しく動作するかを確認します。

17.7. リバースプロキシの設定

リバースプロキシは、クライアントからのリクエストを受け取り、背後にある別のサーバーやアプリケーションに転送する仕組みです。アプリケーションの前に nginx を置くと、HTTPS の処理、静的ファイルの配信、アクセスログの記録などを nginx に任せられます。

17.7.1. 転送先のアプリケーションの準備

ここでは動作確認のため、Python に標準で付属する簡易 Web サーバーを、転送先のアプリケーションとして使います。別の端末で次のコマンドを実行し、127.0.0.1 の 8000 番ポートで待ち受けます。

1$ mkdir -p ~/app && echo 'Hello from backend' > ~/app/index.html
2$ python3 -m http.server 8000 --bind 127.0.0.1 --directory ~/app

127.0.0.1 で待ち受けているため、このアプリケーションには外部から直接アクセスできず、nginx を経由した場合だけアクセスできます。

17.7.2. nginx の設定

次に、app.example.com へのアクセスを 127.0.0.1:8000 に転送する設定の例を示します。

リスト 17.3 /etc/nginx/conf.d/reverse_proxy.conf
 1# ------------------------------------------------------------
 2# reverse_proxy.conf - nginx をリバースプロキシとして使う設定例
 3#
 4# 第 17 章で使用します。/etc/nginx/conf.d/ に配置します。
 5# http://app.example.com/ へのアクセスを、同じサーバーの
 6# 127.0.0.1:8000 で待ち受けるアプリケーションへ転送します。
 7#
 8# SELinux が有効な環境では、nginx から他のポートへの接続を許可する必要があります。
 9#   sudo setsebool -P httpd_can_network_connect on
10# ------------------------------------------------------------
11upstream app_backend {
12    server 127.0.0.1:8000;
13}
14
15server {
16    listen       80;
17    listen       [::]:80;
18    server_name  app.example.com;
19
20    access_log   /var/log/nginx/app.access.log;
21    error_log    /var/log/nginx/app.error.log;
22
23    server_tokens off;
24
25    location / {
26        proxy_pass http://app_backend;
27
28        # 転送先のアプリケーションに、元のリクエストの情報を伝える
29        proxy_set_header Host              $host;
30        proxy_set_header X-Real-IP         $remote_addr;
31        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
32        proxy_set_header X-Forwarded-Proto $scheme;
33
34        # 転送先の応答を待つ時間
35        proxy_connect_timeout 5s;
36        proxy_read_timeout    60s;
37    }
38}

reverse_proxy.conf をダウンロード

proxy_pass で転送先を指定し、proxy_set_header で元のリクエストの情報（クライアントの IP アドレスや、HTTP と HTTPS のどちらでアクセスされたか）を転送先に伝えています。

SELinux は、既定では Web サーバーが他のポートへ接続することを禁止しています。リバースプロキシとして使うには、ブール値 httpd_can_network_connect を有効にします（「SELinux」を参照）。

1$ sudo setsebool -P httpd_can_network_connect on
2$ sudo nginx -t
3$ sudo systemctl reload nginx
4$ curl -H "Host: app.example.com" http://localhost/
5Hello from backend
