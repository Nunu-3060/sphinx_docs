2. コンピューターアーキテクチャとは

この章では、本書の主題である「コンピューターアーキテクチャ」が何を指すのかを説明します。コンピューターは何層もの抽象化の上に成り立っており、アーキテクチャはそのうちハードウェアとソフトウェアの境界にあたる部分を扱います。特に、ソフトウェアとの約束事である「命令セットアーキテクチャ」と、それを実現する回路の構成である「マイクロアーキテクチャ」を区別することが、本書全体を理解する鍵になります。

後半では、プログラムとデータの置き場所に関するノイマン型とハーバード型の違い、アーキテクチャを設計するときに考えるトレードオフ、そしてソフトウェアのエンジニアがアーキテクチャを学ぶ意味を説明します。

2.1. 抽象化の階層

現代のコンピューターは、数十億個のトランジスタからなる回路の上で、数百万行のソフトウェアが動く巨大なシステムです。これを人間が設計し、理解できるのは、システムを複数の抽象化の階層（abstraction layers）に分け、各層が下の層の詳細を隠して、上の層に単純なインターフェースだけを見せているからです。

各層の役割は次のとおりです。

2.2. ISA とマイクロアーキテクチャ

コンピューターの「アーキテクチャ」という言葉の意味は、1964 年に IBM が System/360 を発表したときに、その設計者たちが論文の中で次のように定義しました（詳しくは「アーキテクチャの歴史」で説明します）。

プログラマーから見たシステムの属性、すなわち概念的な構造と機能的な振る舞いであり、データの流れや制御の構成、論理設計、物理的な実装とは区別されるもの。

この意味でのアーキテクチャが、現在命令セットアーキテクチャ（Instruction Set Architecture：ISA）と呼ばれるものです。ISA は、ソフトウェアとハードウェアの間の契約であり、次のようなことを定めます。

  • 命令の種類と、それぞれの命令の動作（加算、ロード、分岐など）。

  • 命令のビット列としての形式（エンコーディング）。

  • ソフトウェアから見えるレジスタの数と幅。

  • データの型と表現（整数の幅、浮動小数点数の形式、バイトオーダー）。

  • メモリのアドレスの付け方と、メモリアクセスの順序に関する規則（メモリモデル）。

  • 例外や割り込みが起きたときの動作、特権レベル。

これに対し、ISA を実際の回路としてどう実現するかをマイクロアーキテクチャ（microarchitecture）と呼びます。パイプラインの段数、同時に実行できる命令の数、キャッシュの容量と構成、分岐予測の方式などはマイクロアーキテクチャの選択であり、ISA には現れません。ヘネシーとパターソンの教科書では、マイクロアーキテクチャを構成（organization）とも呼び、ISA、構成、ハードウェア（論理設計や製造技術）の 3 つをあわせて広い意味のコンピューターアーキテクチャとしています。

2.2.1. 同じ ISA、異なる実装

ISA とマイクロアーキテクチャを分けたことの最大の利点は、同じソフトウェアを、性能や価格の異なるさまざまなハードウェアで動かせることです。現在の具体例をいくつか挙げます。

  • x86-64 は Intel と AMD の両社がプロセッサを製造しています。どちらの製品でも同じ Linux や Windows の実行ファイルが動きますが、パイプラインの構成、命令を同時に発行できる数、キャッシュの容量、分岐予測器の設計などは両社でまったく異なります。同じ会社の製品でも、世代ごとにマイクロアーキテクチャは大きく変わります。

  • AArch64 は Arm が ISA を定め、他社にライセンスしています。Arm 自身が設計した Cortex シリーズのコアのほか、Apple の M シリーズのように、ライセンスを受けた企業が独自に設計したコアもあります。

  • RISC-V は仕様が公開されたオープンな ISA で、授業用の小さなパイプラインから、高性能なアウトオブオーダー実行のコアまで、多様な実装があります。

ISA が同じなら、プログラムは「正しく動く」ことが保証されます。しかし「どれだけ速く動くか」はマイクロアーキテクチャによって決まります。同じ実行ファイルでも、プロセッサによって実行時間が数倍違うことは珍しくありません。また、性能を追求したプログラムは、特定のマイクロアーキテクチャのキャッシュの容量やパイプラインの特性に合わせてチューニングされることがあります。

2.2.2. アーキテクチャとして見えるもの、見えないもの

どこまでが ISA でどこからがマイクロアーキテクチャかは、「ソフトウェアがその違いを観測して、正しさが変わるか」で判断できます。

2.3. ノイマン型とハーバード型

プログラムとデータをどこに置くかという観点から、コンピューターの構成は 2 つの型に分けられます。

2.3.1. ノイマン型

1945 年にフォン・ノイマンがまとめた報告書に基づく構成をノイマン型（von Neumann architecture）と呼びます。その特徴は、命令とデータを同じメモリに格納し（プログラム内蔵方式、stored-program）、同じ経路で読み出すことです。プログラムもデータもメモリ上のビット列にすぎないので、プログラムを読み込んでから実行したり、コンパイラが生成した機械語をそのまま実行したりできます。現在のほとんどのコンピューターは、ソフトウェアから見るとノイマン型です。

ノイマン型では、命令の読み出しとデータの読み書きが 1 本の経路を共有するため、プロセッサとメモリの間の転送が性能の上限を決めがちです。この問題はノイマン・ボトルネック（von Neumann bottleneck）と呼ばれます。この言葉は、ジョン・バッカスが 1977 年度のチューリング賞の受賞講演（論文は 1978 年）で用いて広まったものです。プロセッサの速度の向上にメモリの速度の向上が追いつかないため、この問題は年々深刻になってきました。キャッシュをはじめとするメモリ階層は、この問題への対策です。

2.3.2. ハーバード型

これに対し、命令とデータを別々のメモリに格納し、別々の経路で読み出す構成をハーバード型（Harvard architecture）と呼びます。名前は、紙テープから命令を読み、データを別の装置に保持したリレー式計算機ハーバード Mark I に由来します。命令とデータを同時に読み出せるので、経路の競合がありません。現在でも、一部のマイクロコントローラや DSP（デジタル信号処理プロセッサ）は、プログラムをフラッシュメモリに、データを SRAM に置く、ハーバード型の構成をとっています。

2.3.3. 変形ハーバード型

現在の高性能なプロセッサは、両者を組み合わせた変形ハーバード型（modified Harvard architecture）をとっています。主記憶と、それに近い L2 以降のキャッシュは命令とデータで共有する（ノイマン型）一方で、プロセッサのコアに最も近い L1 キャッシュは命令キャッシュとデータキャッシュに分けています（ハーバード型）。

パイプラインで処理するプロセッサは、毎サイクル、命令の読み出しとデータのロード・ストアを同時に行います。L1 キャッシュを分けることで、この 2 つが競合せずに済みます。一方、ソフトウェアから見ると命令とデータは同じアドレス空間にあるので、プログラムを読み込んで実行するというノイマン型の柔軟さは失われません。

注釈

命令キャッシュとデータキャッシュが分かれていると、プログラムが自分で書き込んだ命令（JIT コンパイラが生成した機械語など）を実行するときに注意が必要です。書き込みはデータキャッシュに入るので、命令キャッシュとの一貫性を保つ操作が必要になることがあります。RISC-V では fence.i 命令がこの目的のために用意されています。

2.4. 設計上のトレードオフ

アーキテクチャの設計は、互いに対立する複数の目標の間で折り合いをつける作業です。主な目標は次のとおりです。

第 3 章、第 6 章

これらの目標は互いに対立します。たとえば、キャッシュの容量を 2 倍にすればキャッシュミスが減って性能は上がりますが、面積と電力が増え、アクセスにかかるサイクル数も増えるかもしれません。アウトオブオーダー実行は 1 サイクルあたりに実行できる命令の数を増やしますが、そのための回路は大きく、電力を多く消費します。

どの目標を重視するかは、製品の用途によって変わります。

  • サーバー向けのプロセッサは、多数のコアと大容量のキャッシュを持ち、スループットを重視します。消費電力は数百ワットに達します。

  • スマートフォン向けのプロセッサは、電池の持ちと発熱の制約が厳しいため、電力あたりの性能を重視します。高性能なコアと省電力なコアを組み合わせる構成が一般的です。

  • マイクロコントローラは、家電や機器の制御に使われ、コストと消費電力が最も重視されます。パイプラインは数段程度で、キャッシュを持たないものも多くあります。

互換性は特に重い制約です。x86 の ISA は 1978 年の 8086 以来、過去の命令をほぼすべて残しながら拡張されてきました。そのため現在の x86-64 のプロセッサも、命令の長さが 1〜15 バイトと可変で、デコードが複雑になるという負担を抱えています。それでも、膨大なソフトウェア資産を動かせるという価値が、その負担を上回ってきました。逆に、互換性の制約から自由な新しい ISA を作っても、ソフトウェアがそろわなければ普及しません。このせめぎ合いは「アーキテクチャの歴史」で繰り返し登場します。

2.5. なぜエンジニアがアーキテクチャを学ぶのか

高水準言語でプログラムを書いていると、ハードウェアを意識する機会はあまりありません。それでも、次のような場面ではアーキテクチャの知識が欠かせません。

2.5.1. 性能のチューニング

同じ計算量のアルゴリズムでも、メモリアクセスのパターンによって実行時間は大きく変わります。次の 2 つの関数は、どちらも 2 次元配列のすべての要素の合計を求めますが、配列が大きい場合、行の順にたどる sum_rows のほうが、列の順にたどる sum_cols より数倍以上速くなるのが普通です。

 1#define N 4096
 2double a[N][N];
 3
 4double sum_rows(void) {          /* 行の順にたどる */
 5    double s = 0.0;
 6    for (int i = 0; i < N; i++)
 7        for (int j = 0; j < N; j++)
 8            s += a[i][j];
 9    return s;
10}
11
12double sum_cols(void) {          /* 列の順にたどる */
13    double s = 0.0;
14    for (int j = 0; j < N; j++)
15        for (int i = 0; i < N; i++)
16            s += a[i][j];
17    return s;
18}

C の 2 次元配列は行の順にメモリに並んでいます。sum_rows は連続したアドレスを順に読むので、キャッシュラインの残りの要素やハードウェアのプリフェッチを活かせます。sum_cols は 1 回ごとに \(4096 \times 8 = 32{,}768\) バイト離れたアドレスを読むので、ほぼ毎回キャッシュミスを起こします。理由は「メモリ階層とキャッシュ」で詳しく説明します。このほかにも、分岐予測が外れやすいコード、複数のコアが同じキャッシュラインに載った別々の変数に書き込む false sharing（偽共有）など、アーキテクチャを知らないと原因が分からない性能の問題は数多くあります。

2.5.2. 並行プログラミングのバグ

マルチスレッドのプログラムでは、あるスレッドが書き込んだ値が、他のスレッドからいつ、どの順序で見えるかが問題になります。プロセッサはストアバッファやアウトオブオーダー実行によってメモリアクセスの順序を入れ替えることがあり、どこまで入れ替えてよいかは ISA のメモリモデル（memory consistency model）が定めています。x86-64 は比較的強い順序を保証しますが、AArch64 や RISC-V はより弱い順序しか保証しません。そのため、x86-64 で正しく動いていたロックフリーのコードが、Arm のサーバーに移すと時々おかしな結果を出す、ということが起こります。詳しくは「並列アーキテクチャ」で説明します。

2.5.3. セキュリティ

前述の Spectre や Meltdown は、投機実行とキャッシュという、性能のためのマイクロアーキテクチャの仕組みが情報漏えいの経路になることを示しました。また、DRAM の特定の行に高い頻度でアクセスすると隣の行のビットが反転する Rowhammer という現象も知られています。こうした攻撃と対策を理解するには、ハードウェアの仕組みの知識が欠かせません。

2.5.4. ハードウェアの選択

クラウドでは、x86-64 と Arm の CPU、さまざまな GPU やアクセラレーターを選んで使えます。処理の性質（演算が多いのか、メモリアクセスが多いのか、並列化できるのか）とハードウェアの特徴を結び付けて考えられれば、より速く、より安く処理を実行できます。

2.6. この章のまとめ

  • コンピューターは、アプリケーションからトランジスタまでの抽象化の階層からなります。コンピューターアーキテクチャは、そのうち ISA とマイクロアーキテクチャを中心に扱います。

  • ISA はソフトウェアとハードウェアの契約であり、命令、レジスタ、データの表現、メモリモデルなどを定めます。マイクロアーキテクチャは ISA を実現する回路の構成です。

  • 同じ ISA でも実装は多様です（例: Intel と AMD の x86-64、Arm の Cortex と Apple の M シリーズ）。ISA は正しさを保証し、性能はマイクロアーキテクチャで決まります。

  • ノイマン型は命令とデータを同じメモリに置き、ハーバード型は分けて置きます。現在の高性能なプロセッサは、L1 キャッシュだけを命令用とデータ用に分ける変形ハーバード型です。

  • アーキテクチャの設計は、性能、電力、面積、コスト、互換性の間のトレードオフです。

  • 性能チューニング、並行プログラミング、セキュリティ、ハードウェアの選択のいずれにも、アーキテクチャの知識が役立ちます。
