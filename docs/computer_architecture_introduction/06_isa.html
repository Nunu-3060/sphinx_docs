6. 命令セットアーキテクチャ

プロセッサが実行できる命令の種類と形式、プログラムから見えるレジスタ、メモリの扱い方などを定めた仕様を命令セットアーキテクチャ（Instruction Set Architecture：ISA）と呼びます。ISA はソフトウェアとハードウェアの境界にある約束事です。コンパイラは ISA に従って機械語を生成し、プロセッサの設計者は ISA に従う限り内部の回路を自由に工夫できます。

この章では、ISA が定めるものを整理したあと、本書で例として使う RISC-V（RV32I）の命令形式、アドレッシングモード、主な命令を説明します。さらに、x86-64 と AArch64 と比較しながら RISC と CISC の違いを考え、最後に 1 つの命令を実際に 32 ビットの機械語に符号化してみます。

6.1. ISA が定めるもの

ISA は、プログラムを正しく実行するためにソフトウェアが知っておく必要のあることをすべて定めます。逆に、命令を何サイクルで実行するか、キャッシュがいくつあるかといった性能に関わる実装の詳細は ISA には含まれず、マイクロアーキテクチャ（microarchitecture）の側で決まります。ISA が定める主な項目は次のとおりです。

6.2. レジスタとレジスタファイル

レジスタ（register）は、プロセッサの内部にある少数の高速な記憶場所です。演算の入力と出力は原則としてレジスタに置きます。プログラムから番号で指定できるレジスタを汎用レジスタ（general-purpose register）と呼び、汎用レジスタをまとめて実装した回路をレジスタファイル（register file）と呼びます。

RV32I には 32 ビット幅の汎用レジスタが 32 本（x0〜x31）あります。命令の中でレジスタ番号を表すのに 5 ビット（\(2^5 = 32\)）を使います。x0 は特別なレジスタで、読むと常に 0 が返り、書き込みは無視されます。定数 0 がいつでも使えるため、「レジスタの値をコピーする」「何もしない」といった操作を専用の命令なしで表現できます。汎用レジスタとは別に、次に実行する命令のアドレスを保持するプログラムカウンタ（Program Counter：PC）があります。RISC-V の PC はプログラムから直接は読み書きできず、分岐やジャンプ命令、auipc命令を通じて間接的に扱います。

レジスタの本数は ISA の重要な設計判断です。本数が多いほど多くの変数をレジスタに置けてメモリアクセスが減りますが、レジスタ番号を表すビット数が増えて命令が長くなり、レジスタファイルも大きく遅くなります。32 本は、この兼ね合いから多くの RISC 型 ISA が選んでいる値です。レジスタファイルの回路は「論理回路の復習」で説明します。

6.3. 命令形式

RV32I の命令はすべて 32 ビットの固定長で、命令形式（instruction format）は R、I、S、B、U、J の 6 種類です。どの形式でも、下位 7 ビットが命令の種類を表すオペコード（opcode）で、レジスタ番号を表すフィールド rd（書き込み先）、rs1、rs2（読み出し元）は、使う形式では常に同じビット位置にあります。こうしておくと、命令の種類を判別する前にレジスタファイルの読み出しを始められるので、ハードウェアが単純で高速になります。

即値の扱いには次のような工夫があります。

  • 即値の最上位ビット（符号ビット）は、どの形式でも命令のビット 31 にあります。そのため、形式を判別する前に符号拡張の準備ができます。

  • I 形式の即値は 12 ビットの符号付き整数で、\(-2048\) から \(2047\) までを表せます。

  • B 形式と J 形式の即値は 2 の倍数（ビット 0 が常に 0）なので、ビット 0 を命令に含めず、その分だけ範囲を広げています。条件分岐は PC から約 \(\pm 4\) KiB、jal は約 \(\pm 1\) MiB の範囲に飛べます。

  • U 形式の即値は 32 ビットの上位 20 ビットを与えます。lui で上位 20 ビットを、addi で下位 12 ビットを設定すると、任意の 32 ビット定数を 2 命令で作れます。addi の即値は符号拡張されるので、定数のビット 11 が 1 のときは lui に渡す値を 1 だけ大きくして補正します（「機械語とプログラム」の擬似命令 li を参照）。

B 形式や J 形式の即値のビットの並びが不規則に見えるのは、S 形式や I 形式とできるだけ同じ位置に同じ即値ビットが来るように並べた結果です。人間には読みにくくなりますが、即値を組み立てるマルチプレクサが減り、ハードウェアが単純になります。

6.5. 主な命令

ここでは RV32I の命令を用途別に見ていきます。すべての命令の一覧は「付録：RISC-V RV32I 命令一覧」にあります。アセンブリ言語では、書き込み先のレジスタを最初に書くのが RISC-V の慣習です。

6.5.1. 算術論理命令

算術論理命令は、レジスタ同士（R 形式）またはレジスタと即値（I 形式）の間で演算します。

1add  x5, x6, x7     # x5 = x6 + x7
2sub  x5, x6, x7     # x5 = x6 - x7
3addi x5, x6, -1     # x5 = x6 - 1（subi はなく、負の即値を使う）
4and  x5, x6, x7     # ビットごとの AND
5ori  x5, x6, 0xff   # ビットごとの OR（即値）
6slli x5, x6, 2      # 左シフト（x5 = x6 * 4）
7srai x5, x6, 1      # 算術右シフト（符号付きの 2 での除算に近い）
8slt  x5, x6, x7     # 符号付きで x6 < x7 なら 1、そうでなければ 0
9lui  x5, 0x12345    # x5 = 0x12345000

加算と減算はオーバーフローしても例外を起こさず、結果の下位 32 ビットを残します。RV32I には乗算と除算の命令がなく、M 拡張（後述）で追加されます。

6.5.2. ロード命令とストア命令

メモリを読む命令をロード（load）、書く命令をストア（store）と呼びます。アドレスは「ベース + 変位」で指定します。

1lw   x5, 8(x6)      # x5 = メモリ[x6 + 8] の 4 バイト
2lb   x5, 0(x6)      # 1 バイト読み、符号拡張して 32 ビットにする
3lbu  x5, 0(x6)      # 1 バイト読み、ゼロ拡張して 32 ビットにする
4sw   x5, 12(x6)     # メモリ[x6 + 12] に x5 の 4 バイトを書く
5sb   x5, 3(x6)      # x5 の下位 1 バイトを書く

1 バイトや 2 バイトの読み出しには、符号拡張する lb、lh と、ゼロ拡張する lbu、lhu があります。C 言語の signed char と unsigned char の区別は、この命令の使い分けとして機械語に現れます。RISC-V はリトルエンディアンで、ワードの最下位バイトが最も小さいアドレスに置かれます。

6.5.3. 分岐命令とジャンプ命令

条件分岐命令は 2 つのレジスタを比較し、条件が成り立てば PC 相対のアドレスへ分岐します。比較と分岐が 1 命令になっていて、比較結果を保持するフラグ（flag）を使わないのが RISC-V の特徴です。

1beq  x5, x6, L1     # x5 == x6 なら L1 へ
2bne  x5, x0, L1     # x5 != 0 なら L1 へ
3blt  x5, x6, L1     # 符号付きで x5 < x6 なら L1 へ
4bgeu x5, x6, L1     # 符号なしで x5 >= x6 なら L1 へ
5jal  x1, func       # x1 = PC + 4 として func へジャンプ（関数呼び出し）
6jalr x0, 0(x1)      # x1 + 0 のアドレスへジャンプ（関数からの戻り）

jal（jump and link）は、次の命令のアドレス（PC + 4）を rd に保存してからジャンプします。保存したアドレスに jalr で戻れば、関数呼び出しと復帰になります。rd に x0 を指定すると戻りアドレスは捨てられ、単なるジャンプになります。「より大きい」「以下」の分岐命令はありませんが、オペランドを入れ替えれば blt と bge で表せます。

6.6. ロード／ストアアーキテクチャ

RISC-V では、メモリにアクセスできるのはロード命令とストア命令だけで、算術論理命令のオペランドは必ずレジスタか即値です。このような ISA をロード／ストアアーキテクチャ（load/store architecture）と呼びます。たとえば「メモリ上の変数 x に 1 を足す」には、次の 3 命令が必要です。

1lw   x5, 0(x10)     # x5 = x（x10 は x のアドレス）
2addi x5, x5, 1      # x5 = x5 + 1
3sw   x5, 0(x10)     # x = x5

x86-64 では add dword ptr [rdi], 1 の 1 命令で同じことができます。命令数だけを比べると x86-64 のほうが少なく見えますが、ロード／ストアアーキテクチャには次の利点があります。

  • 1 つの命令が行うメモリアクセスは高々 1 回で、命令の実行の流れが単純になります。パイプライン化（「パイプライン」）が容易になります。

  • メモリアクセスで起きる例外（ページフォールトなど）の発生箇所が限られ、例外処理が単純になります。

  • ロードを早めに発行して、値が届くまでの間に他の命令を実行するといった最適化をコンパイラが行いやすくなります。

6.7. RISC-V のモジュール構成

RISC-V は、小さな基本 ISA に必要な拡張（extension）を組み合わせるモジュール構成をとります。仕様はオープンで、誰でもライセンス料なしに RISC-V のプロセッサを設計できます。RISC-V はカリフォルニア大学バークレー校で 2010 年に始まったプロジェクトから生まれ、現在は RISC-V International が仕様を管理しています。

6.9. RISC と CISC

1980 年前後に、命令を単純にして高速に実行するという設計思想が提唱され、RISC（Reduced Instruction Set Computer）と呼ばれました。これに対して、それ以前の複雑な命令を持つ ISA はCISC（Complex Instruction Set Computer）と呼ばれるようになりました。歴史的な経緯は「アーキテクチャの歴史」で説明しています。典型的な特徴を比べると次のようになります。

多くの命令がメモリオペランドを取れます。

小さいです（命令数は増えます）。

大きいです（命令数は減ります）。

デコード

単純です。

複雑です（命令の境界を見つけるだけでも手間がかかります）。

代表例

RISC-V、AArch64、MIPS、SPARC、POWER

x86、x86-64、IBM System/360 の後継、VAX

性能の式（「性能の測り方」）で考えると、CPU 時間は「命令数 × CPI × クロックサイクル時間」です。CISC は命令数を減らし、RISC は CPI とクロックサイクル時間を減らすことを狙った設計といえます。

現在では、この区別は ISA の表面上のものになっています。x86-64 のプロセッサは、Intel の Pentium Pro（1995 年）以降、x86 の命令をデコーダで RISC 風の単純な内部命令であるマイクロオペレーション（micro-operation：μop）に分解して実行しています。たとえば add dword ptr [rdi], 1 は、おおよそ「ロード」「加算」「ストア」の μop に分解されます。複雑な命令はマイクロコードによって多数の μop の列に展開されます。分解した μop は、RISC のプロセッサと同じようにパイプラインとアウトオブオーダー実行（「命令レベル並列性」）で処理されます。最近の x86-64 のプロセッサは、デコード済みの μop を保存する μop キャッシュを持ち、複雑なデコードを繰り返さずに済むようにしています。

つまり、CISC の ISA の利点（バイナリ互換性とコード密度）を保ちながら、内部は RISC と同じ技術で高速化しているのです。その代償として、デコーダの面積と電力が余分にかかります。

6.10. エンコード例

最後に、命令 add x5, x6, x7 を 32 ビットの機械語に符号化する手順を追います。

  1. add はレジスタ間の演算なので R 形式です。

  2. 仕様から、add のオペコードは 0110011、funct3 は 000、funct7 は 0000000 です。

  3. rd = x5、rs1 = x6、rs2 = x7 なので、それぞれ 5 ビットの 2 進数で 00101、00110、00111 です。

  4. 各フィールドを R 形式の位置に並べます。

並べた 32 ビットを 4 ビットずつ区切って 16 進数にします。

10000000 00111 00110 000 00101 0110011
2= 0000 0000 0111 0011 0000 0010 1011 0011
3= 0x007302B3

したがって add x5, x6, x7 の機械語は 0x007302B3 です。メモリにはリトルエンディアンで B3 02 73 00 の順にバイトが並びます。

同様に I 形式の addi x5, x6, -1 を符号化してみます。即値 \(-1\) は 12 ビットの 2 の補数で 111111111111 です。addi のオペコードは 0010011、funct3 は 000 なので、次のようになります。

1111111111111 00110 000 00101 0010011
2= 1111 1111 1111 0011 0000 0010 1001 0011
3= 0xFFF30293

逆に、機械語からアセンブリを復元することを逆アセンブル（disassemble）と呼びます。デコーダは下位 7 ビットのオペコードで形式を判別し、funct3、funct7 で演算を特定します。これはプロセッサの命令デコーダが行っていることと同じです。命令を実際に実行するシミュレーターは「プロセッサの設計」で作ります。

6.11. この章のまとめ

  • ISA は、レジスタ、データ型、命令とその符号化、アドレッシングモード、メモリモデル、例外を定める、ソフトウェアとハードウェアの約束事です。

  • RV32I の命令は 32 ビット固定長で、R、I、S、B、U、J の 6 形式があり、レジスタ番号と即値の符号ビットの位置がそろえられています。

  • RISC-V のアドレッシングモードはレジスタ、即値、ベース + 変位、PC 相対の少数に限られます。

  • メモリにアクセスできるのはロードとストアだけです（ロード／ストアアーキテクチャ）。

  • RISC-V は基本 ISA（RV32I、RV64I）に M、A、F、D、C、V などの拡張を組み合わせるモジュール構成です。

  • x86-64 は可変長命令、2 オペランド、メモリオペランド、フラグを持つ CISC 型の ISA ですが、内部では μop に分解して RISC と同様の技術で実行しています。

  • add x5, x6, x7 の機械語は 0x007302B3 です。
