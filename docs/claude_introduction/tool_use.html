7. ツール利用

ツール利用（tool use）は、Claude に外部の関数やサービスを呼び出させる仕組みです。データベースの検索、社内システムの API の呼び出し、計算、ファイルの操作など、モデル単体ではできない処理を Claude の判断で実行させられます。関数呼び出し（function calling）とも呼ばれます。

7.1. 仕組み

Claude 自身がツールを実行するわけではありません。Claude は「どのツールを、どの引数で呼びたいか」を応答として返し、実際の実行はアプリケーションが行います。流れは図 7.1 のとおりです。

ツールを実行するのはアプリケーションなので、どの処理を許可するか、実行前に人の承認を挟むかといった制御は、アプリケーション側で行えます。

7.2. ツールの定義

ツールは、名前、説明、入力の JSON スキーマで定義し、tools 引数に渡します。

コード 7.1 ツールの定義の例
 1{
 2    "name": "get_stock",
 3    "description": "商品コードを指定して在庫数を取得する。",
 4    "strict": True,
 5    "input_schema": {
 6        "type": "object",
 7        "properties": {
 8            "item_code": {
 9                "type": "string",
10                "description": "商品コード。例: A-100",
11            },
12        },
13        "required": ["item_code"],
14        "additionalProperties": False,
15    },
16}
表 7.1 ツール定義の項目

項目

説明

name

ツールの名前。英数字、下線、ハイフンで付けます

description

ツールの説明。Claude はこの説明を読んで、いつ、どう使うかを判断します

input_schema

引数の JSON スキーマ。各引数にも description を付けます

strict

True にすると、Claude が生成する引数がスキーマに必ず従います。スキーマには required と "additionalProperties": False が必要

description は、ツール利用の精度を最も左右する項目です。何をするツールか、どのような場面で使うべきか、引数の形式、返す値の意味を、事情を知らない人にも分かるように書いてください。

7.3. ツール利用のループ

在庫と単価を調べて合計金額を答えさせる例で、ループの書き方を示します。

コード 7.2 ex11_tool_use_manual.py
  1"""ツール利用のループを自分で書くサンプル.
  2
  3Claude が「どのツールをどの引数で呼ぶか」を決め、プログラム側が実際に
  4ツールを実行して結果を返します。stop_reason が tool_use の間はこれを
  5繰り返し、end_turn になったら終了します。
  6
  7実行例:
  8    python ex11_tool_use_manual.py
  9"""
 10
 11import json
 12import os
 13from typing import Any
 14
 15import anthropic
 16from anthropic.types import MessageParam, ToolParam, ToolResultBlockParam
 17
 18MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
 19MAX_TURNS = 10  # 無限ループを防ぐための上限
 20
 21# 在庫データの代わりに使う辞書 (実際にはデータベースなどを参照する)
 22STOCK = {"A-100": 12, "B-200": 0, "C-300": 5}
 23PRICE = {"A-100": 1500, "B-200": 3200, "C-300": 800}
 24
 25TOOLS: list[ToolParam] = [
 26    {
 27        "name": "get_stock",
 28        "description": "商品コードを指定して在庫数を取得する。",
 29        "strict": True,
 30        "input_schema": {
 31            "type": "object",
 32            "properties": {
 33                "item_code": {
 34                    "type": "string",
 35                    "description": "商品コード。例: A-100",
 36                },
 37            },
 38            "required": ["item_code"],
 39            "additionalProperties": False,
 40        },
 41    },
 42    {
 43        "name": "get_price",
 44        "description": "商品コードを指定して税抜単価 (円) を取得する。",
 45        "strict": True,
 46        "input_schema": {
 47            "type": "object",
 48            "properties": {
 49                "item_code": {"type": "string"},
 50            },
 51            "required": ["item_code"],
 52            "additionalProperties": False,
 53        },
 54    },
 55]
 56
 57
 58def run_tool(name: str, tool_input: dict[str, Any]) -> tuple[str, bool]:
 59    """ツールを実行し、(結果の文字列, エラーかどうか) を返す."""
 60    code = str(tool_input.get("item_code", ""))
 61    table = {"get_stock": STOCK, "get_price": PRICE}.get(name)
 62    if table is None:
 63        return f"不明なツールです: {name}", True
 64    if code not in table:
 65        return f"商品コード {code} は存在しません。", True
 66    return json.dumps({"item_code": code, "value": table[code]}), False
 67
 68
 69def main() -> None:
 70    client = anthropic.Anthropic()
 71    messages: list[MessageParam] = [
 72        {
 73            "role": "user",
 74            "content": "A-100 と B-200 の在庫と単価を調べて、"
 75            "在庫がある商品の在庫金額の合計を教えてください。",
 76        },
 77    ]
 78
 79    for _ in range(MAX_TURNS):
 80        response = client.messages.create(
 81            model=MODEL,
 82            max_tokens=4096,
 83            tools=TOOLS,
 84            messages=messages,
 85        )
 86        # Claude の応答 (tool_use ブロックを含む) を履歴に追加する
 87        messages.append({"role": "assistant", "content": response.content})
 88
 89        if response.stop_reason != "tool_use":
 90            break
 91
 92        # 要求されたツールをすべて実行し、結果を 1 つの user メッセージで返す
 93        results: list[ToolResultBlockParam] = []
 94        for block in response.content:
 95            if block.type == "tool_use":
 96                content, is_error = run_tool(block.name, block.input)
 97                print(f"[tool] {block.name}({block.input}) -> {content}")
 98                results.append(
 99                    {
100                        "type": "tool_result",
101                        "tool_use_id": block.id,
102                        "content": content,
103                        "is_error": is_error,
104                    }
105                )
106        messages.append({"role": "user", "content": results})
107    else:
108        # break せずにループが終わった = 上限までツール呼び出しが続いた
109        print(f"[警告] {MAX_TURNS} ターン以内に作業が終わりませんでした。")
110        return
111
112    if response.stop_reason != "end_turn":
113        print(f"[警告] 応答が完了していません (stop_reason={response.stop_reason})")
114    print("".join(b.text for b in response.content if b.type == "text"))
115
116
117if __name__ == "__main__":
118    main()

ポイントは次のとおりです。

  • Claude の応答は、tool_use ブロックを含めてそのまま履歴に追加します（87 行目）。

  • stop_reason が tool_use でなくなったら、ループを抜けます（89 〜 90 行目）。

  • 1 つの応答に複数の tool_use ブロックが含まれることがあります。すべて実行し、結果はまとめて 1 つの user メッセージで返します（92 〜 106 行目）。結果を複数のメッセージに分けて返すと、Claude が以後ツールを並列に呼ばなくなる原因になります。

  • 各結果には、対応する tool_use ブロックの id を tool_use_id として付けます。

  • ツールの実行に失敗した場合は、結果を省略せず、is_error を True にしてエラーの内容を返します（103 行目）。Claude はエラーの内容を読み、引数を直して再試行するなどの対応をとります。

  • 想定外の繰り返しを防ぐため、ループの回数に上限を設けます（79 行目）。

7.4. ツールの選択の制御

tool_choice 引数で、ツールを使うかどうかの方針を指定できます。既定値は {"type": "auto"} で、ツールを使うかどうかを Claude が判断します。{"type": "none"} を指定すると、ツールを使わずに回答させられます。

特定のツールを必ず使わせる指定（any や tool）は、Claude Opus 5.5、Claude Sonnet 5.5、Claude Fable 5.1 では使えず、指定すると 400 エラーになります。特定のツールを使わせたい場合は、プロンプトでツール名を挙げて使うように指示し、引数の形式は strict で保証します。ツールを呼ぶ目的が JSON 形式の出力を得ることだけなら、API の応用の構造化出力を使うほうが簡潔です。

7.5. ツールランナー

前節のループは、どのアプリケーションでもほぼ同じ形になります。Python SDK のツールランナー（ベータ機能）を使うと、ループの制御を SDK に任せられます。

コード 7.3 ex12_tool_runner.py
 1"""SDK のツールランナーでツール利用のループを自動化するサンプル.
 2
 3@beta_tool を付けた関数は、型ヒントと docstring からツール定義が
 4自動生成されます。ループの制御は SDK が行います (ベータ機能)。
 5
 6実行例:
 7    python ex12_tool_runner.py
 8"""
 9
10import os
11from datetime import date
12
13import anthropic
14from anthropic import beta_tool
15
16MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
17
18
19@beta_tool
20def days_until(target: str) -> str:
21    """今日から指定日までの日数を返す.
22
23    Args:
24        target: 日付。YYYY-MM-DD 形式。
25    """
26    try:
27        delta = date.fromisoformat(target) - date.today()
28    except ValueError:
29        return f"日付の形式が正しくありません: {target}"
30    return f"{target} まで {delta.days} 日です。"
31
32
33@beta_tool
34def weekday_of(target: str) -> str:
35    """指定日の曜日を返す.
36
37    Args:
38        target: 日付。YYYY-MM-DD 形式。
39    """
40    names = ["月", "火", "水", "木", "金", "土", "日"]
41    try:
42        day = date.fromisoformat(target)
43    except ValueError:
44        return f"日付の形式が正しくありません: {target}"
45    return f"{target} は {names[day.weekday()]} 曜日です。"
46
47
48def main() -> None:
49    client = anthropic.Anthropic()
50
51    runner = client.beta.messages.tool_runner(
52        model=MODEL,
53        max_tokens=4096,
54        tools=[days_until, weekday_of],
55        messages=[
56            {
57                "role": "user",
58                "content": "2026-12-25 は何曜日で、今日から何日後ですか。",
59            },
60        ],
61    )
62
63    # ツール呼び出しが無くなるまで、各ターンの応答が順に返される
64    for message in runner:
65        for block in message.content:
66            if block.type == "tool_use":
67                print(f"[tool] {block.name}({block.input})")
68            elif block.type == "text":
69                print(block.text)
70
71
72if __name__ == "__main__":
73    main()

@beta_tool を付けた関数は、関数名、型ヒント、docstring からツール定義が自動的に生成されます（19 行目、33 行目）。docstring の 1 行目がツールの説明、Args: の各行が引数の説明になります。

ツールランナーは、ツールの呼び出しがなくなるまで自動でループし、各ターンの応答を順に返します（64 行目）。for 文の中で各ターンの応答を確認したり、ログに記録したりできるため、多くの場合はツールランナーで十分です。ループの細部まで制御したい場合や、ベータ機能に依存したくない場合は、前節のように自分でループを書きます。

7.6. サーバーツール

ここまでのツールはアプリケーションが実行するものでしたが、Anthropic のサーバー上で実行されるツールもあります。これらは tools に宣言するだけで使え、実行結果も同じ応答に含まれます。

表 7.2 主なサーバーツール

ツール

内容

Web 検索

Web を検索し、結果をもとに出典付きで回答します

Web 取得

指定された URL のページや PDF の内容を取得します

コード実行

サンドボックス環境で Python などのコードを実行します。データ分析やグラフの作成に使います
コード 7.4 Web 検索ツールを使う
 1response = client.messages.create(
 2    model="claude-opus-5-5",
 3    max_tokens=16000,
 4    tools=[
 5        {
 6            "type": "web_search_20260209",
 7            "name": "web_search",
 8            "max_uses": 5,
 9            "allowed_domains": ["docs.python.org", "peps.python.org"],
10        },
11    ],
12    messages=[
13        {"role": "user", "content": "Python 3.14 の主な新機能を調べて"},
14    ],
15)

type の末尾の日付は、ツールの版を表します。使える版はモデルによって異なるため、公式ドキュメントで確認してください。max_uses で検索回数の上限を、allowed_domains で検索対象のドメインを制限できます。

7.7. ツール設計のこつ

  • ツールの数を絞る：似た機能のツールが多いと、Claude が選択を誤りやすくなります。用途ごとに少数の明確なツールを用意します。

  • 結果は簡潔に返す：ツールの結果は入力トークンとして課金され、コンテキストウィンドウも消費します。必要な項目に絞り、大量のデータは件数を制限するか要約して返します。

  • エラーは具体的に返す：「失敗しました」ではなく、「商品コード X-1 は存在しません。商品コードは A-100 の形式です」のように、Claude が次の行動を判断できる情報を返します。

  • 危険な操作は確認を挟む：データの削除、メールの送信、決済など、取り消せない操作をするツールは、実行前に人の承認を求めるようにします。

  • 引数を検証する：Claude が生成した引数は、外部からの入力と同じく信用せず、アプリケーション側で検証します。例えばファイルパスを受け取るツールでは、許可したディレクトリの外を指していないかを確認します。
