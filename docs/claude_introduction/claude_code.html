9. Claude Code 入門

9.1. Claude Code とは

Claude Code は、Anthropic が提供するコーディングエージェントです。利用者が自然言語で作業を依頼すると、Claude がソースコードを読み、コマンドを実行し、ファイルを編集しながら作業を進めます。コードの調査、機能の実装、不具合の修正、テストの作成、リファクタリング、Git の操作など、開発作業の多くを任せられます。

Claude Code は次の環境で使えます。

  • ターミナル（コマンドラインツール claude）

  • VS Code と JetBrains 系 IDE の拡張機能

  • Claude のデスクトップアプリ

  • Web ブラウザ（クラウド上の環境で実行）

本章では、すべての環境に共通する基本として、ターミナルでの使い方を説明します。

9.2. インストールと起動

インストーラーを使ってインストールします。

コード 9.1 Claude Code のインストール
1# macOS / Linux
2$ curl -fsSL https://claude.ai/install.sh | bash
3
4# Windows（PowerShell）
5PS> irm https://claude.ai/install.ps1 | iex

インストール後、作業したいプロジェクトのディレクトリで claude を実行します。初回は認証を求められるので、claude.ai の有料プランか Claude Console のアカウントでログインします。

コード 9.2 Claude Code の起動
1$ cd ~/projects/my-app
2$ claude

9.3. 基本操作

起動すると対話画面になり、依頼を入力して Enter キーで送信します。Claude は必要に応じてファイルを読み、コマンドを実行し、変更を提案します。ファイルの編集やコマンドの実行の前には、既定では利用者の許可を求めます。

表 9.1 基本操作

Claude を介さずにシェルのコマンドを直接実行し、結果を会話に含めます

9.4. 作業の進め方

Claude Code に大きな作業を任せるときは、図 9.1 の流れで進めると、手戻りを減らせます。

  1. 調査：いきなり実装を頼まず、まず関連するコードを読ませ、現状を説明させます。

  2. 計画：変更の方針を立てさせ、内容を確認します。後述の計画モードを使うと、Claude はファイルを変更せずに調査と計画だけを行います。

  3. 実装：計画に合意したら、実装を依頼します。

  4. 検証：テストや静的解析を実行させ、失敗したら修正させます。検証の手段を用意しておくことが、品質を保つうえで最も重要です。

  5. 記録：変更内容を確認し、コミットします。こまめにコミットしておくと、問題があったときに戻しやすくなります。

9.4.1. 依頼のこつ

  • 具体的に頼む：「テストを書いて」より「src/order.py の calculate_total に、割引が 100% の場合と数量が 0 の場合のテストを追加して」のほうが、意図どおりの結果になります。

  • 完了条件を示す：「pytest がすべて成功するまで修正して」のように、Claude が自分で確かめられる条件を示します。

  • 作業ごとに会話を分ける：別の作業に移るときは /clear で履歴を消します。無関係な履歴が残っていると、判断の質が下がり、利用量も増えます。

  • 画面やエラーをそのまま渡す：エラーメッセージやスクリーンショットは、要約せずにそのまま貼り付けます。

9.5. CLAUDE.md

CLAUDE.md は、プロジェクトの情報や作業のルールを Claude Code に伝えるためのファイルです。セッションの開始時に自動的に読み込まれるため、毎回同じ説明をする必要がなくなります。

表 9.3 CLAUDE.md の置き場所

場所

用途

プロジェクト直下の CLAUDE.md

プロジェクト固有の情報。リポジトリに含めてチームで共有します

サブディレクトリの CLAUDE.md

そのディレクトリ配下で作業するときにだけ必要な情報

~/.claude/CLAUDE.md

すべてのプロジェクトに共通する個人の好み

CLAUDE.md には、Claude がコードを読むだけでは分からないこと、つまり、よく使うコマンド、コーディング規約、触れてはいけないファイル、作業時の注意を書きます。記述例を示します。

コード 9.3 CLAUDE.md の例（CLAUDE.sample.md）
 1# プロジェクト概要
 2
 3社内向け在庫管理 Web アプリケーション。バックエンドは Python (FastAPI)、
 4フロントエンドは TypeScript (React)。
 5
 6# よく使うコマンド
 7
 8- 開発サーバー起動: `make dev`
 9- テスト: `pytest -q` (個別に実行する場合は `pytest tests/test_xxx.py -q`)
10- 静的解析: `flake8 src && mypy src`
11
12# コーディング規約
13
14- Python は PEP 8 に従い、すべての関数に型ヒントを付ける
15- 例外は握りつぶさず、ログに出力してから再送出する
16- データベースへのアクセスは `src/repository/` 配下に集約する
17
18# 作業時の注意
19
20- `migrations/` 配下のファイルは手で編集しない (`make migrate-new` で生成する)
21- 変更後は必ずテストと静的解析を実行し、結果を報告する
22- `.env` には本番の認証情報が含まれるため、読み取らない

CLAUDE.md の内容は、毎回コンテキストに含まれます。長くなりすぎないよう、要点に絞って書いてください。/init を実行すると、プロジェクトを調査して雛形を作成します。

9.6. 権限モード

Claude Code が利用者の許可なしにどこまで操作してよいかは、権限モードで切り替えます。

表 9.4 主な権限モード

モード

内容

default

ファイルの編集やコマンドの実行のたびに許可を求めます

acceptEdits

ファイルの編集は許可なしで行い、コマンドの実行には許可を求めます

plan

調査と計画だけを行い、ファイルの変更や、変更を伴うコマンドの実行はしません

auto

安全と判断された操作は自動で実行し、危険の可能性がある操作は止めます

dontAsk

設定ファイルで事前に許可した操作だけを実行し、それ以外は確認せずに拒否します。無人で動かす自動化向けです

bypassPermissions

すべての操作を許可なしで実行します。外部から隔離された環境以外では使いません

慣れないうちは default で始め、Claude の振る舞いを確認しながら、信頼できる操作を後述の設定ファイルで許可していくのが安全です。

9.7. 設定ファイル

Claude Code の設定は、settings.json に書きます。

表 9.5 設定ファイルの置き場所

場所

用途

~/.claude/settings.json

すべてのプロジェクトに共通する個人の設定

.claude/settings.json

プロジェクトの設定。リポジトリに含めてチームで共有します

.claude/settings.local.json

プロジェクトに対する個人の設定。リポジトリには含めません
コード 9.4 settings.json の例（settings.sample.json）
 1{
 2  "permissions": {
 3    "allow": [
 4      "Bash(pytest *)",
 5      "Bash(flake8 *)",
 6      "Bash(mypy *)"
 7    ],
 8    "deny": [
 9      "Read(./.env)",
10      "Read(./secrets/**)"
11    ]
12  },
13  "hooks": {
14    "PostToolUse": [
15      {
16        "matcher": "Edit|Write",
17        "hooks": [
18          {
19            "type": "command",
20            "command": "python -m flake8 src 1>&2 || exit 2"
21          }
22        ]
23      }
24    ]
25  }
26}

permissions の allow には許可なしで実行してよい操作を、deny には禁止する操作を書きます（2 〜 12 行目）。この例では、テストと静的解析のコマンドを許可し、認証情報を含むファイルの読み取りを禁止しています。

9.7.1. フック

フックは、Claude Code の動作の特定の時点で、指定したコマンドを自動的に実行する仕組みです。上の例の hooks では、Claude がファイルを編集するたびに flake8 を実行しています（13 〜 25 行目）。フックのコマンドが終了コード 2 で終わると、標準エラー出力の内容が Claude に伝えられます。この例では flake8 が違反を検出したときに終了コード 2 を返すようにしているため（20 行目）、Claude は違反の内容を読んで修正します。

表 9.6 主なフックの種類

種類

実行される時点

PreToolUse

ツールを使う直前。コマンドの終了コードによって、ツールの使用を止めることもできます

PostToolUse

ツールを使った直後。整形ツールや静的解析の実行に使います

UserPromptSubmit

利用者が依頼を送信したとき

Stop

Claude が応答を終えたとき。作業完了の通知などに使います

SessionStart

セッションを開始したとき

CLAUDE.md に書いた指示は Claude が判断して従うものですが、フックは必ず実行されます。「編集後は必ず整形する」のように例外なく守らせたい処理は、フックで実現します。

9.8. Claude Code の拡張

9.8.1. スキル

スキルは、特定の作業の手順や知識をまとめたものです。.claude/skills/<スキル名>/SKILL.md に置くと、Claude は関連する作業を頼まれたときに、そのスキルを読み込んで手順に従います。/<スキル名> で明示的に呼び出すこともできます。

コード 9.5 スキルの例（SKILL.sample.md）
 1---
 2name: release-notes
 3description: Git の履歴からリリースノートを作成する。リリースノートや変更履歴の作成を頼まれたときに使う。
 4---
 5
 6# リリースノートの作成手順
 7
 81. `git log --oneline <前回のタグ>..HEAD` で対象のコミットを一覧にする
 92. コミットを「新機能」「改善」「不具合修正」「その他」に分類する
103. 利用者に影響のない変更 (リファクタリング、テストのみの変更) は省く
114. 下記の形式で `docs/release-notes.md` の先頭に追記する
12
13## 形式
14
15    ## v<バージョン> (<リリース日>)
16
17    ### 新機能
18    - ...
19
20    ### 不具合修正
21    - ...

先頭の name と description（2 〜 3 行目）は常に Claude に示され、Claude はこの説明を見て、スキルを使うかどうかを判断します。本文は使うときにだけ読み込まれるため、スキルをたくさん用意してもコンテキストを圧迫しません。

9.8.2. サブエージェント

サブエージェントは、特定の作業を担当する専用のエージェントです。メインの会話とは別のコンテキストで作業し、結果だけを返します。大量のファイルを読む調査や、独立した観点でのレビューを任せると、メインの会話のコンテキストを節約できます。

サブエージェントは .claude/agents/<名前>.md に定義します。/agents コマンドで対話的に作成することもできます。

コード 9.6 サブエージェントの例（agent.sample.md）
 1---
 2name: code-reviewer
 3description: 変更差分をレビューし、不具合や保守性の問題を指摘する。実装が終わった後のレビューに使う。
 4tools: Read, Grep, Glob, Bash
 5model: sonnet
 6---
 7
 8あなたは経験豊富なコードレビュー担当者です。
 9
101. `git diff` で変更内容を確認する
112. 次の観点で問題を探す
12   - 不具合 (境界値、例外処理、競合状態)
13   - セキュリティ (入力検証、機密情報の扱い)
14   - 可読性と保守性
153. 指摘は重要度の高い順に、ファイル名と行番号を付けて報告する
164. 問題がなければ「指摘なし」と報告する

tools で使えるツールを、model で使うモデルを指定できます（4 〜 5 行目）。この例では、レビュー担当にファイルを編集する Edit や Write のツールを与えていません。

9.8.3. MCP サーバー

MCP によるツール連携で説明したとおり、MCP サーバーを登録すると、Claude Code から外部のサービスやデータベースを操作できます。課題管理サービスの MCP サーバーを登録すれば、「課題 123 の内容を読んで実装して」のような依頼ができるようになります。

9.9. 自動化での利用

-p オプションを付けると、Claude Code を対話画面なしで実行し、結果を標準出力に出力できます。シェルスクリプトや CI（継続的インテグレーション）に組み込めます。

コード 9.7 対話画面なしでの実行
1# 結果をテキストで受け取る
2$ claude -p "src 配下の TODO コメントを一覧にして"
3
4# 結果を JSON で受け取り、jq で処理する
5$ claude -p "直近のコミットの変更点を要約して" --output-format json | jq -r .result
6
7# 標準入力からデータを渡す
8$ cat error.log | claude -p "このログからエラーの原因を推定して"

GitHub と連携すると、プルリクエストや課題のコメントで Claude に依頼し、レビューや修正を任せることもできます。より高度な自動化には、エージェントの構築で説明する Claude Agent SDK を使います。

9.10. 安全に使うために

  • 権限は段階的に広げる：最初は default モードで振る舞いを確認し、信頼できる操作だけを許可します。

  • 機密情報を読ませない：認証情報を含むファイルは、設定ファイルの deny で読み取りを禁止します。

  • 変更は必ずレビューする：Claude が作成したコードも、人が書いたコードと同じくレビューしてからマージします。

  • 信頼できない内容に注意する：外部から取得したファイルや Web ページに、Claude を誤った操作に誘導する指示が含まれている場合があります（プロンプトインジェクション参照）。信頼できないリポジトリで作業するときは、権限を絞るか、隔離された環境を使います。
