10. エージェントの構築

10.1. ワークフローとエージェント

Claude を組み込んだシステムは、処理の流れを誰が決めるかによって、2 種類に分けられます。

  • ワークフロー：処理の手順をプログラムで決めておき、各段階で Claude を呼び出す方式です。「要約する、分類する、分類に応じて担当者に通知する」のように手順が決まっている処理に向いています。

  • エージェント：目標だけを与え、どのツールをどの順で使うかを Claude 自身に判断させる方式です。「この不具合を直して」のように、事前に手順を決めきれない処理に向いています。

エージェントは柔軟ですが、料金と処理時間が増え、動作の予測や検証も難しくなります。まずは 1 回の API 呼び出しやワークフローで実現できないかを検討し、それでは不十分な場合にエージェントを採用するのが基本です。

10.1.1. エージェントを採用するかの判断

次の 4 つの問いにすべて「はい」と答えられる場合に、エージェントの採用を検討します。

表 10.1 エージェントを採用する条件

観点

問い

複雑さ

作業が多段階で、手順を事前に決めきれないか

価値

成果が、増える料金と処理時間に見合うか

実現性

Claude がその種類の作業を十分にこなせるか（評価で確認したか）

誤りの影響

誤りをテスト、レビュー、取り消しなどで検出し、回復できるか

10.2. ワークフローの典型的なパターン

ワークフローには、よく使われるパターンがいくつかあります。

表 10.2 ワークフローのパターン

パターン

内容と例

プロンプトの連鎖

作業を段階に分け、前段の出力を次段の入力にします。例：資料から要点を抽出し、要点から報告書を書きます

振り分け

入力を分類し、分類ごとに専用のプロンプトやモデルで処理します。例：問い合わせを種類別に振り分け、簡単なものは小さなモデルで答えます

並列化

独立した処理を同時に実行し、結果をまとめます。例：文書を章ごとに並行して要約します

指揮者と作業者

指揮役の呼び出しが作業を分割し、作業役の呼び出しに割り当て、結果を統合します。例：複数のファイルにまたがる変更

評価者と改善者

一方が出力を作り、もう一方が評価して改善点を返すことを繰り返します。例：翻訳の推敲

これらは組み合わせて使えます。どのパターンも、API 入門とツール利用で説明した API の呼び出しを組み合わせるだけで実装できます。

10.3. 構築手段の選び方

エージェントを構築する手段は、エージェントのループ（ツールを呼んで結果を返す繰り返し）を誰が実装するかと、エージェントを動かす環境を誰が用意するかで、表 10.3 の 4 つに分けられます。

最初の 2 つはツール利用で説明しました。本節では残りの 2 つを紹介します。

10.3.1. Claude Agent SDK

Claude Agent SDK は、Claude Code 入門で説明した Claude Code のエージェント機能を、ライブラリとして使えるようにしたものです。ファイルの読み書き、検索、コマンドの実行、Web 検索などの組み込みツール、エージェントのループ、コンテキストの管理、権限の制御があらかじめ用意されているため、少ないコードで本格的なエージェントを作れます。Python 版と TypeScript 版があります。

コード 10.1 ex15_agent_sdk.py
 1"""Claude Agent SDK でコードベースを調査するエージェントを動かすサンプル.
 2
 3Claude Agent SDK は、Claude Code のエージェント機能をライブラリとして
 4使えるようにしたものです。ファイルの読み取りや検索などの組み込みツールと、
 5エージェントのループがあらかじめ用意されています。
 6
 7事前に次のパッケージをインストールしてください。
 8    pip install claude-agent-sdk
 9
10実行例:
11    python ex15_agent_sdk.py /path/to/repository
12"""
13
14import asyncio
15import sys
16
17from claude_agent_sdk import (
18    AssistantMessage,
19    ClaudeAgentOptions,
20    ResultMessage,
21    TextBlock,
22    ToolUseBlock,
23    query,
24)
25
26PROMPT = """\
27このリポジトリの構成を調査し、次の 3 点を日本語で簡潔に報告してください。
281. 主な機能
292. ディレクトリ構成と各ディレクトリの役割
303. テストの実行方法
31"""
32
33
34async def investigate(repository: str) -> None:
35    """リポジトリを読み取り専用で調査し、経過と結果を表示する."""
36    options = ClaudeAgentOptions(
37        cwd=repository,
38        # 読み取り系のツールだけを許可し、ファイルの変更やコマンド実行はさせない
39        allowed_tools=["Read", "Grep", "Glob"],
40        permission_mode="dontAsk",
41        max_turns=30,
42        max_budget_usd=1.0,
43    )
44
45    async for message in query(prompt=PROMPT, options=options):
46        if isinstance(message, AssistantMessage):
47            for block in message.content:
48                if isinstance(block, ToolUseBlock):
49                    print(f"[tool] {block.name} {block.input}")
50                elif isinstance(block, TextBlock):
51                    print(block.text)
52        elif isinstance(message, ResultMessage):
53            cost = message.total_cost_usd or 0.0
54            print(f"\n--- ターン数: {message.num_turns}, 料金: ${cost:.4f}")
55
56
57def main() -> None:
58    if len(sys.argv) != 2:
59        print("使い方: python ex15_agent_sdk.py <リポジトリのパス>")
60        sys.exit(1)
61    asyncio.run(investigate(sys.argv[1]))
62
63
64if __name__ == "__main__":
65    main()

ClaudeAgentOptions で、作業ディレクトリ、使用を許可するツール、権限の扱い、ターン数と料金の上限を指定しています（36 〜 43 行目）。この例では読み取り系のツールだけを許可し、権限モードを dontAsk（許可していない操作は確認せずに拒否する）にしているため、エージェントがファイルを変更することはありません。権限モードについては Claude Code 入門を参照してください。

query() は、エージェントの経過を表すメッセージを順に返します（45 行目）。AssistantMessage には Claude の発言とツールの呼び出しが、最後の ResultMessage には最終結果、ターン数、料金が入ります。

10.3.2. Claude Managed Agents

Claude Managed Agents（ベータ機能）は、エージェントのループと、ツールを実行するコンテナ環境の両方を Anthropic が提供するサービスです。エージェントの設定（モデル、システムプロンプト、ツールなど）をサーバーに登録し、セッションを開始すると、セッションごとに専用のコンテナが用意され、その中でコマンドの実行やファイルの操作が行われます。

実行環境を自前で用意・管理する必要がないため、長時間かかる作業、定期的な実行、多数のセッションの並行実行に向いています。

10.4. エージェント設計の要点

10.4.1. コンテキストを管理する

エージェントは作業の過程で大量のファイルやツールの結果を読み込むため、コンテキストウィンドウを消費しやすくなります。コンテキストに不要な情報がたまると、料金が増えるだけでなく、判断の質も下がります。

  • 調査のように大量の情報を読む作業は、サブエージェントに任せ、結論だけを受け取ります

  • 長い作業では、API の応用で説明したコンパクションやコンテキスト編集を使います

  • 作業の進捗や決定事項をファイルに書き出させ、必要なときに読み直させます

10.4.2. ツールの権限を絞る

エージェントに与えるツールと権限は、作業に必要な最小限にします。ファイルの削除、外部への送信、本番環境の操作など、取り消せない操作には人の承認を挟みます。

10.4.3. 上限を設ける

エージェントは、想定外の状況で同じ操作を繰り返したり、作業を必要以上に広げたりすることがあります。ターン数、料金、処理時間に上限を設け、上限に達したら停止して人に報告するようにします。

10.4.4. 完了条件を明確にする

「テストがすべて成功し、静的解析の違反がない状態になったら完了」のように、検証可能な完了条件を与えると、エージェントは自分の作業を確かめながら進められます。テストのような自動で検証できる手段を用意しておくことが、エージェントの品質を高める最も効果的な方法です。
