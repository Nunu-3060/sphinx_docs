5. API 入門

本章では、Python から Claude API を呼び出す方法を説明します。Claude API の中心は、メッセージを送って応答を受け取る Messages API（POST /v1/messages）です。ツール利用や構造化出力などの機能も、すべてこのエンドポイントのパラメーターとして提供されています。

5.1. 準備

5.1.1. API キーの取得

Claude Console（https://platform.claude.com/）でアカウントを作成し、支払い方法を登録したうえで API キーを発行します。API キーは発行時に一度しか表示されないため、安全な場所に保管してください。

API キーは、ソースコードに直接書かず、環境変数 ANTHROPIC_API_KEY で渡すのが原則です。ソースコードに書いたキーは、リポジトリへのコミットなどを通じて漏えいする危険があります。

コード 5.1 環境変数の設定（1 行目は Linux / macOS、2 行目は Windows PowerShell）
1$ export ANTHROPIC_API_KEY="sk-ant-..."
2PS> $env:ANTHROPIC_API_KEY = "sk-ant-..."

5.1.2. SDK のインストール

Anthropic は Python、TypeScript、Java、Go、Ruby、C#、PHP の公式 SDK を提供しています。本書では Python SDK（anthropic パッケージ）を使います。仮想環境を作成してインストールします。

コード 5.2 仮想環境の作成と SDK のインストール
1$ python -m venv .venv
2$ source .venv/bin/activate      # Windows では .venv\Scripts\activate
3$ pip install anthropic

本書のサンプルコードをまとめて実行する場合は、サンプルコード一覧の requirements.txt を使って pip install -r requirements.txt を実行してください。

5.2. 最初のリクエスト

最小構成のプログラムは次のとおりです。

コード 5.3 ex01_hello_claude.py
 1"""最小構成で Claude にメッセージを送るサンプル.
 2
 3実行前に環境変数 ANTHROPIC_API_KEY を設定してください。
 4使用するモデルは環境変数 CLAUDE_MODEL で変更できます。
 5
 6実行例:
 7    python ex01_hello_claude.py
 8"""
 9
10import os
11
12import anthropic
13
14MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
15
16
17def main() -> None:
18    # API キーは環境変数 ANTHROPIC_API_KEY から自動的に読み込まれる
19    client = anthropic.Anthropic()
20
21    response = client.messages.create(
22        model=MODEL,
23        max_tokens=1024,
24        messages=[
25            {"role": "user", "content": "Python の特徴を 3 行で説明してください。"},
26        ],
27    )
28
29    # 応答はコンテンツブロックのリスト。テキストブロックだけを表示する
30    for block in response.content:
31        if block.type == "text":
32            print(block.text)
33
34    print("---")
35    print(f"stop_reason  : {response.stop_reason}")
36    print(f"input_tokens : {response.usage.input_tokens}")
37    print(f"output_tokens: {response.usage.output_tokens}")
38
39
40if __name__ == "__main__":
41    main()

anthropic.Anthropic() は、環境変数 ANTHROPIC_API_KEY から API キーを読み込んでクライアントを生成します（19 行目）。client.messages.create() の主な引数は次のとおりです。

○

5.3. 応答の構造

messages.create() は Message オブジェクトを返します。主な属性は次のとおりです。

表 5.2 Message の主な属性

属性

説明

content

応答本体。コンテンツブロックのリスト

stop_reason

生成が止まった理由

usage

入力と出力のトークン数。料金の計算に使います

model

実際に応答したモデルの ID

id

メッセージの ID

5.3.1. コンテンツブロック

応答の content は、文字列ではなくブロックのリストです。ブロックには種類（type）があり、テキストは text、思考の内容は thinking、ツールの呼び出し要求は tool_use というブロックで返されます。

1 つの応答に複数の種類のブロックが含まれることがあるため、response.content[0].text のように先頭のブロックを決め打ちで読むのは避けてください。ex01_hello_claude.py の 30 〜 32 行目のように、type を確認してから読むのが安全です。

5.3.2. stop_reason

stop_reason は、応答を利用する前に必ず確認すべき属性です。

表 5.3 stop_reason の値

値

意味と対処

end_turn

応答が自然に完了しました

max_tokens

max_tokens の上限に達し、応答が途中で切れています。max_tokens を引き上げます（大きな値にする場合はストリーミングを使います）

stop_sequence

stop_sequences に指定した文字列が出力されました

tool_use

Claude がツールの呼び出しを求めています（ツール利用参照）

pause_turn

サーバー側のツールの処理が長くなり、一時停止しました。応答をそのまま送り返すと処理が再開されます

refusal

安全上の理由で応答が拒否されました。stop_details に分類が入ります

5.4. システムプロンプト

システムプロンプトは、会話全体に適用される前提や方針を指定するための入力で、system 引数に渡します。役割、応答の方針、出力の形式、利用できる資料などを書きます。

コード 5.4 ex02_system_prompt.py
 1"""システムプロンプトで Claude の役割と出力形式を指定するサンプル.
 2
 3同じ質問に対して、システムプロンプトの有無で応答がどう変わるかを比較します。
 4
 5実行例:
 6    python ex02_system_prompt.py
 7"""
 8
 9import os
10
11import anthropic
12
13MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
14
15SYSTEM_PROMPT = """\
16あなたは社内向けの Python コードレビュー担当者です。
17以下のルールに従って回答してください。
18
19- 指摘は重要度の高い順に箇条書きで示す
20- 各指摘には修正後のコードを付ける
21- 問題がなければ「指摘なし」とだけ答える
22"""
23
24CODE = """\
25def average(values):
26    return sum(values) / len(values)
27"""
28
29
30def ask(client: anthropic.Anthropic, system: str | None) -> str:
31    """CODE のレビューを依頼し、応答テキストを返す."""
32    question = f"次のコードをレビューしてください。\n\n{CODE}"
33    if system is None:
34        response = client.messages.create(
35            model=MODEL,
36            max_tokens=2048,
37            messages=[{"role": "user", "content": question}],
38        )
39    else:
40        response = client.messages.create(
41            model=MODEL,
42            max_tokens=2048,
43            system=system,
44            messages=[{"role": "user", "content": question}],
45        )
46    return "".join(b.text for b in response.content if b.type == "text")
47
48
49def main() -> None:
50    client = anthropic.Anthropic()
51
52    print("=== システムプロンプトなし ===")
53    print(ask(client, None))
54    print()
55    print("=== システムプロンプトあり ===")
56    print(ask(client, SYSTEM_PROMPT))
57
58
59if __name__ == "__main__":
60    main()

利用者が入力する内容は messages に、アプリケーション側で固定する指示は system に、と分けるのが基本です。

5.5. 複数ターンの対話

Messages API はステートレスです。サーバーは過去のやり取りを記憶しないため、会話を続けるには、これまでの履歴をすべて messages に含めて毎回送信します（図 5.1）。

コード 5.5 ex03_multi_turn.py
 1"""会話履歴を保持して複数ターンの対話を行うサンプル.
 2
 3Messages API はステートレスです。過去のやり取りを覚えてもらうには、
 4毎回の呼び出しで会話履歴全体を messages に渡します。
 5
 6実行例:
 7    python ex03_multi_turn.py
 8    (空行を入力すると終了します)
 9"""
10
11import os
12
13import anthropic
14from anthropic.types import MessageParam
15
16MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
17
18
19class Conversation:
20    """会話履歴を保持し、Claude との対話を管理するクラス."""
21
22    def __init__(self, client: anthropic.Anthropic, system: str) -> None:
23        self._client = client
24        self._system = system
25        self._history: list[MessageParam] = []
26
27    def send(self, user_text: str) -> str:
28        """利用者の発言を送信し、Claude の応答テキストを返す."""
29        self._history.append({"role": "user", "content": user_text})
30
31        response = self._client.messages.create(
32            model=MODEL,
33            max_tokens=4096,
34            system=self._system,
35            messages=self._history,
36        )
37
38        # 応答のコンテンツブロックをそのまま履歴に追加する。
39        # テキストだけを取り出して追加すると、思考ブロックなどが失われる。
40        self._history.append(
41            {"role": "assistant", "content": response.content}
42        )
43
44        return "".join(b.text for b in response.content if b.type == "text")
45
46
47def main() -> None:
48    conversation = Conversation(
49        anthropic.Anthropic(),
50        system="あなたは簡潔に答えるアシスタントです。",
51    )
52
53    while True:
54        user_text = input("あなた> ").strip()
55        if not user_text:
56            break
57        print(f"Claude> {conversation.send(user_text)}\n")
58
59
60if __name__ == "__main__":
61    main()

40 〜 42 行目では、応答のテキストだけでなく、コンテンツブロックのリスト（response.content）をそのまま履歴に追加しています。応答には thinking ブロックや tool_use ブロックが含まれることがあり、それらを落とすと後続の応答の質が下がったり、エラーになったりするためです。

messages の先頭は user でなければなりません。また、履歴が長くなるほど入力トークンが増え、料金も増えます。長い会話の扱いについては長い会話の管理を参照してください。

5.6. ストリーミング

通常の呼び出しでは、応答がすべて生成されるまで結果が返りません。ストリーミングを使うと、生成された部分から順に受け取れます。チャット画面のように応答を逐次表示したい場合や、出力が長くなる場合に使います。

コード 5.6 ex04_streaming.py
 1"""応答をストリーミングで逐次表示するサンプル.
 2
 3長い応答を生成する場合は、ストリーミングを使うと最初の文字が表示される
 4までの待ち時間が短くなり、HTTP のタイムアウトも避けられます。
 5
 6実行例:
 7    python ex04_streaming.py
 8"""
 9
10import os
11
12import anthropic
13
14MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
15
16
17def main() -> None:
18    client = anthropic.Anthropic()
19
20    with client.messages.stream(
21        model=MODEL,
22        max_tokens=16000,
23        messages=[
24            {
25                "role": "user",
26                "content": "HTTP と HTTPS の違いを 400 字程度で説明してください。",
27            },
28        ],
29    ) as stream:
30        # テキストの断片が届くたびに表示する
31        for text in stream.text_stream:
32            print(text, end="", flush=True)
33
34        # ストリーム終了後、組み立て済みの完全なメッセージを取得できる
35        message = stream.get_final_message()
36
37    print()
38    print("---")
39    print(f"stop_reason  : {message.stop_reason}")
40    print(f"output_tokens: {message.usage.output_tokens}")
41
42
43if __name__ == "__main__":
44    main()

client.messages.stream() をコンテキストマネージャーとして使い、text_stream からテキストの断片を受け取ります（31 〜 32 行目）。ストリームを読み終えた後は get_final_message() で、通常の呼び出しと同じ Message オブジェクトを取得できます（35 行目）。

max_tokens を大きくする場合や入力が長い場合は、応答に時間がかかり、通常の呼び出しでは HTTP のタイムアウトに達することがあります。生成に時間がかかりそうな処理では、表示の必要がなくてもストリーミングを使い、get_final_message() で結果を受け取るのが安全です。

5.7. エラー処理

API の呼び出しは、ネットワークの障害、レート制限、サーバーの過負荷などで失敗することがあります。主な HTTP ステータスコードは次のとおりです。

表 5.4 主なエラー

コード

SDK の例外クラス

意味と対処

400

BadRequestError

リクエストの形式や内容に誤りがあります。再試行しても成功しないため、内容を修正します

401

AuthenticationError

API キーが無効

403

PermissionDeniedError

API キーに必要な権限がありません

404

NotFoundError

モデル ID などが存在しません

429

RateLimitError

レート制限を超えました。retry-after ヘッダーの秒数だけ待って再試行します

500

InternalServerError

サーバー内部のエラー。時間をおいて再試行します

529

OverloadedError

サーバーが過負荷の状態。時間をおいて再試行します

SDK は、408、409、429、5xx のような再試行で回復しうるエラーと接続エラーを、間隔を空けながら自動で再試行します（既定は 2 回）。それでも失敗した場合に備え、例外を具体的なクラスから順に捕捉します。

コード 5.7 ex05_error_handling.py
 1"""API 呼び出しのエラー処理と stop_reason の確認を行うサンプル.
 2
 3SDK は 408、409、429、5xx と接続エラーを自動で再試行します (既定 2 回)。
 4それでも失敗した場合に備え、例外を具体的な型から順に捕捉します。
 5
 6実行例:
 7    python ex05_error_handling.py
 8"""
 9
10import os
11import sys
12
13import anthropic
14from anthropic.types import Message
15
16MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
17
18
19def create_message(client: anthropic.Anthropic, prompt: str) -> Message | None:
20    """メッセージを送信する。失敗した場合は原因を表示して None を返す."""
21    try:
22        return client.messages.create(
23            model=MODEL,
24            max_tokens=1024,
25            messages=[{"role": "user", "content": prompt}],
26        )
27    except anthropic.AuthenticationError:
28        print("API キーが無効です。ANTHROPIC_API_KEY を確認してください。")
29    except anthropic.NotFoundError:
30        print(f"モデル '{MODEL}' が見つかりません。モデル ID を確認してください。")
31    except anthropic.BadRequestError as e:
32        print(f"リクエストの内容に誤りがあります: {e.message}")
33    except anthropic.RateLimitError as e:
34        retry_after = e.response.headers.get("retry-after", "不明")
35        print(f"レート制限に達しました。{retry_after} 秒後に再試行してください。")
36    except anthropic.APIStatusError as e:
37        print(f"API エラー (HTTP {e.status_code}): {e.message}")
38    except anthropic.APIConnectionError:
39        print("API に接続できません。ネットワーク設定を確認してください。")
40    return None
41
42
43def print_result(message: Message) -> None:
44    """stop_reason に応じて結果を表示する."""
45    # 問い合わせ時に役立つリクエスト ID
46    print(f"request_id: {message._request_id}")
47
48    if message.stop_reason == "refusal":
49        # 安全上の理由で応答が拒否された場合、content を読む前に判定する
50        details = message.stop_details
51        category = details.category if details else None
52        print(f"応答が拒否されました (category={category})")
53        return
54
55    text = "".join(b.text for b in message.content if b.type == "text")
56    print(text)
57
58    if message.stop_reason == "max_tokens":
59        print("[警告] max_tokens に達したため、応答が途中で切れています。")
60
61
62def main() -> None:
63    # 再試行回数とタイムアウト (秒) はクライアント生成時に変更できる
64    client = anthropic.Anthropic(max_retries=3, timeout=60.0)
65
66    message = create_message(client, "1 から 10 までの素数を列挙してください。")
67    if message is None:
68        sys.exit(1)
69    print_result(message)
70
71
72if __name__ == "__main__":
73    main()

ポイントは次のとおりです。

  • 例外は具体的なクラスから順に捕捉します（27 〜 39 行目）。APIStatusError は HTTP エラー全般の親クラスなので、個別のクラスより後に置きます。

  • stop_reason が refusal の場合は、content を読む前に判定します（48 〜 53 行目）。

  • 問い合わせの際に必要になるリクエスト ID は _request_id で取得できます（46 行目）。名前は下線で始まりますが、公開された属性です。

  • 再試行の回数とタイムアウトは、クライアントの生成時に max_retries と timeout で変更できます（64 行目）。

5.7.1. レート制限

API には、1 分あたりのリクエスト数、入力トークン数、出力トークン数の上限（レート制限）があります。上限は利用実績に応じた利用枠（ティア）によって決まり、利用額が増えると引き上げられます。現在の上限は Claude Console で確認できます。

大量のリクエストを送る処理では、同時実行数を制限する、即時性の不要な処理を API の応用のバッチ処理に回す、プロンプトキャッシュで入力トークンを減らす、といった対策を組み合わせます。

5.8. トークン数と料金

API の料金は、入力と出力のトークン数に応じて決まります。入力トークン数を \(N_{\mathrm{in}}\)、出力トークン数を \(N_{\mathrm{out}}\)、100 万トークンあたりの入力と出力の単価をそれぞれ \(P_{\mathrm{in}}\)、\(P_{\mathrm{out}}\) とすると、1 回の呼び出しの料金 \(C\) は次の式で求められます。

\[C = \frac{N_{\mathrm{in}} \, P_{\mathrm{in}} + N_{\mathrm{out}} \, P_{\mathrm{out}}}{10^{6}}\]

例えば Claude Opus 5.5（\(P_{\mathrm{in}} = 4\)、\(P_{\mathrm{out}} = 20\)）に 20,000 トークンを入力し、2,000 トークンの出力を得た場合の料金は次のとおりです。

\[C = \frac{20000 \times 4 + 2000 \times 20}{10^{6}} = 0.12 \ \text{(米ドル)}\]

出力の単価は入力の 5 倍なので、出力が短くても料金に占める割合は小さくありません。

5.8.1. トークン数の計測

実際のトークン数は、応答の usage で確認できます。送信前にトークン数を知りたい場合は、トークン計測 API（messages.count_tokens()）を使います。トークン計測 API は無料で、メッセージは生成されません。

コード 5.8 ex06_count_tokens.py
 1"""送信前にトークン数を数え、料金を概算するサンプル.
 2
 3count_tokens エンドポイントは料金がかからず、メッセージを生成しません。
 4ここでは入力トークン数と、出力トークン数の想定値から料金を概算します。
 5
 6実行例:
 7    python ex06_count_tokens.py
 8"""
 9
10import os
11
12import anthropic
13
14MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")
15
16# 100 万トークンあたりの料金 (米ドル)。2026 年 10 月時点の公表値。
17# 最新の料金は公式の料金ページで確認すること。
18PRICES_PER_MTOK: dict[str, tuple[float, float]] = {
19    "claude-fable-5-1": (10.00, 50.00),
20    "claude-opus-5-5": (4.00, 20.00),
21    "claude-sonnet-5-5": (2.00, 10.00),
22    "claude-haiku-4-5": (1.00, 5.00),
23}
24
25
26def estimate_cost(model: str, input_tokens: int, output_tokens: int) -> float:
27    """入出力トークン数から料金 (米ドル) を計算する."""
28    input_price, output_price = PRICES_PER_MTOK[model]
29    return (
30        input_tokens * input_price + output_tokens * output_price
31    ) / 1_000_000
32
33
34def main() -> None:
35    client = anthropic.Anthropic()
36
37    system = "あなたは技術文書の翻訳者です。"
38    document = "Claude is a family of large language models. " * 200
39
40    count = client.messages.count_tokens(
41        model=MODEL,
42        system=system,
43        messages=[
44            {"role": "user", "content": f"次の文章を和訳してください。\n\n{document}"},
45        ],
46    )
47
48    expected_output_tokens = 3000  # 想定する出力トークン数
49    cost = estimate_cost(MODEL, count.input_tokens, expected_output_tokens)
50
51    print(f"モデル              : {MODEL}")
52    print(f"入力トークン数      : {count.input_tokens:,}")
53    print(f"想定出力トークン数  : {expected_output_tokens:,}")
54    print(f"概算料金            : ${cost:.4f}")
55
56
57if __name__ == "__main__":
58    main()

トークンの数え方はモデルによって異なります。同じ文章でもモデルを変えるとトークン数が変わることがあるため、料金の見積もりは使用するモデルで計測してください。

5.9. 非同期クライアント

Web アプリケーションなど、複数のリクエストを並行して処理する場合は、非同期クライアント AsyncAnthropic を使います。使い方は同期版と同じで、呼び出しに await を付けます。

コード 5.9 非同期クライアントで複数の要約を並行して実行する例
 1import asyncio
 2
 3import anthropic
 4
 5MAX_CONCURRENCY = 5  # 同時に送るリクエストの上限
 6
 7
 8async def summarize(
 9    client: anthropic.AsyncAnthropic, limit: asyncio.Semaphore, text: str
10) -> str:
11    async with limit:  # 上限を超えるリクエストはここで待つ
12        response = await client.messages.create(
13            model="claude-opus-5-5",
14            max_tokens=1024,
15            messages=[{"role": "user", "content": f"100 字で要約して:\n{text}"}],
16        )
17    return "".join(b.text for b in response.content if b.type == "text")
18
19
20async def main(texts: list[str]) -> list[str]:
21    client = anthropic.AsyncAnthropic()
22    limit = asyncio.Semaphore(MAX_CONCURRENCY)
23    return await asyncio.gather(*(summarize(client, limit, t) for t in texts))
24
25
26summaries = asyncio.run(main(["文書 1 の本文...", "文書 2 の本文..."]))

並行数を増やしすぎるとレート制限に達するため、この例では asyncio.Semaphore で同時実行数を制限しています（11 行目と 22 行目）。
