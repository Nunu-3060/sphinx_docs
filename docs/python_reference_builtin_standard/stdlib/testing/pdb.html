pdb

Python に標準で組み込まれている、対話的なソースコードデバッガ。プログラムの 実行を任意の場所で一時停止し、その時点の変数の値を確認したり、1 行ずつ実行 しながら処理の流れを追ったりできる。print を挿入してのデバッグでは 追いきれない複雑な不具合の調査に役立つ。

デバッグセッションの開始

スクリプト全体を最初から pdb の管理下で実行したい場合は、python -m pdb を使ってスクリプトを起動する。プログラムの先頭で自動的に一時停止した状態から始まる。

$ python -m pdb myscript.py

コードの特定の場所でだけ一時停止したい場合は、その位置に組み込み関数 breakpoint() を呼び出すコードを挿入する。これが標準的な方法で、デフォルトでは内部的に pdb.set_trace() を呼び出す（sys.breakpointhook や環境変数 PYTHONBREAKPOINT を設定することで、別のデバッガを呼び出すように変更することもできる）。

def calculate(a, b):
    breakpoint()  # ここで実行が一時停止し、pdb のプロンプトが起動する
    return a / b

calculate(10, 0)

pdb セッション内でのコマンド

breakpoint() や python -m pdb によって (Pdb) プロンプトが表示された状態になったら、以下のようなコマンドを入力して対話的にデバッグを進める。これらは実行可能な Python コードではなく、pdbプロンプトに直接入力する対話コマンドである点に注意。

  • n (next) --- 現在の行を実行し、次の行へ進む（関数呼び出しの中へは 入らない）。

  • s (step) --- 現在の行を実行し、関数呼び出しがあればその内部へ ステップインする。

  • c (continue) --- 次のブレークポイント（または breakpoint() の 呼び出し）まで実行を再開する。

  • l (list) --- 現在実行中の行の周辺のソースコードを表示する。

  • p <式> (print) --- 指定した式を評価し、その結果を表示する （例: p a、p a + b）。

  • q (quit) --- デバッグセッションを終了し、プログラムの実行を 中断する。

pdb.pm

プログラムが例外を送出して異常終了した「後」に、その時点のトレースバック に対してデバッガを起動する（ポストモーテムデバッグ）。対話的な REPL で コードを実行していて、事前に breakpoint() を仕込んでいなかった場合に、 発生した例外の状況をさかのぼって調べたいときに使う。

>>> def divide(a, b):
...     return a / b
...
>>> divide(10, 0)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 2, in divide
ZeroDivisionError: division by zero
>>> import pdb
>>> pdb.pm()
> <stdin>(2)divide()
(Pdb) p a
10
(Pdb) p b
0
(Pdb) q

注釈

VS Code や PyCharm などのエディタ・IDE が備えるグラフィカルなデバッガも、 基本的には pdb と同じ仕組み（ブレークポイント、ステップ実行、 変数の検査）の上に構築されている。とはいえ pdb は追加のインストール や設定が不要で、SSH 接続先のサーバーなど IDE を使えないターミナル環境 で手早くデバッグしたい場合に今でも有用。
