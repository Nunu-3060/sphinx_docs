メンバーシップ・同一性演算子

コンテナに要素が含まれているかを調べる in / not in、オブジェクトの同一性（メモリ上で同じオブジェクトかどうか）を調べる is / is not について解説する。

in / not in

左辺の値が右辺のコンテナに含まれているか（含まれていないか）を判定し、bool を返す。list / tuple / str / dict（キー）/ set のいずれに対しても使用できる。

>>> 3 in [1, 2, 3]
True
>>> "py" in "python"
True
>>> "a" in {"a": 1, "b": 2}
True
>>> 5 not in (1, 2, 3)
True
>>> 3 in {1, 2, 3}
True

注釈

list や tuple に対する in は先頭から要素を1つずつ調べるため、要素数 n に対して最悪 O(n) の時間がかかる。一方 set や dict はハッシュテーブルとして実装されているため、in による判定は平均 O(1) で済む。大量のデータに対して頻繁にメンバーシップ判定を行う場合は、list ではなく set を使うことが高速化の定番の手段となる。

>>> names_list = ["alice", "bob", "carol"]
>>> names_set = {"alice", "bob", "carol"}
>>> "carol" in names_list  # 要素数に比例して遅くなる
True
>>> "carol" in names_set   # 要素数に関わらずほぼ一定時間
True

is / is not

2つのオブジェクトが同一のオブジェクト（メモリ上の同じ実体）であるかどうかを判定する。値が等しいかどうかを調べる == とは異なる概念である点に注意。

>>> a = [1, 2]
>>> b = [1, 2]
>>> c = a
>>> a == b
True
>>> a is b
False
>>> a is c
True

注釈

小さな整数（おおよそ -5〜256）や一部の短い文字列は、CPythonの実装上キャッシュ・インターン化されており、値が同じであれば is が True を返すことがある。しかしこれは CPythonの実装詳細 であり、言語仕様として保証されたものではないため、値の比較に is を使うべきではない。値の比較には常に == を使い、is / is not は、None や True / False といったシングルトンオブジェクトの判定（x is None など）に限定して使うのがよい。

>>> x = 100
>>> y = 100
>>> x is y  # 小さい整数はキャッシュされ、たまたま True になる
True
>>> x = 1000
>>> y = 1000
>>> x is y  # 大きい整数では保証されない（False になりやすい）
False

>>> value = None
>>> value is None  # シングルトン判定にはこちらが推奨される
True
