代入演算子

= による通常の代入に加えて、演算と代入を1つにまとめた複合代入演算子（拡張代入演算子）について解説する。

複合代入演算子の基本

x += 1 は多くの場合 x = x + 1 と同じ結果になる。四則演算やビット演算それぞれに対応する複合代入演算子が存在する。

>>> x = 10
>>> x += 5
>>> x
15
>>> x -= 3
>>> x
12
>>> x *= 2
>>> x
24
>>> x //= 5
>>> x
4
>>> x **= 2
>>> x
16

>>> flags = 0b0000
>>> flags |= 0b0001
>>> bin(flags)
'0b1'
>>> flags &= 0b0001
>>> bin(flags)
'0b1'

対応する複合代入演算子は次の通り。

  • 算術: += -= *= /= //= %= **=

  • ビット: &= |= ^= <<= >>=

ミュータブルなオブジェクトでの挙動の違い

int や str のようなイミュータブルな型では x += y は x = x + y と全く同じ（新しいオブジェクトを作って x に再代入する）だが、list のようなミュータブルな型では += は __iadd__ を通じて その場でオブジェクトを変更する。これは シーケンス演算子 で解説した + 演算子（常に新しいオブジェクトを生成する）とは異なる挙動であり、関数に渡したリストを += で更新すると呼び出し元のリストも変わってしまう点に注意が必要。

>>> a = [1, 2]
>>> b = a
>>> a += [3]       # in-place で変更される
>>> a
[1, 2, 3]
>>> b               # b も同じオブジェクトを参照しているため変わる
[1, 2, 3]

>>> a = [1, 2]
>>> b = a
>>> a = a + [3]     # 新しいオブジェクトが作られ、a に再代入される
>>> a
[1, 2, 3]
>>> b               # b は元のオブジェクトを参照したままなので変わらない
[1, 2]

注釈

関数の引数としてミュータブルなオブジェクトを受け取り、それを += で更新するコードは、呼び出し元のオブジェクトにも影響が及ぶことを意識しておく必要がある。呼び出し元に影響を与えたくない場合は、a = a + [...] のように新しいオブジェクトを作って再代入するか、事前に copy でコピーを取っておく。

代入式（walrus 演算子） :=

:= は「代入式」（assignment expression、PEP 572）と呼ばれる演算子で、見た目がセイウチの顔に似ていることから walrus 演算子とも呼ばれる。通常の = による代入は文（statement）であり値を返さないが、:= は 変数への代入を行いながら、その値を式として返す。これにより、代入と条件判定・利用を同時に行うことができる。

>>> while (chunk := input("chunk> ")) != "done":
...     print(f"got: {chunk}")
...
chunk> hello
got: hello
chunk> done

上の例では、input() の戻り値を chunk に代入しつつ、その場で != "done" の判定に使っている。:= がなければ、ループの中と外の2 か所で input() を呼び出すか、一度別の行で代入してから判定する必要があった。

計算済みの値をフィルタ条件と結果の両方で使いたいリスト内包表記でも、:= を使うと同じ計算を 2 回書かずに済む。:= を使わない場合、x * 2 をフィルタ条件と出力式のそれぞれで計算する必要があり、計算コストが高い処理では非効率になる。

>>> data = [1, 4, 9, 14, 21, 30]
>>> results = [y for x in data if (y := x * 2) > 10]
>>> results
[18, 28, 42, 60]

注釈

:= は式の一部として使う必要があるため、x := 1 のように単独の文としては書けず、括弧が必須になる場面が多い（(x := 1)）。単純な代入であれば、通常の = を使う方が読みやすい。
