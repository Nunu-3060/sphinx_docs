3. 開発環境とビルドの流れ

本章では、C++ のプログラムを作成して実行するための環境を準備し、ソースコードが実行ファイルになるまでの流れを説明します。

3.1. コンパイラーの導入

Python ではインタープリターを導入すればプログラムを実行できますが、C++ ではソースコードを実行ファイルに変換するコンパイラーが必要です。代表的なコンパイラーは GCC、Clang、MSVC（Microsoft Visual C++）の 3 種類です。

OS

導入方法の例

Windows

Visual Studio を導入し、インストーラーで「C++ によるデスクトップ開発」ワークロードを選択する

macOS

ターミナルで xcode-select --install を実行し、Xcode Command Line Tools（Clang）を導入する

Linux

パッケージマネージャーで GCC または Clang を導入する（Ubuntu の場合は sudo apt install build-essential）

注釈

Windows で MSVC をコマンドラインから使うには、スタートメニューから「Developer Command Prompt for VS」または「Developer PowerShell for VS」を起動します。通常のコマンドプロンプトでは、コンパイラー cl の場所が環境変数 PATH に設定されていないため、cl を実行できません。

3.2. Hello World

画面に文字列を表示するだけの最小のプログラムを作成し、コンパイルして実行します。以下の内容を hello.cpp という名前で保存します。

examples/ch03/hello.cpp
#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}

各行の意味は次のとおりです。

  • #include <iostream> は、標準入出力の機能を使うためにヘッダーファイルを取り込む指示です。Python の import に近い役割を持ちます。

  • int main() は、プログラムの実行開始位置となる関数です。

  • std::cout << "Hello, World!" は、文字列を標準出力に書き出します。std::endl は改行を出力します。

  • return 0; は、プログラムが正常に終了したことを OS に伝えます。

GCC または Clang の場合は、以下のコマンドでコンパイルと実行を行います。Clang の場合は g++ を clang++ に置き換えます。

$ g++ -std=c++17 -Wall -Wextra -o hello hello.cpp
$ ./hello
Hello, World!

MSVC の場合は、Developer Command Prompt で以下のコマンドを実行します。

> cl /std:c++17 /EHsc /W4 /utf-8 hello.cpp
> hello.exe
Hello, World!

主なオプションの意味を以下に示します。

GCC、Clang

MSVC

本資料のサンプルコードは UTF-8 で保存しており、コメントに日本語を含みます。MSVC は既定ではソースファイルをシステムの文字コード（日本語環境では Shift_JIS）として読み込むため、/utf-8 を指定しないと警告や文字化けが発生する場合があります。

3.3. ビルドの流れ

ソースコードから実行ファイルを作る作業をビルドと呼びます。ビルドは、プリプロセス、コンパイル、リンクの 3 段階で行われます。前節の g++ や cl のコマンドは、この 3 段階をまとめて実行しています。

段階

役割

プリプロセス

#include などのプリプロセッサーディレクティブを処理する。#include の行は、指定したヘッダーファイルの内容に置き換えられる

コンパイル

プリプロセス後のソースコードを機械語に変換し、オブジェクトファイル（.o または .obj）を生成する

リンク

複数のオブジェクトファイルとライブラリを結合し、実行ファイルを生成する

エラーがどの段階で発生したかは、エラーメッセージから判断できます。

  • コンパイルエラー：文法の誤りや型の不一致など、ソースコード 1 つを変換する時点で見つかる誤りです。エラーメッセージにはファイル名と行番号が表示されます。

  • リンクエラー：関数を宣言しているのに定義が見つからない場合などに発生します。MSVC では LNK2019、GCC では undefined reference というメッセージが表示されます。

3.4. コンパイラーの警告

コンパイラーは、エラーではないものの誤りの可能性が高い記述を警告として報告します。例えば、初期化していない変数の使用や、小数を含む値を整数型の変数に代入して値が失われる可能性がある場合などです。

Python では実行してみるまで気付かない誤りの多くを、C++ ではコンパイラーの警告で事前に発見できます。警告オプション（GCC と Clang では -Wall -Wextra、MSVC では /W4）を常に有効にし、警告が出なくなるまでソースコードを修正する習慣を付けてください。
